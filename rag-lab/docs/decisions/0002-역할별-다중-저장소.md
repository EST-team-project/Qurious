## 1. 맥락

ADR-0001(2026-09-22)은 전체 코퍼스가 작고(청크 약 1,190개 · 벡터 1.7MB) **배포 대상이 t2.micro(1GiB)** 라서,
Qdrant 를 띄우면 메모리가 모자랄 수 있다는 이유로 **pgvector 단독**을 골랐다. 그런데 2026-09-28 에 코드를 대조해 보니
결정과 실제가 어긋나 있었다.

| 결정 (ADR-0001) | 실제 코드 (`220c4a7`) | 확실도 |
|---|---|:-:|
| pgvector 단독 | `/chat` 은 pgvector(`vector_chunks`) — 분석 화면 RAG(`/api/rag/*`)는 **Qdrant 전용**인데 compose 에 Qdrant 가 없어 **늘 503** | 🟢 |
| Meilisearch 대신 pgvector | `meilisearch` 서비스와 선택형 검색 코드가 남아 있다(없으면 원문 검색으로 폴백) | 🟢 |
| (언급 없음) | **MongoDB** 가 퀴즈 · 단어시험 · 분석 로그인을 맡는다 — 퀴즈는 기동 때 Mongo 에 시드를 넣는다 | 🟢 |
| (언급 없음) | Redis 서비스가 있지만 **앱 코드가 쓰지 않는다** | 🟢 |
| Qdrant 코드 제거 | 교재 색인 스크립트(`app/ops/index_curriculum.py`)가 Qdrant 전용 · prod compose 가 그것을 돌린다 | 🟢 |

그리고 전제 두 가지가 바뀌었다.

1. **AWS 는 우선 제외한다** — 로컬 · 오픈소스로 먼저 완성한다. t2.micro 1GiB 는 더 이상 설계를 묶는 조건이 아니다.
2. **팀 HF Organization(`qurious-quant`)의 데이터를 써야 한다** — KRX 전 종목 일봉 · 수정주가 · 총수익(TR) · 배당 · 자체 벤치마크가
   파케이로 매일 올라간다(Qurious 수집기). 지금 이 앱은 시장 데이터를 외부 차트 · pykrx 로 그때그때 부르고,
   ML API 14개 중 5개(결정경계 · 교차검증 · k-평균 · MLP · SVM)는 `make_classification` 같은 **합성 데이터**로 돈다.

## 2. 결정

**데이터마다 가장 맞는 저장소 하나를 「정본」으로 정하고, 저장소는 역할별로 여러 개를 쓴다(polyglot persistence).**
코드는 저장소를 직접 부르지 않고 **포트(인터페이스) → 어댑터** 로 부른다. 어떤 어댑터를 쓸지는 환경 변수로 고른다.

| 저장소 | 정본으로 맡는 것 | 한 줄 이유 |
|---|---|---|
| **PostgreSQL** | 계정 · 세션 · 대화 기록 · 개인 일정 · 시세 캐시(`stock_price_history`) | 관계 · 트랜잭션이 필요한 것 |
| **pgvector** (PG 안) | 대화 장기 기억(`long_term_memories`) · 작은 벡터 색인의 **대체 경로** | 계정과 같은 트랜잭션에 묶이는 벡터 |
| **Qdrant** | 문서 검색 벡터 색인(교재 · 강의 · 업로드 문서) | 컬렉션 · 필터 · 색인 재구축이 독립적 |
| **MongoDB** | 퀴즈 문제은행 · 단어시험 제출 · 이용 활동 로그 | 모양이 자주 바뀌는 문서 · 추가만 하는 이벤트 |
| **HF Hub** (읽기 전용) | KRX 일봉 · 수정주가 · TR · 배당 · 벤치마크 | 팀 수집기가 매일 올리는 정본을 **받아서 읽기만** |
| Meilisearch · Redis | (선택) 전문 검색 · 외부 호출 캐시 | 없어도 기능이 멈추지 않게 폴백을 둔다 |

**벡터 색인은 정본이 아니다** — 문서 원문(PG `document_chunks` · 파일)에서 언제든 다시 만든다. 그래서 Qdrant 와 pgvector 는
「어느 쪽이든 같은 포트」로 바꿔 끼울 수 있고, 색인마다 **어떤 임베딩으로 만들었는지(embed method id)** 를 기록해 질의와 맞지
않으면 거절한다.

## 3. 근거 — 고려한 대안

| 대안 | 장점 | 단점 | 판정 |
|---|---|---|:-:|
| A. pgvector 단독 유지 (ADR-0001) | 서비스 하나 · 운영 단순 | 이미 Qdrant · Mongo 코드가 기능을 맡고 있어 **다시 옮기는 비용**이 크다 · HF 데이터 자리가 없다 | ✗ |
| B. 저장소를 여럿 두되 코드가 직접 부름 (지금 모습) | 추가 작업 없음 | 저장소 하나가 없으면 **기동 실패 · 503** · 같은 문서가 두 방식으로 임베딩돼 있다 | ✗ |
| **C. 역할별 정본 + 포트/어댑터 + 폴백** | 저장소를 바꿔 끼울 수 있다 · 없는 저장소가 있어도 앱이 뜬다 · HF 를 원천으로 붙일 자리가 생긴다 | 포트 계층 코드 · 서비스 수 증가 · 저장소 사이 트랜잭션 없음 | ✅ |
| D. 한 종류 문서 DB(Mongo)로 통일 | 저장소 하나 | 벡터 검색 · 관계형 무결성을 다시 만들어야 한다 | ✗ |

## 4. 결과

**좋아지는 것**
- 분석 화면 RAG 가 compose 에 Qdrant 를 되살리는 것만으로 다시 돈다(코드 변경 없이 — 1단계).
- Mongo · Qdrant · Meilisearch · Redis 가 없어도 **앱은 뜨고**, 그 저장소를 쓰는 기능만 「준비 안 됨」을 알린다.
- 과거 일봉 · 수정주가 · TR · 배당이 필요한 분석 · ML 이 합성 데이터 대신 **팀 수집 원천**(공공데이터포털 · OpenDART 파생)을 쓴다.
- 화면 표시용 외부 차트 호출은 **그대로 둔다** — 받아서 보여 주기만 하고 저장하지 않으므로 수집이 아니다(사용자 판단 · 2026-09-28).
  단 받은 값을 표에 저장하는 경로가 한 곳 있다(`market.py` `/period-return/extend` → `stock_price_history`) — 설계 문서 §4.4.

**대가 · 위험**
- 🔴 **HF 데이터는 private 이다.** 팀이 쓰기로 한 근거는 「private · 팀 범위」 하나뿐이다(Qurious `collector/README.md` §9.2).
  이 저장소는 **공개(Public)** 이고 배포 이력도 있다 → 파케이 파일을 커밋하지 않고, **공개 배포에서는 HF 원천을 끄거나**
  원자료 행을 그대로 내보내지 않는 집계만 보여 준다. 조건이 바뀌면 다시 판단한다(설계 문서 §6).
- 🟡 저장소 사이 트랜잭션이 없다 → 엔티티마다 정본을 하나로 정하고, 파생(벡터 색인 · 시세 캐시)은 **다시 만들 수 있게** 한다.
- 🟡 서비스가 늘어 로컬 메모리 · 기동 시간이 는다 → compose **프로필**로 필요한 것만 띄운다.
- 🟡 로그인이 두 벌(PG `/auth` · Mongo `/api/auth`)이다 → 계정 정본은 PG 하나로, Mongo 는 활동 로그만(설계 문서 §4.3).

### 4.1 후속 조치 (단계 — 설계 문서 §7)

1. Qdrant 를 compose 에 되살리고 교재 색인 잡을 붙인다 → 분석 RAG 503 해소
2. Mongo 없이도 기동(퀴즈 시드 가드) · 계정 정본 PG 로 일원화
3. 시장 데이터 포트 + **HF 파케이 어댑터**(로컬 캐시 · 읽기 전용) → 분석 · ML 의 과거 데이터 원천 (표시용 외부 차트 호출은 그대로)
4. 벡터 색인 포트(Qdrant | pgvector) + 임베딩 방식 기록 · 검사
5. (선택) Redis 캐시 · Meilisearch 프로필

변경이력: CN-009 · CN-010 (`00-index/변경이력.md`).
