## 왜 이유를 보여 줘야 하나요?

화면이 「매도」 한 낱말만 보여 주면 사용자는 그 신호를 따를지 말지 판단할 재료가 없습니다. 「일봉의 5일선이 20일선 아래라서」 라는 이유가 함께 있으면, 장기 투자자는 「나는 주봉을 더 보겠다」 처럼 자기 기준으로 다시 판단할 수 있습니다.

설명 가능한 인공지능(XAI, eXplainable AI)은 모델이나 규칙이 왜 그런 결과를 냈는지 사람이 이해할 수 있게 보여 주는 방법을 통틀어 부르는 말입니다. 앱에는 설명이 두 갈래로 있습니다.

| | 규칙 설명 | SHAP 설명 |
|---|---|---|
| 무엇을 설명하나 | 지표 규칙 점수를 더한 다중 주기 신호 | 머신러닝 분류 모델(LightGBM)의 방향 예측 |
| 설명의 근거 | 규칙 표 그 자체 | 섀플리 값으로 나눈 특성별 기여도 |
| 더하면 | 종합 점수 | 그 클래스의 모델 원점수 |
| 앱 함수 | `signal_explain.explain` | `xai.explain_signal` |

## 규칙 신호는 어떻게 설명하나요?

다중 주기 신호([9.3](#/p/multi-timeframe-signals))는 60분봉 · 일봉 · 주봉마다 지표 규칙으로 점수를 매기고, 주기 가중치(0.2 · 0.5 · 0.3)로 평균해 종합 점수를 냅니다. 종합 점수가 +1 이상이면 매수, −1 이하면 매도, 그 사이면 관망입니다.

규칙 설명은 이 계산을 거꾸로 펼칩니다. 근거 한 줄의 기여도는 「그 규칙의 점수 × 주기 가중치 ÷ 가중치 합」 이고, 근거 표의 기여도를 모두 더하면 종합 점수가 됩니다(`app/services/signal_explain.py` 의 `evidence`).

```python
"points": rule.points,
"contribution": rule.points * t["weight"] / wsum,
```

정해 둔 식으로 만든 봉 세 묶음을 앱의 점수 함수 · 결합 함수 · 설명 함수에 차례로 넣었습니다.

```output
[A] 규칙 설명
  분봉(60분)  점수 +3 · 근거 ['RSI 59 중립', 'MA5 > MA20 상승 배열', 'MACD > 시그널', '20MA 위 (추세 우호)']
  일봉       점수 -3 · 근거 ['RSI 34 중립', 'MA5 < MA20 하락 배열', 'MACD < 시그널', '20MA 아래 (추세 비우호)']
  주봉       점수 -1 · 근거 ['RSI 30 중립', 'MA5 < MA20 하락 배열', 'MACD > 시그널', '20MA 아래 (추세 비우호)']
  종합 점수 -1.2 · 신호 매도 · 강도 보통
  문장: 일봉 기준으로 5일선이 20일선 아래고 MACD 가 신호선 아래라 매도 쪽입니다. 다만 주봉은 MACD 가 신호선 위입니다.
  신뢰도 풀이: 주기 셋 중 둘이 매도 쪽 · 기운 정도 보통
  근거 표 12줄의 기여도 합 -1.2000 = 종합 점수 -1.2000
```

종합 점수는 (3 × 0.2 − 3 × 0.5 − 1 × 0.3) ÷ 1.0 = −1.2 이고, 근거 표 12줄의 기여도 합도 −1.2 입니다. 설명이 점수를 남김없이 나눴다는 뜻입니다.

문장은 정해 둔 틀을 따릅니다. 「{주기} 기준으로 {가장 크게 민 근거 둘}이라 {신호} 쪽입니다. 다만 {반대 근거 하나}입니다.」 같은 입력이면 늘 같은 문장이 나오므로, 지난 날의 신호를 다시 열어도 설명이 바뀌지 않습니다.

## 설명 문장에 쓰지 않는 말은 무엇인가요?

규칙 설명 함수는 쓰지 않는 낱말을 목록으로 둡니다.

```python
FORBIDDEN = ("AI", "인공지능", "확률", "강력", "반드시", "보장", "추천", "오를 것", "내릴 것")
```

규칙 점수를 더한 결과를 「AI」 라고 부르면 사용자는 학습된 모델이 판단했다고 오해합니다. 「신뢰도」 는 주기들이 같은 방향을 가리키는 정도(방향 일치도)와 점수 크기를 반씩 섞은 값이라 확률이 아닙니다. 그래서 숫자 대신 「주기 셋 중 둘이 매도 쪽」 처럼 말로 풉니다.

## SHAP 은 무엇을 계산하나요?

SHAP(SHapley Additive exPlanations)은 예측 하나를 「기준값 + 특성마다의 기여도」 로 나누는 방법입니다(Lundberg · Lee, 2017). 여러 사람이 함께 낸 성과를 각자의 몫으로 공정하게 나누는 협력 게임 이론의 섀플리 값(Shapley value)을 특성에 적용했습니다. 기준값은 아무 정보가 없을 때 모델이 내는 평균적인 점수이고, 기여도는 그 특성 값 때문에 점수가 얼마나 올라가거나 내려갔는지입니다.

LightGBM 은 `predict(…, pred_contrib=True)` 로 트리 모델용 SHAP(TreeSHAP) 기여도를 바로 돌려줍니다. 매도 · 관망 · 매수 세 클래스를 가르는 모델이면 「특성 수 + 1(기준값)」 길이의 묶음이 클래스마다 붙어 나오므로, 예측한 클래스의 묶음만 잘라 씁니다(`app/services/xai.py` 의 `lgb_contributions`).

```python
contrib = np.asarray(model.predict(np.asarray(x_row, dtype=float).reshape(1, -1), pred_contrib=True))[0]
n_feat = len(feature_names)
block = n_feat + 1
if contrib.size == block:            # 이진/회귀 형태
    seg = contrib
else:                                 # 다중분류: 클래스별 블록
    seg = contrib[predicted_class * block:(predicted_class + 1) * block]
```

특성 셋(RSI · 5일 수익률 · 거래량 비)으로 만든 자료 600줄에 LightGBM 분류기를 학습하고, RSI 24 · 5일 수익률 +3% · 거래량 1.9배인 한 줄을 설명했습니다.

```output
[B] SHAP 기여도 (LightGBM 4.7.0)
  확률(매도 · 관망 · 매수): [0.001, 0.019, 0.98]
  문장: 모델은 '매수' 신호를 98% 확률로 예측했습니다. 이 판단을 가장 강하게 뒷받침한 요인은 RSI(14) 24.0, 과매도 구간(반등 기대) / 5일 수익률 +3.00%, 1주 보합 입니다. 반대로 거래량/20일 평균 1.90배, 거래량 급증 은(는) 이 판단을 약화시켰습니다.
  RSI(14)              24.0  기여도 +2.9003  몫 67.0%
  5일 수익률             +3.00%  기여도 +1.4201  몫 32.8%
  거래량/20일 평균          1.90배  기여도 -0.0098  몫 0.2%
  기여도 합 + 기준값 1.8407 · 그 클래스 원점수 1.8407
```

마지막 줄이 SHAP 의 가법성입니다. 세 기여도와 기준값을 더한 1.8407 이 모델이 매수 클래스에 매긴 원점수와 같습니다. 기여도의 단위는 확률이 아니라 이 원점수입니다. 그래서 「RSI 가 매수 확률을 67% 올렸다」 고 읽으면 틀립니다. 「몫 67.0%」 는 기여도 크기의 비율일 뿐입니다.

## 우리 서비스에서는 어떻게 쓰나요?

- 신호 설명 카드는 `GET /api/explain` 으로 그날 기록해 둔 다중 주기 신호 한 줄을 읽어 문장과 근거 표를 만듭니다(`app/routes/explain.py`). 새로 계산하지 않으므로 지난 날의 신호도 같은 문장으로 설명됩니다.
- 머신러닝 예측 설명은 투자분석 화면의 AI 예측(`investment_research.ai_predict_return`)과 퀀트 파이프라인이 `xai.explain_signal` 을 불러 만듭니다.
- 두 설명은 문장 규칙이 아직 다릅니다. 규칙 설명은 「확률」 을 쓰지 않지만, SHAP 설명 문장은 모델이 낸 확률을 「98% 확률로」 처럼 그대로 씁니다.

## 흔한 실수

1. **기여도를 원인으로 읽기.** SHAP 은 「모델이 그렇게 계산했다」 는 뜻입니다. RSI 가 낮아서 주가가 오른다는 인과를 말하지 않습니다.
2. **기여도를 확률 % 로 읽기.** 기여도는 원점수 단위이고, 확률은 원점수를 소프트맥스로 바꾼 값입니다.
3. **모델이 낸 확률을 실제 확률로 읽기.** 분류 모델의 확률은 보정(calibration)하지 않으면 실제로 그만큼 맞는다는 뜻이 아닙니다. 학습 자료에서 98% 라도 새 자료에서는 훨씬 낮게 맞을 수 있습니다.
4. **규칙 합산을 AI 라고 부르기.** 사용자가 학습된 판단으로 오해합니다.

## 정리

1. 규칙 설명은 근거 표의 기여도를 더하면 종합 점수가 되도록 계산을 펼칩니다.
2. SHAP 은 예측을 기준값 + 특성별 기여도로 나누고, 그 합은 모델 원점수와 같습니다.
3. 기여도는 원인도 확률도 아닙니다. 설명 문장은 그 한계를 함께 적습니다.
