### 1.2 그리는 곳 · 열림 기억 · 접근성

- `navigate()` 가 화면을 바꿀 때마다 `renderViewGuide(viewKey)` 를 부른다(`core.js:629`). 함수(`core.js:341-375`)는 화면의 첫 자식으로 `<div class="view-guide">` 를 끼우고, 단추 한 줄(「사용법 — 요약」 + 꺾쇠)과 본문(단계 `<ol>` · 용어 칩)을 그린다. 모양은 `app.css:585-600`.
- **열림 기억**: `localStorage` 의 `vg_open_<화면키>`(`core.js:341` · `350` · `370`) — 한 번 펼친 화면은 다음에도 펼친 채로 열린다. 지난 결정대로 새 꼴에서는 버린다.
- **접근성 빈칸**: 단추에 `aria-expanded` · `aria-controls` 가 없다(`core.js:353`) — 화면 읽기 프로그램이 펼침 상태를 알 수 없다(확실도 높음).
- **용어 칩**: `termChip(key)`(`core.js:327-331`) → `openTermModal`(`core.js:311-320`) → 용어 카드 `QTerm.open`(`termcard.js:228` · `241`). 카드 모양(오른쪽 서랍 · 가운데 작은 창 · 큰 창)은 사용자가 내 계정 › 화면 설정에서 고른다(`termcard.js:18-23`). 카드 뿌리 `#q-term-root` 는 `body` 의 보통 `div`(`termcard.js:143-157` · `z-index: 9100` `qurious.css:13`)라 **브라우저 맨 위 층(top layer)에 있지 않다** — 3.2 · 3.4절에서 중요해진다.

### 1.3 이 파일은 강사님 파일 — 우리 갈림은 어디

- `core.js` 는 강사님 기초 코드(화면 기준점 `9478811`)를 받아 고친 파일이다. **사용법 블록(`core.js:341-375`)은 강사님 `c84ae2c` 직전 판과 줄 끝을 맞추면 한 글자도 다르지 않다** — 우리가 고친 적이 없다(`diff --strip-trailing-cr` 0 · 확실도 높음).
- 우리 갈림은 다른 곳에 있다 — `VIEW_GUIDES` 글(새 화면 · 고친 안내)과 메뉴 표. 강사님 최신 판을 기준점 `9478811` 에서 3-way 로 받으면 `core.js` 충돌 7곳이 모두 여기다(메뉴 셋 · 사용법 글 둘 · 더보기 둘 — 2.2절).
- 강사님 화면 파일 규칙(강사님 파일엔 갈림 몇 줄만 · 새 기능은 새 파일)을 따르면 새 꼴은 새 파일에 두고 `core.js` 에는 부르는 몇 줄만 남긴다(5절).

function renderViewGuide(viewKey) {

### 5.2 영상 주소를 어디에 두나 — 시연 녹화 · 도움말 결정과 잇기

- **정본**: 화면마다 단계 파일 하나(누를 곳 · 단계 글 · 장 제목 — `docs/help/steps/<화면키>.yaml` 제안 · 아직 없음 · `docs/발표/준비/2026-10-14-시연녹화-도움말.md` 8.5절). 영상 · 자막은 git 에 넣지 않고 HF 비공개 데이터셋에 보관, 앱은 git 무시 폴더 `public/help/media/` 에서 낸다(같은 문서 1절 4 · 6.2절).
- **앱이 읽는 것**: 내려받기 스크립트가 영상 · 자막과 함께 만드는 목록 `public/help/media/index.json`(git 무시) — 꼴(제안):

```json
{ "data-status": { "src": "/help/media/data-status.webm", "captions": "/help/media/data-status.ko.vtt", "duration": "0:45", "recorded": "2026-10-20" } }
```

- `howto.js` 는 처음 열 때 한 번 읽고 기억한다. 파일이 없거나(404) 못 읽으면 「영상 없음」 — 칸을 숨긴다. **지금은 파일이 없으니 70화면 모두 숨김(= 비워 둠)**.
- `VIEW_GUIDES` 에 영상 칸을 넣지 않는 까닭: 강사님 파일의 자료 표가 커지고(다시 찍을 때마다 `core.js` 를 고침 · 충돌 자리), 영상은 git 밖 자료라 그 목록도 git 밖이 맞다.

### 5.6 다른 주담당 화면에 닿나 · 팀 공지

- **닿는다** — 70화면 모두의 맨 위가 바뀐다(접이식 → 윗줄 + 서랍). 안내 글(`VIEW_GUIDES`)은 그대로라 각 화면 파일은 고치지 않는다(일정 화면 `calendar.js` 한 줄만 — 이동원 화면).
- 주담당별 화면 수는 시연 녹화 조사의 점검표 셈을 따른다 — 72화면(메뉴 12 · 따로 쪽 2 포함) 중 이동원 53 · 신장환 8 · 강민석 6 · 오준영 5(`docs/발표/준비/2026-10-14-시연녹화-도움말.md` 1절 5 · 확실도 중간 — 그때 셈).
- **팀 공지: 필요(짧게)** — 사실(모든 화면 맨 위 「사용법」 이 단추 + 오른쪽 서랍으로 · 펼침 기억이 없어짐 · 안내 글은 `core.js` 의 같은 자료) + 각자 화면의 안내 글이 지금 화면과 맞는지 봐 달라는 부탁(고칠지 · 언제 할지는 주담당이 정함 · 예: 자산배분 2단계는 「'배분 계산' 버튼」 이라고 하지만 지금 단추 이름은 「포트폴리오 최적화 실행」) + 영상은 시연 녹화 결정대로 나중에. 대화방 글은 파일로 써서 사용자가 올린다.
- 강사님 최신 판은 화면 안내 글을 여러 곳 다시 썼다(2.2절 충돌 둘) — 팀원이 안내 글을 볼 때 함께 볼 거리다.
