> **이 문서가 답하는 질문**
> 1. 새로 생긴 화면(내 정보 · 강사님 기초 코드로 들어온 다섯 곳 · 금융 강의 · 용어사전)은 무엇이 어디에 있고, 2.0 흐름에 맞추려면 무엇을 바꾸나?
> 2. 주 경로 화면은 휴대폰 폭(390)에서 어떻게 쌓이나?
> 3. 2차 규칙을 검증할 화면(N2)은 어떤 모양으로 시작하나?
> 4. 화면 안의 용어를 누르면 무엇이 어디에 열리고, 사용자는 그 모양을 어떻게 고르나?
> 5. 지난 판에서 그린 12장 중 무엇이 그대로이고 무엇을 다시 봐야 하나?
> 6. 로그인 첫 화면(투자 대시보드)과 위 메뉴 · 전체 메뉴는 어떻게 생겼고, 상태마다 무엇을 보여 주나?
>
> **읽는 순서** — 팀원: 요약 → 10절(첫 화면 · 메뉴가 바뀌었다) → 내 담당 화면의 절(2 ~ 4 · 8 · 9 · 11) → 6절 표 · 화면 담당: 0절 → 2절 · 9절(화면 한 장 명세의 본보기) → 5절 모바일 · 강사님: 요약 → 8절 · 9절 → 4절 N2 · 처음 온 사람: 0절 → 부록 A → 9절

## 요약

1. 저충실도 와이어프레임이다 — 배치 · 순서 · 버튼 위치만 정하고 색 · 글꼴 · 크기는 정하지 않는다. 이 판은 **로그인 첫 화면 「투자 대시보드」(W23)와 위 메뉴 · 전체 메뉴 · 증권사 API 설정의 새 칸**(10절)을 더하고, 지난 판 부록 C 에 사실로 쌓였던 W21 데이터 관제 · W22 일정(11절)과 용어 카드의 연관 개념 칸(9.6절)을 본문으로 옮겼다. 2 ~ 6절은 v0.3 그대로다.
2. 새 화면은 모두 Figma 로 경우를 나눠 설계하고 사용자가 고른 안으로 만든 뒤 브라우저로 보고 그렸다 — 7 ~ 11절의 「지금」 은 제안이 아니라 사실이다. 10절은 강사님 새 기초 코드의 첫 화면을 우리 서비스에 맞춰 받은 것이다(KIS 키는 사용자마다 · 서버 설정 이름을 화면에 내지 않음 · 매매가 0회면 0% 대신 「신호 없음」).
3. 2 ~ 6절의 배치(W13 ~ W18 · N2 · 모바일)는 여전히 D1 ③ · 💬 Q8([IA v1.0](IA_v1.0.md) 10절)이 정해지기 전의 **제안**이다. 용어사전의 남은 조각(교재 밑줄 · 작은 관계 지도)과 금융 강의의 화면 비율 정리는 9.6절 · 부록 C 에 적었다.

## 0. 읽는 법

표 1 은 「와이어프레임의 기호는 무슨 뜻인가」 에 답한다.

**표 1. 기호**

| 기호 | 뜻 | 기호 | 뜻 |
|---|---|---|---|
| `[ 버튼 ]` | 누르는 것 | `( 입력 )` | 적는 칸 |
| `(선택 ▾)` | 고르는 칸 | `▓▓▓` | 차트 · 그림 자리 |
| `●━━○━━○` | 단계 표시(● 지금) | `⚠` · `ⓘ` | 경고 · 안내 |
| `┆ … ┆` | 접혀 있는 영역 | `☰` | 메뉴 열기 |

## 1. 공통 틀 — 머리글 사용자 메뉴

공통 틀(데스크톱 W0 · 모바일 W0-m)은 [와이어프레임 v0.2](와이어프레임_v0.2.md) 1절 그대로다. v0.3 에서 바뀐 곳은 머리글 오른쪽의 사용자 영역이고, 이 판에서 머리글 왼쪽의 서비스 이름과 바닥글이 바뀌었다(7절).

그림 1 은 「머리글 오른쪽의 이름 · 로그아웃 · 더보기는 지금 어떻고, 무엇으로 바꾸자고 하나」 에 답한다.

**그림 1. 머리글 오른쪽 — 지금 · 추가 작업 · 제안**

```text
지금 (92087da)
 (시세 띠) (● 동기화) [U] 홍길동  [로그아웃]  [⋮]
   · 이름 · 아바타는 눌러도 반응이 없다
   · ☰ 버튼은 코드에 있지만 늘 숨어 있다 (I12)

2026-09-30 추가 (PR #75 · 지금)
 (시세 띠) (● 동기화) [홍] 홍길동  [로그아웃]  [⋮]
                      └ 누르면 W13 내 정보
   [⋮] 더보기 → 금융 지식 · 시스템 · 내 계정

제안 (2.0)
 (시세 띠*) (홍 ▾)
            ├ 내 정보
            └ 로그아웃
   * 1440 미만에서 숨긴다 · 모바일도 같은 자리
```

제안은 이름 · 로그아웃을 사용자 메뉴 하나로 모아, 데스크톱과 모바일이 같은 자리에서 내 정보와 로그아웃을 찾게 하는 것이다.

**표 3. 머리글 — 바뀌는 것** · 재사용 ✅ 글자 · 위치만 / 🟡 작은 수정 / 🔴 새 부품

### 3.2 W15 위험 한도 — W10 에 모으는 안

**지금** 🟢 코드 — 한도 입력 4칸(일손실 한도 · 종목당 최대 비중 · 하루 최대 주문 · 중복 주문 쿨다운 — 기본값 3% · 30% · 20건 · 30분)은 W5 연결 설정 안에 있고, 상태 5칸과 「🛑 비상 정지」 · 「해제」 는 `quant-auto`(동결 제안)에만 있다. 주 경로 자동매매 화면 W10 에는 둘 다 없다(I16).

```text
서랍 (기본)                          작은 창 · 큰 창
 보던 화면          │ 용어 ✕          ░░░░░░░░░░░░░░░░░░░░░░░░
 (그대로 보인다)    │ [← 이전 용어]   ░░ ┌ 용어 ─────── ✕ ░░
                    │ 샤프 비율       ░░ │ (같은 카드)     ░░
                    │ (카드)          ░░ └───────────── ░░
                    │ [용어사전에서   ░░░░░░░░░░░░░░░░░░░░░░░░
                    │  자세히 →]      작은 창 = 짧은 풀이
 오른쪽에서 밀려 나온다 · 폭 420     큰 창 = 긴 풀이 · 그림을 넓게
 (표 · 그림이 든 풀이는 560)          (화면 폭 · 높이를 넘지 않는다)
```

모든 모양이 Esc · ✕ 로 닫히고, 창 · 시트는 흐린 바깥을 눌러도 닫힌다(서랍은 뒤 화면을 흐리게 하지 않는다). 풀이에 표 · 그림 · 수식이 있거나 글이 길면 서랍은 넓은 서랍으로, 작은 창은 큰 창 크기로 저절로 넓어진다(결정 ②). 창은 강사님 「기능 완성도」 배지보다 위에 뜬다 — 처음에는 배지가 서랍을 가렸다.

## 부록 B. 만든 방법

### B.1 다시 만드는 법

- 화면 목록 — `env -u PYTHONIOENCODING PYTHONUTF8=1 python scripts/view_scan.py --md` 로 화면 ID · 선언 위치를 뽑는다([IA v1.0](IA_v1.0.md) 부록 B).
- 「지금」 배치 — 각 화면의 선언 블록(`public/app.html` 의 `data-view`)과 그 화면을 그리는 `public/js/` 파일을 읽어 칸 순서를 옮긴다. 7 ~ 9절은 `brand.js` · `finlearn.js` · `glossary.js` · `termcard.js` · `mypage.js` · `css/qurious.css` 를 읽고, 만든 날 브라우저(Playwright · 1440 × 900 · 390 × 844)로 본 모습과 맞췄다. 찾기 결과의 예(「per」 8개)는 로컬 앱의 `GET /api/glossary?q=per` 응답이다.
- 그림 폭 — 코드 블록의 줄마다 표시 폭(한글 2칸)을 세어 70 이하인지 본다. 이 판은 짧은 파이썬 검사로 모든 그림이 70 이하인 것을 확인했다.
- Mermaid — 그림 4 · 5 · 8 은 로컬 Mermaid CLI 로 그려 문법 오류가 없는 것을 확인했다(v0.3). v0.4 는 Edge 머리 없는 실행으로 `mermaid.parse()` 를 다시 돌렸다.
- 10절 — 강사님 새 판은 강사님 화면 파일을 우리 서버 API 에 붙여(로컬 중계 · 같은 점검 계정) 찍고, 만든 화면은 Playwright 로 1280 · 1440 · 1600 · 1920 · 390 폭에서 단추 · 탭 · 바로가기를 하나씩 눌러 봤다. 그림 24 ~ 26 은 그 화면을 옮겨 그렸다.

### B.2 한계

- 2 ~ 6절의 「지금」 은 모두 코드 읽기다 — 새 화면 6장 · 모바일 3장은 브라우저로 보지 않았다. 지금 모바일에서는 메뉴가 열리지 않으므로(I12) 모바일 그림은 전부 제안이다. 7 ~ 9절만 만든 뒤 브라우저로 봤다.
