# 회의 · 팀 소통 기록

> 팀원에게 알리거나 물은 글(Discord 공지 · 제안 · 요청)과 **일일 스크럼 · 퇴근 전 보고 기록**을 두는 곳이다.
> 2026-09-28 S57 에 만들었다. 그 전에는 저장소 밖(`team_project/_discord/`)에 두었는데, 밖에 둘 이유가 없어
> 여기로 옮겼다(사용자 결정). 산출물 10구분의 **3. 일정·업무 관리**(일일 보고 기록)에 해당한다.

## 1. 무엇을 두나

| 종류 | 파일 이름 | 누가 · 언제 |
|---|---|---|
| 팀에 올린 글 (공지 · 제안 · 의견 요청) | `YYYY-MM-DD-주제.md` | 쓴 사람이 Discord 에 올리기 **전에** 만든다 |
| 일일 기록 (09:00 스크럼 · 17:30 보고) | `일일/YYYY-MM-DD.md` | [양식](양식-일일-스크럼-보고.md) — ⏳ **팀 논의 중(제안)** |
| 회의록 (정해진 것이 있는 회의) | `YYYY-MM-DD-회의-주제.md` | 회의 뒤 기록자 |
| 주간보고 | `주간보고/<주 첫날>주_주간보고.md` | 이동원 초안 · 각 주담당이 자기 줄 · 매주 금요일 |
| 옮겨 온 대화방 글 | `대화방/YYYY-MM-DD-주제.txt` | 2026-10-16 개인 초안 폴더 정리 때 옮김(보낸 그대로) |

## 2. 규칙

- **저장소가 공개(Public)다.** 연락처 · 계정 · 초대 링크 · 토큰은 쓰지 않는다. 팀원의 말은 **요지만** 옮기고,
  이름은 이미 공개 문서(역할 분배안)에 있는 수준(이름 · 파트)까지만 쓴다.
- **Discord 형식** — 메시지 하나가 **2,000자**를 넘으면 `--- 메시지 2 ---` 로 끊는다. Discord 는 **표를 그리지 않으므로**
  올리는 글은 목록으로 쓴다. 긴 근거는 저장소 문서에 두고 글에는 요약과 링크만 둔다.
- 글 파일은 **올린 그대로** 둔다. 나중에 고칠 것이 생기면 새 파일로 쓰고 옛 파일은 지우지 않는다(판 관리와 같은 뜻).
- 답글 · 의견은 Discord 에서 받고, 결정에 쓰인 것은 해당 문서(결정 대장 등)에 옮긴다.
- 올리기(PR)는 **몰아서** — 일일 기록은 주 1회 한 PR 로 묶는다(GitHub 쓰기를 줄인다 · 계정 보호).
