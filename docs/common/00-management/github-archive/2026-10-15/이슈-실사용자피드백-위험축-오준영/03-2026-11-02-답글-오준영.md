답이 없던 항목까지 제 담당 결정을 정리했습니다. [PR #479](https://github.com/EST-team-project/Qurious/pull/479)의 작업 계획 §29에 같은 내용을 기록했습니다.

1. **스크리닝 경계:** #373의 기존 스크리닝/신호 기록 순위 탭 분리에 동의합니다. 기록된 점수 정렬을 팩터·재무·기술·복합 스크리닝 요구 전체의 구현으로 보지는 않습니다. 새 축별 등급/종합 산식은 이번에 추가하지 않습니다.
2. **위험 축:** #351의 `ATR(14)/확정 종가`·‘평균 진폭 ATR(14)’는 퀀트 대시보드 참고값입니다. 주문 손절/계좌 일손실과 구분하고 순위·배분 전체로 확대하지 않습니다.
3. **깨짐/관문:** 주문을 막은 위험 관문 사유를 먼저, 분석 조건 변화는 따로 보이는 방향입니다. 차단을 자동 매도 권고로 바꾸지 않습니다. 개인 근거 일지는 미구현이며 시스템 가상 일지와 구분합니다.
4. **주기:** 일별 분석은 확정 봉 갱신 뒤, 위험 검사는 전송 직전, 리밸런싱은 저장된 시간/이탈/현금흐름 정책으로 구분합니다.
5. **담기:** 이번 PR에 **종목 허브→리밸런싱 목표 입력** 연결을 구현했습니다. 6자리 코드만 넘기고 비중은 비웁니다. 사용자가 비중 입력·추가·저장을 확인합니다. 여러 후보로 최적화 유니버스를 자동 교체하는 기능까지 포함하지 않습니다.
6. **작은 차트/관련 종목:** 이번에는 미채택. 기존 차트/근거 화면 연결을 사용합니다.
7. **관심 종목:** 보유/목표와 별도 목록이어야 한다는 구조에는 동의합니다. 사용자별 서버 관심 목록은 이번 미채택·미구현이며 비교 목록을 보유로 해석하지 않습니다.
8. **섹터:** 종목 비중 상한을 섹터 한도로 부르지 않습니다. 기존 테마 플랜을 보존하고 새 섹터 한도는 이번에 추가하지 않습니다.

제 담당 답변이며 다른 담당의 일정/팀 전체 합의를 대신하지 않습니다. 선택 제안을 미구현 오류로 일괄 집계하지 않고 채택 여부를 위와 같이 명시해 정리하는 데 동의합니다.
