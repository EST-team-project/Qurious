@janghwan-god 님, C2 의견 확인했습니다. 제시하신 가격·ATR을 입력해 `risk_quantity`를 다시 실행했고, 예산 100만 원에서는 두 방식 모두 3주, 예산 1,000만 원에서는 손절 1%가 10주·ATR × 2가 4주라는 결과를 확인했습니다.

**제안하신 방향에 대체로 동의하며, 다음 안으로 보완하고 싶습니다. 아직 추가 구현에 착수한 것은 아니고, 이 답글에 의견을 주시면 확인한 뒤 진행하겠습니다.**

1. **입력 계약과 기존 상한은 유지합니다.** `size_kind = risk_pct | fixed_budget`, `risk_pct`의 % 단위, QUANT 가상 자산 기준, 첫 진입만 허용하는 정책을 유지하겠습니다. 위험 금액은 반드시 채워 쓰는 예산이 아니라 상한이므로, 현금·1회 예산·종목 비중이 먼저 걸리면 더 작은 수량을 선택하는 현재 동작이 맞다고 봅니다. 위험 모드를 켰다는 이유로 1회 예산을 우회하지 않겠습니다.
2. **수량을 결정한 제한을 표시합니다.** 위험·현금·1회 예산·종목 비중 중 무엇이 수량을 제한했는지 계산 결과와 화면에 남겨, 고정 금액 방식과 수량이 같아진 이유를 설명하겠습니다.
3. **진입 당시 손절 기준 저장을 우선하겠습니다.** 현재 보유분에도 변경된 설정이 적용되는 점은 보완이 필요합니다. 진입 당시 기준 가격·손절 종류/설정·손절선을 보존하고, 이후 설정 변경이 기존 보유분에 소급되지 않도록 하는 안입니다. 저장 기준이 없는 기존 보유분은 진입 당시 값을 복원할 수 있다고 가정하지 않고, 적용·전환 규칙을 별도로 명시하겠습니다. 설정 저장뿐 아니라 보유 중 손절 판정도 같은 저장 기준을 읽도록 맞추겠습니다.
4. **ATR 손절은 선택지로 추가하는 안에 동의합니다.** `stop_kind = pct | atr`와 공통 `ta_utils.atr`의 Wilder 14일 기준을 사용하고, ATR 배수는 2를 초기 제안값으로 두겠습니다. 다만 기존 설정의 의미가 바뀌지 않도록 기존 사용자의 % 손절은 유지하고, ATR 선택 시 적용하는 방향을 제안합니다. 신규 위험 모드의 기본값까지 ATR로 바꿀지는 이번 의견을 받은 뒤 정하겠습니다. ATR 계산에 필요한 자료가 없으면 다른 손절 방식으로 조용히 대체하지 않고 해당 진입을 보류하는 쪽이 맞다고 봅니다.

손절선을 고정하거나 ATR을 쓰더라도 갭·슬리피지·미체결 때문에 실제 손실이 계좌 1% 안으로 보장되는 것은 아니라는 안내는 유지하겠습니다.

별도로, 앞서 보고된 **동일 종목 미확정 주문 보류 정책과 기존 시험의 충돌은 수정·검증 후 브랜치에 올렸습니다.** 커밋 [`9e43aa9`](https://github.com/EST-team-project/Qurious/commit/9e43aa9)이며, 테스트와 정책 설명 주석만 변경해 실제 주문·리밸런싱 동작은 바꾸지 않았습니다. 관련 시험 161건 통과, 전체 시험은 1,748건 통과·11건 건너뜀·4건 실패였고, 4건은 수정 전 main에서도 동일하게 재현한 Yahoo 참조 검사·차트 API 시험 문제입니다. 이 수정은 아직 main 병합 전이며, 위 손절 기능 보완과는 별개입니다.

위 안, 특히 **1회 예산 유지·기존 보유분 전환·ATR 선택 방식**에 대한 답글을 확인한 뒤 추가 구현과 시험을 진행하겠습니다.
