#170에서 말씀드린 배분→리밸런싱 연결을 구현하고 시험했습니다. 아래 방식으로 먼저 만들었는데, 담당 화면과 연결해도 괜찮을지 의견 부탁드립니다. 팀 합의가 끝난 정책이나 운영 적용 완료로 간주하지는 않았습니다.

구현: [작업 브랜치](https://github.com/EST-team-project/Qurious/tree/feat/allocation-rebalance-handoff) · [변경 비교](https://github.com/EST-team-project/Qurious/compare/main...feat/allocation-rebalance-handoff) · 커밋 `36e89a1`
설계·API·검증 기록: 브랜치의 `docs/설계/배분-리밸런싱-연결.md`

## 구현한 내용

1. **음수 비중 수정·공통 함수**: 장기 보정을 기존 현금·채권 비중 안에서만 적용합니다. 성향 3개 × 기간 1~10년 모두 합계 100%, 음수 없음입니다. 기존 정상 결과는 유지하고, 공격형 10년은 국내주식/해외주식/채권/대체/현금 = **47/37/8/8/0**으로 수정했습니다.
2. **#168 가벼운 비중 조회**: `GET /api/ml/robo/weights?risk_profile=moderate&horizon_years=3`. 기존 자산군 키 5개를 유지합니다. 로그인은 필요하며 시세 스캔·AI 학습·DB 계산을 하지 않습니다. 상품 안내 화면도 이 API를 사용하도록 연결했습니다. 공통 함수는 `app.services.asset_allocation.asset_allocation`입니다.
3. **배분 결과 저장**: 기존 계산 POST 완료 시 사용자별 최신 결과 한 건을 저장합니다. `GET /api/ml/robo/allocation/latest`와 ‘저장한 배분 보기’로 다시 읽습니다. 다른 계정의 결과는 읽지 않으며 실패한 계산은 이전 저장본을 유지합니다.
4. **리밸런싱 가져오기**: 저장 시각·종목별 목표·미적용 자산군·현금 비중을 확인받고 편집안에 채웁니다. 편집안의 자동 실행은 끄고, 사용자가 ‘플랜 저장’을 눌러야 기존 플랜에 반영합니다. 저장/가져오기 자체로 주문하지 않습니다. 저장 전에는 서버의 기존 플랜·예약이 유지된다는 점도 화면에 안내합니다.

## 이렇게 결정했는데 어떠신가요?

**A. 현재는 국내주식 부분만 가져오기**

현재 최적화 후보가 국내주식이므로, 해외주식 비중까지 국내 종목에 합치던 계산은 수정했습니다. 예를 들어 중립형 3년의 원래 자산군 결과 **30/25/30/10/5**는 보존하되, 실제 리밸런싱 목표는 **국내주식 30%·현금 70%**입니다. 해외주식 25%·채권 30%·대체자산 10%는 아직 매수하지 않는다고 명시하고 동의받습니다. 종목 비중은 소수 둘째 자리까지 합계를 맞춥니다.

추천 종목 표시와 예상 성과의 기준도 이 국내주식 부분에 맞췄습니다. 성과 화면에는 나머지를 현금으로 보고 연 2.5%를 가정한다는 점을 표시했습니다. 완전한 5자산군 성과라고 표시하지 않습니다. 기존 ‘플랜 외 종목 보호’ 설정에 따라 관리 대상 밖 보유 종목은 비중 계산에서 제외됩니다.

→ **이번 통합은 이 부분 적용으로 진행하고, 해외주식·채권·대체자산의 국내 상장 ETF 매핑은 후속으로 분리해도 괜찮을까요?**

**B. 최신 결과 한 건 저장 + 확인 후 수동 저장**

배분 계산 때마다 본인의 최신 결과만 갱신하며, 리밸런싱 연결 시 자동 실행을 켜지 않습니다. 여러 전략의 저장 이력과 비교는 이번 범위에 넣지 않았습니다.

→ **우선 이 흐름으로 연결하고, 전략별 복수 저장은 필요성이 확인되면 확장하는 방향이 괜찮을까요?**

**C. 상품 안내의 공통 비중 계약**

상품 안내는 기존과 같은 성향·3년 기준으로 경량 GET을 호출합니다. 비중표를 별도로 복제하지 않습니다.

→ **#168 담당 쪽에서도 이 함수·API와 키 이름으로 사용해도 괜찮을까요?** 기간 선택을 공유해야 한다면 후속 계약으로 맞추겠습니다.
