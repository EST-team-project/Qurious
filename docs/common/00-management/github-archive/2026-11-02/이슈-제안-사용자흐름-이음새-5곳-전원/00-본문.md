# [제안] 기능은 다 있는데 이어지지 않는다 — 사용자 흐름 한 줄을 11-05 전에 끝까지 통과시키기(이음새 5곳)

@신장환 @오준영 @강민석 — 새 기능을 더 만들자는 제안이 아닙니다. 각자 맡은 기능이 거의 다 구현됐는데, **화면 사이가 이어지지 않아** 사용자가 쓰기에는 애매한 느낌이 있어서 **이음새만 맞추는 일**을 같이 하자는 제안입니다. 읽고 답할 것은 아래 5절뿐입니다.

## 1. 왜 — 기능은 화면 단위, 사용자는 흐름 단위

사용자는 「종목을 찾고 → 왜 그런지 보고 → 위험을 확인하고 → 주문하고 → 체결을 확인하고 → 나중에 잘했는지 본다」 를 한 번에 씁니다. 지금은 이 흐름의 **화면마다는** 있는데, 화면에서 다음 화면으로 **넘어가는 길**이 없거나 짧습니다. 실제 투자 서비스의 가치(상품성)는 이 연결에서 나온다고 봅니다.

## 2. 코드로 확인한 끊김(2026-11-02 이동원이 읽은 것)

- **종목이 화면 사이를 못 건넙니다.** 종목 서랍을 여는 입구는 AI 투자 상담 카드와 투자 정보 리서치 종목 칩 **두 곳뿐**입니다. 신호 화면(`public/js/signal-rank.js` · `quant.js`)과 모의주문 화면(`paper.js`)에는 다른 화면으로 종목을 넘기는 `navigate` 호출이 없어서, 신호를 보고 근거나 주문으로 가려면 종목 코드를 다시 입력해야 합니다.
- **체결 알림이 한 길에서만 납니다.** 체결(`notify_order_filled`) · 위험 건너뜀(`notify_risk_skip`) 알림은 `app/services/auto_trade.py` 에서만 부릅니다. 수동 모의주문(`app/services/paper_trading.py` · `app/routes/paper.py`)과 KIS 실행(`app/services/kis_execution.py`)에는 알림 호출이 없어서, 모의로 주문해도 체결 알림이 오지 않습니다.
- 확인하지 못한 것: 주문 화면 쪽에서 다른 길(`trading.js` 등)로 알림을 부르는지는 제가 다 읽지 못했습니다 — 틀렸다면 알려 주세요.

## 3. 제안 — 시나리오 한 줄을 끝까지 통과시키기

**시나리오**: 신호 화면에서 종목을 보고 → 「근거」 를 눌러 서랍(기준일 · 출처 · 까닭)을 열고 → 「모의주문」 을 눌러 종목과 위험 기준 수량이 채워진 주문 화면으로 가서 → 주문하면 → 체결 알림이 오고 → 일지 · 대사 화면에 같은 건이 남는다.

**통과 기준**: ① 사람이 한 번 끊김 없이 눌러서 끝까지 간다 ② 이 한 줄을 지키는 시험(E2E) 한 건. 11-05 전까지.
