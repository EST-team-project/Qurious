# [안내] 알림 채널 보안 점검 — 슬랙 · 메일 서버 주소 검사 · 설정 없는 사용자의 개인 알림은 공용 채널로 안 감 · 텔레그램 · SMS · 카카오 당분간 안 씀

@신장환 @오준영 @강민석 — 이동원 몫 알림 쪽 변경이라 알립니다. 읽고 할 일은 아래 3절뿐입니다.

## 1. 무엇이 바뀌었나

알림 코드를 `feature-dev:code-reviewer` 로 보안 위주로 읽혔고, 나온 결함 5건 가운데 코드에서 직접 확인한 것을 고쳤습니다.

- **슬랙 웹훅 주소** — 사용자가 넣은 주소를 서버가 대신 부르는데 검사가 없었습니다(내부망 주소도 저장되어 요청이 나갈 수 있었음). 이제 `https://hooks.slack.com/…` 모양만 받습니다(저장 422 + 보내기 직전 다시 검사). 조회 응답에서는 디스코드처럼 `****` 로 가려집니다.
- **사용자가 정한 메일 서버** — 서버 이름 모양(`smtp.example.com`) · 포트(25 · 587 · 2525) · 이름이 가리키는 모든 IP 가 공인 주소인지 검사합니다(저장 422 + 보내기 직전). 사용자가 서버를 적으면 서비스(`.env`) SMTP 아이디 · 비밀번호를 **섞지 않고**(예전엔 계정 칸이 비면 서비스 계정으로 그 서버에 로그인했음) 인증서도 검증합니다.
- **알림 설정이 없거나 읽지 못한 사용자** — 이 사용자의 개인 알림(체결 · 예수금 부족 등)은 `.env` 공용 채널로 보내지 않습니다(예전엔 「사용자 없는 운영 알림」 과 같은 빈 설정으로 읽혀 팀 채널로 샜음). 이력에는 「채널 없음」(`no_channels`)으로 남습니다. 사용자 없는 운영 알림(수집 보고 등)은 그대로 기본 채널입니다.
- **텔레그램 · SMS · 카카오톡은 당분간 쓰지 않습니다**(텔레그램 유료화로 한국에서 시험이 어려움 · SMS · 카카오는 비용 · API 발급 절차를 조사한 뒤 개발 여부 결정). 코드는 지우지 않았고, 이 채널들의 폴백 · `/test` 호출 제한 문제는 채널을 다시 켜기 전에 고칩니다.
- API 명세서 v0.58 · UI 명세서 v0.42 · 결정 대장 v1.19 에 반영했습니다.

## 2. 팀원 코드에 닿는 곳

- 사용자 알림을 `notification.dispatch(...)` / `dispatch_event(ev, user_id=…)` 로 보내는 호출부는 **그대로 쓰면 됩니다**(인자 · 반환 변화 없음). 알림 설정을 저장하지 않은 사용자는 이제 알림을 받지 못하는 것이 정상입니다 — 화면에서 「알림이 안 온다」 로 보이면 알림 설정부터 확인해 주세요.
- 시험에서 `notification._load_user_settings` 를 가짜로 바꾼다면: `{}` 는 「사용자 없는 운영 알림」, `notification.NO_SETTINGS`(`{"_no_settings": True}`)는 「사용자는 있는데 설정이 없음」 입니다.
- 시험에서 슬랙 주소를 넣는 가짜 값은 `https://hooks.slack.com/services/T/B/x` 같은 모양으로 쓰세요(`http://x.invalid` 는 이제 보내기 전에 막힙니다 — 이동원 시험 세 파일은 이미 고쳤습니다).

## 3. 팀원이 할 일

1. `git pull` 뒤 별도 조치는 없습니다(마이그레이션 없음).
2. 위 2절의 가짜 슬랙 주소를 쓰는 자기 시험이 있으면 모양만 바꿔 주세요.
3. 알림이 안 간다는 사용자를 보면 알림 설정 저장 여부를 먼저 확인해 주세요.
