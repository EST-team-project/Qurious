## 확인 · 부탁드릴 것

1. **`signal_explain.load_day` 의 읽는 양.** `symbols` 없이 부르면 종목마다 최신 한 줄을 ORM 으로 전부 읽은 뒤 파이썬에서 `limit` 로 자릅니다. 줄이 401 → 3,950 이 되어 한 번에 약 7 MB(JSONB 포함)를 읽습니다. DB 쪽 질의는 30 ms 였고 앱 쪽 비용은 아직 재지 않았습니다. 순위 화면이 붙으면 매 요청이라 `limit` 를 SQL 로 내리는 방법(상위 N 만)이 필요할 수 있습니다 — 고쳐 주실지, 이동원이 서버 읽기 쪽을 손대도 되는지 알려 주세요.
2. **`not_universe` 의 뜻.** `signal_explain._universe()` 는 지금도 분봉 유니버스(401)입니다. 기록 대상이 넓어져 「기록이 없는 종목」 대부분은 이제 `none`(아직 기록 전 · KONEX 등)이 맞습니다. 허브 쪽 안내 문장은 제가 고쳤습니다(`stock_hub.SIGNAL_NOT_UNIVERSE`). `_universe()` 를 그대로 둬도 되는지 확인 부탁드립니다.
3. 그림자 일지 · `signals_yahoo.py` 는 신호 기록을 읽지 않거나 따로 쓰는 길이라 영향이 없다고 봤습니다(`grep` 확인). 다르게 읽는 곳이 있으면 알려 주세요.

## 되돌리는 법

러너 `Step("signals_all", …)` 한 줄을 지우면 이전과 같습니다. 쓴 줄은 `DELETE FROM signal_snapshots WHERE symbol NOT IN (분봉 유니버스)` 로 지웁니다(표 구조 변경 없음).
