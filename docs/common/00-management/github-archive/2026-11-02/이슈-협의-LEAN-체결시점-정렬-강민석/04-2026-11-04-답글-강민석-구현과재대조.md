## 구현 및 11월 4일 재대조 결과 공유

이동원 님, 협의했던 범위로 구현한 뒤 11월 4일 Docker 재실행까지 완료했습니다. 기존에 발생했던 신호·보유 상태·주문·체결가 불일치가 해소된 것을 확인했습니다.

### 1. 질문별 진행 결과

| 항목 | 적용 및 검증 결과 |
|---|---|
| 1. 15:29 배치 의도 | 당일 종가 체결을 명시적으로 의도한 것은 아닙니다. 15:29는 일봉 커스텀 데이터에 부여한 시각이며, 실제 체결 시점은 LEAN 엔진의 일봉 해상도 및 주문 변환 규칙에 맡겨져 있었습니다. |
| 2. `fill_timing="next_open"` | 적용 완료. 기본값 `default`는 유지하고 대사 스크립트에서만 `next_open`을 명시적으로 선택합니다. |
| 3. Collector DB 전환 | 대사 모드에 적용 완료. 신호는 수정종가, 수량 산정 및 평가는 원주가 종가, 체결은 다음 거래일 원주가 시가를 사용합니다. Collector 데이터 누락 시 Yahoo로 대체하지 않고 실패 처리하도록 했습니다. |
| 4. 매수 여유분 0.95 | 아직 적용하지 않았습니다. 이번 검증은 기존 기준인 1.00으로 진행했습니다. 0.95 비교는 별도 실험으로 남겨두며, 검증 전 기본값이나 전략 비중을 변경하지 않겠습니다. |
| 5. 매도 비율 0.5 | 매도 비율 0.5를 적용한 재계산에서 6→3→2→1→1주 패턴이 재현됐습니다. 원본 일지 주문 행까지 확인하기 전에는 원인을 확정했다고 표현하지 않겠습니다. |
| 6. 원격 서버 및 화면 표기 | 이번 검증은 로컬 Docker 기준입니다. 원격 `domain-rag-lab`의 날짜·시간 규칙은 아직 확인하지 못했습니다. 화면의 신호 기준일·체결일·체결 기준 가격·시간대·가격 출처 표기도 후속 작업으로 남깁니다. |

### 3. 구현 방식

기존 화면 실행과 대사 실행은 분리했습니다.

- 기본 `fill_timing="default"` 경로는 기존 Yahoo Finance 데이터와 주문 방식을 유지합니다.
- `daily_lean_reconcile.py`에서만 `fill_timing="next_open"`을 사용합니다.
- 대사 모드에서는 Collector DB의 수정종가와 원주가 데이터를 구분해 사용합니다.
- 다음 거래일 시가 체결을 위해 MOO 주문과 사용자 정의 체결 모델을 적용했습니다.
- 결과 JSON에 `fill_timing`, `price_source`를 기록합니다.

이번 결과는 신호·주문·체결 재현성 검증이며, 누적 수익률이나 위험지표 검증을 의미하지는 않습니다.
