# #497 검토 의견 및 회신

이슈 #497의 재계산 결과를 확인했습니다. 방향은 **기존 화면 동작은 유지하면서, 대사 전용 실행 모드에서만 일지와 동일한 가격·체결 규칙을 명시적으로 적용**하는 것으로 정리하겠습니다.

## 질문별 답변

1. **15:29 배치의 의도**  
   당일 종가 체결을 명시적으로 의도한 것은 아닙니다. 현재 코드에서 15:29는 일봉 커스텀 데이터에 부여한 시각이고, 시장가 주문의 실제 체결 시점은 LEAN의 일봉 해상도 및 장 마감까지 남은 시간에 따른 엔진 변환에 맡겨져 있습니다. 따라서 기존 결과를 당일 종가 체결이라고 해석하면 안 됩니다. 보고서에는 실제 엔진 체결 규칙을 구분해 적어야 합니다.

2. **`fill_timing="next_open"` 선택 모드**  
   승인합니다. 단, 기본값과 기존 화면 결과는 바꾸지 않고 `daily_lean_reconcile.py`에서만 명시적으로 선택하도록 해 주세요. 주문 생성일과 체결일을 분리하고, 다음 거래일 시가 체결 여부를 결과 이벤트에서 확인할 수 있어야 합니다. 기본값은 현재 동작을 유지해야 합니다.

3. **대사용 입력 데이터의 Collector DB 전환**  
   대사 모드에 한해 승인합니다. 신호 계산은 Collector 수정종가, 주문 수량 산정 및 장부 평가는 원주가 종가, 체결은 다음 거래일 원주가 시가를 사용해야 합니다. Collector 데이터가 없거나 누락된 경우 Yahoo로 조용히 대체하지 말고 대사를 실패 처리해 주세요. 기본 화면 경로의 데이터 소스까지 일괄 변경하는 것은 이번 승인 범위에 포함하지 않습니다. 보고서의 가격 데이터 항목도 대사 모드 기준으로 명시하면 됩니다.

4. **진입 여유분 0.95 적용**  
   대사 실행의 별도 매수 여유분으로 시험하는 것은 동의합니다. 다만 전략의 목표 비중이나 기존 종목별 30% 상한을 변경하는 방식은 안 됩니다. 실제 다음 거래일 시가와 슬리피지·수수료를 반영해 주문 가능 수량을 정수로 계산하고, 1.00과 0.95의 주문 거절 및 미투자 차이를 비교해 주세요. 검증 전에는 기본값으로 반영하지 않습니다.

5. **보고서 3.2절 매도 비율 설명**  
   수정 제안에 동의합니다. 다만 일지의 원본 주문 행을 직접 확인하지 않은 재계산이라면 원인을 확정했다고 쓰지 말고, “매도 비율 0.5를 적용한 재계산에서 6→3→2→1→1주 패턴이 재현됐다”고 표현해 주세요. 원본 일지 주문 수량까지 확인한 뒤에만 “원인 확인”으로 격상할 수 있습니다.

6. **원격 `domain-rag-lab`의 날짜·시간 규칙 및 화면 표기**  
   현재 확인된 로컬 `Qurious` 코드만으로 원격 서버가 자정 시각, `end_time`, 종료일 +1일 규칙을 쓰는지는 확인할 수 없습니다. 원격 서버의 실제 실행 코드와 설정을 확인한 뒤 답을 확정하겠습니다. 화면에는 엔진 이름만 표시하지 말고 최소한 신호 기준일, 체결일, 체결 기준 가격(시가/종가), 시간대, 가격 데이터 출처를 표시하는 것이 맞습니다.
