# [협의] LEAN 체결 시점을 그림자 일지와 맞추기 — 6가지 질문

@rkdalstjr 강민석 님, #497 보고서 잘 읽었습니다. 보고서의 체결가 차이와 불일치 날짜를 수집 DB 값으로 다시 계산해 보니 원인이 둘로 갈렸습니다. 코드는 바꾸지 않았고, 아래 여섯 가지에 의견을 듣고 싶습니다.

## 먼저, 확인한 것

| 항목 | 내용 | 확인 방법 |
|---|---|---|
| 체결가 차이 223.46bp(09-30 매수) · 440.84bp(10-23 매도) | **체결 시각의 값이 다르기 때문**입니다. 일지는 다음 거래일 **원주가 시가** × (1 ± 10bp), LEAN 은 입력이 하루 한 값(15:29)뿐이라 같은 날 **종가** × (1 ± 10bp) 로 체결됩니다. 슬리피지 10bp 는 양쪽에서 지워집니다 | 수집 DB `price_daily` 삼성전자 09-30 시가 274,500 · 종가 268,500 / 10-23 시가 206,000 · 종가 215,500 으로 보고서 3.4절 체결가를 정확히 재현 |
| LEAN 의 체결 날 | 신호 **다음 거래일(D+1)** 입니다. 15:29 시장가가 엔진 규칙으로 MarketOnOpen 으로 바뀝니다(LEAN 로그 `Warning: market orders on daily resolution data ... converted into MarketOnClose orders (or MarketOnOpen near the close)`). 입력에 시가 줄이 없어 D+1 종가가 됩니다 | `data/lean-workflows/daily_replay_2026-10-30.json` |
| 09-29 증거금 부족 | 09-28 종가로 수량(36.93791주)을 세고 09-29 값(272,500)으로 평가하면 10,065,580 → 수수료 포함 10,067,361. 로그의 필요 증거금과 4원 차이로 재현됩니다. #433 과 같은 꼴입니다 | 계산 |
| 나머지 네 날(10-23 · 10-26 · 10-27 · 10-28) | 체결 시점이 아니라 **일지의 매도 비율 0.5**(`app/models/trading.py` `quant_sell_ratio` 기본값)로 보입니다. 일지 규칙을 DB 값으로 재계산하면 6→3→2→1→1주로 나눠 팔고 10-29 에 모두 파는데, LEAN 은 10-23 에 한꺼번에 팝니다. 재계산한 거래대금 6,205,620원이 보고서 3.5절 값과 같습니다 | 계산(일지 행을 직접 읽은 것은 아니라 🟡) |

## 질문

1. **15:29 배치 의도**가 「당일 종가 체결」이었나요? 로그상으로는 다음 날 체결(MarketOnOpen 변환)입니다.
2. `lean_backtest.py` 에 선택 모드 `fill_timing="next_open"`(**기본값 불변 · 대사 스크립트만 사용**)을 더해도 될까요? 공동 파일이라 먼저 여쭙니다. 구현은 이동원이 하고 PR 에서 리뷰를 부탁드리는 방식을 생각하고 있습니다.
3. 대사 때 LEAN 입력을 야후 대신 **수집 DB**(수정 종가 + 원주가 시가)로 바꿔도 될까요? 일지와 같은 자료가 되어 데이터 층 차이가 사라지고, 보고서 머리표의 「가격 데이터」 칸이 바뀝니다.
4. 진입 크기를 `set_holdings(1)` 에서 **여유분(예: 0.95)** 으로 바꾸는 데 의견이 있나요? 시가 체결로 바꾸면 갭 상승이 약 0.25% 만 넘어도 거절됩니다(09-29 와 같은 꼴). 삼성전자 2020~2026 에서 5% 넘는 갭은 1.1% 였습니다.
5. 보고서 3.2절 「나머지 네 날 원인 확정 불가」를 **매도 비율 0.5 재현 결과**로 바꿔도 될까요? 보고서는 강민석 님 문서라 이동원이 고치지 않고 제안만 드립니다.
6. 원격 domain-rag-lab 서버 코드가 `rag-lab/` 사본처럼 **자정 시각 + `end_time` +1일** 규칙인가요? 화면의 LEAN 결과에 체결 규칙을 표기할지도 의견 부탁드립니다.
