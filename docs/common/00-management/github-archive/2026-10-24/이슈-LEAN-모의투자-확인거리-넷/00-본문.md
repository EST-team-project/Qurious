## 1. 자동매매 「당일 자동 주문」 이 늘 0건으로 보입니다 (DF-152)

주문 수를 **세는 쪽**과 **화면에 읽어 주는 쪽**의 Redis 열쇠가 다릅니다.

| 하는 일 | 부르는 곳 | 넘기는 사용자 값 | 실제 열쇠 |
|---|---|---|---|
| 주문 수 +1 | 자동매매 매수 · 매도 · 재주문 | `<uid>` | `quant:orders:<uid>:<날짜>` |
| 하루 한도 판정 | 자동매매 사이클 | `<uid>` | `quant:orders:<uid>:<날짜>` |
| 화면 표시 | `GET /api/quant/risk/status` | `<uid>:quant` | `quant:orders:<uid>:quant:<날짜>` |

- 상태 API 가 `:quant` 를 붙여 넘깁니다 — [stocks.py:1043-1058](https://github.com/EST-team-project/Qurious/blob/b86152a/app/routes/stocks.py#L1043-L1058)
- `risk_status` 는 받은 값 하나로 시작 자산과 주문 수를 함께 읽습니다 — [risk_guard.py:187-200](https://github.com/EST-team-project/Qurious/blob/b86152a/app/services/risk_guard.py#L187-L200) · 열쇠 꼴 [:105-118](https://github.com/EST-team-project/Qurious/blob/b86152a/app/services/risk_guard.py#L105-L118)
- 세는 쪽과 한도 판정은 접미사 없이 씁니다 — [auto_trade.py:1040](https://github.com/EST-team-project/Qurious/blob/b86152a/app/services/auto_trade.py#L1040) · [:1149-1176](https://github.com/EST-team-project/Qurious/blob/b86152a/app/services/auto_trade.py#L1149-L1176) · [order_retry.py:128](https://github.com/EST-team-project/Qurious/blob/b86152a/app/services/order_retry.py#L128). 접미사는 시작 자산에만 붙어 있습니다(`auto_trade.py:991-997`).

**화면에서는** 퀀트 자동매매 현황 → 위험관리 상태의 「당일 자동 주문」 이 주문이 나가도 `0건 / 최대 N` 으로 남습니다([quant.js:176](https://github.com/EST-team-project/Qurious/blob/b86152a/public/js/quant.js#L176)). 같은 화면 아래 사이클 로그의 「주문 n건」 은 맞게 나와서 두 숫자가 어긋나 보입니다. 한도 판정은 세는 쪽과 같은 열쇠라 제대로 막습니다 — 틀리는 것은 보이는 숫자뿐입니다.

**제안** — #297 을 고친 #302(`ca337eb`)에서 시작 자산 열쇠를 장부마다 나누면서 주문 수 열쇠도 함께 바뀐 것으로 보입니다(그 커밋의 부작용 **후보** — 실행해 확인하지는 않았습니다). 주문 수만 접미사 없는 값으로 읽게 하거나, 세는 쪽까지 같은 열쇠로 맞추는 것 가운데 고르시면 됩니다. 지금 시험은 `risk_status` 를 가짜로 바꿔 열쇠를 보지 않으니(`tests/test_risk_execution.py:111-115`), 「세고 → 상태 API 로 읽기」 시험 하나가 있으면 다시 갈라지지 않을 것 같습니다. 3차에 위험 관문을 이어받는 오준영 님과 함께 보셔도 됩니다.

**방법 셋**

① 저장소에서만 빼기 — `--cached` 라 강민석 님 PC 의 파일은 그대로 남고, 다른 사람은 다음 pull 때 지워집니다.

```bash
git rm -r --cached data/lean-workflows
git rm app/routes/tradingview.py.bak_fills app/services/lean_backtest.py.bak_fills \
  app/services/tradingview.py.bak_fills tests/test_tradingview.py.bak_fills
```

백업도 PC 에 남기시려면 둘째 줄에도 `--cached` 를 붙이시면 됩니다.

② `.gitignore` 에 두 줄 — 더 넓은 꼴(예: `*.bak*`)이 좋으면 판단대로 하시면 됩니다.

```
data/lean-workflows/
*.bak_fills
```

③ 10-26 까지 정리하시는 실행 조건 · 결과 문서에는 일곱 폴더 가운데 쓸 결과만 요약표(실행 시각 · 종목 · 기간 · 수익률 · MDD · 체결 수)로 남기면 폴더 없이도 다시 볼 수 있습니다.

이력은 고치지 않습니다 — 팀 저장소 강제 push 는 부담이 크고, 자료가 작아 지우는 커밋으로 충분합니다. 데이터 원본은 공개 저장소에 올리지 않고 필요한 자료는 HF 비공개 데이터셋에 두는 것이 우리 규칙이고, Yahoo 가격은 재배포 조건도 분명하지 않습니다.
