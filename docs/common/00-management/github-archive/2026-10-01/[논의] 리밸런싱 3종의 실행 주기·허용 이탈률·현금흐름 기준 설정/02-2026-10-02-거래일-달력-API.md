## 거래일 달력 · 배당 일정 주소가 먼저 생겼습니다 (2026-10-02)

> **쉬운 요약**
> 1. 앞 답글 4번에서 「W4(10-06 ~ 10-07)에 드리겠다」 고 한 거래일 달력 · 배당 일정 주소를 오늘 만들었습니다. PR 이 머지되면 main 에서 바로 쓰실 수 있습니다.
> 2. 휴장일은 공휴일 표(한국천문연구원 특일 정보)와 거래소 규칙(근로자의 날 · 연말 휴장일)으로 정하고, 지난날은 수집한 시세로 확인합니다. 2020-01-02 ~ 2026-09-30 의 거래일 1,655일과 한 날도 어긋나지 않았고, 2027-12-31 까지 있습니다.
> 3. 앞 답글 3번의 예(「1일 09:00」 이라 11-01(일) · 2027-01-01(금 · 신정)에 켜짐)는 이 달력으로 「그 달 첫 거래일」 = **11-02(월)** · **2027-01-04(월)** 로 바꿀 수 있습니다.

### 주소 둘 — 로그인 없이 읽습니다

| 주소 | 주는 것 |
|---|---|
| `GET /api/calendar/trading-days?from=2026-11-01&to=2026-11-03` | 하루하루 — 거래일인지 · 휴장이면 까닭 · 근거(`observed` 시세로 확인 / `rule` 예정) |
| `GET /api/calendar/events?from=2026-10-01&to=2026-12-31&kind=dividend_record,dividend_ex&symbol=005930` | 배당 기준일 · 배당락일 · 코스피200 만기 · 평일 휴장(`kind` 로 고름) |

로컬에서 실제로 받은 응답 일부입니다(오늘 앱 · 오늘 데이터).

```json
{"date": "2026-11-01", "weekday": "일", "is_trading_day": false, "reason": "일요일", "basis": "rule"}
{"date": "2026-11-02", "weekday": "월", "is_trading_day": true, "reason": "", "basis": "rule"}
{"date": "2026-12-31", "weekday": "목", "is_trading_day": false, "reason": "연말 휴장일"}
{"date": "2027-01-01", "weekday": "금", "is_trading_day": false, "reason": "1월1일"}
{"date": "2027-01-04", "weekday": "월", "is_trading_day": true, "reason": ""}
```

### 리밸런싱에서 쓰는 법 (제안)

- **「매월 · 분기 · 연 첫 거래일」** — `trading-days` 로 그 달을 받아 `is_trading_day` 가 참인 첫 날. 지금 코드의 「1일 09:00」 을 이 날의 09:00 으로 바꾸면 휴장일에 켜지지 않습니다.
- **배당 현금흐름** — `events` 의 `dividend_record`(기준일 · 공시에 적힌 값) · `dividend_ex`(배당락일 · 거래일로 센 값). 지급일 칸은 아직 없습니다(공시 본문에서 더 읽을 예정).
- **달력 끝** — 응답의 `calendar.end`(지금 2027-12-31). 그 뒤를 물으면 `partial: true` 와 까닭이 붙습니다 — 빈칸을 「거래일 없음」 으로 읽지 않게요.

### 함께 바뀐 것

- 배당락일 계산이 앞날의 거래일을 모르던 결함을 고쳤습니다. 아직 오지 않은 기준일을 달력 끝에서 세어, 기준일 10-13 의 배당락일이 09-29 로 들어가 있었습니다(맞는 값 10-12 — 10-09 한글날). 총수익(TR)도 다시 만들었습니다.
- 데이터가 언제 것인지 보는 주소(`GET /api/data/status` · 로그인 뒤)도 생겼습니다 — 매일 12:30 갱신 결과와 표마다 「몇 거래일 늦었나」 를 줍니다.
