신호 단계를 러너에 연결했습니다 — 러너 묶음 PR(브랜치 `feat/runner-signals-step`)에 들어 있고, 머지되면 다음 12:30 회차부터 돕니다. 약속드린 확인 결과와, 연결하다 찾은 것 하나를 적습니다.

**자리 · 이름표** — 말씀하신 대로 `ohlcv` 뒤 · `manifest` 앞, 이름표 「신호」 · 묶음 「계산」 · 시간 한도 10분 · `fatal=False` 입니다. 배치 코드는 고치지 않고 부르기만 합니다.

**확인 결과(2026-10-08 · 이 PC)**

```text
python scripts/signals_daily.py --dry-run
계산 — 2026-10-07 ~ 2026-10-07 거래일 1 · 종목 401 · 줄 401 · 오류 0 · 55초
  신호 — 매수 149 · 매도 133 · 관망 119 · 정의 판 tv-2026

python scripts/daily_update.py run --only signals
앱 DB 주소(PC 쪽 · compose 에서) 127.0.0.1:15432/fin_ai — 앱 DB 를 쓰는 단계에만 넘긴다
  기록 — signal_snapshots 401줄(같은 날 · 같은 판은 새 값으로 바꿈)
✅ signals · 종료코드 0 · 41초 · 시세 기준일 20261007
```

**찾은 것 — PC 에서 돌면 앱 DB 주소가 다릅니다.** 처음 `run --only signals` 는 앱 DB 컨테이너가 떠 있는데도 `ConnectionRefusedError`(종료코드 3)로 끝났습니다. 앱 설정(`app/config.py`)은 `ENV_FILE` 이 없으면 `.env.dev` 를 읽는데, 컨테이너가 쓰는 주소(`postgres:5432`)는 compose 의 environment 에만 있고 PC 에서는 compose 가 연 포트(`15432`)로 붙어야 하기 때문입니다. 러너가 compose 에서 PC 쪽 주소를 만들어 신호 단계에만 넘기게 고쳤습니다(개발 모드 스크립트 `dev.ps1` 과 같은 값). 배치를 PC 에서 손으로 돌리실 때도 같은 일이 생길 수 있어요 — 그때는 `dev.ps1` 창에서 돌리거나 `DATABASE_URL` 을 `127.0.0.1:15432` 로 주시면 됩니다.

**앱 DB 가 꺼진 날** — 답글에 적은 「회차를 실패로 세지 않고 그 단계만 노랑 건너뜀」 은 그대로인데, 방법을 바꿨습니다. 종료코드 3 만 보고 건너뜀으로 바꾸면 위의 주소 문제처럼 「DB 는 떠 있는데 설정이 틀린」 날도 건너뜀 뒤에 숨어서, **러너가 돌리기 전에 앱 DB 포트를 먼저 확인**합니다(실무 도구 사례를 조사해 정했어요 — 조사서 https://github.com/EST-team-project/Qurious/blob/main/docs/조사/러너단계결과-화면실행통로-조사.md).

- 포트가 닫혀 있으면: 돌리지 않음(계산 45초도 아낌) · 수집 일정 화면에 노랑 「건너뜀 · 앱 DB 꺼짐」 과 빠진 거래일 · 회차는 성공 그대로(리밸런싱 하루 점검을 막지 않음)
- 포트가 열렸는데 실패하면: 경고(설정 결함을 숨기지 않음)
- 빠진 날 채우기: `python scripts/signals_daily.py --from YYYY-MM-DD --to YYYY-MM-DD` — 화면의 「이 단계만 다시」 를 열면 함께 보입니다

**선택 제안 하나(정하시는 대로)** — 배치가 「앱 DB 에 닿지 못함」 을 다른 뜻과 겹치지 않는 코드(예: 75 = 일시 오류)로 내고, 401종목을 계산하기 **전에** 연결을 먼저 확인하면 꺼진 날 계산을 버리지 않습니다. 지금 러너는 포트 확인으로 막고 있어서 급하지 않아요.
