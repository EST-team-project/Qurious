작업 ID만 알면 비로그인 상태에서도 Celery 결과를 조회하거나 작업을 취소할 수 있던 문제를 수정합니다. 이제 세션·JWT로 인증한 요청자의 소유 작업만 조회·취소할 수 있습니다.

Closes #200

- 채팅 비동기 및 인제스트 비동기 4개 경로에서 소유자를 PostgreSQL에 커밋한 뒤 큐에 발행합니다. 소유자 저장 실패 시 발행하지 않으며, 큐 수신 여부가 불확실하면 소유자 기록을 보존하고 자동 재발행하지 않습니다.
- 일반 사용자에게 타인 작업과 소유자 없는 기존·시스템 작업은 동일한 404를 반환합니다. admin 역할은 해당 작업에 접근할 수 있고, terminate=true는 관리자만 허용합니다. 권한 저장소 장애 시 관리자도 503으로 차단합니다.
- Celery·DB 통신과 실행 실패의 내부 예외를 응답에 노출하지 않고 한국어 안내를 제공합니다. 취소 응답의 revoked=true는 요청 전송을 뜻하며 실제 취소 여부는 상태 조회로 확인합니다.
- API 명세·카탈로그, 데이터 속성 대장 및 시험 추적표를 갱신했습니다.

검증: 관련 pytest 104개 통과(실패·건너뜀 0). 인증·소유권 경계, 다섯 발행 경로, 저장 실패 시 발행 차단, 불확실한 발행, 내부 오류 비노출 및 실제 PostgreSQL의 발행 전 커밋·사용자 삭제 연쇄 처리를 확인했습니다. 격리 PostgreSQL·Redis·Celery 워커에서도 성공 결과 조회, 타인 접근 차단, 실패 안내 및 실제 REVOKED 전환을 확인했습니다. 빈 DB의 전체 마이그레이션과 0025 → 0024 → 0025 적용·되돌리기, 기존 사용자 보존을 확인했습니다. API 문서·카탈로그 일치 검사, 문서 이름 검사 및 git diff --check도 통과했습니다.

적용 시 앱 교체 전에 `alembic upgrade head`로 `0025_task_ownership`을 적용해야 합니다. 과거 작업의 소유자는 소급 추정하지 않으므로 일반 사용자는 해당 작업을 조회·취소할 수 없습니다. 이 PR은 이슈 #200만 다루며 운영 배포는 수행하지 않았습니다.
