## Why

- 강사님 일정의 **10-06(화) 오전 칸**이 IA · 와이어프레임과 함께 ERD 를 봅니다. 결정 대장(의견 기한 09-30 23:59)과 IA(D1 ③ 확정 뒤)는 기다려야 해서, 막힘 없는 ERD · 데이터 사전을 먼저 새 틀로 올렸습니다.
- 사전을 다시 뽑아 보니 **감자 결함(DF-01)을 고치며 더한 조정 이벤트 값 `shares` 가 사전에 안 나왔습니다.** 스캐너가 수집 DB 표의 칸 설명을 DB 파일에 저장된 CREATE 문(표를 처음 만들 때 것)에서 읽고 있었기 때문입니다 — 사전이 약속한 「설명을 고치려면 코드 주석을 고친다」 가 수집 DB 쪽에서는 지켜지지 않고 있었습니다.

```
 코드의 CREATE 문 ──(칸 설명)──┐

                                        └──▶ 요약: 코드 ↔ DB 파일 대조 · 대장 대조 (⚠️ 로 알림)
```

- 고른 것 — 「대장이 모든 표를 덮는다」 는 **실제 저장소 시험에 걸지 않았습니다.** 팀원이 표를 더하면 시험이 깨지기 때문입니다(API 명세 스캐너 시험과 같은 원칙). 판정 규칙은 합성 대장으로 재고, 실제 대장에는 파일 형식만 겁니다.
- 고른 것 — 업무 분류는 **담당 파트 대신 업무 영역**. 표에 파트를 붙이면 역할 결정을 앞지릅니다.
- 버린 것 — 사전의 `kind` 한 줄만 손으로 고치기(「손으로 고치지 말 것」 을 깬다) · 그림 번호를 스캐너가 붙이게(스캐너는 문서의 번호를 모른다 → 자동 블록은 제목만).
