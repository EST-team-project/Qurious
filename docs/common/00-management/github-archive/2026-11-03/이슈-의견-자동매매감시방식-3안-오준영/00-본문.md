자동매매의 감시 기능을 어떤 방식으로 구현할지 팀 의견을 구합니다.

현재는 **우리 서버가 가격과 조건을 확인하고 주문을 실행하는 방식**이 구현돼 있습니다. 추가로 검토하던 ‘증권사 상주 감시’는 우리 서버가 꺼져도 증권사에서 감시를 계속하는 기능입니다.

공식 문서를 다시 확인한 결과, 고객센터 답변을 기다리지 않고 개발할 수 있는 범위도 있어 아래 세 가지 중 **이번 프로젝트의 완료 범위**를 정하면 좋겠습니다.

| 선택안 | 구현 내용 | 장점·제약 |
|---|---|---|
| **1안. 우리 서버 감시 방식 유지·보완** | 현재 구현을 바탕으로 감시·주문·장애 복구와 예외 처리를 보완 | 기존 구조를 활용할 수 있음. 우리 서버가 중단되면 감시도 중단됨 |
| **2안. 거래소 스톱지정가 연동 추가** | 조건가격에 도달하면 지정가 주문이 유효해지는 기능을 공개 API로 연결 | 주문·정정·취소·발동 조회 규격이 공개돼 있음. 모의투자 지원과 실제 동작 검증이 필요하며, 장기 감시·복합 조건을 모두 대체하지는 않음 |
| **3안. 증권사 서버 상주 감시 연동** | 증권사에 조건을 등록하고, 우리 서버가 꺼져도 감시가 유지되도록 연결 | HTS에서는 최장 30일 감시 기능이 제공됨. 외부 프로그램용 API와 모의투자 지원 여부는 아직 확인되지 않음 |

현재 확인한 근거는 다음과 같습니다.

- KIS 공개 주문 API에는 스톱지정가 주문과 조건가격 항목이 있습니다. 따라서 **2안은 공개 규격으로 구현을 시작할 수 있습니다.** [공식 주문 API](https://apiportal.koreainvestment.com/api/apis/public/detail?accessUrl=/uapi/domestic-stock/v1/trading/order-cash)
- 일부 관련 조회 API는 모의투자를 지원하지 않아, **모의 환경에서 전체 과정을 검증할 수 있는지는 추가 확인이 필요합니다.** [정정·취소 가능 주문 조회 API](https://apiportal.koreainvestment.com/api/apis/public/detail?accessUrl=/uapi/domestic-stock/v1/trading/inquire-psbl-rvsecncl)
- HTS 0954의 서버자동 주문 기능은 존재하지만, 이를 우리 프로그램에서 등록·조회·삭제할 공개 API 규격은 아직 찾지 못했습니다. **API가 없다고 확정한 상태는 아닙니다.** [HTS 기능 안내](https://www.truefriend.com/plus_help/0954.html)

제안은 **2안을 우선 검토하면서 모의투자 지원 여부를 확인하는 방향**입니다. 3안까지 프로젝트에 필요하다면 KIS 공식 문의를 병행해 지원 API와 이용 조건을 확인하면 좋겠습니다.

다음 두 가지에 의견 부탁드립니다.

예: `2안 우선 진행 / 공식 문의 병행 찬성`
