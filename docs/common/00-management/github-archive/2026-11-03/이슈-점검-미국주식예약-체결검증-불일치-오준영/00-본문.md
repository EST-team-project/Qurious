@rkdalstjr 강민석 님, @dev-dongwon05253 이동원 님 — 11월 3일 프로젝트 전체 시험에서 미국주식 예약 관련 시험 2건이 실패했습니다.

예약 서비스는 미국 종목을 대기 주문으로 저장하지만, 이후 체결에 사용하는 공통 함수는 국내 종목만 허용하고 있습니다. **접수할 때 허용하는 범위와 체결할 때 허용하는 범위가 서로 다릅니다.**

[#255의 이동원 님 댓글](https://github.com/EST-team-project/Qurious/issues/255#issuecomment-6281193775)에서도 예약이 `skipped`로 빠질 수 있다는 지적이 있었고, 이번 DB 시험에서 해당 흐름이 재현됐습니다. 담당 범위가 연결된 문제여서 두 분께 함께 확인을 요청드립니다.

**1. 확인한 사실**

점검 기준은 `main 34c4d56f`입니다. 아래 내용은 코드 확인과 분리된 시험용 PostgreSQL에서 실행한 결과를 구분해 적었습니다.

| 위치 | 확인한 내용 | 확인 방법 |
|---|---|---|
| [`us_reserve.place`](https://github.com/EST-team-project/Qurious/blob/34c4d56f/app/services/us_reserve.py#L136) | 미국 종목을 `pending` 상태의 예약 주문으로 저장합니다. | 코드·DB 시험 |
| [`POST /api/paper/stocks/reservations`](https://github.com/EST-team-project/Qurious/blob/34c4d56f/app/routes/us_reserve.py#L47) | 위 서비스를 호출하며, 성공 응답은 HTTP 201로 정의되어 있습니다. | 코드 |
| [`us_reserve.fill_due`](https://github.com/EST-team-project/Qurious/blob/34c4d56f/app/services/us_reserve.py#L195) | 다음 정규장 시가와 환율을 받아 `_fill_stock_order`로 체결을 요청합니다. | 코드·DB 시험 |
| [`_ensure_supported_market`](https://github.com/EST-team-project/Qurious/blob/34c4d56f/app/services/paper_trading.py#L66) | `currency != KRW`인 종목을 거부합니다. | 코드·DB 시험 |
| [`GET /api/paper/stocks/reservations`](https://github.com/EST-team-project/Qurious/blob/34c4d56f/app/routes/us_reserve.py#L38) | 목록을 반환하기 전에 `fill_due`를 실행하고 변경 내용을 커밋합니다. | 코드 |

따라서 현재 흐름은 다음과 같습니다.

```text
미국주식 예약 접수
→ pending 저장
→ 예약 목록 조회 시 체결 시도
→ 공통 체결 함수의 국내 전용 검증에서 거부
→ 예약 상태 skipped
```

여기서 확인한 대상은 **앱 내부 가상 모의장부의 미국주식 예약**입니다. KIS 모의투자 주문 접수 실패를 뜻하지 않습니다.

**2. 실제 실패한 시험**

| 시험 | 기존 기대 결과 | 실제 결과 |
|---|---|---|
| `test_reserve_then_fill_at_the_first_session_open` | 다음 정규장 시가로 체결되어 `filled` | 국내 전용 검증에 막혀 `skipped` |
| `test_fill_is_skipped_with_a_reason_when_cash_is_short` | 잔액 부족으로 건너뛰고 사유에 `현금` 표시 | 잔액 검사에 앞서 해외 종목 거부 사유가 반환됨 |

두 번째 시험에서 실제 반환된 사유입니다.

```text
PLUG 는 해외 종목(USD)입니다.
국내주식 모의주문은 원화 종목만 지원합니다.
```

두 건 모두 같은 시장 지원 범위 불일치에서 발생했습니다. 두 번째 실패만으로 별도의 현금 계산 오류가 확인된 것은 아닙니다.

**3. 재현 조건과 방법**

개발용 시험 의존성을 설치하고, `QURIOUS_TEST_DATABASE_URL`을 **운영 DB와 분리된 시험용 PostgreSQL**로 지정한 뒤 실행합니다.

```bash
python -m pytest -q \
  tests/test_us_reserve.py::test_reserve_then_fill_at_the_first_session_open \
  tests/test_us_reserve.py::test_fill_is_skipped_with_a_reason_when_cash_is_short
```

시험은 다음 조건을 고정합니다.

- 종목: `PLUG`, 통화: `USD`
- 예약 시각: 2026-10-17 토요일 17:00 KST
- 다음 정규장 시작: 2026-10-19 월요일 22:30 KST
- 정상 체결 시험: 1주 예약
- 잔액 부족 시험: 1,000주 예약, 현금 1,000원
- 시세·캔들 응답은 시험용 값으로 대체합니다. 실제 미국주식 주문을 전송하지 않습니다.

**4. 사용자에게 생기는 영향**

미국주식 화면은 장이 닫혀 있으면 예약을 접수하고 다음 정규장 시작가로 체결을 시도한다는 안내를 표시합니다. 하지만 현재 공통 체결 함수에서는 USD 종목이 허용되지 않습니다. 사용자는 예약을 정상적으로 접수한 뒤에야 지원하지 않는 거래라는 사실을 알게 됩니다. [화면 코드](https://github.com/EST-team-project/Qurious/blob/34c4d56f/public/js/us.js#L324)

또한 목록 조회가 체결 시도를 동반하므로, **화면에서 예약 내역을 확인하는 동작이 예약 상태 변경으로 이어집니다.** 기존 대기 예약을 어떻게 보여 주고 처리할지도 함께 정할 필요가 있습니다.

**5. 우선 수정 제안과 담당별 요청**

이번 점검에서는 **국내 전용 범위를 유지하고, 체결할 수 없는 미국 예약은 접수 전에 명확히 거부하는 방향**을 우선 제안합니다. 해외 비용 모델 구현과 미국주식 매매 전체 개방은 별도 후속으로 다뤘으면 합니다.

| 요청 대상 | 확인·수정 요청 |
|---|---|
| **강민석 님 — 모의장부·공통 체결·비용 정책** | 현재 해외 주문 미지원 범위를 확인하고, 예약 서비스에서도 같은 지원 여부를 판단할 수 있도록 검증 위치와 오류 응답을 정해 주세요. |
| **이동원 님 — 미국 예약 서비스·화면** | 미지원 예약이 `pending`으로 저장되지 않도록 접수 경로를 맞추고, 버튼·확인창·접수 안내가 실제 지원 범위와 일치하도록 수정해 주세요. |
| **두 분 확인 필요** | 이미 저장된 대기 예약의 조회·취소와 상태 처리 방식을 정해 주세요. 기존 기록을 임의로 삭제하거나 계좌를 초기화하는 방식은 제안하지 않습니다. |

담당 구분은 [#255의 후속 담당 정리](https://github.com/EST-team-project/Qurious/issues/255#issuecomment-6281193775)와 기능완성도 점검표를 기준으로 했습니다.

국내 검증을 제거하거나 미국 종목을 국내 시장으로 취급해 시험만 통과시키는 수정은 피하고, **시험의 기대 결과도 확정된 지원 정책에 맞춰 변경**해야 합니다.
