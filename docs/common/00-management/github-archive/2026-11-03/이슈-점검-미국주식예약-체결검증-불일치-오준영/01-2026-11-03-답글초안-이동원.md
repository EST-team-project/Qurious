@GoonGuMa 오준영 님, @rkdalstjr 강민석 님 — 점검 감사합니다. 미국 예약 서비스와 화면은 제 몫이라 제 쪽에서 직접 재현하고 코드를 맞대 봤습니다. 기준 `main 82ef202`(#517 ~ #519 포함)입니다.

**1. 재현 — 같은 두 시험이 최신 main 에서도 실패합니다**
일회용 시험 PostgreSQL(`scripts/personal/test.ps1 -Path tests\test_us_reserve.py`)에서 `2 failed, 19 passed` 입니다. 두 번째 시험의 사유 문구도 오준영 님 글과 같습니다(`PLUG 는 해외 종목(USD)입니다. 국내주식 모의주문은 원화 종목만 지원합니다.`).

**2. 언제부터 어긋났나**
- 예약 서비스(`us_reserve.py`)는 10-17 에 제가 만들었고, 체결 때 `paper_trading._fill_stock_order` 에 USD 종목을 그대로 넘깁니다(220행).
- 10-20 강민석 님 커밋 `27a1998`(#255)이 `_ensure_supported_market` 을 `_fill_stock_order` 의 최종 방어선(533행)에도 넣었고, 그날부터 **예약 체결은 항상 `skipped`** 가 됩니다.
- 제가 10-20 #255 댓글 1번에 이 충돌을 미리 적었는데, 그 뒤 정책 결정과 제 쪽 반영이 이어지지 않았습니다. 이번 수정은 제 몫으로 가져가겠습니다.

**3. 오준영 님 글에 덧붙이는 사실 — 예약만이 아닙니다**
같은 검증이 `stock_preview`(447행)와 `stock_order`(512행)에도 있어서, 미국주식 화면의 **장이 열린 때 직접 매수와 금액 미리 보기도 같은 까닭으로 거부**됩니다. 지금 모의 장부로는 미국주식 매수가 예약 · 직접 모두 되지 않는 상태입니다(코드로 확인했고 앱에 직접 호출해 본 것은 아닙니다).
화면 쪽 사정도 있습니다. 미리 보기 거절 사유는 확인 상자에 빨간 글로 보이지만(10-30), 상자의 「예약 걸기」 · 「매수 주문 내기」 단추는 그대로 열려 있어 사용자가 눌러 접수할 수 있습니다(`usorder.js` `usoConfirm`).

**4. 제안한 방향에 동의하고, 제 쪽은 이렇게 맞추겠습니다**
국내 전용 범위를 유지하고 접수 전에 거부하는 안에 동의합니다. 해외 비용 모델과 미국 매수 개방은 별도 후속으로 두겠습니다.

| 할 일 | 내용 |
|---|---|
| 접수 전 거부 | `us_reserve.place` 가 저장 전에 장부와 같은 지원 범위 판단을 하고, 미지원이면 `pending` 을 만들지 않은 채 400 과 같은 사유를 돌려줍니다 |
| 화면 | 미지원이면 확인 상자 단추를 막고, 접수 안내 · 주문 폼 문구를 지원 범위에 맞춥니다 |
| 기존 대기 예약 | 목록 · 취소는 그대로 둡니다. 지원하지 않는 대기 예약은 체결 시도로 상태를 바꾸지 않고 「지원하지 않는 예약 — 취소해 주세요」 로 보이게 해서, **목록을 여는 것만으로 상태가 바뀌는 문제**도 함께 없앱니다 |
| 시험 | 실패한 두 시험을 「접수 전 거부 · 저장 0 · 현금 · 보유 변화 0」 을 확인하는 시험으로 바꾸고, 국내 주문 · 체결 시험이 그대로 통과하는지 확인합니다 |

**5. 강민석 님께 확인 두 가지**
1. 지원 범위 판단을 서버 여러 곳에서 같은 것으로 쓰도록, `paper_trading` 쪽에 **공개 함수**(예: `is_supported_market(info)`)를 두는 것이 좋을까요? 아니면 제가 지금의 `_ensure_supported_market` 을 그대로 불러도 될까요(비공개 이름이라 확인드립니다).
2. 해외 비용 모델 · 미국 매수 개방의 시점 계획이 있다면 알려 주세요. 11-12 시연이나 영상에 미국 모의 매수 장면이 있는지는 제가 아직 확인하지 못했습니다.
