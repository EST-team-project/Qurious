@dev-dongwon05253 이동원 님, @rkdalstjr 강민석 님 — 11월 3일 프로젝트 전체 시험에서 야후 참조 증가를 검사하는 시험 1건이 실패했습니다.

`paper_trading.py`의 기준선은 10줄인데 현재 검사 결과는 11줄입니다. 변경 이력을 확인하니 가격 출처 감사 정보에 추가된 `yahoo_finance` 문자열이 집계에 포함되어 있었습니다.

**현재 확인된 것은 참조 문자열의 줄 수 증가입니다. 실제 외부 호출이 늘었는지는 별도로 확인해야 하므로, 기준선만 바로 올리지 않고 두 분께 검토를 요청드립니다.**

**1. 확인한 사실**

| 항목 | 확인 결과 | 근거 |
|---|---|---|
| 실패 시험 | `test_야후_참조가_기준선과_같다` | [`tests/test_no_yahoo_regression.py`](https://github.com/EST-team-project/Qurious/blob/34c4d56f/tests/test_no_yahoo_regression.py#L123) |
| 저장된 기준선 | `paper_trading.py`: 10줄 | 같은 파일 45행 |
| 실제 검사 결과 | `paper_trading.py`: 11줄 | 전체 시험 실패 로그 |
| 검사 방식 | `yahoo`, `yfinance`, `query1.finance`, `query2.finance`와 일치하는 **줄**을 셉니다. | 같은 파일 30행·106행 이후 |
| 관련 변경 | 가격 출처 감사 정보 추가 | [커밋 `4e7c1fa2`](https://github.com/EST-team-project/Qurious/commit/4e7c1fa256dac08266410322340b3aba12f619b8) |

실패 메시지의 핵심은 다음과 같습니다.

```text
app/services/paper_trading.py: 11줄 (기준선 10)
```

이 시험은 호출 횟수를 측정하지 않습니다. **주석과 데이터 문자열도 검사 대상**이며, 참조 줄 수가 줄어든 경우에도 기준선을 함께 갱신하도록 설계되어 있습니다.

**2. 10줄에서 11줄이 된 이유**

관련 커밋에서 검사 패턴에 걸리는 줄의 변경은 다음과 같습니다.

| 변경 | 줄 수 |
|---|---:|
| 기존 Yahoo 설명 주석 삭제 | -1 |
| 대체자산 평가 가격의 `source: "yahoo_finance"` 추가 | +1 |
| 환율 환산 감사 정보의 `"yahoo_finance"` 추가 | +1 |
| **합계** | **+1** |

현재 추가된 문자열은 다음 위치에 있습니다.

- [`paper_trading.py` 1176행](https://github.com/EST-team-project/Qurious/blob/34c4d56f/app/services/paper_trading.py#L1176): 대체자산 가격 출처
- [`paper_trading.py` 1199행](https://github.com/EST-team-project/Qurious/blob/34c4d56f/app/services/paper_trading.py#L1199): 환율 환산 값의 출처

이 변경으로 **문자열 기준선이 어긋난 이유는 설명됩니다.** 다만 해당 사실만으로 관련 기능 전체의 네트워크 호출 횟수가 동일하다고 확정하지는 않았습니다.

**3. 영향과 재현 방법**

현재 영향은 회귀 시험 실패입니다. 이 결과만으로 주문·체결 오류나 새로운 야후 요청 발생이 확인된 것은 아닙니다.

프로젝트 시험 환경에서 다음 명령으로 재현할 수 있습니다. 이 검사는 DB나 야후 서버 연결 없이 소스 파일을 읽습니다.

```bash
python -m pytest -q \
  tests/test_no_yahoo_regression.py::test_야후_참조가_기준선과_같다

python -m tests.test_no_yahoo_regression
```

첫 명령은 기준선 불일치를 검사하고, 두 번째 명령은 파일별 현재 참조 줄 수를 출력합니다.

**4. 담당별 확인 요청과 수정 제안**

| 요청 대상 | 확인 요청 |
|---|---|
| **강민석 님 — 가격 출처 감사 정보 추가 부분** | 두 출처 문자열이 어떤 기존 조회 결과를 표시하는지, 감사 정보 활성화로 별도 외부 조회가 추가되는지 확인해 주세요. |
| **이동원 님 — 야후 의존 증가 방지 시험** | 위 확인 결과를 바탕으로 기준선 예외를 인정할 수 있는지 검토해 주세요. 시험 파일에도 증가 시 PR에 사유를 적도록 되어 있습니다. |

검토 결과 **기존 조회 결과에 출처 표시만 추가된 것으로 확인된다면**, 최소 수정은 다음과 같습니다.

1. `paper_trading.py` 기준선을 `10 → 11`로 변경합니다.
2. 기준선 옆에 관련 커밋과 `주석 1줄 삭제 + 출처 문자열 2줄 추가`라는 근거를 남깁니다.
3. PR 설명에 외부 의존 증가 여부를 어떻게 확인했는지 적습니다.
4. 야후 참조 검사와 가격 출처 관련 시험을 다시 실행합니다.

새 외부 조회가 확인되면 기준선 조정 전에 그 필요성과 기존 데이터 사용 원칙부터 검토해야 합니다.

검사를 삭제하거나, 출처 문자열 이름만 바꿔 검색을 피하는 방식은 제안하지 않습니다. 검사 방식 자체를 개선할 필요가 있다면 이번 기준선 정리와 범위를 구분했으면 합니다.
