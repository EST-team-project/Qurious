1. 모의 장부를 바꾸는 주문 출처가 여섯 가지인데, 초기화 · 주문 내역 화면 · 직접매매 최근 주문이 **서로 다른 출처만** 다룹니다.

3. 입금 · 출금이 일간 수익률에서 보정되지 않아 입금한 날 수익률이 부풀려집니다.

## 1. 주문 출처 필터가 서로 다릅니다

| 용도 | 위치 | 포함하는 `source` |
|---|---|---|
| 초기화가 지우는 주문 | `paper_trading.py:139-145` | `WEB`, `PAPER` (`broker != kis`) |
| 모의 주문 내역 화면 | `paper_trading.py:615` `stock_order_history` | `WEB`, `PAPER`, `PINE`, `SIM` |
| 직접매매 최근 주문 | `routes/stocks.py:423` | `WEB`, `PAPER`, `PINE` |
| **PAPER 장부를 실제로 바꾸는 경로** | `openapi.py:132` · `fill_sync.py:200` 등 | `WEB`, `PAPER`, `PINE`, `OPENAPI`, `TRADINGVIEW`, `REBALANCE` (+ `RESERVED` → `PAPER`) |

코드 읽기로 추론한 결과:

- `TRADINGVIEW` · `REBALANCE` · `OPENAPI` 체결은 모의 현금 · 보유를 바꾸는데 **주문 내역 화면에는 나오지 않습니다.**
- 초기화 뒤에도 이 주문들은 `orders` 에 남는 것으로 읽었습니다(`PINE` 은 코드 주석이 「보존」 이라고 적음). 한편 `Portfolio`(PAPER 장부)는 초기화에서 지워집니다.
- `SIM` 은 쓰는 코드를 찾지 못했습니다.
- `Order` · `CashflowEvent` 에는 `epoch` 칸이 없어 회차 경계를 가를 수 없습니다. (#123 에서 `CashflowEvent` 에 epoch 를 더하겠다고 하셨는데, **`Order` 에도 같은 구분이 필요한지** 함께 봐 주세요.)

## 2. 직접매매 가격

- `routes/stocks.py:355-409` `place_order` 는 `apply_cash` + `_apply_portfolio` 를 직접 쓰는 **별도 구현**이고, 체결가는 **요청 본문의 `price`** 입니다. 평균단가 계산이 `paper_trading._fill_stock_order` 와 복제돼 있습니다(`stocks.py:343`). 비용은 `order_costs` 로 같게 뗍니다.
- `_fill_stock_order` 주석은 「클라이언트가 가격을 지정하는 API가 아니다」 라고 적었는데 이 경로는 다릅니다.
- 이 경로는 공통 관문과 비상 정지도 지나지 않습니다(오준영 님께 별도 문의 이슈로 올렸습니다).

## 3. 입금 · 출금이 일간 수익률에 섞입니다

- `paper_snapshot_service.py` · `performance_service.py` · `snapshot_pricing.py` · `paper_trading.py` 에서 cashflow / deposit / 입금 / 출금을 보정하는 코드를 찾지 못했습니다(검색 0건).
- `daily_return` 이 총자산 비율이라 `DEPOSIT` / `WITHDRAW` 로 총자산이 바뀐 날 그만큼이 수익률에 섞입니다. 합성 계산(손으로 정한 값): 9만큼 입금한 날 0.99% 가 9.90% 로 나옵니다. 리셋 경계도 −4.76% 로 나옵니다(보정하면 0 처리).
- 배당 입금(`DIVIDEND`)은 소득이므로 수익률에 들어가는 것이 맞고, 외부 현금흐름인 `DEPOSIT` / `WITHDRAW` 만 보정 대상이라고 이해했습니다.
