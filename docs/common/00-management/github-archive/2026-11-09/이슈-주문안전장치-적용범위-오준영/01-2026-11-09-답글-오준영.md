1. **웹 직접매매·일반 모의주문이 공통 관문 밖인 이유와 설명 범위**

   자동매매 계열과 개인 KIS 모의주문에 공통 관문을 연결했지만, 기존 일반 PAPER 수동 주문 경로까지 이관한 상태는 아닙니다. `POST /api/orders`는 PAPER 현금·보유를 확인한 뒤 직접 가상 체결하고, 일반 모의투자 주문도 `source != "TRADINGVIEW"`이면 `_fill_stock_order`를 직접 호출합니다. 따라서 현재 비상 정지를 모든 주문에 적용되는 전역 정지로 설명하면 안 됩니다. 다만 **개인 KIS 수동 모의주문도 정지 대상**이므로, 단순히 “자동매매만”이라고 쓰기보다는 아래 적용 범위를 명시하는 것이 정확합니다.

   > 비상 정지는 자동매매, 개인 KIS 수동 모의주문, TradingView의 PAPER 주문, QUANT 판2 실행에 적용됩니다. 웹 직접매매·일반 PAPER 수동 주문·Open API 모의주문에는 적용되지 않습니다.

   이 제외 범위를 모든 수동 주문에 대한 의도된 안전정책으로 확정한 것은 아닙니다. 일반 PAPER 경로까지 확대할지는 별도 후속으로 검토하겠습니다.

   맞습니다. 사이클이 임시 쿨다운 슬롯을 확보한 뒤, 공통 관문에서 기존 의도를 찾으면 전송 없이 기존 결과를 돌려줍니다. `order_preflight.execute_quant`가 이를 `status="duplicate"`로 바꾸고, 사이클은 이번 시도의 임시 슬롯을 반납하며 Redis 주문 수를 추가하지 않습니다. **PG의 기존 `OrderIntent`와 주문 중복 방지 기록은 삭제하지 않으므로 같은 주문을 다시 보내라는 의미는 아닙니다.** 다만 이 연결 전체와 동시 실행·쿨다운 경계의 전용 회귀시험이 충분하다고 확인한 것은 아닙니다. 해당 조합의 검증 보완은 별도 후속으로 남기겠습니다.
