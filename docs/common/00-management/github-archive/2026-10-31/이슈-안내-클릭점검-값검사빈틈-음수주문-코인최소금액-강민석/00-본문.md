**주담당** 강민석 @rkdalstjr (④ 모의투자 · 서버) · 작성 이동원

강민석 님, 모든 화면의 버튼을 하나씩 눌러 보는 점검(10-31)에서 **서버가 값을 막지 않아 잘못된 주문이 그대로 기록되는 곳** 셋과 문구 하나가 나와 알려 드립니다. 화면에서는 먼저 막아 두었지만 화면은 우회될 수 있어(API 직접 호출) 서버에서도 막는 편이 안전합니다.

### ① 음수 수량 · 가격이 「매수 기록 완료」 로 통과합니다 — 가장 먼저
- 재현: 직접매매 › 주문(`#trading-order`) → 종목 005930 · 가격 `-100` · 수량 `-5` → 매수. 화면에는 「매수 기록 완료 (앱 안 기록 · 가상 매매)」 가 뜹니다.
- 원인(코드 확인): `app/routes/stocks.py:323` 의 `OrderBody` 에 `quantity: int` · `price: float` 만 있고 범위 제약이 없습니다. `_apply_portfolio` 가 음수 수량으로 보유 · 평균단가 · 현금을 바꿉니다.
- 제안: `quantity: int = Field(..., ge=1)` · `price: float = Field(..., gt=0)` (한 줄씩). 안내 글은 `PydanticCustomError` 로 한국어로 던지면 화면이 그대로 보입니다(기존 규칙).
- 이 담당이 강민석 님이 아니면 알려 주세요(`/api/orders` 라우트 작성자는 확인하지 못했습니다).

### ② 코인 최소 주문 금액(1,000원)이 화면 속성에만 있습니다
- 재현: 모의투자 › 코인(`#paper-crypto`) 매수 금액 `500` → 「KRW-BTC 매수 체결 · 수량 0.00000479」.
- 원인: `public/app.html` 의 `min="1000"` 은 화면 속성일 뿐이고 서버 `app/routes/paper.py:210` 은 `buyKrw: float = Field(..., gt=0)` 입니다.
- 제안: 서버 최소 금액을 정하는 쪽(`Field(..., ge=1000)` 또는 업비트 최소 주문 금액 상수)으로. 얼마가 맞는지는 강민석 님이 정해 주세요.

### ③ 서버 422 안내가 영어 원문으로 화면에 뜹니다
- 재현: 모의 주식 수량 `-5` → 「Input should be greater than or equal to 1」 · 코인 음수 → 「Input should be greater than 0」 · LEAN 자금 `-100` → 빨간 글 「Input should be greater than or equal to 1000」.
- 안내는 나오지만 한국어가 아닙니다(조용한 빈 화면은 아님). 화면 `api()`(`public/js/common.js`)가 422 의 `detail[].msg` 를 그대로 잇기 때문입니다.
- 제안: ①②처럼 검사 칸을 만질 때 `PydanticCustomError` 로 한국어 문구를 같이 정해 두면 한 번에 해결됩니다(모든 칸을 한꺼번에 하자는 뜻이 아닙니다).

### 이미 한 것 (이동원 · 화면만 · PR #…)
- 직접매매 · 미국 주문 · 모의 주식 · 코인 화면에서 음수 · 0 · 1,000원 미만을 **서버로 보내기 전에** 한국어로 막았습니다(실제 브라우저에서 서버로 나간 요청 0건 확인). 서버 검사를 대신하지 않으니 ①②는 여전히 필요합니다.
- 같은 점검에서 미국 주문의 「입력 직후 매수를 누르면 시세를 받지 못했다고 뜨는」 경합도 화면에서 고쳤습니다.
