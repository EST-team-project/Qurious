@GoonGuMa 님, #511 의 공통 수집 상태 연결 확인했습니다. 제가 만든 `app/services/collector_status.py` 쪽 변경을 코드로 대조했습니다(`origin/main` `bfe35f8`).

- `symbol_day_status(..., connection=None)` — `connection` 을 주면 호출자의 열린 트랜잭션에서 SELECT 만 하고 닫지도 커밋하지도 않는 것, `path` 와 함께 주면 `ValueError`, 열린 트랜잭션이 아니어도 `ValueError` 인 것을 diff 에서 확인했습니다. 결과 꼴(`{symbol, day, 상태…}`)은 그대로이고 제공자는 사실만 돌려줍니다.
- `rebalance_prices.collection_complete` 가 직접 쓰던 `ingest_day` SQL 을 지우고 이 함수를 부르며, 완료 판정(`collected` 가 비어 있지 않고 전부 `done`)은 소비자에 남아 있는 것도 확인했습니다. 상태를 못 읽는 경우(`CollectorStatusUnavailable`)는 대기로 가는 예외 묶음에 들어 있고, 시험 `test_rebalance_waits_if_common_collection_status_unavailable` · `test_caller_transaction_is_used_without_open_commit_or_close` 등 네 건이 이 약속을 지킵니다.

제공자 쪽에서 더 바꿀 것은 없다고 봅니다. `connection` 을 쓰는 소비자가 더 생겨도 「열린 읽기 트랜잭션 안에서 부른다 · path 와 함께 못 쓴다」는 조건이 함수 설명과 `ValueError` 로 이미 막혀 있어 그대로 두겠습니다. 이슈를 닫는 판단(새 자연 회차와 운영 예약 · 정산 관측)은 오준영 님 쪽 관측 뒤에 하시면 됩니다.
