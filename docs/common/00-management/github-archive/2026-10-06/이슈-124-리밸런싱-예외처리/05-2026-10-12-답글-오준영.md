데이터 쪽 후속 계획 확인했습니다. 오후 재수집은 관리자 화면의 「이 단계만 다시」·「전체 수집」을 사용하는 방향으로 이해했습니다.

종목별 상태 조회에는 현재 리밸런싱 판정에서 사용하는 다음 정보가 필요합니다.

| 정보 | 사용하는 곳 |
|---|---|
| 종목·기준 날짜·출처 구분(주식/ETF) | 판단·예약 체결 대상 자료 식별 |
| 해당 날짜의 출처별 수집 완료 여부 | 수집 지연과 수집 완료 후 가격 부재 구분 |
| 해당 종목·날짜의 가격 행 존재 여부 | 가격 확인 대기 또는 미체결 종료 판단 |
| 거래정지 여부·거래량 0 여부 | 해당 거래일의 시가 체결 가능 여부 판단 |

핵심은 **수집이 끝나지 않아 기다리는 상태**와 **수집은 끝났지만 해당 날짜에 체결할 수 없어 미체결로 종료하는 상태**를 구분하는 것입니다. 출처를 확인할 수 없는 종목은 현재 주식·ETF 양쪽 수집 완료를 요구하므로, 이 경우도 구분할 수 있으면 좋겠습니다.

조회 인터페이스가 정해지면 현재 `ingest_day`를 직접 읽는 부분을 공통 조회 경로로 연결하겠습니다. 원주가 시가·종가는 기존 가격 조회 경로를 유지하면 됩니다.

실제 정산 검증을 위해 **같은 회차의 수집 DB와 원본 `state/daily_update_last.json`을 함께 확보할 수 있는 방법**도 부탁드립니다. 판단 회차뿐 아니라 예약 체결일 시가가 포함된 후속 회차 자료까지 연결해, 예약부터 체결 확정·현금·보유 수량·비용·중복 방지를 확인하려고 합니다.

전체 회차 성공 조건을 리밸런싱 필수 자료 중심으로 보완하는 의견은 #163에 남겼습니다. 해당 변경과 이 종목별 상태 조회가 같은 기준을 사용하도록 맞추겠습니다.

예약 취소·휴장일 이동·미체결 종료는 #136·#145로 구현·병합됐지만, 실제 회차 정산 검증은 남아 있으므로 **#124는 아직 완료 처리하지 않겠습니다.**
