## #124 [논의] 리밸런싱 수동·현금흐름 점검과 예약 변경의 예외 처리 규칙

> **쉬운 요약**
> 1. 자동 정기 점검의 전 거래일 종가 판단 → 다음 거래일 시가 예약·정산은 구현했습니다(PR #121).
> 2. 같은 기준을 수동 실행·입출금 후 점검에 어디까지 적용할지, 예약 후 계좌가 바뀌면 어떻게 처리할지는 아직 미정입니다.
> 3. #79에 남긴 질문을 별도 이슈로 분리합니다. 아래 선택지와 제안은 아직 팀 확정 사항이 아닙니다.

## 1. 현재 구현과 남은 부분

| 구분 | 현재 동작 |
|---|---|
| 자동 정기 점검 | 12:30에 시작하는 데이터 갱신의 완료·기준일을 확인한 뒤 거래일당 한 번 점검 |
| 자동 판단·체결 | 전 거래일 종가로 판단 → 다음 거래일 시가 예약 → 해당 시가 수집 후 체결 확정 |
| 자동 종가 제안의 사용자 승인 | 즉시 체결하지 않고 예약 |
| ‘지금 점검’·수동 신규 리밸런싱 | 기존 조회 시세 경로 유지. 기존 자동 종가 제안·예약은 덮어쓰지 않음 |
| 입금·출금·수동 배당 | 현금 반영 후 기존 조건 점검 경로 사용 |
| 예약 후 계좌·설정 변경 | 변경 감지 시 체결을 보류. 자동 취소·재계산·보류 해제 기능은 미구현 |

시가 체결일과 데이터 수집 후 **체결을 확정하는 시점**은 다릅니다. 예약 이후 변경 정책은 이 시간차도 고려해야 합니다.

## 2. 가격 판단·체결 기준을 어디까지 통일할까요?

| 안 | 적용 방식 |
|---|---|
| A | 자동 정기 점검, ‘지금 점검’, 수동 리밸런싱, 입출금·배당 후 점검 모두 전 거래일 종가 판단 → 다음 거래일 시가 예약으로 통일 |
| B | 자동은 위 기준으로 처리하고, 수동 실행은 조회 시세로 즉시 모의 체결하는 예외 유지 |

- 기존 #79 댓글의 제안은 **가격·체결 기준 통일(A)**입니다. 모의투자 처리 및 시연 관점에서 의견 부탁드립니다.
- ‘지금 점검’과 수동 실행의 적용 범위를 각각 확인하고 싶습니다.
- 종가 자료가 미갱신·누락된 경우에는 다른 가격으로 대체하지 않고 대기시키는 것으로 할까요?
- 휴장일 또는 정기 점검 전 요청을 받았을 때의 대기·예약일 기준도 함께 정해야 합니다.

## 3. 입출금·배당 후 언제 점검할까요?

현금 이벤트 자체는 즉시 장부에 반영하는 것을 전제로, 리밸런싱 판단 시점을 정하려고 합니다.

| 안 | 점검 시점 |
|---|---|
| A | 다음 정기 점검까지 현금흐름을 누적한 뒤 판단 |
| B | 이벤트 직후 판단하고, 예약 체결 기준을 선택했다면 다음 거래일 시가로 예약 |

- B를 선택할 경우 같은 날 정기 점검을 이미 완료했거나, 추가 입출금·배당이 여러 번 발생했을 때 재점검을 허용할까요?
- 기존 하루 한 번 자동 점검·중복 계획 방지와 어떻게 연결할지 함께 정해야 합니다.
- 이 항목은 **점검 시점**에 관한 질문입니다. 출금은 우선 보유 현금 안에서만 허용하고, 이후 필요한 매도로 목표 현금 비중을 회복하는 현재 범위를 전제로 합니다.

## 4. 예약 후 계좌·설정이 바뀌면 어떻게 할까요?

대상은 추가 입출금·배당, 직접 매매, 목표 비중·리밸런싱 설정 변경, 플랜 비활성화 등입니다.

| 안 | 처리 방식 | 함께 정할 사항 |
|---|---|---|
| A | 기존 예약 유지 | 원래 수량 유지 여부, 현금·주식 부족 시 실패/부분 체결 기준 |
| B | 기존 예약 취소 | 취소 후 다음 정기 점검까지 기다릴지 |
| C | 기존 예약 취소 후 재판단 | 재판단 가격·예약일, 사용자 재승인 필요 여부 |
| D | 확인 대기 후 사용자 선택 | 취소·재계산 등 화면 동작과 보류 해제 조건 |

- **현재 코드는 변경 감지 시 확인 대기까지만 처리**합니다. 대기 상태가 계속 남아 이후 자동 계획도 막힐 수 있으므로 후속 동작이 필요합니다.
- 예약 체결일 이전 변경과, 체결일이 지났지만 아직 시가를 수집하지 못한 사이의 변경을 같은 방식으로 처리할까요? 뒤늦은 확정이 장부의 거래 순서를 뒤집지 않도록 확인이 필요합니다.
- 설정 비활성화 시에는 예약도 취소할지 별도로 확인 부탁드립니다.
- 시가 누락·장기 거래정지로 예약이 오래 남는 경우, 계속 대기할지 취소/만료 기준을 둘지도 함께 정하면 좋겠습니다. 다른 날짜의 시가로 임의 체결하지 않는 것이 현재 동작입니다.

## 5. 의견 요청 및 완료 조건

모의투자 담당 강민석님께는 예약·잔고·체결 이력의 처리 순서를, 데이터 담당 이동원님께는 가격 확정 시점과 자료 부족 시 대기 기준을 확인 부탁드립니다.

```text
가격·체결 기준: A 또는 B / 지금 점검·수동 실행의 범위
자료 미갱신·휴장일 요청: 대기 및 예약일 기준
입출금·배당 후 점검: A 또는 B / 같은 날 추가 이벤트 처리
예약 후 변경: A·B·C·D / 변경 시점에 따른 예외 / 재승인 여부
플랜 비활성화·장기 미체결: 취소·만료·대기 기준
```

- [ ] 위 정책을 합의하고 항목별 결정 기록
- [ ] 예약 변경·보류 해제 경로를 포함한 후속 구현과 시험 항목에 반영

자동 정기 경로의 기존 구현과 구분하여 **남은 예외 정책을 확정하는 이슈**입니다. 정책 합의와 구현 완료는 별도로 기록하겠습니다.
