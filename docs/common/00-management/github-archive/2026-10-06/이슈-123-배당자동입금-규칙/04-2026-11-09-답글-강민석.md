@dev-dongwon05253 이동원 님, 추가 확인 사항에 대한 모의투자 장부 담당 의견입니다.

1. **WEB 체결 포함 여부**
   - 동일한 PAPER 계좌의 포지션과 현금 장부에 실제 반영된 WEB 체결은 권리 수량에 포함하겠습니다.
   - 주문 출처만으로 판단하지 않고 실제 체결 수량과 PAPER 장부 반영 여부를 기준으로 하겠습니다.

2. **계좌 초기화 전후 배당 기록**
   - 기존 배당 기록은 삭제하지 않겠습니다.
   - `CashflowEvent`에 계좌 epoch를 추가해 초기화 전후의 기록을 구분하고, 자동 입금은 현재 epoch에 대해서만 처리하겠습니다.
   - 과거 epoch의 체결 이력으로 권리 수량을 확정할 수 없다면 자동 입금하지 않고 확인 대기로 두겠습니다.

3. **감액 정정 및 현금 부족**
   - 현금이 부족한 경우 계좌 현금을 음수로 만들지 않겠습니다.
   - 원래 배당 기록은 유지하고 조정 건을 확인 대기 상태로 남기겠습니다. 현금 부족이 해소되거나 담당자가 확인한 뒤 조정하겠습니다.

4. **리밸런싱 예산 반영**
   - 자동 배당도 기존 수동 `DIVIDEND`와 동일하게 `remaining_budget`에 반영하겠습니다.
   - 입금 후 정정에 따른 조정 금액도 예산에 반영하되, 이미 사용한 예산보다 감액이 큰 경우에는 자동 차감하지 않고 확인 대기로 처리하겠습니다.

5. **세금 계산**
   - 세전 금액, 소득세, 지방소득세, 세후 금액을 각각 기록하겠습니다.
   - 기본 계산은 소득세 14%, 지방소득세는 소득세의 10%, 소득세 원천징수액 1,000원 미만은 소액부징수 규칙을 적용하는 방향입니다.
   - 다만 원 단위 끝수 처리 규칙은 근거가 확인되지 않았으므로 임의로 확정하지 않고, 규칙 버전과 반올림·절사 방식을 별도 확정한 뒤 자동 입금에 적용하겠습니다.

6. **ETF 분배금**
   - 이번 자동 입금 범위에서는 제외하고 기존 수동 처리 방식을 유지하겠습니다.

기존 수동 배당 기록은 삭제하지 않으며, 자동 배당과 동일한 배당인지 확인된 경우에만 중복 입금을 차단하겠습니다. 동일 배당 여부가 불확실하면 자동 입금하지 않고 확인 대기로 처리하겠습니다.

위 기준으로 장부 설계와 구현 범위를 확정하겠습니다.
