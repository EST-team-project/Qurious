## #123 [논의] 배당 자동 입금의 금액·권리 수량·정정·중복 처리 규칙

> **쉬운 요약**
> 1. 배당 지급일 API를 리밸런싱에 연결하기 전에 입금 금액·배당 권리·정정·중복 처리 규칙을 정하려고 합니다.
> 2. 현재 배당은 사용자가 금액을 직접 입력하는 방식이며, 지급일 자동 입금은 아직 구현하지 않았습니다.
> 3. 아래 질문에 의견을 주시면 모의투자 장부와 연결해 구현하겠습니다. 선택지와 제안은 아직 팀 확정 사항이 아닙니다.

## 1. 배경과 현재 상태

#79에서 이동원님이 배당 지급일 API와 「지급일이 없는 배당은 추정하지 않기」 방향을 안내해 주셨습니다. 실행 기준 논의가 길어져 배당 자동 입금의 세부 규칙을 별도 이슈로 분리합니다.

- 지급 일정: `GET /api/calendar/events?from=2026-10-01&to=2026-12-31&kind=dividend_pay`
- 현재 리밸런싱은 수동 배당 이벤트를 현금흐름 조건에 반영합니다.
- 자동 입금에는 지급일 외에도 주당 배당금, 배당 권리가 있는 당시의 수량, 같은 배당을 구분하는 정보가 필요합니다.
- 이 이슈의 범위는 **모의투자 계좌의 배당 입금 규칙**입니다. 배당 반영 후 언제 리밸런싱을 점검할지는 별도 점검·체결 예외 이슈에서 논의합니다.

## 2. 입금 금액 — 세전 또는 세후

| 안 | 처리 방식 |
|---|---|
| A | 권리 수량 × 주당 배당금의 세전 금액을 입금하고, 모의 계산임을 표시 |
| B | 세금 차감 후 금액을 입금하고, 세전 금액·세금·실제 입금액을 각각 기록 |

- 2차 프로젝트에서는 어느 방식으로 할까요?
- B라면 적용 대상·세율의 근거·원 단위 반올림/절사 규칙은 무엇으로 할까요?
- 화면과 장부에서 세전·세후를 혼동하지 않도록 표시 기준도 함께 정하면 좋겠습니다.

## 3. 배당 권리 수량과 데이터 연결

이동원님의 기존 의견은 **배당락일 전날 장 마감 때 보유 수량**을 기준으로 하는 방향입니다. 지급일의 현재 보유 수량을 사용하면 중간 매매를 잘못 반영할 수 있습니다.

- 해당 기준을 모의투자 장부에 어떻게 적용할까요? 휴장일을 고려한 권리 시점과 사용할 체결 이력/보유 수량 기록을 확인하고 싶습니다.
- 과거 체결 이력이 부족해 권리 수량을 확인할 수 없는 경우에는 자동 입금을 보류하는 것으로 할까요?
- 일정 API의 표시용 `detail` 문자열 대신, 계산용 주당 배당금·배당락일/기준일·지급일·원본/정정 식별 정보를 어떤 구조로 받을 수 있을까요?
- 우선 자동 처리할 대상은 국내 주식의 현금배당으로 할까요? ETF 분배금 포함 여부도 데이터 제공 범위와 함께 확인 부탁드립니다.

## 4. 지급일 미정·지연 수집·정정

- **지급일 미정:** 날짜를 추측하지 않고 미정으로 표시한 뒤, 지급일이 확인되면 처리하는 방향을 제안합니다.
- **수집 지연:** 지급일이 지난 뒤 자료가 들어오면 미처리 배당을 뒤늦게 입금할까요? 이 경우 지급일과 실제 처리 시각을 구분해 기록하면 좋겠습니다.
- **입금 전 정정:** 지급일·주당 배당금이 바뀌면 최신 확인 자료로 갱신할까요?
- **입금 후 정정:** 기존 기록을 보존하고 차액을 조정할지, 확인 대기로 전환할지 정해야 합니다. 감액 정정인데 현금이 부족한 경우도 포함합니다.

## 5. 수동·자동 입금의 중복 방지

현재 수동 입력은 금액 중심이라 자동 배당과 같은 건인지 금액만으로 판단하기 어렵습니다.

- A: 자동 처리 대상 배당의 수동 입력을 제한하고, 예외 건만 별도 수동 처리.
- B: 수동 입력 시 해당 배당을 선택하게 하여 자동 처리와 같은 식별 정보로 중복 방지.
- 기존에 금액만 입력한 배당은 어떻게 대조할까요? 불확실한 건은 확인 대기로 둘까요?
- 정정 공시의 접수번호가 바뀌어도 같은 배당임을 추적할 수 있는 식별 규칙이 필요합니다.
- 작업 재시도나 동시 실행에서도 **계좌별 같은 배당은 한 번만 입금**되도록 구현하겠습니다.

## 6. 의견 요청 및 완료 조건

데이터 담당 이동원님께는 지급·권리·정정 정보 제공 범위를, 모의투자 담당 강민석님께는 과거 보유 수량과 장부 조정 방식을 확인 부탁드립니다. 전체 항목에 답하지 않아도 괜찮습니다.

```text
입금 금액: 세전/세후, 세후라면 계산·반올림 기준
권리 수량: 기준 시점 / 사용할 장부 / 자료 부족 시 처리
자동 처리 대상: 국내 주식 현금배당 / ETF 포함 여부
지급일 미정·지연 수집: 처리 방향
지급일·금액 정정: 입금 전 / 입금 후
수동·자동 중복: A 또는 B / 기존 수동 기록 처리
```

- [ ] 위 규칙과 담당 간 데이터 연결 방식을 합의하고 기록
- [ ] 합의 내용을 설계서·구현 작업·검증 항목에 반영

이 이슈는 **정책 합의**를 위한 것이며, 이슈가 닫혔다고 자동 입금 구현까지 완료된 것으로 보지는 않습니다.
