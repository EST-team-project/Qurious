### 먼저 못 하는 것 (원문으로 읽은 것)
- 국내 주식은 **서버 공유 키 하나로 받은 시세를 모든 사용자 화면에 실시간으로 보이면 안 됩니다.** KIS 약관 제5조③(개인의 업무에 한해 이용 · 제3자 제공 금지) · KIS 제휴 안내(코스콤 계약 없이는 제휴사 앱 화면의 시세 이용 불가) · 코스콤 정보이용정책(계약 없는 최종이용사는 제3자 제공 권한 없음). 실제 증권 서비스는 이 계약이 있어 가능합니다.
- 공유 키로 받은 값을 HF · 팀에 저장하는 것도 제3자 제공입니다(조사서 `실시간시세-지연표기-조사.md` 3.4절 · 2026-10-19 판정).

### 지금 반영한 것 — 1단계(내 KIS 키 방식 · 프런트만)
- 지표 대시보드의 「현재가」 카드가 **본인 KIS 키가 연결된 사람만** 증권사 조회 값(`GET /api/quote/now` 의 `source = kis_user`)을 보이고, 장중이면 약 10초마다 다시 받아 차트 끝에 「오늘 점」 을 더합니다. 장이 닫혀 있으면 다시 받지 않고, 키가 없으면 지연 시세 + 「내 증권사를 연결하면 …」 안내를 보입니다.
- 이 값은 체결마다가 아니라 서버의 10초 저장본이라 화면은 「실시간」 이라고 쓰지 않습니다.
- 코드 `public/js/companyview.js` · `company.js` · 시험 `tests/test_companyview_screen.py`(TC-CV 12건). 서버 응답 꼴은 그대로입니다.

### 부탁 — 2단계 설계(SCH-RT) 의견
1. **담당 · 시기**: 서버가 사용자별로 KIS 웹소켓(실시간 체결가 `H0STCNT0`)에 접속하고 브라우저에는 SSE 로 전달하는 구조를 3차 안에 하실 수 있는지, 아니면 후속으로 두는지.
2. 알려진 제약(조사서 · **공식 원문은 못 읽었고 「대체로」**): 앱키당 1세션 · 합산 41건 · 모의 웹소켓 주소(`ws://ops.koreainvestment.com:31000`)의 동작은 확인 못 함 · 접속키 `/oauth2/Approval`.
3. 화면이 받을 응답 꼴 제안(바꾸셔도 됩니다): `{symbol, price, change_pct, traded_at(체결 시각), source: "kis_user", market_state}` — 지금 `/api/quote/now` 와 같은 칸이라 화면은 주소만 바꾸면 됩니다. 연결이 끊기면 마지막 값의 시각을 그대로 보이게 `traded_at` 이 필요합니다.
4. 키가 없는 사용자는 계속 지연 · 종가 표기입니다. **계약(코스콤 정보이용 · 증권사 제휴)을 맺는 경우는 3단계로 두고 지금은 하지 않습니다** — 맺는다면 공유 키 실시간이 가능해지니 알려 주세요.

### 제가 하는 것 / 안 하는 것
