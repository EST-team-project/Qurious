여섯 질문에 대한 현재 담당 결정을 [PR #479](https://github.com/EST-team-project/Qurious/pull/479)의 연동 설계 §14/작업 계획 §29에 기록했습니다.

| 질문 | 결정 |
|---|---|
| 전략설정·프로필 | 기존 사용자별 `BrokerSettings`·`ExecutionPolicy`의 기본값/범위, 전략 ID/판과 실행 시 설정 서명을 사용합니다. 서버 전체 공유 설정·새 설정별 성과 프로필은 이번에 추가하지 않습니다. |
| 서버/화면 값 | 서버 입력 범위·실거래 차단·주문 관문을 우회하지 않는 구조를 유지합니다. 기존 사용자 위험 한도(0=해당 한도 비활성) 계약은 유지하며 환경변수 기본값을 새로운 불변 상한으로 바꾸지는 않습니다. |
| 비상 정지 | 기존 자동매매 현황의 **사용자별 정지**를 유지합니다. 로그인만으로 전체 사용자 배치를 시작/해제하는 공용 제어는 받지 않습니다. |
| 주문 주체 | 자동/수동은 `OrderIntent.user_id/source/strategy_id/version`, 회차는 `ExecutionRun.source`; 가상 리밸런싱은 `Order.source=REBALANCE`와 사용자·run/trigger/context를 사용합니다. IP·브라우저 수집은 추가하지 않습니다. |
| 계약 v0.7 | 보관 원본은 v0.5로 유지합니다. 상대 서버와 합동 계약 검증 없이 판 번호만 올리지 않습니다. 개인 키 직접 경로/게이트웨이 차이는 Qurious 연동 설계에 명시했고 v0.7 전체 도입은 이번에 채택하지 않습니다. |
| 테마 플랜 | 기존 저장 목표를 보존하는 원칙에 동의합니다. 새 ETF 연결도 확인→편집→저장을 거치며 기존 플랜을 자동 변환하지 않습니다. |

알려 주신 `celery_app.py`·`kis_batch.py`의 3분 주석과 게이트웨이의 같은 옛 설명을 **실제 값 600초(10분)**에 맞췄습니다. 실제 주기 값은 바꾸지 않았습니다. 참고 후보의 스트레스/챗봇 주문도 이번 도입 범위에는 넣지 않습니다.
