강민석 님(@rkdalstjr), 신장환 님(@janghwan-god), 3차 증권사 API 연동을 준비하면서 **LEAN 실행 방식과 신호·전략 전달 형식**을 함께 맞추고자 합니다.

제 주담당은 팀 계획서의 **P02-⑤-1~3 증권사 API 연동 자동화**입니다. 기존 KIS 국내주식 모의계좌를 우선 활용하는 일정안을 PR #313에 올렸습니다. 두 분의 역할을 추가로 정하는 요청이 아니라, 전략·LEAN과 주문 처리 사이의 연결 경계를 확인하려는 협의입니다.

## 강민석 님께 남은 확인 요청

1. **이번 연결 시험에 사용할 실행처와 버전:** 기존 LEAN 원격·로컬 구현 중 실제로 사용할 실행 위치와 준비 가능한 표본을 알려 주세요. 공유 가능한 실행 문서가 있으면 기존 문서로 맞추겠습니다. 인증 정보는 이슈에 올리지 않습니다.
2. **기존 명세 평가 경로 유지 여부:** 현재의 「검증된 전략 명세를 받아 Qurious에서 평가」하는 경로를 기준으로 연결하려 합니다. 3차에 LEAN 자체의 현재 신호 출력으로 바꿀 예정인 경우에만 변경 경계·표본을 맞추고 싶습니다. 새 신호 API를 기본 의무로 요청하지 않습니다.
3. **시험 가능 시점:** 10/27 최소 연결 시험에 사용할 기존 합격 전략/고정 입력과 준비 가능한 날짜를 확인 부탁드립니다. 실제 LEAN 시험과 고정 입력 시험은 구분해 기록하겠습니다.

## 신장환 님께 남은 확인 요청

1. **기존 명세의 연결 시험용 버전:** 위에서 확인한 필드를 새로 정의하기보다, 10/27 최소 연결에 사용할 수 있는 현재 전략 ID·버전·예시를 지정 부탁드립니다. 10/28 전 명세 확장과 11/2 백테스트 일정은 기존 답변을 기준으로 맞추겠습니다.
2. **KIS 모의계좌에 적용할 때의 차이:** #183 합의는 QUANT 가상 자산 기준입니다. KIS 모의계좌 잔고·체결을 기준으로 연결할 때 기존 규칙과 달라져야 하는 부분이 있는지 확인 부탁드립니다. 기존 상한을 우회하거나 수량 계산을 전략과 주문 쪽에서 중복 적용하지 않겠습니다. ATR·손절선 후속 결정은 #183에서 이어가고 여기에는 연결 결과만 남깁니다.
3. **반복 판단 식별:** 현재 명세 평가 방식에서는 판단 봉·전략 버전으로 같은 판단을 식별하는 안을 검토하겠습니다. 별도의 신호 출력을 제공할 계획이면 식별자 재사용·유효 시각 규칙만 추가로 맞추면 됩니다. PR #313의 JSON은 새 기능의 필수 계약이 아닌 변경 선택 시 검토용 초안입니다.

## 제가 맡아서 연결할 부분

- 서버에서 확인한 사용자와 KIS 모의계좌에 신호·전략을 연결
- 동일 신호 중복 주문 방지, 손실 한도·비상 정지 검사
- 주문 접수·체결·실패·접수 여부 불명 상태를 구분하고 기록
- 로컬 Docker 기준 정기 실행·실행 로그·실패 알림 연결

10/22 제 로컬 앱에서 **KIS 모의 인증·잔고·시세 조회는 성공**했습니다. 주문은 실행하지 않았습니다. 현재 제 앱의 LEAN 원격 주소는 미설정이고, 로컬 설정이 참조하는 LEAN 이미지도 없어 실행 위치를 먼저 맞추려 합니다. 이는 제 로컬 상태이며 두 분의 환경이 준비되지 않았다는 뜻은 아닙니다. EC2·CloudWatch 사용을 전제로 요청하지 않습니다.
