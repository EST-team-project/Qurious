## 1. 10/27 최소 연결용 카드 — 지금 계약 칸만

말씀대로 새 칸을 정의하지 않고, 계약 v0.5 1절 `StrategySpec` 의 지금 칸만 썼습니다.

```json
{
  "strategy_id": "ma_cross_20_60",
  "version": 1,
  "name": "이동평균 교차 20 · 60 (연결 시험용 고정 입력)",
  "universe": ["005930"],
  "timeframe": "1d",
  "entry": { "indicator": "ma_cross", "params": { "short_window": 20, "long_window": 60 }, "condition": "short_above_long" },
  "exit":  { "indicator": "ma_cross", "params": { "short_window": 20, "long_window": 60 }, "condition": "short_below_long" },
  "signal_weights": { "technical": 1.0, "lightgbm": 0.0, "buy_threshold": 0.6, "sell_threshold": -0.6 },
  "position_sizing": { "max_position_pct": 30.0, "max_symbols": 5 }
}
```

- **고정 입력이고, 합격 판정을 받은 전략이 아닙니다.** 백테스트로 합격한 전략이 아니라서 `backtest_result` · `acceptance` 칸은 넣지 않았습니다. 시험 기록에도 「고정 입력」 으로 남겨 주세요.
- **지금 코드에서 돌려 봤습니다.** 이 카드를 `auto_trade.py` 의 `apply_strategy_spec_to_signal` 에 넣으니, 20일선이 60일선 위로 가는 종가에는 「매수」, 아래로 가는 종가에는 「매도」 가 나왔습니다(`evaluate_spec_rules` 의 `ma_cross`).
- **넣는 자리** — 자동매매 사이클은 카드를 바깥 전략 서버(`strategy_loader` · domain-rag-lab)에서 받고, 못 받으면 기본 규칙으로 돌아갑니다(`auto_trade.py` 907 · 918줄). 제 PC 는 그 서버 주소가 비어 있습니다. 고정 입력으로 시험하실 때는 이 카드를 사이클의 `strategy_spec` 자리에 넣으시면 됩니다.
- **`ma_cross` 를 고른 까닭** — 지금 앱이 지표로 직접 계산하는 규칙은 `ma_cross` · `momentum` 둘이고(`evaluate_spec_rules`), 그중 매수 · 매도 조건이 가장 단순합니다.

## 2. 손절 · 익절 · 수량 칸 — 10/27 에 판 2로

10/28 Pine 칸 전에 맞추기로 한 칸(#161 A1)입니다. 제 백테스트에 붙이는 10/27 에 1 의 카드에 칸을 더한 판(`version` 2)으로 드리겠습니다.

| 칸 | 이름 · 값 | 이름의 출처 |
|---|---|---|
| 수량 방식 | `size_kind` = `risk_pct` · `fixed_budget` / `risk_pct` = 1.0(%) | 준영님 `execution_policy.py` 의 이름 그대로 |
| 체결 시점 | `entry_mode` · `exit_mode` = `close` · `open` | 강민석 님 백테스트 `quant_pipeline.py` 의 이름 그대로 — #161 · 이동원 님 대사 문서의 `entry` = `close` · `next_open` 과 같은 뜻입니다(`open` = 다음 봉 시가) |
| 손절 · 익절 | `stops` — ATR(14) × 2 손절 · 손익비 **기본 2**(1.5 ~ 3 에서 종목 변동성 · 추세에 맞게 바꿈) | 새 칸 · #159 강민석 님 의견대로 · #161 |
| 손절 판정 | `judge` = `close` · `next_open` · `intrabar` | 새 칸 · #161 · 이동원 님 대사 문서와 같은 이름 · 값 |
| ATR 고정 | `lock` = `entry` — ATR · 손절선을 진입할 때 정하고 보유 중에는 움직이지 않음 | #161 A1 · #183 에서 드린 의견(진입 때 손절선 저장 · 보유 중 고정) |
| 다시 진입 | `reentry` = `new_signal` — 청산 뒤 새 매수 신호가 날 때만 다시 삼 | #161 A1 · 지금 백테스트 엔진과 같음(#161 Q1 「청산 뒤 신호가 새로 바뀔 때까지 현금」) |

손익비 기본값은 #161 · #159 에 1.5 로 적었는데, #159 에서 강민석 님 의견대로 하기로 한 **2** 로 바로잡습니다(1.5 ~ 3 에서 바꿀 수 있는 것은 그대로). 기능 설계서 · RTM 이 본보기로 든 강사님 실습(ATR × 2 손절 · × 3 익절 = 손익비 1.5)은 이 범위 안이라, 손익비를 1.5 로 둔 카드로 그대로 만들 수 있습니다.

백테스트 결과 응답에도 `entry_mode` · `exit_mode` · `judge` 를 같은 이름으로 싣겠습니다 — 성과 지표 · 대사가 「어느 기준으로 잰 값인지」 를 읽을 수 있게 하자는 강민석 님 의견(#161 · A3)대로입니다.

지금 자동매매 코드는 스펙의 `position_sizing` 에서 `max_symbols` 만 읽고(`auto_trade.py` 400줄) 위 칸은 읽지 않아서, 칸을 더해도 지금 동작은 바뀌지 않습니다.

계약 문서(`docs/common/02-design/contracts/kis-autotrade-api.md`)는 강사님 원본과 바이트까지 같게 두는 자리라(docs README 3.3절) 고치지 않고, 판 2 의 칸은 제 설계서와 카드 파일에 적겠습니다. 전략 ID · 판의 뜻은 계약 그대로입니다.

## 3. KIS 모의계좌 기준일 때 — 제안

#183 에서 맞춘 것(첫 진입만 · 현금 · 1회 예산 · 종목 비중 상한)은 그대로 두고, KIS 모의계좌를 기준으로 하면 아래 셋이 달라진다고 봅니다. 주문 쪽은 준영님이 정하실 부분이라 제안으로 드립니다.

| | QUANT 가상 자산 기준(#183) | KIS 모의계좌 기준(제안) |
|---|---|---|
| 「계좌 자산」 | 앱 안 가상 자산 | 주문 직전에 조회한 KIS 모의계좌 평가금액 |
| 수량 계산 | 준영님 `risk_quantity` | 같은 곳에서 한 번만 — 카드에는 방식과 값만 있고 수량은 없습니다. 설계안 4절 「수량은 서버의 예산 · 잔고 · 보유량 · 위험 제한으로 산출」 과 같습니다 |
| 손절선 기준 가격 | 판단한 순간의 가격 | 실제 체결가 − 2 × ATR — 체결가가 판단 가격과 달라도 처음 정한 위험(1%)이 지켜집니다 |

ATR 을 마지막 확정 일봉까지로 계산하자는 것은 #183 에서 드린 제 의견 그대로입니다. 정하시는 기준에 제 백테스트도 맞추겠습니다.

## 4. 같은 판단 알아보기 · 별도 신호 출력

- **같은 판단 = 전략 ID · 판 · 종목 · 판단 봉(`bar_end_at`) · 방향** — 본문 「신장환 님께 남은 확인 요청」 3번의 안(판단 봉 · 전략 판으로 식별)에 찬성합니다. 자동매매 사이클이 10분마다 돌아서(`QUANT_CYCLE_SEC = 600`) 같은 판단이 여러 번 나올 수 있는데, 이 다섯이 같으면 같은 판단으로 보시면 됩니다.
- **별도 신호 출력은 만들지 않겠습니다.** 판단은 지금처럼 앱이 카드를 읽어 계산하고, 저는 카드(명세)까지 맡겠습니다.

## 이동원 님께 — Pine 생성기 · 문서에서 맞출 것

@dev-dongwon05253 님, 10/28 Pine 생성기가 2 의 칸을 읽게 되어서 맞출 것을 적습니다. 문서는 이동원 님 몫이라 고치지 않았습니다.

1. **칸 이름** — #161 A1 에서는 `take.kind` · `size.kind` 로 적었는데, 판 2 에서는 이미 코드에 있는 이름을 따라 `stops.take_kind` · `size_kind`(준영님 `execution_policy.py`)로 씁니다. `lock` · `judge` · `reentry` 는 A1 그대로입니다. Pine 생성기는 판 2 이름으로 읽어 주시면 됩니다.
2. **손익비 기본 2** — `strategy.exit` 익절은 「진입가 + 손절 거리 × 2」(ATR × 2 손절이면 ATR × 4)가 기본이고, 입력은 1.5 ~ 3 입니다.
3. **본보기 숫자** — 기능 설계서 `P02-①-2`(434 · 439줄) · RTM(184줄) · 강사님 자료 기능 대조(56줄)의 「ATR × 2 손절 · × 3 익절」(손익비 1.5)은 범위 안이라 본보기로 그대로 두셔도 됩니다. 카드 기본값 2 를 같이 적어 주시면 문서끼리 같은 말을 할 것 같은데, 고치실지는 판단 부탁드립니다.
4. **체결 시점 이름** — 대사 문서 「차이 원인」 의 `entry`(`close` · `next_open`)와 백테스트 코드의 `entry_mode`(`close` · `open`)는 같은 뜻입니다. 카드는 코드 이름(`entry_mode`)을 씁니다. 대사 문서를 어느 이름으로 둘지 말씀 주시면 그대로 맞추겠습니다.
