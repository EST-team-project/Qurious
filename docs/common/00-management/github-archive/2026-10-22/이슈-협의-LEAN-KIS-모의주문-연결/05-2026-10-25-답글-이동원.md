## 3. 기존 알림 채널 — 그대로 쓰시면 됩니다

보내기는 `notification.dispatch`(`app/services/notification.py:280` — 사용자가 고른 텔레그램 · 슬랙 · 메일 · 카카오 · 문자, 고르지 않았으면 서버 설정에 있는 채널)를, 이력은 `notification_log` 를 그대로 씁니다. 새 채널은 만들지 않습니다.

다만 설계안 5절의 「`(run_id, event_type)` 기준 한 건 저장 · 발송 결과 구분」 에는 지금 표가 모자랍니다.

- `notification_log` 에는 제목 · 본문 · 채널별 결과만 있어서(`app/models/misc.py:51`) 무슨 알림인지는 제목 앞머리(`[매매 알림]` · `[위험관리]` · `[TradingView]`)로만 갈립니다.
- 같은 회차를 두 번 보내도 막는 곳이 없고, 이력 기록이 실패해도 조용히 지나갑니다(`notification.py:385` `except Exception: pass`).

## 4. TradingView 알림과 실행 실패 알림의 경계

경계를 「신호를 받아 기록하는 데까지」 와 「주문 길에 들어간 뒤」 로 나누면 어떨까요.

| | TradingView 알림(받는 쪽) | 실행 실패 알림(보내는 쪽) |
|---|---|---|
| 담당 | 이동원 — `P02-③-3` · ①-08(10/30) · ①-14(11/3) | 오준영 — `P02-⑤-3`(10/30) |
| 무엇 | TradingView 가 보낸 신호를 검증(토큰 · 보내는 IP 넷 · 같은 알림 두 번 · 늦게 온 알림)하고 기록 · 받았다는 알림 | 전략 실행 회차(LEAN 신호 · 주문 전송)가 실패 · 거부 · 접수 불명일 때 회차별 한 건 |
| 들어오는 곳 | `POST /api/webhooks/tradingview`(`app/routes/tradingview.py:36`) | 정기 실행 · 시작 시 1회(Celery · `auto_trade.py`) |
| 기록 | `webhook_signals`(받은 신호) | 회차 기록(설계안 5절의 새 표) |
| 보내기 · 이력 | 같은 `notification.dispatch` · 같은 `notification_log` | 같음 |

TradingView 신호가 주문 길로 넘어간 뒤의 실패(관문 거부 · 증권사 오류 · 접수 불명)는 오준영 님 알림 한 길로 보내고, 저는 받는 데까지만 알리겠습니다. 그러면 같은 실패가 두 번 오지 않습니다.

이력 표를 하나로 쓸지 정해 주세요.

| 안 | 무엇 | 좋은 점 | 아쉬운 점 |
|---|---|---|---|
| **가(추천)** | `notification_log` 에 칸 둘 — `kind`(실행 실패 · TradingView · 주문 · 위험관리 · 정합성) · `ref`(회차 번호 · 신호 번호) — 과 `(kind, ref)` 유일 색인 | 알림 이력 화면이 하나 · 같은 회차를 두 번 보내는 것을 표가 막음 | 마이그레이션 하나 — 먼저 필요한 쪽(10/30 오준영 님)이 만들어 주시면 저는 11/3 에 따라가겠습니다 |
| 나 | 실행 실패는 설계안의 회차별 알림 표, 나머지는 지금 표 | 서로 건드리지 않음 | 알림 이력이 두 곳 · 화면도 둘 |
