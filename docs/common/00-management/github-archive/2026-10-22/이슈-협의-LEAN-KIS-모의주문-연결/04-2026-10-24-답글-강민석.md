## 담당 범위 진행 상황 및 연결 시험 관련 확인 답변

요청하신 4가지 항목에 답변드리며, 현재까지의 검증 결과와 남은 작업 및 목표 일정을 함께 정리합니다.

### 1. 연결 시험 실행처 및 LEAN 버전

현재 실제 실행을 확인한 환경은 **로컬 WSL Ubuntu 22.04 + Docker Desktop 기반 LEAN 실행 환경**입니다.

- 실행 모드: `LEAN_MODE=docker`
- LEAN 이미지: `quantconnect/lean:latest`
- 확인한 이미지 digest: `sha256:aa3e0248d8d20f891e9337e395045a1317e2612986413136bfd8e2fc25c709e6`
- Docker Engine: `29.8.2`
- 가격 데이터: Yahoo Finance 일봉 데이터
- 데이터 전달 방식: CSV를 LEAN의 사용자 정의 `YFPrice` 데이터로 공급

원격 SSH 실행 경로도 코드상 지원하지만, 이번 담당 작업에서는 로컬 Docker 실행만 실제 검증했습니다. 원격 실행까지 검증이 완료된 것으로 간주하지 않겠습니다.

현재까지 실행한 표본은 다음과 같습니다.

| 항목 | 설정 |
|---|---|
| 종목 | 삼성전자 `005930.KS` |
| 기간 | 2024-01-02 ~ 2024-03-29 |
| 초기자금 | 1,000,000 KRW |
| 전략 | 이동평균 교차, 단기 5일 / 장기 20일 |
| LEAN 실행 | 성공 |
| LEAN 순수익률 | -1.754% |
| LEAN MDD | 14.20% |
| LEAN Sharpe | -0.289 |
| 주문 및 추출 체결 | 각 5건 |
| LEAN 총 수수료·세금 | ₩4,055.19 |

국내주식 수수료 및 관련 비용과 고정 10bp 슬리피지 가정을 적용했습니다. 실제 호가 데이터로 슬리피지를 측정한 것은 아닙니다.

위 표본은 실행 및 비용 모델 검증용이며, 팀에서 승인한 전략이라는 의미는 아닙니다. 또한 사용자 정의 Yahoo Finance 데이터 기반이므로 KRX 원본 데이터와 실제 체결을 완전히 재현한 시험으로 보아서는 안 됩니다.

실행 환경과 결과를 정리한 별도 문서는 현재 준비 중입니다. 인증 정보는 이슈에 기재하지 않겠습니다.

### 2. 기존 전략 명세 평가 경로 유지 여부

현재 작업에서는 기존의 **검증된 전략 명세를 받아 Qurious에서 평가하는 경로를 유지**하는 방향입니다.

이번 LEAN 백테스트는 동일한 고정 입력에서 엔진 실행 결과와 성과지표 및 체결 데이터를 비교하기 위한 검증 수단으로 사용합니다. LEAN 자체의 신호 출력을 기본 신호 공급원으로 교체하거나 새 신호 API를 기본 의무로 추가할 계획은 없습니다.

팀 논의에서 제안된 `ma_cross_20_60`은 연결 및 실행 검증을 위한 고정 테스트 입력으로 취급하겠습니다. 전략 승인이나 채택 여부와는 별개입니다.

기존 명세 평가 경로와 LEAN 실행 검증 경로는 구분해 기록하겠습니다. 향후 LEAN 자체 신호 출력으로 변경할 필요가 생긴다면, 기존 경로를 유지하면서 별도 변경 경계와 시험 표본을 먼저 합의하는 것이 적절하다고 생각합니다.

### 3. 10월 27일 최소 연결 시험 준비

현재까지 실제 실행한 표본은 `ma_cross` 5/20 설정입니다. `ma_cross_20_60` 설정은 아직 실제 LEAN 실행 결과를 확보하지 않았으므로, 이미 검증된 결과처럼 보고하지 않겠습니다.

10월 27일 최소 연결 시험에 사용할 고정 입력은 다음과 같이 준비하겠습니다.

- 종목: `005930.KS`
- 기간: 2024-01-02 ~ 2024-03-29
- 초기자금: 1,000,000 KRW
- 검증용 입력: `ma_cross_20_60`
- 준비 목표: 10월 26일(월) 18:00
- 최소 연결 시험 목표: 10월 27일(화)

10월 26일까지 고정 입력의 실행 결과와 재현 조건을 정리하고, 10월 27일 시험에서 사용할 수 있도록 준비하겠습니다.

다만 현재 제가 확인한 실행 기록만으로는 팀에서 이미 합격 판정을 내린 전략의 ID나 명세를 특정할 수 없습니다. 따라서 `ma_cross_20_60`을 기존 합격 전략이라고 부르지는 않겠습니다. 연결 시험에 반드시 기존 합격 전략을 사용해야 한다면 해당 전략의 ID 또는 고정 명세를 공유해 주시면 그 기준을 우선하겠습니다. 별도의 합격 전략 지정이 없다면 위 입력을 테스트 픽스처로 사용하고 실제 LEAN 실행과 고정 입력 시험은 각각 구분해 기록하겠습니다.
