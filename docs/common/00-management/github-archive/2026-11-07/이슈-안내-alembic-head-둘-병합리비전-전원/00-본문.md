# [안내] 마이그레이션 head 가 둘 — `alembic upgrade head` 실패 · 병합 리비전 PR 예정

- 작성: 이동원 · 2026-11-07
- 알릴 사람: 강민석(PR #602) · 오준영(알림 암호화 운영 · 배포)

## 확인한 것

PR #602(`7b256714`)가 들어온 뒤 `alembic/versions` 에서 갈래가 둘로 갈라졌습니다.

| 리비전 | 만든 곳 | down_revision |
|---|---|---|
| `0044_notification_secrets` | PR #576 (알림 비밀 암호화) | `0043_regime_targets` |
| `0044_paper_kis_reconciliations` → `0045_paper_kis_track` | PR #602 (Paper↔KIS 대사) | `0043_regime_targets` |

- `alembic heads` 가 `0044_notification_secrets (head)` 와 `0045_paper_kis_track (head)` 둘을 돌려줍니다.
- 이 PC 도커 앱 기동 로그: `DB 마이그레이션 실패 — 스키마를 바꾸지 않고 연결만 한다: Multiple head revisions are present for given argument 'head'`.
- 병합 리비전은 없습니다(`down_revision` 이 튜플인 파일 없음).

## 영향

- 새 DB · 개발 DB 에서 `upgrade head` 가 멈춥니다 → 알림 비밀 암호화(0044)와 대사 표(0044 · 0045)가 **둘 다 안 만들어질 수** 있습니다. 이 PC 개발 DB 는 `0042_merge_cancel_audits` 에 서 있습니다.
- 오준영 님 운영(복제) DB 는 점검표 기록상 11-06 에 `0044_notification_secrets` 까지 전환을 마쳤습니다. 거기에 #602 가 배포되면 `upgrade head` 가 같은 오류로 멈춥니다(대사 표 0044 · 0045 가 안 생김).
- 강민석 님의 「0044, 0045 적용 확인」은 `upgrade heads` 로 돌렸거나 한쪽만 있던 DB 였을 것으로 짐작합니다(확인 못 함).

## 제안

스키마를 바꾸지 않는 **병합 리비전 하나**를 더합니다(`0046_merge_notif_paper_kis` · `down_revision = ("0044_notification_secrets", "0045_paper_kis_track")` · upgrade/downgrade 빈 함수). 두 갈래는 서로 다른 표라 순서 의존이 없습니다. 일회용 PostgreSQL 에서 (가) 0043 에서 `upgrade head` (나) 두 갈래를 `heads` 로 적용해 둔 DB 에서 `upgrade head` 를 확인한 뒤 이동원이 작은 PR 로 올리겠습니다. 이미 올리신 분이 있으면 알려 주세요.

## 부탁

- 오준영 님: #602 를 운영(복제)에 배포하기 전에 이 병합 리비전이 먼저 들어가야 합니다(배포계획서 한 줄은 제가 맞추겠습니다). 이미 두 갈래를 `upgrade heads` 로 적용했다면 알려 주세요.
- 강민석 님: 이후 리비전은 `alembic heads` 가 하나인지 확인한 뒤 올려 주세요.
