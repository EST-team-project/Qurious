## 1. 자동매매 신호 일봉 신선도 가드 (이동원 몫: 데이터 · 자동매매 입구)
- **문제**: 일봉 정본(공공데이터포털)이 기준일 다음 영업일 13시 이후라, 오전 신호는 이틀 전 종가였다(11-04 11:00 실측: 수집 DB 마지막 봉 11-02). 주문 직전 가격만 증권사 현재가.
- **수정**: `signal_freshness.py`(새) — 있어야 할 확정 일봉 날짜(거래일 15:40 이후면 오늘)와 수집 DB `as_of` 를 맞대고, 낡으면 **그 사용자 자기 KIS 키**로 확정일 일봉만 메모리에서 붙인다(수집 DB · HF 에 쓰지 않음 · 겹치는 날 종가 0.5% 안에서 같을 때만 · 확정일 캐시는 사용자별 · 호출 간격 1.1초). 그래도 낡으면 신호 주문은 「데이터 대기」로 기록하고 내지 않는다(손절 · 익절 같은 위험 매도는 실시간 시세 판단이라 제외).
- 판단가와 주문 직전 가격이 3% 이상 벌어지면 근거에 경고만 남긴다(`SIGNAL_PRICE_GAP_WARN_PCT` · 막지 않음). 스위치 `SIGNAL_FRESHNESS_GUARD` · `SIGNAL_KIS_TAIL`.
- **실측**(읽기 전용 · KIS 모의 키): 31종목 신호 단계 리허설 전부 fresh · `kis+1` · 34.8초 · 오류 0. KIS 일봉과 수집 DB 겹치는 3일 종가 4종목 모두 일치. 모의 서버는 0.6초 간격 호출에 500 을 냈다 → 1.1초. **미실측**: 오늘 봉이 15:40 에 확정되는지 · 애프터마켓(16:00~20:00) 반영 여부(15:42 · 17:02 · 20:32 재조회 예약).
- **시험**: `test_signal_freshness.py` 30건 + 관련 자동매매 시험 통과. 전체 시험 3,808 passed · 0 failed · 490 skipped(도커가 필요한 `test_kis_recovery_session.py` · Windows CPU 시간 `test_proc_stats.py` 제외).
- **한계**: 모의 장부만 쓰고 KIS 키가 없는 사용자는 오전 사이클이 「데이터 대기」로 보류된다(예전엔 낡은 신호로 주문). 강사님 게이트웨이(`STOCK_COIN_TRADE_BASE_URL`)가 비어 있는 설정에서도 동작하도록 사용자 키를 우선했다.
