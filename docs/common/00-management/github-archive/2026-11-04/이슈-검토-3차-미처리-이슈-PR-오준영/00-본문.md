## 1. 우선 확인이 필요한 오류

### 1-1. 누락된 체결 또는 비교 0건을 ‘일치’로 표시

- 관련: #386, #497
- 확인 요청: **강민석님**
- 위치: `scripts/daily_lean_reconcile.py`의 `judge_order` 및 보고서 생성 부분

주문 방향 비교가 LEAN에 존재하는 날짜만 순회합니다. 일지에만 있는 체결은 비교에서 빠지고, 불일치 목록이 비어 있으면 ‘일치’로 표시합니다.

main 함수를 격리 실행한 결과 다음 경우를 재현했습니다.

| 재현 상황 | 현재 결과 |
|---|---|
| 일지에 매수·매도가 있지만 LEAN 체결은 0건 | ✅ 일치 — 일치 0 / 불일치 0 |
| 일지의 매도 체결이 LEAN에서 누락 | ✅ 일치 — 매수 1건만 비교 |
| LEAN에만 체결이 있고 해당 날짜의 일지는 없음 | ✅ 일치 — 비교 0 / 스킵 1 |

**확인 요청**

- [ ] 양쪽 기록을 기준으로 누락 체결 검사
- [ ] 비교 0건·비교 불가·불일치 구분
- [ ] 양방향 누락과 0건에 대한 판정 시험 추가
- [ ] 수정 후 기존 대사 보고서 재확인

### 1-2. LEAN에 전략 카드의 투자 비중이 전달되지 않음

- 관련: #433, #314, #497, #503
- 확인 요청: **강민석님**
- 체결 시점 비교 기준 협의: **이동원님**
- 위치: `app/services/lean_backtest.py`, `scripts/daily_lean_reconcile.py`

#433의 11월 3일 답변에서 카드의 `positionPct`를 연결하겠다고 했으나, main의 MA·momentum·buy_hold 생성 코드는 여전히 `set_holdings(..., 1)`을 사용합니다. 일일 대사 호출에도 카드 비중·위험 수량 전달이 없습니다.

과거 9월 29일 증거금 부족으로 첫 주문이 거절된 원인과 관련된 코드가 남아 있습니다. 이번 확인에서 LEAN을 새로 실행해 같은 주문 거절을 재현한 것은 아닙니다.

**확인 요청**

- [ ] 카드 비중과 비용 여유를 LEAN 실행에 반영
- [ ] 첫 주문 접수 여부와 카드 대비 수량 재검증
- [ ] #503의 체결 시점 정렬안은 채택 여부 또는 비교 한계 명시
