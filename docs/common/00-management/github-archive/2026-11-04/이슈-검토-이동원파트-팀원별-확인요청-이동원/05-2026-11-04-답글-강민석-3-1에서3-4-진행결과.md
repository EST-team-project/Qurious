- 최소 주문금액 정책은 기존과 동일하게 1,000원으로 유지했습니다.
- 서버의 `crypto_preview()`와 `crypto_buy()` 양쪽에서 1,000원 미만 주문 및 유효하지 않은 입력값을 검증하도록 반영했습니다.
- 프론트엔드 `paper.js`에도 동일한 기준을 적용했습니다.
- 테스트 결과:
  - 999원: Preview 거부
  - 999원: Buy 거부
  - 1,000원: Preview 통과
  - 1,000원: Buy 주문 생성 경로 통과(Mock)
- 실제 거래소 주문이 아닌 Mock 검증입니다.

**결과: 완료**

### 3-2. DSR 문구와 계산 가정 일치

- DSR 계산의 기본 `n_trials`를 50으로 명시하고 서비스 호출 경로에서 해당 값을 전달하도록 반영했습니다.
- Sharpe는 일별 기준으로 환산한 값을 DSR 계산에 전달합니다.
- `n_trials=50`은 실제 전략 시험 횟수를 측정한 값이 아니라 현재 계산에 사용하는 고정 가정임을 문서에 명시했습니다.
- 용어집의 `summary`, `definition`, `example`, `caution`, `app_note`를 계산 방식과 일치하도록 수정했습니다.
- 기존 공식, UI의 0.95 기준 및 표시 방식은 유지했습니다.
- JSON 유효성 검사와 `git diff --check`를 통과했습니다.

**결과: 완료**

### 3-3. LEAN 체결 시점 정렬 및 대사 (#503)

확인 요청에 대한 답변입니다.

1. **카드의 `positionPct` 전달 여부**
   - 현재 확인한 `scripts/daily_lean_reconcile.py`에서는 카드의 `positionPct`를 읽어 전달하지 않습니다.
   - `max_position_pct=30.0`을 고정값으로 전달하고 있습니다.
   - 따라서 카드 설정과 일일 대사의 포지션 상한은 현재 연결되어 있지 않습니다.

2. **구간별 비교 결과·건수 표시 형식**
   - `봉인 전 사후 계산`과 `봉인 후 전진 기록`을 별도 구간으로 구분하는 형식을 제안합니다.
   - 각 구간은 다음 항목으로 표시하면 좋겠습니다.
     - 전체 비교 건수
     - 일치 건수
     - 불일치 건수
     - 미확인·누락 건수
   - 기간과 데이터 기준일도 함께 표시하고, 아직 대조하지 않은 항목은 0건이 아닌 `미실시`로 구분합니다.
   - 이동원 님께서 이 형식에 맞춰 화면과 문서의 표시를 정리해 주시면 됩니다.

3. **기존 대조 결과**
   - 신호 비교 41/41 일치
   - 보유 상태 41/41 일치
   - 주문 12/12 일치
   - 체결 12/12 일치
   - 최대 가격 차이 0.0bp
   - 해당 결과는 기존 검증 구간의 결과이며, 이후 전진 기록 검증과는 구분합니다.

4. **추가 확인이 필요한 사항**
   - 이동원 담당인 그림자 일지 기대값 확인
   - Docker 재실행 대조
   - 위 두 항목은 아직 완료하지 않았으므로 후속 확인이 필요합니다.

5. **판 2 관련 확인**
   - 현재 확인된 일지 상태에서는 `card_ma_cross_20_60`과 `auto_default` 모두 판 1 기록만 확인됩니다.
   - 판 2의 생성 및 봉인 여부, 판 2 기준 비교 결과는 아직 확인되지 않았습니다.
   - 따라서 판 1의 기존 대조 결과와 판 2의 검증 결과를 혼합하지 않고 별도로 관리해야 합니다.
   - 판 2가 생성된 경우 봉인 전 사후 계산과 봉인 후 전진 기록을 구분하여 추가 대조가 필요합니다.

**결과: 기존 코드 및 검증 결과 확인 완료. 일지 기대값·Docker 재실행 대조는 후속 확인 필요.**
