## 3. 강민석 님께

**3-1. 코인 최소 주문금액 서버 검증**(#530 2-2)

- 근거: 서버는 0 초과만 검사합니다. `CryptoBuyBody.buyKrw` 가 `Field(..., gt=0)`(`app/routes/paper.py:218`), 매수 서비스는 `buy_krw <= 0` 일 때만 거절합니다(`app/services/paper_trading.py:941-942`). 1,000원 제한은 화면에만 있었습니다. 화면 쪽은 위 1-1 에서 맞췄습니다.
- 확인 요청
  - [ ] 1,000원을 이 앱의 정책값으로 유지할지
  - [ ] 서버에 최소 금액 상수를 한 곳(예: `ge=1000`)에 두고 화면 · 미리보기 · 매수가 같은 값을 쓰게 할지, 오류 문구도 한국어로 통일할지

**3-2. DSR 문구와 계산 가정의 일치**(#530 2-5 · #362)

- 근거: 시행 수는 `n_trials=50` 기본값으로 고정되어 있고 실제 시도 횟수와 연결되어 있지 않습니다(`app/services/performance_service.py:56`). 계산식은 `app/services/evaluation_risk.py` 주석에 기대 최대 Sharpe 근사식으로 적혀 있습니다.
- 확인 요청
  - [ ] 위 1-1 의 각주(「근사값」 · 「시도 횟수는 가정한 값」 · 「짧은 표본은 해석이 어렵다」)가 계산의 가정과 맞는지

**3-3. 체결 시점 정렬(#503) 이후**(#530 1-2)

- 근거: `9bb0fc2` 로 `fill_timing=next_open` 이 들어왔고 KRX `ma_cross` 일일 대사에만 쓸 수 있습니다(`app/services/lean_backtest.py:241-242`). 일일 대사 호출은 `max_position_pct=30.0` 과 `fill_timing="next_open"` 을 넘깁니다(`scripts/daily_lean_reconcile.py:194-195`). momentum · buy_hold 생성 코드는 아직 `set_holdings(self.asset, 1)` 입니다.
- 확인 요청
  - [ ] 카드의 `positionPct` 를 읽어 넘기는 것인지, 일일 대사의 30.0 이 고정값인지
  - [ ] 구간별(봉인 전 사후 계산 / 이후 전진 기록) 비교 결과 · 건수의 **형식**이 정해지면 알려 주세요. 이동원이 화면과 문서의 표시를 맞추겠습니다(#530 2-4)
  - [ ] 이동원 몫인 일지 쪽 기대값 확인과 도커 재실행 대조는 위 1-3 에서 아직 하지 않았다고 적었습니다. 결과는 #503 에 남기겠습니다

**3-4. `signals_yahoo.py` 임시 예외 만료**(#439 · #530 3절)

- 근거: 만료 2026-11-12 는 `tests/test_no_yahoo_regression.py` 주석에만 적혀 있고(`:103-105`) 날짜가 지나도 시험이 실패하는 **자동 만료 장치는 없습니다.** 같은 주석은 담당을 강민석 님으로 적고 앱 어디에서도 이 스크립트를 부르지 않는다고 적습니다.
