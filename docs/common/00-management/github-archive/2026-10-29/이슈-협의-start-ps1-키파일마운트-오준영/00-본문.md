### 무슨 일이 있나 (이동원 · 10-29 · 학원 PC 개발 환경에서 확인)
#397/#402 로 증권사 자격증명이 암호화되면서, 앱 · worker · beat 는 키 파일(`BROKER_CREDENTIAL_KEY_FILE`)을 읽기 전용 마운트로 받아야 합니다(운영 문서 `docs/phase-3/05-deployment/증권사-자격증명-암호화-운영.md`).

이 PC 개발 환경에서는 키 파일을 `secrets/broker/broker-credentials.json`(gitignore)에 두고, **PC 전용 덧씌우기 `scripts/personal/compose.local.yml`(gitignore)** 로 마운트를 줬습니다. 그런데 `scripts/personal/start.ps1` 은 `docker-compose.yml` + (개발 모드면) `compose.dev.yml` 만 읽습니다. 그래서:

- `start.ps1` 로 앱 컨테이너를 **다시 만들면** 마운트가 빠져, 증권사 설정 저장 · 조회가 `503 CREDENTIAL_STORAGE_UNAVAILABLE` 을 냅니다(키 누락 시 평문으로 우회하지 않고 막는 의도된 동작).
- 지금은 세 파일을 직접 겹치는 명령으로 다시 올리는 우회로 쓰고 있습니다:
  `docker compose -p qurious -f docker-compose.yml -f scripts/personal/compose.dev.yml -f scripts/personal/compose.local.yml up -d app`

### 여쭙고 싶은 것 (start.ps1 은 팀 공용 파일이라 코드는 건드리지 않았습니다)
1. 개발 PC 에서 키 파일 마운트를 어떻게 주고 계신가요? (`start.ps1` 이 알게 하는 방식이 이미 정해져 있으면 그대로 따르겠습니다.)
2. `start.ps1` 이 `scripts/personal/compose.local.yml` 이 **있으면** 자동으로 겹치게 하는 방안은 어떨까요? 없으면 지금과 똑같이 동작하므로 다른 PC 에는 영향이 없을 것으로 봅니다. 이 변경은 오준영 님 쪽에서 하시는 게 좋을지, 제가 PR 로 올릴지 정해 주세요.
3. 키 파일 위치(`secrets/broker/…`)와 `.gitignore` · `.dockerignore` 에 `secrets/` 를 넣은 것(PR #406)이 운영 문서와 어긋나지 않는지 확인 부탁드립니다.

회신 마감은 급하지 않습니다(이 PC 는 우회 명령으로 동작 중). 11-05 전에 정해지면 좋겠습니다.
