#415 확인 후 [PR #417](https://github.com/EST-team-project/Qurious/pull/417)로 수정했습니다.

| 문의 | 처리 내용 |
|---|---|
| 현재 키 제공 방식 | 제 운영은 저장소 밖에 원본 키를 보관하고 별도 볼륨을 `/run/secrets`에 읽기 전용으로 연결합니다. 앱·worker·beat·마이그레이션이 동일 키를 사용합니다. |
| start.ps1 보완 담당·방식 | 제가 수정했습니다. 일반 모드는 기본→로컬, 개발 모드는 기본→개발→로컬 순서입니다. 로컬 파일이 없으면 기존 동작을 유지합니다. |
| 개발 PC secrets 경로 | `secrets/broker/`와 #406의 Git·빌드 제외 방식은 개발 PC용으로 사용 가능합니다. 운영의 저장소 밖 보관과 구분해 문서에 명시했습니다. 기존 DB에 대응하는 키는 그대로 유지합니다. |

키 내용 없는 `compose.local.example.yml`도 추가했습니다. 기존 `compose.local.yml`을 덮어쓰지 말고 필요한 설정만 병합하면 됩니다. 로컬 설정을 사용할 때 읽기 전용 키 마운트와 host bind 파일 존재를 시작 전에 확인하며, 누락되면 컨테이너 생성 전에 중단합니다. Compose 원문과 키 내용은 출력하지 않습니다.

**검증:** 실제 PowerShell 5.1·격리 Docker 7시나리오 통과. 파일 유무와 두 모드, 세 서비스 설정 병합, 일반→개발→일반 재생성 후 같은 합성 키 복호화/읽기 전용 유지, 일회성 app 실행, 누락 키 차단을 확인했습니다. Docker Desktop의 누락 경로 생성도 관측해 사전 검사를 추가했습니다.

**현재 상태:** 수정·시험 완료, PR 검토 및 학원 PC 적용 확인은 남아 있습니다. 운영 DB나 실제 키를 변경한 작업은 아닙니다. 실행 방법은 README·암호화 운영 문서, 진행 상태는 일정표 §19.12와 ERR-020에 반영했습니다.
