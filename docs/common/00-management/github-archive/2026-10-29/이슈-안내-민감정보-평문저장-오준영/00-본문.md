10-29 에 가입 화면 약관 · 개인정보 동의 문구를 쓰려고 이 앱이 **무엇을 어떻게 저장하는지** 코드로 확인했습니다(조사: `docs/phase-3/01-analysis/research/배경조사/2026-10-29-가입-약관-동의/결과.md` D.2). 그중 증권사 쪽에 닿는 것입니다.

| 무엇 | 어디 | 사실 |
|---|---|---|
| 증권사 API 키 · 비밀키 · 계좌번호 | `app/models/trading.py:116-118`(`broker_settings.app_key` · `app_secret` · `account_no`) · `app/routes/stocks.py:490-516, 535-540` | 그냥 문자열 칸으로 저장. 코드에 **암호화가 없습니다**(암호화 라이브러리 사용 grep 0건). 화면에는 키 앞 4자만 보입니다 |

(이동원 몫 알림 설정도 같은 모양입니다 — 텔레그램 토큰 · 슬랙 웹훅 · SMTP 비밀번호 · 카카오/문자 API 키 · **휴대전화번호**가 `notification_settings` 에 평문이고, 응답에서 토큰 · 비밀은 `****` 로 가리지만 **전화번호는 가리지 않고** 돌려줍니다. 이쪽은 제가 고칩니다.)

### 왜 지금 말씀드리나
- 가입 약관 문구에 「암호화해 보관합니다」 라고 **쓸 수 없습니다**(사실이 아니라서). 그래서 약관에는 「서비스 데이터베이스에 저장됩니다(비밀번호 · 키 · 토큰은 화면에 일부만 표시)」 라고 사실대로 적었고, 이 문구는 `public/js/terms.js` 에 있습니다 — **저장 방식이 바뀌면 문구도 같이 바꿔야** 합니다(시험 TC-TM-03 이 「서비스 데이터베이스에 저장됩니다」 를 확인합니다).
- 지금은 **모의투자 키만 쓰고 실거래는 코드로 막혀 있어**(ADR-0001 · `QURIOUS_ALLOW_LIVE_TRADING` 기본 꺼짐) 당장의 피해 크기는 작습니다. 다만 DB 가 유출되면 키가 그대로 나오고, 3차 이후 실계좌 키로 바뀌면 문제가 커집니다.

### 의견 부탁 (오준영 님 몫 — 증권사 연동 설계 ADR-0004 와 이어짐)
1. **저장 시 암호화**(앱 비밀키로 대칭 암호화 · 읽을 때 복호화 · 기존 평문 값은 읽기 호환 후 다시 저장 때 암호화) — 마이그레이션이 필요합니다. 키 관리(환경변수)가 따라옵니다.
2. **저장하지 않기**(요청마다 입력 · 세션에만 보관) — 자동매매가 밤새 도는 흐름과 안 맞을 수 있습니다.
3. **3차에서는 그대로 두고 약관 문구로만 알리기**(지금 상태 · 모의 키 한정) — 후속 과제로 남깁니다.

어느 쪽이든 11-05 전 수요가 큰 시기라, **3번(알리기 + 후속)** 이 현실적일 수 있습니다. 정해 주시면 약관 문구와 점검표를 같이 맞추겠습니다. 답이 없으면 3번으로 두겠습니다.
