## How

- **Celery Beat 가 아니라 Windows 작업 스케줄러**에 올렸습니다. Beat 는 스택(Redis)이 떠 있을 때만 돕니다 — 수집기를 스택과 떼어 둔 이유(README 2절)와 같습니다. 팀이 스택을 늘 띄우기로 하면 옮기되 **둘 중 하나만** 남깁니다.
- 등록은 PowerShell `Register-ScheduledTask` 대신 **작업 정의 XML + `schtasks`** 입니다. Windows PowerShell 5.1 은 BOM 없는 UTF-8 스크립트를 ANSI 로 읽어 한글 설명이 깨집니다.
- 배당을 수정주가보다 **앞**에 두었습니다. 파생 단계 판정을 한 번만 하는데, 배당이 뒤면 "배당만 새로 온 날" TR 이 건너뛰어집니다(처음 초안의 결함 · 시험 `test_dividend_change_alone_runs_derived`).
- 공유 스위치(`QURIOUS_RAW_SHARING`)는 `.env` 가 아니라 러너가 `--upload` 실행의 export·upload 자식에게만 넘깁니다. private 확인 · xet 확인은 `upload()` 가 그대로 겁니다.

## Proof (트러블슈팅)

- **초안의 순서 결함** — 처음엔 배당을 수정주가 뒤에 두었습니다. 판정이 수정주가 직전에 한 번이라, 시세가 그대로이고 배당만 바뀐 날 TR 이 안 돌았습니다. 순서를 바꾸고 그 경우를 시험으로 박았습니다.
- **Windows 의 `os.kill(pid, 0)`** 은 살아 있는지 묻는 것이 아니라 그 프로세스를 **종료**시킵니다. 잠금의 생존 확인을 `OpenProcess` 로 했고, 시험이 자기 PID 로 확인합니다(죽으면 시험이 끝나지 못합니다).
- **수정주가는 닫힌 연도 파일도 바뀝니다.** 오늘을 1.0 으로 거꾸로 누적하므로 첫 실행에서 `price_adjusted` 7개 연도 파일이 전부 바뀌었습니다(50.6MB). `hf_dataset.py` 의 "닫힌 연도는 0바이트" 는 시세·TR 에만 맞습니다 — xet 가 바뀐 청크만 보내 업로드는 20초였습니다.
- 작업 스케줄러는 창 없는 `pythonw` 로 러너를 부르는데, 자식까지 `pythonw` 면 표준출력이 없어 로그가 빕니다 → 자식은 같은 폴더의 `python` 을 창 없이(`CREATE_NO_WINDOW`) 부릅니다.

## Learn

- "단계가 다 있다" 와 "데이터가 최신이다" 는 다릅니다. 이어 부르는 것이 없으면 **단계마다 다른 날에 멈춥니다.**
