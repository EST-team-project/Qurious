## 4. 함께 찾은 것 — DF-84

- **무엇**: `app/services/brokers/kis.py` 는 접근 토큰을 클라이언트 객체 안에만 들고 있고, 앱은 요청마다 클라이언트를 새로 만든다 → 요청마다 토큰을 새로 받는다.
- **왜 문제인가**: 증권사는 토큰 발급을 1분에 1회로 묶는다(오류 EGW00133 「접근토큰 발급 잠시 후 다시 시도하세요(1분당 1회)」 — 2차 출처 둘에서 확인 · 공식 포털 원문은 못 열었다). 같은 사용자가 1분 안에 잔고 · 시세 · 주문을 이어 부르면 둘째부터 막힐 수 있다.
- **지금 피한 방법**: 점검 KIS 묶음은 증권사 호출을 잔고 1회로 줄였다.
- **고치는 안(제안)**: 토큰을 앱 키별로 Redis 에 만료 시각과 함께 두고 만료 전에는 다시 쓴다(값은 기록 · 로그에 남기지 않음).
- 담당(제안): 오준영(3차 증권사 연동) — 2차 모의 주문에서 먼저 걸리면 강민석.
