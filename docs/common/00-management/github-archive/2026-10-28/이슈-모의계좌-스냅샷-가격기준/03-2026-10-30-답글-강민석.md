## #371 PAPER 계좌 일일 스냅샷 저장 및 배치 검증 결과

### 1. 작업 목적
PAPER 계좌의 일일 스냅샷 저장 구조를 점검하고, 불완전한 가격 데이터가 일일 수익률 계산에 잘못 반영되지 않도록 처리 기준을 확인했습니다.

### 2. 기존 문제 및 원인
- 기존 DB의 일일 스냅샷 일부가 `completeness=unknown`, `origin=unknown`으로 저장되고 있었습니다.
- 원인은 APP와 Celery Worker·Beat가 서로 다른 코드를 실행하고 있었기 때문입니다.
- APP는 소스 코드 바인드 마운트를 사용해 최신 코드를 읽었지만, Worker와 Beat는 구버전 Docker 이미지에 포함된 코드를 실행하고 있었습니다.
- 이에 따라 정기 배치에서 최신 스냅샷 메타데이터와 수익률 검증 정책이 반영되지 않았습니다.

### 3. 조치 사항
- `celery-worker`, `celery-beat` 이미지 재빌드
- Worker와 Beat 컨테이너 재시작
- APP·Worker·Beat의 주요 파일 SHA-256 비교
- 일일 스냅샷 수동 배치 실행
- DB 저장 결과 및 Worker 실행 로그 확인

### 7. 일일 수익률 초기화 정책 검증
기존 2026-10-29 스냅샷은 구버전 코드로 기록되어 다음과 같은 상태입니다.
- `completeness=unknown`
- `origin=unknown`

새 코드는 이전 스냅샷이 `complete`이고 `daily` 출처인 경우에만 일일 수익률을 연결합니다.

따라서 10월 30일 수익률을 0으로 초기화한 것은 의도된 동작입니다. 불완전하거나 출처가 확인되지 않은 과거 데이터를 기준으로 수익률을 계산하지 않도록 정상적으로 차단했습니다.

기존 과거 스냅샷은 삭제하거나 임의로 수정하지 않았습니다.
