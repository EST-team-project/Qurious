# [BUG] paper_journal pull 실패 — HF 원장 Parquet SHA-256 불일치

@dev-dongwon05253 확인 부탁드립니다.

## 1. 문제 현상

`python scripts/daily_lean_reconcile.py` 실행 시 HF 원장 pull 단계에서 실패합니다.

`python scripts/paper_journal.py pull`을 단독 실행해 확인한 결과, 토큰 설정 문제를 해결한 이후에도 `ValueError`가 발생합니다.

실패 상태 파일(`data/collector/state/paper_journal_pull_last.json`)에는 다음과 같이 기록됩니다.

- `state`: `error`
- `why`: `ValueError`
- `imported`: `0`

현재 `daily_lean_reconcile.py`는 하위 프로세스의 `stderr`만 출력하므로, 실제 예외 메시지가 `stdout`에 기록되는 경우 원인을 확인하기 어렵습니다.

## 2. 확인된 내용

`scripts/paper_journal.py`의 `_ledger_download()`는 HF 원장의 `manifest.json`을 읽은 뒤 각 파일의 SHA-256을 계산하여 manifest에 기록된 값과 비교합니다.

불일치하면 다음 예외를 발생시킵니다.

`ValueError: 원장 파일이 지문 목록과 다르다 — {rel}`

두 개의 임시 다운로드 디렉터리에서 확인한 결과, manifest에 등록된 76개 파일 중 68개 파일의 SHA-256이 일치하지 않았습니다.

대표 사례는 다음과 같습니다.

| 항목 | 값 |
|---|---|
| 파일 | `rows/auto_default/v1/2026-09-01.parquet` |
| 실제 파일 크기 | 16,927 bytes |
| manifest의 `bytes` | 16,927 |
| 실제 SHA-256 | `c6adc44750805ee4a73c4b909efad632487e9ede9b727b407dd69981f88b3726` |
| manifest의 `sha256` | `7574f48916356df2ee1630b84f6de67763f626c3f9bd027f8f22ba3c6ba0a009` |
| manifest의 `content_sha256` | `07278f8763f9ba4168237f99ec266ea0a58f5457965eebdacf86646b10d2fbc8` |

파일 크기는 일치하지만 실제 파일 바이트의 SHA-256은 manifest의 값과 다릅니다. 두 다운로드 디렉터리에서 다수의 파일이 같은 유형의 불일치를 보였습니다.

## 3. 관련 코드

### 다운로드 검증

`scripts/paper_journal.py`의 `_ledger_download()`에서 다음 검증을 수행합니다.

- HF 저장소의 특정 revision을 조회합니다.
- `snapshot_download()`로 해당 revision의 파일을 다운로드합니다.
- `manifest.json`에 기록된 파일별 SHA-256과 실제 파일의 SHA-256을 비교합니다.
- 불일치하면 `ValueError`를 발생시킵니다.

### 업로드 및 manifest 갱신

`cmd_upload()`에서는 `plan_upload()`를 통해 기존 파일의 `content_sha256`을 비교하고, 원격에 없는 파일만 신규 업로드 대상으로 선정합니다. 이후 `manifest.json`과 `README.md`를 갱신합니다.

이 구조에서는 기존 파일의 논리적 내용이 동일하더라도 Parquet 직렬화 결과가 달라질 경우, manifest의 `sha256`과 원격에 남아 있는 파일의 실제 바이트가 불일치할 가능성이 있습니다.

다만, 이 가능성이 현재 문제의 직접적인 원인인지는 추가 확인이 필요합니다.

## 4. 확인 요청 사항

1. 문제가 발생한 HF revision에서 원격 `manifest.json`과 실제 Parquet 파일의 SHA-256이 일치하는지 확인합니다.
2. 동일 revision을 기준으로 다운로드한 파일에서도 동일한 불일치가 재현되는지 확인합니다.
3. `write_export()`의 Parquet 직렬화 결과와 `cmd_upload()`의 기존 파일 업로드 제외 조건이 서로 일관적인지 확인합니다.
4. 기존 파일이 갱신되지 않은 상태에서 manifest만 갱신될 수 있는 경로가 있는지 확인합니다.
5. `daily_lean_reconcile.py`가 하위 프로세스의 `stdout`에 기록된 오류 메시지도 출력하도록 개선할 필요가 있는지 검토합니다.

## 5. 기대 동작

- HF 원장의 manifest와 실제 파일의 체크섬이 일관되게 유지되어야 합니다.
- 원장 파일의 무결성 검증에 실패하면 원인을 명확하게 확인할 수 있어야 합니다.
- 기존 파일을 재업로드하지 않는 경우에도 manifest의 체크섬이 원격 파일의 실제 바이트와 일치해야 합니다.

## 6. 영향 범위

현재 원장 pull 단계에서 실패하여 일일 LEAN 대조 작업을 정상적으로 진행할 수 없습니다.

원인을 확인하기 전까지 원장 export, 원격 upload 및 원격 데이터 변경 작업은 수행하지 않았습니다.

@dev-dongwon05253 원격 manifest와 실제 파일의 무결성부터 확인한 뒤, 업로드 및 manifest 갱신 로직을 검토해 주시면 감사하겠습니다.
