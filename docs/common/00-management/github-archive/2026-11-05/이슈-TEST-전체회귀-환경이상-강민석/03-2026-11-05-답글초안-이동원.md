강민석 님, 막혀 계신 것 확인했습니다. 결론부터 말씀드리면 **보이는 실패의 큰 줄기는 제품 코드 회귀가 아니라 WSL 의 Node v12 가 너무 낮아서**일 가능성이 높고, `INTERNALERROR` 는 **제 쪽 시험의 설계 문제**입니다. 이 PC(Windows · Node v24.22.1 · Python 3.13)에서는 두 시험이 모두 통과합니다. 리눅스(WSL)에서 직접 재현해 보지는 못했고, 아래는 코드와 이 PC 의 시험으로 확인한 것입니다.

**지금 바로 푸는 방법**

1. WSL 의 Node 를 22 이상으로 올려 주세요(예: `nvm install 22`). 하한 숫자는 제가 24 에서만 돌려 봐서 정확히 모르니, 22 이상을 권합니다.
2. 시험은 `PYTHONDONTWRITEBYTECODE=1` 을 붙여 돌리면 `__pycache__` 권한 문제를 피합니다.
3. `tests/test_api_docs.py` 의 임시 수정은 Node 를 올리면 필요 없으니 커밋하지 말아 주세요.
4. 그래도 남는 실패가 있으면 그것만 목록으로 달아 주세요. 그때부터가 진짜 회귀 후보입니다.

**조사 요청에 대한 답**

| 요청 | 확인한 것 |
|---|---|
| 1 · 2. 공식 Node 버전, 통일 여부 | **없었습니다.** `package.json` · `.nvmrc` · CI 가 없고 README 에도 Python 3.12 만 적혀 있습니다. 「바뀐」 것이 아니라 처음부터 문서가 없었고, 제 PC 는 Node v24.22.1 입니다. |
| 3 · 4. ES Module 호환성, 암묵적 전제 | **있습니다.** Node 를 부르는 시험이 53개 파일이고, 그중 34개가 `?.` · `??`(Node 14+ 문법)를 씁니다. 또 시험이 만든 `.mjs` 가 `public/js` 의 `.js`(91개가 `export` 사용, `package.json` 없음)를 `import` 하므로 Node 가 `.js` 안의 `export` 를 스스로 ESM 으로 알아보는 최신 기능에 기댑니다. 그래서 Node 12 에서 수십 건 실패가 나는 것은 자연스럽습니다. |
| A-②. `test_baseline_notice` | 제가 10-30 에 쓴 시험입니다. `.mjs` 안 최상위 `await` 가 Node 14.8 이상을 요구하는데 제가 문서에 적지 않았습니다. 시험 자체의 오류가 아니라 전제 누락입니다. |
| 5 · 6. `WindowsPath`, 전역 상태 오염 | **원인을 코드에서 찾았습니다.** `tests/test_schedule_until.py` 의 `_install` 이 `monkeypatch.setattr(du.os, "name", "nt")` 를 하는데, `du.os` 는 전역 `os` 모듈이라 프로세스 전체의 `os.name` 이 `"nt"` 가 됩니다(`cw` · `wr` 도 같고, `test_weekly_rehearsal.py` 에도 1곳). 윈도우에서는 원래 `nt` 라 드러나지 않았지만, 리눅스에서는 그 구간의 `Path()` 가 `WindowsPath` 를 만들려다 실패하고, 실패 보고서를 만드는 pytest 도 같은 오류로 `INTERNALERROR` 가 납니다. 이 시험들은 윈도우 작업 스케줄러를 흉내 내는 것이라 윈도우 전용이 맞습니다. 다만 리눅스에서 실제로 재현해 본 것은 아닙니다. |
| 7. `__pycache__` 권한 | 코드 문제는 아닌 것으로 보이지만 제 PC 에서는 확인할 수 없었습니다(`/mnt/c` 의 윈도우 쪽 폴더를 WSL 이 쓰는 권한 차이로 짐작하는 정도입니다). |
| 8 · 9. 재실행, 실패 목록 | 리눅스 환경이 없어 제가 만들 수 없습니다. Node 를 올리고 다시 돌린 뒤 남는 실패만 알려 주시면 회귀인지 환경인지 같이 가리겠습니다. |

**제가 올릴 작은 PR(제안)**

1. README(와 AGENTS)에 「시험은 Node 22 이상」 을 적고, `tests/conftest.py` 가 시험 머리에 Node 버전을 찍으며 낮으면 경고하게 합니다.
2. `os.name` 을 바꾸는 시험 9곳을 윈도우에서만 돌게(`skipif`) 합니다. 제품 코드는 건드리지 않습니다.

이 둘은 제가 맡겠습니다. 올리면 PR 번호를 이 이슈에 알려 드리겠습니다. 이슈에서 조사하신 범위(임의로 제품 코드를 고치지 않은 것, `paper.js` 작업과 분리한 것)는 그대로 좋았습니다.
