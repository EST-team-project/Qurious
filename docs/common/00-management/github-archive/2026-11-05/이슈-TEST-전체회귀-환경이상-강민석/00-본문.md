# [TEST] 전체 회귀 테스트 환경 이상 및 비작업 영역 다수 실패 원인 조사

## 배경
2026-11-05 전체 회귀 테스트 실행 중 다수의 테스트 실패(F)와 오류(E)가 발생했으며, 이후 pytest 자체에서 INTERNALERROR가 발생했습니다.

현재 진행 중인 작업 영역과 직접 관련 없는 기존 테스트에서도 실패가 확인되고 있습니다. 개별 기능을 임의로 수정하기 전에 테스트 환경, Node.js 호환성, 기존 테스트 코드 및 환경 설정의 변경 여부를 먼저 조사할 필요가 있습니다.

## 1. 실행 환경
- OS: Ubuntu / WSL
- Python: 3.10.12
- pytest: 8.3.3
- Node.js: v12.22.9
- Node 경로: `/usr/bin/node`
- 프로젝트 내 `package.json`, `.nvmrc`, `.node-version` 확인되지 않음

## 2. 확인된 문제

### A. Node.js ES Module 호환성

**① `tests/test_api_docs.py::test_core_merge_filter_one_op_and_hash`**

발생 오류:
- Node.js가 `api-docs-core.js`를 CommonJS로 해석
- `export const METHODS`에서 `SyntaxError: Unexpected token 'export'`

조치:
- 테스트 실행 시 원본 ES Module을 임시 `.mjs` 파일로 복사하도록 테스트 실행부 수정
- 단일 테스트 재실행 결과 통과(1 passed)
- 원본 제품 코드 변경 없음

**② `tests/test_baseline_notice.py::test_card_model_states_in_node`**

발생 오류:
- 기존 테스트에서 `const fs = await import("node:fs");` 사용
- Node.js 12.22.9에서 최상위 await를 지원하지 않아 `SyntaxError: Unexpected reserved word` 발생
- 해당 테스트는 2026-10-30 커밋 `937af603`에서 작성된 코드로 확인

현재 수정하지 않은 상태이며, 공식 Node.js 지원 버전과 테스트 실행 방식 확인 필요.

### B. Pytest INTERNALERROR

전체 회귀 테스트 실행 중 다음 오류 발생:

`NotImplementedError: cannot instantiate 'WindowsPath' on your system`

발생 위치:
- pytest 실패 보고서 생성 과정
- pytest 세션 종료 및 캐시 정리 과정

Linux 환경에서 `WindowsPath` 객체를 생성하려다가 발생한 것으로 확인됨.

현재 원인은 미확정이며, 테스트 또는 fixture에서 pathlib 경로 클래스가 변경되는지, 다른 테스트 간 전역 상태가 오염되는지 조사 필요.

### C. Python 컴파일 검사 권한 문제

기본 컴파일 검사:

`python3 -m compileall -q app tests scripts`

결과:
- 다수의 `__pycache__` 경로에서 PermissionError 발생

별도 캐시 경로를 지정한 검사:

`PYTHONPYCACHEPREFIX=/tmp/qurious-pycache python3 -m compileall -q app tests scripts`

결과:
- 통과(EXIT_CODE=0)

현재 확인된 것은 Python 문법 오류가 아닌 기존 캐시 디렉터리의 쓰기 권한 문제임.

## 3. 전체 회귀 테스트 현황

- 최초 전체 테스트 실행에서 다수의 F 발생
- 일부 구간에서 E 발생
- 20~50% 진행 구간까지 실패가 지속적으로 확인됨
- 정상적인 최종 테스트 요약 출력 전에 pytest INTERNALERROR 발생
- 최초 실패를 순차적으로 추적하면서 Node 호환성 문제 2건 확인
- 나머지 실패 원인은 미확정

## 4. 조사 요청 사항

1. 프로젝트에서 기존에 사용하던 공식 Node.js 버전과 현재 실행환경 비교
2. CI 및 개발환경의 Node.js 버전 통일 여부 확인
3. Node.js 버전별 ES Module 테스트 호환성 검토
4. 기존 테스트가 특정 Node.js 버전 또는 실행환경을 암묵적으로 전제하는지 확인
5. `WindowsPath`가 Linux 테스트 실행 중 생성되는 원인 추적
6. pytest fixture 및 테스트 간 전역 상태 오염 여부 확인
7. `__pycache__` 소유권 및 쓰기 권한 확인
8. 환경 문제 해결 후 전체 회귀 테스트 재실행
9. 실제 제품 코드 회귀와 테스트 환경 문제를 구분한 최종 실패 목록 작성
