# #567 이동원 확인 — 조사 요청 1~9 와 근거

## 한 줄 결론

## 두 Node 오류의 정체

- `test_api_docs` : `.mjs` 시험 스크립트가 `public/…/api-docs-core.js` 를 `import` → Node 12 는 `.js` 를 CommonJS 로만 읽어 `export` 에서 오류. **같은 원인이 91개 `export` 파일을 쓰는 다른 시험에도 해당**한다. 임시로 `.mjs` 복사하면 이 시험 하나만 지나간다.
- `test_baseline_notice` : `.mjs` 안의 최상위 `await`(Node 14.8+). 이 시험은 **내가 10-30 에 쓴 것**(`937af603`). 시험 자체의 잘못이 아니라 Node 전제가 문서에 없었다.
- 따라서 「다른 실패도 같은 Node 문제」 라고 **단정은 안 하되**, 34개 파일의 `?.`/`??` 와 91개 ESM 파일을 보면 **Node 12 에서 수십 건 실패가 나는 것이 오히려 자연스럽다**.

## INTERNALERROR(`WindowsPath`) — 메커니즘

- `tests/test_schedule_until.py` 의 `_install` 이 `monkeypatch.setattr(du.os, "name", "nt")` (cw · wr 도 같은 방식) — `du.os` 는 **전역 `os` 모듈 그 자체**라서 프로세스 전체의 `os.name` 이 `"nt"` 로 바뀐다. `tests/test_weekly_rehearsal.py:116` 도 같다. 해당 코드 8곳 + 1곳.
- 파이썬 3.10 의 `pathlib.Path(...)` 는 `os.name == "nt"` 이면 `WindowsPath` 를 만든다 → 리눅스에서는 `NotImplementedError: cannot instantiate 'WindowsPath'`. 그 구간에서 시험이 실패하면 **pytest 가 실패 보고서를 만들며 `Path` 를 부르다 같은 오류**로 INTERNALERROR 가 난다. 윈도우에서는 원래 `nt` 라 드러나지 않았다.
- 이 시험들은 윈도우 작업 스케줄러(`schtasks`)를 흉내 내는 것이라 **윈도우 전용**이 맞다.
- ⚠ 리눅스에서 재현하지 못했다(이 PC 는 윈도우). 「메커니즘이 코드에서 확인됨 · 재현은 안 함」 으로 말한다.

## `__pycache__` PermissionError

- 코드 문제 아님. 이 PC 에서는 확인 불가(WSL 이 `/mnt/c` 의 윈도우 쪽 파일/폴더를 쓸 때 권한 · 소유가 다른 것으로 짐작). **추정이며 확인 못 함**.
- 우회: `PYTHONDONTWRITEBYTECODE=1` 또는 `PYTHONPYCACHEPREFIX=/tmp/…` 를 시험 실행에 붙이면 된다(이미 쓰신 방식).

## 못 한 것 · 남은 불확실

- 리눅스 · Node 12 에서 실제로 몇 건이 어떤 이유로 실패하는지 목록은 **내가 만들 수 없다** (환경이 없다). 강민석 님이 Node 22 로 올린 뒤 재실행해 **남는 실패만** 제품 회귀 후보로 올리는 방식이 가장 빠르다.
- 공식 Node 하한: 어디에도 적혀 있지 않았다. 「공식 지원 버전이 있었는데 바뀐 것」이 아니라 **처음부터 문서가 없었다**(이 점은 내 쪽 책임).
