> 신호 순위 화면에는 필터를 달았고, 퀀트 카드에도 달았다. 그런데 **퀀트 대시보드 맨 위의 「관찰 목록 — 기록된 신호」 표에는 필터도 새로고침도 없었다.** 사용자가 스크린샷을 보여 주며 말했다. 「이런 곳을 세심하게 살펴보라는 거였다.」
> 그 뒤에 한 번 더 말했다. 「필터와 새로고침이 필요한 화면을 전체적으로 확인하고 구현하는 것이 중요하다.」

---

## 개념 정리

### 1. 요청이 한 화면을 말해도, 같은 데이터를 보이는 화면을 전부 본다

내가 푼 범위는 가장 좁았다. 내가 아는 화면 둘(신호 순위 · 일봉 규칙 카드)만 풀었고, 사용자가 실제로 가장 먼저 보는 표를 놓쳤다.

그래서 순서를 바꿨다.

1. `data-view` 로 화면 목록을 뽑는다 (77개).
2. 화면마다 목록 · 표 · 카드가 있는지, 필터와 새로고침이 있는지 본다.
3. 필요한 곳을 표로 만들어 사용자에게 보여 준 뒤 구현한다.

점검 결과 필요한 곳은 약 20곳이었다. 읽기 전용 조사 에이전트가 표를 만들었고, 요약은 `docs/_local/화면-필터-새로고침-점검-2026-11-05.md` 에 두었다.

🔑 같은 요청이 다시 오면 「이번에는 어디까지 넓히는가」부터 말한다. **화면 하나가 아니라 같은 데이터를 보이는 모든 화면**이 범위다.

### 2. 공용 도우미 하나에 화면마다 얇게 붙인다

약 20곳에 각자 다른 필터를 만들면 모양이 제각각이 된다. `public/js/listbar.js` 하나를 두고, 화면 파일은 DOM 을 얇게 붙이는 방식으로 갔다. 칩의 모양과 새로고침 단추의 위치가 모든 화면에서 같아졌다.

묶음은 이렇다.

| 묶음 | 화면 | 칩의 예 |
|---|---|---|
| 퀀트 | 관찰 목록 표 · 일봉 규칙 카드 | 신호 |
| 모의투자 | 국내주식 · 코인 · 대체자산 · 계좌 현황 | 매매 · 출처 · 구분 |
| 자동매매 | 현황 · 의사결정 | 회차 · 신호 · 로그 종류 |
| 실행 · 알림 | 실주문 · 알림 발송 이력 · 리밸런싱 이력 등 | 상태 · 환경 · 트리거 |
| 미국 · 직접매매 | 미국 주문 · 종목 카드 등 | 매수/매도 · 크게 오름/내림 |

시험은 묶음마다 TC-LB · PLB · ATL · LBS · LBR · LBT · LBF · LBM 으로 나눠 붙였다. 화면 파일을 읽는 시험 109개 파일이 실패 0이었다(에이전트 확인).

🔑 같은 모양이 반복되면 **도우미를 먼저 만들고** 화면은 그 위에 얇게 얹는다.

### 3. 새로고침은 「무엇을 다시 하는가」부터 정한다

「새로고침」은 화면마다 뜻이 달랐다.

| 뜻 | 예 |
|---|---|
| 서버에서 기록을 다시 읽기 | 관찰 목록 · 이력 표 |
| 지금 가격을 붙이기 | 카드 (S206 의 (b)) |
| 다시 계산하기 | 신호 판단 — 일지 지문 대상이라 11-12 전에는 하지 않는다 |

화면마다 어느 뜻인지 PR 표의 「새로고침의 뜻」 칸에 적었다. 주문이나 발송을 부르는 화면은 **다시 읽기만** 하게 했다. 새로고침이 주문을 내면 안 된다.

🔑 새로고침을 만들기 전에 **다시 하는 일이 무엇인지**를 한 줄로 적는다. 적을 수 없으면 단추를 달 때가 아니다.

### 4. 단추만 달면 같은 저장본이 되돌아온다 — macro 의 `?refresh=true`

거시 · 산업 · 미국 세 화면은 서버가 야후에서 받은 값을 `data_cache` 에 최대 2시간 저장해 둔다. 단추만 달면 눌러도 **같은 저장본이 돌아와서 「눌러도 안 바뀐다」** 가 된다. 서버를 고칠 수밖에 없었다(`app/routes/macro.py` 하나).

세 라우트(`/indicators` · `/industry` · `/us-stocks`)에 `refresh` 인자를 더했다.

| 규칙 | 이유 |
|---|---|
| 저장본 한도를 2시간에서 **60초**로 줄인다 | 연타해도 야후를 연달아 부르지 않는다 |
| 60초 안에 받은 값은 그대로 쓴다 | 위와 같다 |
| 받은 값이 **전부 비면** 저장본을 덮어쓰지 않고 이전 저장본을 돌려준다 (`refresh.failed`) | 한 사람의 새로고침이 모두의 화면을 비우지 않게 |
| 메뉴로 들어올 때는 평소 저장본 | 눌렀을 때만 우회 |

응답에는 `refresh: {requested, reused_cache, min_age_seconds, failed?}` 를 넣어 화면이 안내 글(「60초 안에 받은 값이라 그대로」)을 보여 줄 수 있게 했다. 시험은 TC-MR-01~06 이다.

🔑 우회 인자를 열 때는 **실패했을 때 남이 쓰는 저장본을 지키는 것**까지 같이 만든다. 한 사람의 새로고침이 다른 사람의 화면을 비우면 안 된다.

### 5. 신장환 님이 실제 화면에서 눌러 본 결과가 버그 둘을 찾았다

퀀트 카드 필터를 신장환 님이 로그인한 실제 화면(1280 · 390)에서 눌러 보고 두 가지를 알려 주었다.

1. 필터를 건 채 「나머지 접기」 를 누르면 카드는 줄지만 「n개 일치」 글은 그대로다.
2. 관찰 목록 31종목이 모두 `.KS` 라서 KOSDAQ 칩은 항상 0개다.

코드를 열어 둘 다 맞는 지적임을 확인했다. 고친 것은 필터 중 「나머지 접기」 단추를 숨기는 것, 시장 칩은 목록에 시장이 둘 이상일 때만 보이게 하는 것이다. 시험 TC-SCD-18 · 19 를 더했다. 신호 순위 화면의 KOSDAQ 필터는 서버 필터라 별개로 정상이다(181종목).

🔑 내 시험은 **가짜 DOM**에서 통과했다. 실제 화면에서 눌러 본 사람이 찾은 버그였다. 구현 뒤에는 화면을 눌러 프레임으로 확인한다.

## 직접 해 본 것

- 관찰 목록 표(신호 필터 · 새로고침 · 필터 유지)와 거시 · 산업 · 미국 새로고침을 실제 화면에서 눌러 확인했다. macro 는 서버 변경이 반영되어 「60초 안에 받은 값이라 그대로」 안내가 떴다.
- 나머지 화면은 구현 에이전트가 프레임과 390px 로 확인한 결과를 받았다. 지문 대상 조각을 건드리지 않았고 `paper_journal.py daily --dry-run` 에 `version_would_change` 가 없었다.
- 팀원 소유 화면 파일(`paper.js` 강민석 · `quant.js` 신장환 · `robo.js` · `settings.js` · `rebalance.js` 오준영)에는 UI 만 더하고 백엔드 로직은 건드리지 않았다. 안내 이슈 초안을 썼다.
- 같은 날 팀 전체 3차 영상 후보를 조사시켰다. 강민석 님 영상 B 는 화면 문구가 서버 동작과 어긋나 촬영할 수 없다는 것을 확인했고(코드 대조: 실행 · 삭제는 백테스트 전용 장부만 건드리는데 화면 안내는 모의 계좌까지 초기화한다고 한다) 사용자가 이슈 #559 로 올렸다.
- 오준영 님 #561 답글을 코드와 대조했다. 보유 중 가격 조정 사건을 감지하면 추가 진입과 자동 청산을 보류한다는 설명은 `strategy_v2_execution.py` · `strategy_v2.py` 와 일치했다.

## 막힌 것 · 남은 것

- **실제 보유 · 체결 · 이력으로 채운 표는 가짜 응답으로만 봤다.** 미국 주문 · 직접매매 · LEAN 이력 · 감사 로그 · 모의투자 표가 그렇다.
- 칩은 **받은 줄 안**만 거른다. 서버가 자르는 곳(감사 로그 100 · LEAN 이력 15 · 주문 내역 200 · 실주문 30)은 그 안에서만 거른다. 안내 글에 밝혔다.
- 지표 비교와 업종 카드는 서버가 5분 저장본을 주어서 새로고침해도 5분 안에는 같은 값이다. 우회 인자는 이 PR 에 없다.
- 새로고침 단추가 늘어 안내 글이 길어진 곳이 있다. 다듬을 후보로 남겼다.
- `paper.js` 는 강민석 님 #559 와 같은 파일이다. 문구 3곳은 이 PR 이 건드리지 않았으니 충돌하면 강민석 님 쪽을 따른다.

## 배운 것

1. **요청은 가장 좁게 풀면 틀린다.** 같은 데이터를 보이는 화면이 몇 곳인지 먼저 센다.
2. **반복되는 모양은 도우미 하나로 묶는다.** 20곳을 따로 만들었다면 지금쯤 모양이 달랐을 것이다.
3. **새로고침의 뜻은 화면마다 다르다.** 다시 읽기 · 지금 값 · 다시 계산을 구분하고, 주문을 부르는 화면에는 다시 읽기만 허락한다.
4. **서버의 저장본이 단추의 효과를 지울 수 있다.** 우회 인자는 실패 때의 보호와 함께 연다.
5. **가짜 DOM 시험은 실제 화면을 대신하지 못한다.** 신장환 님이 눌러 보고서야 버그 둘이 나왔다.
