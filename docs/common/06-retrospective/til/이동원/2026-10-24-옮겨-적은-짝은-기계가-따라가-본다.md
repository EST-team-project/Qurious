## 배운 것

- **사람이 옮겨 적은 대응은 기계가 다시 따라가게 둔다.** 31건 짝은 이름이 거의 같아 눈으로는 맞아 보였다. 그래서 점검을 「번호 꼴」 에서 멈추지 않고 「그 자리에 정말 이 요구가 있나」 까지 따라가게 했고, 대장을 일부러 한 줄 밀어 적어 「RA-006 가 겹친다」 · 「#3 은 P01-①-1 의 기준이다」 로 잡히는 것을 봤다.
- **어제 적은 「칸을 더해도 깨지지 않는다」 는 반만 맞았다.** 읽는 쪽(`csv.DictReader`)은 그대로였지만, 형식 점검이 머리 줄을 18칸으로 고정해 두어 옛 스캐너는 새 대장에서 「머리 줄이 다르다」 로 실패했다. 칸을 더하는 일은 읽는 쪽과 점검하는 쪽을 함께 본다 — 결정 대장에도 바로잡음을 적었다.
- **팀원 PR 은 받자마자 「무엇이 들어왔나」 부터 센다.** #329 는 코드 셋 · 시험 셋에 더해 런타임 출력 폴더(28MB · Yahoo 가격 CSV)와 백업 파일 넷을 공개 main 에 넣었다. 기본 출력 경로가 `.gitignore` 밖이면 `git add` 한 번에 올라간다. 우리 PR 에서 지우면 그분 PC 의 실행 결과까지 pull 때 지워지므로, `--cached` 로 빼는 방법을 적어 그분께 드렸다.
- **세는 도구는 서식을 벗기고 센다.** 결함대장 상태 칸 하나가 굵은 글씨(`**닫힘**`)라 기계 셈이 닫힘을 하나 덜 셌다 — 세 갈래 합이 줄 수(146)와 안 맞는 것을 보고 찾았다.
