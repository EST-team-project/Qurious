# 저울의 바늘이 눈금판 뒤에 숨어 있었다 — 주문 0건으로 요율을 잰 날

> 2026-09-21 (월) · Qurious 2.0 · [#51](https://github.com/devlee328288/Qurious/issues/51)
> 관련 PR: 아래 「무엇을 고쳤나」

## 한 줄

**네 세션을 미룬 "장중에 주문을 내서 요율표를 검증한다" 는 계획은, 주문을 한 건도 내지 않고
끝났다.** 재야 할 것이 애초에 주문 결과가 아니었기 때문이다.

---

## 1. 미뤄 온 일

우리 코드에는 매매비용 요율표(`app/services/trading_cost.py`)가 있다. 수수료·증권거래세·
농특세를 계산해 백테스트와 주문 정산에 쓴다. 그런데 **이 값이 실제와 맞는지 한 번도 확인한
적이 없었다.** 확인하려면 증권사가 실제로 뗀 금액을 봐야 하고, 그러려면 주문을 내야 하고,
주문을 내려면 장이 열려야 한다 — 그래서 주말마다 "월요일에" 로 밀렸다. 네 번.

그 사이 S38 에서 전제를 먼저 따져 봤고([#51](https://github.com/devlee328288/Qurious/issues/51)),
**모의투자 체결로는 요율표를 검증할 수 없다**는 결론이 나왔다. 모의 환경은 수수료를 실전과
다르게 계산할 자유가 있다. 그러니 월요일에 할 일은 "검증" 이 아니라 세 가지로 바뀌었다.

1. 관측 장치 수리
2. 주문 0건 확인
3. 배관 확인

## 2. 저울이 고장 나 있었다

체결 조회는 이렇게 생겼다.

```python
body = self._check(r.json(), "체결 조회")
rows.extend(body.get("output1") or [])     # ← output1 만 모은다
```

그리고 제비용을 이렇게 읽었다.

```python
fee_raw = str(row.get("prsm_tlex_smtl", "")).strip()   # row 는 output1 의 한 줄
```

**`prsm_tlex_smtl`(추정제비용합계)은 `output1` 에 없다.** KIS 응답은 두 칸으로 나뉘는데,
`output1` 이 주문별 목록이고 `output2` 가 조회 범위 전체의 요약이다. 제비용은 요약 쪽에 있다.

```
응답
├── output1  [ {주문1}, {주문2}, … ]   ← 우리가 모으던 곳. 제비용 없음
└── output2  { tot_ord_qty, tot_ccld_qty, tot_ccld_amt,
               prsm_tlex_smtl,          ← 여기 있었다
               pchs_avg_pric }
```

즉 **주문을 냈어도 화면에는 "제비용 미제공" 만 떴을 것이다.** 실계좌로 바꿔도 같았다.
버리는 쪽이 코드였기 때문이다. 네 세션을 기다린 실험은, 했어도 아무것도 재지 못했다.

> **용어 — `prsm_tlex_smtl`**
> `prsm` 추정(presume) · `tlex` 제비용(total expense) · `smtl` 합계(sum total).
> **이 문서에서는** 증권사가 "이 거래에 이만큼 뗀다" 고 알려 주는 금액을 말한다.
> **헷갈리는 점**: 강사님 카탈로그의 한글 라벨은 이 칸을 "총체결금액" 이라 적어 두었다.
> 필드명과 어긋난다. 라벨이 아니라 필드명을 따랐고, 오늘 그 판단이 맞았음이 확인됐다.

## 3. 주문 없이 눈금을 확인하다

고친 뒤, **체결이 0건인 날**로 조회했다. 주문을 내지 않았으니 값은 전부 0 일 것이다.
그런데 0 이 나온다는 것 자체가 증거가 된다 — **칸이 거기 있어야 0 이라도 나온다.**

```
― 요약 칸(output2) ―
  총주문수량 0 · 총체결수량 0
  총체결금액 0 · 매입평균가 0.00
  🟢 추정제비용합계(prsm_tlex_smtl) = 0.00 원  ← 칸이 output2 에 있음이 확인됐습니다
  원문: {"tot_ord_qty":"0","tot_ccld_qty":"0","tot_ccld_amt":"0",
         "prsm_tlex_smtl":"0","pchs_avg_pric":"0.0000"}
```

체결 0건 · 비용 0원 · 주문 0건으로 **필드 위치가 🟡 추정에서 🟢 확정으로** 바뀌었다.

## 4. 수수료율도 주문 없이 나왔다

두 번째 질문은 "모의투자는 수수료를 떼는가" 였다. 이것도 체결을 봐야 알 것 같았는데,
**매수가능조회**로 풀렸다. 이 조회는 "이 가격이면 몇 주까지 살 수 있나" 를 증권사가
계산해 준다. 그 계산 안에 수수료가 이미 들어가 있다. 거꾸로 풀면 요율이 나온다.

```
최대매수수량 = floor( 주문가능현금 / (주문단가 × (1 + 수수료율)) )
```

수량이 **내림**되므로 요율이 한 점으로 떨어지지는 않고 구간으로 나온다. 단가를 낮출수록
수량이 커지고 구간이 좁아진다.

| 단가 | 미수 없는 수량 | 역산 구간 |
|---|---|---|
| 269,000원 | 36주 | (-0.030%, +2.747%] |
| 26,900원 | 369주 | (-0.030%, +0.241%] |
| 2,690원 | 3,698주 | (-0.003%, +0.024%] |
| **269원** | **36,988주** | **(-0.0004%, +0.0023%]** |

마지막 줄에서 갈렸다. 수수료 0원이면 36,988주, 실전 요율(0.017693%)이면 36,982주 —
**6주 차이.** 실측은 36,988주였다.

```
교집합: f ∈ (-0.00000412, +0.00002292]
🟢 모의 수수료는 0원입니다. 구간이 0 만 품고 실전 요율은 배제됩니다.
```

상한 0.0023% 는 실전 요율의 **1/8** 이다. 0 과 실전 요율 중 하나만 남는다.

## 5. 한 번 더 틀렸던 곳

처음에는 `max_buy_amt`(최대매수금액)로 역산했다. 결과가 **-80%** 라는 말이 안 되는 값이
나왔다. 원문을 보니 이랬다.

```
단가 269,000 → max_buy_amt 50,000,000
단가  26,900 → max_buy_amt 50,000,000
단가   2,690 → max_buy_amt 50,000,000    ← 단가가 바뀌어도 그대로
```

`max_buy_amt` 는 **미수·증거금을 포함한 한도**라서 고정값이었고, 수수료가 애초에 들어가지
않는다. 써야 할 칸은 `nrcvb_buy_qty`(미수 없는 매수 수량)였다. 이쪽은 `floor(주문가능현금 /
단가)` 와 정확히 맞아떨어졌다.

**말이 안 되는 값이 나온 것이 다행이었다.** -80% 는 누가 봐도 틀렸으니 모형을 다시 봤다.
만약 0.02% 쯤 되는 그럴듯한 값이 나왔다면 그대로 믿고 기록했을 것이다.

## 6. 무엇을 고쳤나

| 파일 | 무엇 |
|---|---|
| `app/services/brokers/base.py` | `FillSummary` 신설 — `output2` 를 담을 그릇. 주문별 값이 아님을 자료형 설명에 못 박았다 |
| `app/services/brokers/kis.py` | `get_daily_fills_with_summary()` 로 `output2` 회수. 기존 `get_daily_fills()` 는 래퍼로 남겨 인터페이스 유지 |
| `scripts/sync_fills.py` | 요약 칸 출력 · 합계 대조 · 허용오차 상수화 · **"한 건도 대조 못 했다" 를 말하게** 했다 |
| `scripts/probe_kis_fee_rate.py` | 신설 — 주문 없이 요율을 역산한다 |

`sync_fills.py` 의 마지막 항목은 따로 적어 둘 만하다. 예전에는 일치 0건 · 불일치 0건이면
**아무 말 없이** 끝났다. "검증했고 통과" 와 "검증 자체를 못 했다" 가 화면에서 같아 보였다.

## 7. 아직 모르는 것

- 🔴 **실전 요율은 여전히 못 쟀다.** 실계좌 매수가능조회를 1회 해봤으나(승인 후 · 주문 0건)
  예수금이 0원이라 수량이 0으로 나와 역산이 불가능했다. **입금하면 조회 1회로 확정된다** —
  주문도, 체결도 필요 없다는 것이 오늘의 소득이다.
- 🟡 "추정제비용" 의 **"추정"** 이 무슨 뜻인지 모른다. 장중값과 마감 후 값이 다른지도.
- 🔴 수수료·유관기관비에 **시행일 구조가 없다.** 2016년 거래에 2025년 요율이 붙는다.

## 8. 배운 것

**측정할 수 없다고 생각한 것이 실은 측정 장치가 고장 난 것이었다.**

네 세션 동안 "장이 열려야 한다" 고 믿었다. 실제로 장이 열려야 했던 부분은 없었다.
필드 위치는 빈 응답으로 확인됐고, 수수료율은 조회 한 번으로 역산됐다. 기다린 것은
**실험 조건이 아니라 내 가정**이었다.

그리고 하나 더 — **0 이 나오는 것도 데이터다.** 체결 0건 응답에서 `"prsm_tlex_smtl":"0"` 을
본 순간 질문이 닫혔다. 아무 일도 일어나지 않은 상태를 관측하는 것이, 일을 벌여서 관측하는
것보다 빠를 때가 있다.

모의 수수료가 0원이라는 결론은 **모의 도메인에 한정**되며, 실전 요율을 대신하지 않는다.
