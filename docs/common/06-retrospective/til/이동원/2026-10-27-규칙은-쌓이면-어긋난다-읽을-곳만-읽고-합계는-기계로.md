## 한 일

- 세션 규칙 전문(585줄 · 202KB)을 주제 열네 갈래 표로 옮겨 정리본을 만들었다. 매 세션 붙이는 요약 블록에 개정으로 뒤집힌 항목이 다섯(작업 수 · 채팅에 보이는 범위 · 다른 영역 · 에이전트 수 · 강사님 자료 점검)이라는 것을 찾았고, 「한 세션 한 작업」 은 「관련 작업 2 ~ 3개 묶음 + 밀림 금지」 로 정했다.
- `_git-drafts` 에 지금과 바로 앞 세션만 둔다는 규칙이 지켜지지 않아 쌓인 폴더 여덟 개를 복사 → 해시 확인 → 휴지통 세 단계로 정리했다(도구 48 보존 · 90 휴지통).

## 배운 것

- **「전부 옮기기」 와 「읽히게 줄이기」 는 다른 일이다.** 규칙 574개를 하나도 빠뜨리지 않고 옮겼더니 정리본이 253KB 로 원문(202KB)보다 커졌다. 읽을 곳은 부딪힘 · 잊히기 쉬운 규칙 · 체크리스트 · 블록 대조 85줄뿐이다. 검색용과 읽는 용을 한 파일 안에서 절로 나누고 「어디부터 읽나」 를 맨 앞에 적는다.
- **지켜야 할 규칙은 기억이 아니라 세션 끝 체크리스트에 넣는다.** 「초안 폴더에는 지금과 앞 세션만」 은 이미 있던 규칙인데 열 세션 넘게 지켜지지 않았고, 요약 블록에는 아예 없었다. 오늘 이 TIL 도 같은 까닭으로 10-27 분이 비어 있었다 — 세션 끝 확인 일곱 줄 가운데 1번(형상 · TIL)을 건너뛴 것이다.
- **다시 잰 숫자는 한 곳이 아니라 같은 숫자가 든 줄 전부를 찾아 고친다.** 표 5 머리말과 제목은 고쳤는데 합계 줄(191파일 · 2690)을 놓쳤다가, 표 줄의 합을 스크립트로 세어 어긋남을 찾았다. 합계는 줄 수와 합을 기계로 대조한다.
- **종료코드는 어느 명령의 것인지 본다.** `A && B; echo $?` 에서 A 가 실패하면 B 는 돌지도 않는데, 종료코드 1 이 시험(B)의 것처럼 읽혔다. 시험을 따로 한 줄로 돌려 통과를 확인했다.
- **PR 본문의 말도 변경 파일 목록으로 대조한다.** #353 본문은 「산출물목록 판 칸이 v0.4」 라고 했지만 바뀐 파일에 산출물목록이 없었다. 본문의 「했다」 는 `git diff --stat` 로 확인한 뒤 받는다.
- **두 PR 이 같은 파일의 다른 줄을 고치면 내 판을 보관 → 기준판으로 되돌림 → 앞으로 감기 → 3-way 합치기로 받는다.** 이번에는 시험-요구 대장 한 곳이었고 `git merge-file` 이 충돌 0 으로 끝냈다.
