# 힌트를 그대로 믿었으면 1,881건이 부서졌다 — 벤치마크를 스스로 만든 날

> 2026-09-21 (월) · Qurious 2.0 · 벤치마크 지수 자체 계산 + HF 백업 경로
> 관련 PR: `feat/benchmark-and-hf-backup`

## 한 줄

**우리 데이터로 코스피를 다시 만들었더니 공식값과 평균 0.066% 차이로 맞았다.** 그런데 그
과정에서, 옳아 보이는 보정 규칙 하나가 **멀쩡한 1,881건을 부술 뻔했다.**

---

## 1. 왜 벤치마크를 직접 만드나

전략이 좋은지 나쁜지는 **무엇과 비교하느냐**로 정해진다. 코스피가 20% 올랐는데 내 전략이
15% 벌었다면 그건 진 것이다. 그래서 백테스트에는 기준선이 반드시 있어야 한다.

문제는 **KRX 공식 지수를 쓸 수 없다**는 것이다. 우리가 접근 가능한 소스는 약관 검토를 거쳐
두 곳으로 줄었고(#23 · #33), 거기에 지수 시계열이 없다. 그래서 **가지고 있는 종목별 시세로
지수를 다시 만들기로** 했다.

```
price_daily (4,460,710행)  →  benchmark_index (19,776행)
  종목 × 날짜                   시장 × 계열 × 날짜
                                KOSPI·KOSDAQ·KONEX × PR·TR·TRN·EW = 12계열
```

> **용어 — PR · TR · TRN · EW**
> - **PR**(Price Return) 가격만. 배당을 빼고 본 수익
> - **TR**(Total Return) 배당까지 재투자했다고 보는 수익
> - **TRN**(TR Net) 배당소득세를 뗀 뒤의 TR
> - **EW**(Equal Weight) 시가총액이 아니라 **모든 종목에 똑같이** 투자한 지수
>
> **이 문서에서는** 전략과 비교할 기준선을 말한다. 보통 PR 과 비교하지만, 배당을 받는
> 전략이라면 TR 과 비교해야 공정하다.
> **헷갈리는 점**: 뉴스에 나오는 "코스피 지수" 는 PR 이다. 배당이 빠져 있어서, 장기
> 백테스트를 PR 과 비교하면 내 전략이 실제보다 좋아 보인다.

## 2. 맞는지 어떻게 아나

공식 연말 종가 6개와 맞대어 봤다.

| 기준일 | 공식 | 재현 | 오차 |
|---|---|---|---|
| 20221229 | 2236.40 | **2236.41** | 0.0004% |
| … 6점 평균 | | | **0.066%** |
| … 최대 | | | 0.166% |

일별 등락률이 **소수 둘째 자리까지** 맞았고, 2026-07-31 의 +17.91%(역대 최대 상승)도
그대로 재현됐다. 🟢

그런데 **코스닥은 평균 0.871%** 로 13배 어긋난다. 이건 아직 못 고쳤다(7절).

## 3. 편입 규칙 — 빼는 게 늘 좋은 건 아니다

지수에 무엇을 넣을지부터 정해야 했다. 상식적으로는 "보통주만 넣고 우선주·리츠·인프라펀드는
뺀다" 가 맞아 보인다. 실제로 해봤다.

| 편입 규칙 | 코스피 평균 오차 |
|---|---|
| **우선주만 제외** (현행) | **0.066%** 🟢 |
| + 리츠 제외 | 0.167% (2.5배 나빠짐) |
| + 인프라펀드까지 제외 | 0.230% (3.5배 나빠짐) |

**스팩·리츠·인프라펀드를 KRX 가 코스피에 넣고 있었다.** 뺄수록 멀어진다 — 빼는 항목을
하나씩 더할 때마다 오차가 단계적으로 커진다.

덤으로 좋은 일이 생겼다 — 리츠·인프라펀드를 가리려면 종목명으로 판단해야 했는데(이름에
"리츠" 가 들어가는지), 그 필터가 통째로 사라졌다. **'617종목이 이름을 바꿨다' 는 함정도
같이 사라졌다.** 이름으로 자산을 분류하는 규칙은 언제 깨질지 모른다.

## 4. 그리고 치명적인 한 건

계산해 보니 코스닥에 이상한 날이 있었다. **2026-02-09 하루에 +3.060%p** 가 한 종목에서
나왔다.

```
제일바이오 052670
  2026-02-06  종가   2,080원   상장주식수 29,129,064
  2026-02-09  종가 625,000원   상장주식수     19,419
                    ↑ 300배        ↑ 1,500 : 1 감자
```

**1,500주를 1주로 합친 것이다.** 회사 가치는 그대로고 주식 수가 줄었으니 주당 가격이 오른
것뿐인데, 조정계수가 이 사건을 놓쳐서 지수에는 **+29,948% 짜리 폭등**으로 들어갔다.

왜 놓쳤나 — 조정계수는 `vs`(기준가)를 보고 판단하는데, **거래정지 중이라 `vs` 가 0** 이었다.
0 이면 계산이 안 되니 계수 1.0(=조정 없음)이 된다. 이걸 「아이엠텍 사각지대」라 부른다.

그 결과 코스닥 지수에 **가짜 +3.060%p 가 영구히 각인**돼 있었다. 고치니:

```
KOSDAQ PR  1261.84  →  1225.78
```

## 5. 힌트를 그대로 믿었다면

이걸 어떻게 잡을까. 가장 자연스러운 발상은 **"가격비가 주식수비와 맞아떨어지면 감자다"** 이다.

```
ρ = 오늘가격 / 어제가격    c = 어제주식수 / 오늘주식수
ρ ≈ c 이면 감자 → ρ 대신 ρ×c 를 쓴다 (1 에 가까워진다)
```

제일바이오는 ρ=300.5, c=1500 이라 이 규칙에 잘 걸린다. **여기서 멈췄으면 큰일 날 뻔했다.**
전 구간에 적용해 보니:

| 조건을 빼면 | 무엇이 부서지나 |
|---|---|
| ② 주식수 변화 조건 없음 | **진짜 폭락**을 건드린다. 카프로 −94.9% · 에코바이브 −97.7% 는 주식수가 안 변한 실제 등락이다 |
| ③ 가격제한폭 조건 없음 | **상한가·하한가 날**을 부순다. 104건. 에코마이스터의 −29.2% 가 **+7.6%** 로 뒤집힌다 |
| ①④ 조건 없음 | **유상증자 신주상장 1,881건**을 전부 부순다. 바른전자 20200113 은 ρ=1.000 인데 c=38.59 라 하루 **+3,759%** 가 된다 |

마지막 줄이 특히 무섭다. 유상증자는 **현금을 받고 새 주식을 찍는 것**이라 시가총액이 느는 게
당연하다. 그건 수익이 아니다. 그런데 "주식수가 변했으니 보정" 이라는 규칙은 이걸 구분하지
못한다.

그래서 **네 조건을 동시에 만족할 때만** 보정하도록 좁혔다.

```
① cum_factor 가 그날 안 움직였다      (조정을 한 건도 안 걸었다)
② 그런데 주식수는 움직였다             (c ≠ 1)
③ 가격비가 가격제한폭의 두 배 밖이다   (|ρ−1| > 0.60 · 제도상 하루 ±30%)
④ c 를 곱하면 1 에 훨씬 가까워진다     (로그거리 2배 이상 감소)
```

**전 구간·전 시장에서 걸리는 것은 제일바이오 단 1건이다.** 여유도 충분하다 — 그 건은 기준의
12배를 넘고, 가장 가까운 탈락자(코스온 20231011 · 실제 −88%)는 9배 모자란다. 코스피는
후보가 0건이라 한 값도 바뀌지 않았다.

```
    보정 대상
    ─────────────────────────────────────────────
    조건 없음        ████████████████████  1,881+건  ← 전부 파괴
    ②만             ███████████████        1,985건
    ②③             ██                       139건
    ②③①④          ▏                          1건  ← 제일바이오
```

## 6. 바깥 기준점은 언제나 과거에 있다

여기서 하나 배웠다. **공식 연말 종가 대조(게이트 2)는 이 버그를 못 잡았다.**

제일바이오 사건은 2026-02-09 인데, 공식 상수의 마지막 점은 **2025-12-30** 이다. 보정 전후로
연말 대조표가 **한 자리도 바뀌지 않았다.** 여섯 해의 코스피 대조를 통과하면서도 코스닥에
+3.060%p 가 들어 있었다.

> 검증 기준점은 **과거에만** 있다. 가장 최근 데이터는 언제나 아무도 확인해 주지 않는다.

그래서 기준점 없이 판정하는 게이트를 따로 뒀다 — **게이트 6: 하루에 20배 넘게 오른 종목이
있는가.** 감자 미흡수는 반드시 *위로* 튀므로(가격 ×1500, 주식수 ÷1500) 그 방향만 막으면
된다. 아래로 튀는 것은 정리매매의 진짜 −99% 와 구별할 수 없고, 구별하려 들면 **진짜 손실을
지우게 된다.**

같은 이유로 **±60% 클리핑을 하지 않았다.** 이상치를 잘라내면 지수가 깔끔해 보이지만,
잘리는 것은 감자·정리매매·거래재개의 **실제** 등락이다. 지우면 벤치마크가 실제보다 좋아
보이고, 그건 백테스트에서 가장 피해야 할 방향이다. 세기만 한다.

## 7. 아직 못 고친 것 — 정직하게

- 🔴 **코스닥 재현 오차 평균 0.871% · 최대 1.896%** (코스피의 13배). 제일바이오와 **무관한
  별개 결함**이다. 원인 가설 두 개는 이미 기각됐다:
  - "폐지를 −100% 로 안 쳐서" → 소멸성 폐지 92종목의 잔존 시총은 전체의 0.06%
  - "잔존 이상치 138건" → 누적 기여가 −1.766% 로 **부호가 반대**

  남은 후보는 KRX 의 관리종목·신규편입 시점 규칙이다.
- 🔴 **원천 표는 아직 오염돼 있다.** 지수만 고쳤다. `price_adjusted.adj_clpr` 의 052670
  20260209 은 여전히 2,080 → 625,000 이고, `price_total_return.tr_index` 도 그대로다.
  고치려면 `collector/preprocess.py` 의 `factors`/`classify` 를 봐야 한다.
- 🟡 **이 계열은 KRX 공식 지수가 아니다.** 자체 재현치이고, 코스닥은 코스피와 같은 신뢰도로
  쓰면 안 된다.

## 8. 덤 — 백업 경로를 함께 열었다

수집한 데이터(556MB)를 Hugging Face private 저장소에 올리는 경로를 만들었다.
핵심은 **복원이 실제로 되는지**를 확인한 것이다.

```
restore 실측 : 13,428,316행 · 2.2GB · 184.6초
원문 sha256  : 12,697 / 12,697 일치
```

행 수만 맞는 사본은 백업이 아니다. gzip 을 풀어 sha256 을 전부 다시 계산해 원문과 맞는지
확인해야 **"로컬을 지워도 된다"** 고 말할 수 있다.

그리고 아찔했던 일 하나 — `data/hf_export/` 가 `.gitignore` 에 없었다. **556MB 가 Public
저장소에 들어갈 뻔했다.** 확인하다 또 배운 것:

> `.gitignore` 의 마지막 줄이 빈 줄이면 `git check-ignore` 가 **가짜 exit 0** 을 준다.
> 판정은 `git status --short` 로 해야 한다.

## 9. 배운 것

**그럴듯한 규칙일수록 반대 사례를 먼저 세어 봐야 한다.**

"가격비 ≈ 주식수비면 감자" 는 제일바이오에서 완벽하게 작동했다. 한 건만 보면 아무 문제가
없다. 전 구간에 돌려 보고 나서야 1,881건이 부서진다는 걸 알았다. **한 사례로 검증한 규칙은
검증된 것이 아니다.**

그리고 — **고쳐서 좋아 보이는 방향을 의심한다.** 이상치를 자르면 지수가 예뻐지고, 오차도
줄어든다. 하지만 그건 실제 손실을 지우는 일이다. 숫자가 좋아지는 수정일수록 왜 좋아지는지
먼저 따져야 한다.
