## 배운 것

- **판이 다른 코드는 원격에서 막을 수 없다 — 출처부터 지운다.** 노트북의 옛 코드는 임대를 몰라서, 새 코드 PC 가 아무리 앞 커밋을 비교해도 옛 코드의 올리기는 그 비교를 하지 않는다. 그래서 순서는 「그 PC 의 예약을 지운다 → 도는 일이 끝났나 본다 → 상태(앱 DB)를 챙긴다 → 다시 켜지지 않게 한다 → 새 PC 가 넘겨받는다」 였다. 다음 판부터는 원격에 최소 판 번호를 두어 코드가 차례를 지키게 한다(할 일 ①-28).
- **「어느 PC 가 가장 새것인가」 는 말이 아니라 원격과 DB 로 잰다.** 사용자는 데스크톱이 최신이라고 봤고 코드 · 문서는 맞았지만, 수집 DB 는 노트북이 그날 12:30 회차만큼 더 새것이었다(원격 커밋 제목의 행 수 · 이 PC 의 행 수 · 파일 시각). 역할을 바꾸기 전에 숫자를 보여 주고 물으니 결정이 「노트북 분리」 로 더 분명해졌다.
- **이름이 같은 컨테이너는 이름으로 고르지 않는다.** 강사님 lumina-invest 도 `fin-ai-*` 이름을 쓴다. 멈출 컨테이너는 compose 프로젝트 표식(`qurious`)으로 골랐고, PowerShell 5.1 의 네이티브 인자 속 큰따옴표가 깨지는 것도 형식 문자열에서 피했다.
- **설계 전에 앞선 결정부터 찾는다.** ①-04 첫 초안은 2차 끝(10-19)에 이미 만든 「기능별 두 갈래」 표와 `quote_now.py` 를 모른 채 같은 표를 다시 그렸다. 할 일 줄의 「지금 근거」 칸이 단서였다 — 앞 표를 이어받는 꼴로 다시 쓰고, 그때 정해 두고 남은 일 둘(공용 키 시세 · 오래된 값 N초)을 어긋남에 올렸다.
- **시험이 원격만이 아니라 이 PC 의 진짜 자료 경로도 쓰는지 본다.** DF-154 는 원격(HF)이었고, DF-156 은 이 PC 의 `data/hf_export/meta/run_record.json` 이었다. 고칠 때는 「경로부터 보고 회차를 도는」 시험을 먼저 넣어, 고치기 앞 판에서도 진짜 파일을 쓰지 않고 실패하게 했다.
