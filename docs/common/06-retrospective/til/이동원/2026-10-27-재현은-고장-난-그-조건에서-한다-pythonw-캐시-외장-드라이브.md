## 배운 것

- **재현은 고장 난 그 조건에서 한다.** 터미널에서 `run_lease status` 는 늘 성공했다. 「`pythonw` 라서」 라는 가설도 처음 재현은 통과했다 — 그 임대 버전이 캐시에 이미 있어 다운로드 자체를 안 했기 때문이다. 빈 `HF_HOME` + 표준출력 · 표준오류 `None` 두 조건을 모두 맞추자 같은 `AttributeError` 가 났다. 재현이 한 번 통과했다고 가설을 버리지 않고, 재현이 그 조건을 정말 만들었는지부터 본다.
- **예외를 이름만 남기면 원인이 사라진다.** 로그에는 `AttributeError` 한 단어뿐이었다(`type(e).__name__`). 같은 일이 다시 나면 또 하나하나 재현해야 한다. 안전하게 멈추는(fail-closed) 코드라도 원인 예외는 `__cause__` 로 남기거나 메시지 앞부분을 적는다.
- **처음 세운 가설(회차 도중 코드를 바꿔 옛 코드와 새 코드가 섞였다)은 틀렸다.** 증거(`run_lease.read()` 가 두 판에서 같다)로 가르고 나서야 다음 가설로 갔다. 의심스러운 사람 행동(내가 돌린 시험 · 코드 갱신)부터 탓하지 않는다.
- **외장 드라이브가 내려갔다 올라오면 도커 마운트가 끊긴다.** `docker restart` 가 아니라 Docker Desktop 을 다시 켠다. 손상된 DB 에는 아무것도 쓰지 않고(`sync` · 수리도 쓰기다) 멀쩡한 사본으로 통째로 바꾼다. 새 작업 자리는 통째 복사가 아니라 `git clone` + 읽기 전용 해시 대조 + 더하기만 복사.
- **컨테이너 전용 코드는 Windows 에서 가져올 수 있어야 시험이 돈다.** `fcntl` 은 함수 안이나 `try` 로 가져오고, 심볼릭 링크를 못 만드는 환경에서는 그 시험만 건너뛴다. 한 파일의 수집 오류가 전체 `pytest` 를 멈춘다.
- **`grep -c $'\r'` 는 이 환경에서 CR 을 못 센다.** CRLF 파일이 「0」 으로 나와 LF 로 가정하고 패치했다가 멈췄다. 줄바꿈은 파이썬으로 바이트를 센다.
- **「5분마다 알려 달라」 는 모니터 한 줄로 해결된다.** 30분 한도로 만료되니 다시 걸고, 줄에 「마지막으로 쓴 파일과 시각」 을 같이 찍으면 멈춤 여부를 사람이 바로 판단한다.
