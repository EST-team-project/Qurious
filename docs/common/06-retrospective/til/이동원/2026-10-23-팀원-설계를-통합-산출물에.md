## 1. 무엇을 했나

- 3차 발표일을 「11-11 추정」 에서 강사님 일정 화면의 원문(11-12 오전 발표 · 오후 수료식)으로 고쳤다. 계획서 · 할 일 · 이해관계자 목록 · 산출물목록 · 추적 이슈 본문 다섯 곳이 같은 날짜를 말하게 했다.
- 강사님 자료 이슈 둘 본문에 새 후보 다섯을 넣고, 전날 정한 결정(설정 키 0)과 어긋난 3-1 줄을 취소선으로 고쳤다.
- 통합 산출물에 팀원 설계가 얼마나 들어갔는지 10-13 기준점과 같은 잣대로 다시 쟀다.

## 2. 배운 것

- **「추정」 이라고 적은 날짜는 원문이 나오면 그날 고친다.** 발표일 하나가 다섯 문서에 흩어져 있었다 — 한 곳만 고치면 문서끼리 다른 날을 말한다. `grep` 으로 날짜를 먼저 모두 찾고 「기간(10-22 ~ 11-11)」 과 「발표일」 을 가려서 발표일만 고쳤다.
- **코드에서 다시 만드는 문서는 저절로 따라오지만, 설계는 따라오지 않는다.** 요구 대장 · RTM · API 명세서는 코드를 훑어 만들어 네 명 몫이 다 있었다. 그런데 팀원이 10-22 에 낸 3차 설계(카드 판 2 · 신호 계약)는 코드가 아직 없어 통합 문서 어디에도 없었다 — 설계서를 「먼저 읽고 옮겨 적는」 일을 따로 해야 한다.
- **같은 뜻의 칸 이름이 세 벌로 갈라진다.** `take.kind` · `stops.take_kind`, `entry` · `entry_mode` — 설계 글 · 코드 · 대사 문서가 각자 이름을 썼다. 한 이름을 정본으로 정하고 나머지에 짝 표를 두는 것이 먼저다.

## 3. 다음에

- 팀원 화면 UI 명세는 3차 화면 8개부터(신장환 님 화면 설계 뒤) · 강민석 님 몫은 코드 기준 초안 먼저.
- 기초 코드 3-way 지킴이(3-12)에 크롤링 메뉴 셋까지 — 시험부터.
