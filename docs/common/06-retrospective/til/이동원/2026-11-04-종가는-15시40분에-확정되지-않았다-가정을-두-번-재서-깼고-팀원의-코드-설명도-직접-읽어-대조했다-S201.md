## 개념 정리

### 1. 「15시 40분이면 확정」은 가정이었다 — 같은 날 두 번 재서 깼다

수집 회차는 증권사(KIS) 일봉에 오늘 봉이 들어 있다고 보고 `SETTLE_TIME` 을 15시 40분으로 두었다. 이 가정을 실제로 읽어 보았다. 대형주 4종목(삼성전자 · SK하이닉스 · 카카오 · 현대차)의 일봉을 두 시각에 읽었다. 읽기만 했고 주문은 없었다.

| 종목 | 15:40 | 17:00 |
|---|---|---|
| 삼성전자 | 218,000 | 217,000 |
| SK하이닉스 | 1,396,000 | 1,393,000 |
| 카카오 | 29,100 | 28,950 |
| 현대차 | 283,500 | 281,500 |

15:40 에 일봉에 오늘 봉은 있었다. 과거 4일의 값은 수집 DB 와 차이 0 이었다. 그런데 **17:00 에 오늘 종가가 네 종목 모두 달라졌다.** 오늘 봉은 있지만, 그것이 확정된 종가라는 보장은 15:40 에 없었다. 공식 종가와 대조하기 전이라 이유는 모른다. 코드(`SETTLE_TIME`)는 바꾸지 않고 두었다. 남은 측정은 20:30 이후 한 번, 그리고 다음 날 12:30 회차 뒤 수집 DB 와의 대조였다.

🔑 「언제 확정된다」는 문장은 **재서 확인한 값이 아니면 가정**이다. 두 시각만 읽어도 가정이 깨지는 것을 볼 수 있다. 왜 달라졌는지 모르면 모른다고 적고 코드는 바꾸지 않는다.

### 2. 팀원의 코드 설명도 읽어서 대조한다 — 맞는 부분과 다른 부분을 나눈다

강민석 님이 LEAN 대사의 보유 비중(`positionPct`)에 대해 이렇게 답했다. 카드 값은 LEAN 에 전달되지 않고, 「LEAN 매수는 `set_holdings(..., 1)` 이라 30% 가 실효 아니다」. 코드를 직접 읽어 대조했다(실행은 안 했다).

| 주장 | 코드 | 판정 |
|---|---|---|
| 카드 값은 LEAN 에 안 넘어감 | `daily_lean_reconcile.py` 가 `max_position_pct=30.0` 상수. `/api/lean` 은 인자를 안 넘겨 기본 100% | 일치 |
| 매수는 `set_holdings(..., 1)` | `momentum` · `buy_hold` 만 그렇다. `ma_cross` 는 수량을 계산하고 `cap_value = equity × pct/100` 상한이 있다 (#534 이후) | 일부 다름 |

그래서 발표 문구를 어떻게 쓸지가 달라졌다. 「LEAN 은 상한 없음」이라고 쓰면 `ma_cross` 대사에서 틀리고, 「30% 적용」이라고 쓰면 카드 값이 전달되지 않아 반쪽이다. 강민석 님이 코드 대조에 동의했고, **「일일 대사는 `ma_cross` · 최대 보유 비중 30% 고정 조건에서 수행」** 이라는 조건 표기로 합의했다.

🔑 팀원의 설명을 의심하는 것이 아니다. **한 줄을 더 읽으면 조건이 보이고, 조건이 보이면 문장이 정확해진다.**

### 3. 생성물 파일은 원본을 고쳐야 한다 — 직접 고치면 다음 빌드가 되돌린다

강민석 님 PR #547 (#533 의 3-1~3-4, 17:00 머지)이 `terms.json` 을 직접 고쳤다. 그런데 이 파일은 `glossary_build.py` 가 만드는 **생성물**이다. 직접 고친 값은 다음 빌드에서 사라지고, 당장도 `test_glossary` 2건이 깨졌다.

내 PR #550 으로 고침을 생성 원본(`glossary_build.py`)으로 옮기고 다시 빌드했다. 같이 있던 `terms.json.bak` 22,524줄도 지웠다. 강민석 님이 한 설명 자체(고정 가정 명시)는 그대로 살렸다.

🔑 파일을 고치기 전에 **누가 만드는 파일인가**를 본다. 생성물이면 원본을 고친다.

### 4. 학습 장 정정은 코드 줄까지 내려가 확인한다 — 쓰지 못하는 것은 쓰지 않는다

오준영 님이 학습 장 5편(리밸런싱 · 평균분산 · 리스크 패리티 · 블랙-리터만 · 시장 국면)을 검수했다. 계산 코드 오류는 없고 설명 정정이 3곳이었다. 코드로 하나씩 확인했다.

1. 국면 자동 갱신은 구현되어 있다. `rebalance_regime.update_for_day` 가 국면 설정을 켠 플랜의 목표를 갱신하고, 이때 주문은 내지 않는다. 장에는 「자동 교체 미구현」이라고 6곳에 적혀 있었다.
2. 평균분산의 목적함수 `0.5δwᵀΣw − wᵀμ` 은 음의 효용을 **최소화**하는 것이고 곧 효용 최대화다.
3. 기준 비중 검사(합 100 · 0.1% · 비음수 · 1~95%)는 모델 분기 앞이라 모든 모델에 적용된다. 국면만 `bounds` 가 비어 결과에 1~95% 제약이 없다.

**쓰지 않은 문장도 있었다.** 「자동 예약은 별도이며 꺼져 있으면 제안만 만든다」는 `update_for_day` 밖의 일이라 그때는 코드로 확인하지 못해서 넣지 않았다. 재검수에서 오준영 님이 124행 문장 하나를 더 보완해 달라고 했고, 그때 `check_daily → update_for_day → check_due → settlement.reserve → _fill_stock_order` 경로를 따라가 보니 증권사 직접 전송이 없고 앱 모의 장부로 간다는 것이 확인되어 정정에 넣었다.

🔑 설명을 정정할 때는 **코드로 확인한 문장만** 넣는다. 확인하지 못한 문장은 다음에 확인된 뒤 넣는다.

## 배운 것

1. **시각 가정은 재서 확인한다.** 한 번 읽고 같다고 끝내지 말고 두 번 읽는다.
2. **팀원 설명은 읽어서 대조하고 나서 조건을 적는다.** 틀렸다는 뜻이 아니라 문장이 정확해진다는 뜻이다.
3. **생성물을 직접 고치면 다음 빌드가 되돌린다.** 원본을 고친다.
