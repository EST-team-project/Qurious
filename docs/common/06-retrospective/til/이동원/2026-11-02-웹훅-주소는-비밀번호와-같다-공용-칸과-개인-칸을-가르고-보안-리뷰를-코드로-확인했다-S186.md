## 개념 정리 (특강 필기처럼)

### 1. 비밀값으로서의 웹훅 URL

웹훅(webhook)은 정해진 주소로 글을 보내면 채널에 올라가는 일방향 입구다. 인증 토큰이 **주소 안에** 들어 있어서 주소를 아는 사람은 누구든 그 채널에 글을 쓸 수 있다. 즉 비밀번호와 같다. 그래서 로그 · 문서 · 시험 · 응답 · 커밋 어디에도 글자로 남기지 않고, 화면에서는 가린다. 이 글에도 값을 적지 않았다.

우리 구현은 알림 설정에 **사용자별 칸**을 두는 것이다(마이그레이션 0036). 조회 응답은 `****` 로 가리고, 틀린 주소 모양은 DB 를 건드리기 전에 422 로 막고, `****` 로 온 값은 「바꾸지 않음」, 빈 값은 「지움」 으로 읽는다. 새 주소를 저장하려면 알림 연동 선택 동의가 먼저이고 동의문 판이 `n0.1` 에서 `n0.2` 로 올랐다. 저장은 **평문**이다(암호화하지 않는다는 점을 동의문에 적었다). 암호화는 아직 이동원 몫으로 남아 있다.

🔑 주소 안에 토큰이 있으면 그 주소는 비밀번호로 다룬다.

### 2. SSRF 와 허용 목록

SSRF(서버 측 요청 위조)는 사용자가 준 주소로 서버가 요청을 보내는 기능을 이용해, 서버가 내부망(사설 IP, 클라우드 메타데이터 주소)을 두드리게 만드는 공격이다. 방어는 허용 목록(allow-list)이다. 정해진 것만 통과시킨다. 우리 서버는 사용자가 알림 설정에 넣은 슬랙 주소와 메일 서버로 대신 요청을 보내므로 해당된다(코드 주석: 아무 주소나 받으면 내부망으로 요청이 나간다).

```python
# 슬랙: 공식 도메인의 정해진 경로만
_SLACK_HOOK_RE = re.compile(r"^https://hooks\.slack\.com/(?:services|workflows|triggers)/[A-Za-z0-9/_.\-]{4,}$")
SMTP_PORTS = (25, 587, 2525)   # 메일 서버: STARTTLS 로 쓸 수 있는 포트만
```

메일 서버는 이름 모양을 보고(IP 숫자 · `http://` · 경로 금지) 포트를 제한한 뒤, 그 이름이 가리키는 **모든 IP** 가 공인 주소여야 보낸다(`smtp_target_error`). 이름 하나가 여러 IP 로 풀릴 수 있어 하나라도 내부망이면 거절한다. 슬랙은 저장할 때 422, 보내기 직전에 한 번 더 같은 검사를 한다.

🔑 사용자가 준 주소는 모양이 아니라 가리키는 곳으로 검사한다.

### 3. 기본값 안전 — 모를 때는 보내지 않는다 (fail closed)

서버 설정의 공용 칸은 팀 테스트 채널로 두고 개인 채널은 사용자가 화면에서 직접 넣는다. 그러면 「자기 주소가 없는 사용자의 개인 알림(체결, 예수금)」 이 어디로 가는지가 문제가 된다. 결정이 두 번 바뀌었다.

| 시점 | 규칙 |
|---|---|
| S184 | 자기 주소 없이 디스코드만 켜면 팀 채널로 간다 |
| S185 | 「공용 채널로도 받기」 체크 상자(`preferences.discord_use_shared`, **기본 꺼짐**)를 켠 사람만 공용으로도 받는다. 주소도 없고 상자도 꺼져 있으면 어느 채널로도 안 간다 |
| S186 | 설정 행이 없거나 조회가 실패한 사용자는 `NO_SETTINGS` 로 표시해 채널 목록을 비운다 |

S186 이전에는 「사용자 없는 운영 알림」 과 「설정 없는 사용자」 가 둘 다 빈 `{}` 라 후자의 개인 알림이 공용 채널로 샜다(코드 주석). 사용자 없는 운영 알림(수집 보고)은 계속 공용이다.

🔑 선택은 켜는 쪽이 하고, 조회가 실패하면 닫힌 쪽으로 간다.

### 4. 공급망 — 이름이 같은 다른 패키지

같은 날 도구를 설치하다가 사용자가 권고한 도구의 설치 줄을 검색 결과 요약에서 가져와 건넸는데, 패키지 저장소(PyPI)의 같은 이름은 **다른 제작자의 다른 프로젝트**였다. 사용자가 설치한 뒤 제거했다. 이후 설치 줄을 건네기 전에 제작자 · 저장소가 사용자가 말한 곳과 같은지 확인하고, 설치한 뒤 `pip show` 로 출처를 읽는다.

🔑 설치 줄은 이름이 아니라 제작자로 확인한다.

## 직접 해 본 것

- **사용자별 칸 + 시험 격리(S184, #470)**: 브라우저로 디스코드 체크 시 칸이 나오는지, 틀린 주소에 한국어 422 안내가 뜨는지, 모양만 맞는 가짜 주소는 동의 없이는 막히는지 확인했다(실제 주소 · 실제 발송은 없었다). 서버 공용 칸에 팀 채널이 들어가면 알림 코드를 지나가는 모든 시험이 팀 채널에 글을 올릴 수 있다. 그래서 `tests/conftest.py` 의 `_no_real_alert_channels`(autouse)가 채널 설정을 빈 값으로 시작하게 했고 TC-NR-13 이 지킨다. 새 채널이나 새 호출을 붙이면 목록 `_ALERT_CHANNEL_SETTINGS` 에 항목을 더해야 한다. 11-01 17:40 ~ 17:52 전체 시험(실행)은 3,629건 · 통과 3,606 · 실패 5(알려진 것) · 건너뜀 18 · 737초였다.
- **예약 작업의 수집 보고(#471)**: 수집 보고가 예약 작업에서 알림 채널을 못 찾았다. 예약 작업(pythonw)은 환경 파일 지정이 없어 앱 설정이 `.env.dev` 만 읽는데 거기에는 알림 채널이 비어 있었다. 앞 커밋에 `scripts/collect_report.py` 가 빠져 있기도 했다. 후속 PR 한 개(1 file, 30줄)로 비어 있는 칸만 `.env` 에서 채우게 했다(TC-CRN-06).
- **공용 채널 옵션(S185, #472)**: 위 3절의 번복이다. 시험 TC-ARP-06 · TC-ADI-11 을 더했다.

- 주소에 토큰이 들어 있으면 비밀번호처럼 다루고, 문서에도 값을 적지 않는다.
