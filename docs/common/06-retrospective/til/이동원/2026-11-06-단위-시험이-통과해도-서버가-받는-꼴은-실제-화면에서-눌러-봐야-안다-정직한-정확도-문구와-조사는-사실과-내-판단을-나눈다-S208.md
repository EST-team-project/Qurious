|---|---|
| 날짜 | 2026-11-06 (S208) |
| 코드 | 종목 근거 모달 「지금 값 보기」(`stockdrawer.js` · TC-SDR-22) · 신호 적중 문구에 기준선 51.3% 와 표본 한계(`stockplain.js` · TC-SDR-13) |
| 관련 | 사용자 피드백(종목 근거 · 현재가 괴리 · 정확도 · 관리자 · 실시간 TradingView) · `docs/_local/종목근거-조사-2026-11-06/`(조사 4편) · `.gitignore` 의 `docs/phase-4/` |

## 개념 정리

### 1. 단위 시험은 내가 짐작한 입력만 시험한다 — 서버가 받는 꼴은 눌러 봐야 안다

「지금 값 보기」 단추는 모달에서 누를 때만 `/api/quote/now` 를 부른다. 처음에는 모달이 가진 종목 코드(`003380`)를 그대로 넘겼고, Node 시험(TC-SDR-22) 21건 + 기존 시험은 모두 통과했다. 그런데 실제 화면에서 눌러 보니 **「지금 값을 받지 못했습니다 — 수집 DB 종가 없음」**이 나왔다.

원인은 서버였다. 이 길은 6자리만 받으면 수집 DB 를 못 찾고(`003380` → 빈손), 시장 꼬리를 붙여야 값이 온다(`003380.KQ` → 11,210원). 게다가 시장 꼬리를 **틀리게** 붙이면(`003380.KS`) 다른 종목의 오래된 값(「7월 20일 05:00 체결」)이 나온다. 시험의 입력이 내 짐작(코드 그대로)이었으니 시험이 통과한 것은 당연했다.

| 입력 | 서버 응답 |
|---|---|
| `003380` | 가격 없음 · 증권사 키 없음 · 지연 시세 없음 · 수집 DB 종가 없음 |
| `003380.KS` | 5,840원 · 「7월 20일 05:00 체결」(다른 시장의 오래된 값) |
| `003380.KQ` | 11,210원 · 지연 시세 · 13:51 체결 |

고친 것: 허브가 아는 시장(코스피 `.KS` · 코스닥 `.KQ`)으로만 꼬리를 붙이고, **시장을 모르면 짐작하지 않고 조회하지 않는다**(`sdNowSymbol`). 시험에 「꼬리 있음 · 시장별 · 시장 모름 · ETF · null」 입력을 더했다.

🔑 새 화면이 **서버를 부르는 길이면 시험이 통과해도 실제 응답을 한 번은 본다.** 특히 「코드 그대로 넘겨도 되겠지」 같은 짐작은 시험 안에서 검증되지 않는다. 확인 도구(`check_now_button.py` · `check_quote_forms.py`)는 `docs/_local/종목근거-조사-2026-11-06/` 에 두었다.

### 2. 정직한 문구는 기준선과 한계를 같은 문장에 둔다

기존 적중 문구는 「매수 쪽 48.9~50.1% · 매도 쪽 45.5% 로 동전 던지기와 비슷했다」였다. 여기에 두 가지를 더했다.

- **기준선**: 같은 기간 「무조건 오른다」고 찍었을 때의 적중률은 51.3% 이고(5거래일 · 신호 결과.md 에서 직접 확인), 매수 쪽 적중률은 그보다 낮았다.
- **표본 한계**: 같은 날의 종목들은 함께 움직여 표본이 겉보기보다 적을 수 있으므로 이 차이가 우연인지는 가리기 어렵다.

조사에서는 날짜 단위 유효 표본이 138 이하이고 5일 겹침을 보정하면 약 28까지 줄 수 있다고 나왔다(에이전트 계산 — 실제 유효 N 은 아직 못 잼). 그래서 **구간 숫자는 화면에 쓰지 않았다.** 재지 않은 숫자로 「신뢰구간」이라고 쓰는 것이 더 큰 거짓이기 때문이다. 유효 표본을 오프라인에서 먼저 재는 일은 다음 과제로 남겼다.

🔑 정확도를 말할 때는 **기준선 · 표본 한계 · 재지 않은 것**을 같은 자리에 둔다. 숫자 하나만 보이면 「낮다/높다」만 남는다.

### 3. 조사 결과는 「사실」과 「내 판단」을 파일 안에서 나눈다

조사 에이전트 셋의 보고서에는 출처 등급 표기(원문 · 2차 · 검색 요약 · 내 분석)가 있었다. 그래서 종합 문서(04)에서 이렇게 갈랐다.

- **사실로 못 박은 것**: TradingView 위젯은 KRX 종목을 못 그린다(직접 렌더해 실패 확인) · Advanced Charts 라이브러리는 Public 저장소에서 쓸 수 없다 · KIS 안내가 시세 제3자 제공 불가.
- **내 판단으로 남긴 것**: 관리자 6패널 · 판정 문구 세 가지 · 저장소 이관 방식 권고. 「확인 못 함」 목록을 문서에서 지우지 않았다.

그 결과 「실시간 TradingView 를 여러 화면에서」라는 요청은 **임베드 불가**로 답하고, 대안(우리 일봉 + 확정 종가 수평선 + 기준일 표기 + 외부 링크)을 제안했다. 요청을 받아 안 되는 이유를 근거와 함께 말하는 쪽이, 되는 척 만들다 약관에서 멈추는 것보다 빠르다.

🔑 조사 문서는 **사실 / 적용안 / 확인 못 한 것** 세 칸으로 나누어 쓴다. 한 칸이 비어도 그대로 비워 둔다.

### 4. 개인 프로젝트로 넘어갈 설계는 팀 저장소 밖에 둔다

phase-4(개인 프로젝트 전환 재설계)는 `docs/phase-4/` 에 두고 `.gitignore` 에 올렸다. 팀 산출물목록 · README 에 섞이지 않고, 팀 발표(11-12) 전에 팀 저장소를 어지럽히지 않는다. phase-3 에서 되는 것만 phase-3 로 들어온다. 이관 문서 전략(새 저장소 push · 이메일 재작성 · 키 회전 → 서면 동의 → 백업 → 기술 이전 순서)은 02 문서에 남겼다. 이력 재작성 · 강제 push 는 사용자 승인 후에만 한다.

🔑 **범위를 나눌 때 폴더도 같이 나눈다.** 어디에 올라가는지가 정해져야 쓰는 말도 정해진다(팀 문서는 합의 문서, phase-4 는 본인 설계).

## 오늘 배운 것 한 줄씩

- 시험 통과 ≠ 서버가 받는 꼴 확인. 호출하는 화면은 실제 응답을 한 번 본다.
- 시장 구분처럼 **짐작하면 틀리는 값**은 모르면 조회하지 않는다(틀린 꼬리가 다른 종목의 오래된 값을 줬다).
- 정확도 문구는 기준선과 표본 한계를 한 문장에 둔다. 재지 않은 구간은 쓰지 않는다.
- 사용자가 모르는 이슈 초안(「작성: 오준영 · 담당 확인: 이동원」)이 들어와 있었다. 작성자는 끝내 불명이지만 **주장한 시험 실패 네 건은 로컬에서 모두 재현됐다**(키 교체 도구 UTF-8 초기화 누락 · 마이페이지로 옮겨진 화면 셋 · 메뉴 묶음 12 ≠ 13 · 학습 메뉴 묶음 이름 변경). 글쓴이를 믿거나 의심하는 대신 주장만 따로 재현해서 가른다.
