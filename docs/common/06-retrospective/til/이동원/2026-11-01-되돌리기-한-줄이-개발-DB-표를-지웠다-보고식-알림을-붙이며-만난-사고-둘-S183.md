## 개념 정리 (특강 필기처럼)

### 1. 마이그레이션 up / down 과 버전 표

마이그레이션 도구(우리는 Alembic)는 DB 구조 변경을 파일 하나씩 쌓고 순서대로 적용한다. 지금 어느 변경까지 적용됐는지는 `alembic_version` 이라는 **한 줄짜리 표**에 적는다. 이 표의 `version_num` 칸은 `varchar(32)` 라서 리비전 id 가 32자를 넘으면 기록이 안 들어간다. `downgrade -1` 은 「방금 시도한 것 취소」 가 아니라 **기록된 현재 리비전의 하나 전으로** 돌아가라는 뜻이다.

이번 일은 다음 순서로 일어났다.

| 순서 | 일어난 일 |
|---|---|
| 1 | 리비전 이름을 `0035_notification_preferences_payload`(37자)로 지었다 |
| 2 | `upgrade` 가 실패했다. 기록은 여전히 0034 였다 |
| 3 | 이어 돌린 `downgrade -1` 이 **이미 있던 0034 를 취소**해 0033 으로 돌아갔다 |
| 4 | 0034 가 만든 `backtest_accounts` · `backtest_snapshots` 표가 지워졌다 |
| 5 | 이름을 `0035_notification_prefs`(23자)로 줄여 다시 올렸고 표는 빈 채로 복구했다 |

지워진 것은 개발 DB 의 점검 계정 백테스트 행으로, 다시 만들어지는 파생 값이다.

🔑 `upgrade → downgrade -1 → upgrade` 를 한 줄로 이어 돌리지 않는다. 되돌리기는 번호 이름을 지정하고 직전에 `alembic current` 를 본다.

### 2. 시험 격리 (test isolation)

시험이 외부로 부수 효과(알림, 업로드, 외부 API)를 내지 않게, 시험 기본값을 꺼 두는 일이다. 이번에는 회차 끝에 수집 보고 알림을 붙였는데, `.env` 가 시험에도 읽히기 때문에 `run_all` 을 끝까지 돌리는 `test_daily_update.py` 가 실제 디스코드 · 슬랙 · 이메일로 「일일 수집 회차 완료」 를 보냈을 수 있었다. 15:37 에 시작한 전체 시험(15:38 ~ 15:43 무렵)이 그 시간대였다. **실제로 몇 건이 나갔는지는 모른다.** 마무리 검토(advisor)가 짚어서 알았다.

같은 부류의 앞선 사건이 있다. 10-25 S147 에서 러너 시험이 `.env` 토큰으로 실제 HF 저장소에 쓴 일이고, 그때 `_no_real_hub` 가 생겼다.

조치는 `tests/conftest.py` 에 수집 보고 알림을 끄는 환경 변수(`COLLECT_REPORT_NOTIFY=false`)를 기본으로 거는 autouse 를 더하고, 끈 상태를 지키는 시험 TC-CRN-06 을 두는 것이다.

🔑 원격에 닿는 새 호출을 붙이는 변경에는 같은 변경에서 시험 기본값을 끈다. 시험이 통과해도 이 부작용은 보이지 않는다.

### 3. 알림 설계 — 모드 · 조용한 시간 · 묶음 · 채널별 모양

보고식 알림은 사건마다 보낼 방식을 고르게 한다.

| 요소 | 규칙 | 우리 코드 |
|---|---|---|
| 모드 | 사건별 `on`(그대로) · `silent`(소리 없이) · `off` | `alert_prefs.MODES` |
| 조용한 시간 | 기본 꺼짐, 켜면 21 ~ 08시 KST. 긴급이 아닌 알림을 보관했다가 끝나면 요약 1건 | `DEFAULT_QUIET` |
| 묶음 | 같은 사건이 몰리면 120초 창 동안 보관해 한 건으로 합친다. 대상은 「위험관리로 주문 생략」 뿐 | `GROUP_WINDOW_SEC` |
| 긴급 | 비상 정지는 끌 수 없고 조용한 시간에도 즉시 간다 | `risk_halt` |

TradingView 신호는 지연되면 안 되므로 묶음 대상에서 뺐다. `silent` 는 텔레그램 · 디스코드만 소리를 끌 수 있고 슬랙 · 이메일은 그대로 보내며, 건당 요금이 드는 카카오 · SMS 는 건너뛴다. 한 payload 를 채널마다 그리는 일은 `alert_format.py`(렌더러, DB 없음)가, 보낼지 보관할지는 `alert_prefs.py`(규칙, DB 없는 순수 함수)가 맡는다.

🔑 「무엇을 보낼까」 와 「보낼까 말까」 를 분리하면 각각 DB 없이 시험할 수 있다.

## 직접 해 본 것

### 1. 조사 → 질문 → 구현

- 병렬 에이전트 조사 넷(실제 서비스 · 오픈소스 · 설계 원칙 · 우리 코드의 호출 지점)을 먼저 하고 사용자에게 질문했다. 답은 자세한 정도 「보통」 · 채널마다 다른 모양 · 사건별 + 조용한 시간 + 묶음 · 텔레그램 이스케이프 · 수집 회차 보고 · 이력에 보고 원본이었다.
- 구현은 `alert_format.py` · `alert_prefs.py`(사건 11종) · `notification.py`(`dispatch_event` · `flush_held` · 풀기 작업) · 마이그레이션 0035 · `scripts/collect_report.py` 다. 새 마이그레이션 번호를 쓰기 전에 팀 브랜치 원격 참조 421개에 0035 가 없는 것을 확인했다.
- 새로 등록한 시험은 TC-AF 11 · TC-ARP 5 · TC-ADI 10 · TC-AFL 4(일회용 PG) · TC-CRN 5 다. 15:50 전체 시험(`test.ps1 -Split`, **실행**)은 3,623건 · 통과 3,593 · 실패 12 · 건너뜀 18 · 771초였고, 실패 12 는 알려진 5 + cp949 6(`PYTHONUTF8=1` 로 통과 확인) + `test_user_consents` 1(새 `preferences` 칸이 개인정보 칸이 아님을 시험에 반영해 고침)이다.

### 2. 팀 파일은 고치지 않았다

`auto_trade.py` · `routes/stocks.py` · `tradingview.py` 등 팀원 파일의 호출부는 건드리지 않았다. 옛 `dispatch(message, html_message)` 호출은 어댑터로 그대로 동작하고, 헬퍼에 선택 인자(`details` · `risk_note`)만 열어 두었다. 값을 넘기는 일은 안내 이슈 #468 로 맡겼다. 「사건을 모두 끄면 `.env` 채널로 간다」 는 각자 개인 채널을 쓰므로 문제가 아니라는 것이 사용자 판단이다.

### 3. 같은 세션의 화면 일

클릭 점검(일반 + 관리자 계정)이 찾은 화면 JS 결함을 고쳤다. 서버의 pydantic 422 영어 문구를 한국어로 바꾸는 함수는 **`api()` 안에 둬야** TC-RS-05 가 통과했다(시험이 `api` 함수만 떼어 돌린다). UI 명세서 v0.39 에서 그림 20장을 새로 찍어 낡은 31장 중 19장이 풀렸고 12장이 남았다.

### 4. 실제 채널로 시험 보내기

디스코드는 한글 · 이모지 · 특수문자가 그대로 도착했다(사용자 확인). 슬랙은 쓰던 웹훅이 앱 개인 메시지 칸용이라 `messages_tab_disabled` 였고 사용자가 다시 추가했다. 이메일은 서버 칸에 호스트가 아닌 값이 들어 있어 이름 풀이가 실패했다(값은 여기 적지 않는다).

## 배운 것

- 마이그레이션 시험에서 `downgrade -1` 은 기록된 현재 리비전 기준이다. 실패한 `upgrade` 뒤에는 기록이 바뀌지 않았다는 사실이 사고의 열쇠였다.
- 시험 통과만으로 보이지 않는 외부 부수 효과는 코드를 붙이는 순간 격리를 같이 건다.
- 코드에서 항목을 뺀 날에는 그 항목 수가 적힌 문서도 같이 센다(12 → 11).
- 보낸 건수를 모르는 사고는 「모른다」 고 적는다.
