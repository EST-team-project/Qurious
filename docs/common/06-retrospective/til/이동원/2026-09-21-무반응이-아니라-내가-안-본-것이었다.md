# 무반응이 아니라, 내가 안 본 것이었다

> 2026-09-21 (KST) · S42 · 관련 PR #74 · 논의 D#6·#7·#10·#13·#17·#29

## 무슨 일이 있었나

세션을 열 때마다 팀 논의의 반응을 확인했다. 방법은 이랬다 — GraphQL 로 논의 목록을 받아
각 스레드의 **마지막 댓글 작성자**를 보고, 그게 나면 "아직 답이 없다"로 셌다.

```graphql
discussions(first: 12) {
  nodes { number title comments(last: 1) { nodes { author { login } } } }
}
                                    ↑ 여기가 문제였다
```

이 방법으로 **16세션 동안 "반응 0건"** 이라고 기록했다. 오늘 세션 프롬프트에도 그렇게 적었다.
*"S26~S41 16세션 연속 0건."*

사용자가 "댓글 단 것도 있으니 꼼꼼히 확인해봐"라고 해서 **전수로 다시 훑었다**. 결과:

| | 첫 조회 (`comments(last:1)`) | 전수 조회 |
|---|---:|---:|
| 팀원이 쓴 논의 댓글·답글 | **0건** | **11건** |
| 그중 오늘(09-21) | 0건 | **6건** |

## 왜 안 보였나

댓글이 **스레드 구조**이기 때문이다. GitHub Discussion 의 댓글에는 답글(`replies`)이 달리고,
`comments(last: 1)` 은 **최상위 댓글 중 마지막 하나**만 준다. 그 아래 답글은 보지 않는다.

```
D#13
├─ 댓글 1 (나)          ← comments 에 포함
│   └─ 답글 (민석님) ★   ← replies. 안 봤다
├─ 댓글 2 (나)
│   └─ 답글 (민석님) ★   ← 안 봤다
└─ 댓글 3 (나)          ← comments(last:1) 이 보여 준 건 이것뿐
     "마지막 댓글이 나 = 무반응" 이라고 판정
```

게다가 **내가 답글을 달면 그 스레드는 영영 "내가 마지막"이 된다.** 성실하게 답할수록
지표가 0에 가까워지는 구조였다.

## 진짜 교훈은 그 다음이다

조회 코드를 고치는 것은 쉽다. 무서운 것은 **그 0이 판단으로 이어졌다**는 점이다.

- 메모리에 *"S26~S41 16세션 연속 0건"* 이라고 적어 뒀다
- 세션 프롬프트에 *"★ 회신 요청 억지로 금지"* 라는 규칙을 만들었다 — 무반응이 길어지니
  재촉하지 말자는 뜻이었다
- 논의 8건의 결론을 **혼자 정해서 초안을 쓰는** 방향으로 계획을 세웠다

**세 가지 다 "팀원이 답하지 않는다"는 전제 위에 있었다.** 전제는 사실이 아니었고,
민석님은 09-15 부터 꾸준히 답하고 있었다.

> 잘못된 계측은 잘못된 숫자로 끝나지 않는다. **그 숫자를 설명하려고 만든 규칙까지**
> 남긴다. 오늘 지운 것은 지표 하나가 아니라, 그 지표가 낳은 태도였다.

## 같은 실수를 두 번 더 했다 — 이번엔 스캐너에서

오늘 만든 `scripts/schema_scan.py` 도 처음엔 두 번 틀렸다. 성격이 정반대다.

| # | 증상 | 원인 | 어느 쪽으로 틀렸나 |
|---|---|---|---|
| 1 | "마이그레이션이 만드는 표 **0개**" → 26개 표가 전부 "모델에만 있음" | 파일 전체에서 `create_table` 과 `drop_table` 을 셌다. `downgrade()` 의 drop 이 **전부 상쇄** | 🔴 **빨간불** — 없는 문제를 만들었다 |
| 2 | `benchmark_index.variant` 설명 칸에 **옆 칸 설명**이 들어감 | DDL 의 줄 전체 주석을 *앞 칸*에 붙였다. 실제로는 **다음 칸**의 설명 | 🟡 **조용한 오염** — 그럴듯해서 안 틀려 보인다 |

1번은 출력이 요란해서 바로 의심했다. **2번이 더 위험하다** — 설명이 한 칸씩 밀린 표는
읽으면 말이 되고, 대조할 원본이 없으면 영원히 안 들킨다. 데이터 사전이 347칸인데
그중 한 칸이 밀려 있어도 아무도 모른다.

세 사고의 공통점이 있다:

```
       계측 방식이 만든 착각
            │
  ┌─────────┼─────────┐
  │         │         │
마지막 댓글   파일 전체   앞 칸에 붙임
 만 본다    를 센다    (다음 칸인데)
  │         │         │
"무반응"   "표 0개"   "설명 밀림"
  │         │         │
  └────▶ 셋 다 "내가 본 범위"를 "사실"로 읽었다 ◀────┘
```

## 다음부터 이렇게 한다

1. **반응 확인은 전수로.** `comments(first: 50) { … replies(first: 30) }` 로 답글까지 받고,
   *내가 아닌 작성자*만 걸러 센다. 마지막 댓글 작성자는 지표가 아니다.
2. **"0" 이 나오면 조회를 먼저 의심한다.** 0은 "없다"가 아니라 "내 조회로는 안 보인다"이다.
   특히 **연속으로 0** 이면 대상이 아니라 자(ruler)를 본다.
3. **스캐너는 자기가 만든 0·전부를 의심한다.** 이번엔 "26개 전부 불일치"라는 극단값이
   단서였다. 전부이거나 전무이면 십중팔구 파싱이 틀린 것이다.
4. **조용히 틀리는 쪽에 장치를 둔다.** 2번 같은 밀림은 경고가 안 뜬다. 그래서 스캐너에
   *설명이 붙은 칸 비율*을 출력하게 했다 — 다음에 돌렸을 때 숫자가 이상하면 보인다.
