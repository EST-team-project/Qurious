## 배운 것

- **검증을 우회하지 않고도 「지문표가 틀린」 경우는 고칠 수 있다.** 내용 지문은 80개 모두 같고 바이트 지문만 72개 어긋나 있었다. 지문표의 바이트 지문을 **실제 원격 바이트**에 맞추면 받는 쪽은 바이트 대조에서 바로 통과한다. 단 조건을 코드에 박았다 — 내용이 다르거나 못 읽거나 파일이 없으면 정정을 통째로 거부하고, 원격 머리를 `parent_commit` 으로 걸고, 올린 뒤 다시 받아 확인한다.
- **오류 문구가 코드 판을 말해 주면 가설이 빨리 갈린다.** 강민석 님의 문구가 #375 코드의 문구와 글자까지 같다는 것으로 「옛 코드 때문」 이라는 첫 가설이 무너졌다. 같은 말을 되풀이하는 오류 문구는 어느 검사 · 어느 판인지를 담게 한다(S162 의 배움이 이번에 값을 했다).
- **기록은 기록 대상과 같은 트랜잭션에 쓴다.** `audit()` 은 모든 예외를 삼켜서 동의 기록이 조용히 빠질 수 있었다. 사용자 행을 `flush()` 해 id 를 받고 동의 행을 얹은 뒤 commit 한 번 — 시험이 「동의 행을 못 쓰면 가입도 안 된다」 와 「audit 이 아무것도 못 남겨도 동의 행은 남는다」 를 지킨다.
- **쌓기만 하는 표는 시험이 「고치는 코드가 없다」 를 지킨다.** 철회도 새 행이고 지금 상태는 가장 늦은 행으로 읽는다. 앱 코드에 `update(UserConsent` · `delete(UserConsent` 가 없다는 것을 소스를 읽는 시험으로 고정했다.
- **약관 문구는 반대 증거까지 찾아본다.** 「알림을 받을 수 없다」 고 쓰려다가 운영자 공용 `.env` 채널로도 발송된다는 코드를 보고 「연동 정보를 저장할 수 없다」 로 고쳤다.
- **검사가 한 번도 안 걸리면 고장과 구별되지 않는다.** 실제 DB 는 깨끗해서 품질 검사가 늘 ✅ 였다 — 일부러 결함을 넣은 합성 데이터 시험으로 열 가지가 실제로 걸리는지 봤다. 긴 구간(600 거래일) 실측에서는 정상 휴장일 41일이 「적재 empty」 로 잡혀, 검사 범위를 「시세가 있는 날」 로 좁혔다.
- **멈춘 시험은 열린 트랜잭션을 먼저 의심한다.** `update` 뒤 `commit` 없이 SQLite `backup` 을 부르면 락을 기다리며 영원히 멈춘다(`faulthandler_timeout` 으로 위치를 찾았다).
