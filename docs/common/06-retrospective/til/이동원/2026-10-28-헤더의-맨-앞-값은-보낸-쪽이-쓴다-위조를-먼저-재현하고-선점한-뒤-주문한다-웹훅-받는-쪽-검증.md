## 한 일

- **발신 IP 검사의 구멍을 찾아 막았다.** 옛 코드는 `x-forwarded-for` 의 **맨 앞 값**을 발신 IP 로 믿었다. 옛 라우트를 git 에서 꺼내 같은 시험을 돌리니 위조 헤더가 200 으로 통과했고, 새 코드는 403 이다. 프록시 개수를 설정(`TRADINGVIEW_TRUSTED_PROXY_HOPS`, 기본 0 = 헤더를 믿지 않음)으로 받고 **오른쪽에서 N 번째** 값만 쓴다.
- **본문 4KB · 필수 칸 · 지연 · 알림 단위 중복**을 설계 3.6 대로 구현했다. 같은 알림은 `(사용자, strategy_id, 판, 종목, 방향, 신호)` 해시를 유일 색인으로 두고, **먼저 한 줄을 잡은 뒤에 주문**한다. 일회용 PG 에서 같은 알림 넷을 동시에 보내도 주문은 한 번이었다.
- **감사 기록 · 사용자 알림을 응답 뒤로** 옮겨, 알림 채널이 5초 걸려도 라우트는 1초 안에 돌아오게 했다.
- 처음에는 오준영 님 브랜치보다 먼저 만들었다가, 그쪽(#368)이 먼저 머지되기로 해 **그 위로 다시 얹었다** — 마이그레이션은 `0029`(`down_revision` = `0028_execution_control`), 주문은 #368 의 공통 관문(`signal_key` · `strategy_id="tv:…"`)을 쓰고, 내가 만들었던 자체 위험 검사 · 1분 쿨다운은 걷었다. 필수 칸은 `signal_id | bar_time | time` 가운데 하나(`strategy_id` 는 없으면 전략 이름), 지연은 `sent_at` 이 있을 때만 잰다.
- 시험 54건(TC-WH 41 · TC-WHP 13)을 더하고, 시험 계획서 v1.70 · RTM v1.57 · 설계서 v0.4 로 판을 올렸다.

## 배운 것

- **헤더는 들어온 순서가 아니라 누가 썼는지로 읽는다.** `x-forwarded-for` 는 프록시가 오른쪽에 덧붙이고, 맨 앞은 보낸 쪽이 마음대로 쓴다. 「몇 단계를 믿는가」 를 설정으로 두고, 모자라면 거부한다. 기본은 아무것도 믿지 않는 쪽(fail-closed)이다.
- **고친 코드만 시험하면 시험이 일을 했는지 모른다.** 옛 코드로 같은 요청을 돌려 200 이 나오는 것을 본 뒤에야 「이 시험이 구멍을 잡는다」 고 말할 수 있다. 옛 판은 git 읽기(`git show HEAD:…`)로 꺼내 임시 모듈로 돌리면 작업 트리를 건드리지 않는다.
- **중복은 확인하고 쓰는 것이 아니라 먼저 잡고 쓰는 것이다.** 「이미 있나 보고 없으면 주문」 은 동시에 오면 둘 다 통과한다. 유일 색인에 먼저 한 줄을 넣고(savepoint) 못 넣은 쪽이 중복이 되게 하면 DB 가 순서를 정한다. 동시성은 가짜가 아니라 진짜 PG 로 시험해야 한다 — 일회용 컨테이너를 따로 띄워 쓰고 내렸다.
- **설계를 그대로 옮기지 말고 어긋나는 곳을 적는다.** 토큰 거부는 사용자를 몰라 줄을 못 만들고(로그로), 크기 초과는 400 보다 413 이 맞고, 분봉 한도는 `{{interval}}` 형식을 확인하지 못해 하지 않았다. 설계서 표에 「설계와 다른 점」 칸을 두니 하지 않은 것도 숨지 않는다.
- **같은 곳을 두 사람이 고치면, 먼저 들어올 쪽의 규칙에 맞춘다.** 내 구현이 끝났어도 남의 PR 이 먼저 머지되기로 정해지면, 내 규칙(필수 칸 · 쿨다운 · 위험 검사)을 고집하지 않고 그쪽의 이름 · 입력에 맞춰 줄였다. 합치기 전에 임시 폴더에서 그쪽 시험까지 같이 돌려 겹침을 먼저 봤다.
- **시험은 서로의 상태를 바꾼다.** 마이그레이션을 도는 다른 시험이 `alembic/env.py` 의 `fileConfig` 로 이미 만든 로거를 꺼서, 단독으로는 통과하던 로그 시험이 묶음에서만 실패했다. 묶어서 돌려 보기 전에는 몰랐다.

## 다음에

- 주문(모의 체결)이 아직 요청 안에서 돈다. 체결 직전 시세 확인이 네트워크를 타면 3초를 못 지킬 수 있다 — 실측하고 필요하면 뒤로 옮긴다.
- 위험 관문은 오준영 님 #368 이 주문 때 맡는다 — 웹훅 기본이 「받으면 모의 체결」 이어도 되는지, 설계의 「주문 끔」 제안을 정한다. 분봉 한도는 `{{interval}}` 형식을 공식 문서로 확인한 뒤 정한다.
- 실제 수신의 선행 조건 셋(웹훅 요금제 · 공개 HTTPS 주소 · 보안 검토)을 확인하고, 준비되는 날 실제 알림 한 번을 손으로 본다.
