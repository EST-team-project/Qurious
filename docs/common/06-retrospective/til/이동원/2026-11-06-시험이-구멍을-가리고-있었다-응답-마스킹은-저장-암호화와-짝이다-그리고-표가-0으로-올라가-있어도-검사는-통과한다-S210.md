## 개념 정리

### 1. 저장을 암호화했으면 응답에서 가리는 일도 같이 센다

11-05 에 알림 비밀 9칸을 암호화 저장으로 바꿨다(0044). 그런데 설정 GET 은 9칸 중 8칸만 `****` 로 가리고 `kakao_sender_key`(발신 프로필 키) 하나는 평문으로 돌려주고 있었다. 암호화 전부터 가리지 않던 칸이라 「전과 같음」 이라고 운영 문서에 적어 두었다.

문제는 처리방침이 「키 · 토큰은 화면에서 가립니다」 라고 말한다는 점이다. 저장을 암호화한 칸은 **화면에서도 가린다**는 약속에 같이 걸린다. 칸 목록(`FIELDS` 9칸)이 정해지면 응답 가림 목록도 같은 목록에서 나와야 한다.

### 2. 시험이 알려진 구멍을 피해 가고 있었다

TC-NS-12 에는 이런 줄이 있었다.

```python
assert "route-" not in got.text.replace(body["kakao_sender_key"], ""), "비밀 평문이 응답에 새지 않는다"
```

「응답 전체에 평문이 없다」 를 확인하면서, 새는 칸의 값을 먼저 **지우고** 비교한다. 시험이 구멍을 알고 있었고, 통과시키려고 그 구멍만 빼 둔 것이다. 이런 `.replace(...)` 는 고쳐야 할 것이 있다는 표시다. 오늘은 칸을 가리고 `replace` 를 걷어 낸 뒤 「응답 전체에 평문이 없다」 로 되돌렸다.

### 3. 가림값을 받는 쪽도 같이 고친다

가리기만 하면 안 된다. 화면은 받은 값을 입력칸에 그대로 넣고, 저장할 때 그 입력칸 값을 되돌려 보낸다. 가림값(`****`)을 그대로 저장하면 키가 `****` 로 덮인다. 그래서 POST 가 세 곳을 바꿨다.

| 곳 | 고친 것 |
|---|---|
| GET | `mask(row.kakao_sender_key)` |
| POST 저장 | 가림값이면 저장값 유지, 빈 값은 지움(슬랙 · 디스코드 주소와 같은 규칙) |
| 동의 판단(`brings_new_personal_data`) | 가림값은 새 입력이 아니다 — 안 그러면 동의 없는 사람이 저장할 때 422 |

시험은 가림값을 되돌려 보낸 뒤 DB 의 값이 그대로인지 읽어 확인한다.

### 4. 「건너뜀」 을 통과로 읽지 않는다 — 일회용 DB 를 직접 띄웠다

TC-NS-12 는 일회용 PostgreSQL 이 있어야 돈다. 환경변수가 없으면 5건이 **건너뜀**이라 「통과」 표시만 보고 끝낼 뻔했다. `postgres:16.15-alpine` 을 따로 55432 포트에 띄워 돌렸고(DB 이름에 `test` 가 들어가야 시험이 받아 준다), 30건이 건너뜀 없이 통과했다. 운영 DB 는 건드리지 않았고 컨테이너는 바로 껐다.

### 5. 문서 검사가 통과해도 표가 비어 있을 수 있다

RTM 을 다시 채우려 `rtm_scan.py --doc` 를 돌렸더니 367줄이 바뀌었다. 열어 보니 앞 판 표의 시험 건수 칸이 `TC-RKS 0 · TC-SCD 0 …` 처럼 **46곳이 0** 이었다. `--check` 는 「표가 대장 · 코드와 같다」 만 본다. 0 으로 찍힌 채 올라가 있었어도 그 시점에 같은 도구를 같은 조건에서 돌렸다면 통과했을 것이다. 원인은 확인하지 못했다(그때 수집이 건수를 못 세는 환경이었을 가능성 — 추정).

배운 것: 도구가 만든 표는 **내용을 한 번 읽어 본다.** 숫자 칸이 전부 같은 값이면 의심한다.

## 오늘의 작업 메모

- 문서 판 올림 4건을 코드에서 바로(전역 7.1 보다 11-06 결정이 우선): API 명세서에는 `signal-rank` 이 부르는 API 의 이동과 `rows[].market` 풀이를, UI 명세서 25.7절에는 v0.51 이 틀리게 적은 호출 API 의 정정을 넣었다. 틀리게 적었던 문장은 지우지 않고 「v0.52 정정」 줄로 남겼다.
- 판을 올리면 **지난판 사본**이 짝으로 필요하다(`docs_scan.py --bump`). 이미 고친 파일에는 바로 쓸 수 없어서 HEAD 판을 잠깐 되돌려 사본을 만들고 수정본을 되돌렸다.
- 팀 PR 시험 파일 4곳(`credential_storage_logs` 등)은 계획서 표 5 에 아직 없다. 내 두 묶음(+2건)만 올리고 나머지는 담당 팀원 판 올림에 맡겼다.
- 처리방침 화면에는 변경 이력 칸이 없다(13절은 「판 번호와 시행일을 바꾼다」 만 말한다). 그래서 「처리방침 변경 이력에 한 줄」 은 알림 암호화 운영 문서에 변경 기록 절로 적었다.
