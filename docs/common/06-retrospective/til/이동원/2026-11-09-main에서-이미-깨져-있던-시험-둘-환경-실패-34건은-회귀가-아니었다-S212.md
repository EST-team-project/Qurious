## 개념 정리

### 1. 수집 단계를 끼운 PR 이 「단계 목록을 세는 시험」을 몰랐다

전체 시험(일회용 PG · 7묶음)을 돌리자 4,530건 중 실패가 37건이었다. 그중 세 건은 **환경 탓이 아니라 main 이 이미 깨뜨린 것**이었다. PR #602 가 수집 단계 `paper_kis_reconcile` 을 끼웠는데, 단계 목록을 세는 `test_daily_update` 와 의존 모델을 적은 `test_paper_journal`(TC-PJ-13) · `scripts/pipeline_profile.py` 의 DEPS 를 같이 고치지 않았다.

**단계를 하나 끼우면 단계 목록을 가정하는 곳이 따로 있다.** 시험이 그 가정을 알려 준다 — 통과한 줄만 믿지 말고 전체 시험을 돌려야 보인다.

### 2. 실패 37건을 모두 회귀로 읽지 않는다

| 구분 | 건수 | 읽은 방법 |
|---|--:|---|
| 환경(KIS 복구 시험 30 + proc_stats 4) | 34 | 환경 탓으로 분류 — 세부 원인은 이 글에 남기지 못했다(미확인) |
| 고친 것 | 3 | 위 1번 |

환경 실패와 고칠 실패를 먼저 가른 뒤에 숫자를 보고했다(통과 4,462 · 실패 37 · 건너뜀 31). 화면 훑기(`smoke_views.py`)는 77개 화면 문제 0.

### 3. 되살아난 파일은 지운다

`scripts/signals_yahoo.py` 가 다시 나타나 있었다. 지우고 RTM 대장에 시험 두 묶음(TC-LRS · TC-PKR)을 등록했다.

### 4. 코드를 읽다가 문구와 사실의 틈을 찾았다

100일 백테스트 결과(`BacktestSnapshot`)를 읽는 곳이 `app/` 에 없고, QFRS 는 `PaperAccountSnapshot` 만 읽는다. 그런데 카드는 「QFRS 지표가 100일치로 계산됩니다」 라고 말한다. **코드 읽기만 한 것이라 실행으로 재현하지 않았다.** 강민석 님 화면이라 확인 요청이 필요하다.
