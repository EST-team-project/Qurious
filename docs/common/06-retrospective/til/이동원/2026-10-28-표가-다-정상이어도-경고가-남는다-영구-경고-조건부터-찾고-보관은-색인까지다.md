## 배운 것

- **경고 판정은 「영구 경고가 되는 입력」 부터 찾는다.** 표가 모두 정상인데 종합이 주황이면 지표가 틀린 게 아니라 종합이 읽는 입력 하나(러너 기록)가 어떤 PC 에서는 아예 없다. 「없음」 을 이상으로 읽는 판정은 그 입력이 없는 환경에서 늘 경고를 낸다 — 경고를 숨기지 말고, 없을 때 읽을 다른 출처(임대 파일)와 「정말 없음」 을 갈라야 한다.
- **그림을 그리기 전에 이미 있는 것을 읽는다.** 서랍의 설명 문장을 내가 짓는 줄 알고 그렸는데, 신장환 님의 `/api/explain` 이 요약 · 근거 · 반대 근거를 이미 내고 「문장 숫자 = 응답 값」 시험까지 있었다. 앱 화면과 견주니 왼쪽 메뉴 때문에 표와 서랍이 나란히 안 들어간다는 것도 그제야 보였다 — 그림은 코드 읽기만으로 닫지 말고 실제 화면과 견준다.
- **보관은 색인까지가 보관이고, 초안에는 자리가 있다.** 팀원 글 원문 파일을 만들고도 README 색인을 「나중에」 로 미뤄 사용자가 글이 있는 줄도 몰랐고, 이슈 · 답글 초안을 `_git-drafts` 에 쌓아 규칙(그 폴더는 도구 · PR 본문 · 커밋 메시지 · 변경노트 · 프롬프트만)을 어겼다. 병렬 에이전트에게 일을 맡길 때도 파일 자리를 브리프에 적어야 규칙이 따라간다.
- **코드로 읽은 것과 확인한 것을 갈라 적는다.** 판정표 · 이슈 초안의 각 칸에 「읽음 / 못 읽음(`.env` · 게이트웨이 · `kis_monitor`)」 을 적었고, 외부 서비스 동작은 추측하지 않고 질문으로 남겼다.
