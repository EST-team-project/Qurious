## 개념 정리

### 1. 필터는 limit 전에 서버에서 건다

신호 순위 화면에는 이름과 코드 검색칸 하나뿐이었다. API(`GET /api/stock-hub/signal-rank`)의 인자는 `on` · `symbols` · `limit`(기본 50, 최대 500) · `components` 였다.

필터를 화면에서만 걸면 문제가 생긴다. **서버가 위 50줄만 보낸 상태에서 화면이 걸러 버리면, 그 밖에 있는 종목은 영원히 안 보인다.** 「매도」 칩을 눌렀는데 위 50줄 안에 매도 종목이 3개밖에 없으면 화면에는 3개만 나오고, 51등 밖에 있는 매도 종목 수백 개는 없는 것처럼 보인다.

그래서 서버 인자 `signal`(매수 · 매도 · 관망)과 `market`(KOSPI · KOSDAQ · ETF)을 더하고 **limit 전에** 거르게 했다. 응답에는 맞는 종목 수 `matched` 와 적용된 `filter` 를 넣었다. 시장 구분을 읽을 수 없으면 말없이 전체를 보여 주지 않고 503, 잘못된 낱말은 422 로 돌려보낸다.

시험(TC-XR-FILTER)은 「limit 전에 걸리는지」를 일회용 DB 로 확인한다. 실제 수집 DB 에서는 시장별 코드 수를 쟀다: KOSPI 939 · KOSDAQ 1,829 · ETF 1,185.

🔑 서버가 자르는 목록에 걸리는 필터는 **자르기 전에** 서버에서 건다. 화면에서 거르면 자른 뒤의 일부만 거른다.

### 2. 남의 파일을 고칠 때는 옛 호출이 그대로인지부터 지킨다

신호 순위의 줄을 읽는 함수 `signal_explain.load_day` 는 신장환 님 파일이다. 필터 때문에 선택 인자 `signal` · `only_codes` 를 더했다. **인자를 안 주면 옛 호출과 똑같이 돌게** 했다. 신장환 님이 쓰던 호출이 바뀌지 않으므로, 이 변경은 안내 이슈 초안(#554)에서 「인자 추가뿐」이라고 밝혔다.

신장환 님은 이후 퀀트 대시보드가 필터 없이 `signal-rank` 를 읽으므로 `load_day` 인자에 영향이 없음을 코드로 확인해 주었다.

🔑 남의 함수를 고칠 때는 **인자를 안 줄 때 옛 동작과 같은지**를 시험으로 박아 둔다. 그래야 안내 한 줄로 끝난다.

### 3. 새로고침이 하는 일을 먼저 정하고 충돌점을 밝힌다

「새로고침 때 기준 시간대를 다시 판단」은 크게 들리지만, 현재 코드를 읽으니 신호 순위는 **매 거래일 12:30 회차가 기록한 줄을 읽기만 한다**(「새로 계산하지 않는다」). 다시 판단하려면 계산 경로를 새로 만들어야 했다. 충돌점을 네 개 적었다.

| 충돌 | 내용 |
|---|---|
| 일지 지문 | 판단 함수(`_generate_signal` 등)는 그림자 일지 판의 지문 대상이라 **11-12 전까지는 건드리지 않는다.** 화면용 재판단은 새 경로여야 한다 |
| 실시간 값 | 지연 시세와 출처 표기를 붙이는 `quote_now` 한 곳만 쓴다. 야후 이용 정책(공개 노출에 수집 DB 값)도 확인해야 한다 |
| 종가 확정 시각 | 증권사 일봉이 오늘 종가를 언제 확정하는지 아직 모른다. 「오늘 봉」을 섞는 순간 신선도 문제가 다시 생긴다 |
| 비용 | 약 3,950종목을 요청마다 다시 계산하면 비싸다. 관찰 목록 31종목으로 좁히는 것이 현실적이다 |

그래서 사용자에게 범위를 세 단계로 나눠 물었다. (a) 기록 다시 읽기 + 지금 가격 표시, (b) 관찰 목록 카드만 재계산, (c) 순위 전체 재판단. **(a)를 먼저 하고 (c)는 11월 12일 뒤 설계로 남기는 것**으로 정했다.

PR #558 은 필터 줄에 「새로고침」 단추를 두고, 지금 조건으로 기록된 신호를 다시 읽고 위 10종목에만 지금 가격을 한 줄(「지금 72,300원 · 지연 시세 · 약 20분」)로 붙인다. 가격은 한 번에 5개씩 받고, 그 사이 조건이 바뀌면 낡은 가격은 붙이지 않는다. 안내 글은 이렇게 쓴다: 「새로고침 13:12:34 (KST) · 기록된 신호를 다시 읽었습니다 — 신호는 새로 계산하지 않습니다」.

🔑 큰 제안은 **지금 코드가 하는 일 · 못 건드리는 것 · 모르는 것**을 먼저 적고, 지금 할 수 있는 한 단계만 한다. 하지 않은 단계는 발표의 한계 문장이 된다(8장 약점 표에 한 줄 더했다).

### 4. 판 올림은 요구 ID 를 지어내지 않는다

동결일이라 문서 판 올림을 같은 PR 에 묶었다: RTM v1.80 · 테스트 계획서 v1.92 · API 명세서 v0.62 · UI 명세서 v0.49 · IA v1.15 · 화면 대장 v0.6 · 산출물목록 v3.12 · 신호 전체 종목 기록 설계 v0.3. 새 시험 여섯 묶음(`TC-SF` 33 · `TC-CWS` 11 · `TC-CMT` 10 · `TC-KR` 10 · `TC-PL` 7 · `TC-IT` 22)을 시험-요구 대장에 올릴 때, 어느 요구에 해당하는지 확실하지 않은 칸은 **지어내지 않고 `—` 로 비워 작성자 확인을 받게 했다.**

시험 결과를 쟀더니 4,354건에서 실패 52가 나왔다. 원인을 나누니 이렇다.

| 건수 | 원인 |
|---|---|
| 34 | Windows 환경 (기존) |
| 1 | 강민석 님 몫 (기존) |
| 16 | 장 시작 전 시각에만 실패. 09:04 재실행은 통과, 원인은 확인 못 함 → 결함 DF-167 로 열었다 |
| 1 | 접수일이 고정이라 11-05 부터 깨짐 → DF-166, 고침 |

「시각에 따라 통과하고 실패하는 시험」은 DF-167 로 열려 있었고, 나중에 오준영 님이 #569 로 처리해 닫혔다.

🔑 모르는 칸은 **비워 두고 확인을 받는다.** 채워 넣은 거짓 숫자는 나중에 고치기 더 어렵다.

### 5. 코드 리뷰는 고쳐 준 사람이 모르는 경계까지 본다 — 강민석 님 #521

강민석 님이 환율 감사 경로의 동시 진입 문제를 `fx.py` 에서 고쳤다. 통화마다 `asyncio.Lock` 을 두고 잠금 뒤에 캐시를 다시 확인해서, 동시에 캐시를 놓친 요청이 외부 조회를 두 번 하던 것을 한 번으로 줄였다. 시험 14건과 기준선 2건이 통과했다.

머지된 코드를 직접 읽고 시험 16건을 돌렸다. 맞게 고쳐졌다. 다만 한 가지 경계를 더 확인했다. **모듈 전역 `asyncio.Lock` 은 `asyncio.run()` 을 여러 번 부르는 배치에서, 앞선 루프에서 경합이 있던 잠금을 새 루프가 쓰면 `RuntimeError` 가 난다.** 이 PC 에서 재현했다. 지금은 스냅샷이 차례로 호출하는 구조라 안전하다. 이 점을 답글 초안에 「남은 점검」으로 적었다.

🔑 고쳐진 것을 확인하는 것으로 끝내지 않고, **그 고침이 깨질 조건**을 한 번 재현해 본다. 지금 안전한 이유를 적어 두면 나중에 구조를 바꿀 때 알 수 있다.

## 막힌 것 · 남은 것

- **필터 단추를 로그인한 실제 화면에서 눌러 보지 못했다.** 시험은 합성 응답과 일회용 DB 다. 390px 와 다크 모드 눈 확인도 아직이다. (이 점은 S203 에서 신장환 님이 눌러 보고 버그 둘이 나온 것으로 확인됐다.)
- `public/api-docs/catalog.json` 은 다시 만들지 않았다. 팀원 변경 18건이 함께 들어와 오준영 님 판 올림 뒤에 한 번만 만들기로 미뤘다(`api_scan --catalog --check` 가 아직 1).
- 신장환 님 문서 `목표기능2-패턴예측-XAI-설계` 576행에 `signals_yahoo.py` 가 아직 적혀 있다. 동기화 대장 SY-08 · 09 가 걸려 있어 이번에는 고치지 않았다. 신장환 님 판 올림 때 정정을 부탁한다.
- 증권사 일봉의 오늘 종가 확정 시각은 공식 종가와 대조하기 전이라 `SETTLE_TIME` 설정은 그대로 두었다.
- (c) 순위 전체의 실시간 재판단은 11월 12일 뒤 설계로 남겼다.

## 배운 것

1. **필터가 자르기 전에 걸려야 하는지 본다.** 서버가 limit 으로 자르는 목록은 서버에서 거른다.
2. **남의 함수에 인자를 더할 때는 안 줄 때의 동작을 시험으로 박는다.**
3. **큰 제안은 지금 코드를 읽고 충돌점부터 쓴다.** 그리고 지금 할 수 있는 한 단계만 한다.
4. **모르는 칸은 비운다.** 시험-요구 대장의 요구 ID 를 지어내지 않았다.
5. **고침을 확인할 때는 깨질 조건도 한 번 재현한다.** 지금 안전한 이유를 글로 남긴다.
