> 74개 화면을 열고 필터 17곳의 칩과 새로고침을 눌러 봤다. 오류는 0이었다. 그런데 390px 에서 **10개 화면이 잘려 있었다.** 팀이 쓰는 「가로 넘침 0」 점검은 이것을 못 잡는다.
> 같은 날 알림 설정의 비밀값 9칸을 암호화했다. 앱 컨테이너가 **파일을 저장하는 순간 마이그레이션을 실행**하는 구조라, 사본에서 개발했다.

---

## 개념 정리

### 1. 문서 `scrollWidth` 는 바깥이 잘라 버리면 0 이다

가로 넘침을 `document.documentElement.scrollWidth > 창 너비` 로 재면, 안쪽 요소가 넘쳐도 **바깥 컨테이너가 `overflow` 로 잘라 버리면 문서 폭은 그대로**라 0 이 나온다. 눈에는 잘려 보이는데 점검은 통과한다.

그래서 요소의 오른쪽 끝을 직접 쟀다: `getBoundingClientRect().right > 390`. 이 기준으로 74화면을 다시 재니 10화면(코인 · TradingView · 패턴 인식 · LEAN · 학습 장 5곳 · 학습 허브)이 걸렸다.

🔑 「넘침 0」은 **어디를 재느냐**의 문제다. 잘리는 것이 걱정이면 문서 폭이 아니라 **요소의 오른쪽 끝**을 잰다.

### 2. CSS 그리드의 `1fr` 은 최소 폭이 있다

원인은 그리드였다. `grid-template-columns: 1fr` 는 `minmax(auto, 1fr)` 라서 긴 내용(긴 주소, 표)이 칸을 **밀어낸다**. `grid md:grid-cols-2` 처럼 기본 열이 없는 경우도 같다. 고치는 법은 두 가지다.

- 기본 열을 명시한다: `grid-cols-1 md:grid-cols-2`, 또는 `minmax(0, 1fr)`.
- 긴 글(주소 · 링크)은 줄바꿈하게 하고, 표는 카드 안에서 가로 스크롤하게 둔다.

강사님 원본 구조에서 온 것이라 #564 와는 무관했고, 같은 모양이 `app.html` 에 십수 곳 더 있다(지금은 잘림 0).

🔑 그리드 칸이 내용에 밀리면 `1fr` 대신 **`minmax(0, 1fr)`** 이다.

### 3. 저장하는 순간 바뀌는 환경에서는 사본에서 개발한다

앱 컨테이너가 `app/` 과 `alembic/` 를 **bind mount** 하고, `--reload` 로 돌며, **기동할 때 `alembic upgrade head` 를 자동 실행**한다. 그러니 마이그레이션 파일을 저장하는 순간 로컬 DB가 바뀐다. 암호화 마이그레이션(평문 → 암호문)은 되돌리는 downgrade 를 막아 둔 것이라, 실수가 곧 되돌릴 수 없는 일이 된다.

그래서 **작업 폴더 밖 사본 + 일회용 PostgreSQL**(`postgres:16.15-alpine` · 포트 55432 · DB 이름에 `test`)에서 개발하고 시험한 뒤, 백업을 뜨고 앱을 멈춘 채 반영했다.

두 번 부딪힌 것:
- 사본을 만들 때 `data/`(약 10GB)까지 복사해서 C: 여유가 12GB 로 줄었다. 지우고 24GB 로 돌렸다.
- 일회용 DB 시험은 `QURIOUS_TEST_DATABASE_URL` 이 없으면 **건너뛴다.** 건너뛴 채 통과라고 보고하면 안 된다.

🔑 위험한 변경은 **저장이 곧 실행인 곳**에서 하지 않는다. 사본 · 일회용 DB · 백업, 이 셋이 있어야 반영할 수 있다.

### 4. 비밀값 9칸 암호화의 구조

- 증권사 자격증명(0031)과 **같은 키 파일**을 쓰되, 접두어 `qnc1:` · AAD `notification_settings.<칸>` 으로 도메인을 나눴다. 증권사 암호문 형식 · AAD · 키 ID 는 건드리지 않는다.
- 칸은 **9개**다(발신 프로필 키 포함). 설계서의 「8칸 확정」은 계산 오류였고 오준영 님 원문 목록이 맞았다. 전화번호 · 채팅 ID · 이메일 주소 칸은 이번 범위 밖(후속).
- 기동할 때 키를 점검하되 **기동을 막지 않고 error 로그만** 남긴다. 복호화 실패는 일반 조회 실패와 구분해 `[CREDENTIAL_STORAGE]` 로 남긴다.
- 동의 철회는 행을 읽지 않고 삭제한다(키가 깨져도 철회가 된다).
- 팀원 코드는 고치지 않는다: 오준영 님의 `rotate_broker_credentials.py` 수정은 원복하고 **형제 스크립트** `rotate_notification_credentials.py` 를 새로 만들었다(두 스크립트를 모두 돌린 뒤 옛 키를 지운다).
- 동의문 `terms.js` 는 「암호화 저장을 하지 않습니다」 문구 4곳만 사실대로 고쳤고, 동의문 **판은 올리지 않았다**(법률 판단이 아니라 사용자 결정).

🔑 암호화는 **되돌릴 수 있을 때만** 시작한다 — 키 점검은 막지 않고 알리기만 하고, 철회는 키 없이도 되게 한다.

## 직접 해 본 것

- 74화면(사이드바)을 시연 계정(로컬 전용)으로 열고 필터 17화면의 칩 · 새로고침을 눌렀다. 스크립트 오류 0, 403 은 관리자 전용 화면뿐.
- 390px 잘림을 오른쪽 끝으로 재서 10화면을 찾고, `app.html`(클래스 · 속성) · `finlearn.css` 를 고쳐 **74화면 잘림 0** 으로 만들었다. 새 시험 TC-MCG-01~03 은 **수정 전 소스에서 3건 실패**하는 것을 먼저 확인했다. 관련 66파일 728 통과.
- 암호화 시험 TC-NS 13건(일회용 PG 포함). **변이 3종**으로 시험이 결함을 실제로 잡는지도 확인했다(어떤 변이였는지는 이 글에 옮기지 못했다 — 시험 파일 주석에 있다).
- 전체 시험은 약 14분: 통과 4,414 · 실패 35 · 건너뜀 31. 실패 35건은 4개 파일이고 **변경 전 HEAD 에서도 같다**(Windows 환경).

## 막힌 것 · 남은 것

- 운영 전환(복제 DB 리허설 → 새 백업 → app · worker · beat 를 같은 태그로 함께)은 오준영 님 몫이고 늦어도 11-10 이다. #577 에 답이 없다.
- 시연 계정 데이터가 비어서 필터 칩의 「줄어듦」은 코인 순위 · 데이터 관제 · 알림 이력만 확인했다. 값이 있는 계정으로 다시 봐야 한다.
- 키가 깨졌을 때 설정 조회가 503 이라 **화면에서 철회 단추까지 못 갈 수 있다**(API 수준에서만 확인).
- 실제 평문 → 암호문 전환은 일회용 PG 에서만 해 봤다. worker · beat 가 같은 키를 쓰는지는 운영 전환 체크리스트에 있다.

## 배운 것

1. 점검 기준 하나가 맹점이면 **그 기준으로 통과한 모든 보고**가 흔들린다. 「0」이 나오면 무엇을 재서 0인지 먼저 본다.
2. 환경이 저장 즉시 반영이면 개발 순서를 뒤집는다: 사본 → 일회용 DB → 백업 → 반영.
3. 건너뛴 시험을 통과로 세지 않는다. 보고에 「건너뜀 n」을 따로 쓴다.
4. 팀원 코드는 고치지 않고 **옆에 형제를 놓는다**(회전 스크립트). 합칠지는 그분과 정한다.
5. TIL 을 당일에 못 쓰면 이렇게 복원해야 한다. 복원은 사실만 남고 **고른 이유와 버린 선택지**가 빠진다(이 글도 그렇다).
