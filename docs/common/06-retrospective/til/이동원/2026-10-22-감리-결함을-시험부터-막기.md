## 1. 무엇을 했나

- 강사님 배포본 감리가 찾은 HIGH 결함(목표 시뮬레이션에 수익률 −101 → 서버 오류 500)이 우리 코드에서도 그대로 재현됐다. 새 시험 다섯(15건)을 먼저 써서 고치기 전 코드로 **14 실패**를 본 뒤 고쳤다(19 통과).
- 입력 모델에 칸마다 범위 표를 두고, 넘으면 계산 전에 422 와 한국어 안내 글을 돌려준다. 계산 함수에도 안전판(수익률 −100% 이하 · 넘친 결과)을 두어 라우트가 422 로 바꾼다. 켜 둔 앱에서도 −101 → 422 안내 글, −99.9 → 200 을 확인했다.
- 「증권사 API 설정」 을 다시 저장하면 저장된 키가 가린 값(`앞 4자 + ****`)과 빈 비밀키로 덮이는 결함을 일회용 계정 · 가짜 키로 재현했다(DF-145 · 주담당 확인 물음은 다음).
- 강사님 자료 이슈 셋(#319 · #318 · #317)과 #6 닫는 댓글에 들어갈 그림 넷을 Figma 로 그렸다.

## 2. 배운 것

1. **pydantic 의 기본 422 글은 영어다.** 화면 `api()` 는 detail 목록의 `msg` 를 그대로 잇는다. `Field(gt=-100)` 만 두면 「Input should be greater than -100」 이 보이고, 검사기에서 `ValueError` 를 던지면 앞에 「Value error, 」 가 붙는다. `PydanticCustomError` 로 던지면 안내 글만 남는다.
2. **경계 바로 안쪽 시험도 하나 둔다.** −99.9 → 200 을 보는 시험은 고치기 전에도 통과한다. 「막지 말아야 할 입력을 막지 않는다」 를 지키는 시험이라 빨강이 아니어도 맞다.
3. **파이썬 실수 거듭제곱은 넘치면 예외, 곱셈은 inf.** `(1 + r) ** years` 는 `OverflowError` 를 내고 `원금 * 큰 수` 는 inf 가 된다. 둘 다 잡아야 500 이 안 난다.
4. **재현은 진짜 키가 없는 계정으로.** 점검 계정에는 실제 모의 키가 있어 덮이면 연동이 끊긴다. 일회용 계정 · 가짜 키로 재현하고 끝에 그 계정을 mock 으로 되돌렸다.
5. **그림 PNG 를 128색으로 줄일 때 방식이 중요하다.** FASTOCTREE 는 주말 칸 회색(241, 242, 245)을 (252, 252, 253)으로 바꿔 지웠다. MEDIANCUT 은 그대로 남았다(픽셀 값으로 잼).
