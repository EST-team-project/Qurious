## 개념 정리

### 1. 글자 수를 줄이는 것과 풀어 쓰는 것은 다른 일이다

오전에는 9장 · 12장의 글을 200자 아래로 줄였고(391 → 175 · 433 → 174), 오후에는 12장 · 19장이 다시 616자 · 568자로 늘었다. 사용자 피드백이 이유다. 「PR #529」 「TC-WH 12」 「오준영 님 #368」 은 우리에게는 한 단어지만 발표를 듣는 사람은 무엇인지 모른다. 줄인 것이 내용이 아니라 **설명**이었다.

정리한 기준: 줄여야 하는 것은 같은 말을 되풀이한 글이고, 풀어야 하는 것은 듣는 사람이 모르는 내부 용어다. 용어 하나를 풀 때는 「PR = 코드 변경을 팀 저장소에 합쳐 달라는 요청」 처럼 **한 줄 정의**를 그 용어가 처음 나오는 장에 붙인다. 구조(4단계 카드 · 8단계 표)는 그대로 두고 칸 안의 글만 늘렸다.

늘린 만큼 화면이 넘친다. 처음 만든 판은 15쪽 · 19쪽 모두 푸터와 겹쳤다. 설명을 한 줄로 줄이고(표 열 하나를 「무엇을 확인하나」 로 신설, 설명은 한 칸 한 줄) 열 너비를 다시 나눠서 맞췄다. **풀어 쓴 뒤에는 반드시 화면으로 본다.**

### 2. 숫자를 바꾸는 정규식은 형식이 다르면 소리 없이 지나간다

통합 덱에서 오준영 님 슬라이드만 푸터가 「02 / 06」 이었다. 조립기 `fix_numbers` 는 `class="pg"` 칸과 강민석 덱의 `.foot` 두 형식만 알았고, 오준영 덱의 `<span>02 / 06</span>`(class 없음)은 **오류 없이 통과**했다. 에러가 없으니 56장을 만들고도 몰랐다.

고친 것은 정규식 한 줄이지만 배운 것은 검증 방식이다. 형식이 다른 가져온 덱은 「치환 횟수가 기대와 같은가」 를 센다(S220 TIL 과 같은 이야기). 이번에는 사람별 슬라이드 한 장씩 푸터를 눈으로 보는 것을 사례 C-0004 의 재발 방지에 적었다.

### 3. 점검은 「다시 읽은 것」 과 「다시 돌린 것」 을 나눠 적는다

질의응답의 약한 수치 목록을 점검하면서 기준 전략 「110개 · 합격 0」 을 결과 파일에서 다시 읽어 확인했다. 스크립트를 다시 돌린 것은 아니다. 그래서 문서에도 「다시 읽어 확인했습니다 · 스크립트는 다시 돌리지 않았습니다」 라고 적었다. 코드 줄 번호 141곳은 파일 존재와 줄 수를 스크립트로 대조해 1곳(`signal_targets.py:19-42`, 실제 41줄)을 고쳤고, 내용이 맞는지는 핵심 9곳만 열어 봤다고 범위를 밝혔다. 확인의 깊이를 숨기면 뒤에서 「확인했다」 가 과장으로 읽힌다.

### 4. 판정이 같다는 말에는 근거 범위가 필요하다

레드펜 점검표 11-10 칸에서 아홉 문항의 판정(🟢 0 · 🟡 8 · 🔴 1)이 11-05 기록과 같았다. 같다고 쓰려면 이유가 있어야 한다. 11-09 점검 기준 커밋(`81e51d06`)과 지금 사이에 바뀐 코드를 `git diff --stat` 로 읽었더니 5파일뿐이었고, 그중 `performance_service.py` 는 줄 번호만 옮겨졌다(`:56` → `:64` 등). 판정은 유지하되 **줄 번호는 새로 적었다.** 「안 바뀌었다」 는 말은 어디서 어디까지를 본 결과인지를 함께 쓴다.

### 5. 도구가 막으면 우회하지 않고 사용자에게 넘긴다

`sync-lecture.sh` 는 훅의 허용 간격에 걸려 막혔다. 재시도 루프나 다른 명령으로 돌리지 않고 「사용자가 직접」 항목으로 남겼다. 훅은 계정 보호 장치라서 막혔다는 사실 자체가 정상 동작이다.

### 6. 용어를 풀 때는 화면 한 곳에 모아 두면 글이 덜 늘어난다

14쪽의 「SHA-256」 지적 뒤에 이동원 슬라이드 14장을 모두 훑었다. 장마다 본문 사이에 괄호로 풀면 글이 끊겨 읽기 어렵고 구조가 흐트러진다. 그래서 장 아래쪽에 「쉬운 말」 풀이 상자(점선 틀 · 14.5px)를 한 줄씩 두고, 본문에는 용어를 그대로 쓰되 상자에서 정의를 찾게 했다. 수치도 같은 방식으로, 원자료에서 확인되는 값만 더했다(통과율 4,462 ÷ 4,530 = 98.5% · 적중률 49.1%의 95% 구간 45.9~52.2% · 기준 전략 샤프 0/110 · 수집 DB 26표 24,191,640행). 시장 조사 장(4 · 6 · 7장)은 일부러 수치를 더 만들지 않았다 — 근거가 「가설」 이거나 논문 수치가 호출마다 엇갈렸기 때문이다. **수치를 늘리라는 요구에도 확인 안 된 숫자는 넣지 않는다.**
