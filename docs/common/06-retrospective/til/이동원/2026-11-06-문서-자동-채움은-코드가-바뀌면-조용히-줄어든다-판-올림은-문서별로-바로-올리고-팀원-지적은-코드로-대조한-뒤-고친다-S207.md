> 아침에 세 가지가 있었다. 사용자는 **「판 올림은 하루에 한 번에 하지 말고 지금부터 차근차근 하자」**고 했고, 강사님이 중요하다고 한 **산출물 완성**을 위해 **기능 완성도를 다시 점검하자**고 했다. 그리고 낮에는 신장환 님이 두 번 연달아 지적을 보냈다.
> 오늘 가장 크게 배운 것은 하나다. **자동으로 채우는 표는 코드 구조가 바뀌면 틀렸다는 경고 없이 조용히 줄어든다.**

---

## 개념 정리

### 1. 자동 채움은 구조가 바뀌면 조용히 줄어든다 — 화면이 부르는 API 148 → 132

API 명세서의 「부르는 화면」 칸은 `api_scan.py`가 `view_scan.py`의 결과로 채운다. 그런데 `--doc`을 사본에 돌려 보니 「화면이 부르는 API」가 148에서 **132**로 줄었다. 오류도 경고도 없었다. 이력 라우트 16곳의 화면 칸이 그냥 `(다른 곳)`으로 바뀌었다.

원인은 어제 내가 올린 #564다. `paper.js`를 재구성하면서 호출이 `훅 → 로더 → const X = listPanel({ load: api(…) })`로 한 단계 깊어졌고, 스캐너는 진입 훅에서 **한 단계만** 따라간다. 기능이 사라진 것이 아니라 **측정 도구가 구조를 못 따라간** 것이다.

고치는 중에 두 번 틀렸다.

| 시도 | 결과 |
|---|---|
| 호출을 3단계까지 따라가게 함 | `robo-patterns` 한 화면에 API가 80여 개 붙음 — 공용 헬퍼를 타고 번졌다 |
| 진입 2단계 + 조작 1단계 + 3개 화면 이상이 함께 닿는 함수는 공용 헬퍼로 제외 | 148 → 132 → **146**. 남은 3곳은 호출이 3단계 아래라 한계로 적었다 |

기존 시험 두 개가 깨졌는데(`agent-news`, `signal-rank`의 기대 API), 기대값을 바로 고치지 않고 호출 경로를 하나씩 추적했다. `research.js`의 타임라인과 종목 자동완성, `signalrankview.js`의 종목 검색이 **실제로 부르는** API였다. 그제서야 시험을 고쳤다.

🔑 자동 채움 도구의 출력이 줄었을 때 「기능이 줄었나」보다 먼저 **「도구가 새 구조를 따라가나」**를 본다. 도구를 고친 뒤 판을 올린다.

### 2. 도구가 안 세는 것이 있다 — 대장 밖 시험 12묶음

RTM과 테스트 계획서는 **시험-요구 대장에 등록된** 시험 파일만 센다. 지난 이틀 동안 내가 만든 시험 12묶음(TC-LB 외 필터·새로고침 8개, TC-MR, TC-MCG, TC-NODE, TC-NS)이 대장에 없어서 문서 건수에 잡히지 않고 있었다. 등록하고 RTM을 다시 채우니 수집 건수가 **4,366 → 4,492건, 306 → 320파일**이 되었다.

같은 구멍이 점검표에도 있었다. 3차에 새로 생긴 화면 `signal-rank`와 `kis-results`가 기능 완성도 점검표 72행에 **없었다**. 화면은 77개인데 점검표는 72행이었다. 점수는 근거 없이 올리지 않는 규칙이라 둘을 배점표로 처음부터 매겼다(84점, 77점 — 오준영 님 몫인 `kis-results`는 초안으로 확인 요청).

🔑 문서가 센 숫자를 믿기 전에 **세는 쪽 목록에 빠진 것이 있는지**부터 본다. 새로 만든 시험·화면·표는 목록에 올려야 숫자에 잡힌다.

### 3. 판 올림을 몰아서 하면 같은 날 서로의 판과 부딪힌다

사용자 방침으로 판 올림을 문서별로 바로 올리기 시작했다. 마침 같은 날 오준영 님도 산출물목록을 v3.17, v3.18로 올렸고, 내 로컬에는 같은 문서를 v3.17로 올린 미커밋 수정과 지난판 `산출물목록_v3.16.md`가 있었다. 첫 묶음의 병합이 **"Your local changes would be overwritten"**로 멈췄다.

이 멈춤은 오류가 아니라 안전장치였다. 풀지 않고 이렇게 처리했다.

1. 내 수정을 패치와 사본으로 백업한다(`docs/_local/s207-backup/`).
2. 겹친 파일 셋만 되돌린다.
3. 병합하고 push한다.
4. 머지된 새 main(v3.18) 위에서 내 수정을 **v3.19로** 다시 적용하고, 지난판 v3.18을 보존한다.

그 사이 main에 오준영 님의 새 시험이 들어와 4,486건이 4,492건이 되었다. 이미 만든 RTM·계획서 숫자를 다시 맞췄다.

🔑 같은 문서를 두 사람이 고치는 날에는 **병합이 멈추는 것이 정상**이다. 백업 → 되돌림 → 병합 → 새 판 위에서 재적용 순서로 푼다. 판 올림을 작게 자주 하면 이 일이 한 번에 몰리지 않는다.

### 4. 팀원 지적은 맞는 말도 코드로 한 번 더 대조한다

**#580 (신장환 님)**: 카드를 「매수」로 거른 채 새로고침하면 지금 값이 보이는 카드가 아니라 숨은 카드에 붙는다는 지적이었다. 코드를 열어 보니 `qdAttachNow`가 필터와 상관없이 `[data-qd-sym]` 앞 10장을 고르고 있었다. 보이는 카드에서 고르도록 고치고 시험(TC-SCD-26)을 더했다. 그리고 **실제 화면**에서 확인했다. 매수 칩을 건 채 새로고침하니 보이는 8장에만 지금 값이 붙었고 숨은 카드는 0이었다.

**#572 (신장환 님)**: 영상 자막과 내 발표 자료에서 열 가지를 짚었다. 하나씩 코드와 문서로 확인했고 열 개 모두 맞았다. 예를 들면 이렇다.

- 합격선 첫 기준은 손익비가 아니라 PF다(`baseline_trials.py`의 `PASS`). 익절 손익비와 이름이 같아 **같은 말이 두 뜻**으로 나왔다.
- 성과 검증 탭에는 기간 입력칸이 없고, 국내 일봉은 수집 DB의 2020-01-02부터다. 「최근 10년」은 틀렸다.
- 카드의 이동평균 규칙은 교차하는 순간이 아니라 `단기 > 장기`인 **상태**다(`evaluate_spec_rules`).
- 수량은 위험·현금·예산·종목 비중 **네 한도 중 가장 작은 값**이다(`risk_quantity`).

고치는 도중에 **내 정정 문장도 한 번 틀렸다.** 「슬라이드 15장·17장과 같은 근거」라고 썼는데 110개 시도는 내 덱에서 16장에만 나왔다. 쓴 뒤 실제 위치를 grep으로 확인하고 고쳤다.

🔑 지적이 맞는지 **먼저 코드로 보고**, 고친 뒤에는 **내가 쓴 정정이 맞는지도 한 번 더** 본다. 정정은 새 오류를 만들기 쉽다.

### 5. 관측을 원인으로 착각하지 않는다 — company-sector

전 화면 확인에서 `company-sector`가 「새로고침을 눌렀는데 안내 글이 비어 있다」고 나왔다. 코드를 읽어서는 새로고침 뒤 안내 글이 그려져야 했다. 시간대별로 재현해 보니 로드가 끝나면 안내는 정상이었고, **업종 묶음의 첫 계산이 13초** 걸리는 동안 안내 칸이 비어 있었다. 더 나쁜 것은 그 사이 새로고침을 누르면 같은 무거운 계산을 서버에 한 번 더 요청한다는 점이었다(응답 2번, 13.3초와 13.8초).

고친 것은 안내 글 칸이 아니라 **첫 로드 중 상태**다. 안내 글을 보이고 새로고침을 잠갔다.

고친 뒤 실제 화면으로 확인하다가 **내 확인 스크립트가 틀렸다.** 카드가 90초, 170초가 지나도 안 뜬다고 나와서 한동안 내 수정이 로딩을 깨뜨렸다고 의심했다. 그런데 같은 화면을 클릭 없이 열었을 때는 6초 만에 떴고, 원인은 스크립트가 기다린 선택자(`[class*=rounded]`)가 카드에 맞지 않았던 것이다. 선택자를 화면의 글자로 바꿔 다시 재니 첫 계산 11.4초 동안 안내가 보이고 새로고침이 잠겼고 요청은 1번이었다.

🔑 「안 보인다」는 관측과 「안 그린다」는 원인은 다르다. **시간 순서로 재현**하면 원인이 달라질 때가 있다. 그리고 **확인 도구가 실패하면 제품보다 도구를 먼저 의심한다.** 같은 화면을 가장 단순한 방법(클릭 없이)으로 한 번 열어 보면 가려진다.

### 6. 측정 도구가 못 본 것은 「없음」이 아니라 「확인 못 함」으로 적는다

전 화면 24곳을 데스크톱·모바일 두 폭으로 눌러 봤는데, 일곱 화면은 내 탐지 기준(`data-lb-*`)에 안 걸렸다. 기존 검색 줄이거나 계산 뒤에야 생기는 줄이었다. 이것을 「필터가 없다」고 적으면 틀린다. 기록에는 **확인 못 함**으로 분류하고 이유를 붙였다. 관리자 화면은 시연 계정이 관리자가 아니라 403이었다는 것도 그대로 적었다.

그래도 하나는 실제로 찾았다. `paper-stock`의 카드 두 개가 390px에서 오른쪽으로 2px 넘친다(결함 후보).

🔑 측정에 쓴 기준이 틀릴 수 있다. 결과에는 **기준과 한계**를 같이 적는다.

## 막힌 것 · 남은 것

- 필터를 건 채 채워진 표의 동작은 시연 계정에 데이터가 없어 가짜 응답으로만 본 상태다.
- 필터를 건 채 채워진 표의 동작은 시연 계정에 데이터가 없어 가짜 응답으로만 본 상태다(위와 같음).

- API 화면 연결 3곳(`API-STK-39`, `API-NOTI-04`, `API-LEAN-03`)은 호출이 3단계 아래라 아직 `(다른 곳)`이다.
- 오준영 님 시험 파일 둘(`test_strategy_v2_corporate_action.py` 8건, `test_credential_storage_logs.py` 4건)은 묶음 이름 확인 전이라 대장 밖이다.
- 점검표의 오래된 51행은 화면 파일 변경 이력만으로는 점수 영향을 가를 수 없어 점수를 바꾸지 않았다.

## 배운 것

1. **자동 채움 출력이 줄면 도구부터 의심한다.** 148 → 132는 기능이 아니라 구조 변화를 못 따라간 것이었다.
2. **도구는 목록에 있는 것만 센다.** 새로 만든 시험·화면·표는 목록에 올린다.
3. **같은 문서를 같은 날 두 사람이 고치면 병합이 멈춘다.** 백업하고 되돌리고 새 판 위에서 다시 올린다.
4. **지적은 코드로 대조하고, 내 정정도 대조한다.**
5. **관측과 원인을 나눈다.** 재현은 시간 순서로 한다.
6. **측정 결과에는 기준과 한계를 적는다.** 못 본 것은 「없음」이 아니다.
