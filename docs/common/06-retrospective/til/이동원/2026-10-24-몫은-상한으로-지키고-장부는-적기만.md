## 배운 것

- **몫은 상한으로 지키고, 장부는 적기만 한다.** OpenDART 는 남은 횟수를 알려 주지 않는다. 그래서 「오늘 몇 번 불렀나」 를 세는 장부를 두되, 장부가 막게 하지 않았다 — 막는 일은 단계마다의 상한(`--max-calls`)이 하고, 상한 합(3,000)은 시험이 지킨다. 장부가 막으면 장부 파일 하나가 깨졌을 때 수집이 멈춘다. 장부는 못 써도 수집은 끝까지 간다.
- **큰 일은 회차 밖으로.** 지난 해 채우기(하루 15,000회)는 러너 단계가 아니라 회차가 끝난 뒤에만 돈다 — 시작할 때와 부르기 전마다 회차 잠금 · 12:20 ~ 13:20 을 보고 멈춘다. 같은 하루 한도를 나눠 쓰는 둘이 서로를 모르게 두면 회차가 한도에 걸린다.
- **같은 판은 처음 값.** DART 재무 API 는 지금 판만 준다. 분기 대조에서 같은 접수번호인데 값이 바뀌어 있으면(조용한 고침) 우리 줄을 고치지 않고 대조 표에 적는다 — 백테스트가 「그날 알 수 있었던 값」 만 읽게.
- **계획 글의 `USING` 은 훑기에도 붙는다.** 깨 보기에서 접수번호 색인을 지워도 「마지막 날짜 질의가 색인을 쓰나」 시험이 통과했다. SQLite 는 기본 키 자동 색인을 처음부터 끝까지 훑으면서도 계획 글을 `SEARCH … USING COVERING INDEX` 로 적는다(60만 줄 임시 DB 에서 0.0ms → 72ms). 그래서 「쓰는 색인의 앞 칸이 정말 찾는 칸인가」 까지 보게 시험을 고쳤고, 고친 시험이 ECOS 표도 같은 꼴로 훑는 것을 찾았다(약 8만 줄 · 7ms — 작은 표로 둠).
- **깨 보기 도구도 옮길 짐이다.** 노트북에서 메모리가 모자라 데스크톱으로 옮기며 깨 보기 도구(scratchpad)를 두고 왔다. 목록만 남아 데스크톱에서 다시 짰고, 그 덕에 놓친 셋(분기 대조 하루 50곳 · 연결 → 별도 떠보기 · 색인)을 찾아 시험 둘을 더했다.
