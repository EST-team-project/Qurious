> 11-04 낮에 두 일이 겹쳤다. 하나는 사용자의 지시 「C202 학습 장 이어쓰기부터 쭉 진행」이었고, 다른 하나는 오준영 님이 #530 에 올린 **3차 처리 안 된 이슈 94개 · PR 152개 검토**에서 이동원이 지목된 항목들이었다.

---

## 개념 정리

### 1. 장에 쓴 주장은 요약 말고 원문에서 확인한다

학습 장 네 편(C202 공개 API · C203 데이터셋 버전 관리 · C204 배치 스케줄링 · C205 거래일 달력)을 뼈대에서 초안으로 다시 쓰고, 장 여덟 편을 더했다(뉴스 · 공시 수집, 다중 시장 레지스트리, 현재가 실시간, 국면 동적 배분, 팩터 스크리닝, 재무 필터, 기술 스크리닝, 스트레스 시나리오). 장 수 단언은 71 에서 79 로 올렸고 사용자가 시험 수정을 허용했다.

그리고 사용자 지시대로 **원문 대조**를 했다. 검색 요약이나 기억이 아니라 원문 HTML · PDF 를 `urllib` 로 받고 `pdftotext` 로 풀어서 읽었다. 약 45개 주장을 맞춰 보았다.

| 결과 | 건수 |
|---|---|
| 일치 | 40여 개 |
| 장 수정 | 6곳 |
| 못 열어 본 것 | 4곳 (BCBS d450 PDF는 차단, George–Hwang 2004는 주소 404, SEC T+1은 403, Hamilton) |

수정한 6곳의 예는 이렇다. C204 의 SRE 월급 문장은 근거와 달라서 고쳤고, C202 의 GCS 인증 문장은 원문에 없어서 지웠다. C908 에는 Park–Irwin 2010 의 「17개 중 2개」를 추가했고, C910 은 연준 기준과 최악 시나리오로 바로잡았다.

못 열어 본 것은 **확인한 것처럼 쓰지 않았다.** 장의 `status` 는 `draft` 로 유지했다. sec.gov 와 bis.org 의 PDF 는 자동 접근이 막혀 있어서 브라우저(사용자 손)가 필요하다.

🔑 요약 경유의 주장은 **원문과 대조하지 않은 주장**이다. 열 수 없었던 곳은 「못 열었다」고 적어 둔다.

### 2. 사실 규칙을 장 앞에 정해 두면 쓰면서 흔들리지 않는다

장을 쓰기 전에 규칙을 정했다. 조사 메모에서 「직접 열람」으로 표시된 것만 단정하고, 2차 자료는 「보도에 따르면」으로 쓴다. 요약을 거친 출처는 「더 읽을거리」에 원문 대조 주석을 단다. C205 에서는 코드를 확인해야 하는 목록을 따로 만들었다: 앱의 휴장일 손목록(17일)과 수집기 달력이 정본이 둘이라는 점, 5/1 의 옛 이름, 대체휴장의 특일정보 반영, 위클리 옵션 만기가 없다는 점.

🔑 규칙은 **쓰기 전에** 정한다. 쓰는 중에는 고치기 쉬운 쪽으로 기운다.

### 3. 지목된 항목은 이슈로 먼저 꺼내고 팀원별로 나눠 묻는다

오준영 님의 #530 검토는 이동원 몫을 여럿 짚었다: 알림 웹훅 · SMTP 비밀 암호화 범위(#397 · #469 · #474), 코인 최소 주문금액(화면 1,000원, 서비스는 0 초과라 500원 매수 성공을 재현), DSR 근사 설명 누락(#362), 체결 시점 정렬안(#503), 실제 TradingView · Pine 검증, 이름표 200표본, #512 차트 설명, 기능완성도 표 갱신.

먼저 에이전트가 코드로 대조한 결과(`docs/_local/issue530-check-2026-11-04/대조결과.md`)를 **줄 단위로 내가 다시 확인한 뒤에** 답글을 썼다. 이 글의 주장은 코드로 확인하기 전에는 사실로 쓰지 않는다는 규칙이다.

사용자의 지시는 이랬다. 「이동원 역시도 필요한 부분에 대해서 오준영님처럼 이슈를 생성하는 것이 좋을 것 같습니다.」 처음에는 별도 이슈 세 건(알림 암호화 설계 · 최소금액 정책 통일 · #439 만료 판단)을 약속했는데, 사용자가 **한 이슈에 합치고 파트 · 팀원별(오준영 · 강민석 · 신장환)로 나눠 쓰라**고 해서 통합 이슈 #533 으로 바꿨다. 팀원마다 자기 몫만 읽으면 되게 한 것이다.

| 팀원 | #533 에서 묻는 것 |
|---|---|
| 오준영 | 알림 암호화 키 재사용 |
| 강민석 | 서버 최소금액 · DSR 문구 · 체결 시점 · #439 |
| 신장환 | #512 문구 · #446 |

약속한 화면 문구 3종(코인 최소금액 안내, DSR 각주, 차트 설명 세 경우)은 로컬에서 먼저 고쳤고(`paper.js` · `common.js` · `app.html` · `robo.js` · `stockchart.js`), PR #535 로 올렸다. 서버의 최소금액 `ge=1000` 은 강민석 님 코드라 **제안만** 했다.

🔑 팀원의 코드는 고치지 않고 **제안한다.** 내 몫은 화면 문구와 설계이고, 나머지는 질문으로 남긴다.

### 4. 암호화는 합의 → 백업 → 구현 순서로 간다

#533 에 오준영 님이 답했다. 알림 비밀을 증권사 자격증명과 같은 키(`BROKER_CREDENTIAL_KEY_FILE`)로 암호화하는 설계에 동의했고, 경계를 다섯 개 제시했다.

1. 증권사 암호문 형식은 바꾸지 않는다.
2. 알림용 식별자와 `notification_settings.<필드>` 를 AAD 로 쓰고 새 nonce 를 쓴다.
3. 비밀 필드만 암호화한다(발신 프로필 키 포함).
4. 칸을 `Text` 로 바꾼다.
5. 키 오류가 나도 평문으로 우회하지 않는다.

그 사이 오준영 님은 12:54 에 운영 DB 암호화 백업과 일회용 DB 복원 검증을 끝냈다. 사용자는 **전화번호 칸은 이번에는 뺀다**고 정했고, 구현은 11-05 판 올림 뒤(11-06~08 리허설 DB)에 시작하기로 했다. 그날 15:45 운영 전환은 하지 않았다. 구현 자체가 검증됐다는 뜻은 아니라는 것을 답글에 적었다.

🔑 합의, 백업, 복원 검증이 끝나기 전에는 구현에 들어가지 않는다. **동의는 검증이 아니다.**

## 직접 해 본 것

- C202~C205 네 편의 예제를 실행해 출력을 붙였다(Python 3.13.14 `-X utf8 -I`). 그림 4개는 SVG 로 만들었고 글자는 path 로 바꿨다. 학습 시험 49건이 통과했고, 앱(8966)에서 장 · 그림 · 예제가 200을 돌려주었다.
- 에이전트의 코드 대조 표를 줄 단위로 다시 열어 답글 초안에 쓸 문장만 골랐다.
- #530 이동원 답글은 사용자가 올렸고(11-04), 이어 통합 이슈 #533 을 올렸다.

## 막힌 것 · 남은 것

- **원문을 못 연 곳**은 BCBS d450 PDF · George–Hwang 2004 · SEC T+1 · Hamilton 이다. 장 `status` 는 draft 다.
- 장 본문 줄 수가 285~295줄로 규칙(150~260줄)을 넘었다. 출력 블록 때문이다.
- 남은 새 장(C206~C208 · C905~C908 · C910)은 아직 파일이 없다.
- 알림 암호화 ⑦(키 오류 완화 범위)은 사용자에게 아직 묻지 않았다. 기본은 런타임 fail-closed 만이다.
- 판 올림에서 `map.md` 와 장 대장의 「지금 상태」 칸은 「뼈대 → 초안」으로 고쳐야 한다(이번에는 건드리지 않았다).

## 배운 것

1. **요약을 거친 주장은 원문과 맞춰 본다.** 열 수 없었던 곳은 열지 못했다고 적는다.
2. **작성 규칙은 쓰기 전에 정한다.** 직접 열람 / 보도 / 요약 경유를 나눠 쓴다.
3. **지적받은 몫은 이슈로 꺼내 팀원별로 나눈다.** 각자 자기 몫만 읽는다.
4. **남의 코드는 제안으로 남긴다.** 서버 최소금액은 강민석 님 코드라 고치지 않았다.
5. **동의와 검증은 다르다.** 백업과 복원 검증이 끝난 뒤에 구현한다.
