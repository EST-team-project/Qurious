## 배운 것

- **시험이 호스트에서만 돌면 컨테이너 안은 아무도 못 본다.** 카드 API 시험은 통과했는데 앱 컨테이너에서는 `cards: 0` 이었다. 이미지가 `docs/` 를 복사하지 않아서다. 시험은 「이 함수가 맞게 계산한다」 만 보았고 「이 파일이 실행되는 곳에 있다」 는 보지 않았다. 지금은 Dockerfile 복사 줄 · 개발 compose 마운트 · 코드가 읽는 경로가 같은지를 시험(TC-SC-IMG)으로 지킨다. 새 API 를 만들면 **실행 중인 앱에서 한 번 부른다.**
- **라우트 함수 이름이 가져온 모듈 이름과 같으면 모듈이 가려진다.** `macro_industry` 라는 서비스 모듈을 가져오고 같은 이름의 라우트 함수가 이미 있었다. 라우트를 실제로 부르는 시험(TC-MI-05)이 없었다면 서버에서 처음 호출할 때 500 이 났을 것이다. 서비스 함수만 시험하지 말고 **라우트까지 한 번** 부른다.
- **화면 안의 칸이 어느 화면 소속인지는 줄 번호 범위가 아니라 화면 경계로 가린다.** `pc-card` 가 W17 안에 있다고 답글에 썼다가 틀렸다(`indicator-tradingview` 안). 줄 범위를 훑는 방식은 다음 화면이 시작되는 줄을 넘어서도 읽는다. `data-view` 를 따라가며 현재 화면을 추적한다.
- **기존 시험이 함수를 직접 부르면 인자 순서도 계약이다.** `login(body, response)` 로 부르는 시험 셋이 내가 `request` 를 중간에 끼우자 깨졌다. 일회용 PG 시험을 돌리고서야 알았다. 인자는 맨 뒤 · 선택으로 더한다.
- **같은 코드에 이름이 둘이면 어느 쪽이 나올지 정해지지 않는다.** KSIC 이름 표에 10차와 11차가 함께 들어 있었다. 우리 351곳의 업종코드가 11차에는 모두 있고 10차에는 349곳뿐이라는 **데이터로 개정판을 정했다.**
- **약관은 앱이 하는 일만 쓴다.** 조사가 「암호화해 보관」 · 「누구였는지 지운 채 남김」 이 코드와 맞지 않는다고 짚었다(증권사 키는 평문 칸 · 탈퇴 뒤에도 고객번호 문자열은 남음). 기존 탈퇴 안내문까지 사실대로 고쳤고, 약관 시험이 금지어와 로그인 잠금 숫자를 코드와 견준다.
- **로그인 제한은 「맞는 비밀번호도 막는다 · 없는 이메일도 똑같이 센다 · Redis 가 죽으면 열린 채」 가 한 묶음이다.** 하나만 빠져도 가입 여부가 새거나 정상 사용자가 갇힌다. 만료가 빠진 키(INCR 뒤 끊김)를 다시 붙이는 것도 시험으로 만들었다.
- **브라우저가 `app.html` 을 캐시하면 새 칸이 안 보인다.** 화면을 확인할 때는 주소에 `?v=` 를 붙인다.
