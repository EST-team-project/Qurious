## 1. 도움이 필요할 때 — 키 · 계정 · 승인

키 값은 사람(팀장)이 로컬 `.env` 에 넣는다. AI 도구(Claude Code 등)는 `.env` 의 값을 읽거나 출력하지 않고 **이름만** 쓴다. 새 키가 필요하면 작업 보고의 「도움이 필요한 것」 칸에 키 이름 · 받는 곳 · 쓰는 곳을 적고, 키가 없을 때도 화면 · 수집 단계가 멈추지 않고 「키 없음」 을 알리게 만든다.

**<표 1> 키 이름과 쓰는 곳** — 값이 아니라 이름이다. 견본은 `.env.example`.

| 키 이름 | 받는 곳 | 쓰는 곳 | 지킬 조건 | 없을 때 |
|---|---|---|---|---|
| `FINANCE_SUPERVISORY_API_KEY` | 금융감독원 「금융상품 한눈에」 오픈 API | 상품 안내 현금성 탭 — 예금 · 적금 · 연금저축 | 개인 1일 10,000건 · 12개월 쓰지 않으면 삭제 · 키 양도 금지 · 받은 값 저장 금지 · 출처 문구 표시(이용약관 제5 · 7 · 9조) | 화면에 「키 없음」 안내 · 고칠 곳은 관리자에게만 |
| `DATA_GO_KR_API_KEY` | 공공데이터포털 | 매일 시세 수집(주식 · ETF 등) | 데이터마다 이용 조건(예: 증권상품시세정보는 공공누리 제4유형) | 그 수집 단계를 건너뛰고 까닭을 남김 |
| `DART_API_KEY` | 전자공시 OpenDART | 공시 · 재무 수집 | OpenDART 이용 조건 | 같음 |
| `LAW_API_OC` | 국가법령정보 공동활용 | 근거 법령 수집 | 공동활용 이용 조건 | 같음 |
| `HUGGINGFACE_ACCESS_TOKEN` | Hugging Face 조직 `qurious-quant`(write) | 팀 데이터셋 올리기 · 받기 | 데이터셋은 모두 private | 올리기 단계를 건너뜀 |
| `KIS_APP_KEY` · `KIS_APP_SECRET` | 한국투자증권 Open API(모의) | 모의 주문 · 잔고 | 토큰 발급 횟수 제한 | 증권사 연동 칸이 「연결 안 됨」 |

## 2. 모은 자료는 어디에 두나 — Hugging Face private 데이터셋

필요한 자료는 **그때그때 받아** 팀 조직 `qurious-quant` 의 **private 데이터셋**에 둔다. 로컬 사본은 `data/collector/` 아래에 두며 git 에 커밋하지 않는다.

**<표 2> 보관 규칙**

| 규칙 | 내용 | 까닭 |
|---|---|---|
| 데이터셋 하나 = 기능 · 종류 하나 | 예: `product-guide-regulations`(상품 안내의 규제 근거 원문) | 기능을 고칠 때 그 근거만 찾아 읽게 |
| 원문마다 폴더 하나 | `sources/<발행처>/<해>/<날짜>_<열쇠>/` 에 받은 원문 · 본문 글자(`text.txt`) · 메타(`meta.json` — 제목 · 주소 · 받은 때 · sha256 · 쓰는 곳) | 같은 기관의 글이 해마다 쌓여도 날짜로 찾는다 |
| 색인 · 매니페스트 | `index.tsv`(한 줄 = 원문 하나) · `meta/manifest.json`(파일마다 sha256 · 크기) | 받은 쪽에서 무결성을 대조한다 |
| 열쇠를 코드와 맞춘다 | 코드의 상수표가 쓰는 출처 열쇠 = 데이터셋 열쇠(예: `etp_requirements.SOURCES` 의 `fsc_2026_07_24`) | 숫자를 고칠 때 그날 원문으로 바로 간다 |
| 사본을 두지 않는 글 | 증권사 공지 · 다른 회사 글 · 법령은 주소만 색인에 적는다(`copy=False`) | 회사 저작물 · 법령은 국가법령정보센터가 판을 관리 |
| 판 = 태그 | 올릴 때마다 `<이름>-<날짜>` 태그(예: `regulations-2026-10-12`) | 지난 판으로 되돌아가 읽을 수 있다 |
| 관문 넷 | 공유 스위치 · 로컬 sha256 · hf_xet · **원격이 실제로 private 인지 확인** — 하나라도 못 넘으면 올리지 않는다 | 이미 있는 저장소는 `private=True` 로 만들어도 공개 범위가 바뀌지 않는다 |

올리는 차례는 스크립트마다 같다: `build`(또는 `export`) → `status` → `upload`(미리 보기) → `upload --yes` → `verify`(받아서 sha256 대조).

**<표 3> 이 문서와 함께 만든 데이터셋**

| 데이터셋 | 무엇 | 스크립트 | 갱신 |
|---|---|---|---|
| `qurious-quant/product-guide-regulations` | 상품 안내 「실제로 사려면」 요건의 근거 — 금융위원회 · 금융감독원 보도자료 원문 사본 8 · 주소만 2 | `scripts/hf_regulations.py` | 규제가 바뀌어 상수표를 고칠 때 |

다른 팀 데이터셋(시세 · 일봉 · 공시 · 근거 법령 · 검색 색인 등)의 목록과 크기는 앱의 「자료 안내」 화면과 HF 조직 쪽에서 본다.

## 3. 저장하지 않는 자료

**<표 4> 저장하지 않는 자료와 대신 하는 일**

| 자료 | 까닭 | 대신 |
|---|---|---|
| 금융감독원 「금융상품 한눈에」 응답(예금 · 적금 · 연금저축) | 이용약관 — 실시간 조회만 · 저장 · 복제 · 전송 금지 | 볼 때마다 받아 보여 주기만 한다(캐시 · DB · 파일 없음 — 시험 TC-FL 이 코드에 저장하는 줄이 없는지 본다) · 출처 문구를 그대로 |
| 증권사 공지 · 다른 회사 글 | 그 회사 저작물 | 주소만 색인에 |
| 개인정보 · 계좌 · 키 값 | 보안 | 저장소 · 데이터셋 어디에도 두지 않는다 |
| 강의 자료 원본(교재 · 강사님 배포 원문) | 저작권 · 수업 규칙 | 커밋 · 업로드하지 않는다 |
| 공공누리 제4유형 자료(예: 증권상품시세정보) | 변경 금지 · 재배포 금지 | 서비스 안에서 보기만 · 내려받기 단추를 두지 않는다 · 팀 데이터셋은 private |

## 4. 작업을 마칠 때 점검표

- [ ] 이번 작업에 새 키 · 계정 · 승인이 필요했나 → <표 1> 에 줄을 더하고 보고의 「도움이 필요한 것」 에 적었다
- [ ] 새로 받은 자료가 있나 → 2절 꼴로 private 데이터셋에 올리고 `verify` 까지 했다 · 열쇠를 코드 상수표와 맞췄다
- [ ] 저장하면 안 되는 자료(3절)를 저장하지 않았다
- [ ] 이 문서와 자료 안내 출처 대장을 고쳤다
