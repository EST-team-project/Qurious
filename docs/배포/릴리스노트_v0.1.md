> **이 문서로 알 수 있는 것**
> 1. 날짜마다 사용자가 볼 수 있는 무엇이 더해지고 · 바뀌고 · 고쳐졌나?

## 요약

릴리스는 아직 태그를 붙이지 않고, **main 에 머지된 날짜**를 릴리스 이름으로 쓴다(제안 · 1절). 2차가 시작된 10-01 부터 사흘 동안 사용자가 볼 수 있는 큰 변화는 투자 대시보드(로그인 첫 화면), 용어사전 화면과 모든 화면의 용어 설명, 데이터 관제와 금융 일정 화면, 법령 근거 찾기 API, 모의계좌 성과 지표다. 증권사 모의 키는 사용자마다 따로 쓰게 바뀌었다.

## 1. 읽는 법

- 한 릴리스 = 그날 main 에 머지된 PR 묶음이다. 태그 · 판 번호(예: 0.2.0)를 붙일지는 팀이 정한다.
- 갈래는 넷이다 — **추가**(새 기능) · **변경**(있던 기능의 동작) · **수정**(결함) · **보안**. 문서만 바뀐 PR 은 「문서」 한 줄로 모았다.
- 줄 끝 괄호는 PR 번호, `DF-NN` 은 결함대장 번호다.

날짜별로 머지된 PR 수는 <그림 1> 과 같다.

## 부록 A. 만든 방법

- `git log --merges --first-parent main --since=2026-09-23` 의 머지마다 PR 번호와 브랜치 끝 커밋의 제목을 뽑고, 사용자에게 보이는 변화만 골라 네 갈래로 나눴다. 코드 정리 · 문서만 바뀐 PR 은 「문서」 한 줄로 모았다.
- 갈래는 Keep a Changelog 1.1.0 을 따랐다(https://keepachangelog.com/en/1.1.0/).
- 다음 판은 새 날짜의 릴리스를 맨 위에 더한다. 각 주담당은 자기 PR 의 줄을 직접 고친다.
