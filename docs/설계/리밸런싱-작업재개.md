## Docker 환경

실서비스 프로젝트는 **qurious**. 다른 강사님 프로젝트 lumina-invest와 이름/네트워크/DB를 분리한다.

```bash
docker compose -p qurious -f docker-compose.yml -f scripts/personal/compose.qurious.yml build app
docker compose -p qurious -f docker-compose.yml -f scripts/personal/compose.qurious.yml up -d --no-build app celery-worker celery-beat
```

홈: http://localhost:8966 / 리밸런싱: http://localhost:8966/app.html#robo-rebalance
`.env`는 비공개 로컬 설정이므로 출력하거나 커밋하지 않는다.

시험용 컨테이너: `qurious-rebalance-tests` (네트워크 qurious-net, 저장소 /workspace 읽기 전용 마운트).
시험용 DB: `qurious_rebalance_test` on `qurious-postgres` — **실서비스 DB fin_ai와 별개**.
컨테이너 DATABASE_URL/QURIOUS_TEST_DATABASE_URL에 시험 DB 설정이 있다. pytest는 이 컨테이너에 설치했으며, 새 컨테이너를 만들면 다시 필요.
시험용 uvicorn은 `docker exec -d ... sh -c 'uvicorn app.main:app --host 0.0.0.0 --port 8000 > /tmp/ui-server.log 2>&1'`로 시작했다. 컨테이너 재시작 시 재실행해야 한다.

주의: 계정/장부 회귀 시험은 시험 DB 테이블을 drop/create한다. 브라우저 시험과 동시에 돌리지 않는다. 회귀 시험 후에는 시험 DB 전체 스키마 재생성 및 시험 서버 재시작이 필요하다.
