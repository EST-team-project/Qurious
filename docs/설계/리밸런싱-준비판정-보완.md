## 1. 결정 기록과 적용 범위

배당·공시·뉴스 등 비필수 단계가 실패하면 전체 회차 `ok=false`가 된다. 기존 리밸런싱은 시세와 달력이 준비됐더라도 이 값 때문에 판단·정산을 모두 기다렸다. 리밸런싱 준비 판정에서 전체 `ok` 의존을 제거하고, 필수 자료의 성공과 신선도를 직접 확인한다. 관제의 전체 회차 결과와 원본 기록은 변경하지 않는다.

2026-10-12 주담당이 #163에 의견을 게시하고 사용자 승인으로 구현했다. 전체 팀의 최종 합의나 운영 배포 완료를 뜻하지 않는다. 이전 설계서 및 #124의 **전체 러너 성공 유지** 정책은 이번 작업본의 준비 판정에 한해 이 문서로 대체한다. 기존 설계서 v0.2·v0.3은 과거 기록으로 보존한다.

## 2. 준비 판정과 종목별 검증

준비 판정의 진입점은 [rebalance_daily.readiness](../../app/services/rebalance_daily.py)다. 수동 미리보기·실행과 일별 점검·예약 정산이 같은 기준을 사용한다.

| 검사 | 허용 조건 / 실패 시 처리 |
|---|---|
| 거래일·시각 | 거래일이며 12:30 이후. 휴장일·이전 시각이면 대기 |
| 회차 기록 | 당일 12:30 이후 시작. 시간대 있는 시작·완료 시각, 시작 ≤ 완료 ≤ 현재 |
| 실행 중·중단 | 잠금 파일 없음, 실행 중 아님, `stopped` 없음. 오래된 잠금도 완료로 간주하지 않음 |
| 시세·달력 | `price`, `calendar` 각각 하나의 기록, 정수 종료코드 `0`. 누락·중복·실패·건너뜀은 대기. 문자열 `"0"`·불리언 `false`도 거부 |
| 기준일 | 실제 수집 DB `as_of`와 회차 `price_max`가 정확한 전 거래일과 일치 |
| 비필수 단계 | 실패하더라도 위 조건을 만족하면 리밸런싱 준비 허용. 관제에는 실패·경고 유지 |

`ready=true`는 회차 공통 조건의 충족이다. 모든 종목의 가격이 준비됐다는 뜻은 아니다. 이후 [종목별 가격 조회](../../app/services/rebalance_prices.py)와 [정산](../../app/services/rebalance_settlement.py)에서 다음을 계속 검사한다.

- 판단은 관리 대상 주식·ETF의 **정확한 전 거래일 원종가**를 요구한다. 누락 시 과거 날짜나 현재가로 대체하지 않고, 일별 판단 완료일을 소비하지 않는다.
- 예약 정산은 **예약 체결일 원시가**를 요구한다. 일부 종목만 준비되면 전체 예약을 대기한다.
- 해당 날짜·출처의 `ingest_day.status=done` 뒤 가격 행 없음·거래정지·거래량 0을 확인해야 `cancelled / open_not_tradable`로 종료한다. 주식 완료로 ETF 완료를 대신하지 않으며, 출처 불명은 양쪽 완료를 요구한다.
- 거래량이 있는데 시가가 잘못된 경우는 자료 오류로 대기한다. 잠금·재시도·중복 정산 방지·비용 계산은 기존 정책을 유지한다.

## 3. 검증 근거

실제 SQLite 형식의 시험 수집 DB와 격리 PostgreSQL 18을 사용했다. 가격·시계·회차 기록은 시험 입력이며 운영 수집 회차 증거가 아니다.

관련 시험 **233개 최종 통과, 실패·건너뜀 0**. 최초 확대 실행은 231개 통과·2개 실패였고, 임시 환경의 누락 패키지 `PyYAML` 설치 후 실패한 러너 시험 2개만 다시 실행해 통과했다. 실행 로그·JUnit 결과는 Git 제외 경로 `data/local-run/rebalance-readiness-163-20261012/`에 보관한다.

이후 연결된 **실제 수집 DB의 가격·달력·출처별 수집 완료 자료로 추가 6개 시나리오를 통과**했다. 주식끼리·주식→ETF·ETF→주식 각각 정상 회차와 비필수 실패 회차를 재현했다. 현금·수량·비용을 독립 계산하고 반복 정산 방지를 확인했다. 자세한 범위와 숫자는 [실수집 자료 정산 검증 결과서](../시험/리밸런싱-실수집자료-정산검증.md)에 기록했다. 원본 러너 기록 부재가 실제 가격을 사용한 정산 검증을 막지는 않는다.

| 시험 | 확인 내용 |
|---|---|
| [일별 준비 판정](../../tests/test_rebalance_daily.py) | 수정 전 비필수 실패 5종에서 차단 재현. 수정 후 허용, 관제 경고·원본 파일 유지. 필수 단계 누락·실패·잘못된 종료코드·중복 차단 |
| [수동 경로](../../tests/test_rebalance_unified.py) | 전체 `ok=false`에서도 유효한 종가로 미리보기·예약. 즉시 주문 없음, 필수 실패 때 대체 가격 없음 |
| [혼합 주식·ETF 정산](../../tests/test_rebalance_settlement.py) | ETF 종가 누락 → 재시도 예약 → 시가 누락 대기 → 출처 완료 후 체결 또는 미체결 종료. 반복 실행 시 중복 주문 없음 |
| [예약 예외](../../tests/test_rebalance_exceptions.py) | 출처별 완료, 취소·휴장일 이동·잘못된 시가 대기 보호 |

관련 회귀 시험 명령(시험용 DB만 지정):

```sh
python -m pytest tests/test_rebalance*.py tests/test_paper_ledger_i14.py tests/test_risk_guard*.py tests/test_data_status.py tests/test_daily_update.py tests/test_migration_heads.py
```

## 4. 남은 작업과 경계

1. **#124 실제 수집 가격 정산 검증 완료:** 현재 수집 자료로 예약 → 체결 → 현금·보유 수량·비용·중복 방지 검증을 마쳤다. 같은 회차 원본 `state/daily_update_last.json`을 대조하는 운영 연동 확인은 별도 후속이다.
2. **#124 공통 종목 상태 조회:** 데이터 담당의 계약이 확정되면 `ingest_day` 직접 조회를 연결한다. 계약 미확정 상태에서 새 API를 가정하지 않는다.
3. **#163 DF-99:** 러너에서 따라잡기·정기 회차 충돌을 막는 안에 찬성했다. 이 변경은 리밸런싱의 당일 12:30 시작 조건을 완화하지 않으며 DF-99 수정 완료를 의미하지 않는다.
4. 큰 KIS 리밸런싱 변경과 회차 중간 준비 기록은 별도 범위로 검토한다. #124의 실제 가격 정산 검증 항목은 완료이며, 공통 조회 계약·운영 연동 확인과 이슈 종료 판단을 구분한다.
