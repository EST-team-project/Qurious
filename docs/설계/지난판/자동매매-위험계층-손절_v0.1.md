## 2. 실제 위험 점검 순서

근거: `app/services/auto_trade.py`, `aggressive_mode.py`, `risk_guard.py`.

1. 활성 사용자에 대해 사이클을 시작하고 비상 정지 스위치를 확인한다. 켜져 있으면 주문 판단을 진행하지 않고 자동매매 활성 플래그를 내린다.
2. 가격·지표와 전략을 계산한다. 공격 모드는 평균매입가 대비 익절/손절과 약세 신호로 매도 후보를 만든다. 매도 후보 수에도 사이클별 상한이 있다.
3. **주문 루프 전 일손실 한도**를 확인한다. 자동매매 가상 장부의 당일 첫 관측 자산 대비 손익이며 기본 한도는 3%다. 게이트웨이 연동 `live` 경로는 증권사 계좌 평가액도 별도 확인한다. 도달하면 비상 정지하고 루프에 들어가지 않는다.
4. 매수 수량은 고정 주문 예산 × 매수 비율 ÷ 현재가로 정한다. **손절 거리 기반 수량이 아니다.** 기본 주문 예산은 100만 원, KIS 배치 설정은 30만 원이며 사용자 설정에 따라 다르다. 기존 코드에 최소 1주 보정이 있어 1주 가격이 예산보다 높으면 산식상 예산을 넘을 수 있다. 이후 현금·비중 한도가 추가로 적용된다.
5. 주문 직전 게이트는 **일 주문 수 → 매수의 종목 비중 → 같은 종목·방향 쿨다운** 순서다. 종목 비중 기본 30%이며 게이트웨이 미체결 매수 노출도 더한다. 매도는 비중 상한 검사를 건너뛰지만 일 주문 수와 쿨다운은 적용된다. **손절 매도도 예외가 아니다.**
6. 가상 장부에 비용·현금을 반영한 뒤, 연결 설정에 따라 증권사 일반 주문을 전송하고 별도 상태를 추적한다. 가상 체결과 증권사 접수·체결은 같은 상태가 아니다.
7. 사이클 이후 가상 장부의 일손실 한도를 다시 확인한다.

공격 모드를 켜면 쿨다운과 일 주문 수 상한은 공격 모드 설정으로 바뀐다. 위험 상태 API도 이번에 같은 유효 설정을 표시하도록 맞췄다. 기본값은 `app/config.py` 기준이며 운영 환경변수는 별도로 읽거나 변경하지 않았다.

**장부 경계:** 자동매매는 `QuantVirtualAccount + Portfolio.book=QUANT`, 리밸런싱·직접 모의 주문은 `PaperAccount + book=PAPER`다. 이 문서의 3%·30% 한도가 PAPER 리밸런싱 전체에 자동 적용된다는 뜻이 아니다.

## 3. 비상 정지와 미체결

비상 정지는 자동매매를 끄고 추적 중인 접수/부분체결 게이트웨이 주문의 취소를 요청한다. 보유 주식을 시장가로 전량 청산하지 않는다. 취소 요청도 취소 완료와 다르며, 이미 진행 중인 주문/체결을 되돌린다고 보장하지 않는다.

| 상태/상황 | 실제 처리·이번 확인 |
|---|---|
| `ACCEPTED` / `PARTIALLY_FILLED` | 기본 2분 체결 확인 작업으로 조회. 수량·상태 갱신. 남은 수량에 대해 새 주문을 자동 생성하지 않음 |
| 오래된 접수/부분체결 | `STOCK_COIN_TRADE_CANCEL_OPEN_AFTER_MIN > 0`이면 취소 요청. 기본값 0은 기능 꺼짐 |
| `UNKNOWN`, 주문번호 없음 | 게이트웨이까지 요청이 닿았는지 알 수 없음. 활성 live 설정·정지 해제 상태에서만 같은 `clientOrderId`로 정해진 시간 창 안에 재전송. 원래 요청이 미접수라면 이 재전송이 신규 주문을 만들 수 있음 |
| **정지 중 `UNKNOWN`** | **이번 수정:** 사용자 본인의 DB 설정에서 비상 정지·자동매매 비활성·live 경로 아님·설정 없음이면 재전송을 보류. `UNKNOWN`을 유지하고 증권사 내역 수동 확인 안내. 정지 중에는 시간 창 만료로 임의 해소하지 않음 |
| 재전송 허용 상태에서 시간 창 만료 | 기존 정책대로 `LOST`, 알림·수동 확인. 미접수나 취소 완료가 확정됐다는 뜻이 아님 |
| 주문번호가 있는 주문, 정지 이후 | GET 체결 확인은 계속한다. 이미 체결된 결과를 누락하지 않음 |
| 수동 비상 정지 버튼 | 기존에는 자동매매 비활성만 처리했다. 이번에 미체결 취소 요청도 추가하고 요청/실패/미확인 수를 API에 반환. 실패해도 앞서 저장한 정지 상태는 유지 |
| 하한가·VI·거래정지 | 별도 시장 상태 판정·손절 재주문 정책은 아직 없음. 게이트웨이의 거절/부분체결/미체결 상태로 다루므로 실제 해당 시장 상황을 재현한 검증과 구분 |

정지 해제만으로 자동매매가 재시작되지는 않는다. 응답 불명 주문은 증권사 기록에서 확인한 뒤 재개해야 한다. 재전송 직전 DB 상태 확인으로 정지 후 별도 작업이 주문을 새로 보내는 경로를 막았지만, 이미 진행 중인 네트워크 요청과 정지 요청 전체를 원자적으로 묶은 것은 아니다.

**추가 점검이 필요한 기존 동작:** 증권사 계좌 평가 조회 실패 시 별도 계좌 일손실 검사 결과가 `breached=False`로 돌아오는 경로, 가상 매도 완료 후 실주문 실패 시 장부 차이, 자동매매 사이클 도중의 동시 정지, 주문번호 없는 주문의 조회 계약은 후속 대상이다. 미체결 자동 재주문이나 손절의 한도 우회는 이번에 추가하지 않았다.

## 4. 비용 뒤 손익비

`app/services/risk_execution.py`는 기존 `trading_cost.cost_rate`의 매수/매도 비용을 각각 사용한다. 같은 진입 금액을 기준으로 다음을 계산한다.

```
익절 순수익률 = (1 + 익절률) × (1 - 매도 비용률) ÷ (1 + 매수 비용률) - 1
손절 순손익률 = (1 - 손절률) × (1 - 매도 비용률) ÷ (1 + 매수 비용률) - 1
손익비 = 익절 순이익 ÷ 손절 순손실
본전 승률 = 손절 순손실 ÷ (익절 순이익 + 손절 순손실)
```

2026-10-14 날짜를 기존 코드의 요율표에 넣고 일반 코스피 주식·온라인 수수료, 익절 +1.5%·손절 -1%로 계산한 결과다. 실제 계좌 비용이나 현행 법령을 이번에 새로 검증한 값은 아니다.

| 편도 슬리피지 가정 | 익절 순수익 | 손절 순손익 | 손익비 | 본전 승률 |
|---|---:|---:|---:|---:|
| 0bp | +1.2611% | -1.2330% | 1.0228 | 49.4359% |
| 10bp | +1.0586% | -1.4305% | 0.7400 | 57.4709% |

#162의 왕복 비용 0.23% 어림과 방향은 같지만, 기존 모듈의 위탁·유관기관 비용과 각 매도 금액을 적용하므로 숫자는 조금 다르다. 10bp는 가정이며 관측된 비용이 아니다. 갭·미체결·호가 단위·주수·원 단위 절사·개별 계좌 수수료는 이 비율 예시에 포함하지 않는다. 익절도 비용 뒤 손실이면 손익비/본전 승률을 숫자로 제시하지 않는다. 기본 익절·손절 설정은 바꾸지 않았다.

## 5. 검증과 적용

- 관련 pytest **85건 통과**, 신규 **28건** 포함. 새 묶음 `test_risk_execution.py` 15건, 게이트웨이 재전송/부분체결 10건, 실제 공격 모드 사이클의 일손실/주문 수/쿨다운 3건.
