## 요약

1. 명세서 3절(UC-01 ~ 05)과 같은 칸을 썼다. 지시서의 「사전 조건」 은 명세서의 「시작 조건」, 「사후 조건」 은 「끝난 모습」 이다.
2. 주 흐름의 각 단계 끝에 근거 파일:줄을 달았다. 화면 줄은 `public/js/*.js`, 서버 줄은 `app/routes/*.py` · `app/services/*.py` 다.
3. 코드와 명세서 2절 표가 다른 곳이 셋 있다. UC-06 의 설명 API(`GET /api/explain`)를 부르는 화면이 없고, UC-10 스크리닝 화면의 점검표 주담당(신장환)과 명세서 주담당(오준영)이 다르며, UC-12 의 「매 거래일 결과가 쌓인다(일지)」 는 코드에 없다.

**주 흐름**

6. 보유 여부 · 위험 관문을 보고 의견을 더한다(UC-12 3 ~ 5단계) — `stocks.py:976`.

- 4b. 기록을 읽다 오류가 나면 기록 없음으로 본다 — `stocks.py:927-928`.
- 6a. 앱 DB 에 닿지 않으면 미보유로 가정하고 의견을 낸다 — `stocks.py:952-953`.
- 설명만 따로 받는 `GET /api/explain`(`app/routes/explain.py:23`)은 기록이 없으면 404 를 돌려준다(`explain.py:34`). 이 API 를 부르는 화면 JS 는 커밋 판에서 찾지 못했다 — `robo.js:676` 에 주석만 있다.

**주담당 확인(신장환)**

## 부록 B. 만든 방법

- 화면 요소 → 바인딩 줄 → 부르는 API 는 스크립트로 뽑고(`git show HEAD:public/...` 판), 라우트 → 서비스 함수는 라우트 본문을 직접 읽어 줄 번호를 옮겼다.
- 실행 · 화면 확인은 하지 않았다. 「다른 흐름」 은 코드에 있는 갈래만 적었다(지어낸 갈래 없음).
- 한계: 화면 JS 의 그리기 함수(응답 칸 → 화면 칸)는 따라가지 못한 곳이 있다. 그 단계에는 줄 번호를 달지 않았다.
