### 1-4 이름 규칙(제안)

- 페이지: 두 자리 번호 + 한국어 이름(`05 시안`) — 순서가 이름으로 고정된다. 구분 페이지는 선만.
- 틀(프레임): `화면 / 폭 / 상태`(예: `메뉴 / 390 / ☰ 열림`) — 블로그의 「Frame 123 금지」 · 우리 S108 「설계명 틀」.
- 컴포넌트 변형 속성: `상태 = 기본 · 올림 · 초점 · 지금` · `폭 = 넓음 · 좁음` — 코드의 클래스 · 상태 이름과 맞춰 두면 구현 대조가 쉽다(블로그 「design-friendly names 를 코드에 잇기」).
- 변수: 앱 CSS 변수 이름과 **같은 이름**(`--accent` → `accent` · 묶음 `color/accent`) — 블로그 「Style names that match token or variable names in code」(Figma 「Tips for a better developer workflow」 검색 요약 · 확실도 중).

## 2절 도구 표

MCP 문서: 「Education plans have the same limits as Full and Dev seats on the Professional plan」. 그래서 아래 표에서 **「Organization 이상」 · 「Enterprise 전용」 은 우리에게 막혀 있다.** 확실도 상(공식 두 곳).

주의 둘: ①② 의 `use_figma` 쓰기는 우리 규칙(S88 — MCP 쓰기는 사용자 확인)대로 한다. ② 의 「웹 코드 이름(code syntax)」 칸은 요금제 조건을 원문으로 확인하지 못했다 — 안 되면 변수 설명 칸에 `var(--이름)` 을 적어 갈음한다. ③ 의 「복사해 붙이기」 가 라이브러리 게시 없이 원본과 끊긴 사본이 되는지는 메인이 처음 한 번 확인한다.
