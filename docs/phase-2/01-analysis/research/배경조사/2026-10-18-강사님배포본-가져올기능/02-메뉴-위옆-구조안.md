# 위 메뉴는 필요한 것만, 옆에 전체 메뉴 — 구조안

| 문서 정보 | |
|---|---|

| 사용자 원문 | 「위의 메뉴바에는 이제 필요한 기능만 넣고 옆 사이드에 전체 메뉴를 두는 것은 괜찮은 것 같습니다(화면 설계 재시도 필요할 듯)」 |

## 요약 4줄

1. 지금 우리 위 메뉴는 묶음 10개를 폭에 들어가는 만큼 보이고(1280 에서 7개 + 「더보기 3」 · 10-14 실측) 나머지는 「더보기 N ▾」 와 오른쪽 서랍 「전체 메뉴」 로 보낸다. 왼쪽 메뉴는 지금 묶음의 항목만 보인다.
2. 강사님 fd 는 위 탭을 넷으로 고정하고 나머지 아홉 묶음을 오른쪽 서랍에 둔다. 「옆 전체 메뉴」 를 글자 그대로 따르면 **왼쪽 메뉴를 전체 묶음 트리로 바꾸는 것**(fe-vanilla · iv · KRX 꼴)이 가장 가깝다.
3. 안 셋 가운데 **안 가(위 고정 5 + 왼쪽 전체 트리)를 추천**한다. 사용자 말과 가장 가깝고, 지금 서랍 코드(`drawerItem`)와 왼쪽 메뉴 자리를 다시 쓰며, 폭 계산(Priority+)을 없애 위 메뉴 넘침 결함이 다시 생길 길을 닫는다.
4. 메뉴를 바꾸면 영상 일곱이 모두 다시 찍어야 하는 화면이 된다(머리 · 왼쪽 메뉴가 모든 장면에 보임). 2차 발표(10-21) 전에는 바꾸지 않고, 3차 (바) 첫 이틀(10-22 ~ 23)에 구현해 10-26 오전 IA · 와이어프레임 칸에서 보이는 차례를 추천한다.

## 6. 추천과 까닭

안 가를 추천한다. 까닭은 넷이다.

1. 사용자 말 「위에는 필요한 기능만, 옆에 전체 메뉴」 를 그대로 옮긴 꼴이다. 안 나는 전체 메뉴가 닫힌 서랍이라 같은 말이 되지 않는다.
2. 지금 있는 부품을 다시 쓴다. 서랍의 묶음 그리기(`drawerItem` · 소제목 · 바깥 주소)를 왼쪽 자리로 옮기면 되고, 폭 계산(`fitGnbTabs` · `gnbmore.js`)은 좁은 화면 전용으로 줄일 수 있다.
3. 위 다섯은 2 · 3차 발표의 큰 줄기(로보 어드바이저 · 투자 인디케이터)와 사용자가 다시 짚은 「배우기」 · 「모의투자」 · 「데이터 관제」 를 한 줄에 보인다. 묶음 이름 「배우기」(금융 필수 지식 + 개념 학습)는 04 문서의 개념 학습 앱 안 통합과 같이 정한다.
4. 차례는 2차 발표 뒤다. 메뉴를 바꾸면 영상 일곱을 다시 찍어야 하고 10-19 · 20 은 영상 · 발표 자료 칸이다. 3차 (바) 10-22 ~ 23 에 Figma 세 안 → 결정 → 구현, 10-26 오전 IA · 와이어프레임 칸에서 보이는 것이 일정에 맞다.
