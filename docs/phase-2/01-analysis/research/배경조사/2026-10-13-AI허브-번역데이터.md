## 요약 5줄

1. 앱 코드(`translation_ingest.py`)가 기대하는 데이터는 AI 허브 **「금융 분야 다국어 병렬 말뭉치 데이터」(번호 71782 · 판 1.2 · 2024-12-04)** 다. 칸 이름 · 문서 유형 다섯 · 언어 다섯이 모두 맞는다 🟢. 데이터셋 쪽에 따로 붙은 조항은 없어 「AI 허브 개방 데이터」 이용정책 10항이 적용된다 🟢.
2. **사용자 의견 중 「HF private 저장」 은 약관이 막는다** 🟢 — 이용정책 3항 「국외 반출을 위해서는 … 별도로 합의가 필요」 + 자주 찾는 질문 「해외에 소재한 서버나 클라우드 환경으로 전송·저장하거나 해당 환경에서 학습에 활용하는 경우에도 국외 반출에 해당」 + HF 문서 「For non-Team or Enterprise users, repositories are always stored in the US」.
3. 팀 공유는 **신청자 단위**다 🟢 — 승인을 받지 않은 사람에게 「열람하게 하거나 제공」 금지(5항) · 계정 · 이용 권한 양도 금지(약관 15조 · 17조). 각자 신청은 쉽다 — 휴대폰 본인인증 뒤 자동 승인 · 3개월 유효.
4. 만든 것 — **모델 · 수치 · 그래프는 출처를 밝히고 배포 가능** 🟢, 원문 · 번역을 담은 색인과 승인 안 받은 사람에게 원문 문장을 보여 주는 화면 · 시연은 안 됨 🟢. 출처 = 정식 명칭 + AI 허브(aihub.or.kr) + 한국지능정보사회진흥원 사업결과 🟢.
5. 추천은 **안 B — 쓸 사람이 각자 신청해 자기 PC 에서만 · HF private 에는 데이터가 아닌 것(로컬 학습 모델 · 모델 카드 · 내려받기 안내)만.** 사용자 의견의 「로컬 사용 · 2 · 3차 사용」 은 그대로 살아난다. 데이터 자체를 HF 에 두려면 수행기관 · NIA 합의(A′)가 먼저다.

## 3. 추천

**안 B** — 쓸 사람이 각자 신청해 자기 PC 에서만 쓴다. HF private 에는 데이터가 아닌 것만 둔다(조사서 <표 10>).

- 사용자 의견이 우선이지만 **「HF 에 private 으로 저장」 부분은 약관이 막는다** — 이 사실을 댓글 · 조사서 맨 앞에 적었다.
- 사용자 의견의 나머지(로컬에서 사용 · 2 · 3차에 사용)는 안 B 로 그대로 된다.
- A′(수행기관 · NIA 합의 요청)는 데이터 자체를 HF 에 둘 까닭이 생길 때만. C(쓰지 않음)는 2 · 3차에 이 소재를 쓸 계획이 없을 때.

- 신청 때 동의서 원문(로그인 필요) — 팀 · 단체 이용 조항이 따로 있으면 물음 ① 을 다시 본다.
- 데이터 설명서 · 구축활용가이드 PDF(INNORIX 프로그램 필요) — 원천 문서별 `license` 값 분포를 모른다.
- 데이터 용량(쪽에서 자바스크립트로 채움) · 우리 HF 조직의 요금제(HF API 를 부르지 않음 — 어느 요금제든 한국 지역은 없어 답은 같음).
