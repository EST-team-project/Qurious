> **실측 도구**: `python scripts/schema_scan.py --md` — **이 문서의 §3 이하는 그 출력
> 그대로다.** 손으로 고치면 다음 실행과 어긋난다. 고쳐야 할 것이 있으면 **코드의 주석을**
> 고친다(§2).
> **기준 커밋**: `b861859` · **작성일** 2026-09-21 (KST)
> **짝 문서**: [ERD_v1.0.md](ERD_v1.0.md) — 표가 서로 **어떻게 이어지는지**는 그쪽에 있다.

## 1. 이 문서를 읽는 법

| 표시 | 뜻 |
|---|---|
| 🟢 **실측** | 실제 DB 파일을 열어 읽었다. 행 수까지 셌다 |
| 🟡 **정의** | SQLAlchemy 모델에 그렇게 적혀 있다. **실제 DB 가 그 모양이라는 보장은 아니다** |
| `PK` | 기본키 — 이 칸(들)이 행 하나를 가리킨다 |
| `FK` | 외래키 — 다른 표의 행을 가리킨다. 설명 칸에 `→ 표.칸` 으로 적힌다 |
| `NOT NULL` | 빈 값을 넣을 수 없다 |

**용어 — 데이터 사전(data dictionary)**
- 뜻: 표와 칸 하나하나가 **무엇을 담는지** 적어 둔 목록입니다.
- 이 문서에서: 34개 표 347칸을 빠짐없이 싣습니다. 관계는 [ERD](ERD_v1.0.md) 가 맡습니다.
- 헷갈리는 점: 사전은 **"무엇이 있는가"**를 적을 뿐, **"그 값이 옳은가"**는 말하지 않습니다.
  실제로 알려진 오염이 있습니다 — `price_adjusted.adj_clpr` 의 `052670`
  ([#55](https://github.com/devlee328288/Qurious/issues/55)).

## 2. 🔴 설명 칸은 **코드 주석에서 자동으로 딸려 온 것**입니다

이 사전의 "설명" 칸은 사람이 여기 적은 글이 아닙니다. 두 곳에서 **기계가 긁어 옵니다**:

| 어디서 | 무엇을 | 예 |
|---|---|---|
| `collector/db.py` 의 `CREATE TABLE` 문 | 칸 옆·위의 `-- 한국어 주석` | `dividend.dps` → "1주당 배당금(원) 보통주식" |
| `app/models/*.py` | 칸 위·옆의 `# 주석` | `orders.cost_basis` → "none(안 뗌) \| estimated(요율표로 계산) \| broker(증권사가 준 실제 금액)" |

**그래서 설명을 고치려면 이 문서가 아니라 코드를 고쳐야 합니다.** 여기서 고치면 다음
실행에서 사라집니다. 이 구조를 택한 이유는 단순합니다 — 사전과 코드가 갈라지면,
**갈라졌다는 사실조차 아무도 모르게 되기 때문**입니다.

### 2.1 그 결과가 곧 우리 문서화 상태입니다 🟢 실측

| | 표 | 칸 | 설명이 붙은 칸 | 비율 |
|---|---:|---:|---:|---:|
| **수집기 DB** (우리가 썼다) | 8 | 88 | **57** | **64%** |
| **앱 DB** (물려받았다) | 26 | 259 | **15** | **5%** |
| 합계 | 34 | 347 | 72 | 20% |

**설명이 한 칸도 없는 표**:

- 수집기 1개 — `ingest_day`
- 앱 **21개** — `users`·`portfolio`·`paper_accounts`·`broker_settings`·`api_keys`·
  `conversations`·`chats`·`custom_indicators`·`lean_backtest_runs`·`notification_settings`·
  `notification_log`·`audit_events`·`data_cache`·`crawled_docs`·`uploaded_docs`·
  `bank_products`·`fund_products`·`corporate_cb_stats`·`personal_cb_stats`·
  `alternative_positions`·`quant_virtual_accounts`

숫자를 그대로 읽으면 이렇습니다 — **우리가 새로 만든 수집기는 3칸 중 2칸에 설명이 있고,
물려받은 앱은 20칸 중 1칸에 있습니다.** 앱 DB 는 사실상 문서화돼 있지 않습니다.

이것을 "문서를 더 쓰자"로 풀면 같은 문제가 반복됩니다. **코드에 주석을 다는 쪽이
사전을 자동으로 채웁니다.** 앱 DB 표를 손대는 작업(예: [#61](https://github.com/devlee328288/Qurious/issues/61)
P1-1 어댑터)을 할 때 그 표의 칸 주석을 함께 다는 것이 가장 값싼 길입니다.

⚠️ 다만 **설명이 붙었다고 옳다는 뜻은 아닙니다.** 이 스캐너는 주석을 옮길 뿐,
주석이 사실인지 검사하지 않습니다.

### 2.2 다시 만드는 법

```bash
python scripts/schema_scan.py           # 요약 + 문서화 비율 + 어긋난 곳
python scripts/schema_scan.py --md      # 이 문서의 §3 이하
python scripts/schema_scan.py --erd     # ERD 문서의 그림
python scripts/schema_scan.py --json    # 기계용
```

수집기 DB 파일(`data/collector/market.sqlite3`)은 `.gitignore` 대상이라 저장소에 없습니다.
파일이 없으면 **수집기 부분을 건너뛰고 앱 부분만** 나옵니다 — 멈추지 않습니다.
