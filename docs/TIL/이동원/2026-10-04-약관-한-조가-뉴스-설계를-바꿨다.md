## 1. 무엇을 했나

- **공시 목록을 2020년부터 받았다.** DART 공시 목록을 유형(A~J) × 시장(유가 · 코스닥 · 코넥스)으로 나눠 774,462건을 쌓았다. 응답에 유형 칸이 없어서 유형별로 불러야 「정기공시인지 거래소공시인지」 를 안다. 석 달 창 840조합을 세션 밖 프로세스 넷으로 구간을 나눠 동시에 받았고(앞 구간을 마친 프로세스는 감시가 멈췄다), 매일은 최근 3일을 다시 받는다.
- **재무 주요계정을 100개사씩 받았다.** 다중회사 주요계정 API 로 상장폐지사까지 3,990곳의 2019 ~ 2026 보고서를 1,280번에 받았다(1,879,130행). 정정본마다 새 판으로 쌓고, 재무 API 는 기준일 전에 접수된 판의 값만 쓴다.
- **이름표와 검색을 붙였다.** 공시마다 종목 · 주제(사건 규칙 21) · 용어 · 유형 이름표를 달고, 근거 문서와 같은 두 글자 묶음 낱말로 찾는 색인을 따로 만들었다. 찾은 공시에는 그 기간의 매출 · 영업이익 · 순이익이나 1주당 배당금을 함께 붙인다.
- **일정 넷을 더했다.** 잠정실적 공시로 실적 발표일을, 자본시장법 조문으로 정기보고서 제출 기한을, 한국은행 · 연준 누리집으로 금통위 · FOMC 를 만들었다. 12:30 러너에는 공시 · 재무 · 검색 단계 셋을 더했다(실패해도 다른 단계를 막지 않는다).
- **시험으로 묶었다.** 다섯 묶음 31건. 한 번에 통과한 시험은 코드 여덟 곳을 일부러 느슨하게 바꿔 깨지는지 봤다.

## 2. 막힌 것 · 알게 된 것

- **설계서의 뉴스 계획은 약관이 막고 있었다.** 설계는 「네이버 검색 API 로 뉴스 제목 · 요약을 받아 저장 · 이름표 · 검색」 이었다. 시작 전에 약관 원문을 열었더니 검색 API 조항이 검색 결과의 저장 · 캐싱, AI 입력 · 학습 · 평가, 제3자 제공을 금지했고, 신규 신청은 두 달 전에 닫혀 있었다. 「이용 조건 원문 먼저」 를 하지 않았다면 수집기를 다 만든 뒤에 알았을 것이다. 뉴스는 재사용이 허락된 공공 자료(정책브리핑 · 공공누리 제1유형)로 바꾸고, 언론사 기사는 제목과 원문 링크만 두기로 했다.
- **DART 는 마지막 정정본만 준다.** GS건설 2023 사업보고서는 2024년 3월에 처음 나오고 세 번 고쳐졌는데, 지금 API 를 부르면 2026년 6월 정정본 값만 온다. 받은 판의 5.9%, 사업보고서는 14.4% 가 이렇다. 처음엔 「처음 공개일」 로 거르면 되겠다고 생각했지만, 그러면 고친 숫자를 원래 날짜에 붙이게 된다. 현업 자료(Sharadar 의 As Reported · Compustat 의 처음 보고값)와 1차 프로젝트 코드가 모두 「그날 실제로 나온 판」 을 쓰고 있어서 그쪽을 기본으로 했다.
- **1차 프로젝트가 이미 답을 갖고 있었다.** 접수 시각이 없으니 다음 거래일부터 쓴다, 정정 표시는 그 보고서 자기 제목에서 읽는다(공시 목록의 「정」 표시는 나중에 붙는 것이라 그 자체가 미래 참조다), 「가장 최근」 은 결산 순서다 — 세 규칙을 그대로 가져왔다. 2차에서 더한 것은 정정본마다 판을 쌓는 것이라, 내일부터는 처음 보고값 이력이 생긴다.
- **시험 둘이 실제로는 아무것도 지키지 않았다.** 원문 중복을 막는 줄을 지워도 시험이 통과했다. 같은 초에 두 번 받아서 원문 표의 기본 키(받은 시각)가 같았기 때문이다. 낱말 AND 를 OR 로 바꿔도 통과했는데, 표본 여섯 건에서는 결과가 같았다. 받은 시각을 1초씩 늘리고, 서로 다른 공시에만 있는 두 낱말을 넣어 고쳤다.
- **시험은 다 통과했는데 도커 앱에서만 검색이 안 열렸다.** 검색 색인을 WAL 로 만들었는데, 앱은 `data/` 를 읽기 전용으로 붙여 연다. WAL 파일은 읽을 때도 보조 파일(`-shm`)이 있어야 하고, 만든 뒤 닫으면 그 파일이 지워진다. 수집 DB 가 잘 열리던 것은 보조 파일이 우연히 남아 있어서였다. 롤백 저널로 바꾸고 시험에 저널 확인을 더했다(DF-67). 점검 스크립트로 실제 앱을 두드려 보지 않았다면 머지한 뒤에 알았을 것이다.
- **기존 화면은 결정 ③ 을 시험으로 지키고 있었다.** 서버에 일정 종류를 넷 더하자 「화면의 넷 = 서버의 넷」 시험이 깨졌다. 화면에 새 종류를 올리는 것은 Figma 결정 뒤라, 서버가 `kind` 없이 주는 것은 넷 그대로 두었다. 덕분에 지난해 12월 달력이 2,000건 상한에 걸려 잘린다는 것(DF-66)도 같이 찾았다.
