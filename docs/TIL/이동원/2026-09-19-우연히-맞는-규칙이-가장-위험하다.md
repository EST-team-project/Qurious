## 1. 무엇을 했나

DART 공시 본문에서 **배당기준일과 주당배당금**을 읽어 `dividend` 표에 쌓는 수집기를 만들었다
(`collector/sources/dart.py` 663줄 + `collector/dividend.py` 336줄). 하루 안에 전량을 훑었다 — 실측:

| | 값 |
|---|---|
| 훑은 달 | **81 / 81** (열두 달 × 7년) |
| `dividend` 행 | **9,188건** · **1,618종목** · 기간 20181231~20260930 |
| 검토필요 | **17건** (완주 직후) |
| 배당락일 미정 | 1,036건 — 기준일이 우리 시세 구간(2020-01-02~) 앞. **정상이다** |

곁들여 Celery 쪽 결함 둘과 수집 시작일 실측값(#35)도 담았다. PR 이 셋으로 갈린 건 **사고**다(5.3).

## 2. 왜 했나

앞 장([데이터가 알려 주는 조정계수](2026-09-19-데이터가-알려주는-조정계수.md))에서 세운 수정주가는
**PR(Price Return, 가격수익 — 주가가 움직인 만큼만 센 수익률)** 이다. 여기에 받은 배당까지 더한
것이 **TR(Total Return, 총수익)** 이고, 이번에 만든 `dividend` 표가 그 재료다. 문제는 배당이
"나중에 더하면 되는 것" 이 아니라는 데 있었다.

```
  현금배당은 거래소가 기준가를 조정하지 않는다
        ├─► 포털 일별시세의 vs(전일대비)에 안 나타난다
        └─► 그래서 corporate_action 표에도 안 잡힌다
              ▼  시세를 아무리 잘 모아도 배당은 영원히 안 생긴다.
                 출처가 다른 곳(DART 공시)에서 따로 가져와야 한다.
```

이걸 모르면 은행·통신·지주처럼 배당수익률이 높은 종목은 **매년 그만큼 깎인 채로** 백테스트에
들어간다. 벤치마크 비교도 성립하지 않는다 — KOSPI **TR** 과 우리 **PR** 을 견주면 지는 게
당연하다. 틀린 줄 모르고 "이 전략은 별로네" 라고 결론 낼 뻔한 자리다.

## 3. 어떻게 했나 — 고른 것과 버린 것

### 3.1 주 경로 고르기

S29([#33](https://github.com/devlee328288/Qurious/issues/33) 10.4)에서 실호출해 둔 둘 중 **「현금ㆍ현물
배당결정」 본문(`document.xml`)** 을 골랐다. 기준일·금액·시가배당율·총액이 다 나오고 응답이 2KB다.
사업보고서 배당 항목(`alotMatter.json`)은 **배당기준일이 없고 연간 합계**라 분기배당을 못 가른다
(삼성전자 `1,444원` 은 네 번의 합이다). 버리진 않고 **교차검증용**으로 남겼는데, 뒤에서 버그를 잡는다(4.2).

### 3.2 ★ S29 에 적어 둔 "배당락일 = 기준일 T-2" 가 틀렸다

S29 에 나는 *"배당락일 = 배당기준일 T-2 역산"* 이라고 적어 뒀다. **우연히 맞는 경우가 있어서 틀린 줄 몰랐다.**

```
  올바른 규칙:  L = 기준일 이하의 마지막 거래일 · 배당락일 = L 의 한 거래일 전
    (매수일 D 의 결제는 D+2거래일. 명부에 오르려면 D+2거래일 ≤ L 이므로
     배당받는 마지막 매수일이 L-2거래일이고, 그 다음 날부터 배당이 없다)

  경우 ①  기준일 2020-12-31 (휴장일)      경우 ②  기준일 2021-06-30 (거래일)
    L = 12-30                               L = 06-30
    올바른 답 = 12-29                        올바른 답 = 06-29
    달력 T-2  = 12-29  ← 우연히 맞는다       달력 T-2  = 06-28  ← 하루 틀린다
    S29 는 이 경우만 보고 규칙을 적었다.                        ▲ 여기를 못 봤다
```

결산배당은 기준일이 12-31(휴장일)이라 T-2 로도 맞는다. 그런데 **분기·중간배당은 기준일이
6-30·9-30 처럼 거래일**이라 전부 하루씩 어긋난다. 2021년 7월분 41건 중 **39건**이 그 경우였다.

거래일 달력은 새로 만들지 않았다 — `price_daily` 에 이미 쌓인 날들이 곧 거래일이다
([`dart.py:519`](https://github.com/devlee328288/Qurious/blob/722cdb4/collector/sources/dart.py#L519) ·
역산 [`dart.py:529`](https://github.com/devlee328288/Qurious/blob/722cdb4/collector/sources/dart.py#L529)).
틀린 달력을 따로 들고 있느니 **없는 편이 낫다**.

### 3.3 제목에 "배당" 이 있다고 다 배당이 아니다

넓게 받아서 **제외 규칙으로 좁히는** 쪽을 골랐다. 제목이 「[기재정정]현금ㆍ현물배당결정」처럼
갈리는 데다 가운뎃점이 `ㆍ`(U+318D)라 눈으로 구분이 안 된다. 좁게 잡아 놓치면 영영 모르지만,
넓게 받아 잘못 든 것은 파싱에 실패해 눈에 띈다.

| 섞여 드는 것 | 왜 빼야 하나 | 실측 |
|---|---|---|
| 「…(자회사의 주요경영사항)」 | 본문 금액이 **자회사 것**이다. 공시를 낸 종목코드에 붙이면 두 종목이 함께 틀린다 | 에코프로(086520) 공시의 450원은 **에코프로비엠(247540)** 배당이었다 |
| 「…주주명부폐쇄(기준일)결정」 | 기준일만 정하는 공시라 **금액이 없다** | 제외하되 세어서 보고 |
| 「**주식배당**결정」 | 현금이 아니라 주식을 준다. **거래소가 배당락일에 기준가를 조정**하므로 이미 `corporate_action` 에 있다 → 담으면 **이중 계상** | 24건 |
| 「기타경영사항(자율공시)(**배당기준일 변경 안내**)」 | 기준일만 알린다. 금액이 없다 | **399건** |

제외 사유는 건수가 아니라 **이름으로** 돌려준다([`dart.py:204`](https://github.com/devlee328288/Qurious/blob/722cdb4/collector/sources/dart.py#L204)) —
주식배당은 *버리는 것*이 아니라 *다른 표가 이미 가진 것*이라서다. 처음엔 이 24건을 "서식이 달라
금액 칸을 못 읽는다"는 **파싱 실패**로 분류했었다. 다시 보니 못 읽는 게 문제가 아니라 **넣으면 안
되는 값**이었다. 진단이 바뀌면 처방도 바뀐다.

### 3.4 배당철 일곱 달만 훑으려던 것을 열두 달로

처음엔 *"배당 결의는 달이 정해져 있다 — 결산 1~3월, 분기·중간 4·7·10월, 미리 여는 곳이 12월"*
이라고 적고 `DIVIDEND_MONTHS = (1,2,3,4,7,10,12)` 로 뒀다. **틀렸다.**

```
  공시는 기준일이 아니라 "이사회 결의일" 에 나간다.
  기준일 2021-06-30 (회사마다 같다)
        ├─ 6월에 미리 결의하는 회사   ┐
        ├─ 7월에 하는 회사             ├─► 접수월이 흩어진다. 어느 회사가
        └─ 8월  ◄─ 신한지주            ┘   어느 달인지 미리 알 길이 없다.
             (2021-08-13 · 2022-08-12)
```

고쳐서 `DIVIDEND_MONTHS = tuple(range(1, 13))`
([`dart.py:99`](https://github.com/devlee328288/Qurious/blob/722cdb4/collector/sources/dart.py#L99)). 목록
호출 약 1,600 → 2,800회, 본문 약 10,000 → 12,000회로 하루 한도(20,000)의 58% → 74% 를 쓴다. 여유가
줄지만 **놓친 배당은 영영 모른다** — 빠진 자리에 아무 표시도 남지 않고 조용히 적게 나온다.

## 4. 어떻게 확인했나

### 4.1 배당락일 역산 — 네 가지로 쟀다 (규칙을 한 번 틀렸으니 말로 할 수 없었다)

| 근거 | 결과 | 확실도 |
|---|---|:---:|
| ① 기준일을 일부러 민 대조군 (표본 30건 · 2020~2024) | 시가배당율 평균 절대오차 우리 값 0.030%p · `+3` 밀면 0.082%p(2.7배) · `+5` 면 0.116%p(3.8배) | 🟢 늦게 미는 방향은 배제. 앞으로 1~3거래일은 이 검정으로 안 갈린다 🟡 |
| ② KRX 공표 배당락일 | 2020~2024 **5년 연속 일치** | 🟢 |
| ③ 가격이 실제로 그날 빠진다 (2021-06-29 · n=39) | 배당표본 −1.817% vs 시장 −0.065% = **−1.752%p** · 시가배당율과 상관 `r=+0.609` · 회귀 기울기 `+1.23` | 🟡 표본이 **같은 하루**에 몰려 있다 |
| ④ `corporate_action` 과 대조 | 기준일 2020-12-31 주식배당 22종목이 역산한 `20201229` 에 **22/22** 있었다 | 🟢 거래소 자신의 조정이라 가격 해석이 안 끼어든다 |

③ 의 한계를 ④ 가 메운다. ④ 는 주식배당을 빼려고 들여다본 공시에서 **덤으로 얻은** 검증이었다.

### 4.2 교차검증이 실제로 버그를 잡았다

주 경로는 공시를 놓치면 조용히 적게 나온다. 다른 경로와 맞춰 보는 것 말고는 알 방법이 없어서
`alotMatter`(연간 확정치)와 8종목 × 5개년을 대조했다([`dividend.py:301`](https://github.com/devlee328288/Qurious/blob/722cdb4/collector/dividend.py#L301)).

| 시점 | 대조 | 일치 | 어긋남 | 설명 안 되는 것 |
|---|---:|---:|---:|---|
| 일곱 달 시절 | 36 | 24 | 12 | **1건 → `DIVIDEND_MONTHS` 결함** |
| 열두 달 완주 | 47 | 41 | 6 | 4건 |
| 사업연도 매핑 + 총액 대조 추가 | 48 | **44** | 4 | **0건** |

설명 안 되던 1건이 신한지주였고 그게 3.4절의 8월이다. **이 검증이 없었으면 8월 배당을 통째로 잃은
채 "다 모았다"고 적었을 것이다.** 그래서 일회용 스크립트로 두지 않고 CLI 에 남겼다. 건진 것:

| 배당구분 | 일곱 달 시절 | 열두 달 완주 | 증가 |
|---|---:|---:|---:|
| 결산배당 | 8,063 | 8,174 | +111 |
| **분기배당** | 327 | **681** | **+108%** |
| **중간배당** | 128 | **319** | **+149%** |

결산배당은 기준일이 12월로 고정이라 거의 다 잡혔지만 **분기·중간배당은 절반 넘게 놓치고 있었다.**
추가 비용은 30달에 호출 1,284회뿐이다 — 이미 훑은 달의 본문은 다시 받지 않기 때문이다.

## 5. 막힌 것 · 남은 것

### 5.1 파싱이 "0건 성공" 으로 조용히 실패했다

표본 12건이 전부 *"배당이 안 적혀 있다"* 로 나왔다. 본문이 XML 이 아니라 **HTML** 이고 태그마다
줄이 바뀌어 있는 게 원인이었다.

```
  <td><span>6. 배당기준일</span></td>      ← 태그마다 줄이 바뀐다
  <td><span>2020-12-31</span></td>
  줄바꿈을 살린 채 </td>→탭, </tr>→줄바꿈 으로 바꾸면
      "6. 배당기준일 \t"  ← 라벨만 있는 줄      ★ 라벨과 값이 갈라졌다
      "2020-12-31 \t"     ← 값만 있는 줄
  → 값 칸이 늘 빈다 → "공시에 배당이 없다" 는 잘못된 결론
  고침: 원본 줄바꿈을 먼저 없앤 뒤 태그를 치환한다.
```

본문 8KB 중 6KB 가 `<style>` 안 CSS 였던 것도 여기서 알았다 — 통째로 버린다. **예외가 안 난다는 게
무서운 점이다.** 표본을 눈으로 안 봤으면 전량을 훑고 "우리 시장엔 배당이 없다" 고 적었을 것이다.

### 5.2 `reparse` 를 한 번도 안 돌려 보고 커밋했다

제외 규칙이 바뀐 행을 `(srtn_cd, record_dt)` 로 지우는 코드인데 **SELECT 절에 `record_dt` 를 안 넣어**
첫 대상에서 `IndexError` 로 죽었다. `dividend` 의 기본키가 그 두 칸이다. 고친 건
[한 줄](https://github.com/devlee328288/Qurious/blob/722cdb4/collector/dividend.py#L231)이고, 고친 뒤 실측은
보존 원문 8,945건 재파싱 → 검토필요 **1,496 → 402건** · 주식배당 잔존 **58 → 0건**. `reparse` 는
**네트워크를 0회** 쓴다 — 원문을 남겨 뒀기 때문이다.

### 5.3 `#36` 에서 커밋 3개가 push 안 된 채 머지됐다

로컬엔 4커밋이 있었는데 원격엔 첫 1개만 올라간 채 머지됐다(`head_sha=e747437`·`commits=1`). 그래서
`main` 에는 **일곱 달만 훑고 주식배당을 이중 계상하는** 수집기가 들어가 있었다. 잃은 건 없어서
`main` 위에 다시 얹어 #37 로 올렸다. #35 도 같은 종류다 — PR #34 를 머지한 **8분 뒤**에 올린
커밋 2건이 따라붙지 않았다.

### 5.4 남은 것

| | 내용 |
|---|---|
| 🔴 | **TR 계산 자체는 아직 없다.** 이 표는 재료까지다 |
| 🔴 | 현물배당 2건은 서식이 달라 금액을 못 읽는다. 표본에 없어 대응 안 했다 |
| 🟡 | 교차검증 표본이 **8종목뿐**. 전 종목은 종목당 2회 ≈ 6,700회라 따로 하루가 든다. 사업연도 매핑도 **12월 결산 가정**이라 3월·6월 결산법인은 어긋난다 |
| 🟡 | 우선주 배당(`dps_pref`)을 **우선주 종목코드에 못 붙인다**. 공시가 보통주 `corp_code` 로만 온다 |
| 🟡 | 2024년 제도 변경 — 결산배당 기준일이 12-31 밖인 비율이 2% → **2024년 12% → 2025년 26%**. "배당락은 12월 말에 몰린다"는 통념으로 짠 전략은 이후 구간에서 어긋난다 |

## 6. 배운 것

**우연히 맞는 규칙이 가장 위험하다.** T-2 는 결산배당에서 맞았다. 맞는 사례만 보고 규칙으로
적었더니 분기·중간배당에서 전부 하루씩 틀렸다. 규칙은 맞는 경우가 아니라 **갈리는 경우**로 세운다.

**이번에 찾은 결함은 전부 예외를 내지 않았다.**

| 조용히 실패한 것 | 겉보기 | 무엇이 잡았나 |

| Celery `autodiscover_tasks` 가 0개 등록 | 워커가 `ready` 를 찍는다 | 태스크를 실제로 보내 봤다 |

공통점은 **빠진 자리에 표시가 남지 않는다**는 것이다. 같은 경로를 다시 봐서는 못 잡고, 성질이 다른 두 번째 경로가 있어야 한다.

**원문을 남겨 두면 규칙을 고칠 수 있다.** 파싱 규칙은 틀린다(5.1이 증거다). 원문이 있으면
`reparse` 가 네트워크 0회로 다시 읽고, 제외 규칙이 바뀌면 이미 담긴 행까지 스스로 치운다.

**어긋남을 자동으로 맞추지 않는다.** 고려아연은 우리 값이 더 컸는데 원문을 읽어 보니 틀린 쪽은
사업보고서였다(기준일 2019-12-31 배당을 FY2020 "당기"로 적었다). "이 회사는 밀려 적는다"고 종목
단위로 보정하려다, 같은 회사 2021~2023 이 안 어긋나서 그 추정이 틀린 걸 알았다. **잘못된 자동
보정은 틀린 값을 조용히 맞는 값으로 둔갑시킨다** — 총액으로 책임 소재만 표시하게 바꿨다.

그리고 **파싱 실패처럼 보이는 것이 정답인 경우도 있다.** 웅진씽크빅 한 건은 정정 사유가 *"기준일
주주명부 미확정으로 인한 배당금 미지급"* 이고 정정후 칸이 비어 있었다. 파서가 0원을 채우지 않은
게 옳았다 — 0원으로 담겼다면 **실재하지 않는 배당**이 백테스트에 들어갔을 것이다.
