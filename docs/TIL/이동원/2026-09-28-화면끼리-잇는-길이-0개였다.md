## 4. 어떻게 확인했나

- `view_scan.py` — 화면 선언 49 = 메뉴 항목 49 = 사용법 안내 49 · 진입 훅 30 · 화면 사이 링크 0 · 숨은 의존 2 · 중복 리스너 1.
- 스캐너가 잡은 것 중 사람이 코드로 다시 본 것 — 자동매매 경로 두 벌(`stocks.py:688-718`) · 증권사 설정 한 행(`stocks.py:395-520`) · DB 초기화 권한(`admin.py:19-22`) · 목업 제목(`app.html:1216`) · 숨은 의존 2곳(`:3404` · `:4310`).
- 옛 A13 의 「새로고침하면 처음 화면」 — 조사 기준 커밋 `04f476a` 에도 해시 라우팅 두 줄이 있었다(`:3073` · `:3589`) → 처음부터 틀렸다.
- `post_check.py` — 새 글 4개 통과(최대 9,060자). 옛 기록 75건 중 옮기기 전 **초과 4 · 경고 3**, 옮긴 뒤 **초과 5 · 경고 2** — 폴더가 한 단계 깊어져 상대 링크가 길어졌고, `논의-030` 이 65,127 → 65,697자로 한도를 넘었다.
- 기록 폴더 이전 — 상대 링크 2,722곳 · GitHub 주소 3곳 · 본문 경로 6곳을 다시 계산했다. 저장소 전체의 깨진 상대 링크가 **옮기기 전 6 = 옮긴 뒤 6**(모두 이번 일과 무관한 `onprem.md`·`pipeline.md` 의 옛 링크).

## 5. 막힌 것 · 남은 것

- 스캐너 첫 판이 **두 번 틀렸다.** ① `settings` 화면의 조작 API 에 `/broker/settings` 를 넣었다 — 실제로는 직접매매 화면 버튼이 `settings` 의 입력칸을 읽은 것이었다. ② 공용 종목 검색 창을 「숨은 의존」으로 잡았다. 둘 다 규칙을 고쳤다.
- 「설정 저장처가 두 갈래」라고 먼저 적었다가, 백엔드를 보니 **같은 한 행**이었다. 확인하기 전에 쓴 문장이었다.
- 49개를 **브라우저로 돌려 보지 못했다.** 스캐너 세 개에 시험 코드가 없다.
- 강사님 일정표(2차 10-01~10-21)가 **우리 반 공식 일정인지** 모른다 — ~~우리 계획서는 2차를 09-27~10-26 으로 잡았다.~~

## 6. 배운 것

- **화면 49개가 늘 DOM 에 있는 SPA 는 숨은 의존을 에러 없이 감춘다.** 다른 화면의 입력칸을 읽어도 값이 있으니 돌아간다. 실행해서는 안 보이고 정적 검사로만 보인다.
- **분류는 외부 기준과 대조하기 전까지 초안이다.** D1 ③(09-23 결론 초안)은 09-21 에 바뀐 강사님 일정표를 보지 못했고, 동결 제안 5개가 강사님 산출물과 겹쳤다.
- **원격을 사람에게 넘겨도 확인은 된다.** 사용자가 받아 둔 로컬 참조와 `FETCH_HEAD` 시각이 곧 증거다 — AI 가 원격을 다시 두드릴 필요가 없었다.
