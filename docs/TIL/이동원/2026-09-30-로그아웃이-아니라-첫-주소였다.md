## 1. 무엇을 했나

- **개발 모드** — 팀장이 「지금부터 로컬로 띄워 두고, 코드를 고치면 바로 반영되게」 를 요청했다. 호스트 파이썬에는 앱 패키지가 없어서 `dev.ps1`(호스트 uvicorn)을 그대로 쓸 수 없었다. 대신 compose 덧씌우기 파일로 코드 폴더를 컨테이너에 **읽기 전용**으로 붙이고 `uvicorn --reload` · Celery 는 `watchfiles` 로 감쌌다 → `start.ps1 -Dev`. 저장하면 앱이 몇 초 안에 다시 켜진다.
- **계정 점검 → 계정 관리** — 「로그인/회원가입 CRUD 되나」 를 점검 스크립트에 넣어 돌리자 결함 셋(대문자 이메일 로그인 불가 · 긴 비밀번호 500 · 긴 이름 500)과 빈 곳 셋(서버 비밀번호 규칙 · 수정 · 탈퇴 없음)이 나왔다. 팀장이 「대문자로 쓰는 사람도 있다 · 마이페이지가 필요하다 · 현업 CRUD 로」 를 요청해, OWASP · NIST · 개인정보 보호법을 먼저 읽고 한 번에 만들었다.
- **기능별 동작 원리서 v0.1** — 기능 21개마다 「어느 코드 · 차례 · 핵심 코드 · 확인 · 한계」. 계정 절은 고친 뒤의 동작으로 다시 썼다.
- IA · 와이어프레임 v0.3 은 에이전트 하나에 병렬로 맡겼다(읽을 파일을 지정해서).

## 2. 막힌 것 · 알게 된 것

- **「자동 로그아웃」 은 로그아웃이 아니었다.** 팀장은 JWT 가 필요해 보인다고 했다. 쿠키를 먼저 봤다 — `HttpOnly · Max-Age=604800 · Path=/` 로 멀쩡했고 같은 쿠키로 `/api/me` 는 200 이었다. 원인은 `app/main.py` 의 첫 주소 `/` 가 **로그인 여부와 상관없이** 로그인 화면으로 보내는 것이었다. 게다가 앱의 `boot()` 는 어떤 오류든 잡히면 로그인 화면으로 보내서, 화면 초기화 오류도 로그아웃처럼 보일 수 있었다. JWT 로 바꿨다면 문제는 그대로이고 오히려 토큰을 JS 가 읽는 곳에 둘 뻔했다(OWASP: localStorage 금지 · HttpOnly 쿠키 권장). **증상의 이름(「로그아웃」)이 원인을 말해 주지는 않는다.**
- **같은 입력이 두 모양으로 들어갔다.** 가입 본문은 `EmailStr`(도메인만 소문자로 바꿈) · 로그인 본문은 `str`(그대로). 둘 다 「이메일」 인데 규칙이 다른 곳에 있었다. 규칙을 `account.py` 한 곳으로 모으고, 라우트가 bcrypt 를 직접 부르지 않는지 시험이 본다.
- **패키지 판이 오르며 동작이 바뀌었다.** requirements 는 `bcrypt>=4.2.0` 이라 새로 만든 이미지에는 5.0.0 이 들어갔고, 5.0 은 72바이트가 넘는 비밀번호를 **잘라 주지 않고 예외**를 낸다. 한글은 한 글자가 3바이트라 25자면 넘는다. 앱 로그에는 500 의 원인 줄이 없었다(앱 로거가 꺼진 옛 결함) — 컨테이너에서 `bcrypt.hashpw` 를 직접 불러 재현했다.
- **현업 기준이 내가 알던 것과 달랐다.** NIST 최신판(2025-08)은 조합 규칙(특수문자 강제)을 **금지**하고, 다중 인증이 없으면 **15자 이상**을 요구한다. 국내 관행(2종류 10자 · 3종류 8자)과 다르다. 그래서 최소 길이는 설정(`PASSWORD_MIN_LENGTH`)으로 빼고 팀 결정으로 남겼다.
- **탈퇴는 표 목록을 손으로 적으면 안 된다.** 사용자 행을 가리키는 표가 25개였다. 모델 메타데이터에서 외래 키를 읽어 지우게 하고, 「모든 외래 키가 목록에 있다」 를 시험으로 묶었다 — 표가 늘어도 빠지지 않는다.
- **시험이 내 시험을 잡았다.** 72바이트 경계 예시로 `"가" × 24` 를 썼더니 「같은 글자 반복」 규칙에 먼저 걸렸다. 규칙은 맞았고 예시가 틀렸다.
