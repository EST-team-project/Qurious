## 1. 무엇을 했나

- **근거 문서를 받아 두는 길을 처음 만들었다(W5 첫 판).** 국가법령정보센터 Open API 로 법령 10 · 감독규정 4, 모두 14문서를 받아(호출 38회 · 70초) 기준일에 시행 중인 판을 고르고, 조문 3,463개를 청크 4,034개로 쪼갰다. 벡터 색인(Qdrant `kb_v1`)은 모델 둘(bge-m3 · nomic-embed-text)을 이름 붙은 벡터로 나란히 두고, 멈춰도 이어서 돌게 했다.
- **근거 문서는 수집 DB 가 아니라 별도 파일에 뒀다.** 낱말 색인(FTS5)이 보조 표 다섯을 함께 만들어 「모든 표는 백업하거나 이유와 함께 뺀다」 는 HF 백업 규칙을 흐리고, 법령은 언제든 다시 받는 공개 자료라서다.
- **HF 백업의 남은 확인 둘을 마쳐 DF-42 를 닫았다.** 전체 검증(51건 · 43초) · 복원 리허설(1,875만 행 · 476초) · 원격 지문 46/46 · 원문 16,053/16,053.
- **팀원 PR #92 의 충돌을 풀었다.** `core.js` 는 바뀐 줄이 328줄이었지만 공백을 무시하면 10줄이었다(나머지는 자동 서식). main 판 위에 그 10줄만 얹었다.

## 2. 막힌 것 · 알게 된 것

- **설계서의 판 고르기 규칙이 틀렸다.** 설계서는 「시행일이 기준일 이전인 판 가운데 공포일이 가장 늦은 판」 이라고 적었다. 자본시장법 시행령은 같은 날(09-29) 두 판이 공포됐다 — 10-02 시행인 제36728호와 10-01 시행인 제36729호. 공포번호가 큰 쪽을 고르면 10-02 에 시행된 네 조가 빠진다. 규칙을 「시행일이 가장 늦은 판」 으로 바꾸고, 그 뒤에 공포된 판의 개정이 담겼는지 조마다 대조하게 했다.
- **「현행」 표시가 틀린 줄 알았는데, 내가 길을 잘못 들었다.** 증권거래세법 시행령 제5조가 옛 세율로 나와 법령 DB 를 의심했다. 원인은 호출 경로였다 — 법령 일련번호로 부르면 공포될 때의 본문이, 시행일 판으로 부르면 그날 시행 중인 본문이 온다. 사흘 전 「DB 에 새 판이 없다」 고 판독한 것도 같은 실수였다.
- **목록 응답에 내 API 키가 실려 왔다.** 상세 링크 칸이 요청한 키를 그대로 담아 돌려준다. 원문을 저장하거나 화면에 찍기 전에 지우게 했다.
- **CPU 임베딩은 생각보다 느렸다.** 초당 1개 남짓이라 4,034개는 한 시간이 넘는다. 80개에서 멈췄다 — 청크 머리를 어떻게 둘지 정하기 전에 다 넣으면, 머리가 바뀌는 순간 처음부터 다시 넣어야 해서다.
- **git 이 못 잡는 충돌이 있다.** 팀원 마이그레이션과 내 마이그레이션이 같은 부모를 가리켜 머리가 둘이 됐다. 글자는 하나도 겹치지 않아 git 은 아무 말도 하지 않는다. 빈 합침 마이그레이션 하나로 이었고, 저장소 밖 복사본에서 머리가 하나인지 · 시험이 도는지 확인한 뒤 건넸다.
