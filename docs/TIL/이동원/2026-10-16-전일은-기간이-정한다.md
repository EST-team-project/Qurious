## 1. 무엇을 했나

- **「전일 대비」 가 5거래일 전 종가 대비였다(DF-123).** 미국주식 대시보드 · 거시경제 지표 · 산업 분석이 시세를 기간 5일 차트로 받고, `chartPreviousClose` 를 전일 종가로 썼다.
  - 이 칸은 「차트 첫 봉 바로 앞의 종가」 다. 기간이 5일이면 5거래일 전 종가가 된다.
  - 같은 시각에 두 기간으로 받아 견줬다. AAPL −0.28% 가 +0.46% 로, TSLA −1.29% 가 −3.35% 로 보였고, TSLA 는 ±1.5% 규칙에 걸려 「SELL」 이 붙었다.
  - 9-28 에 같은 꼴을 `get_quote` 한 곳만 고쳤고, 복사본 둘(`macro._get_latest` · `sync_scheduler._yahoo_latest`)이 남아 있었다. 이제 함수는 하나다. 라우트는 동기화의 함수를 모듈 이름으로 부르고, 기간은 1일이다. 모르는 등락은 None 이고, 현재가가 없으면 0 으로 메우지 않고 오류 줄을 낸다.
- **AI 투자 상담이 다른 회사의 재무 숫자를 답했다(DF-124).** 두 가지 꼴이었다.
  - 금융회사라 「셀 수 없음」 으로 온 비율을 0% 나 지어낸 값으로 채웠다.
  - 모델이 종목 코드를 짐작해 신한지주를 051910(LG화학)으로 불렀고, 그 회사의 값을 신한지주의 값이라고 말했다(6회 중 2회).
  - 고친 것: 도구는 회사 이름을 받고 서버가 코드를 찾는다. 도구 글은 지표마다 「이름: 값 — 문장」 이다. 답 끝에는 「서버가 계산한 값」 을 붙이고, 답의 숫자가 서버 값과 다르거나 서버가 본 회사가 질문에 없으면 경고를 붙인다.
  - 같은 질문을 세 번씩 물었다. 회사가 맞은 횟수는 2/3 → 3/3, 「셀 수 없음」 을 지킨 횟수는 0/2 → 3/3 이 됐다.
- **화면이 언제 값인지 말한다.** 미국주식 대시보드의 「● LIVE」 를 「지연 시세」 칩으로 바꿨다.
  - 시세를 못 받으면 예시 가격을 그리던 길(`mockUsPrice`)을 지웠다. 대신 「시세를 받지 못했습니다」 를 보인다.
  - 카드 아래에는 서버가 지은 머리 글(지연 시세 · 장이 닫힌 뒤 받은 값 · 마지막 체결 · 받은 시각 · 저장본 나이)을 그대로 보인다.
  - ±1.5% 를 넘은 종목에는 「BUY · SELL」 대신 「▲ 크게 오름 · ▼ 크게 내림」 을 붙인다.
- **전략 분석에 종목 찾기 칸을 넣었다.** 고정 다섯 종목 대신 국내 상장 종목 전체를 찾는다. 비었을 때는 최근 본 종목과 대표 다섯을 보이고, 화살표 · Enter · Esc 로 쓸 수 있다.
  - 제목의 「10년 Mockup」 을 뺐다. 「AI 시그널」 은 「규칙 신호(RSI · 이동평균 · 볼린저 합산)」 로 바꿨다.
- **상품 상세 창에 연습 상자를 넣었다.** 「모의 주문에서 열기 →」 를 누르면 창을 닫고 국내주식 모의주문을 그 코드로 연다. 화면은 시세 조회까지만 하고, 주문은 사용자가 한다.
- **화면 셋은 Figma 로 먼저 정했다.** 세 안을 만들었고, 사용자가 「잘 융합」 을 고른 뒤 융합안을 「이대로 진행」 으로 정했다.
- **숫자.** 새 시험 28건(TC-QL 10 · TC-QVS 4 · TC-SPK 4 · TC-AGR +9 · TC-PCS +1) · 깨 보기 36 / 36 · 62차 2007 통과 · 2 건너뜀 · 실패 2(둘 다 `main` 의 알려진 DF-110) · 시험 2009건 · 결함 124.

## 2. 막힌 것 · 알게 된 것

- **칸 이름은 뜻을 보장하지 않는다.** `chartPreviousClose` 는 이름만 보면 전일 종가다. 같은 시각에 기간 둘로 받아 견줘 보고서야 5거래일 전 종가임을 알았다. 공급자 칸은 이름이 아니라 값으로 확인한다.
- **한 곳만 고치면 복사본이 남는다.** 9-28 에 고친 버그가 복사본 둘에 그대로 있었다. 이번에는 함수를 하나로 합쳤고, 「라우트가 동기화 함수를 따라가나」 를 시험(TC-QL-05)으로 지킨다. 함수를 갈아 끼우면 라우트도 따라가야 통과한다.
- **대역이 한 기간만 알면, 기간이 틀려도 시험이 통과한다.** 「현재가가 없으면 오류 줄」 시험(TC-QL-03)의 대역은 1일 기간 응답만 갖고 있었다. 그래서 기간을 5일로 되돌려도 응답이 없어 오류 줄이 나오고, 시험은 우연히 통과했다.
  - 깨 보기 전에 대역부터 의심했다. 기간과 상관없이 같은 응답을 주는 대역을 따로 둬서, 기간이 아닌 것을 보는 시험이 기간 탓에 통과하지 않게 했다.
- **모델에게 코드를 짐작하게 하면 엉뚱한 회사를 정확하게 답한다.** 숫자는 서버가 맞게 계산했다. 틀린 것은 「누구의 숫자인가」 였다. 사람이 쓰는 이름을 받고 서버가 찾는 편이 옳다.
- **답을 고치지 말고 서버 값을 옆에 둔다.** 모델의 문장을 서버가 몰래 고치면 그것도 말없는 대체다. 그래서 답은 그대로 두고 서버 값 블록과 어긋남 경고를 붙였다. 「200% 이상이면」 같은 기준 문장의 숫자는 비교에서 뺀다.
- **시험이 진짜 수집 DB 를 열 뻔했다.** 회사 이름으로 코드를 찾는 함수가 생기자, 도구 시험이 이 PC 의 수집 DB 를 읽기 전용으로 열었다. 바로 점검(데이터 16/16 정상)한 뒤, 시험마다 없는 경로를 가리키게 했다.
- **봉인 시험은 낱말을 센다.** 야후 참조를 세는 시험(TC-YH)이 새 설명 글의 영어 이름까지 셌다. 이름표를 「야후 파이낸스」 로 써서 기준 수를 바꾸지 않았다. 이 사실은 PR 본문에 적는다.
- **결함 수는 짐작하지 않고 표에서 센다.** 지난 판 제목의 「열림 24 · 닫힘 90」 은 표를 세면 25 · 89 였다. 이번 판에서 기계로 센 값으로 바로잡았다.

## 3. 원칙으로 다시 보기

- **SSoT** — 최신 시세 함수는 하나다(라우트와 동기화). 머리 글은 `data_provenance.quote_note` 한 곳, ±1.5% 문턱은 `quoteview.js` 의 `MOVE_LIMIT` 한 곳이다. 화면의 종목 기호 규칙은 수집 DB 다리의 규칙과 같은지 시험으로 맞댄다.
- **말없는 fallback 금지** — 모르는 등락은 None · 「—」 다. 예시 가격 · 0 가격을 쓰지 않는다. 에이전트의 「셀 수 없음」 은 숫자로 바꾸지 않고, 서버는 답을 몰래 고치지 않고 옆에 붙인다.
- **일관성** — 등락률은 서버가 한 번 계산하고, 화면은 다시 셈하지 않는다. 국내 기호 꼴은 JS 와 파이썬에 둘 다 적힐 수밖에 없어서 시험으로 맞댄다.
- **멱등성** — 문서 고치기 도구는 모두 두 번째 실행에서 「고침 0」 을 확인했다.
