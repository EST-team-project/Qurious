## 2. 막힌 것 · 알게 된 것

- **생성 그림은 캔버스용이라 문서에 넣으면 글자가 안 보인다.** FigJam 그림은 2,600px 폭에 16px 글자라, 문서 폭 1,000px 로 줄이면 약 6px 가 된다. 글자를 26 · 22px 로 키우고 나서야 읽혔다. 구역 이름은 내보낸 그림에 찍히지 않아 구역 안에 이름표 글자를 따로 넣었다.
- **한 장에 다 넣으면 세로로 길어졌다.** 「규칙 투자자」 한 사람에게서 유스케이스 열한 개로 선이 나가자 그림 도구가 같은 층의 상자를 한 줄로 쌓아 1,768 × 3,617 이 됐다. 가로로 다시 놓으면 선이 상자를 가로질렀다. 결국 **묶음 단위 개요(가로) + 표 + 접어 둔 상세**로 나누는 것이 답이었다 — 유스케이스 실무 글이 말하는 「묶음 요약 그림 + 묶음별 상세」 와 같은 결론이다.
- **꺾인 선의 길찾기는 상자를 피하지 못했다.** 배포 구성도에서 끝점 방향을 하나하나 정해도 선이 그림 밖으로 돌아갔다. 곧은 선 + 자동 연결점 + 상자를 세 줄로 놓는 쪽이 훨씬 깔끔했다.
- **대시보드의 기본 성과는 실제 비용이 아니었다.** 백테스트 엔진을 한 번 불러 보니 투자 대시보드 「기본 전략 성능」 은 「왕복 대칭 10bp(실제 국내주식 비용이 아니다)」 로 계산하고 있었다. 실제 비용 모델(2026 · 코스피 매도 약 0.318%)이 따로 있다 — 화면 기본을 무엇으로 둘지는 성과 주담당께 물었다(이슈 초안).
- **포트 여섯이 모든 망 연결에 열려 있었다.** 인프라 구성도를 쓰며 `docker port` 를 재 보니 DB 포트까지 `0.0.0.0` 이었다. compose 는 팀 공용 파일이라 고치지 않고 안을 적었다.
- **기계로 바꾼 범례는 사람이 다시 읽어야 했다.** 이모지를 글자로 한꺼번에 바꾸자 「완료 끝 · 진행 진행」 같은 범례가 생겼다. 바꾼 뒤 범례 줄만 골라 손으로 고쳤다.
