## 1. 무엇을 했나

- **강사님 기초 코드(th06 `289bfb5`)를 3-way 로 들였다.** 로그인 세션이 쓰는 동안 30일로 늘어나고(5분마다 연장 · 쿠키도 다시 굽는다), 대화 방식(로컬 모델 · OpenAI · 근거 대화)과 Redis AOF 가 생겼다. 우리 사본이 기준과 같던 여섯 파일은 강사님 판 그대로, 셋은 깨끗이 합쳐졌고, 나머지는 우리 고침(토큰 폐기 키 · 서버가 세션을 보고 고르는 페이지 · 서비스 이름)을 지키며 손으로 얹었다.
- **벡터 저장소(Qdrant)를 늘 켜고, 문서 올리기 · 근거 검색이 처음으로 실제로 돌게 했다.** 올리기 → 찾기 → 근거 대화 → 지우기 → 다시 찾기 0 을 점검에 넣었다.
- **용어사전 화면과 모든 화면의 용어 설명을 만들었다.** Figma 에서 경우를 나눠 그리고 사용자가 고른 대로 — 찾기 첫 화면 → 용어 한 장, 다른 화면에서는 오른쪽 서랍(기본) · 작은 창 · 큰 창 · 휴대폰 시트, 고르는 곳은 내 정보 「화면 설정」. 서비스 이름은 Qurious 로, 이름 · 부제 · 바닥글은 한 파일에서.
- **10-06 오전 칸 문서를 모두 새 판으로 냈다** — ERD · 데이터 사전 v1.3 · IA · 와이어프레임 v0.4 · 화면 설계 절차 v0.2 · 결정 대장 v1.0(규칙 적용판).

## 2. 막힌 것 · 알게 된 것

- **비밀번호를 바꾼 기기까지 로그아웃됐다(DF-37).** 우리 시험은 비밀번호 바꾸기 라우트를 직접 불러 통과했다. 그런데 강사님 판의 미들웨어는 응답이 나갈 때 「옛 세션 ID 로 쿠키를 다시 굽는」 예약을 실행한다. 라우트가 새 쿠키를 넣은 뒤라 응답에 쿠키가 [새, 옛] 순서로 실리고 브라우저는 뒤의 것을 쓴다. 5분 간격이 걸린 요청에서만 생겨, 될 때도 안 될 때도 있었다. 미들웨어를 거치는 작은 앱과 가짜 시계로 실제 순서를 재현하는 시험을 먼저 만들고, 고침을 끈 판에서 그 시험이 실패하는 것을 본 뒤에 고쳤다. **남의 미들웨어와 내 라우트가 만나는 곳은 라우트만 부르는 시험으로는 보이지 않는다.**
- **「업로드 완료 (0조각 저장)」 가 성공(200)으로 왔다(DF-38).** 저장소 라이브러리가 비동기 클라이언트를 받는 척하다 만들 때마다 죽었고, 코드가 그 오류를 삼켰다. 성공 응답 안의 숫자 하나(0)가 유일한 단서였다. 지금은 저장에 실패하면 503 이다.
- **ERD 가 예고한 일이 그대로 일어났다.** v1.2 는 「자동 생성을 돌리면 인덱스 넷을 지우는 마이그레이션이 생긴다」 고 적었다. 팀원 마이그레이션이 정말 그 넷을 지웠다 — 모델과 DB 의 어긋남은 0 이 됐지만, 모델을 고친 것이 아니라 DB 를 모델에 맞춘 쪽이다. 그 파트의 몫이라 이슈 초안으로 넘겼다.
- **「반대가 없었다」 와 「반대를 보지 못했다」 는 다르다.** 결정 대장을 규칙대로 옮기며, 팀 대화방 의견을 보지 못했다는 것을 머리표 · 요약 · 줄마다(「반대 못 봄」) 적었다. 확정 25줄은 그 꼬리를 달고 있다.
- **스캐너가 메뉴의 들여쓴 항목 아홉을 세지 못했다.** 「메뉴에 없는 화면 9」 를 문서에 옮길 뻔했다 — 메뉴 한 줄을 읽는 정규식이 `label` 바로 뒤의 `}` 만 받았다. 고치고, 옛 규칙이면 실패하는 시험을 붙였다.
- **사람이 적는 대장은 코드가 바뀌어도 알려 주지 않는다.** 표 속성 대장의 `users` 보존 칸이 「탈퇴 기능이 없다」 였는데, 탈퇴는 이틀 전에 생겼다. 판을 올리며 줄마다 코드와 다시 맞춰 보다 찾았다.
