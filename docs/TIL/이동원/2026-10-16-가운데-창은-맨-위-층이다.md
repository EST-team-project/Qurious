## 1. 무엇을 했나

- **모든 화면의 「사용법」 을 가운데 창으로 바꿨다.** 화면 맨 위에서 펼치던 줄 대신 윗줄(지금 위치 · 「사용법」)을 누르면 창이 뜬다.
  - 안 셋(가운데 창 · 오른쪽 서랍 · 고친 접이식)을 Figma 에 지금 꼴과 나란히 놓고 골랐다. 추천은 서랍이었지만, 뒤에 차트 · 시각 자료를 넣을 자리와 사용자들의 말을 따라 가운데 창이 됐다.
  - 창 크기는 화면마다 다르다. 차트 · 분석 화면은 크게, 나머지는 안내 글 양으로 작게 · 보통 · 크게를 고른다.
  - 끝줄에 그 화면의 개념 학습 장을 이었다(70곳 중 38곳).
- **판단과 여닫기를 나눴다.** 크기 · 장 · HTML 은 아무것도 가져오지 않는 `howtoview.js`, 여닫기는 `howto.js`. 그래서 node 로 70화면을 그대로 돌려 시험할 수 있다.
- **팀원 머지를 중간에 받아 결함 하나를 닫았다.** 오준영 님 #207 이 같은 종목 미확인 주문 시험을 정한 규칙대로 나눠, 10-14 부터 이어지던 「알려진 실패 다섯」 이 넷이 됐다(DF-112).
- **숫자.** 시험 1890건(TC-HT 10 · #207 의 +27 · #208 의 +1) · 55차 1886 통과 · 실패 4(모두 `main` 의 알려진 것) · 깨 보기 26 / 26.

## 2. 막힌 것 · 알게 된 것

- **`showModal` 로 연 창은 맨 위 층(top layer)에 뜬다.** 그래서 z-index 9100 의 용어 서랍이 창 뒤에 깔려 눌리지 않는다. z-index 를 올려도 맨 위 층은 못 넘는다.
  - 용어 카드를 창 안에 그렸다. 받기 · 대체 글 · 다시 시도를 용어 서랍에서 `fillTermCard` 로 꺼내 둘이 같이 쓰니, 받기가 한 곳으로 남았다.
- **닫을 때 초점을 돌려주는 줄을 지워도 손 시험이 통과했다.** 브라우저가 HTML 표준의 dialog 닫기 규칙대로, 열기 전 초점이 있던 단추로 스스로 돌려준다.
  - 그 줄은 이중 장치다. 깨 보기는 「코드가 하는 일」 이 아니라 「사용자에게 보이는 일」 을 잰다는 것을 다시 봤다.
- **「Tab 열두 번 뒤 초점이 창 안」 시험이 한 화면에서만 실패했다.** 창 안 칸이 다섯이면 열두 번째 Tab 이 마침 「한 바퀴 끝 → 브라우저 쪽」 에 떨어진다.
  - 지킬 것을 「초점이 뒤 화면으로 한 번도 가지 않는다」 로 바꿨다. 셈이 맞아떨어져 통과하던 다른 화면은 운이었다.
- **창 폭은 두 곳(JS · CSS)에 적힌다.** 크기를 정하는 JS 와 실제 폭을 그리는 CSS 가 어긋나도 아무 시험도 깨지지 않았다. 깨 보기 목록을 짜다 알아 둘을 맞대는 시험을 더했다.
- **색인 표 사이 빈 줄 하나가 표를 둘로 끊었다.** 지난 PR 에서 「## 더할 때」 앞에 줄을 끼우며 빈 줄을 남겼다. 마크다운 표는 빈 줄에서 끝난다.

## 3. 원칙으로 다시 보기

- **SSoT** — 크기 · 장은 판단 모듈 한 곳, 용어 받기는 함수 하나. 두 곳에 적힐 수밖에 없는 창 폭은 시험이 맞댄다.
- **일관성** — 상품 상세 창과 같은 경계(760 아래 화면 전체)와 같은 꼴(가운데 창).
- **말없는 fallback 금지** — 용어사전에 없으면(404) 화면의 짧은 설명, 그 밖의 실패는 「다시 시도」 를 붙인다. 용어 서랍과 같은 규칙을 같은 함수가 지킨다.
- **원자성** — 기초 코드 갈림을 `core.js` 7줄로 줄여, 기초 코드 반영 때 부딪힐 자리를 한 덩어리로 묶었다.
