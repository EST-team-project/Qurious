## 1. 무엇을 했나

- 팀장 요청 넷을 받았다 — ① AI 도구 없이도 혼자 프로젝트를 로컬에서 돌릴 스크립트 ② 코드마다 상세한 주석 ③ 산출물에 기능별 핵심 코드 · 동작 원리 그림 ④ `scripts/` 안 폴더에 PowerShell 로 돌려 curl 처럼 동작을 확인하는 스크립트. 팀에서 「로컬에서 전체 기능을 먼저 확인하고, AWS 는 강사님 안내 뒤」 로 이야기가 된 상태다.
- `scripts/personal/` 에 일곱 개를 만들었다 — `start`(띄우기) · `check`(기능 점검 45건) · `status` · `logs` · `stop` · `test`(자동 시험 · 일회용 시험 DB) · `dev`(앱만 호스트 파이썬). 공용 함수 파일 하나와 패키지 대조 도우미 하나, README.
- 산출물로 [로컬 실행 안내서 v0.1](../../배포/로컬실행안내서_v0.1.md)을 냈다 — 운영 매뉴얼 틀(목적 · 사전 조건 · 번호 단계 · 확인 · 실패하면 · 되돌리기)에 동작 원리 그림 8개 · 핵심 코드 발췌 · 점검 45건 표 · 발견 10가지. 팀원용 사용법 이슈 본문도 썼다.
- 번호 채우기: S68 PR #68(머지 `88d5813`) · 논의 #69(강사님 최신 반영 — 옛 D8 번호와 다른 글).

## 2. 왜 했나

- 지금까지는 앱을 띄우는 일이 대화 안에서만 일어났다. 팀원이 각자 PC 에서 같은 앱을 같은 방법으로 띄울 수 없으면 「로컬에서 전 기능 확인」 이라는 합의가 증거를 남기지 못한다.
- 빠르게 만든 기능이 많을수록, 「이 기능이 도는가」 를 사람이 하나씩 눌러 보는 비용이 커진다. 점검을 목록으로 묶으면 같은 확인을 몇 초에 다시 할 수 있고, 목록 자체가 「기능 → API → 무엇이 오면 통과」 의 문서가 된다.

## 3. 어떻게 했나 — 고른 것과 버린 것

- **고른 것: 저장소(DB) 먼저, 준비를 확인한 뒤 앱.** 처음엔 compose 로 한꺼번에 띄웠는데 앱 로그에 「Neo4j 연결 실패 (그래프 기능 비활성)」 가 찍혔다. `depends_on` 은 「켜졌다」 까지만 보장하고 「준비됐다」 는 보장하지 않는다. 앱은 켜질 때 한 번만 붙어 보고 포기한다. 순서를 지키자 사라졌다.
- **고른 것: 코드가 이미지보다 새로우면 스스로 다시 빌드.** 컨테이너는 이미지를 만든 순간의 코드로 돈다 — `git pull` 뒤 옛 화면을 보는 착각이 팀 작업에서 가장 흔하다. Dockerfile 이 복사하는 파일들의 수정 시각과 이미지 생성 시각을 비교한다.
- **고른 것: 점검 한 건 = 요청 1건 + 통과 조건 + 한 줄 요약.** 응답에서 「기능이 돌았다는 증거 하나」(봉 개수 · 출처 · 기준일, 백테스트의 비용 모델 등)를 골라 적는다. 계산이 맞는지는 자동 시험 몫으로 남겼다 — 두 층을 섞으면 어느 쪽도 믿기 어렵다.
- **고른 것: 판정 넷(OK · 주의 · 실패 · 건너뜀).** Ollama 가 없어 AI 채팅이 안 되는 것은 설계상 동결 기능이라 실패로 세면 안 되고, LEAN 이미지가 없는 것은 동작엔 문제가 없지만 알려야 한다.
- 버린 것: 기존 강사님 코드 전체에 주석 달기 — 다음 3-way 병합의 충돌이 늘어난다. 우리가 쓴 코드에는 주석을 상세히, 강사님 코드의 설명은 문서(「동작 원리」 절)로 하자고 문서 작성 기준 부록 C 에 제안했다.
- 버린 것: 사용자 anaconda 환경에 빠진 패키지를 설치해 개발 모드 확인 — 공용 환경을 건드리지 않고, 기존 패키지를 빌려 쓰는 임시 가상환경에 빠진 5개만 넣어 확인한 뒤 지웠다.

## 4. 어떻게 확인했나

- 꺼진 상태에서 `start.ps1` 30초 · 떠 있을 때 다시 6초(멱등) · Neo4j 경고 없음.
- `check.ps1 -Full -Write -SaveReport` 45건: 통과 43 · 주의 1(LEAN 이미지) · 건너뜀 1(AI 연결) · 실패 0 · 46.7초. 개발 모드 앱에도 33건 통과(호스트 앱은 Ollama 에 닿아 AI 연결까지 통과).
- `test.ps1`: 249/249 · 86초 · 시험 DB 는 끝나고 지워졌다. `stop.ps1` 은 도커 밖의 개발 앱까지 알아챘다.
- 스크립트 여덟 개 모두 PowerShell 5.1 파서로 구문 오류 0 · UTF-8 BOM.

## 5. 막힌 것 · 남은 것

- **PowerShell 5.1 이 한글을 두 번 깨뜨렸다.** BOM 없는 파일을 cp949 로 읽고, charset 없는 JSON 을 ISO-8859-1 로 읽는다(`ê¸ìµ AI Agent`). 바이트를 UTF-8 로 직접 풀어 막았다.
- **함수가 명령 출력을 삼켰다.** PowerShell 함수는 안에서 실행한 명령의 출력까지 반환값으로 내보낸다 — `logs.ps1` 이 로그를 한 줄도 안 보여 줘서 알았다. `| Out-Host` 한 줄.
- **시험 DB 가 55432 에 안 떴다.** 이 PC 는 55367~55466 을 Windows 가 예약해 두었다(산출물목록에 이미 적혀 있었는데 놓쳤다). 고정 포트 대신 후보에서 고른다.
- **`localhost` 가 2초 늦었다.** 5.1 은 IPv6 로 먼저 붙는다 — 127.0.0.1 에만 뜬 Ollama 를 「없음」 으로 잘못 봤다.
- 점검으로 **주문 미리보기가 비용을 빼지 않는 것**을 찾았다(1주 48원) — 모의투자 담당 파트 몫이라 결함 후보(DF-21)로만 적었다.
- 새 PC(이미지 캐시 없음)의 첫 빌드 시간 · PowerShell 7 은 아직 못 쟀다 — 사용법 이슈 댓글로 받는다.

## 6. 배운 것

- **「켜짐」 과 「준비됨」 은 다르다.** 컨테이너 상태가 Started 여도 안의 서비스는 아직 준비 중일 수 있다. 기다림은 상태가 아니라 **실제 요청**(pg_isready · HTTP 200)으로 판정해야 한다.
- **스크립트가 문서가 된다.** 점검 목록을 「요청 + 통과 조건 + 요약」 으로 적어 두니, 그 목록을 그대로 옮긴 표가 「기능마다 어떻게 확인했나」 의 답이 됐다. 발표 · 면접에서 쓸 문장이 코드 옆에 있다.
- 추정 숫자를 문서와 스크립트 주석에 적었다가 지웠다(개발 모드 「1~2초 안에 재시작」 — 앱 시작 과정 전체를 다시 돌므로 재지 않고는 말할 수 없다). 재지 않은 칸은 「—」 가 정직하다.
