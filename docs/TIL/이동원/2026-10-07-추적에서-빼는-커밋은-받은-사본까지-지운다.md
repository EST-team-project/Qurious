## 1. 무엇을 했나

- **강의 2일차가 읽는 시세 JSON 둘을 공개 저장소의 추적에서 뺐다.** `public/lectures/days/assets/etf-catalog.json`(579,632B · 네이버 금융 목록과 토스증권 화면 응답으로 모은 ETF 1,009종) · `leverage-etf-volume.json`(901B · 네이버 금융 월봉 계산). 통합본 쪽 원본은 이미 「HF 보관」 이라 비공개 데이터셋 `qurious-quant/rag-lab-display-data` 에 있었는데, 강의 빌드가 옮긴 사본만 커밋돼 있었다. 사본 두 줄을 `.gitignore` 에 더하고 추적에서만 뺐다(이 PC 의 파일은 남는다).
- **강의 빌드가 「HF 보관」 파일을 가려 다루게 했다.** 반입 대장에서 그 줄을 읽어, 통합본 사본에 받아 둔 파일은 지금처럼 옮기고(사본은 git 무시) 없으면 건너뛰며 받는 명령(`python scripts/raglab_data.py pull`)을 알린다. 받는 도구도 끝에 「앱 강의 화면에 쓰려면 빌드를 한 번」 을 알린다.
- **시험부터 썼다.** TC-LC-12(옮기는 사본도 `.gitignore` 에 있다) · TC-LC-13(받지 않은 PC 에서 건너뛴다 — 쓰지도 지우지도 다르다고 하지도 않는다). 둘 다 한 번에 통과해 일부러 깨 봤고 넷 모두 잡았다. 전체 시험은 971 통과 · 2 건너뜀 · 실패 0 이다(그 뒤 머지된 팀원 #131 의 7건은 따로 통과).
- **브라우저로 두 경우를 봤다.** 파일이 있으면 ETF 목록 창은 1,009종 · 85쪽, 레버리지 창은 막대 12개 · 합계 625.2조 원으로 그린다. 파일을 잠시 치우면 두 창이 각자 「불러오지 못했습니다」 를 띄우고 나머지는 그대로다.

## 2. 막힌 것 · 알게 된 것

- **추적에서 빼는 커밋은 다른 PC 에서 파일을 지운다.** `git rm --cached` 는 내 작업 트리의 파일을 남기지만, 그 커밋을 pull 하는 PC(머지 뒤의 이 PC 도)에서는 git 이 「지워진 파일」 로 보고 작업 트리에서 지운다. 받아 둔 PC 는 빌드를 한 번 돌려야 사본이 다시 생긴다 — 그래서 빌드 점검(`--check`)과 TC-LC-01 이 그 경우를 「빠진 파일 — 빌드 한 번이면 생긴다」 로 알린다.
- **「건너뛴다」 의 뜻을 셋으로 나눠야 했다.** 쓰지 않는 것만으로는 모자랐다. 빌드는 결과에 없는 public 파일을 지우므로, 받지 않은 PC 에 옛 사본이 남아 있으면 지워 버린다. 그리고 점검은 그 파일을 「남는 파일」 로 실패시킨다. 건너뛴 파일은 비교에서 아예 빼서 쓰지도 · 지우지도 · 다르다고 하지도 않게 했다(깨 보기 M3 이 이 빼기를 끈 판을 잡는다).
- **빼도 이력에는 남는다.** 2026-10-07 전 커밋에는 두 파일이 그대로 있다. 공개 저장소의 이력을 다시 쓰는 일(강제 push)은 하지 않았다 — 지금부터 새로 들어가지 않게 막은 것이다.
- **명령 인자로 넘긴 목록이 비면 도구는 「전부」 로 읽는다.** `pytest $(grep …)` 의 grep 이 아무것도 찾지 못해 pytest 가 인자 없이 전체 시험을 일회용 DB 없이 돌리기 시작했다. 3분 만에 멈췄고 DB 시험은 주소가 없어 건너뛰었으며, 기능 점검 데이터 13 이 통과해 앱은 그대로였다. 시험 파일은 이름으로 적어 넘긴다.

## 3. 다음에 할 것

- 받지 않은 PC 에서 두 창이 「잠시 후 다시 시도하세요」 를 띄운다 — 다시 해도 같으니 맞지 않는 안내다. 강의 빌드가 문구를 바꿀지 정한다.
- 데이터 화면의 「DB 초기화」 가 모든 사용자의 주문 · 감사 로그까지 지운다(DF-78) — 크롤링 세 화면 구현 때 단추를 빼며 시험으로 막는다.
