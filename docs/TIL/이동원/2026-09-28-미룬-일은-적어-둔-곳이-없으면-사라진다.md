## 2. 왜 했나

- 기록 색인은 이 저장소에서 「GitHub 에 무엇이 올라갔나」를 답하는 유일한 곳이다. 옛 저장소가 닫힌 뒤로 GitHub 를 직접 볼 수 없는 팀원은 여기만 본다.
- 그런데 S54 의 PR #28 이 글 폴더 2개(`이슈-화면결함-파트별/` · `PR-docs-wireframe-v0-2/`)를 더하면서 **색인에 줄을 하나도 더하지 않았다.** 번호가 올린 뒤에 나오니 「다음 기록 PR 에서」 로 미룬 것이다. 미룬 것 자체는 맞았는데, **미뤘다는 사실이 색인 어디에도 남지 않았다.** PR #27 은 자기 줄을 「(올린 뒤 적음)」 으로 먼저 넣어 뒀기 때문에 S55 에 찾기 쉬웠다. 차이는 그 한 줄이었다.
- 산출물목록도 같았다. S53·S54 두 세션이 산출물(일일 갱신 · I14 · 와이어프레임 v0.2)을 냈는데 11절 줄이 S52 에서 멈춰 있었다. S42 가 똑같이 빠뜨려 S43 이 채운 적이 있다(그 줄에 적혀 있다). **세 번째**다.

## 3. 어떻게 했나 — 고른 것과 버린 것

- **고른 것 — 폴더 이름으로 센다.** 색인 표의 링크는 늘 `(<날짜>/<글 폴더>/00-본문.md)` 꼴이다. 그래서 `<날짜>/<글 폴더>/` 문자열이 README 에 한 번도 없으면 빠진 것이다. 옛 글 75개도 같은 꼴이라 규칙 하나로 85개를 다 본다. 뒤의 `/` 까지 맞추는 것은 `PR-새` 가 `PR-새글` 에 묻혀 통과하지 않게 하려는 것이다(시험 1건).
- **고른 것 — 알림이지 실패가 아니다.** 이 스크립트는 길이 초과만 실패(종료 코드 1)로 본다. 색인은 PR 을 만들기 전에 채우면 되는 것이라, 막지 않고 보이게만 했다.
- 버린 것 ① **「(올린 뒤 적음)」 이 남은 줄도 알리기** — 방금 만든 PR 의 줄은 원래 그 상태다. 매번 뜨는 알림은 곧 안 보게 된다.
- 버린 것 ② **산출물목록 11절도 검사하기** — 세션 번호는 파일에 적힌 곳이 없어 셀 기준이 없다. 이번에는 사람이 채우고, 기준을 먼저 세운 뒤에 본다.
- 버린 것 ③ **PR #28 본문 · 이슈 #26 본문 원본을 고치기** — 그 파일은 GitHub 에 올라간 글의 원본이다. 올린 뒤에 고치면 원본과 올라간 글이 달라진다. TIL 본문의 「이슈 초안」 두 곳도 그때의 사실이라 두었다(README 규칙 5).

- 색인에 적은 글자 수를 다시 쟀더니 **넷이 파일과 달랐다** — `#16` 2,288 → 2,573 · `#27` 3,116 → 3,141 · IA 이슈와 추적 이슈는 1자씩. 두 파일은 커밋 뒤 바뀐 적이 없다(`git log`). 잰 뒤에 파일을 고친 것이다. 다시 잰 값으로 바꾸고 표 위에 한 줄로 적었다.

## 6. 배운 것

- **「나중에 채운다」 는 자리를 먼저 만들어 둘 때만 지켜진다.** 빈칸이 있는 줄은 눈에 띄지만, 줄이 없으면 빠진 것도 안 보인다. 번호를 모르면 줄을 비워서라도 넣는다.
- **숫자는 잰 시점의 것이다.** 파일을 잰 뒤에 고치면 색인의 숫자는 틀린 채로 남는다. 색인에 숫자를 적는 PR 은 커밋 직전에 한 번 더 잰다.
