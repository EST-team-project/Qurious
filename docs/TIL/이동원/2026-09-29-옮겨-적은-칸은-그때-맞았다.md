## 3. 어떻게 했나 — 고른 것과 버린 것

- **고른 것 — 줄마다 「다시 잰 방법」 을 적는다.** 상태만 바꾸면 다음 판에서 또 「이건 언제 잰 거지?」 가 된다. `crawl.py:110` 그대로 · `app.html:3333` 그대로처럼 **줄 번호까지** 적었다.
- **고른 것 — DF-06 을 구체적으로.** v1.0 은 「문자열 보간 버그」 한 줄이었다. 읽어 보니 `100 - parseInt(buyTh)` 가 `${}` 밖에 있어 Pine 코드에 글자 그대로 찍힌다. 같은 식을 파이썬 생성기는 `${}` 안에 넣어 맞게 쓴다 — 고칠 사람(P-B)이 옆 줄을 따라 하면 된다.
- **고른 것 — 이미 올린 글은 새 댓글을 달지 않는다.** 「시험 102건」 은 올린 때의 사실이고 결론이 바뀌지 않았다. 하루 5건 · 10분 간격 규칙에서 숫자 하나를 고치려고 댓글을 쓰는 건 아깝다. **아직 안 올린** 파일만 제자리에서 고쳤다.
- 버린 것 ① **DF-11 · DF-16 을 이 PR 에서 고치기** — 문서 판을 내는 PR 에 코드를 섞으면 리뷰가 둘로 갈린다. 테스트계획서 6절 1·2순위로 남겼다.
- 버린 것 ② **올린 글 17건의 새 번호를 이번에 채우기** — 목록 페이지로 짝은 다 맞췄지만 다음 세션 작업(①)이다. 한 세션에 작업 하나.

## 4. 어떻게 확인했나

- **DF-04 의 「0」 이 이상했다.** 옛 `#53` 은 「공유 스위치에 막힌 실행이 종료코드 0」 이라 적었다. 스위치를 끄고 게이트 함수를 부르니 **1** 이었다. `git log -L` 로 보니 그 함수는 09-20 뒤로 바뀐 적이 없다. 파이썬은 문자열을 받은 `SystemExit` 을 1 로 낸다. 그때 `… | tail` 뒤에서 `$?` 를 읽었다면 `tail` 의 0 이 찍힌다 — 가장 그럴듯하지만 기록이 없어 🟡 로 적었다. 같은 댓글의 두 번째 사례(`upload_large_folder` 의 조용한 재시도)는 진짜였고 전체 업로드에 남아 있다. → **일부 닫힘.**
- **DF-11 은 두 배였다.** v1.1 의 「나머지 스크립트 5개」 를 AST 로 다시 세니 `print` 안에 이모지가 있고 UTF-8 처리가 없는 파일이 `scripts/` 5 + `collector/` 5 였다. `benchmark status` 를 사용자 셸 조건으로 돌리자 이모지가 아니라 **줄표 `—`** 에서 죽었다. 일일 러너는 자식에 `PYTHONIOENCODING=utf-8` 을 넣어 살아 있었을 뿐이다.
- DF-02 는 `benchmark verify` 로 — 코스닥 평균 0.871% · 최대 1.896%, 옛 `#56` 과 한 자리도 다르지 않다. 게이트(평균 1.00%)는 통과로 찍는다. 게이트와 결함대장은 다른 질문이다.
- 이슈 · 논의 목록은 github.com 목록 페이지를 세 장 읽어 맞췄다(토큰 API 없이 · 사용자 확인 뒤).

## 5. 막힌 것 · 남은 것 — 이번 세션의 사고 셋

- **`--help` 가 전 종목 재계산을 시작했다.** 모듈마다 사용자 셸에서 죽는지 보려고 `python -m collector.preprocess --help` 를 돌렸는데, 이 모듈의 `main()` 은 인자를 보지 않는다. 도움말 대신 쓰기 트랜잭션이 열렸다. 마침 예약 작업이 같은 일을 하고 있어 잠금을 기다리다 멈췄고(한 트랜잭션이라 중단하면 되돌려진다), 반복문의 다음 차례(`dividend` — DART 수집일 수 있었다)가 오기 전에 멈췄다. 해는 없었다. → **DF-16.**
- **예약 작업과 겹쳤다.** 일일 갱신이 09:06 에 돌기 시작한 줄 모르고 실제 DB 시험 · 벤치마크 검증을 함께 돌렸다. 러너의 수정주가 단계가 398초 → **1,286초**. 30분 제한 안이라 성공했다. → 판정 원칙 7번째: 돌리기 전에 `daily_update.py status` 의 「실행 중」 을 본다.
- **시각을 9시간 틀리게 보고했다.** Git Bash 의 `TZ=Asia/Seoul date` 가 시간대 파일 없이 UTC 로 찍어 「00:05 KST」 라고 말했다. 실제는 09:05 였다. PowerShell `Get-Date` 로 잰다.
- 남은 것: DF-11 · DF-16 코드(P-A) · 매매비용 시험 · 보조담당 블랙박스 시험 0건 · DB 없이 돌린 결과(111 · 6)는 S59 값을 옮겼다.

## 6. 배운 것

- **「무엇을 만들까」 의 답이 강사님 교안에 이미 있었다.** 일정표 10/28 은 「TradingView — Webhook 수신 · Pine 전략」, 11/3 은 「Pine · LEAN · 로컬 신호 대사」 를 요구하는데, th03 16단계 코스가 그 재료(`strategy.exit` + ATR · 수수료 0.015%)를 담고 있다. 우리 생성기는 `indicator()` 에서 멈춰 있다 — 결함대장 DF-05 가 요구사항 쪽에서도 같은 자리를 가리킨다.

- **옮겨 적은 칸은 「그때 맞았다」 이지 「지금 맞다」 가 아니다.** 이번에 다시 재 보니 9건 중 2건의 상태가 바뀌었고, 1건은 원래 기록이 잘못 잰 값이었을 수 있다. 판마다 다시 잰다.
- **읽기 전용 명령인지는 이름이 아니라 코드가 정한다.** `--help` 는 관례일 뿐이다. 인자를 모르는 모듈에는 먼저 `main()` 을 읽는다.
- **잰 값 옆에 잰 방법을 적는다.** 방법이 없으면 다음 사람은 믿거나 다시 재거나 둘 중 하나밖에 못 한다. DF-04 의 「0」 이 그랬다.
