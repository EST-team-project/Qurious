## 1. 무엇을 했나

- **화면 69개와 로그인 · 가입을 같은 기준으로 다시 매겼다.** 강사님 배지의 기준(UI 20 · 서버 30 · DB/외부 연동 25 · 자동 시험 25)은 그대로 두고, 강사님 점수가 있는 화면은 그 뒤 바뀐 근거만큼만 더하고 뺐다. 기능 점검 스크립트의 실제 왕복은 +4, 그 뒤 생긴 자동 시험은 +3, 근거가 틀렸거나 새로 찾은 결함은 감점이다. 미평가 화면은 배점표로 처음부터 매겼다. 배지 평균(미평가 0 포함)은 52.8 에서 70.0 이 됐고 38개 화면의 점수가 바뀌었다.
- **다섯 부분을 바깥과 견줬다.** 근거 답 · 인디케이터 · 로보어드바이저 · 데이터 · 학습에서 오픈소스 13 · 실제 서비스와 공공 API 13 · 표준 1, 모두 27곳을 봤다. 라이선스는 저장소의 LICENSE 원문 첫 줄로 다시 맞췄다. 한국은행 ECOS 는 표본 키로 실제 불러 통계용어사전과 100대 통계지표가 오는 것을 확인했다.
- **이동원 몫에서 둘을 고쳤다.** 크롤 조각의 벡터 DB 번호를 내장 `hash()` 에서 sha256 으로 바꾸고, 다시 모을 때 같은 주소의 옛 점을 지우게 했다. 배지에는 이동원 몫 20줄을 팀 점검 값으로 더하고, 그 줄이 점검표와 같은지 보는 시험을 붙였다. 팀원 화면은 고치지 않고 파트별 이슈 초안 넷으로 넘겼다.

## 2. 막힌 것 · 알게 된 것

- **배지는 개발해도 바뀌지 않는 고정 표였다.** `completion.js` 는 점수를 글자로 들고 있고 시험 · API · 화면 코드와 이어진 곳이 없다. 2026-09-30 뒤로 아무도 고치지 않았고, 강사님조차 10-03 에 시험을 더하면서 점수표는 두었다. 그래서 강민석 님이 만든 테스트베드 화면이 「미평가 0%」 로 뜨고, 시험 21건을 붙인 AI 투자 상담이 감사 때의 68점 그대로였다. 숫자가 저절로 맞는다고 믿으면 배지는 오히려 틀린 정보를 준다.
- **배지 근거 하나가 코드와 달랐다.** 「투자 정보 리서치」 는 「RAG 검색 API 구현」 으로 평가됐는데, 실제로는 수집 기사 표를 글자로 찾아 5건을 돌려줄 뿐이었다. 화면 안내문도 「AI RAG로 검색」 이라고 적는다. 점수를 그대로 옮겨 적었다면 이 차이를 못 봤을 것이다.
- **같은 결함에 번호를 두 번 매길 뻔했다.** 크롤 중복을 고치며 새 결함 번호(DF-61)를 붙였는데, 9월 갱신 댓글을 읽다가 결함대장에 같은 결함이 DF-03 으로 열려 있는 것을 찾았다. 번호를 다시 매기고 DF-03 을 닫았다. 새 번호를 매기기 전에 결함대장에서 같은 파일 · 함수를 먼저 찾아야 한다.
- **고치기 전 코드로 시험을 돌려 시험이 결함을 잡는지 봤다.** `git archive HEAD` 로 고치기 전 트리를 풀고 새 시험만 넣으니 3건이 실패했다. 실제 Qdrant 에서도 임시 컬렉션으로 「같은 글 다시 3 → 3점 · 짧아진 글 → 2점 · 끼워 넣은 옛 번호 중복 → 지워짐」 을 쟀다. 앱 컬렉션은 비어 있어 지울 옛 중복은 없었다.
- **임베딩이 하나도 안 될 때 지우지 않게 했다.** 다시 모을 때 옛 점을 정리하는 길은 임베딩 서버가 꺼져 있으면 「옛 근거를 다 지우고 아무것도 못 넣는」 길이 된다. 이번에 쓴 점이 0개면 정리하지 않도록 막고 시험으로 묶었다.
- **실제 서비스 규칙이 팀 논의의 근거가 됐다.** Betterment 는 기본 이탈 허용 3% 이고, 입출금 · 배당이 들어올 때 모자란 것을 사서 먼저 맞추고(reactive), 그래도 넘으면 사고판다(proactive). 오준영 님의 리밸런싱 논의에 그대로 쓸 수 있는 실무 근거라 점검 이슈에 붙였다.
