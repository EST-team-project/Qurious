## 2. 막힌 것 · 알게 된 것

- **전체 시험이 「실패」 가 아니라 「0건」 으로 멈췄다.** 새 시험 파일 하나가 `@pytest.mark.asyncio` 를 쓰는데 이 저장소는 `--strict-markers` 이고 `pytest-asyncio` 가 요구 패키지에 없다. 모아 세기 단계의 오류 하나가 나머지 2,300여 건을 돌지 못하게 막는다 — 실패 다섯보다 훨씬 큰 결함이다(DF-142). 그 파일만 빼고(`PYTEST_ADDOPTS=--ignore=…`) 점검을 이어 가고, 고칠 길은 사용자가 골랐다.
- **패키지를 하나 깔았더니 시험 도구의 큰 판이 바뀌었다.** `pytest-asyncio` 최신(1.4)은 pytest 9 를 끌어온다. 판을 묶지 않으면 팀원마다 다른 pytest 로 돈다 — `>=1.3,<1.4` 로 묶고 `strict` 로 두어, 기존 비동기 시험(anyio)은 그대로 anyio 가 맡게 했다.
- **Windows 는 이름에 `:` 가 든 파일을 만들 수 없다.** 그런 파일이 하나라도 든 커밋은 체크아웃 전체가 멈춘다. 고침 커밋도 Windows 에서 만들어야 해서, `core.protectNTFS=false` 를 임시 인덱스에 올리는 한 명령에만 걸고 작업 트리에는 쓰지 않았다.
- **점검 도구가 칸 이름을 오해하고 있었다.** `paper = false` 는 「실전」 이 아니라 「앱 안 가상 체결이 아니라 증권사(모의 서버)로 주문」 이다. 서버가 모의인지는 다른 칸(`environment`)이 말한다 — 도구를 고쳤다(DF-143).
- **세션이 세 번 끊겼는데 충돌이 아니라 메모리였다.** 쓸 수 있는 메모리가 1.8 GB 일 때 VS Code 확장 호스트가 「응답 없음」 → 다시 시작했다. 오래 도는 시험은 세션 밖 프로세스로 돌리고 상태 파일로 결과를 읽었다.

## 3. 원칙으로 다시 보기

- **멱등성** — 고침 도구는 「새 글이 이미 있나」 를 먼저 보고, 쓴 뒤 같은 인자로 다시 돌려 0곳인지 본다(오늘도 그림 범례 한 곳이 두 번 붙을 뻔했다).
- **재현성** — 한 파일 판은 같은 원본이면 바이트까지 같아야 한다. 글꼴 저장 시각(`head.modified`)이 끼어 처음엔 4바이트가 달랐다.
- **알 수 없는 것은 그대로 적기** — 팀원 칸은 발표 자료의 문장을 옮긴 초안으로 두고 판단 칸은 비웠다.
