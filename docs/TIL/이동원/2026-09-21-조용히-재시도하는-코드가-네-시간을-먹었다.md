# 조용히 재시도하는 코드가 네 시간을 먹었다 — 그리고 우리가 모은 것을 우리가 쓰지 않고 있었다

> 2026-09-21 (월) · Qurious 2.0 · [#53](https://github.com/devlee328288/Qurious/issues/53) · [#61](https://github.com/devlee328288/Qurious/issues/61)
> 커밋 `edb60d1`

## 한 줄

**업로드가 4시간 24분 동안 멈춰 있었는데 종료코드는 0이었다.** 원인은 YAML 한 줄이었고, 진짜
문제는 그걸 조용히 감춘 코드였다.

---

## 1. 멈춘 게 아니라 반복하고 있었다

HuggingFace 백업 556MB를 올리는데 진행이 40%에서 멈췄다. 프로세스는 살아 있었다.

```
업로드 시작 ·········· 09:28:33
Xet 캐시 마지막 쓰기 ·· 09:29:30   ← 시작 1분 뒤
확인 시각 ············ 13:53       ← 4시간 24분간 활동 0
CPU 사용률 ··········· 3%          ← 대기만 하고 있다
```

처음엔 큰 파일(`raw_response/portal.parquet` 275MB)을 처리하다 교착된 줄 알았다. 파일 수와
용량이 4시간 전 조회와 **한 바이트도 다르지 않았다**(21개 · 221.7MB).

프로세스를 죽이고 로그를 열자 답이 있었다.

```
Failed to commit: Invalid metadata in README.md.
- "license_name" must only contain lowercase characters
- "license_name" with value "공공데이터포털·OpenDART 파생 — 출처별 이용약관 준수"
    fails to match the required pattern: /^[a-z0-9-.]+$/
Failed to commit 11 files at once. Will retry with less files in next batch.
```

이 네 줄이 4시간 24분간 반복됐다.

## 2. 한 칸만 규칙이 달랐다

데이터셋 README의 YAML 머리말이다.

```yaml
pretty_name: "KRX 일별 시세·수정주가·총수익지수·벤치마크 (2020–2026)"   # ← 한글 OK
license: other
license_name: "공공데이터포털·OpenDART 파생 — 출처별 이용약관 준수"      # ← 여기만 안 된다
```

`license_name`은 서버가 `/^[a-z0-9-.]+$/`로 검사한다 — **소문자·숫자·하이픈·점만.** 바로 위
`pretty_name`은 한글이 되고 본문도 한글이 된다. **같은 머리말 안에서 칸마다 규칙이 다르다.**

고친 것:

```yaml
license_name: kogl-type1-and-opendart-derived
```

한글 설명은 본문으로 옮겼다. 그리고 같은 명령이 **11.3초**에 끝났다.

> 4시간을 먹은 것은 네트워크도 파일 크기도 아니었다.

## 3. 진짜 배운 것 — 조용한 재시도는 실패를 성공처럼 만든다

`license_name`은 사소한 실수다. 5분이면 고친다. 문제는 **그 실수가 4시간짜리가 된 이유**다.

| 층 | 무엇이 일어났나 | 왜 안 보였나 |
|---|---|---|
| ① 서버 | 커밋 거부 (422) | 정확한 이유를 말해 줬다 🟢 |
| ② `upload_large_folder` | **조용히 재시도** | 예외를 던지지 않는다 |
| ③ 프로세스 | 무한 반복 | 살아 있으니 "진행 중"으로 보인다 |
| ④ 종료코드 | **0** | 자동화에서 성공과 구분 안 됨 |
| ⑤ 내 실행 | `2>&1 \| tail -40` | **파이프 버퍼링으로 로그가 0바이트** |

①은 잘 작동했다. ②~⑤가 그 정보를 차례로 지웠다.

⑤는 내 실수다. `tail`로 파이프하면 프로세스가 끝날 때까지 출력이 안 나온다. 그래서 4시간 동안
로그 파일이 **0바이트**였고, 나는 "버퍼링 때문"이라고 넘겼다. 실은 그 안에 답이 계속 쌓이고
있었다. 재실행할 때 `PYTHONUNBUFFERED=1`을 붙였다.

### 이건 이미 적어 둔 문제의 재발이다

어제 #53을 쓰면서 5절에 이렇게 남겼다.

> 🟡 다만 막힌 경로는 **종료코드 0으로** 끝난다 — "막혔다"가 아니라 "하지 않았다"로 취급한다.
> CI에서 성공과 구분하려면 종료코드가 아니라 출력을 봐야 한다.

**같은 계열의 문제를 알고 적어 뒀는데, 다음 날 그것에 4시간을 냈다.** 적어 두는 것과 막는 것은
다르다. 게이트를 세우지 않으면 기록은 사후 변명이 된다.

## 4. 덤 — 우리가 모은 것을 우리가 쓰지 않고 있었다

같은 날 강사님 요구사항 242항목을 저장소와 대조했다([#61](https://github.com/devlee328288/Qurious/issues/61)). 가장 큰 발견은 기능 부족이 아니었다.

```
app/services/stock.py:9   YAHOO_CHART = query2.finance.yahoo.com
       → get_candles() → ml.py · quant.py · stocks.py · lean_backtest.py

app/ 에서 수집 DB(market.sqlite3) 참조 ······ 0건
app/ 에서 benchmark_index 참조 ············· 0건
```

**시세 4,460,710행 · 배당 9,188건 · 벤치마크 12계열을 모아 놓고, 앱은 Yahoo Finance로 돈다.**
S30~S39에 만든 것이 화면에 한 번도 닿지 않았다.

그리고 판정이 한 번 더 정정됐다 — 야후 의존은 한 함수가 아니라 **3층 24지점**이었다.

```
1층  get_candles() 호출 14곳 ········ 한 함수 교체로 따라온다
2층  _yahoo_chart() 직접 호출 5곳 ···· get_candles 를 우회한다
3층  독립 URL 5곳 ·················· lean_backtest.py:100 ★ LEAN 시세를 직접 받는다
```

3층 때문에 "동일 데이터·기간·수수료 조건" 요구가 1층 수정으로는 충족되지 않는다.

> **만든 것과 쓰이는 것은 다르다.** 수집기를 여덟 세션 동안 키웠지만 배선을 한 번도 하지 않았고,
> 그래서 우리 최대 자산이 발표에서 증명될 수 없는 상태였다.

## 5. 또 하나 — 근거를 정직하게 갈라야 했다

처음엔 이렇게 보고했다: *"금지된 소스 위에 서 있다."* 틀렸다.

`docs/rfp-2.md` §3.2가 데이터 소스로 *"KRX, Yahoo Finance, FinanceDataReader 등 공개 데이터
활용"*을 **허용한다.** Yahoo를 쓰는 것 자체는 강사님 요구 위반이 아니다. 배제는 **우리가 약관
검토로 스스로 좁힌 기준**이다.

그래서 배선의 근거가 바뀐다.

| | 틀린 근거 | 맞는 근거 |
|---|---|---|
| 왜 고치나 | "요구사항 위반이다" | **"우리가 모은 446만 행이 앱에서 한 번도 쓰이지 않는다"** |

발표에서도 이렇게 말해야 한다. **요구 근거와 우리 자체 기준을 섞으면 둘 다 약해진다.**

(반대 방향으로 더 강한 것도 나왔다 — 같은 문서 §4.2가 *"실제 증권 계좌를 통한 실거래 자동 주문
실행"*을 **제외 범위로 명시**한다. 지금 열려 있는 실전 주문 경로는 위험 항목이기 **전에 요구사항
위반**이다.)

## 6. 아직 안 한 것

- 🔴 **`verify` 를 이 업로드분에 돌리지 않았다** — 원문 sha256 12,697건 재계산. 순서는
  `export` → `upload` → **`verify`** → 삭제다. 그래서 **로컬 SQLite를 아직 지울 수 없다.**
- 🔴 **조용히 재시도하고 0으로 끝나는 구조는 그대로다.** `license_name`만 고쳤다.
- 🔴 **야후 배선은 손대지 않았다.** 3층 24지점을 확인만 했다.

## 7. 배운 것

**실패를 감추는 코드는 실패보다 비싸다.**

서버는 정확한 이유를 말해 줬다. 그 정보가 다섯 층을 지나며 지워졌고, 마지막에 남은 것은
"종료코드 0"과 "0바이트 로그"였다. 버그를 고치는 데 5분, 버그를 찾는 데 4시간 24분이 걸렸다.

그리고 — **적어 두는 것으로는 막히지 않는다.** 종료코드 문제를 어제 문서에 적었고 오늘 그것에
당했다. 다음에 할 일은 문서에 한 줄 더 적는 게 아니라 **게이트를 세우는 것**이다.
