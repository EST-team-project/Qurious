## 1. 무엇을 했나

- HF 데이터셋 연결을 **읽기 조회만으로** 확인했다 — 계정 `data-student` · 조직 `qurious-quant` 소속 · `krx-daily-market` private · 파케이 27개 555.6MB · 마지막 스냅샷 `snapshot-2026-09-21`. 원격은 로컬 매니페스트와 같았다.
- 수집 9단계를 순서대로 부르는 `scripts/daily_update.py` 를 만들고 **Windows 작업 스케줄러**에 매일 12:30 으로 올렸다. 첫 실행은 등록 직후 `schtasks /Run` 으로 걸었다.
- 배당 수집에 `--recent N`(최근 N달은 `done` 이어도 다시 훑기)을 더했다.

## 2. 왜 했나

- 확인해 보니 **HF 09-21 · 로컬 시세 09-22 · 수정주가·TR·벤치마크 09-17** 이었다. 단계는 다 있는데, 사람이 기억해서 이어 부르지 않으면 단계마다 다른 날에 멈춘다.
- 사용자 요청 — 최신 데이터로 갱신하되 **세션이 바뀌어도 유지되고, 이것 때문에 다음 작업으로 못 넘어가는 일이 없게.**

## 3. 어떻게 했나 — 고른 것과 버린 것

- **Celery Beat 를 버리고 작업 스케줄러를 골랐다.** 저장소에 Beat 일정(`collector-portal-recent` 18:00)이 이미 있지만 Redis·워커가 떠 있을 때만 돈다. 수집기를 스택에서 떼어 둔 이유(README 2절)가 그대로 적용된다.
- **Claude 세션의 백그라운드 프로세스로 돌리지 않았다.** 세션이 끝나면 같이 끝난다. 작업 스케줄러에 올리고 `start` 로 곧바로 한 번 돌려, 첫 실행부터 세션과 무관한 프로세스가 되게 했다.
- **PowerShell 등록 스크립트를 버리고 작업 정의 XML 을 파이썬에서 만들었다.** Windows PowerShell 5.1 은 BOM 없는 UTF-8 을 ANSI 로 읽어 한글 설명이 깨진다.
- **배당은 최근 두 달만 다시 훑는다.** 전부 다시 훑으면 81달(2020-01~2026-09)의 목록을 다시 넘긴다 — 오늘 두 달에 49회였으니 약 2,000회다. 이번 달과 지난달이면 공시가 늦게 잡히는 월말까지 덮는다.
- **업로드는 바뀐 파케이가 있을 때만.** 없어도 올리면 내용 없는 커밋과 태그가 매일 쌓인다.

## 4. 어떻게 확인했나

- 시험 15건 — 연말 경계(`2027-01` 이면 `202612`·`202701`) · 파생 판정 5가지(09-28 실측 상태 포함) · 잠금·생존 확인 5가지 · 작업 XML 2가지 · 업로드 필요 판정. 네트워크·DB 없이 돈다.
- 첫 실행을 **작업 스케줄러 쪽 프로세스**에서 돌려 로그로 봤다: 시세 2초(09-23 1일 · 09-24·25 는 추석이라 빈 응답) · 배당 17초(목록 49회 · 새 공시 0) · 수정주가 398초 · TR 407초 · 벤치마크 253초 · 지문 14초 · 파케이 274초 · 검증 14초 · 업로드 20초 — 합계 23분 18초. 끝난 뒤 원격을 읽기 조회로 다시 봤다: 커밋 `6d612d36` · 태그 `snapshot-2026-09-28` · private · 로컬 매니페스트와 일치.
- 창 없는 `pythonw` 로 불린 러너가 SSL·포털 호출까지 정상인 것을 첫 단계 로그로 확인했다(콘다 환경을 켜지 않은 채로도 됐다).

## 5. 막힌 것 · 남은 것

- **처음 짠 순서가 틀렸다.** 배당을 수정주가 뒤에 두었는데, 파생 단계를 돌릴지는 수정주가 직전에 한 번만 판정한다. 그러면 "배당만 새로 온 날" TR 이 건너뛰어진다. 코드를 다시 읽다 찾았고, 그 경우를 시험으로 박았다.
- **Windows 에서 `os.kill(pid, 0)` 은 프로세스를 죽인다.** 유닉스 습관대로 "살아 있나" 를 물었다면 돌고 있는 수집을 잠금 확인이 끊었을 것이다. 그래서 처음부터 `OpenProcess` 로 물었고, 시험이 자기 PID 로 그것을 확인한다.
- **"닫힌 연도는 다시 안 올라간다" 가 수정주가에는 틀렸다.** 수정주가는 오늘을 1.0 으로 거꾸로 누적해서, 새 조정 이벤트 하나가 2020년 값까지 바꾼다. 첫 실행에서 7개 연도 파일이 전부 바뀌었다(50.6MB). xet 가 바뀐 청크만 보내 20초에 끝났지만, 설명 문구는 시세·TR 에만 맞는 말이었다.
- 남은 것: 앱 화면이 이 데이터를 읽는 길(화면 시세는 아직 야후) · 올리는 사람을 한 명으로 정하는 것(팀 합의) · 기록 색인·TIL 목록 줄(S52 PR 머지 뒤).

## 6. 배운 것

- **"단계가 다 있다" 와 "데이터가 최신이다" 는 다르다.** 이어 부르는 손이 없으면 단계마다 다른 날에 멈추고, 그 차이는 아무도 눈치채지 못한다.
- **`done` 은 닫힌 기간에만 쓸 수 있는 말이다.** 아직 끝나지 않은 이번 달에 `done` 을 찍으면, 그 뒤 들어오는 자료를 영원히 놓친다.
- 오래 걸리는 일은 **기다리지 말고 떼어 낸다.** 떼어 낸 뒤에는 잠금·로그·상태 파일이 있어야 "지금 도는 중인가, 멈췄나" 를 물을 수 있다.
