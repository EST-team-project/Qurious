## 1. 무엇을 했나

- `get_quote` 가 등락률을 채워서 돌려주게 했다. 식은 `_change_from_prev` 한 곳에 두고, 지수 요약도 그 값을 쓴다. 모르면 0 이 아니라 `None` 이다.
- 시험 21건(단위 16 · 계약 5). 09-28 장중 실측 6종목을 고정값으로 넣었다.
- **테스트계획서 v1.1** — v1.0(23건)을 고치지 않고 새 판으로 냈다. 78건 · 계층 5개 · 결과서 2차 · 결함대장 14건 · 강사님 표 도구 대조.
- **산출물목록 v1.4** — 문서 판 현황 · 강사님 표의 「목적·진행 도구」 대조 · 「진행 중 유의사항 7」 대조 · 세션 끝 확인 5줄.
- S55 PR 번호 **#29** 를 기록 색인 · TIL 목록 · S55 TIL 에 채웠다.

## 2. 왜 했나

- **A1** — #26 을 조사하며 찾은 데이터 파트 몫이다. 스크리닝 카드가 `+--%`, 표가 `+0.00%` 로 보이던 C3 의 뿌리가 서버에 있었다. 전일 종가를 받아 놓고 등락률 두 칸을 `None` 으로 박아 두고 있었다.
- **문서** — 사용자가 강사님 산출물 표를 다시 보여 주며 *"작업하고 나면 하는 거 까먹은 거 같아서"* 라고 했다. 맞는 말이었다. 테스트계획서는 S40 에 23건으로 쓴 뒤 **시험이 55건 늘 동안 한 번도 고쳐지지 않았다.** 산출물목록에는 「테스트계획서 표는 아직 23건」 이라는 메모만 있었다. 시험은 코드와 같은 PR 로 들어오는데, 문서는 따로 고쳐야 해서 매번 빠졌다.

## 3. 어떻게 했나 — 고른 것과 버린 것

- **고른 것 — 현재가와 전일 종가로 계산한다.** 응답에는 공급자가 계산한 등락률(`regularMarketChangePercent`)도 있고, 내 계산과 6종목 모두 소수 둘째 자리까지 같았다. 그래도 계산을 골랐다. 필드는 사라진다 — `previousClose` 가 6종목 **모두 null** 이었고, 옛 코드는 `or chartPreviousClose` 로 겨우 살아 있었다. 두 기본값으로 계산하면 `price`·`prev_close`·`change` 세 칸이 늘 서로 맞는다. 공급자 값은 시험의 **대조용**으로만 쓴다(TC-A1-01).
- **고른 것 — 모르면 `None`.** 현재가·전일 종가가 없거나 0 · NaN · 문자 · 음수면 `None` 이다. NaN 을 따로 막은 것은 FastAPI 가 NaN 이 든 응답을 JSON 으로 못 만들어 500 이 나기 때문이다.
- **고른 것 — 테스트계획서는 새 판으로.** v1.0 을 고치면 「S40 에 무엇을 계획했나」가 사라진다. CI/CD 명세가 v1.0~v1.2 를 파일로 남긴 선례를 따랐다.
- 버린 것 ① **공급자 등락률을 그대로 쓰기** — 한 필드에 다시 기댄다. 사라지면 A1 이 되살아난다.
- 버린 것 ② **기간 5일로 받아 전일 종가를 직접 찾기** — 호출이 무거워지고 휴장일을 따로 처리해야 한다. 기간 1일의 `chartPreviousClose` 가 곧 전일 종가라는 것을 시험으로 묶는 편이 가볍다.
- 버린 것 ③ **화면의 `?? 0`(C3)과 화면 3곳의 중복 계산을 고치기** — 스크리닝은 P-C, 나머지 화면도 각 파트 몫이다(S54 부터 데이터 파트는 자기 영역만 고치고, 다른 파트 결함은 이슈로 남긴다). 대신 PR 알림에 「이제 `change_pct` 를 그대로 써도 된다」 고 적었다.
- 버린 것 ④ **거래소 기준가로 계산하기** — 기준가를 주는 출처가 지금 화면 경로에 없다. 수집 DB 로 옮길 때(DF-08) 같이 본다. 주석에 한계만 적었다.

## 4. 어떻게 확인했나

- 고치기 전에 **실제 응답을 먼저 떴다**(장중 13:26). 그때 두 가지가 나왔다 — `previousClose` 는 null, 그리고 `chartPreviousClose` 가 **기간에 따라 다른 값**이라는 것. 같은 삼성전자를 기간 5일로 받으니 285,500(09-23) 이 아니라 252,500(09-17) 이 왔다. 이름은 「전일 종가」인데 정의는 「차트 첫 봉 바로 앞의 종가」였다. 추석 연휴(09-24·25) 덕분에 전일이 09-23 이라는 것도 5일 차트의 날짜로 확인했다.
- **옛 `stock.py` 로 새 계약 시험 조건을 돌렸다** → `change_pct` 가 `None` 이라 실패. 시험이 결함을 잡는다.
- 전체 시험 — DB 없이 69 통과 · 6 건너뜀, Postgres 를 잠깐 띄워 붙이면 **75 통과 · 0 건너뜀**(#29 의 3건을 더하면 78). 컨테이너는 바로 지웠다.
- 야후 봉인 시험 — `stock.py` 참조 줄이 20줄 그대로다. 봉인이 줄 수를 양쪽으로 묶고 있어서 **새 주석에 영문 공급자 이름을 쓰지 않았다.** 봉인이 작업 방식까지 바꾼 경우다.
- `/api/stocks/quote` 를 부르는 화면 5곳을 다 봤다. 3곳은 `change_pct` 를 읽지 않고 `prev_close` 로 같은 식을 따로 계산한다 → 값이 바뀌는 화면은 스크리닝 하나뿐이다. #26 B1(볼린저 ±2%)은 차트 종가로 따로 계산해 무관하다.

## 5. 막힌 것 · 남은 것

- 한국거래소가 **현금배당락 날 기준가를 조정하는지** 원문을 못 봤다. KIND 공시 뷰어가 본문 없이 프레임만 돌려줬다. 2차 자료로는 「현금배당은 조정하지 않고 주식배당만」 이다 🟡. 그래서 코드 주석에는 확실한 것(권리락 · 주식배당락 · 분할 · 병합)만 적었다.
- 화면 시세는 아직 야후다. 수집 DB(1,343만 행)로 옮기는 것이 A1 다음 일이다.
- 결함대장 DF-01~09 는 v1.0 상태를 옮겨 적기만 했다. 다시 재지 않았다.
- 78건이 **전부 P-A 가 쓴 시험**이다. 분배안의 「보조담당이 블랙박스 시험 1개」(§5 규칙 2 ②)가 아직 0건이다 — 「2인 이상」의 증빙이 비어 있다.

## 6. 배운 것

- **필드 이름을 믿지 말고 값의 정의를 잰다.** `chartPreviousClose` 는 이름만 보면 전일 종가다. 요청 인자 하나가 그 뜻을 바꾼다. 그런 필드는 시험이 인자까지 묶어야 한다.
- **모르는 것을 0 으로 보이면 아는 척이다.** 서버가 `None` 을 줘도 화면이 `?? 0` 이면 「보합」이 된다. 결측은 끝까지 결측으로 가야 한다 — 이번엔 서버 쪽만 지켰다.
- **문서가 코드를 따라오게 하려면 세션 끝의 확인 목록에 넣어야 한다.** 「나중에 문서도」 는 여섯 번 빠졌다. 산출물목록에 5줄짜리 확인표를 두고, 다음 세션 프롬프트에도 넣는다.
