## 1. 무엇을 했나

- **강사님 기초 코드 `9478811`(KIS 자동매매 연동 · 41파일)의 서버 쪽을 받았다.** 전체 41파일 가운데 서버 쪽만 — 깨끗이 합쳐짐 6 · 강사님 판 그대로 3 · 손으로 합침 3(충돌 4곳) · 새 파일 9 + 시험 13. 화면 파일 여섯(충돌 3곳 포함)은 다음으로 미뤘다. 강사님 마이그레이션 `0009_live_orders` 는 우리 `0009` 가 이미 있어 `0013` 으로 번호만 바꿨다.
- **위험한 두 줄을 받기 전에 시험부터 썼다.** 반영 전 코드에서 7건이 실패하는 것을 보고 나서 합쳤다.
- **KIS 키를 사용자마다 쓰게 바꿔 받았다.** 강사님 판은 서버 계좌 하나를 모두가 같이 쓴다. 「문제가 될 수 있기 때문에 처음부터 사용자마다」(사용자 결정).
- **문서 판을 올렸다** — 사용자가 「매 세션 판 올리기」 를 새 규칙으로 주었다. API 명세서 v0.2 · ERD · 데이터 사전 v1.4 · 테스트 계획서 v1.4 · RTM v1.2 · 결정 대장 v1.1 · ADR-0004(새).

## 2. 막힌 것 · 알게 된 것

- **가장 위험한 곳은 충돌 표시가 없는 곳이었다.** 강사님의 새 주문 길(게이트웨이)은 증권사 클라이언트를 만들지 않고 HTTP 로 주문한다. 우리 실거래 차단은 「클라이언트를 만드는 팩토리 한 곳」 에 걸려 있었는데, 그 한 곳을 지나지 않는 길이 생긴 것이다. 설정값 한 줄(`real`)이면 실전 서버로 나갔다. `git merge-file` 은 이 줄을 아무 말 없이 합쳤다. ADR-0001 이 「앞으로 생길 경로까지 같이 걸린다」 고 썼던 전제가 깨진 날이다.
- **옆문도 막아야 했다.** 게이트웨이 함수들은 `env=` 인자를 받는데, 이 인자는 환경 설정값을 건너뛴다. 환경값만 막으면 `get_balance(env="real")` 같은 호출이 그대로 나간다. 그래서 환경 판정을 `_env()` 하나로 모았다.
- **지운 모듈 하나가 앱 전체를 멈춘다.** 합친 `auto_trade.py` 맨 위에 09-15 에 지운 SageMaker 점수 모듈 import 가 충돌 없이 들어왔다. 자동매매 라우트가 이 파일을 부르니 앱과 Celery 가 뜨지 않는다. 다음 반영에서도 같은 일이 생기지 않게 「걷어낸 AWS import 가 되살아나지 않는다」 지킴이 시험을 두었다 — 강사님 판을 넣으면 실제로 잡는 것까지 확인했다.
- **시험이 깨진 까닭이 코드가 아니라 시계였다.** 강사님 시험 하나(쿨다운 만료 경계)가 우리 PC 에서만 깨졌다. 이 PC 에는 `localhost:6379` 에 Redis 가 없는데, Windows 는 연결 거부를 받기까지 약 4.7초가 걸린다. 시험은 「만료 0.5초 전」 을 만들어 두고 다시 불렀는데 그사이 0.5초가 지나 버렸다. 강사님 리눅스에서는 거부가 즉시 와서 통과한다.
- **이름은 지키고 뜻만 바꾸면 충돌이 한 파일에 모인다.** 사용자별 키로 바꾸는 방법은 둘이었다 — 강사님의 `kis_credentials.py` 를 받지 않고 부르는 네 파일을 고치기, 또는 그 파일의 「서버가 관리하는 증권사」 목록만 비우기. 뒤의 것을 골랐다. 강사님 라우트 · 자동매매 코드는 손대지 않아도 사용자 행을 쓰게 되고, 다음 반영 때 손으로 합칠 곳이 그 파일 하나다.
- **판을 안 올리면 본문이 낡는다.** 테스트 계획서는 S67 의 v1.3 에서 멈춘 채 부록 C 에 68줄이 쌓였다(시험 188 → 667). 팀원과 강사님이 읽는 것은 본문이다. 이번에 묶음 표를 손으로 쓰지 않고 시험-요구 대장에서 만들게 바꿨다 — 57묶음을 손으로 옮기면 다음 세션에 또 낡는다.
- **정답과 다시 맞춰 보니 명세서가 틀려 있었다.** API 명세서를 v0.1 뒤 처음으로 실제 앱 명세(`app.openapi()`)와 맞춰 보니 223/223 은 맞았지만 질의 인자 셋이 파이썬 이름(`start` · `from_`)으로 적혀 있었다. 주소에서는 `from` 이다. 스캐너가 `Query(alias=...)` 를 읽게 고쳤다.
