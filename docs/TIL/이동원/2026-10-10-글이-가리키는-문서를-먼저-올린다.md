## 2. 막힌 것 · 알게 된 것

- **이슈가 조사서보다 먼저 올라갔다.** 이슈 넷(#149 ~ #152)의 본문은 조사서 경로를 가리키는데, 조사 초안은 git 무시 폴더(`_git-drafts`)에만 있었다. 글이 가리키는 문서를 먼저 PR 로 올려야 링크가 열린다 — 그래서 본 작업 앞에 이 작은 PR 을 따로 냈다.
- **표 안의 빈 줄 하나가 결함 수를 93 에서 19 로 만들었다.** 결함대장을 다시 세는 스크립트가 표 머리부터 첫 빈 줄까지만 읽었는데, DF-19 와 DF-20 사이에 빈 줄이 있었다. GitHub 도 같은 곳에서 표를 끝내 DF-20 부터는 표가 아닌 글로 보였다. 빈 줄을 지우고 다시 세니 96건(93 + 3)이다. 상태 칸의 굵은 표시(`**닫힘**`)도 세는 스크립트를 멈췄다.
- **기억으로 쓴 커밋 칸 넷이 틀렸다.** v2 이슈의 B 묶음 커밋을 조사서 요약에서 옮겼는데, 파일별 분류 대장과 맞대 보니 B1 · B4 · B6 · B7 이 달랐다(B6 대시보드는 `a4225b9` · `f250bda` · `a4be79a` · `c0473f7`).
- **옮길 때 남는 작업 말은 기계로 센다.** 세션 번호 · git 무시 경로 · 「배경 ③」 같은 작업 이름을 닻으로 바꾼 뒤 남은 것을 정규식으로 세니 첫 실행에 두 곳(모의투자 조사서의 「배경 ③ 조사 L2 · L3」)이 남았다.

## 3. 원칙으로 다시 보기

- **SSoT** — 이슈 표의 커밋 칸은 파일별 분류 대장(TSV)에서 가져온다. 요약 문서에서 옮겨 적은 넷이 틀렸다.
- **일관성** — 결함 수는 제목이 아니라 표에서 다시 센다. 세는 쪽이 틀리면(빈 줄 · 굵은 표시) 숫자가 크게 어긋나므로 「93 + 새 3 = 96」 처럼 앞 판과의 차이로 한 번 더 맞춘다.
- **말없는 fallback 금지** — 결함 후보는 조사 결과를 그대로 옮기지 않고 오늘 `main` 코드로 다시 열었다. 미국 종목 매도는 순수 함수를 한 번 돌려 `ValueError` 를 실제로 봤다(매수는 계산됨).
