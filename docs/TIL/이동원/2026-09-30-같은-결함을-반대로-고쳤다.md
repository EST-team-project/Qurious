## 3. 어떻게 했나 — 고른 것과 버린 것

- **고른 것: 파일마다 `git merge-file -p` 로 결과만 받아 쓴다.** 기준을 정하는 게 먼저였다 — Qurious 는 강사님 저장소를 git 이력 없이 복사했으므로, 09-15 에 받은 `6d91401` 과 `039bf43` 사이가 readme 한 줄뿐인 것을 확인하고 `039bf43` 을 기준으로 삼았다. git 쓰기(merge)를 하지 않고 파일만 쓰므로 AI 로컬 전용 규칙 안이다.
- **자동매매 장부는 강사님 방식.** 강사님과 우리가 **같은 결함을 반대로** 고쳤다 — 우리(I14)는 현금을 하나로 합쳤고, 강사님은 보유에 장부 칸(PAPER · QUANT)을 달아 나눴다. 새 기능(리밸런싱 · TradingView · 포트폴리오 API)이 모두 장부 칸 위에 서 있어서 우리 방식을 고집하면 강사님 코드를 여러 곳 걷어내야 했다. 팀장은 「강사님 방식으로, 대신 우리 목표에 맞게 고칠 곳은 논의로」 라고 정했다 — 프로젝트 이름이 「나만의」 어드바이저 · 인디케이터라서.
- **비용은 둘 다 받게.** 백테스트 두 곳에 우리 비용 모델(매도세 비대칭)과 강사님 인자(수수료 · 슬리피지 · 손절 · 익절)가 따로 들어왔다. 강사님 화면은 수수료 입력칸이 있어 기본을 우리 실제 요율로 두면 입력이 무시되는 화면이 된다 → 「`cost_model` 을 주면 그대로 · 비우고 `cost_bps` 를 주면 대칭 · 아무것도 없으면 실제 요율」. 화면 기본을 무엇으로 할지는 D4 ① 논의로.
- 버린 것: 강사님 판으로 파일을 통째로 덮어쓰고 우리 고침만 다시 얹기 — 도구가 「되돌릴 수 없는 덮어쓰기」 로 막았다. 그래서 충돌 구역마다 고치는 보통의 방법으로 했고, 결과는 강사님 판과의 차이가 「주문 비용 · 실거래 차단 · 행 잠금 · 설명」 뿐인지 `diff` 로 확인했다.

## 4. 어떻게 확인했나

- 시험: Postgres 시험 DB(15432) 249/249 · DB 없이 242 · 7. 옛 I14 정적 시험은 장부가 바뀌어 **설계대로 실패**했고, 새 불변식으로 다시 썼다(자동매매는 QUANT 만 · 모의투자 총자산 그대로 · 다른 장부 보유는 못 판다 · 보유 조회마다 장부를 적는다).
- 마이그레이션: 빈 DB 에 `0001` → `0009` 가 끝까지 올라가고 head 하나 · alembic 대조는 알려진 4곳 그대로.
- 충돌 없이 합쳐진 파일도 뜻을 다시 봤다 — 강사님 쪽 `verify=False` 제거가 우리가 더한 함수에는 닿지 않았고, 우리 I14 때 넣은 직접매매 보유 검사는 **장부 칸 없이** 보유를 읽고 있었다.

## 5. 막힌 것 · 남은 것

- 스캐너 둘이 새 구조에서 멈췄다(화면 스캐너가 인라인 스크립트를 찾다 `StopIteration`) — 원천을 「인라인 모듈 + `public/js/*.js`」 로 넓혀 고쳤다. 진입 훅 · 숨은 의존 · 리스너 중복 수가 옛 IA 와 같아 규칙이 맞게 옮겨졌다고 봤다.

- 관리자 초기화가 두 장부의 보유는 지우고 자동매매 현금은 남긴다 — 다른 파트 영역이라 논의 ⑥ 으로.
- rag-lab 복사는 원본 조사까지만 하고 다음으로 미뤘다.

## 6. 배운 것

- **충돌이 안 난 파일이 더 위험하다.** git 은 글자가 겹칠 때만 알려 준다. 강사님이 「보유는 장부별」 로 바꾼 뒤에도 우리 검사 코드는 글자가 안 겹쳐 조용히 합쳐졌고, 그대로 두면 자동매매 보유를 직접매매로 팔 수 있었다. 「보유를 읽는 곳마다 장부를 적는가」 를 정적 시험으로 걸어 두었다.
- **같은 결함을 두 사람이 따로 고치면 설계가 갈린다.** 둘 다 맞다. 그래서 병합의 기준은 「누가 맞나」 가 아니라 「기초 코드를 따르고 갈림길은 팀에 묻는다」 였다.
- 기준 커밋을 먼저 확정하지 않았다면 3-way 가 2-way 로 무너졌을 것이다 — 이력 없이 복사한 저장소는 「언제의 판을 받았나」 를 따로 적어 둬야 한다(이번 반영의 기준은 PR 본문에 `039bf43` → `b055ab0` 로 남겼다).
