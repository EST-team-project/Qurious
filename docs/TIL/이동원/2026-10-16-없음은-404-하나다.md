## 1. 무엇을 했나

- **상품 안내의 자산 배분 비중을 들어올 때 저절로 고른다(#179 계약).** 전에는 「내 자산 배분 비중 불러오기」 단추를 눌러야 했고, 실패하면 말없이 단추로 돌아갔다.
  - 저장본(`API-ML-12`)을 먼저 읽는다. 404 일 때만 진단 성향 · 3년 기본 비중(`API-ML-11`)으로 바꾼다.
  - 연결 실패 · 로그인 · 서버 오류는 「저장본 없음」 이 아니다. 기본 비중으로 메우지 않고 까닭과 「다시 불러오기」 를 보인다.
  - 진단 성향과 저장본 성향이 다르면 저장본을 그대로 쓰고 「다시 계산하러 가기」 안내 한 줄을 붙인다.
  - 판단은 `public/js/productweights.js` 한 곳이고, 화면은 그 결과만 그린다. 받은 비중은 브라우저에 남기지 않는다.
- **2차 화면에서 개념 학습으로 가는 길을 두 방향으로 이었다.** 상품 안내 머리에 「처음이라면 — 「펀드와 ETF」 · 「투자 성향과 적합성」」, 레버리지 · 인버스 주의 상자에 「펀드와 ETF」 를 달았다. 장 끝 「앱에서 해 보기」 가 화면으로 돌아온다.
  - 「투자 성향과 적합성」 장은 뼈대로 새로 썼다(교재 34 → 35편). 「펀드와 ETF」 · 「로보어드바이저와 법」 뼈대는 화면 사실에 맞춰 손봤다.
- **함께 담은 것.** 앱 Celery Beat 의 수집 예약 셋 지우기(D106) · 이슈 번호 바로잡음(#149 ~ #152) · #205 코드 대조(DF-117 닫힘 · DF-118 등록) · 개인 초안 폴더의 문서 47개를 docs 관련 폴더로(사적인 줄이 섞인 21개는 올리지 않는 개인 자리로).
- **숫자.** 시험 1852건(TC-PD 4 → 7 · TC-XA 2 → 8 · TC-DU 69) · 깨 보기 스무 곳 모두 잡음 · 점검표 상품 안내 92 → 95.

## 2. 막힌 것 · 알게 된 것

- **판단을 DOM 없는 모듈로 떼니 계약을 양쪽에서 묶을 수 있었다.** 시험이 서버 라우트를 실제로 불러 응답 모델을 거친 꼴을 만들고, 그 응답을 node 로 판단 함수에 먹인다.
  - 서버가 칸 이름을 바꾸면 칸 대조 시험이, 화면이 404 아닌 오류를 메우면 행동 시험이 깨진다.
- **첫 깨 보기 열셋 가운데 화면 그리기 둘을 못 잡았다.** 그때 시험은 판단 함수만 돌렸다.
  - `products.js` 원문을 import 셋만 가짜로 바꿔 node 에 그대로 올리고, 가짜 문서 객체 위에 상태 다섯을 그려 보게 했다. 셋째 바퀴에서 스물 모두 잡았다.
- **탭 하나에 남긴 비중은 다음 사람에게 보인다.** sessionStorage 는 탭이 닫힐 때까지 남는다. 같은 탭에서 다른 사람이 로그인하면 앞사람 비중이 잠깐 보일 수 있어 아예 남기지 않았다.
- **괄호 안에 괄호는 읽히지 않는다.** 「성향(보수적 (안정추구형))이」 를 「「보수적 (안정추구형)」 성향으로」 로 바꿨다. 실제 화면을 찍어 보고서야 보였다.
- **고침 스크립트의 「이미 됨」 은 표지 글로 본다.** 먼저 끼운 절 안에 다른 줄을 끼우자, 앞 고침의 새 글이 통째로는 보이지 않아 절이 한 번 더 들어갔다.

## 3. 원칙으로 다시 보기

- **말없는 fallback 금지** — 「없음」 은 404 하나다. 그 밖의 실패는 「없음」 으로 바꿔 읽지 않고 까닭을 보인다.
- **SSoT** — 비중 판단은 판단 모듈 한 곳이다. 성향 이름표는 자산 배분 화면의 고르기 글을 읽는다.
- **일관성** — 화면에서 장으로 가면 장에서 그 화면으로 돌아온다. 두 방향을 시험 하나(TC-PD-07)가 묶는다.
- **멱등성** — 고침 스크립트는 다시 돌리면 바꿀 곳이 0 이다. 앞 고침 안에 줄을 끼우는 고침은 표지 글로 「이미 됨」 을 본다.
