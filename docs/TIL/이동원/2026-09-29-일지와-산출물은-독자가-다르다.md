## 1. 무엇을 했나

- **문서 작성 기준 v0.1(제안)** — 실무 양식 25곳을 조사해(원문 확인 21 · 2차 출처 4) 원칙 8 · 공통 머리표 · 강사님 산출물 10구분별 틀 · 그림과 표 규칙 · 용어집 · 전후 예시 2 · 이행 계획을 한 문서로 냈다. 팀 규칙이 되는 문서라 **제안**으로 두고 Discord 로 의견을 받는다(기한 10-02 17:30).
- 지금 판 산출물 15개(약 38만 자)의 **작업 기록 흔적**을 쟀다 — 세션 번호 383 · 코드 줄 번호 344 · 내부 용어 145 · 취소선 84 · 옛 저장소 번호 65.
- 지난 PR 번호 채움 — DF-17 PR #53(머지 `1108c02`) · D8 논의 #54. #47 본문의 「D8 아직 안 올림」 은 갱신 댓글 파일로(다음 새 번호와 묶어 올림).

## 2. 왜 했나

- 팀장 의견 — 산출물이 「개인 프로젝트 스타일」 이라 팀원이 읽기 어렵다. 실무에서 어떻게 쓰는지 조사해 틀을 정하되, 표 · 그림을 상세히 하는 방향은 살린다.
- 10-06 오전 칸(IA · 와이어프레임 · ERD) 산출물을 새로 쓰기 **전에** 틀이 있어야 한다. 틀 없이 쓰면 판을 올릴 때마다 모양이 달라진다.

## 3. 어떻게 했나 — 고른 것과 버린 것

- **고른 것 — 느낌을 숫자로 먼저 바꿨다.** 「개인 스타일」 을 흔적 수로 세니 어디부터 고칠지 보였다 — 테스트 계획서 세션 번호 83 · 와이어프레임 줄 번호 58 · 「다리」 75.
- **고른 것 — 국제 양식과 국내 공공 서식을 같이 봤다.** 강사님 산출물 이름(요구사항정의서 · 테이블정의서 등)이 국내 공공 SW 관행과 겹친다. 행정안전부 지침 · 요구사항 작성 가이드 · DB 표준화 지침 서식은 원문 파일을 직접 받아 읽었다.
- **고른 것 — 지우지 않고 옮긴다.** 경위는 개정 이력 · TIL 로, 추출 방법은 부록 「만든 방법」 으로. 표와 그림은 그대로 두고 「답하는 질문」 한 줄 · 번호 · 범례만 더한다.
- **고른 것 — 기존 문서는 판을 올릴 때 바꾼다.** 기준 때문에 판을 다시 올리지 않는다(작업 중엔 판을 올리지 않는 규칙과 같다).
- 버린 것 — **29119-3 문서 10여 종을 그대로.** 4명 · 3주 규모에는 과하고, 표준 스스로도 「문서에 치중하면 시험을 해친다」 는 비판을 받는다. 테스트 계획서 한 권에 절로 둔다.
- 버린 것 — **요구 ID 를 국내 방식(FR-1)으로 바꾸기.** 계층 ID 가 강사님 원문 구조를 따르고, API 명세서 · 기능 설계서가 이미 그 ID 로 이어져 있다. 유형은 칸으로만 더한다.
- 버린 것 — **흔적 검사 스크립트를 바로 만들기.** 모든 팀원 PR 에 닿는 공용 장치라 논의 먼저(기준 11절 ⑧).

## 4. 어떻게 확인했나

- 출처 25곳 — 원문을 연 21곳은 🟢, 해설 · 요약만 본 4곳은 🟡. 유료 표준(29119-3 · 29148)은 IEEE SA 요약만 봤다고 적었다.
- 국내 PDF 2개는 내려받아 텍스트로 읽었다 — 지침 제44조 · 제59조 · 별지 「사업수행계획서」 목차(11. 표준화계획) · 요구사항 유형 기호. DB 서식(HWP)은 미리보기 텍스트 스트림으로 칸을 읽었다.
- 흔적 수는 정규식으로 셌고(기준 부록 B), 그림 1 막대 길이와 **기준 문서 자신의 흔적**(세션 번호 16 · 내부 용어 31 — 전부 예시 · 인용 안)을 스크립트로 다시 쟀다.
- 시험은 돌리지 않았다 — 코드가 안 바뀌었다. 수집만 다시 세어 **169건 · 14파일** 그대로.

## 5. 막힌 것 · 남은 것

- NIA 표준 산출물 가이드 PDF 는 원래 호스트가 만료됐고, 다른 사본은 직접 내려받기를 막았다. 국가법령정보센터의 행정규칙 본문은 동적으로 그려져 웹 가져오기로는 비어 보였다(첨부파일 직접 받기로 우회). 그래서 국내 산출물 이름은 **공식 목록이 아니라 관행 명칭**(🟡)으로만 썼다.
- 공공 누리집이 파일 이름 머리글을 EUC-KR 로 보내, 내 셸(cp949)에서 그 머리글을 찍다 스크립트가 한 번 죽었다 — 줄표 한 글자 때와 같은 교훈이다(출력은 UTF-8 로).
- Mermaid `accTitle` 이 GitHub 에서 그려지는지는 아직 모른다 — 처음 쓰는 문서에서 확인한다.
- 남은 것 — 팀 의견(10-02) → 기준 v0.2 · 10-06 칸 산출물을 새 틀로 · 용어집을 공용 문서로 떼기 · 산출물목록 v3.0(세션별 기록 → 날짜 · PR 별).

## 6. 배운 것

- **일지와 산출물은 독자가 다르다.** 일지는 쓴 사람이 나중에 읽고, 산출물은 모르는 사람이 지금 읽는다. 같은 사실도 놓일 자리가 다르다.
- **판 번호와 상태를 한 칸에 두면 v1.2 가 확정본처럼 보인다.** 팀 검토 기록이 없는 v1.x 가 여럿이었다.
- **실무 양식은 겉모양이 달라도 같은 말을 한다** — 독자와 질문 먼저 · 본문은 지금 상태 · ID 는 고정 · 그림에는 제목과 범례 · 문서는 코드와 함께 고친다.
- **이런 기준은 공공 SW 에서 「사업수행계획서 11. 표준화계획」 자리에 있다** — 강사님 10구분의 1번(착수)에 해당하는 산출물이다.
