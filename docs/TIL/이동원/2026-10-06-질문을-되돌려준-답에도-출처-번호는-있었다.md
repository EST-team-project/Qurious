## 1. 무엇을 했나

- **답이 근거에 맞는지 자동으로 재는 도구를 만들었다.** Ragas 의 Faithfulness(답을 문장으로 쪼개 근거로 뒷받침되는지 하나씩 판정)를 로컬 판정 모델 둘(llama3.1 · exaone3.5:2.4b — 답 모델과 다른 모델)로 돌린다. 판정 모델이 보는 근거는 앱이 답 모델에 넣은 문맥과 같은 길로 다시 만든다(기준일 · 근거 수 · 순서까지). 그런데 llama3.1 은 사람 판정을 가르지 못했다 — 맞은 답 34 가운데 8 에 0.5 아래를 줬다. 판정 까닭을 읽으니 조문에 단서(「다만 …」)가 있으면 단서를 말하지 않은 답을 「근거에 없다」 고 봤다. 빗나간 조로 단정한 오답에는 1.0 을 줬다 — 빗나간 조에는 충실했으니까. 충실도는 정답성이 아니다.
- **「규정은 없습니다」 를 결론으로 쓴 답은 보이지 않게 했다(DF-64).** 근거는 검색 상위 몇 조뿐이라, 거기 없다고 법에 없는 것이 아니다. 지난 답 271건에 대 보니 틀린 답 둘에만 걸려 맞은 답은 그대로다.
- **답 모델이 실패해 돌린 발췌는 근거 없음처럼 접었다(안 B).** 빗나간 조가 「근거 문서에서 찾은 조문」 으로 펼쳐지던 것을 「질문과 맞는지 확인 전」 으로.
- **섹터 질문 분류 2판.** 놓친 일상 말 91개(반품 · 쇼핑센터 · 식당 · 감기약 …)를 더하고, 낱말을 굳힌 뒤 새로 쓴 표본 밖 13문항으로 다시 재니 정답 5 → 8, 빗나간 조로 단정 2 → 0. 기존 질문은 그대로.
- **로컬에 있던 근거 DB · 검색 색인을 HF private 에 백업했다.** 받아서 복원까지 확인했다.

## 2. 막힌 것 · 알게 된 것

- **질문을 되돌려준 답에도 출처 번호는 있었다.** 「주유소가 가짜 휘발유를 팔면 불법인가요?」 에 답 모델이 질문을 그대로 쓰고 「[출처 4][출처 3]」 만 붙였다. 서버 검사는 출처 번호 · 문장 출처 · 한국어를 보는데 셋 다 통과했다 — 형식이 맞으면 내용이 없어도 「답」 이었다. 질문 되풀이 거름을 더했다(DF-76).
- **그 거름을 처음 짠 정규식은 바로 그 답을 놓쳤다.** 출처 표시와 문장부호를 한 식으로 지우면, 「? [출처 4]」 의 「[」 가 문장부호 쪽에 먼저 먹혀 「출처4」 가 남는다. 시험은 통과했는데 지난 답 388건에 대 보니 0건이었다. 실제 자료에 대 보기 전에는 거름이 도는지 모른다.
- **깨 보기가 틀리면 시험이 약해 보인다.** 평가 도구 시험을 깨 보려고 근거를 문맥에 맞추는 함수를 바꿨는데 시험이 그대로 통과했다. 그 함수는 앱 길과 평가 길이 **함께** 쓰는 것이라 둘이 같이 바뀌었을 뿐이다. 깨 보기는 한쪽 길만 깬다.
- **숫자는 다시 세어 적는다.** 그림에 「일상 말 97개 · 기존 질문 102개」 라고 적었다가, 커밋 전에 다시 세니 실제로 더한 것은 91개(97은 후보)였고 102는 근거가 남아 있지 않았다(다시 세니 서로 다른 질문 55개).
- **OpenAI 호환 주소로는 문맥 길이를 못 정한다.** Ollama 의 OpenAI 호환 길은 `num_ctx` 를 받지 않아 기본 길이로 돈다 — 근거 4,500자가 잘릴 수 있어 Ollama 자체 `/api/chat` 으로 불렀다. 판정 모델이 깨진 JSON 을 낼 때는 씨앗을 바꿔 한 번 더 부른다.
- **판정 모델이 GPU 를 쓰면 12:30 갱신이 느려진다.** 수정주가 단계가 1,227초 걸려 갱신이 13:26 에 끝났다(내장 GPU 는 메모리 대역을 CPU 와 나눠 쓴다). 긴 GPU 작업은 12:30 ~ 13:10 을 피한다.
- **검사가 줄 끝에 속았다.** git 초안을 만들기 직전, API 문서 카탈로그 검사가 「뒤처졌다」 로 실패했는데 `git diff` 는 비어 있었다. 생성기는 LF 로 쓰고 이 PC 의 git 은 체크아웃 때 CRLF 로 바꿔 쓴다 — 바이트를 그대로 견주면 머지 뒤 늘 실패한다(DF-77 · 이틀 전 검색 색인 지문 DF-68 과 같은 꼴). 견주기 전에 줄 끝을 접는다.
- **HF 저장량은 지난 판까지 다 센다.** 매일 올리는 데이터셋은 판이 쌓여 하루 0.5 ~ 0.7GB 씩 는다. 로컬을 비우려면 「올리고 지운다」 보다 무엇을 다시 받을 수 있는지부터 정해야 한다(조사서).
