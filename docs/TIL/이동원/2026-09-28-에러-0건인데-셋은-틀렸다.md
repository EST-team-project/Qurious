## 1. 무엇을 했나

- **도커로 앱을 띄워 주 경로 12개 화면을 브라우저에서 직접 눌렀다.** 저장소 `.env`(실제 키)를 읽지 않는 별도 compose 로 띄웠고, 끝난 뒤 컨테이너·볼륨·이미지를 지웠다.
- 결과를 [IA v0.2](../../화면/IA_v0.2.md) 로 정리했다 — 12개 모두 뜨고 에러 0건, 그러나 🟢 4 · 🟡 5 · 🔴 3. 새 문제 5개(I11~I15). 스크린샷 13장.
- [와이어프레임 v0.1](../../화면/와이어프레임_v0.1.md) 을 착수했다 — 공통 틀 2장 + 대표 화면 5장.
- 강사님 일정이 **공식**으로 확인돼 [계획서 v1.2](../../계획서/프로젝트계획서_v1.2.md)(+ `.docx`)와 결정 대장(S52 보정)에 반영했다. 계획서의 옛 저장소 링크 23개도 기록 문서로 바꿨다.

## 2. 왜 했나

- IA v0.1 은 코드를 읽은 정적 분석이었고, 스스로 「49개를 브라우저로 돌려 보지 않았다」고 적었다. 산출물목록에도 「문서보다 그 검증이 먼저다」가 남아 있었다.
- 강사님 일정표에 「IA·와이어프레임」이 **2차 5번째 칸(10-06(화) 오전)** 산출물로 있다.

## 3. 어떻게 했나 — 고른 것과 버린 것

- **이동은 주소(`#화면ID`)가 아니라 상단 탭 → 왼쪽 메뉴 클릭으로 했다.** 처음에는 `navigate()` 를 직접 부르려 했는데 모듈 스크립트 안이라 밖에서 안 보였다. 덕분에 사용자와 같은 길을 가게 됐고, 「퀀트자동매매」 탭이 첫 화면(동결 후보)의 야후 호출 33건을 매번 거친다는 것(I13)이 함께 잡혔다.
- **`.env` 를 버리고 비밀값만 그 자리에서 만들었다.** 앱 코드는 KIS 키를 환경 변수로 읽지 않고(설정은 DB 한 행), 스크린샷이 공개 저장소에 들어가기 때문이다.
- **LEAN 이미지(수십 GB)는 받지 않았다** — `LEAN_MODE=local`. 그래서 `quant-lean` 은 🟡 로 남겼다.
- 계획서는 v1.1 을 고치지 않고 **v1.2 를 새로** 만들었다(8.1 규칙 — 지난 판은 남긴다). 결정 대장은 S50 과 같이 **v0.9 안에서 보정**했다 — v1.0 은 09-30 기한 뒤다.

## 4. 어떻게 확인했나

- 장부 문제(I14)는 화면 숫자에서 코드로 거슬러 올라갔다: 자동매매 3건 뒤 현금 1억 그대로 → 수동 주문 2주는 현금이 정확히 줄어듦(비용 97.4원까지) → `auto_trade.py` 는 `quant_virtual_accounts`(1천만) 현금을, `paper_trading.py:704-723` 은 `paper_accounts`(1억) 현금 + 공용 `portfolio` 를 본다.
- 「연결 성공」 가격 75,496원을 같은 시각 시세 275,250원과 대조했다. `/broker/test` 는 `ok: true` 를 돌려주는데 다른 화면은 「연결되지 않음」으로 남았다.
- 강사님 일정은 표를 눈으로 읽지 않고 **일정표 JS 를 node 로 실행해** 칸마다 날짜를 뽑았다.
- 계획서 링크 교체는 스크립트로 하고 남은 옛 주소 링크가 0개인지 셌다(24 → 0).

## 5. 막힌 것 · 남은 것

- **요일을 틀렸다.** 메모리에 「10-01(수)」로 적었다가, 일정표가 「10. 1.(목)」으로 뽑혀 나와 고쳤다. 오늘(09-28)이 월요일이면 10-01 은 목요일이다.
- **S51 의 한 문장이 틀렸다** — 「우리 계획서는 2차를 09-27~10-26 으로 잡았다」. 계획서는 「종료일 미정」이었고 10-26 은 옛 이슈의 잠정안이었다. IA · 산출물목록 · TIL 세 곳에 옮겨 적혀 있었다. 확인하지 않고 옮긴 문장이 세 벌이 됐다.
- S51 PR(#16)이 이슈 번호 자리를 글자 「번호」로 채운 채 머지됐다 — 명령 블록의 `IA=번호` 를 바꾸지 않고 돌린 탓이다. 이번에는 번호를 받아 파일에 직접 넣었다.
- 브라우저 도구가 저장소 안에 만든 `.playwright-mcp/` 를 지우면서, **옛 세션(09-15~09-18)의 로그까지 확인 없이 지웠다.** git 밖 임시 로그였지만 되돌릴 수 없다.
- 남은 것: I14 장부 수정(서버 · 10-14 칸 전) · 나머지 7개 와이어프레임 · D1 ③ · Q1~Q7 반영(10-06 칸 전).

## 6. 배운 것

- **에러가 0 이어도 틀린 화면은 있다.** 서버는 200 을 돌려주고 화면도 뜨는데, 숫자·문구가 틀린 경우(가짜 수익 · 가짜 가격의 「연결 성공」 · 거래 0회의 「+0.0%」)는 로그로 못 잡는다. **결과 값을 다른 값과 대조해야**(현금 ↔ 체결 합계, 가격 ↔ 같은 시각 시세) 보인다.
- **사용자와 같은 길로 가야 길의 비용이 보인다.** 주소로 바로 들어갔다면 I13(묶음 첫 화면의 호출 33건)과 I11(1440 에서 안 보이는 탭)은 안 보였다.
- **날짜는 계산해서 적는다.** 일정표처럼 코드가 날짜를 만드는 자료는 코드를 돌려 뽑는 편이 눈으로 읽는 것보다 정확했고, 내 요일 오기도 그 출력이 잡았다.
