# 도구보다 합의가 먼저였다 — 같은 날 CI 방침을 세 번 바꾼 날

> 2026-09-21 (월) · Qurious 2.0 · CI 제거 + 논의 개설
> 관련 PR: `chore/remove-ci-pending-discussion` · ADR-0003

## 한 줄

**두 번째 판에서 「게이트냐 신호등이냐」를 아주 열심히 따졌는데,
따져야 했던 건 「이걸 나 혼자 정해도 되는가」였다.**

---

## 1. 하루에 세 판

| 판 | 결정 | 근거 |
|----|------|------|
| S40 | CI 도입 + 룰셋 **게이트** | "승인자를 못 두니 CI 가 막는다" |
| S41 ① | 게이트 철회 → **신호등** | 게이트가 우리 머지 방식을 막는다 |
| S41 ② | **워크플로 삭제** + 논의 개설 | 팀 도구를 팀 논의 없이 세웠다 |

세 번째가 앞의 둘과 다른 층위다. 앞의 둘은 **어떤 CI 를 쓸까**를 다뒀고,
세 번째는 **그걸 내가 정할 일인가**를 다뤘다.

## 2. 두 번째 판에서 무엇을 놓쳤나

두 번째 판(ADR-0002)은 꽤 공들였다. 사람 리뷰와 자동 시험이 보는 범위가 다르다는 걸
표로 정리했고, `paper=False` 가 여러 PR 을 지나간 이력까지 git 으로 추적해 붙였다.
선택지도 셋으로 늘어놓고 비교했다.

```
  A. 워크플로 유지 + 룰셋 미설정 (신호등)   ← 채택
  B. 워크플로 제거
  C. 워크플로 + 룰셋 (게이트)
```

**선택지 세 개가 전부 "내가 무엇을 만들까"였다.** "팀에 물어본다"가 선택지에 없었다.

논거가 촘촘할수록 그 사실이 가려진다. 표를 세 개 그리고 git log 를 추적하고 나면
**이미 답을 찾은 기분이 들어서**, 답을 찾을 권한이 내게 있는지를 안 묻게 된다.

## 3. 그런데 이 프로젝트엔 이미 논의 규격이 있었다

Discussion 이 9건 있다. D0 팀 운영 방식, D1 무엇을 푸는가, D2 유료 서비스 범위,
D4 검정 규격… **팀에 영향 가는 결정은 전부 저기를 거치게 되어 있다.**

```
  Discussion 을 거친 것        Discussion 을 안 거친 것
  ───────────────────────     ───────────────────────
  팀 운영 방식 (D0)            CI 도입          ← 🔴
  프로젝트 정의 (D1)           룰셋 게이트 계획  ← 🔴
  유료 서비스 범위 (D2)
  기능 범위 (D3)
  검정 규격 (D4)
  …9건
```

CI 는 **모든 팀원의 PR 화면에 나타나는 공용 장치**다. 성격상 D0 과 같은 칸에 있어야 했는데,
「기술 부채를 막는 장치」로 분류해서 혼자 세웠다. 분류를 잘못한 것이다.

## 4. "필요하다"와 "그러니 이걸 쓰자" 사이

ADR-0003 을 쓰면서 가장 정리가 된 문장이다.

> **문제가 있다는 것이 내가 고른 해법을 쓰자로 바로 이어지지 않는다.**

`paper=False` 가 여러 PR 을 지나간 건 사실이고, 그건 진짜 문제다. 그 진단은 지금도 유효하다.
그런데 거기서 GitHub Actions 워크플로까지는 **몇 단계가 더 있다** —

```
   문제 있음  →  자동 검사가 필요한가?  →  무엇을 막나?  →  언제 도나?
                                                              ↓
                        실패하면 어떻게?  ←  누가 관리하나?  ←  어떤 도구?
```

이 단계들이 전부 **팀이 답할 질문**인데, 나는 전부 혼자 답하고 마지막 칸만 사용자에게 보여 줬다.
그래서 논의에는 **결론이 아니라 질문 6개**를 올렸다. 1번은 "자동 시험이 필요한가"이고,
**"필요 없다"도 정당한 답**이라고 적어 뒀다. 그렇게 안 적으면 묻는 시늉만 하는 게 된다.

## 5. 걷어내는 비용이 가장 쌀 때였다

| 항목 | 상태 |
|------|------|
| CI 가 있던 기간 | **하루 미만** (S40 → S41) |
| 실행 이력 | 2건 |
| 그 사이 회귀 | 없음 |
| 시험 23건 | **그대로 둔다** — `python -m pytest` 로 돈다 |
| 잃는 것 | **자동 실행**뿐 |

시험 파일은 안 지웠다. 시험은 「무엇을 지킬 것인가」의 기록이고, 그건 이미 ADR-0001 과
테스트계획서에 합의된 내용이다. 지운 건 **누가 언제 돌릴 것인가**를 나 혼자 정한 부분이다.
그 둘은 다른 결정이었는데 한 덩어리로 묶여 있었다.

## 6. 오늘 배운 것

**1. 결정의 층위를 먼저 본다.**
「무엇을 만들까」를 따지기 전에 「이건 누가 정하는 결정인가」를 본다.
공용 장치·팀 규칙·평가에 걸리는 것은 내 판단 대상이 아니라 **논의 대상**이다.

**2. 논거가 촘촘할수록 권한을 덜 묻게 된다.**
표 세 개와 git 추적까지 붙이고 나면 답을 찾은 기분이 든다. 그 기분이 정확히,
권한을 확인할 시점을 지나치게 만든다. **공들인 분석일수록 한 번 더 멈춘다.**

**3. 되돌린 횟수보다 이유가 남았는지가 중요하다.**
같은 날 세 판은 정상이 아니다. 숨기면 편하지만 ADR-0002 를 「대체됨」으로 표시해
남기고, ADR-0003 §5 에 경위를 적었다. 🟡 대신 규칙을 하나 세웠다 —
**다음에 공용 장치를 들일 때는 만들기 전에 논의를 먼저 연다.**

**4. 질문으로 올릴 때는 "안 한다"도 답으로 열어 둔다.**
6개 질문 중 1번이 "필요한가"이고 거기에 "필요 없다는 답도 정당하다"를 명시했다.
답을 정해 놓고 묻는 것은 논의가 아니라 통보다.
