## 1. 무엇을 했나

- **통합본 19묶음의 자리를 한 번에 정했다.** 화면 설계 절차의 0단계(새 화면인가 · 있는 화면에 합치나 · 바꾸나)를 묶음마다 돌렸다. 「보류」 를 쓰지 않으니 판정이 많이 바뀌었다 — 새 화면 3 → 6, 보류 4 → 0. 묶음마다 담당도 요구 대장에서 찾아 적었다.
- **처음으로 Figma 에 화면을 설계했다.** 지금 화면을 찍어 올리고, 「금융 필수 지식」 에 강의를 넣는 모양 세 가지를 같은 크기로 그렸다. 사용자는 셋 중 하나를 고르지 않고 둘(강의실 + 주제 화면)을 합쳤다.
- **강의 4일치와 교재 단원을 앱 안으로 들였다.** 강의실 화면 하나와 주제 화면 아홉. 강의 페이지는 계산기 · 그림 · 용어 창이 그대로 돌게 앱 안에 싣고, 교재는 마크다운을 목차 | 본문으로 그렸다. 강의 그림이 부르던 시세 주소 일곱은 수집 DB 를 먼저 읽게 옮겼다.
- **아키텍처 그림을 판 번호가 있는 이미지로 만들었다.** SVG 를 원본으로 두고 PNG 를 구워 README 맨 위에 걸었다.

## 2. 막힌 것 · 알게 된 것

- **시험 10개가 다 통과한 뒤에 결함 여섯을 찾았다.** 화면을 눈으로 보니 굵은 글씨 뒤에 별표가 그대로 남아 있었다(`**캔들 차트(…)**는`). 마크다운 표준은 괄호 뒤에 한글이 바로 붙으면 그 별표를 「닫는 표시」 로 보지 않는다. 나머지 다섯도 시험이 아니라 브라우저 콘솔과 실제 응답을 읽다가 나왔다 — 강의가 API 주소를 빈 값으로 다시 정하는 줄, 빌드가 옮기지 않은 스크립트, 옛 서버 주소를 부르는 그림, 저장소 구조가 바뀌어 404 가 난 글꼴, 고른 기간과 다른 날부터 계산한 수익률.
- **그 수익률 결함은 원본에도 있었다.** 2019 년부터를 고르면 2020-01-02 부터의 수익률을 아무 표시 없이 냈다. 가져온 코드라고 맞다고 믿지 않고 결과를 하나씩 불러 본 덕에 찾았다.
- **서버는 새 파일을 주는데 브라우저가 옛 파일을 썼다.** 메뉴는 바뀌었는데 강의실이 비어 있었다. `main.js` 의 받은 크기가 0 이었다 — 캐시 지시가 없으면 브라우저가 어림짐작으로 오래 쓴다. `/js` · `/css` 에 「바뀌었는지 매번 묻기」 를 걸었다. 팀원도 같은 일을 겪었을 것이다.
- **디자인 파일의 글은 저장소 문서와 다르게 써야 했다.** 「읽는 법」 에 저장소 경로와 커밋 번호를 적었다가 지적을 받았다. 디자인 파일은 저장소에 들어올 수 없는 사람도 본다. 실무 디자인 파일은 표지(이름 · 짧은 설명 · 상태 · 날짜)와 말로 쓴 안내로 시작한다. 이미지를 한글 파일 이름으로 올리면 레이어 이름이 깨진다는 것도 그때 알았다.
- **근사 명단은 18% 가 틀렸었다.** 거래소의 공식 구성종목 파일로 분봉 명단을 바꾸니 시가총액 순위로 고른 명단에서 71종목이 빠지고 72종목이 들어왔다.
- **그림이 이상해 보여도 자료가 맞을 수 있다.** 코스피 20일 변동성이 100% 를 넘어 자료를 의심했지만, 종가로 다시 계산한 등락률이 503일 모두 자료와 같았다. 그 기간에 −12% · +9.6% 같은 날이 실제로 48일 있었다.
