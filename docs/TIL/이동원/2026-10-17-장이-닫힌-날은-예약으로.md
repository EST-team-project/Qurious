## 1. 무엇을 했나

- **미국주식 › 주문/매매 화면을 설계 C 로 바꿨다.** 종목을 넣으면 시세 카드(달러가 · 전일 대비 · 원화 환산 · 장 상태 · 마지막 체결 시각 · 환율 글), 수량을 넣으면 예상 금액(서버 미리 보기), 매수는 앱 안 확인 상자를 거친다.
  - 전에는 이 칸에 시세 · 장 상태 · 환율이 하나도 없었고, 단추를 누르면 확인 없이 바로 체결됐다. 토요일에는 금요일 마감 값으로 체결됐다(안내 없음).
- **장이 닫힌 때는 예약 주문으로 받는다.** 다음 정규장의 시가에 그때 환율을 곱해 체결하고, 체결 시각은 그 정규장 시작으로 남긴다.
  - 새 표를 만들지 않았다. 주문 표의 대기 줄(`order_kind="reserved"`)로 두었다 — 스탑 주문과 같은 꼴이다.
- **종목 찾기 API 가 「찾지 못함」 을 502 대신 200 · 빈 목록 + 안내 글로 준다**(DF-125 · #257). 해외 자동완성이 한글 검색어에 400 을 주던 것이 그대로 502 가 되고 있었다.

## 2. 막힌 것 · 알게 된 것

- 모의 장부는 다른 주담당 몫이다. 고치지 않고 장부의 체결 함수를 부르기만 했다. 그 함수가 체결 시각을 받아서, 「그 정규장 시작 · 그 시가」 를 정직하게 남길 수 있었다.
- 일봉의 시각은 두 꼴이었다 — 해외 시세는 그날 09:30(뉴욕), 수집 DB 는 그날 00:00(UTC). 둘 다 **UTC 날짜**로 맞추면 그날이 된다.
- 손 시험에서 확인 상자 안의 두 숫자가 1원 어긋났다. 카드는 원화 환산을 반올림(1,835원)했고, 체결 단가는 원 단위로 버렸다(1,834원). 확인 상자는 서버 미리 보기의 단가를 쓰게 고쳤다.
- 손 시험 스크립트가 「대기 예약 1건이 남았다」 고 셌다. 기다림 조건이 지난 실행의 「취소함」 줄에 바로 걸린 탓이었다. API 로 실제 상태를 보니 둘 다 취소돼 있었다.
- 깨 보기 목록을 짜다가, 시험이 못 잡을 깨기 둘을 찾았다 — 모르는 원화 값을 0원으로 메우기, 예상 금액 줄에 다른 값 넣기. 다른 칸의 같은 글자 때문에 우연히 통과할 시험이었다. 깨기 전에 시험부터 고쳤다.
- 미국 휴장일은 NYSE 공지 원문으로 확인했다. 크리스마스 줄만 검색 발췌에서 잘려 NYSE 관례로 채웠다(확실도 중간). 표에 없는 해는 판정하지 않는다.

## 3. 원칙으로 다시 보기

- **SSoT** — 장 상태 · 예약 규칙은 서버 한 곳(`us_reserve.py`)이 정한다. 화면은 서버 글을 그대로 보이고, 확인 상자의 원화 단가는 체결과 같은 셈(미리 보기)을 쓴다.
- **말없는 fallback 금지** — 시가를 못 받으면 기다리고 다른 날 값으로 메우지 않는다. 장 상태를 모르면 「닫힘」 으로 짐작하지 않는다. 해외 400 은 「찾지 못함」 이지만 연결 끊김 · 5xx 는 502 그대로다.
- **멱등** — 예약 체결 값은 「그 정규장의 시가」 라 언제 읽어도 같다. 대기 줄만 잠그고 처리해 두 번 체결하지 않는다.
- **SRP · 경계** — 모의 장부 · 비용은 손대지 않고 새 모듈 · 새 라우트 파일로 얹었다.
