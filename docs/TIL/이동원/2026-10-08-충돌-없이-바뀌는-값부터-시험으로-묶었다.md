## 1. 무엇을 했나

- **강사님 lumina-invest `9478811` → `e815be3`(23커밋 · 53파일)의 서버 쪽을 3-way 로 받았다.** 충돌은 18파일 60곳이었고 그중 서버 14곳을 풀었다. 충돌 없이 합쳐진 11파일 · 우리가 고친 적 없어 강사님 판 그대로인 6파일 · 새 파일 14(앱 6 · 시험 8)를 함께 받았다. 화면 쪽 32곳(`app.html` 10 · `robo.js` 6 등)은 Figma 결정 뒤로, 리밸런싱 19곳(서비스 9 · 라우트 5 · 화면 5)은 담당 팀원 이슈로 남겼다.
- **충돌 표시 없이 들어오는 값을 먼저 시험으로 묶었다.** 지킴이 TC-BM +11 · 실거래 관문 TC-LT +2 · 벡터 저장 TC-VS +1 을 반영 전에 쓰고, 반영 전 코드에서 8건이 실패하는 것을 본 뒤 합쳤다. 합친 뒤에는 저장소 밖 사본에 강사님 판을 한 곳씩 넣어 열세 곳 모두 시험이 잡는 것을 확인했다.
- **판단이 갈린 넷은 사용자가 골랐다.** 채팅 모델은 우리 값 · 답 길이는 재 보고 정함 / RAG 저장 · 검색은 우리 판(실패를 숨기지 않음)에 강사님 읽기 호환 클래스만 / 「rag」 모드는 서버를 받고 화면 이름만 「검색 결과 요약」 / 다른 주담당 몫 운용 값 넷(자동매매 주기 · 유니버스 · 원클릭 금액 · 정합성 요약)은 받지 않음. 그리고 compose 의 컨테이너 Ollama 기본 모델은 1.5b 그대로 두었다(아래).
- **답 길이 256토큰을 표본 3문항으로 쟀다.** 답 노드와 같은 프롬프트로 자연 길이가 454 · 684 · 579토큰이었고, 256 에서는 셋 다 문장 중간에 끊기며 끝 고지가 사라졌다. 사용자 결정으로 설정 두 칸(`LLM_ANSWER_NUM_PREDICT` 1024 · `LLM_NUM_CTX` 0)에 값을 두었다.
- **점검 계정에 KIS 모의 키를 넣는 스크립트와 점검 KIS 묶음을 더했다.** `.env` 의 모의 칸을 앱의 사용자별 키 저장 길로 넣고 「넣음 · 확인됨」 만 출력한다. 점검은 연동 상태 · 원클릭 준비 상태 · 모의 잔고 셋이고, 증권사는 잔고 1회만 부른다(평가 10,000,000원 · 보유 0).

## 2. 막힌 것 · 알게 된 것

- **충돌은 우리가 고친 줄에서만 난다.** 운용 값 넷 · 에이전트 답 길이 · 메뉴 둘 삭제는 우리가 손대지 않은 줄이라 충돌 표시 없이 강사님 값이 된다. 「충돌 0」 은 「바뀐 것 0」 이 아니었다 — 그래서 값을 지키는 시험을 반영보다 먼저 썼다.
- **같은 결함을 둘이 따로 고쳤다.** LangChain 에 비동기 Qdrant 클라이언트를 넘겨 저장 · 검색이 늘 0건이던 결함(DF-38)을 우리는 10-02 에, 강사님은 10-07 에 다른 방식(직접 호출 · 실패하면 조용히 0)으로 고쳤다. 읽기는 서로 호환돼 저장 · 검색은 우리 판을 두었다.
- **256토큰은 빨랐지만 고지를 잘랐다.** 36 ~ 38초로 옛 값의 절반이었다. 그런데 답 프롬프트가 마지막 줄에 「투자 권유 아님」 을 요구하니 출력 상한이 정확히 그 줄을 지운다. 속도와 내용을 맞바꾼 결과는 표본을 재기 전에는 보이지 않았다.
- **야후 지킴이가 강사님 새 코드를 잡았다.** 전체 시험 첫 회에서 야후 언급 기준선(#61 P1-1)이 다섯 파일에서 늘었다. 새로 야후를 부르는 줄은 없고 KIS ↔ 야후 폴백 설정 이름 · 설명 · 로그여서, 09-30 선례대로 받은 코드의 봉인을 열고 까닭을 적었다.
- **우리 KIS 클라이언트는 접근 토큰을 요청마다 새로 받는다.** 증권사는 토큰 발급을 1분에 1회로 묶는다(EGW00133 — 2차 출처 둘). 같은 사용자가 1분 안에 잔고와 시세를 이어 부르면 둘째가 막힐 수 있어, 점검은 증권사 호출을 한 번으로 줄이고 결함 DF-84 로 적었다.
- **강사님 compose 의 새 기본 모델은 연구용 라이선스였다.** `qwen2.5:3b` 의 모델 카드 LICENSE 원문은 Qwen RESEARCH LICENSE AGREEMENT(2024-09-19) — 「FOR NON-COMMERCIAL PURPOSES ONLY」, 비상업은 「research or evaluation purposes only」 다. `.env` 를 비운 팀원의 도커가 이 값을 받으므로 기본값은 Apache-2.0 인 1.5b 로 두고 지킴이 한 줄을 더했다. 같은 계열 모델이라도 크기마다 라이선스가 다를 수 있었다.
- **옛 말은 선택 칸 · 꼬리표 말고 입력 칸 안내 글에도 남아 있었다.** 「rag」 를 골랐을 때 안내 글이 「유사한 청크를 LLM 없이 그대로 보여줍니다」 였다 — 강사님 판도 이 줄은 고치지 않았다. 시험 · 코드 검색이 아니라 브라우저에서 그 엔진을 골라 보고서야 보였고, 지킴이가 안내 글까지 보게 넓혔다.
- **응답 본문 하나가 계좌번호를 품고 있었다.** 증권사 설정 조회 응답에는 계좌번호가 그대로 들어 있어, 점검의 `-ShowBody` 가 그 응답을 찍지 않게 `NoBody` 표시를 더했다. 넣기가 실패해도 서버 오류 본문을 찍지 않는다 — 입력 검사 오류(422)에는 보낸 값이 되돌아올 수 있다.

## 3. 원칙으로 다시 보기

- **말없는 fallback 금지** — 저장 실패를 0 으로 삼키는 판 대신 `VectorStoreError`(503 · 이유)를 지켰다. TC-VS-03 이 되돌림을 막는다.
- **SSoT** — 답 길이를 세 파일에 박힌 256 대신 설정 한 곳에 두었다. 다음 반영 때 갈리는 곳이 함수 호출 세 줄로 줄었다.
- **이름은 지키고 값만** — 운용 값 넷은 강사님 설정 이름을 받고 기본값만 우리 것으로 두어, 그 이름을 읽는 헬스 · 빠른 시작 · 모니터 · 예약 파일을 고치지 않았다(설정 파일 한 곳 · 지킴이 넷).
- **멱등성** — 연동 스크립트와 대장 편집 스크립트는 두 번 돌려도 결과가 같다(대장 8줄 → 둘째 실행 0줄).
