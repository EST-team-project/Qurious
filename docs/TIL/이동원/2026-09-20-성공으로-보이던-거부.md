## 2. 왜 했나

S34 에서 매매비용 요율표를 만들었다([앞 장](2026-09-20-비용-가정이-화면마다-달랐다.md) ·
`app/services/trading_cost.py`). 수수료·거래세·농어촌특별세·유관기관수수료를 세목별로 계산한다.
그런데 **그 값이 맞는지는 한 번도 확인한 적이 없었다.** 모든 주문의 `cost_basis` 가 `estimated` 였다.

`cost_basis` 는 "이 주문의 비용이 **어디서 온 값인지**" 를 적는 칸이다.
`none`(안 뗌) · `estimated`(우리 요율표) · `broker`(증권사와 대조해 통과) 셋 중 하나인데,
지금까지 `broker` 는 한 건도 없었다.

그런데 작업을 시작하고 나서 **더 근본적인 문제**를 발견했다. 실전 주문 경로가
`orders` 테이블에 아무것도 남기지 않고 있었다.

| 경로 | 증권사에 주문 | `orders` 기록 |
|---|---|---|
| 직접매매 화면 → 증권사 ([`stocks.py:639`](https://github.com/devlee328288/Qurious/blob/2b22703/app/routes/stocks.py#L639)) | ○ | ✗ **없음** |
| 자동매매 → 증권사 ([`auto_trade.py:185`](https://github.com/devlee328288/Qurious/blob/2b22703/app/services/auto_trade.py#L185)) | ○ | ✗ **없음** |
| 직접매매 화면 (가상, [`stocks.py:290`](https://github.com/devlee328288/Qurious/blob/2b22703/app/routes/stocks.py#L290)) | ✗ | ○ |
| 모의투자 화면 (가상, [`paper_trading.py:221`](https://github.com/devlee328288/Qurious/blob/2b22703/app/services/paper_trading.py#L221)) | ✗ | ○ |

**가상 주문만 기록되고 진짜 주문은 기록되지 않았다.** 나는 이 표를 그리기 전까지
"주문 기록은 당연히 있고 비용 칸만 비어 있다" 고 생각하고 있었다. 정반대였다.
그래서 체결 조회는 검증용 보조 기능이 아니라 **실거래의 유일한 기록 경로**가 됐다.

## 3. 어떻게 했나 — 고른 것과 버린 것

### 3.1 대조에 쓸 값을 찾기

강사님 `th03-stock-coin-trade` 에 새로 들어온 `kis_api_catalog.json` 을 읽었다
(KIS 공식 저장소에서 생성된 것이라 1차 출처에 가깝다. 읽기만 하고 작업본에 merge 하지
않았다). 여기서 얻은 것이 이 PR 의 출발점이다.

| 확인 대상 | 그 전의 내 상태 | 카탈로그 확인 |
|---|---|---|
| 제비용을 주는가 | ❓ 모름 | 🟢 `prsm_tlex_smtl`(추정제비용합계)가 응답에 있다 |
| 체결조회 TR | ❓ 모름 | 🟢 `TTTC0081R`(3개월 이내) · `CTSC9215R`(3개월 이전) · 모의는 `VT…` |
| `EXCG_ID_DVSN_CD` | 🟡 "휴일 응답으로 보아 선택인 듯" | 🟢 **필수**였다 (이미 `KRX` 로 보내고 있었다) |

**TR ID**(Transaction ID)는 KIS 에서 "어떤 업무를 요청하는지" 를 가리키는 코드로,
HTTP 헤더에 넣는다. 놀란 점은 **같은 주소(`/inquire-daily-ccld`)인데 조회 기간에 따라
TR 이 갈린다**는 것이다. 3개월 이내와 그 이전이 다른 코드다. 하나만 알고 있었으면
과거 체결이 조용히 0건으로 나왔을 것이다.

다만 카탈로그의 **한글 라벨 일부가 필드명과 어긋나 있었다.** `prsm_tlex_smtl` 에
"총체결금액" 이, `pchs_avg_pric` 에 "추정제비용합계" 가 붙어 있다. 필드명
(`prsm` 추정 · `tlex` 제비용 · `smtl` 합계)이 자명하므로 **라벨이 아니라 필드명을
따랐고**, 대신 응답 원문을 `FillInfo.raw` 에 통째로 남겼다.

### 3.2 어긋났을 때 무엇을 믿을 것인가

가장 오래 고민한 지점이다. 증권사 합계와 우리 추정이 다를 때 `net_amount`(현금 증감)에
무엇을 쓸 것인가.

| 선택 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 증권사 합계를 쓴다 | 현금이 실제와 맞는다 | `net = 체결금액 ± 세목합` 불변식이 깨진다 → **어느 세목이 틀렸는지 영영 모른다** | ✗ |
| 우리 추정을 쓰고 차액을 보고 | 불변식이 지켜져 원인 추적 가능 | 그 행의 현금이 일시적으로 틀리다 | ✓ |

처음엔 당연히 증권사 값이 정답이니 그걸 쓰는 게 맞다고 생각했다. 그런데 KIS 가 주는
것은 **합계 한 칸뿐**이고 세목은 나뉘어 있지 않다. 합계만 덮어쓰면 "틀리긴 한데 수수료가
틀린 건지 세금이 틀린 건지" 를 알 수 없게 된다. 그래서 **틀린 값을 잠깐 두는 대신 틀린
이유를 알 수 있게** 했다 ([`fill_sync.py:166`](https://github.com/devlee328288/Qurious/blob/2b22703/app/services/fill_sync.py#L166)).
요율표를 고치고 다시 동기화하면 그때 `broker` 로 바뀐다.

허용 오차는 **1원**으로 좁게 잡았다. 증권사가 세목마다 원 단위 절사를 한다면 최대 4원까지
벌어질 수 있다는 걸 알지만, 이 모듈의 목적은 "맞다고 넘기는 것" 이 아니라 "맞는지 보는 것" 이다.

### 3.3 작지만 되돌아본 판단 둘

- **`total_fees` 를 `None` 으로 둘 수 있게 했다.** 0.0 은 "0원을 뗐다" 이고 `None` 은
  "알려주지 않았다" 이다. 처음엔 `0.0` 하나로 처리하려다, 그러면 제비용을 주지 않는
  증권사에서 "양쪽 다 0원이니 검증 통과" 라는 거짓 🟢 가 나온다는 걸 깨달았다.
- **미구현 증권사는 빈 리스트가 아니라 `NotImplementedError` 를 던진다.** 같은 이유로,
  빈 리스트는 "체결 없음" 과 "조회 불가" 를 섞는다. 8곳 중 KIS 만 실제 구현이다.

### 3.4 재사용 판정

비용 계산([`trading_cost.py:248`](https://github.com/devlee328288/Qurious/blob/2b22703/app/services/trading_cost.py#L248))
·시장 판별·`OrderCost` 는 **0줄 추가로 그대로 썼고**, TR·필드 스펙은 강사님 카탈로그를 봤다.
`BrokerClient` 는 메서드 1개 확장이고, 신규는 KIS 체결 조회·`fill_sync`·스크립트 2개뿐이다.
특히 `orders`·`order_fills` 스키마가 [#43](https://github.com/devlee328288/Qurious/pull/43) 에서 만든 것과 그대로 맞아떨어져
**마이그레이션이 한 줄도 없다.**

## 4. 어떻게 확인했나

### 4.1 DB 왕복 — 임시 Postgres 16 (`pgvector/pgvector:pg16`)

체결 5건(일치 1 · 불일치 1 · 제비용 미제공 1 · 취소 1 · 미체결 1)을 넣고 **두 번** 동기화했다.

```
[1회차] fetched 5 · created 3 · verified 1 · no_fee_info 1
        skipped_cancelled 1 · skipped_unfilled 1 · mismatch_count 1
        불일치: 0002 sell  증권사 2045.62 vs 우리 1545.62  (차 +500.00원 · +7.04bp)

[2회차] created=0  updated=3     ← 같은 체결을 다시 넣어도 행이 늘지 않는다
        orders 3행 · order_fills 3행

  세목합 검산 (net = 체결금액 ± 세목합) — 3건 모두 OK
    0002  710,000 − 1545.62 = 708,454.38  vs net 708,454.38
```

2회차를 돌린 이유는 중복 생성이 가장 무서웠기 때문이다. 증권사 주문번호로 찾아 갱신하므로
행이 늘지 않는 것을 눈으로 확인했다. 컨테이너는 끝나고 `stop` + `rm`.

## 5. 막힌 것 · 남은 것

### 5.1 잔고 조회가 계속 HTTP 500 이던 것

한참 헤맸다. 토큰도 나오고 현재가도 나오는데 잔고만 500 이었다. 원인은 계좌번호였다.

```
  KIS 는 계좌번호를 CANO(종합계좌번호 8자리) 와 ACNT_PRDT_CD(상품코드 2자리) 로 나눠 받는다

  .env: KIS_MOCK_ACCOUNT_NO=50201820   ← 8자리
              ├─ account_no[:8] → "50201820"   ✅
              └─ account_no[8:] → ""           ❌  → HTTP 500
```

코드가 `[:8]` · `[8:]` 로 자르고 있었는데 계좌번호가 8자리라 상품코드가 **빈 문자열**로
나갔다. 고쳐서 [`_split_account()`](https://github.com/devlee328288/Qurious/blob/2b22703/app/services/brokers/kis.py#L26)
가 `50201820-01` · `5020182001` · `50201820` 을 모두 받고, 없으면 `01`(종합위탁)을 채운다.

내가 여기서 시간을 쓴 이유는 **500 을 서버 문제로 읽었기 때문**이다. 보낸 값이 잘못됐으면
400 이 올 거라고 무심코 가정했다. 상대 서버의 상태코드 규약을 내가 정하지 않는다.

### 5.2 🔴 거부된 주문이 "성공" 으로 올라갔다 — 이 장에서 가장 값진 줄

일요일에 모의계좌로 주문을 내 봤더니 이런 응답이 왔다.

```json
{"rt_cd": "1", "msg_cd": "40100000", "msg1": "모의투자 영업일이 아닙니다."}
```

**그런데 HTTP 상태코드는 200 이었다.** 코드는 `raise_for_status()` 만 보고 있었으므로
이 응답을 성공으로 처리했다.

```
                  거부된 주문의 여정 (고치기 전)

  KIS ──[HTTP 200 + rt_cd=1]──▶ raise_for_status() 통과 ──▶ return r.json()
                                                                 │
   화면:  {"ok": true}   ◀──────────────────────────────────────┤
   알림:  "주문 완료"    ◀──────────────────────────────────────┘
                             ↑ 주문은 접수되지도 않았다
```

사용자에게 "주문 완료" 알림까지 나갔다. 더 나쁜 건 자동매매다. 이 응답을 받으면
**있지도 않은 체결을 전제로 다음 판단을 한다** — 보유하지 않은 종목을 보유한 셈 치고
비중을 계산한다.

고쳐서 모든 KIS 호출이 [`_check()`](https://github.com/devlee328288/Qurious/blob/2b22703/app/services/brokers/kis.py#L43)
를 지난다(현재가·잔고·주문·일봉·체결조회 5곳). 이제
`HTTPException(502, "증권사 API 주문 오류: KIS buy 주문 실패 [40100000] 모의투자 영업일이
아닙니다.")` 로 올라간다. 🟢 재현하고 수정 후 예외가 나오는 것까지 확인했다.

## 6. 배운 것

- **HTTP 200 은 "성공" 이 아니라 "말이 통했다" 다.** 업무 성공 여부는 본문에 따로 있을 수
  있고 `raise_for_status()` 는 전송 계층만 본다. 외부 API 를 붙일 때는 "실패를 어떻게
  표현하는가" 를 문서에서 먼저 찾는다.
- **조용한 성공이 조용한 실패보다 나쁘다.** 실패했으면 에러를 보고 고쳤을 텐데, 성공으로
  보이니 아무도 안 봤다. 그래서 이 PR 에서 두 번이나 같은 선택을 했다 — `total_fees` 를
  `None` 으로 두고, 미구현 증권사가 빈 리스트 대신 예외를 던지게 한 것.
- **"기록이 있다" 고 믿은 것이 가상 주문뿐이었다.** 네 경로를 표로 한 줄씩 세워 보기
  전까지는 몰랐다. 코드를 읽는 것과 **경로를 나열해 보는 것**은 다른 작업이다.
- **장치를 만든 것과 검증을 끝낸 것은 다르다.** 이번에 만든 건 저울이지 계량 결과가 아니다.

  오늘은 그 뒷면을 봤다 — **출처가 준 값의 라벨이 틀려 있을 수 있다.** 그래서 원문을 버리지 않는다.
