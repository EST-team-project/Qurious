## 1. 무엇을 했나

- **통합본 반입** — 강사님 요구 원문의 구현 방안 「domain-rag-lab 와 investment-analysis 의 통합」 을 받으려고, 팀장이 만들어 둔 통합본을 `rag-lab/` 로 들여왔다. 나는 「용어 자료만」 을 권했는데 팀장의 답은 **「AWS 만 빼고 전부 — 전체를 보고 나눠서 화면을 다시 설계해야 한다」** 였다. 314파일(57.6MB)을 복사하고, 외부에서 받은 시세 자료 3개는 팀 비공개 데이터셋에 두고, AWS 12개는 가져오지 않았다.
- **전체 확인 · 분리** — 스캐너로 통합본의 화면 73 · API 110 · 저장소 이름 12를 뽑고, 기능 묶음 19개로 나눠 경우(새 화면 · 합침 · 바꿈 · 참고 · 보류 · 제외)를 붙였다. 파일마다의 상태는 반입 대장에, 묶음마다의 판정은 이식 대장에 적었다.
- **용어사전의 서버 쪽** — 자료 넷(단어장 · 용어집과 한자 어원 사전 · 강의 사이트 용어 · 화면 용어 상수) 948항목을 같은 말끼리 합쳐 용어 755개로 만들었다. 원본은 git 의 용어 파일이고, 표 다섯은 그 사본이다. API 넷이 돌려준다.
- **문서** — 통합본 이식 계획서 · 용어사전 설계서 · 화면 설계 절차(제안)를 새로 쓰고, 판 문서마다 변경 노트를 남겼다.
- **화면은 하지 않았다.** 도중에 팀장이 「화면에 어디에 넣을지는 다음에 설계하자 — 이미 있는 화면에 더하면 되는 자리가 있을 수 있다」 고 방향을 잡았다.

## 2. 막힌 것 · 알게 된 것

- **옮겨 놓은 코드는 「구현된 것」 으로 읽힌다.** 저장소에 파이썬 60개가 생기자 요구 추적 스캐너는 아직 만들지 않은 요구(질의응답의 출처 · 퀴즈)에 코드 흔적이 있다고 세려 했다. 넷으로 막았다 — 도커 빌드에서 빼고, 흔적에서 빼고, 폴더가 대장과 같은지 시험이 보고, 폴더 첫 파일이 「앱과 이어져 있지 않다」 를 알린다. 글로 「읽기용입니다」 라고 적는 것보다 **대장의 상태 칸과 검사**가 낫다.
- **이름이 같다고 같은 말이 아니다.** 「내재가치」 는 용어집에서 기업의 적정 가격이고 강의에서는 옵션의 내재가치다. 뜻 한 줄과 자세한 뜻을 서로 다른 자료에서 가져오면 앞뒤가 안 맞는 풀이가 된다 → 둘은 **같은 자료에서만** 가져오고, 나머지는 자료 이름을 붙여 따로 남겼다. 그래도 놓친 것이 있었다 — 강의 제목 `신용위험(CDS)` 에서 괄호를 떼자 「신용위험」 의 뜻 한 줄이 CDS 계약의 풀이가 됐다.
- **이름 옆의 말이 이름이 아니다.** 강의 용어의 곁말이 사람 소개(「Ray Dalio · 투자자 · 브리지워터 창립자」)라서, 「투자자」 로 찾으면 레이 달리오가 나왔다. 「소재·부품·장비」 는 셋으로 나뉘어 「장비」 로 찾으면 소부장이 나왔다. 자동으로는 가릴 수 없어 사람이 적는 표를 두었고, 그 줄이 자료에 없는 이름을 가리키면 빌드가 멈추게 했다 — 규칙이 말없이 꺼지면 고친 것이 되돌아온다.
- **시험이 다 통과한 뒤에 나온 결함들이다.** 위 둘과 짧은 영문 검색의 잡음(`per` 에 「동산」 「법인」 「부동산」 — property · person 의 per)은 시험 44건이 모두 통과한 상태에서, 실제 자료를 표로 늘어놓고 눈으로 훑다가 찾았다. 시험은 내가 떠올린 경우만 본다. **자료를 다루는 코드는 결과 자료를 직접 읽어야 한다.**
- **「바뀌었나」 를 무엇으로 재나.** 처음에는 용어 파일의 체크섬이 같으면 적재를 건너뛰었다. 그런데 검색용 칸은 파일에 없고 적재할 때 만든다 — 그 규칙만 고치면 파일은 그대로라 표가 옛 값으로 남는다. 실제로 그렇게 될 뻔했다. 판 번호를 손으로 올리게 하는 대신 **넣을 행 자체의 체크섬**을 견주게 바꿨다. 기억에 기대는 장치는 잊힌다.
- **같은 이름의 파일이 다른 폴더에 생기자 드러난 결함.** `start.ps1` 이 매번 이미지를 다시 만들었다. 신선도 판정이 파일 경로에 재귀 옵션을 주어 저장소 전체에서 `requirements.txt` 를 찾고 있었고, `rag-lab/` 의 것이 이미지보다 새로웠다. 폴더가 하나뿐일 때는 맞게 돌던 코드였다.
- **내가 더한 파일이 스캐너를 속였다.** 용어 빌드 스크립트의 분류표(`"rsi": "technical"` …)가 코드 줄이라, 요구 20개의 코드 흔적이 한 파일씩 늘었다. 이름을 자료로 들고 있는 파일은 「이 요구의 흔적으로만 센다」 고 적는 칸을 스캐너에 두었다.
- **실무 권고와 다르게 간 곳은 적어 둔다.** 참조 데이터를 앱 시작 길에서 넣는 것은 권고(여러 인스턴스가 함께 돌 때의 동시성)와 다르다. 잠금과 한 트랜잭션으로 막았고, 배포 구성이 바뀌면 옮긴다고 「뒤집을 조건」 에 적었다. 따르지 않은 권고를 숨기면 다음 사람이 같은 글을 읽고 같은 고민을 한다.
