## 1. 무엇을 했나

- 자동매매 체결이 현금을 `quant_virtual_accounts`(1천만 원) 대신 **`paper_accounts`(1억 원)** 에서 빼게 했다. 수동 모의주문이 쓰던 `paper_trading.get_account(lock=True)` 를 그대로 불렀다.
- 직접매매 화면의 **가상 매도**가 보유보다 많으면 400 으로 거절하게 했다.
- 실제 Postgres 로 도는 회귀 시험 6건 + 정적 가드 1건을 더했다.

## 2. 왜 했나

- S52 브라우저 확인에서 자동매매 3건 뒤 모의투자 화면이 **+3.19%** 를 보여 줬다. 현금은 1억 그대로인데 산 주식 평가액만 더해졌다.
- 모의투자 칸(10-14) 뒤로는 이 화면의 숫자가 일지에 쌓인다. 틀린 채로 쌓으면 「이 규칙을 믿어도 되나」의 답이 틀린다.

## 3. 어떻게 했나 — 고른 것과 버린 것

- **현금을 합쳤다. 보유 표를 쪼개지 않았다.** 처음엔 「표가 둘이라 문제」로 읽었는데, 보유는 이미 한 표(`portfolio`)였다. 문제는 **현금과 보유가 서로 다른 장부를 본다**는 것이었다. 보유를 장부별로 쪼개는 안(대안 B)은 화면·주문 경로 세 곳을 다 고쳐야 하고, D7 ③ 추천안(C1 · `paper_accounts` 하나)과도 반대다.
- **새 함수를 만들지 않았다.** 자동매매 전용 「계좌 조회 + 잠금」을 따로 쓰면 수동 주문과 잠금 방식이 어긋날 수 있다. 같은 함수를 부르는 것이 「같은 행을 같은 방식으로 잠근다」의 가장 짧은 증명이었다.
- `quant_virtual_accounts` 표는 **지우지 않았다.** 마이그레이션이 필요하고, D7 원장(봉인 기록 장부) 설계가 아직이다.
- 이미 틀어진 DB 를 **자동으로 고치지 않았다.** 자동매매 주문(`source=QUANT`)을 모아 현금을 역산할 수는 있지만, 모의투자 화면에 「초기화」가 이미 있다.

## 4. 어떻게 확인했나

- **옛 코드로 같은 거래를 했다.** `git show db00327:app/services/auto_trade.py` 로 꺼내 같은 빈 DB 에서 같은 매수 3건(590,000원어치) → 옛 코드 총 손익 **+590,000**, 고친 코드 **−104**(거래비용). 시험이 초록이라는 것만으로는 그 시험이 버그를 잡는지 모른다.
- 시험의 불변식은 하나다 — **체결가로 평가한 총자산 = 초기 현금 − 거래비용.** 화면이 쓰는 식(`account_snapshot`)을 그대로 따라 셌다.
- SQLite 가 아니라 도커 `pgvector/pgvector:pg16`(보유 이미지)으로 돌렸다. SQLite 는 `FOR UPDATE` 를 무시한다. 끝나고 컨테이너를 지웠다.
- 시험 수: 일일 갱신(#23) 머지 뒤 main 기준 DB 있음 51 통과 · 없음 45 통과 + 6 건너뜀(이 PR 이 더한 것은 7건).

## 5. 막힌 것 · 남은 것

- 초기화 시험이 `crypto_holdings does not exist` 로 한 번 실패했다. `reset_account` 가 코인·대체자산 표까지 지워서, 시험 준비에 네 표가 더 필요했다. 코드가 아니라 시험 준비의 누락이었다.
- **옛 분석(`#12` A9)이 적은 구멍이 아직 살아 있었다** — 「`/api/orders` 는 보유 없이 매도해도 현금이 는다」. 9월 15일에 찾고 13일 동안 아무도 안 고쳤다. 보유 0주에서 10주를 팔면 현금 +698,476원. 같은 불변식이라 이번에 막았다.
- 남은 것: 보유 직접 편집(`POST /api/portfolio`)이 현금 없이 보유를 만든다 · 자동매매가 모듈 전역 한 벌 · 기록 색인·TIL 목록의 #19·#23·#24·이 PR 줄(다음 PR 에서 한 번에).

## 6. 배운 것

- **「같은 표를 쓴다」와 「같은 장부다」는 다르다.** 보유는 같은 표였고, 그래서 오히려 안 맞는 것이 가려졌다. 장부가 맞는지는 표 개수가 아니라 **한 계좌의 현금과 보유가 같은 기록에서 오는가**로 본다.
- **분석 이슈에 적힌 결함은 고칠 때까지 살아 있다.** 찾은 날 작업 이슈로 떼지 않으면, 분석 문서 속 한 줄로 남아 잊힌다.
