## 2. 왜 했나

커스텀 인디케이터 화면은 `cost_bps` 를 아예 보내지 않아 비용이 0 이었고, 성과 검증
화면은 왕복 대칭 10bp 였다. 같은 엔드포인트인데 답이 달랐다.

더 나쁜 것은 화면 문구였다. 커스텀 화면에도 *"매매비용 왕복 기준 10bp를 반영했으며"* 라고
**고정 문자열**로 박혀 있었다([`public/app.html:3533`](https://github.com/devlee328288/Qurious/blob/b157708/public/app.html#L3533)).
비용이 0인데 반영했다고 적혀 있으니, 쓰는 사람은 반영됐다고 믿는다. 숫자가 틀린 것보다
이쪽이 더 나쁘다고 봤다.

| 시행일 | 코스피 거래세 | 농특세 | 코스피 합계 | 코스닥 합계 |

| ~2019-06-02 | 0.15% | 0.15% | 0.30% 🟡 | 0.30% 🟡 |

| 2024-01-01 | 0.03% | 0.15% | **0.18%** | **0.18%** |

2025년 구간에 0.20% 를 쓰면 매도 비용을 **33% 과대계상**한다. 연도를 하나 골라
상수로 두는 길은 처음부터 없었다.

### 비대칭이라는 것도 이번에 몸으로 알았다

```

 매도    0.0140527% + 0.0036396% +  0.05% +  0.15% +  0.10%  = 0.3177%
                                                       왕복  = 0.4354%
```

매도가 매수의 2.7배다. "사고팔 때 똑같이 얼마"라는 가정은 절반이 틀린 게 아니라
**구조가 틀렸다.**

## 4. 어떻게 확인했나

### (1) KIS 신 TR 이 실제로 라우팅되는가 — 대조군을 넣었다 🟢

일요일이라 체결은 불가능하다. 그래서 "체결"이 아니라 "어느 층까지 가는가"를 봤다.
모의계좌로 7건을 실제 호출했다.

| 호출 | HTTP | 코드 | 읽는 법 |
|---|---:|---|---|
| 신 매수 `VTTC0012U` | 200 | `40100000` | 업무단계 도달 🟢 |
| 신 매도 `VTTC0011U` | 200 | `40100000` | 업무단계 도달 🟢 |
| 구 매수/매도 | 200 | `40100000` | 오늘은 아직 산다 (대조군) |
| **없는 TR `VTTC9999U`** | **500** | **`IGW00009`** | 게이트웨이가 먼저 자른다 |

```
   요청 ──▶ [게이트웨이] ──▶ [주문 업무] ──▶ [체결]
              IGW00009        40100000       (휴일이라 도달 못함)
                 ▲               ▲
                 │               └─ 신·구 TR 6건이 모두 여기까지 왔다
                 └─ 없는 TR 만 여기서 잘렸다
```

이 표의 값은 마지막 줄에 있다. 대조군이 없었으면 "200 이 왔으니 된 것"이라고 적었을
텐데, 그건 근거가 아니다. **무효한 값이 실제로 잘리는 것을 보여야** 통과가 뜻을 갖는다.

### (2) 요율표가 #40 의 실측을 재현하는가 🟢

300종목 5/20 이동평균 교차 롱온리, TR(총수익) 계열 기준. 수익률 중앙값:

```
무비용        ████████████████████████████  27.75%
예전 flat     ████████████████▏             16.15%
실제 비용     █████████████▊                13.82%
+슬립 10bp    ██▌                            2.50%
+슬립 20bp   ▊                              -7.47%   ← 중앙값이 음수
```

손실 종목이 111개 → 165개, 무비용에서 이익이던 189종목 중 **54개의 결론이 뒤집힌다.**
삼성전자 한 종목에서도 커스텀 `volume_rsi` 가 무비용 +3.42% → 실제 −5.41% 로 뒤집혔다.

#40 의 S33 실측과 대조하면 중앙값은 0.3~0.6%p 낮은데, **손실 종목 수·뒤집힘 수·이익
종목 수는 정확히 같다.** 표본 선정 규칙이 같은지 확인할 수 없었다 — S33 은 일회용
스크립트로 계산해 남아 있지 않았기 때문이다. 그래서 이번엔 계산을
`scripts/verify_trading_cost.py` 로 **파일에 남겼다.**

### (3) 스키마 — 임시 Postgres 로 실제로 돌렸다 🟢

```
    0001 ──▶ 0002 ──▶ 0003     orders 11칸 ──▶ 23칸 · order_fills 생성
                        │
                        ├─ 기존 행 2건 이행: price → order_price · avg_fill_price
                        │                    cost_basis = "none"  ← 비용을 뗀 적 없음이 남는다
                        └─ downgrade ──▶ 0002 ──▶ 다시 upgrade ──▶ 0003  🟢 왕복 성공
```

`alembic check`(모델 선언과 실제 DB 스키마를 대조하는 명령)에서 `orders`·`order_fills`
차이 **0건**. 부분체결 2건 삽입 · `(order_id, seq)` 중복 거부 · 주문 삭제 시 CASCADE 도
확인했다. 보유 이미지 `pgvector/pgvector:pg16` 을 쓰고 작업 뒤 `stop`+`rm` 했다.

### (4) 덤으로 찾은 버그 🔴 — 자동매매가 잔고를 넘길 수 있었다

```python
max_qty = int(cash_balance // price)   # 수수료를 빼먹는다
```

| 가용현금 | 단가 | 예전 | 그 정산금액 | 판정 |

## 6. 배운 것

- **`None` 을 두 뜻으로 쓰면 언젠가 물린다.** `build("none")` 이 `None` 을 돌려주자
  호출부가 그걸 "인자를 안 넘겼다"로 읽고 기본 비용 모델로 되돌렸다. 그래서
  `cost_model=none` 이 `flat` 과 **같은 값**을 냈다. "없다고 정했다"는 객체로 말해야
  한다 → `NoCostModel`(`app/services/trading_cost.py:456`).
- **쌓아 올린 PR 은 base 가 `main` 이 아닌 것부터 머지한다.** 사슬의 위쪽을 먼저
  제자리에 넣어야 밑동이 그것을 안고 `main` 으로 간다. PR 번호 순서는 아무 의미가
  없다. 다음부터는 머지 순서를 PR 본문 맨 위에 번호로 적는다.
- **틀린 숫자보다 틀린 설명이 나쁘다.** 비용 0 인 화면에 "10bp 반영"이라고 고정 문구가
  박혀 있었다. 이제 응답이 `cost.model` 과 라벨을 함께 실어 보내, 무비용이면 화면에
  "비용 미반영 — 실제 성과보다 낙관적이다"라고 스스로 밝힌다. **설명을 데이터에서
  만들면 거짓말을 할 수 없다.**
- **통과는 대조군이 있어야 뜻을 갖는다.** 없는 TR 이 500 으로 잘리는 것을 같이 보지
  않았다면, 200 응답은 아무것도 증명하지 못했다.
- **검증 계산은 스크립트로 남긴다.** #40 의 실측을 재현하려는데 그 스크립트가 없어서
  0.3~0.6%p 차이의 원인을 끝내 못 밝혔다. 일회용으로 계산한 숫자는 나중에 방어할 수 없다.
