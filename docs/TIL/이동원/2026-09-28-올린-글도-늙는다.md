  글 폴더마다 `01-2026-09-28-갱신.md` — 올린 글은 그 아래에, 안 올린 글은 본문 바로 뒤에 붙인다.

## 2. 왜 했나

- 사용자: *"기존에 있던 것을 최신으로 업데이트해서 부정확한 정보가 팀원에게 전달되지 않도록 … 이전 1차 프로젝트의 한계점이었음."*
- 옛 글은 09-15~09-23 에 쓴 그대로 새 저장소에 한 건씩 다시 올라가고 있었다. 그 사이 **2차 시작일(09-27 → 10-01)** · 백테스트의 데이터(야후 → 수집 DB) ·
  CI(넣었다가 걷어냄) · 모의투자 장부(둘 → 하나)가 바뀌었다. 특히 D0~D7 논의는 **09-30 이 의견 기한**이라, 팀원이 옛 전제로 표를 던질 수 있었다.
- 같은 날 rag-lab 작업에서 HF org 를 조회하다 **데이터셋 10개 중 6개가 public** 인 것을 봤다(사용자가 바로 전부 private 으로 바꿨다).
  한 사람이 바로잡아도 다음 사람이 기본값(public)으로 또 만들 수 있다 — 그래서 팀 규칙으로 올린다.

## 3. 어떻게 했나 — 고른 것과 버린 것

- **고른 것 — 본문을 고치지 않고 댓글 파일을 더한다.** 옛 기록(`00-기록.md`)은 그날의 사실이다. 바뀐 것은 「원문 · 지금 · 근거」 3칸 표로 옆에 둔다.
  결론이 통째로 바뀐 3건(옛 `#1` 인덱스 · D3 · 옛 `#62` 분배안)만 **새 판 예고**.
- **고른 것 — 긴 원문은 에이전트 한 개씩, 숫자는 내가 다시.** 17건만 약 60만 자다. 에이전트 둘을 **차례로**(동시에 아님) 돌리고, 결과의 숫자 여덟 개를 원문과 다시 대조했다.
  둘이 틀렸다 — 옛 `#5` 의 「446만 행」(옛 값 · 지금 447만) · 옛 `#29` 의 정정이 팀원 글을 지적하는 것처럼 읽힘(실제로는 내 답글).
- **고른 것 — 닫힌 이슈 7건은 다시 올리지 않는 안.** 끝난 작업이고 기록 파일이 남는다. 옛 `#49`(계획서 v1.0)를 다시 올리면 「09-27 시작」이 다시 퍼진다.
- 버린 것 ① **옛 판 · TIL 본문의 링크 148곳까지 고치기** — 그날의 기록이다. 링크만 깨진 채 두고, 같은 변환기로 언제든 고칠 수 있다고 적었다.
- 버린 것 ② **올리는 순서를 「하루에 다」** — 09-23 에 26분에 약 20건을 올린 직후 flagged 됐다. 하루 5건 · 10분 간격 · 기한이 걸린 D0~D7 부터.
- 버린 것 ③ **D3 · D1 ③ 을 내가 다시 묻기** — 투표 범위를 바꾸는 일이다. 제안으로 적고 사용자가 정한다(대장 1.1 · 2.3).

## 5. 막힌 것 · 남은 것

- **새 번호를 모른다.** 사용자가 웹에서 올린 17건의 새 번호가 색인에 없다 — 받으면 README 3절 · 옛 `#1` 인덱스 v2 에 채운다. v2 는 그 번호가 있어야 쓴다.
- 사용자가 정할 것 9건(대장 1.1 · 2.3) — 특히 **2026 매도세 재대조**(코드 0.20% vs 법령 DB 0.15%)는 D4 · D7 초안의 기준이라 주인이 필요하다.
- 올리기 — 이 PR 이 머지돼야 댓글의 `main` 링크가 열린다.

## 6. 배운 것

- **글은 올린 뒤에도 늙는다.** 코드는 시험이 낡음을 알려 주지만, 글은 아무도 알려 주지 않는다. 그래서 세션 끝 확인에 ⑥ 「바뀐 사실이 적힌 올린 글」을 더했다.
- **옮긴 기록은 링크부터 죽는다.** 저장소를 옮긴 지 닷새, 지금 판 문서 5개에 28곳 · 전체 176곳이 404 였다. 내용이 맞아도 근거를 못 열면 팀원에게는 틀린 것과 같다.
- **기본값이 public 인 도구에서는 「한 번 확인」이 규칙이 되지 못한다.** 만들 때 지정하고, 올리기 직전에 기계가 다시 본다 — 수집기가 이미 그렇게 하고 있었다.
