## 2. 올리는 규칙과 명령

1. **글 하나 = 폴더 하나**, 그 폴더는 원 작성일 폴더 안에 둔다 — `YYYY-MM-DD/종류-이름/`.
2. 폴더 안 파일은 **올리는 순서대로 번호**를 붙인다 — 0절 표 참조.
3. **파일 하나 = GitHub 글 하나.** GitHub 는 이슈·댓글·PR 본문이 **65,536자**를 넘으면 거절한다.
   올리기 전에 `python scripts/post_check.py` — 60,000자부터 경고, 넘으면 실패. 넘으면 본문·댓글로 나눠 올린다.
4. **링크는 절대 주소로** (`https://github.com/EST-team-project/Qurious/blob/main/…`). 상대 경로는 GitHub 글 안에서 깨진다.
   `@멘션`은 백틱으로 감싸 두고 알림이 필요한 사람만 올리는 사람이 직접 붙인다. 옛 번호는 백틱(`` `#28` ``) — 새 저장소 번호와 겹친다.
5. **올리는 사람은 이동원이다.** AI 도구는 파일만 쓰고 GitHub 에 접속하지 않는다(개인 전역 규칙 10절 · 2026-09-28).
   **이슈 · 논의 · 거기 다는 댓글은 웹에서** 파일 내용을 붙여 넣어 올린다(S52 · 2026-09-28). git bash 로는 커밋 · push · PR 만 한다.
   한 번에 한 건, 결과를 보고 다음 건. ⚠️ **옛 글을 다시 올릴 때는 하루에 몇 건만** — 09-23 에 flag 된 계정의 글을
   26분에 약 20건 다시 올린 직후 계정이 flagged 됐다(원인 추정). 긴 글은 **쉬운 요약 + 이 폴더의 기록 파일 링크**로 올리는 편이 안전하다.

```bash
cd /c/Users/kik32/workspace/EST-Camp-AI-Quant/team_project/Qurious
python scripts/post_check.py                                   # 길이·링크·멘션 검사 (새 글 전부 + 한도 넘는 옛 글) + 색인 없는 글 폴더
T=$(gh auth token --user dev-dongwon05253); [ -n "$T" ] && echo "토큰 OK" || echo "토큰 없음 — 여기서 멈춤"

# 이슈 · 논의 · 댓글은 웹에서 (S52~) — 파일 내용을 붙여 넣고, 새 번호를 3절 색인에 적는다

# PR 만들기 (브랜치를 push 한 뒤)
GH_TOKEN=$T gh pr create --repo EST-team-project/Qurious --base main --head <브랜치> --title "제목" \
  --body-file docs/github-archive/<날짜>/<글 폴더>/00-본문.md
```

- 이슈 · 논의 · 댓글은 **웹에서** 파일 내용을 그대로 붙여 넣는다 — 원본과 GitHub 글이 같아진다(S52 부터 명령으로 올리지 않는다).
- 새 번호가 생기면 Claude 에게 알려 주면 파일에 직접 채운다 — **`sed` 자리 채우기는 쓰지 않는다**(S51 PR #16 이 `#번호` 글자 그대로 머지됐다).
