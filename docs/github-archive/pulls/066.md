## 작업 1 · 실거래 주문 경로 차단 ([#61](../issues/061.md) P0-1)

`docs/rfp-2.md` §4.2 제외 범위 첫 줄이 **"실제 증권 계좌를 통한 실거래 자동 주문 실행"**이다.
그런데 코드에는 실주문 경로가 **셋** 있었다. 세션 지시는 한 곳(`auto_trade.py`)을 지목했지만,
고치기 전에 같은 모양의 다른 곳을 훑어서 나머지 둘을 찾았다.

| # | 경로 | 어떻게 실계좌로 갔나 | 차단 장치 |
|---|------|---------------------|-----------|
| 1 | `auto_trade.py:183` 자동매매 | `paper=False` 를 **코드에 박아** 넘김 | `quant_mode != "live"` 한 줄 |
| 2 | `stocks.py:639` **수동 주문 API** | DB 칸 `broker_settings.paper` 를 **그대로** 넘김 | 없음 |
| 3 | `ebest.py` LS증권 | `paper` 인자를 **아예 받지 않음** | 플래그로 **막을 수 없음** |

**2번**: 코드를 한 줄도 고치지 않고 DB 칸만 `False` 면 실계좌로 나간다.
**3번**: LS증권은 모의·실전이 같은 도메인이라 `paper=True` 를 줘도 실서버로 간다.

> 막았다고 믿는데 막히지 않는 것은, 아예 막지 않은 것보다 나쁘다.

### 해결 — 호출부가 아니라 팩토리에

```
[ 전 ]                          [ 후 ]

auto_trade ─┐                   auto_trade ─┐   ┌──────────────────┐
            ├→ 실전 서버 🔴                 ├───┤ 승인 없으면:      │
stocks    ──┘                   stocks    ──┤   │ paper=False→True │→ 모의 🟢
(ebest 는 플래그 무시)          (앞으로 생길)┘   │ ebest → Mock     │
                                                └──────────────────┘
```

호출 지점을 세는 방식은 **오늘 있는 셋**만 막는다. 팩토리는 모두가 지나는 유일한 목이라
**내일 생길 네 번째 경로**까지 같이 걸린다.

- `QURIOUS_ALLOW_LIVE_TRADING` 이 꺼져 있으면 `paper=False` 를 `True` 로 강등
- 플래그가 듣지 않는 `ebest` 는 `MockBrokerClient` 로 교체
- 강등할 때마다 **경고 로그** — 조용한 차단은 죽은 기능과 구분되지 않는다([#53](../issues/053.md) 교훈)
- 환경변수로 한 이유: 실거래 승인은 **저장소가 아니라 실행 환경**의 결정이다

### 검증 — 스스로 판정하지 않는다 ([#62](../issues/062.md) 규칙 3)

시험 통과만으로 끝내지 않고 **시험 밖에서 다시 실행해** 대조했다.

| 확인 | 기대 | 실측 | |
|------|------|------|---|
| 미승인 · `kis` `paper=False` | 모의 URL | `openapivts...:29443` | ✅ |
| 미승인 · `ebest` | `MockBrokerClient` | `MockBrokerClient` | ✅ |
| 승인 · `kis` `paper=False` | 실전 URL | `openapi...:9443` | ✅ |
| 승인 · `ebest` | `EBestClient` | `EBestClient` | ✅ |
| 셸에 `=1` 남은 채 pytest | 격리되어 23건 통과 | 23건 통과 | ✅ |
| 강등 시 경고 로그 | 출력됨 | 출력됨 | ✅ |

「승인하면 열린다」와 「모의투자는 막지 않는다」도 **짝으로** 시험한다 —
차단만 시험하면 기능이 죽어 있어도 통과하기 때문이다.

## 작업 2 · CI 게이트 착수 ([#61](../issues/061.md) P2-3 · [#62](../issues/062.md) §5.0)

| 점검 | 전 | 후 |
|------|-----|-----|
| 자동화 시험 | **0건** | **23건** · 1.5초 |
| `.github/` | 없음 | `ci.yml` |
| 시험 의존·설정 | 없음 | `requirements-dev.txt` · `pytest.ini` |
| main 직푸시 차단 | ❌ | ⚠️ **룰셋 설정 대기** |

팀원 넷의 시간대가 달라 **사람 승인을 필수로 걸 수 없다.** 사람이 못 막으면 코드가 막아야 한다.

### 야후 의존은 '금지'가 아니라 '봉인'

지금 **8파일 72줄**이 남아 있고 전부 걷어내는 일([#61](../issues/061.md) P1-1)은 별도 작업이다.
그때까지 **늘어나는 것만** 막는다. **줄어도 실패**하게 했는데, 줄었다는 건 치우는 작업이
진행됐다는 뜻이라 기준선을 함께 낮춰야 울타리가 다시 조여지기 때문이다.

### ⚠️ 이것만으로는 아직 안 막힌다

> 워크플로는 검사를 **실행할 뿐**이고, 그 결과를 병합 조건으로 삼는 것은 **룰셋**이다.

룰셋은 저장소 **설정 변경**이라 자동화 대상이 아니다(계정 정지 이력 · 프로젝트 규칙).
절차서를 `docs/배포/CI-CD명세_v1.0.md` **4절**에 적어 뒀다 — **스위치는 사용자가 웹 UI 에서.**
