## 왜

하루 사이에 CI 방침이 세 번 바뀌었습니다. **이번에 되돌리는 것은 기술 판단이 아니라 순서입니다.**

```
  S40       워크플로 도입 + 룰셋 게이트 계획      (명세 v1.0)
  S41 ①    게이트 → 신호등 전환                 (명세 v1.1 · ADR-0002 · PR #68 머지)
  S41 ②    걷어내고 논의 먼저                    (명세 v1.2 · ADR-0003)   ← 이 PR
```

CI 는 **모든 팀원의 PR 화면에 나타나는 공용 장치**입니다. 이 저장소에는 팀에 영향 가는 결정을
올리는 Discussion 규격이 이미 있고 9건이 거기를 거쳤는데, **CI 만 거치지 않았습니다.**
성격상 D0(팀 운영·기록 방식)과 같은 칸에 있어야 했습니다.

ADR-0002 의 분석은 취소하지 않습니다 — 사람 리뷰와 자동 시험이 보는 범위가 다르다는 것도,
`paper=False` 가 `2e2d3f8` 에서 들어와 `2e3cccc` 가 같은 파일을 또 건드렸는데도 지나갔다는 것도
그대로 사실입니다. 다만 **「문제가 있다」가 「내가 고른 해법을 쓰자」로 바로 이어지지 않습니다.**
문제는 논의에 올리고, 해법은 팀이 고릅니다.

ADR-0002 에서 선택지를 셋 늘어놓고 비교했는데, **그 셋이 전부 "내가 무엇을 만들까"였습니다.**
"팀에 물어본다"가 선택지에 없었습니다.

## 시험은 왜 남기나

시험은 **「무엇을 지킬 것인가」의 기록**이고, 그건 ADR-0001·테스트계획서로 이미 합의된 내용입니다.
지운 건 **「누가 언제 돌릴 것인가」** 쪽입니다. 그 둘이 한 덩어리로 묶여 있었는데 사실 다른 결정이었습니다.

```bash
$ python -m pytest -p no:warnings -q
.......................                       [100%]   23 passed
```
