### 개선 때 — 실측 꼴 · 쓰는 모델 보이기

**근거 답 걸린 시간 나누기** — 강사님 메모의 「콜드(올리기 포함) · 웜 · 초당 토큰」 꼴이다. 우리 근거 답은 [걸린 시간을 하나로](https://github.com/EST-team-project/Qurious/blob/ef8cf5bf64585e0b703a7f93001497ce6875d6e4/app/services/kb_answer.py#L446-L450) 싣고 화면은 [「답 모델 · n초」](https://github.com/EST-team-project/Qurious/blob/ef8cf5bf64585e0b703a7f93001497ce6875d6e4/public/js/kbchat.js#L166-L176) 다. Ollama 응답의 `load_duration`([조사서 4.4절 표 8](https://github.com/EST-team-project/Qurious/blob/ef8cf5bf64585e0b703a7f93001497ce6875d6e4/docs/조사/로컬LLM-퀀트활용-조사.md?plain=1#L220-L222) 에서 이미 읽어 본 칸)을 `load_ms` 로 나눠 실으면 느린 첫 답이 모델 올리기 때문인지 가를 수 있다.
- 꼬리표 예: 「22.0초(모델 올리기 15초 포함 — 처음 묻거나 한동안 쉰 뒤에는 느립니다)」(숫자는 예시 · 올리기가 짧으면 괄호 없음).
- 재는 방법(HTTP · 답 길이 고정 · 모델을 바꿀 때 내림)은 [근거 답 평가](https://github.com/EST-team-project/Qurious/blob/ef8cf5bf64585e0b703a7f93001497ce6875d6e4/collector/kb_answer_eval.py#L66-L68)가 이미 같다.
- [개념 학습 「로컬 LLM — Ollama」 장](https://github.com/EST-team-project/Qurious/blob/ef8cf5bf64585e0b703a7f93001497ce6875d6e4/public/learn/content/local-llm-ollama.md?plain=1#L39)(뼈대)을 채울 때 「`ollama run` 으로 재지 않는다 — 답 길이 상한이 없어 PC 를 포화시킨다」 와 함께 쓴다. 숫자는 이 PC 에서 돌린 값만.

**쓰는 모델 보이기** — th24 상태 API 는 연결 방식 이름과 모델을 싣는데, 상태가 읽는 모델(설정 `vllm_model`)과 실제 호출이 쓰는 모델(`QWEN_MODEL`)이 달라 갈릴 수 있다(배포 compose 가 둘을 같은 값으로 맞춰 둘 뿐). 우리 [상태 API](https://github.com/EST-team-project/Qurious/blob/ef8cf5bf64585e0b703a7f93001497ce6875d6e4/app/services/system_info.py#L95-L108) 에는 모델 이름이 없고, 근거 답 모델이 이 PC 에 없으면 [답이 실패해야](https://github.com/EST-team-project/Qurious/blob/ef8cf5bf64585e0b703a7f93001497ce6875d6e4/app/services/kb_answer.py#L134) 알 수 있다. 서버 대시보드 Ollama 카드에 「채팅 · 근거 답 · 임베딩」 모델과 「받아 둠 / 없음」 을, 실제 호출이 읽는 같은 함수에서 가져와 싣는 안이다. 관리자 기능은 이동원 몫 뒤에 한다.

**compose 의 한 번에 한 모델** — compose 의 Ollama 는 [한 번에 한 모델](https://github.com/EST-team-project/Qurious/blob/ef8cf5bf64585e0b703a7f93001497ce6875d6e4/docker-compose.yml#L175)이라 임베딩 · 채팅 모델이 번갈아 올라가 질문마다 콜드가 생길 수 있다(추정 — 재 보지 않았다). 위 시간 나누기를 하면 드러난다.
