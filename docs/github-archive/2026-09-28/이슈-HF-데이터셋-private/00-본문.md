# [작업] HF 데이터셋은 private 으로 만든다 — 만들 때 지정 · 올리기 전 검사 (팀 체크리스트)

> 작성 2026-09-28 (KST) · 데이터 파트(이동원) · Assignee 비움 — 데이터셋을 만드는 사람 누구나 해당합니다.

## 1. 무슨 일이 있었나

팀 HF Organization [`qurious-quant`](https://huggingface.co/qurious-quant) 의 데이터셋을 09-28 오후에 목록으로 조회했더니 **10개 중 6개가 public** 이었습니다.
같은 날 전부 private 으로 바꿨고, 다시 조회해 **10 / 10 private** 을 확인했습니다.

| 데이터셋 | 무엇 | 조회 1회차 | 지금 |
|---|---|---|---|
| `krx-daily-market` | 수집기 일봉 · 수정주가 · TR · 배당 (매일 12:30) | private | private |
| `alphastack-krx-dev` · `alphastack-dart` · `alphastack-krx-holdout` | 1차 KRX 개발 구간 · DART 재무 · 홀드아웃 결과 | private | private |
| `alphastack-backtest-results` · `-cost-sensitivity` · `-breakeven-cost` · `-backtest-kospi200` · `-execution-log` · `-trade-log` | 1차 백테스트 결과 · 비용 · 로그 (각 0.1 MB 이하) | 🔴 **public** | private |

public 이던 6개는 원자료가 아니라 결과 표라 피해는 작습니다. 다만 **같은 실수가 원자료 데이터셋에서 나면 되돌릴 수 없습니다** — 한 번 공개된 파일은 누가 받아 갔는지 알 수 없습니다.

## 2. 왜 private 이어야 하나

| 근거 | 내용 |
|---|---|
| KRX 이용약관 제11조 ② | 제3자 제공 금지 — `alphastack-krx-dev` 카드에 명시 |
| 공공데이터포털 · OpenDART (공공누리 제4유형 · 변경금지) | 팀이 HF 에 올려 쓰기로 한 근거가 **「private Organization 안에서만 공유」** 하나뿐입니다 ([collector/README.md §9.2](https://github.com/EST-team-project/Qurious/blob/main/collector/README.md) · [scripts/hf_dataset.py](https://github.com/EST-team-project/Qurious/blob/main/scripts/hf_dataset.py) `SHARING_DECISION`) |

## 3. 왜 실수가 나기 쉬운가 — 기본값이 public 입니다

```
HfApi().create_repo("qurious-quant/새-데이터셋", repo_type="dataset")          → public  (기본값)
HfApi().create_repo(..., private=True)                                          → private
HfApi().create_repo(..., private=True, exist_ok=True)  ← 이미 public 으로 있으면 → public 그대로 (공개 범위를 안 바꾼다)
```

- `huggingface-cli repo create` · 라이브러리 모두 **`private` 을 빼면 public** 입니다([HF 문서 — Create and manage a repository](https://huggingface.co/docs/huggingface_hub/en/guides/repository)).
- 공식 문서에서 **org 전체의 기본값을 private 으로 강제하는 설정은 찾지 못했습니다** — 저장소마다 지정해야 합니다([Repository Settings](https://huggingface.co/docs/hub/en/repositories-settings)). 🟡 유료 플랜 기능은 확인하지 않았습니다.

## 4. 이렇게 합니다 — 체크리스트

**새 데이터셋을 만들 때**
- [ ] 웹: New Dataset → **Private** 선택 / 코드: `create_repo(..., repo_type="dataset", private=True)`
- [ ] 올리는 스크립트는 **올리기 직전에** 원격이 private 인지 확인하고, 아니면 멈춘다

```python
info = api.repo_info(repo_id, repo_type="dataset")
if not info.private:
    raise SystemExit(f"{repo_id} 가 public 입니다 — Settings 에서 private 으로 바꾼 뒤 다시 올리세요")
```

  이 모양은 수집기 업로드에 이미 있습니다 — [`scripts/hf_dataset.py` 의 `_assert_private()`](https://github.com/EST-team-project/Qurious/blob/main/scripts/hf_dataset.py).

**이미 있는 데이터셋**
- [ ] public 이 필요하다면(예: 발표용 결과 표) **올리기 전에 팀에 먼저** 말한다 — 원자료 · 원자료를 거의 그대로 옮긴 표는 public 불가
- [ ] 한 달에 한 번 목록 점검 — 아래 한 줄로 public 인 것만 뽑힙니다 (토큰은 `.env` 의 `HUGGINGFACE_ACCESS_TOKEN`)

```python
from huggingface_hub import HfApi
print([d.id for d in HfApi().list_datasets(author="qurious-quant") if not d.private] or "전부 private")
```
