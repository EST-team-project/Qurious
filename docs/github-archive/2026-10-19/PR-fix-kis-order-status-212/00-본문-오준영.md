KIS 주문이 토큰 403 등으로 실패해도 자동매매 화면에 매수 완료처럼 보이고 가상 장부가 먼저 바뀌던 문제를 수정합니다. KIS 연동은 증권사 잔고로 판단하고, 주문 접수·확인된 체결·실패·응답 불명을 분리합니다.

Fixes #212

- `quant_mode=live`에서는 QUANT 현금·보유·가상 주문을 변경하지 않습니다. KIS 잔고 조회 실패 시 주문을 보류하며, `paper` 가상매매만 기존 가상 장부를 사용합니다.
- 사용자 키 직접 주문도 전송 전에 `live_orders`에 기록합니다. 계좌·환경·일자·주문번호·종목·방향·수량을 대조하여 체결을 확인합니다. 응답 유실·불완전한 응답은 UNKNOWN으로 남기며 직접 경로는 자동 재전송하지 않습니다.
- 화면과 의사결정 로그가 가상 기록, 주문 요청, 증권사 확인 수량을 구분합니다. 과거 가상 성공 기록은 삭제하지 않고 KIS 체결과 구분하여 표시합니다.
- 토큰을 Redis에서 환경·키별로 공유하고 만료와 동시 발급을 관리합니다. Redis 확인 실패 시 토큰 발급을 우회하지 않습니다. 직접 계좌 주문을 공용 게이트웨이 재주문·취소·보유 대조에 섞지 않습니다.

검증: 관련 Python 회귀시험 258개 통과(실제 격리 PostgreSQL·Redis, KIS HTTP 대역), JS 렌더러 1개 통과, API 문서·카탈로그 일치 및 문서 규칙 검사 통과. API·문서·RTM 도구 시험도 통과했으며 격리 컨테이너에 Node가 없어 API 문서 화면 함수 시험 1개는 건너뛰었습니다(#212 화면 렌더러 시험은 Windows Node로 별도 통과). 전체 RTM 재생성은 하지 않았고 관련 시험 건수만 갱신했습니다.

2026-10-19 사용자가 모의투자용 자격증명을 등록한 뒤 **실제 KIS 모의계좌 인증·잔고 조회에 성공**했습니다. 실행 중인 앱의 KISClient로 모의 서버 tokenP HTTP 200, inquire-balance HTTP 200 및 rt_cd=0을 확인했습니다. 사용자 제공 계좌와 일치하는 설정만 사용했고, 요청을 토큰 발급·잔고 조회 두 경로로 제한했습니다. 주문 요청·자동매매 활성화·배포는 하지 않았습니다. 이 결과는 현재 앱의 계좌 연결 확인이며, PR 코드 배포 후 실제 주문·체결 검증을 의미하지 않습니다. 키·계좌번호·자산 금액은 PR에 공개하지 않습니다.

운영 범위: DB 스키마 변경 없음, 배포하지 않음. 직접 경로의 미확인 주문·미체결 취소는 KIS에서 수동 확인합니다. KIS 이외 증권사의 연동 모드는 잔고 확인을 지원하지 않아 주문을 보류합니다. 기존 가상 장부는 자동 역분개하지 않습니다.
