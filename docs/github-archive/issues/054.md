## 본문

[#51](../issues/051.md) 이 「모의 체결로는 요율표를 검증할 수 없다」를 확정했다. 그래서 장중에 할 일이 **검증**에서 **①관측 장치 수리 ②주문 0건 확인 ③배관 확인** 으로 바뀌었다.

**결과: 주문 0건 · 체결 0건 · 비용 0원으로 열린 질문 두 개가 닫혔다.**

## 1. 🔴 저울이 고장 나 있었다

```python
# app/services/brokers/kis.py (수정 전)
rows.extend(body.get("output1") or [])          # ← output1 만 모은다
...
fee_raw = str(row.get("prsm_tlex_smtl", ""))    # row 는 output1 의 한 줄
```

**`prsm_tlex_smtl`(추정제비용합계)은 `output1` 에 없다.**

```
응답
├── output1  [ {주문1}, {주문2}, … ]   ← 모으던 곳. 제비용 없음
└── output2  { tot_ord_qty, tot_ccld_qty, tot_ccld_amt,
               prsm_tlex_smtl,          ← 여기 있었다
               pchs_avg_pric }
```

⚠️ **주문을 냈어도 「제비용 미제공」만 떴을 것이다. 실계좌로 바꿔도 같다** — 버리는 쪽이 코드였다.

> **용어 — `prsm_tlex_smtl`**
> `prsm` 추정 · `tlex` 제비용 · `smtl` 합계.
> **이 이슈에서는** 증권사가 "이 거래에 이만큼 뗀다" 고 알려 주는 금액.
> **헷갈리는 점**: 강사님 카탈로그의 한글 라벨은 이 칸을 "총체결금액" 이라 적어 두었다. 필드명과 어긋난다. 필드명을 따랐고 오늘 그 판단이 맞았음이 확인됐다.

## 2. 🟢 주문 없이 필드 위치를 확정 — [#51](../issues/051.md) 8절 ① 종결

체결이 0건인 날로 조회했다. **칸이 거기 있어야 0 이라도 나온다.**

```
― 요약 칸(output2) ―
  총주문수량 0 · 총체결수량 0
  🟢 추정제비용합계(prsm_tlex_smtl) = 0.00 원
  원문: {"tot_ord_qty":"0","tot_ccld_qty":"0","tot_ccld_amt":"0",
         "prsm_tlex_smtl":"0","pchs_avg_pric":"0.0000"}
```

**🟡 추정 → 🟢 확정.** Phase C(모의 1주 매매)가 불필요해졌다.

## 3. 🟢 수수료율도 주문 없이 — [#51](../issues/051.md) 8절 ② 종결

**매수가능조회**는 "이 가격이면 몇 주까지 살 수 있나" 를 증권사가 계산해 준다. **그 계산 안에 수수료가 들어 있다.** 거꾸로 풀면 요율이 나온다.

```
최대매수수량 = floor( 주문가능현금 / (주문단가 × (1 + 수수료율)) )

내림이므로 한 점이 아니라 구간으로 나온다:
  C/(p(q+1)) − 1  <  f  ≤  C/(p·q) − 1
```

단가를 낮출수록 수량이 커지고 구간이 좁아진다.

| 단가 | 미수 없는 수량 | 역산 구간 |
|---|---|---|
| 269,000원 | 36주 | (−0.030%, +2.747%] |
| 26,900원 | 369주 | (−0.030%, +0.241%] |
| 2,690원 | 3,698주 | (−0.003%, +0.024%] |
| **269원** | **36,988주** | **(−0.0004%, +0.0023%]** |

마지막 줄에서 갈렸다 — 수수료 0원이면 **36,988주**, 실전 요율(0.017693%)이면 **36,982주**. **6주 차이.**

```
실측 36,988주  →  교집합 f ∈ (−0.00000412, +0.00002292]
🟢 모의 수수료는 0원. 상한이 실전 요율의 1/8 이라 실전 요율은 배제된다.
```

**[#51](../issues/051.md) 의 결론(모의로는 검증 불가)이 독립적으로 증명됐다.**

## 4. ⚠️ 한 번 틀렸던 곳 — `max_buy_amt` 는 쓸 수 없다

처음엔 `max_buy_amt` 로 역산해 **−80%** 라는 말 안 되는 값이 나왔다.

```
단가 269,000 → max_buy_amt 50,000,000
단가  26,900 → max_buy_amt 50,000,000
단가   2,690 → max_buy_amt 50,000,000    ← 단가가 바뀌어도 그대로
```

**미수·증거금 포함 한도라 고정값이고, 수수료가 애초에 안 들어간다.** 써야 할 칸은 `nrcvb_buy_qty`(미수 없는 매수 수량)였다 — `floor(주문가능현금/단가)` 와 정확히 일치.

> 말이 안 되는 값이 나온 것이 다행이었다. 0.02% 쯤 그럴듯한 값이었다면 믿고 기록했을 것이다.

## 7. 함께 고친 것 ([#51](../issues/051.md) 6절)

- ② `sync_fills.py` — matched·mismatched 가 **둘 다 0 이면 아무 말도 안 했다.** "검증하고 통과" 와 "검증 자체를 못 했다" 가 화면에서 같아 보였다 → 🟡 경고를 내고 무엇을 근거로 쓸지 알려 준다
- ⑤ 허용오차 `1.0` 하드코딩 → `fill_sync.DEFAULT_TOLERANCE_WON`

## 8. 🔴 실전 요율은 여전히 못 쟀다 — 그러나 경로가 열렸다

실계좌 매수가능조회를 **승인 후 1회** 실행했다(주문 TR 미호출 · 조회만). 결과: **예수금 0원** 이라 수량이 0 으로 나와 역산 불가.

부수 성과 — **실전 도메인이 응답한다**: 토큰 발급 성공, 조회 4회 모두 `rt_cd=0`. (열린 질문이던 "실전 도메인 유량 미측정" 의 일부가 닫혔다.)

> **입금하면 조회 1회로 실전 요율이 확정된다.** 주문도 체결도 필요 없다 — 이것이 이번 작업의 가장 큰 소득이다.

## 9. 한계 · 뒤집힐 조건

- 🟡 `FillSummary.total_fees` 는 **조회 범위 전체의 합계**다. 여러 건이 섞이면 어느 건이 틀렸는지 알 수 없다 → 한 건만 걸리게 좁혀 조회해야 한다
- 🔴 **"추정제비용" 의 "추정" 이 무슨 뜻인지 모른다.** 장중값과 마감 후 값이 다른지도 미확인
- 🔴 수수료·유관기관비에 **시행일 구조가 없다** — 2016년 거래에 2025년 요율이 붙는다
- 🔴 NXT 유관기관비 상수가 아예 없다 ([#51](../issues/051.md) 7.2 · 네 군데를 함께 열어야 한다)
- 모의 수수료 0원은 **모의 도메인 한정** 결론이며 실전 요율을 대신하지 않는다
- KIS 가 스펙을 바꿔 `output1` 에도 제비용을 넣으면 3절의 역산은 불필요해진다
