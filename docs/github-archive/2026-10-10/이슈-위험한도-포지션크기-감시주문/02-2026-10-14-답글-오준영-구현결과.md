### 점검 결과와 보완

- **C1:** 비상 정지 → 신호 계산 → 일손실 점검 → 주문 수/매수 비중/쿨다운 → 주문 → 사후 일손실 점검 순서를 기록했습니다. 손절 매도도 일 주문 수·쿨다운 제한을 받고, 일손실 한도 도달 시 매도 전에 루프가 멈추는 것을 시험으로 확인했습니다. 비상 정지는 보유 종목 전량 청산이 아닙니다. 자동매매 QUANT 장부와 리밸런싱 PAPER 장부의 한도도 구분했습니다.
- **C5 수정 ①:** 응답 불명(`UNKNOWN`) 주문을 확인하는 별도 작업이 비상 정지 후에도 재전송할 수 있었습니다. 멱등키가 같더라도 원래 요청이 미접수였다면 신규 주문이 될 수 있어, 사용자 본인의 DB 설정에서 비상 정지·자동매매 중지·live 경로 아님·설정 없음이면 재전송을 보류하도록 고쳤습니다. 주문번호가 있는 주문의 체결 확인은 정지 후에도 계속합니다.
- **C5 수정 ②:** 수동 비상 정지 버튼은 기존에 자동매매만 끄고 미체결 취소 요청은 하지 않았습니다. 추적 중인 접수/부분체결 게이트웨이 주문의 취소 요청을 연결하고, 취소 실패·미확인 시 증권사 확인 안내를 표시했습니다. 취소 실패해도 정지 상태는 유지합니다.
- **C4:** 화면에 실제 설정된 판단 주기, 서버 주기 판단 방식, 손절가 체결 보장 없음, 시간 경과 미체결 자동 취소의 설정 상태를 표시했습니다. 증권사 상주 감시 API를 추가한 것은 아닙니다.
- **C6:** 해당 배분·자동매매 화면의 ‘AI 추천’ 표현을 ‘모델·지표 선정/분석 결과’로 정리하고, 자산군 비중은 성향·기간 규칙으로 계산한다는 점을 명시했습니다.
- 공격 모드에서 바뀌는 일 주문 수·쿨다운 한도도 위험 상태 화면에 실제 적용값으로 표시하도록 맞췄습니다.

### C3·Q3 비용 검증

2026-10-14를 **기존 코드의 비용표**에 넣은 일반 코스피 주식·온라인 수수료 가정입니다. 현행 법령이나 실제 계좌 비용을 이번에 새로 검증했다는 의미는 아닙니다. 매수 비용과 매도 금액별 비용을 각각 적용했습니다.

| +1.5% 익절 / -1% 손절 | 익절 순수익 | 손절 순손익 | 손익비 | 본전 승률 |
|---|---:|---:|---:|---:|
| 슬리피지 0bp | +1.2611% | -1.2330% | 1.0228 | 49.4359% |
| 편도 슬리피지 10bp 가정 | +1.0586% | -1.4305% | 0.7400 | 57.4709% |

질문 주신 ‘비용 뒤 약 1:1’이라는 어림은 슬리피지 제외 시 우리 코드 계산과도 가깝습니다. 10bp는 실제 관측값이 아닌 가정이며, 화면에도 이를 구분해 표시했습니다. 기본 익절·손절 수치는 유지했습니다.

### 검증·남은 범위

- 관련 pytest **85건 통과(신규 28건)**. 실제 임시 PostgreSQL에서 사용자별 정지 상태 분리 검증, 게이트웨이는 모의 응답 사용.
- 실제 HTML/JS와 고정 API 응답으로 Chromium **3개 흐름 통과**: 안내/비용 표시, 정지 취소, 정지 확인·취소 실패 안내.
- **작업 브랜치 업로드 완료, main 병합·운영 적용 전. DB 마이그레이션 없음.**
- C2 `risk_pct` 계약, 시장 상황별 손절 재주문·한도 예외, 증권사 상주 감시 주문과 성과 지표 연결은 후속입니다. 이미 진행 중인 요청과 비상 정지를 원자적으로 묶거나, 실제 하한가·VI·거래정지 상황까지 재현한 것은 아닙니다.
- 기존 증권사 평가액 조회 실패 처리와 가상 장부/실주문 실패 차이 등 추가 점검 항목은 문서에 남겼습니다. 따라서 #162 전체를 완료·종료 처리하지 않고 검토를 이어가겠습니다.
