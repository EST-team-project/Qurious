## 1. 왜 이 글을 쓰나요

이동원이 받은 질문입니다 — 「지금 2 · 3차로 **개별 종목을 분석하고 투자 근거를 확인**할 수 있나? 특히 **3차 TradingView 에서 익절 · 손절을 비전공자 · 실제 투자자에게 정확하게** 알려 주고 싶다.」

TradingView 에 손절 · 익절을 그리는 일(Pine `strategy.exit` · 선 · 알림)은 이동원 몫(`P02-③-1 ~ ③-3`)이지만, **무엇을 손절 · 익절로 볼지 정하는 규칙**은 요구 대장에서 신장환 님이 주담당입니다(`P02-①-2` 「지표 조건을 조합해 매수 · 매도 · 손절 · 익절 · 포지션 크기 규칙 설계」 · 부담당 강민석 님). RTM 은 「조건 조합 · 손절 · 익절 · 포지션 크기를 규칙 명세(JSON) 하나로 적고, 백테스트 · Pine 생성 · 자동매매가 **같은 명세를 읽는다**」 고 적었습니다(`docs/요구사항/RTM.md:168`). 그래서 Pine 을 만들기 전에 규칙 명세에 무엇이 들어갈지 여쭙니다.

## 2. 조사 요약 — 손절 · 익절을 정확하게 보여 주는 꼴

**현업 표준 꼴은 「세 가격 + 손익비 + 수량 + 체결 보장 아님」 한 묶음입니다.**

- TradingView 롱 · 숏 포지션 도구 — 진입 · 목표 · 손절 가격, 손익비(=(익절 − 진입) ÷ (진입 − 손절)), 그리고 **수량 = 위험 금액 ÷ ((진입 − 손절) × 포인트 가치)** 를 보여 줍니다(TradingView 도움말 · 확인).
- 강사님 stock-coin-trade TR 실전연습 15단계 — Pine v6 `strategy.exit(stop = 평균가 − ATR×2, limit = 평균가 + ATR×3)` · 명목 손익비 1:1.5 · 주의 문구 「ATR 배수는 손실 금액 자체를 제한하지 않습니다 … 주문 수량, 계좌 위험 한도를 함께」(`frontend/js/tr-pine-advanced.js:1-36` · 확인). RTM 도 이 본보기를 적어 두었습니다(`RTM.md:184`).
- SEC · FINRA · 키움 도움말 모두 「**손절 가격은 체결 가격이 아니다**」(갭 · 빈 호가 · 급변 때 더 나쁘게 체결되거나 안 될 수 있음)를 먼저 말합니다(확인).

<표 1> 방식 비교(요약 — 조사서 <표 9>)

| 방식 | 식 | 언제 맞나 | 우리 앱 지금 |
|---|---|---|---|
| 고정 % | 진입가 × (1 − s%) | 처음 배우기 · 비교 기준 | W3 손절 % · 익절 %(종가 판정) |
| ATR 배수 | 진입가 − ATR × k | 대부분의 규칙(조사서 추천 기본값) | 없음 |
| 추적 손절 | 보유 중 최고가 − 거리 | 추세 추종 | 없음 |
| 샹들리에 | 22일 최고가 − ATR(22) × 3 | 추세 추종(장기) | 없음 |
| 지지 · 저항 기준 | 가까운 지지 아래 · 저항 근처 | 패턴 규칙 · 설명 | 지지 · 저항 API(W18)는 있음 · 손절과 잇지 않음 |

| 포지션 크기(위험 %) | 수량 = 계좌 × r% ÷ (진입 − 손절) | 모든 방식에 덧붙임 | 없음(IA U6 「포지션 크기 칸」 남음) |

|---|---|---|:-:|---|---|

## 4. 제안 — 아이디어 아홉 (반영 여부는 주담당이)

- **A1 규칙 명세 청산 칸 넓히기** — 설계 초안(Q4)에 칸을 몇 개 더하면 백테스트 · Pine · 자동매매가 같은 말을 씁니다.

  ```json
  {
    "exit": {
      "stop":  { "kind": "atr | pct | trail | chandelier", "k": 2.0, "lock": "entry | bar" },
      "take":  { "kind": "rr | atr | pct", "v": 1.5 },
      "time":  { "bars": 10 },
      "judge": "close | intrabar",
      "reentry": "new_signal | immediate"
    },
    "size": { "kind": "risk_pct | pct_equity | fixed", "v": 1.0 }
  }
  ```

  - `lock` — ATR 을 진입 때 고정할지(entry) 매 봉 다시 잴지(bar). 강사님 15단계 코드는 매 봉 다시 계산해 손절선이 진입 뒤에도 움직입니다(`tr-pine-advanced.js:28-30`).
  - `judge` — 종가 판정(지금 우리 엔진) · 봉 안 판정(TradingView · 증권사 감시 주문). 결과 응답에도 실어 화면 · 대사가 읽게.
  - `take.kind = rr` — 익절 거리 = 손절 거리 × 손익비.
  - `size.kind = risk_pct` — 수량 = 계좌 × v% ÷ 손절 거리(TradingView 포지션 도구 식).
- **A2 ATR 배수 손절 + 위험 % 수량을 백테스트에** — 조사서의 추천 안 A 입니다. 고정 % 는 비교용으로 남깁니다.
- **A3 판정 기준을 결과 응답에 싣기** — `judge: "close"` 같은 칸 하나면 화면 · Pine 대사 · 개념 학습 장이 같은 사실을 씁니다.
- **A4 신호 이유 한 문장** — 신호마다 「RSI 28(30 아래) · 20일선 위 · 거래량 1.8배」 꼴의 이유를 응답 칸으로(스크리닝 표의 `reason` 칸이 이미 있습니다 — `public/js/robo.js:254`). 자동매매 근거 카드(강민석 님) · 종목 근거 서랍(이동원)이 그 문장을 그대로 읽을 수 있습니다.
- **A5 XAI 요약에 가격 수준** — 가장 가까운 지지 · 저항(`app/services/patterns.py:89-127` 결과)과 ATR 변동 폭을 요약 문장에 한 줄.
- **A6 스크리닝 범위** — 31종목 고정(Q6)을 넓힐지 · 넓히면 신호 스캔 시간(점검표 13초)을 어떻게 할지.
- **A7 낱말** — Q7 의 셋.
- **A8 개념 학습 F13 「손절 · 익절 · 포지션 크기 — 왜 미리 정하나」 정확성 검토** — 개념 학습 장 대장(#152 조사서)에서 「이동원(글) · 신장환(정확성)」 · 11-02 오전 「포지션 · 위험」 칸 전으로 잡혀 있습니다. 근거는 이 조사서 5절입니다.
- **A9 신호 적중 대조** — 다중 주기 신호는 매일 기록되지만(러너 signals 단계 · #140), 「그 신호 뒤 n일 실제로 어땠나」 를 대조해 보여 주는 곳이 없습니다(코드 검색 「적중 · hit_rate」 0건). 1차 Alpha_Stack 은 최종 결과 표에 「실제 결과 · 적중 O/X」 를 두었습니다(`notebooks/04-모델/최종결과/README.md:27-40`). 신호 근거를 믿어도 되는지 보이는 가장 쉬운 장치라 여쭙니다 — 기록된 신호와 n일 뒤 수익을 잇는 자료(수집 DB 일봉)는 데이터 파트(이동원)가 댈 수 있습니다.
