정리 고맙습니다. 데이터 쪽으로 남겨 주신 두 가지의 계획을 적어 둡니다. 이슈는 그대로 열어 두겠습니다.

**1. 오후 수집 재시도 — 「자동 13:40 재시도」 대신 관리자 화면의 수집 단추로 정했습니다.**
- 출처(공공데이터포털 시세)는 「다음 영업일 13시 이후」 공개라, 12:30 정기 회차가 전 거래일 시세를 놓치는 날이 생길 수 있습니다. 놓쳤을 때 관리자가 「이 단계만 다시(시세)」 나 「전체 수집」 을 누르면, PC 작업자가 1분 안에 가져가 러너를 돌립니다.
- 오늘 서버 쪽 PR 이 올라갑니다(요청 표 · API · 작업자). 화면 단추는 Figma 로 정한 뒤 다음 차례입니다.
- 리밸런싱 준비 판정 코드는 건드리지 않습니다. 다만 한 가지 함께 알아 두시면 좋겠습니다. 수동 「전체 수집」 회차도 회차 기록(`daily_update_last.json`)을 새로 쓰므로, 그 회차가 경고로 끝나면 그날 판정이 다시 기다립니다(지금 규칙 그대로). 반대로, DART 점검 같은 일로 경고가 났던 단계를 점검이 끝난 뒤 「이 단계만 다시」 로 성공시키면, 회차 기록의 그 줄과 `ok` 가 다시 계산되어 판정이 열립니다.

**2. 종목별 상태 제공 — 다음 데이터 작업에서 준비하겠습니다.**
- 지금은 `ingest_day.status=done` 을 직접 읽고 계신 것으로 압니다. 이것을 데이터 쪽 읽기 길로 드리면, 수집 표 구조가 바뀌어도 판정 코드를 고치지 않아도 됩니다.
- 칸 후보는 날짜 · 출처별(주식 · ETF) 수집 완료와, 종목별로 행 있음 · 없음 / 거래량 0 / 거래정지입니다. 판정에 실제로 쓰시는 칸만 알려 주시면 그대로 맞추겠습니다.
