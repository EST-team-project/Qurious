## 1. 종목별 상태 조회 — 계약(안)

판정(기다림 · 미체결 종료)은 지금처럼 리밸런싱 쪽이 내리고, 데이터 쪽은 사실만 줍니다. 같은 판정이 두 곳에 생기지 않게 하려는 뜻입니다.

`symbol_day_status(symbols, day) -> {symbol: 상태}` — 앱 안 함수 · 수집 DB 읽기 전용

| 칸 | 값 | 말씀하신 칸 |
|---|---|---|
| `symbol` · `day` | 단축코드(`.KS` · `.KQ` 도 받음) · 날짜 | 종목 · 기준 날짜 |
| `kind` | `stock` · `etf` · `unknown` — 수집 DB 에서 본 적 있는 표로 가름 | 출처 구분 · 출처를 모르는 종목 |
| `collected` | `{"portal": "done" · "pending" · "failed" · null, "portal_etf": …}` — 그날 출처별 `ingest_day` | 출처별 수집 완료 |
| `row` | 그날 가격 행이 있나(true · false) | 가격 행 |
| `halted` · `volume_zero` | 행이 있을 때만 true · false · 없으면 null | 거래정지 · 거래량 0 |

- `kind` 가 `unknown` 이면 `collected` 에 두 출처를 다 싣습니다. 지금 `collection_complete()` 의 「모르면 둘 다 완료여야 함」 규칙(`app/services/rebalance_prices.py:21-27`)을 그대로 옮길 수 있게요.
- 가격(원시 시가 · 종가)은 지금처럼 `read_prices()`(`:42`)가 읽습니다. 이 함수는 상태만 줍니다.
- 맞대는 시험을 같이 둡니다 — 같은 수집 DB 사본에서 지금 `rebalance_prices.py:64-76` 의 갈림과 이 함수의 사실이 같은 결론을 내는지.
- 자리는 `app/services/collector_status.py`(새 파일 · 이동원)입니다. 머지되면 `ingest_day` 직접 읽기를 이 함수로 바꾸시면 됩니다.

## 2. 같은 회차의 수집 DB · 회차 기록

| 무엇 | 지금 | 받는 법 · 고칠 것 |
|---|---|---|
| 수집 DB | 정기 회차마다 러너가 HF private `qurious-quant/krx-daily-market` 에 수집 표(`ingest_day` 포함)를 올리고 그날 `snapshot-YYYY-MM-DD` 태그를 붙입니다(`scripts/daily_update.py:254-258` · `scripts/hf_dataset.py:168` · `:2160-2165`) | 그날 태그 판을 받아 `python scripts/hf_dataset.py restore --from <받은 폴더>` 로 그때 DB 를 되살림. 같은 날 두 번째 올리기는 태그를 옮기지 않아 태그는 그날 첫 판입니다. 거래일 달력 표는 판에 없고 다시 만드는 명령이 있습니다(`hf_dataset.py:398-401`) |
| 회차 기록 | `daily_update_last.json` 은 회차마다 덮어써 지난 회차가 남지 않고, 이력 `daily_update_history.jsonl` 에 회차마다 한 줄(단계 요약)이 남습니다(`daily_update.py:125-126`) | **이동원이 고침:** HF 에 올릴 때 그 회차의 `daily_update_last.json` 사본을 같은 커밋에 싣기 — 한 판에서 DB 와 회차 기록을 함께 받게. 10-19(월)까지 |
