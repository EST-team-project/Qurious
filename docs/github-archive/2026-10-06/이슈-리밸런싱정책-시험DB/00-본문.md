## 2. 왜

- 이 파일의 `scenario()` 는 `QURIOUS_TEST_DATABASE_URL` 의 DB 에 **표가 이미 있다고 보고** 사용자 · 계좌 · 계획을 넣습니다.
- 같은 절차에서 먼저 도는 계정 시험(`tests/test_account_crud.py`)의 고정물은 시험마다 `drop_all` → `create_all` → 끝나면 `drop_all` 을 합니다. 그래서 리밸런싱 정책 시험 차례에는 표가 없습니다.
- 작성하신 PC 에서는 앱 DB 처럼 마이그레이션이 적용된 DB 를 가리켜 통과했을 것으로 봅니다(추정).

## 4. 고치는 길 (제안)

계정 시험처럼 그 파일이 스스로 표를 만들게 하는 모듈 범위 고정물 하나면 됩니다.

```python
@pytest.fixture(scope="module", autouse=True)
def _schema():
    if not DB_URL:
        yield
        return
    import app.models  # noqa: F401 — 모든 모델을 Base 에 올린다
    from app.models.base import Base
    from sqlalchemy.pool import NullPool

    async def run(fn):
        engine = create_async_engine(DB_URL, poolclass=NullPool)
        async with engine.begin() as conn:
            await conn.run_sync(fn)
        await engine.dispose()

    asyncio.run(run(Base.metadata.create_all))
    yield
```

마이그레이션까지 확인하고 싶으시면 `create_all` 대신 `alembic upgrade head` 를 시험 DB 에 돌리는 방법도 있습니다(더 느림).
