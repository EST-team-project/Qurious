# [결함] 패턴 화면 신호 API 의 보유 조회(#188) — 앱 DB 가 닿지 않으면 신호가 안 나오고, 종목 코드 꼴에 따라 보유를 못 찾습니다

@rkdalstjr님,

#188 에서 `/api/stocks/mtf-signal`(API-STK-35)에 더하신 보유 조회에서 결함 두 가지를 찾았습니다. 고쳐 주시길 부탁드립니다.

## 요약

- **어디** — `app/routes/stocks.py` 904 ~ 915(보유 조회) 한 곳입니다.
- **무엇이** — ① 앱 DB 가 닿지 않으면 패턴 화면의 신호 칸이 통째로 안 나옵니다. ② 종목 코드를 장부와 다른 꼴로 넣으면 보유를 못 찾아 의견이 틀리게 나옵니다.
- 같은 변경으로 깨진 제 시험 2건과 화면 띄어쓰기는 제가 고치겠습니다(아래 「제가 고칠 것」).

## 결함 1 — 앱 DB 가 닿지 않으면 신호가 안 나옵니다

- **화면** — 신호 칸에 「멀티타임프레임 신호를 불러오지 못했습니다: 서버 오류 (HTTP 500)」 가 뜹니다. 차트 · 캔들 패턴 표 · 지지/저항 · 통계는 그대로 보입니다.
- **원인** — 914줄 `await db.execute(select(Portfolio)…)` 를 감싸는 `try` 가 없어서, DB 오류가 그대로 올라가 500 이 됩니다.
- **#188 전** — 같은 상황에서도 그 자리 계산으로 신호가 나왔습니다. 이 라우트에서 앱 DB 를 쓰는 곳은 T2 읽기(889 ~ 892) 하나였고 `try` 로 감싸 두었습니다(설계서 목표 기능 ② 5.3.2 「앱 DB 에 T2 가 없거나 닿지 않아도 그 자리 계산으로 돈다」). 로그인 확인은 Redis 세션(`app/lib/session.py:214`)이라 앱 DB 를 쓰지 않습니다.

## 결함 2 — 종목 코드 꼴에 따라 보유를 못 찾습니다

- **화면** — 삼성전자 1주를 보유한 상태에서 `005930.KS` 로 분석하면 「의견: 보유 · 보유 중」, 소문자 `005930.ks` 로 분석하면 「의견: 관망」(「보유 중」 없음)이 나옵니다. 의견 규칙(`opinion.decide`)대로면 신뢰도 0.6 이상일 때 매수 신호는 「보유」 가 「매수」 로, 매도 신호는 「매도」 가 「관망」 으로 바뀝니다.
- **원인** — 911줄 `Portfolio.symbol == symbol` 이 입력한 글자를 그대로 비교합니다. 장부는 적는 길마다 꼴이 다릅니다 — 모의주문(`paper_trading.resolve_stock`) · 자동매매(`QUANT_STOCKS`)는 `005930.KS` 꼴이고, 포트폴리오 직접 추가(`/api/portfolio`) · 수동 주문(`/api/orders`)은 입력한 그대로입니다. 같은 요청의 T2 읽기는 `normalize_symbol` 로 꼴을 맞춰 찾습니다. 906줄 `norm` 은 계산만 하고 쓰이지 않습니다.
- 접미사 없는 `005930` 은 신호 API 에서는 같은 결과지만, 화면에서는 패턴 API 가 먼저 404 를 내서 의견까지 가지 않습니다. 장부에 `005930` 꼴로 적힌 경우(위 직접 추가 · 수동 주문)는 코드로만 확인했습니다.
