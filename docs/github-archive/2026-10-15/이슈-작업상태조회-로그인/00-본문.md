# [알림] 작업 상태 조회(`GET /api/tasks/{task_id}`)에 로그인이 없습니다 — 사실 공유

@GoonGuMa 님(실행 · 운영 파트로 보여 먼저 여쭙니다 — 다른 분 몫이면 알려 주세요), 모델 비교의 시세 출처를 조사하다 곁에서 본 사실 하나를 공유합니다. 고치지는 않았습니다.

**결론: Celery 작업 상태 조회 API 는 로그인 없이 작업 번호만 알면 그 작업의 결과(답 · 오류 글)를 돌려줍니다. 작업 번호가 길고 무작위라 맞혀 보기는 어렵지만, 번호가 로그 · 주소 기록으로 새면 다른 사람의 결과를 읽을 수 있습니다.**

| 무엇 | 사실(`main` `8921f92` · 코드 읽기) |
|---|---|
| 자리 | `app/routes/tasks.py:26` — `@router.get("/tasks/{task_id}")` · 함수 인자에 로그인 의존성(`get_current_user`)이 없다 |
| 돌려주는 것 | `state` · 끝나면 `result`(작업의 반환값 그대로) · 실패면 `error`(예외 글) |
| 쓰는 곳 | 비동기 엔드포인트(예: `/api/chat/async`)가 준 `task_id` 를 화면이 묻는다 |
| 다른 API 와 견줌 | 같은 앱의 다른 조회는 대부분 로그인을 요구한다(API 명세서 「인증 없음」 55 가운데 하나) |

여쭐 것 — ① 로그인을 붙이고, 작업을 시작한 사용자만 결과를 보게 할지 ② 지금처럼 둘지(번호를 맞히기 어려우니 위험이 낮다고 볼지) 정해 주세요. 붙인다면 그 작업을 띄운 화면 쪽이 로그인한 상태로 묻는지도 함께 확인이 필요합니다.
