#162에서 후속으로 남겼던 C2·C5는 먼저 선택 기능으로 구현했습니다. 아래 방식으로 만들었는데 어떠신가요? 기본값은 기존 고정 예산·재주문 꺼짐이며, 팀 의견을 받아 계약과 적용 범위를 다듬으려 합니다.

- 작업 브랜치 업로드 완료, **main 병합·운영 적용 전**입니다.

## 1. 위험 기준 수량 — C2

자동매매 설정에 `execution_policy.size_kind=fixed_budget|risk_pct` 선택지를 추가했습니다.

- 기준 자산: **자동매매 QUANT 가상 평가 자산**. PAPER 리밸런싱이나 실제 KIS 계좌 전체의 위험 예산을 뜻하지 않습니다.
- 위험 수량 = 예상 손실 예산 ÷ 비용 포함 1주 손실. 기존 비용표에 편도 슬리피지 가정을 더합니다.
- 현금·1회 주문 예산·종목 비중 상한도 함께 적용하며, 1주도 허용되지 않으면 건너뜁니다.
- 첫 진입만 지원하고 보유 종목 추가 매수는 막았습니다. 위험 모드의 손절 거리는 기존 보유분에도 평균매입가 기준으로 적용합니다.
- 초기 입력값은 위험 예산 1%, 손절 거리 1%, 편도 슬리피지 가정 10bp입니다. 이를 권장 투자 비율이나 실제 관측 비용으로 제시하지 않습니다.
- 손절 후보도 기존 비상 정지·일손실·주문 수·쿨다운·공격 모드 사이클별 매도 수 제한을 받습니다. 주기 사이 변동·갭·미체결로 실제 손실이 예상치를 넘을 수 있습니다.

**신장환님 의견 요청:** 우선 위 입력으로 구현했습니다. 전략 명세 `size.kind=risk_pct`와 내부 `execution_policy.size_kind`를 매핑하고, QUANT 기준·첫 진입만·기존 한도 우선 정책으로 연결해도 괜찮을까요? 명세에서 사용할 진입/손절 가격과 단위가 다르면 맞추겠습니다.

## 2. 취소 확정 매도 잔량 재주문 — C5

**추적되는 게이트웨이 모의 지정가 매도**만 대상으로 구현했습니다.

- 원 주문이 `CANCELLED`이고, 증권사 재조회에서도 취소 완료·원 수량·체결 수량이 확인돼야 합니다. 취소 요청 중·접수 불명·잔고 추론만 있는 경우 새 주문을 만들지 않습니다.
- 수량은 `min(원 주문 수량−확인된 체결 수량, 현재 보유 수량)`, 가격은 원 지정가입니다.
- 같은 종목 열린 주문, 잔고·가격 이탈·시간 창·일손실·일 주문 수·쿨다운·사용자 정지 상태를 확인합니다.
- 기본 입력은 최대 1회, 원 주문부터 15분, 원 지정가 대비 가격 변동 1% 이내입니다. 최대 3회/120분으로 제한했습니다.
- 부모당 자식 하나를 DB에 저장하고 멱등키를 고정했습니다. 응답 유실은 같은 주문·같은 키로만 확인하며, 기능 해제·정지 후에는 그 재전송도 보류합니다.
- **시장가·매수·실전·개인 키 직접 KIS 경로는 대상이 아닙니다.** 시장가는 현재 기록 가격이 0이라 가격 이탈 기준을 검증할 수 없습니다. 공격 모드 기본 시장가 주문도 이번 범위 밖입니다.
- 재주문을 켜도 자동 취소는 켜지지 않습니다. 기본 쿨다운 30분이 시간 창 15분보다 길면 실행하지 않습니다. 수동 취소도 조건에 맞으면 대상이므로 재주문을 원치 않으면 기능 또는 자동매매를 먼저 꺼야 합니다.

**실측 한계:** 현재 게이트웨이 계약에는 KIS 모의 체결 내역이 비고 잔고로 추정하는 경우가 명시돼 있습니다. 이번 시험은 모의 응답 기반이며 실제 KIS 모의 재주문 성공을 확인한 것은 아닙니다. 취소 확정 근거가 없으면 실행을 보류합니다. 공유 게이트웨이는 기존 ADR에 따라 자동 활성화하지 않았습니다.

**강민석님 의견 요청:** 원 주문과 재주문을 연결한 이력으로 만들었습니다. 추후 실제 체결 자료를 붙여 ‘계획 대비 실제 손실’을 성과 지표에 연결하는 방향은 어떠신가요? 이번에 해당 성과 지표까지 구현한 것은 아닙니다.

## 3. 증권사 감시 주문 — C4

공식 자료도 확인했습니다.

- [KIS 공식 현금 주문 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/order_cash/order_cash.py)에 스탑지정가 조건가격 `CNDT_PRIC` 필드가 있습니다. 이 사실만으로 모의 지원·감시 지속 조건까지 확인됐다고 보지는 않았습니다.
- [키움 0624 공식 도움말](https://download.kiwoom.com/hero4_help_new/0624.htm)은 서버 자동감시와 HTS 종료 후 감시·최대 30일을 안내합니다. 우리 REST 연동 지원 여부는 별개입니다.
- 현재 연결은 시장가·지정가뿐이라 지원 능력 API/화면에 ‘서버 주기 판단·상주 감시 미연결’을 표시하고, 지원하지 않는 STOP 주문 종류는 명시적으로 거절합니다.

**이동원님·팀 의견 요청:** 화면·개념 학습은 위 구현 기준으로 표현을 맞추고, 실제 상주 감시 연동은 주문 구분 코드·모의 지원·감시 등록/취소·만료/재조회 계약을 확인한 뒤 추가하는 방향으로 진행하려 합니다. 의견 부탁드립니다.

## 4. 검증과 다음 적용 순서

- 관련 pytest **135건 통과(이번 신규 50건)**. 실제 임시 PostgreSQL에서 경합·중복 방지·부분체결 잔량·정지 재확인·응답 불명 복구를 검증했습니다. 증권사 응답은 모의입니다.
- Chromium **6개 흐름 통과**: 이번 설정 저장·복원 3개 + 기존 위험 안내·비상 정지 3개.
- 새 DB 이전 `0022_execution_policy`: 빈 임시 DB 전체 적용, 되돌리기/재적용, 정책 저장·재조회 검증 완료. **배포 시 DB 이전이 먼저 필요합니다.**
- 문서 검사에서 기존 미추적 리밸런싱 버전 파일 두 개의 이름 경고가 남아 있으며 이번 파일은 아닙니다.

제안 순서는 **현재 구현 검토 → 규칙 명세 필드 매핑 → 모의에서 취소 확정 응답 실측 → 시장가 기준 가격 저장·직접 KIS 추적 확대 → 상주 감시 어댑터 검증**입니다. 현재 선택 기능으로 먼저 검토하고, 외부 확인이 필요한 부분은 확인 결과에 따라 넓히겠습니다.
