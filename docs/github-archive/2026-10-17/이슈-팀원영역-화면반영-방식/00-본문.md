# [팀 안내] 강사님 새 화면 반영 방식 — 화면(프론트)만 먼저 · 미리 알림 · 반대하면 되돌림 (잠정)

읽는 사람: 신장환 @janghwan-god · 오준영 @GoonGuMa · 강민석 @rkdalstjr

## 왜

강사님 기초 코드(lumina-invest)에 새 화면 · 기능이 계속 늘고 있습니다. 우리 앱과 차이가 커지는데, 각자 파트 화면을 받아 보기 전에 2차 발표(10-21)가 옵니다. 그래서 **강사님 자료의 화면 쪽은 이동원이 먼저 반영하고 알리는 방식**으로 바꾸려 합니다. 지금까지는 「다른 사람 파트는 고치지 않고 이슈로만 알린다」 였는데, 이것은 팀 합의가 아니라 이동원의 작업 규칙이었습니다.

## 바뀌는 것 (잠정 — 반대가 나오면 되돌립니다)

- **서버는 그대로** — 각자 파트의 계산 · 저장 · API 응답 꼴은 바꾸지 않습니다. 서버에서 고칠 것이 보이면 지금처럼 이슈로 드립니다.
- **화면은 얇게** — 각자 화면 파일에는 새 기능을 부르는 몇 줄만 두고, 새 기능은 새 파일에 둡니다(되돌리기 쉽게 · 충돌이 적게).
- **반영 전에 알림** — 각자의 기존 안내 이슈(#242 · #243 · #244)에 「무엇을 · 어느 파일 · 확인할 것 · 되돌리는 법」 을 더하고 댓글로 짧게 알립니다.
- **이미 「받지 않겠다」 고 한 것은 빼고** — 예: 일목균형표 · 매물대는 2차에 받지 않음 · KIS 모의투자결과 화면은 Figma 설계 뒤.
- **각자의 시험을 함께 돌립니다** — 내 PR 에서 여러분 파트 시험이 깨지지 않는지 같이 확인합니다.

## 반대 · 되돌리기

- 반대하시면 이 이슈나 각자 안내 이슈에 한 줄만 남겨 주세요 — 그 반영은 되돌리고, 이 방식도 다시 정합니다.
- 응답이 없다고 찬성으로 세지 않습니다. PR 은 머지 전에 각자 확인할 수 있게 링크를 드립니다.
