일일 러너에 단계 하나를 더해 주시길 부탁드립니다.

## 요약

- **무엇을** — #140 에서 만든 배치 `scripts/signals_daily.py` 를 러너 단계 `signals` 로 연결
- **왜** — 이 배치가 매일 돌아야 다중 주기 신호가 거래일마다 T2(`signal_snapshots`)에 쌓입니다. T2 는 ④-2 의견 변환(강민석 님)과 ①-5 설명의 입력입니다.

## 넣을 자리와 한 줄

`scripts/daily_update.py` 의 `STEPS` 에서 `ohlcv` 단계 바로 뒤(`manifest` 앞)에 넣어 주세요. 그날 일봉 · 60분봉이 들어온 다음에 돌아야 합니다.

```python
    Step("signals", ["scripts/signals_daily.py"], 10, fatal=False,
         label="신호", group="계산", desc="분봉 유니버스 401종목의 다중 주기 신호를 T2 에 기록"),
```

이름표 · 묶음 · 시간 한도는 예시입니다 — #139 의 규칙에 맞춰 바꿔 주셔도 됩니다.

## 배치가 하는 일

| 항목 | 값 |
|---|---|
| 대상 | 분봉 유니버스 `u2-20260930` 401종목 |
| 날짜 | 인자 없이 돌리면 수집 DB 의 마지막 거래일 하루 |
| 쓰는 곳 | 앱 DB(PostgreSQL · `.env` 의 `DATABASE_URL`) 의 `signal_snapshots` |
| 다시 돌리면 | 같은 날은 값만 바뀌고 줄이 늘지 않습니다 — 놓친 날은 `python scripts/signals_daily.py --date YYYY-MM-DD` 로 채웁니다 |
| 시간 | 401종목 20초 안팎(프로세스 넷) |
| 종료코드 | 0 성공 · 1 모든 종목 실패 · 2 그 날짜에 거래일 없음 · 3 앱 DB 에 연결하지 못함 |

앱 DB 가 꺼져 있으면 종료코드 3 으로 끝나므로, `fatal=False` 로 두면 뒤 단계(백업 등)는 그대로 돕니다.

## 연결 뒤 확인

```powershell
python scripts/signals_daily.py --dry-run          # DB 에 쓰지 않고 줄 수 · 신호 분포만 찍음 (401줄 안팎 · 오류 0 이면 정상)
python scripts/daily_update.py run --only signals  # 러너로 그 단계만 한 번
```
