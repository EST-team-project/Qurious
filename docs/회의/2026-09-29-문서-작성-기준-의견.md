**[Qurious] 산출물 문서 작성 기준 v0.1 — 의견 주세요 (제안)**

지금 산출물(API 명세서 · 테스트 계획서 · 설계서 등)이 제 작업 일지처럼 읽힌다는 걸 확인했어요. 제 작업 회차 번호 · 제가 붙인 용어(「다리」 「봉인」) · 발견 경위가 본문에 섞여 있습니다 — 15개 문서에 회차 번호만 383곳이에요.
그래서 실무 양식 25곳(Google 설계 문서 · ADR · OpenAPI · ISO 시험 · 요구사항 표준 · 행안부 지침과 공공 DB 서식 · 토스 테크니컬 라이팅 등)을 찾아보고 우리 문서의 틀을 정리했습니다.

📄 기준 문서: https://github.com/EST-team-project/Qurious/blob/main/docs/문서작성기준_v0.1.md
👀 5분 버전: 요약 → 3절(원칙 8개) → 9절(고치기 전 · 후 예시)

바뀌는 것 — 표 · 그림은 지금처럼 넉넉히 씁니다
- 문서 맨 위에 머리표 8칸과 「이 문서가 답하는 질문」
- 본문은 지금 상태만, 지나온 경위는 문서 끝 개정 이력으로
- 제 작업 용어 → 정식 이름 (다리 → 수집 DB 어댑터 등)
- 그림 · 표마다 「답하는 질문」 한 줄 · 번호 · 범례

💬 의견 받고 싶은 것 (문서 11절)
- 머리표 칸 수 · 상태 값(초안 / 검토 중 / 확정 / 대체됨)
- 판을 올리는 PR 에 그 문서를 읽고 일하는 파트가 댓글 한 줄로 검토 — 부담이 될까요?
- 용어 이름 · 개정 이력 위치(문서 끝 / 맨 앞)
「필요 없다 · 지금도 괜찮다」 도 답이에요.
