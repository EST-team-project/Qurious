--- 메시지 1 ---

**[알림] 데이터 수집을 화면 단추로 돌릴 수 있게 됐어요 — 앱 DB 에 표 둘(이전 0018)**

지금까지 수집(매일 12:30)은 제 PC 의 작업 스케줄러만 돌렸는데, 이제 관리자 화면 「수집 일정 · 단계」 에서 단추로 돌릴 수 있어요(서버 PR #148 · 화면 PR #155). 웹은 요청만 남기고 제 PC 의 작업자가 1분 안에 가져가 실행하는 꼴이에요.

- **앱 DB 에 표 둘이 생겼어요** — 수집 요청(`collect_requests`)과 PC 작업자 신호(`collect_workers`). alembic 이전은 `0018` 이고, 제가 곧 `0019`(빠진 날 채우기 요청)를 더할 거라 **새 이전을 만드실 분은 `0020` 부터** 써 주세요(#88 규칙).
- 각자 PC 는 `git pull` 뒤 앱을 다시 빌드해 띄우면 시작할 때 이전이 돌아요. 표는 비어 있고, 쓰지 않으면 그대로예요. 단추는 관리자 화면에만 있고 실제 수집은 제 PC 에서만 돌아요.
- 12:30 정기 회차는 그대로예요. 전체 수집 단추는 11:00 ~ 13:30 에 꺼져요 — 리밸런싱 하루 점검이 「오늘 12:30 뒤 시작한 회차」 를 보기 때문이에요(오준영 님 코드는 고치지 않았어요).
- 12:30 시각을 그대로 둘지, 리밸런싱 점검과 맞닿은 결함 후보 둘은 따로 이슈를 올려 의견을 모을게요.

--- 메시지 2 ---

**[의견 부탁] compose 의 포트를 이 PC 안(127.0.0.1)으로만 열지**

조사하다 보니 `docker-compose.yml` 이 앱(8966) · 앱 DB(15432) · Redis(16379) 를 **모든 주소**로 열고 있어요. 앱 DB 계정은 공개 저장소의 compose 에 그대로 적혀 있어서, 같은 와이파이 · 같은 망의 다른 기기가 우리 PC 의 앱 DB 에 붙을 수 있어요(Windows 방화벽이 막는지는 PC 마다 달라요).

제안: 포트 앞에 `127.0.0.1:` 을 붙여 각자 PC 안에서만 열기(예: `"127.0.0.1:15432:5432"`). 각자 브라우저 · DB 도구로 붙는 데는 지장이 없어요. 휴대폰 등 다른 기기에서 앱을 열어 보던 분이 있으면 그때만 막혀요.

하나 더 — 앱 컨테이너가 root 로 돌며 Docker 소켓을 붙이고 있어요(강사님 기초 코드의 LEAN 백테스트). 지금 바꾸자는 건 아니고, 배포를 정할 때 함께 보면 좋겠어요.

compose 는 모두가 쓰는 파일이라 의견을 듣고 고칠게요. 괜찮으면 👍, 다른 기기에서 앱을 써야 하면 말씀해 주세요.
