# 근거 번호가 달린 답과 로컬 LLM — 2026-10-03

> 팀 대화방(Discord)에 올릴 글이다. 메시지 둘 · 표 없음 · 메시지마다 2,000자 안.
> 올리는 때: 이 PR 이 머지된 뒤(링크가 main 의 문서를 가리킨다).

--- 메시지 1 ---

**근거 번호가 달린 답(RAG)이 서버에 붙었어요**

목표 기능 ①-3 「근거 문서와 출처를 포함한 RAG 질의응답」 의 서버 쪽이에요.
- `POST /api/kb/ask`: 2026년 시행 중인 법령 · 감독규정 조문만 찾아 넣고, 답 모델이 근거만으로 답하면서 문장마다 [출처 n] 을 달아요.
- 서버가 출처 번호를 다시 검사해요. 근거 목록에 없는 번호는 지우고, 맞는 번호가 하나도 없으면 답 대신 조문 발췌를 보여요.
- 근거를 못 찾으면 답 모델을 부르지 않고 「근거를 찾지 못했습니다」 로 답해요.
- 「주가가 오를까요」 「지금 사야 할까요」 같은 가격 예측 · 매수 권유 질문은 찾지 않고 돌려보내요.
- 답 아래 출처를 보이는 화면은 Figma 로 먼저 정한 뒤 붙여요.

함께 조사한 것이 있어요(docs/조사/ 새 폴더).
- 퀀트에서 LLM 을 조심하는 이유는 논문으로 확인돼요. 모델이 학습 기간의 지표 값 · 주가 움직임을 기억해서, 그 기간의 백테스트 성과는 실력인지 기억인지 가를 수 없어요.
- 그래서 LLM 은 예측기가 아니라 「그날 공개된 자료를 찾아 설명하는 창구」 로 쓰고, 계산 · 위험 · 체결은 코드가 맡는 쪽이 실무와 연구의 흐름이에요.
- 유료 API 없이 쓰는 법(Ollama · Hugging Face 의 GGUF), 한국어 공개 모델 라이선스, AWS 를 쓴다면 비용(Bedrock 토큰 값 · GPU 서버 시간)도 정리했어요.

조사서: https://github.com/EST-team-project/Qurious/tree/main/docs/조사

--- 메시지 2 ---

**정한 것 · 알려 드릴 것**

투자분석 기초 네 화면(거시경제 지표 · 산업 분석 · 재무제표 분석 · 기술적 분석)
- 요구 대장 · 계획서 역할표에 주인이 없던 화면이에요. 이동원이 기초 구현을 먼저 해 둘게요. 그 뒤에 각자 파트에 맞게 더하거나 바꿔 주세요(예: 기술적 분석은 지표 담당, 재무제표 분석은 스크리닝 담당). 의견 있으면 여기 남겨 주세요.

문서 그림
- 새 문서 그림은 Figma Design 파일에서 그려요(문서마다 페이지 · 그림마다 프레임). 팀 Figma 가 학생 요금제라 FigJam 은 페이지를 쓸 수 없어서예요. 이미 그린 FigJam 그림은 그대로 둬요.

채팅(AI 상담)의 문서 검색
- 채팅이 쓰는 문서 저장소는 지금 비어 있고, 채팅의 임베딩 방식(영어 모델)으로 같은 법령을 넣어 재 보니 한국어 질문의 정답을 거의 찾지 못했어요(Recall@5 0.026, 근거 검색은 0.868). 채팅이 근거 검색 · 답 API 를 도구로 쓰게 하는 쪽으로 정리할 생각이에요.

PC 에서 답 모델을 쓰려면
- 근거 답의 기본 모델은 qwen3:4b-instruct 예요(다섯 모델을 같은 질문으로 견줘 정했어요 · 근거 밖 질문에 지어낸 답 0). `ollama pull qwen3:4b-instruct` 한 줄(약 2.5GB)이면 되고, 없으면 조문 발췌로 답해요.
- Intel 노트북은 Ollama 가 내장 GPU 를 기본으로 빼 둬요. 사용자 환경 변수 OLLAMA_IGPU_ENABLE=1 을 넣고 Ollama 를 다시 켜면 팀장 PC 에서는 질문 읽기가 약 5배 빨라졌어요(조사서 4.4절).
