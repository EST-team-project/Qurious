## 2. 폴더 지도 (2026-10-22 번호 폴더)

```text

├─ phase-3/              3차(10-22 ~ 11-11)에 고치는 문서 — 판을 여기서 이어 올린다

│  ├─ 02-design/         설계 — system/(기능 설계 · 동작 원리 · 목표 기능 설계 · 대장/) · data/(ERD · 데이터 사전 · 대장/) · ui/(IA · UI 명세 · 와이어프레임) · api/(API 명세서 · 대장/)
│  ├─ 03-development/    개발 — conventions/(코딩 표준 · 코드 리뷰 기록) · data-collection/(데이터 수집 안내)
│  ├─ 04-testing/        테스트 — 테스트 계획서 · 백테스트 보고서 · 검증 기록 · 평가셋/ · 깨보기/ · 대장/
│  └─ 05-deployment/     배포 · 운영 — 배포 계획서 · 로컬 실행 안내서 · 릴리스 노트 · 장애 대응 절차서
├─ phase-2/              2차(10-01 ~ 10-21)를 닫은 판 — 얼림(바로잡기만 · 3.3절) · 같은 번호 00 ~ 05
│  └─ 06-retrospective/  2차 발표 — 발표자료.html(한 파일 판) · 발표자료-원본.html · 질의응답 · 그림/ · media/ · 준비/
├─ common/               차수와 상관없이 쌓이는 기록 — 같은 번호
│  ├─ 00-management/     meetings/(팀 대화방 글) · github-archive/(올린 이슈 · 댓글 · PR 본문 · 색인) · commit-map-2026-09-23.tsv
│  ├─ 01-analysis/       references/(제안요청서 rfp-1 · rfp-2 · 수업 노트 01 ~ 05 · 개념 노트 screening · tradingview)
│  ├─ 02-design/         adr/(설계 결정 기록) · contracts/(KIS 자동매매 API 계약) · references/(강사님 설계서 사본 onprem · pipeline) · img/(README 첫 그림 · 폴더 지도 그림) · supabase_schema.sql
│  └─ 06-retrospective/  videos/(시연 영상 — 앱 사용법 창 · 녹화 도구가 읽음) · til/(TIL)
├─ _git-drafts/          개인 git 초안 — git bash · 다음 세션 프롬프트 · 일회용 도구 · 실행 로그만 · 올리지 않는다(.gitignore · 3.3절)
└─ _local/               개인 로컬 자료(섹터 xlsx · 강의 양식 docx · git-drafts-개인/ · 외부원문/) — 올리지 않는다(.gitignore · 3.3절)
```

## 3. 이름 · 판 규칙

### 3.1 새 문서

3차 종류 폴더 맨 위(`phase-3/<번호>-<묶음>/<종류>/` — 04 · 05 는 번호 폴더 바로 아래)에 판 번호 없는 이름으로 만들고, 머리표에 `v0.1` 을 적는다. 산출물목록 0.1절에 한 줄을 더한다. 2차 폴더(`phase-2/`)에는 새 문서를 만들지 않는다(얼림 · 3.3절). 묶음 폴더 바로 아래(`02-design/` 처럼 종류가 여럿인 번호 폴더)에는 문서를 두지 않는다 — `docs_scan --bump` 가 멈춘다.

### 3.2 판 올리기 (다섯 단계)

| 단계 | 할 일 | 명령 · 확인 |
|:-:|---|---|
| 1 | 지금 파일을 `지난판/<이름>_v<지금 판>.md` 사본으로 만든다 | `python scripts/docs_scan.py --bump docs/phase-3/<번호>-<묶음>[/<종류>]/<이름>.md` — 사본은 한 칸 아래 폴더라 상대 링크를 새 자리에 맞춰 쓴다 |
| 2 | 같은 파일(판 없는 이름)을 고치고 머리표의 판 · 최종 수정 · 개정 이력을 올린다 | 큰 변화는 X.0 → (X+1).0, 작은 변화는 +0.1 |
| 3 | 산출물목록 0.1절의 판 칸을 고친다 | **다른 문서의 링크는 고치지 않아도 된다** — 최신을 가리키는 이름이 그대로라서 |
| 4 | 규칙 검사 | `python scripts/docs_scan.py --check` — 맨 위의 판 붙은 문서 0 · 짝 없는 지난판 사본 0 · 옛 자리(`docs/2차` · `docs/3차` · `docs/<옛 종류>` · 옛 맨 위 기록)에 남은 문서 0 |
| 5 | 원천이 있는 통합 문서면 동기화 점검 | 팀원 설계서를 옮기거나 가리키는 절이면(동기화 대장 `phase-3/01-analysis/requirements/대장/설계-동기화.tsv` 에 줄이 있다) 절 머리 「원천」 줄의 판을 맞추고 `python scripts/docs_scan.py --sync-ack <ID>` → `python scripts/docs_scan.py --sync` 오류 0 · 경고 0 — 원천이 올랐거나(경고 A) 판은 그대로인데 절 글이 바뀌었으면(경고 B) 읽고 옮길 일이다(머지는 막지 않는다) |

- **링크를 걸 때** — 같은 번호 폴더 안 3차 문서끼리는 `../ui/IA.md`, 다른 번호 폴더는 `../../04-testing/테스트계획서.md`(04 · 05 는 한 칸 덜), 2차 판은 `../../../phase-2/<번호>-<묶음>/<종류>/<이름>.md`, 그때의 판을 가리키려면 `지난판/<이름>_v<판>.md`.
- GitHub 글 · 대화방 글에는 지금 문서를 `…/blob/main/docs/phase-3/<번호>-<묶음>[/<종류>]/<이름>.md` 로 건다. 2026-10-22 전 주소는 7절 표로, 2차 최종 판은 태그 `phase2-final-2026-10-21`(그 태그 안에서는 옛 경로 `…/docs/<종류>/<이름>.md`)로 본다.
- 판 이름을 붙인 채 맨 위에 새 파일을 만들지 않는다. `--check` 가 잡는다.

### 3.4 2차에만 있는 문서를 3차에 고칠 때 (2026-10-21 · 경로 2026-10-22)

조사서 · 완료보고서처럼 3차 사본을 만들지 않은 문서는 고치기 전에 한 번 3차로 사본을 만든다.

1. `python scripts/docs_scan.py --to3 docs/phase-2/<번호>-<묶음>[/<종류>]/<이름>.md` — `phase-3/` 의 같은 자리에 사본이 생긴다. 상대 링크는 새 자리에 맞추고, 가리키던 2차 문서에 3차 사본이 있으면 3차를 가리킨다.
2. 3차 사본을 고치고 판을 올린다(3.2절 2 ~ 4). 산출물목록 0.1절에 그 줄이 없으면 더한다.
3. 2차 원본은 그대로 둔다(얼림) — 2차 판 전체는 태그 `phase2-final-2026-10-21` 로도 다시 본다.

## 7. 옮긴 자리 (2026-10-22 번호 폴더)

강사님 피드백(2026-10-22) — 「docs/2차 정리는 잘 했는데 폴더 별 넘버링부터 · 일반인은 업무 순서를 모르니 번호를 매기고, 분석 · 설계 · 테스트 밖의 자료 성격은 합쳐 7 ~ 8개로」. 사용자 결정은 세 가지다. 첫째, 일곱 묶음으로 합치되 합친 곳은 옛 종류를 하위 폴더로 둔다. 둘째, 이름은 실무 관행을 따른다 — 영어 소문자 · 하이픈 · 두 자리 번호이고, 번호 폴더와 바로 아래 종류까지만 영어다(그 아래 `지난판/` · `대장/` · `배경조사/` 와 파일 이름은 그대로). 셋째, 뿌리 기록 폴더까지 전부 옮긴다(`docs/common/`).
