## 3. 이름 · 판 규칙

### 3.1 새 문서

3차 차수 폴더의 종류 폴더 맨 위(`3차/<종류>/`)에 판 번호 없는 이름으로 만들고, 머리표에 `v0.1` 을 적는다. 산출물목록 0.1절에 한 줄을 더한다. 2차 폴더에는 새 문서를 만들지 않는다.

### 3.2 판 올리기 (네 단계)

| 단계 | 할 일 | 명령 · 확인 |
|:-:|---|---|
| 1 | 지금 파일을 `지난판/<이름>_v<지금 판>.md` 사본으로 만든다 | `python scripts/docs_scan.py --bump docs/3차/<종류>/<이름>.md` — 사본은 한 칸 아래 폴더라 상대 링크를 새 자리에 맞춰 다시 쓴다(손으로 복사하면 링크가 모두 한 단계 어긋난다) |
| 2 | 같은 파일(판 없는 이름)을 고치고 머리표의 판 · 최종 수정 · 개정 이력을 올린다 | 큰 변화는 X.0 → (X+1).0, 작은 변화는 +0.1 |
| 3 | 산출물목록 0.1절의 판 칸을 고친다 | **다른 문서의 링크는 고치지 않아도 된다** — 최신을 가리키는 이름이 그대로라서 |
| 4 | 규칙 검사 | `python scripts/docs_scan.py --check` — 맨 위의 판 붙은 문서 0 · 짝 없는 지난판 사본 0 · 옛 자리(`docs/<종류>/`)에 남은 문서 0 |

- **3차 사본의 첫 판 올리기** — 3차 사본은 2차 최종 판과 같은 판 번호로 시작한다(링크만 새 자리). 3차에서 처음 판을 올리면 `3차/<종류>/지난판/` 이 생기고, 그 사본은 2차 최종 판과 내용이 같다.
- **링크를 걸 때** — 최신을 가리키려면 판 없는 이름(`../시험/테스트계획서.md` — 3차 문서끼리), 2차 판을 가리키려면 `../../2차/<종류>/<이름>.md`, 그때의 판을 꼭 가리켜야 하면 지난판 사본.
- GitHub 글 · 대화방 글에는 지금 문서를 `…/blob/main/docs/3차/<종류>/<이름>.md` 로, 옮기기 전 2차 판을 `…/blob/phase2-final-2026-10-21/docs/<종류>/<이름>.md`(태그 — 영원히 열림)로 건다.
- 판 이름을 붙인 채 맨 위에 새 파일을 만들지 않는다. `--check` 가 잡는다.

### 3.4 2차에만 있는 문서를 3차에 고칠 때 (2026-10-21)

조사서 · 완료보고서처럼 3차 사본을 만들지 않은 문서는 고치기 전에 한 번 3차로 사본을 만든다.

1. `python scripts/docs_scan.py --to3 docs/2차/<종류>/<이름>.md` — `3차/<종류>/<이름>.md` 가 생긴다. 상대 링크는 새 자리에 맞추고, 가리키던 2차 문서에 3차 사본이 있으면 3차를 가리키게 바꾼다(없으면 2차 그대로).
2. 3차 사본을 고치고 판을 올린다(3.2절 2 ~ 4). 산출물목록 0.1절에 그 줄이 없으면 더한다.
3. 2차 원본은 그대로 둔다(얼림) — 2차 판 전체는 태그 `phase2-final-2026-10-21` 로도 다시 본다.

## 6. 옮긴 자리 (2026-10-21)

옮긴 파일이 899개라 하나하나 적지 않고 규칙으로 적는다. 옛 주소의 새 자리는 아래 <표 6-1> 로 바꿔 읽는다(파일 이름 · 하위 폴더는 그대로).

**<표 6-1> 옮긴 자리 — 규칙 다섯**

| 옛 자리 | 새 자리 | 무엇 |

| `docs/<종류>/…`(종류 12 — 계획서 · 요구사항 · 설계 · 데이터 · 인터페이스 · 화면 · 시험 · 조사 · 배포 · 개발 · 문서기준 · 데이터수집) | `docs/2차/<종류>/…` | 모두 — 2차를 닫은 판(얼림) |
| `docs/발표/2차/…` | `docs/2차/발표/…` | 펼침 — 차수를 한 번만(덱 · 질의응답 · 그림 · media · 지난판) |
