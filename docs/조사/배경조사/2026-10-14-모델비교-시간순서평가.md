## 3. 조사 (원문 · 조회일 2026-10-14 · 확실도)

용어 풀이(처음 나오는 곳):

- **겹(fold)** — 교차검증에서 자료를 나눈 한 조각. 이 문서에서는 「시험 겹」(평가에 쓰는 구간)과 「학습 겹」(그 앞 구간)을 말한다. 헷갈리는 점: 시간 순서 검증에서는 겹마다 학습 구간 길이가 다르다(앞 겹일수록 짧다).
- **워크포워드(walk-forward) · 확장 창** — 과거 구간으로 학습하고 바로 뒤 구간으로 시험한 다음, 시험한 구간을 학습에 더해 앞으로 한 칸 나아가는 방식. scikit-learn `TimeSeriesSplit` 이 이 꼴이다. 헷갈리는 점: 「롤링 창」(학습 길이 고정)과 다르다 — `max_train_size` 를 주면 롤링 창이 된다.
- **간격(gap) · 퍼지(purge)** — 학습 구간 끝과 시험 구간 사이에서 버리는 행. 라벨이 앞날 여러 날을 보는 경우(여기서는 5거래일) 학습 끝 몇 행의 라벨이 시험 구간 가격으로 만들어져 정답이 새기 때문이다. 이 문서에서는 `TimeSeriesSplit(gap=…)` 으로 구현한다.
- **엠바고(embargo)** — 시험 구간 **뒤** 학습 행을 더 버리는 것. 학습이 시험 뒤 자료도 쓰는 K겹(purged K-fold)에서만 필요하다. 워크포워드는 학습이 늘 시험 앞이라 엠바고가 할 일이 없다(헷갈리기 쉬운 점).
- **기준선(baseline)** — 특징을 보지 않거나 아주 단순한 규칙으로 맞히는 비교 대상. 모델이 이것을 넘지 못하면 「배운 것이 없다」 고 읽는다.
- **균형 정확도(balanced accuracy)** — 계층마다 맞힌 비율(재현율)을 낸 뒤 평균한 값. 3계층이면 무작위 · 늘 같은 답이 1/3 이 된다. 헷갈리는 점: 보통 정확도와 달리 「관망」 이 많은 종목에서 「늘 관망」 이 높은 점수를 받지 못한다.
- **다중 비교** — 여러 모델을 같은 자료로 한꺼번에 견주면 실력이 없어도 하나쯤은 우연히 좋아 보이는 문제. 홀름 보정은 p 값을 비교 수만큼 엄격하게 하는 방법(가장 작은 p 부터 남은 비교 수를 곱하고, 앞 값보다 작아지지 않게).

1. 겹은 시간 순서로만 나눈다(R1 · R9) · 간격은 라벨 기간 이상(R3 · R4) · 앞날이 없는 마지막 행은 라벨을 만들지 않는다(R4 · <표 1> 목표 줄).
2. 전처리는 학습 겹에서만 맞춘다(R5) — `Pipeline`.
3. 기준선을 같은 겹 · 같은 행에서 함께 계산하고(R6 · R7), 대표 지표는 균형 정확도(R10).
4. 「낫다」 는 기준선과 같은 행으로 짝지어 비교하고, 이웃 행이 겹치는 만큼 블록으로 다시 뽑고, 모델 수만큼 보정한다(R11 · R12 · R14). 순위 하나로 단정하지 않는다(강사님 피드백 「결론 집착 금지」).

## 4. API v2 설계

### 4.1 경로 · 파일

- 새 경로 **`GET /api/model-compare`** — 새 라우터 `app/routes/model_compare.py` · 계산 · 문장 · 기준값은 서비스 한 곳 `app/services/model_compare.py`.
- 강사님 `GET /api/ml/compare` 는 **그대로 둔다**. 계절성(`/api/seasonality`) · 종목 군집화(`/api/clusters`)가 강사님 길을 두고 새 길로 화면만 옮긴 것과 같은 꼴이다(`app/routes/clusters.py:6-7`).
- 라우트는 `asyncio.to_thread` 로 계산을 돌리고(`clusters.py:32` 와 같음), 오류는 `ModelCompareError(status, message, hint)` → `HTTPException(detail=e.detail(admin))` — 할 일(hint)은 관리자 답에만.
- 자료는 **수집 DB 일봉(수정주가)만** 읽는다. 없으면 KIS · Yahoo 로 말없이 넘어가지 않는다 — 그래야 `data_source` 가 늘 `collector` 다(정할 것 2).
  주의 — `collector_db.get_daily_candles`(`stock.get_candles` 의 첫 단계 · `stock.py:281`)는 DB 가 없을 때도 종목이 없을 때도 `None` 을 돌려준다(`collector_db.py:26-29 · 164-193`). 그래서 라우트는 먼저 `collector_db.db_path()` 가 `None` 이면 503(「시세 자료를 지금 읽을 수 없습니다」 · 관리자에게만 경로 할 일), 그다음 `None` 이면 404(「수집 자료에 없는 종목」)로 나눈다. 다른 길 — `data_ohlcv.read_ohlcv(…, "1d", basis="adj_base")` 는 404 · 503 · 422 를 `OhlcvError` 로 나눠 주지만 줄 모양(`trade_date` …)이 캔들과 달라 바꿔 담는 몇 줄이 든다.
  `time` 은 그날 00:00 UTC 유닉스 초(`collector_db.py:17`) — 시제품은 KST 날짜로 바꿔 같은 날짜를 얻는다. 수집 시작이 2020-01-02 라 `5y` 까지는 꽉 차고 그보다 길면 2020-01-02 부터다.

### 4.4 XAI(신장환 님 파트)와의 경계 — 팀 글 초안

## 5. 화면 세 안 (글 · Figma 는 메인)

세 안 모두 맨 위에 서버 `headline` 한 문장 · 아래에 `data_as_of` · `data_source` · `notice`(「과거 성과는 앞으로의 수익을 보장하지 않습니다. 투자 권유가 아닙니다.」)를 둔다. 숫자 · 차트 · 쉬운 말 근거를 한 덩어리로 묶는다.

- **A 순위표 + 기준선 줄** — 행 = 모델 8개(균형 정확도 순). 칸 = 균형 정확도 · 겹별 흩어짐(최소 ~ 최대 작은 막대) · 기준선과 차이(± · 95% 구간) · 판정 글 · 「1등 묶음」 표시 · 학습 점수(외움 경고). 표 안에 **기준선 셋 줄을 굵은 선**으로, 무작위의 겹별 범위를 「우연 띠」 로 깐다.
  장점 — 익숙하다 · 표 보기(접근성)로도 남는다. 단점 — 순위가 먼저 보여 「1등」 에 눈이 간다(결론 집착).
- **B 겹별 점 그림 + 구간** — 가로 = 균형 정확도, 세로 = 모델 8 + 기준선 4. 겹마다 점 5개 · 합친 값은 마름모 · 기준선과의 차이 95% 구간은 가로 막대. 세로선 = 가장 강한 기준선 · 옅은 띠 = 무작위 범위(1/3 언저리). 위에 **겹 띠 그림**(학습 파랑 · 시험 빨강 · 간격 회색 · 날짜 — R16 꼴)으로 「과거로 배우고 바로 뒤로 시험」 을 보인다.
  장점 — 흩어짐 · 불확실성이 정직하게 보인다. 단점 — 비전공자에게 낯설다.
- **C 요약 카드 + 「왜 이 결과인가」** — 카드 셋: 「기준선을 뚜렷이 넘은 모델 0/8」 · 「가장 높았던 기준선 · 그 점수」 · 「시험한 날 395일 · 기간」. 아래 펼침 「왜?」 — ① 정확도의 함정(늘 같은 답의 정확도 43% vs 균형 정확도 35%) ② 외움(RandomForest 학습 100% → 시험 32%) ③ 우연 띠(무작위도 겹에 따라 34 ~ 45%) — 각 문장 옆에 작은 막대 그림.
  장점 — 비전공자가 바로 읽는다. 단점 — 자세한 숫자가 숨는다.

추천 — **C 를 위에, B 를 「자세히」 펼침으로, A 를 「표로 보기」 전환으로** 한 화면에 둔다(숨기지 않고 구조로 보이기). 예시 숫자는 합성 자료 견본(6절)이다 — 실제 종목 숫자가 아니다.
