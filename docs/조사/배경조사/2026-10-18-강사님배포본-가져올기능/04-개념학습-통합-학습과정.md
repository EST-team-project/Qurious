## 요약 5줄

1. iv 「통합 학습 과정」 10단원은 우리가 이미 싣는 두 원천(투자분석 교재 문서 · domain-rag-lab 이론 데이터)을 10단원으로 다시 배치한 판이다. 쪽 제목 685 중 663(97%)이 같고, 새 글은 쪽 맨 위 「핵심 요약」 10블록(약 3,200자)뿐이다(10-17 조사 <표 5>).
2. multi-db-lab 중급 과정은 기술 노트 18편(파이썬 문법을 주제별로)이다. 10-13 결정대로 새 부 「파이썬 중급」 6장(C1101 ~ C1106) + 새 장 C605 로 다시 쓰며, 장 대장에는 아직 한 줄도 없다.
3. 우리 개념 학습은 따로 된 HTML(`/learn/` · 장 35파일 = 완성 7 · 뼈대 28)이고 앱에서는 새 탭으로만 간다(들어가는 곳 다섯). 「따로 있어서」 보다 「달라 보이고 이동이 끊겨서」 부자연스럽다는 10-06 조사 판정이 그대로 맞다.
4. 앱 안 통합은 세 단계로 나누는 것을 추천한다. 2차(10-20 까지)는 같은 탭 · 같은 머리 · 같은 색 토큰(작은 일 · 영상 일곱에 학습 쪽이 나오지 않아 다시 찍을 것이 없음), 3차 (바)는 앱 안 읽기 화면(안 C′), 3차 (사)는 장 본문이다.
5. 2차 안에 다 넣을 수는 없다. 10-19 · 20 칸은 발표 자료 · 영상 · 문서 · 리허설로 차 있어, 새 몫은 약 3시간 안이 현실적이다. 넣을 것 넷과 빼는 차례를 6절에 두었다(메인이 사용자에게 묻는다).

## 4. 앱 안 통합 안 — 조사서 안 C 와 견줌

| 안 | 무엇을 | 일(어림) | 사용자 말과 | 위험 |
|---|---|---|---|---|
| 조사서 A(전부 앱 안) | `/learn/` 의 모든 길을 앱 화면으로 · 따로 된 쪽 없앰 | 큼 · 3 ~ 5세션 | 가장 가까움 | 두 해시 길을 합침 · `learn.css` 전역 규칙이 앱으로 번짐 · 편집기 · 팀 자료까지 옮김 |
| 조사서 C(추천했던 안) | 공용 셸(`tokens.css` · `shell.js`) · 학습은 앱 안 입구를 늘림 · API 문서는 관리자만 | 중간 · 2 ~ 3세션 | 「디자인 맞춤」 은 됨 · 「통합」 은 반쯤 | 셸이 모든 화면에 닿음(팀 글 먼저) |
| **C′(이번 추천)** | C 의 첫 단계(같은 탭 · 같은 머리 · 토큰 한 벌) + **앱 안 읽기 화면** 하나(왼쪽 = 장 목록 · 본문 = 장 읽기) · 쓰기 · 편집기 · 찾기는 `/learn/` 에 남김 | 2차 작은 단계 1.5 ~ 2시간 + 3차 1 ~ 2세션 | 읽는 사람에게는 앱 안 · 쓰는 사람(팀)에게는 지금 편집기 | 라이브러리 넷을 앱 첫 로딩에 넣지 않게(읽기 화면을 처음 열 때 싣기) |

C′ 를 추천하는 까닭은 셋이다. 사용자가 원한 것은 「읽는 화면이 Qurious 안에 있고 같은 디자인」 이며, 편집기 · 팀 자료(HF 저장 · 로그인)는 읽는 사람이 거의 쓰지 않는다. 02 문서 안 가(왼쪽 전체 트리)와 붙이면 「배우기」 묶음 아래에 장 목록이 그대로 들어간다. 따로 된 쪽(`/learn/`)을 남겨 두면 지금 시험 · 바깥 링크가 깨지지 않는다.
