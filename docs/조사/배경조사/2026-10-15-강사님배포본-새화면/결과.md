## 맨 위 — 요약 5줄 · 메인이 확인할 것 · 정할 것

### 요약 5줄

1. **메뉴**: 강사님 최신 판은 위 메뉴를 **탭 넷**(로보 어드바이저 · 투자 인디케이터 · 전략설정 · 수익율검증)으로 줄이고 나머지 아홉 묶음을 「더보기」 접이식에 넣었다(13묶음 55항목 · 배포본 DOM 도 같음 · `public/js/core.js:6-127` · `public/app.html:35-40`). 묶는 원칙은 「두 프로젝트 + 설정 → 검증 순환」 이고 화면끼리 「전략설정에서 바꾸기」 같은 다음 할 일 단추로 이어진다 — 우리(13묶음 74항목 · 위 탭 10)가 받은 「기능 나열」 피드백의 본보기다. 다만 390 폭 탭 · 로그아웃 겹침, 13칸 표 넘침, 방안 카드 깨짐이 보여 꼴 그대로는 아니다(확실도 중간 — 원칙은 추론).
2. **새 화면 · 기능 26개**를 우리 앱과 견주면 **없음 11 · 다름 15 · 같음 0** 이다(<표 4>). 가장 큰 새것 셋 — **전략설정**(봇 운영 모드 셋 · 칸마다 기본값 · 범위 · 설정 프로필) · **설정별 성과** · **수익률 검증 · 개선 가이드**(일별 평가액 · 승률 · 손익비 · 기대값 · 진단 카드 · 방안 A/B/C 승인) — 은 자동매매 직접 전략 · 투자 성향(D89) · 강민석 님 2차 ④ 성과 해석과 바로 겹친다. 식 편집기 「숫자만 바꿔 조건 만들기」(`5b6fc9a`)는 실사용자 피드백 D90-7(조건을 쉽게 거는 꼴)의 직접 답이다.
3. **「어떻게 쓸 계획인가」**(<표 5>): ① 그대로 2 · ② 가져와 커스터마이징 7 · ③ 주담당 이슈 11 · ④ 안 가져옴 6. 이동원 몫은 사용법 모달(2차 전 · 작음) · 기업 대시보드 DART 근거 줄 · 섹터 인디케이터 · 비교 트레이 · 메뉴 원칙(리팩터링 세션) · 국내 종목 범위 규칙(3차-1) · 진단 카드 꼴 · 개념 글 · 필수 자료 시험이고, 팀원 몫은 오준영 셋 · 신장환 셋 · 강민석 넷 · 둘이 함께 하나(주문 주체)다(5절). 대시보드 상태 카드 · 위험 한도 칸처럼 **우리가 이미 사용자별로 가진 것**은 강사님의 전역 꼴을 받지 않는다.
4. **3-way 위험**: 기준점 뒤 바뀐 186파일 중 **우리도 고친 51파일**이 겹친다(`app.html` +688/−224 · `core.js` +234/−49 · `app.css` · `main.js` · `app/main.py` · `auto_trade.py` · `stock.py` · `celery_app.py` 등 · `3way-파일대조.tsv`). 기초 코드 지킴이 22개(`tests/test_base_code_merge_guard.py` · `def test_` 22)가 메뉴 · 31종목 · 600초 · 바깥 CSS · 사용자 키 주문 · 수집 DB 우선을 이미 막지만, **상태를 바꾸는 새 라우트의 관리자 제한 · 사용자 응답의 IP · 브라우저 정보 · 15:40 스냅샷 중복 · 피할 낱말 · 더보기 목록 하드코딩 · alembic 번호 · 1분 전 종목 스캔 예약** 지킴이는 없다(4절 G1 ~ G7).
5. **다른 세 저장소**: 같은 기능이 있는 곳은 th07 전략 스펙 · 판 이력(전략설정 ② 모드가 부르는 원천) · th03 OHLCV 저장소 표본 · KIS 게이트웨이(평가액 원천) 정도다. lumina 표 밖 새것은 **th03 HTS 시뮬레이션 + 관심 종목 메모 표**(D96 · D97 의 본보기) · th03 ReAct 에이전트 · TradingView 통합 차트 · th24 Lex 챗봇이다. 강사님은 네 사이트를 이미 공통 CSS 한 벌(pr · fd · st · iv — `shared-css/README.md`)과 같은 계약서로 묶어 운영하므로, 「융합」 은 **lumina 를 셸로 두고 부르는 쪽 → 불리는 쪽 차례로 읽는** 꼴이 맞다(6절 · 정할 것 1).
