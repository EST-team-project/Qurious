## 요약

1. 네 여정(A 로보 · B 직접 모의투자 · C 자동매매 · D 근거)을 실제로 밟았다 — 24걸음에서 끊긴 곳 21(🔴 3 · 🟡 13 · 🟢 5). 주담당별: 오준영 7 · 강민석 7 · 이동원 5 · 신장환 2.
2. 가장 큰 끊김은 「돈이 어디 있나」 — 모의 장부가 셋(모의투자 계좌 1억 · 퀀트 가상 장부 1천만 · KIS 모의 계좌)인데 화면마다 섞이거나 어긋난다. 12:32 기준 KIS 모의 계좌 1종목 vs 자동매매 가상 장부 3종목.
3. 🔴 셋 — 대시보드 계좌 칸이 「불러오는 중」 에서 멈춤(강민석) · KIS 모의인데 설정 화면이 「실전투자 (Live)」(오준영) · 자동매매가 KIS 주문 실패(토큰 403)를 「🟢매수」 로 보임(오준영).
4. 여정 A(진단 → 배분 → 상품 안내 비중 자동)는 끝까지 이어진다. 끊기는 곳은 그다음 — 상품 상세 · AI 상담에서 모의 주문 · 앱 신호로 가는 길이 없다(이동원 고칠 목록).
5. 같은 종목(신한지주)을 분석 화면 넷은 「매도」, 자동매매는 「매수」(실제로 두 번 삼) — 판단 출처를 말하는 화면이 없다(신장환 · 논의).

## 확인할 것

1. ⚠️ **자동매매가 점검 계정에서 점검 전부터 켜져 있다** — live · KIS 모의(Testbed) · 10분 주기 · 1회 투자금 30만 원 · 모델 선정 3종목 · 11:55 에 켜진 것으로 보인다. 나는 켜지도 끄지도 않았다(설정 화면이 「실전투자 (Live)」 라 점검 기준대로 멈춤). **12:30 회차가 KIS 모의 서버에 신한지주 3주 매수를 실제로 접수**했고(응답 「모의투자 매수주문이 완료 되었습니다」 · 12:32 KIS 모의 계좌 1종목 285,000원), 30분 쿨다운이 풀릴 때마다 다시 주문이 나갈 수 있다. 끌지는 사용자에게 물어 정할 것(아래 정할 것 1).
2. **실거래는 아니다** — 주문 주소 openapivts(모의) · 응답 「모의투자 …」 · `environment: "paper"` · `route_detail: "KIS 직접 호출(내 키) → 모의(Testbed)"`. 실거래 관문 · 환경 변수 · `.env` 는 건드리지 않았고 읽지도 않았다. 다만 화면 낱말이 「실전투자 (Live)」 라 이슈 02 로 넘긴다.
3. **KIS 토큰 403** — 11:55 주문 3건 · 12:30 두 번째 주문 · 내 연결 테스트 2회 모두 `/oauth2/tokenP` 403. 12:30:57 재시도는 내 「자동매매 회차 피하기」 조건에 빈틈이 있어 회차(12:30:54 토큰) 3초 뒤에 겹쳤다 — 그 회차의 403(12:30:55)은 내 호출보다 앞이라 영향은 없다. 12:26:06 의 403 은 바로 앞 증권사 호출과 3분 떨어져 있어 까닭 미확인(서버의 다른 작업이 토큰을 받았을 수 있음). 내 증권사 호출은 5회 · 모두 65초 이상 띄움(5절).
4. **값 가림** — 걸음 기록 · 응답 발췌는 키 · 계좌번호 · 주문번호 · 사용자 ID 를 `***` 로(정규식 재검사 0건). 캡처는 설정 화면의 App Key · Secret · 계좌번호 칸을 회색으로 덮고, 화면 글의 이메일 · 계좌 꼴 숫자를 바꿨다. 옮기기 전에 캡처 27장 가운데 `C1-*` · `E1-*` · `B1-*` 세 장은 눈으로 한 번 더 봐 줄 것. 도우미 스크립트에는 점검 계정 값을 적지 않았다(실행할 때 `tests/e2e/howto_dialog.py` 에서 읽음).
5. **내가 한 쓰기** — 진단 1 · 배분 계산 저장 1 · 모의 주문 2(앱 안 모의투자 장부 · 매수 → 매도 · 비용 약 6원). 리밸런싱은 「가져오기」 까지만(플랜 저장 안 함). 자동매매 시작 · 중지 · 비상 정지 · 「🧪 데모 데이터」 · 계좌 초기화 · 포트폴리오 추가 · 삭제는 누르지 않았다.
6. **수집 DB 는 열지 않았다** — 앱 화면 · API 만 썼다. git 은 읽기만.
