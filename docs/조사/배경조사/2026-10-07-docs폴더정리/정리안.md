### 2.2 하위 폴더 — 종류마다 한 곳

| 하위 폴더 | 담는 것 | 판 |
|---|---|---|
| (종류 폴더 맨 위) | 문서마다 **판 번호 없는 이름 하나** — 머리표의 판이 최신 | 머리표 · 개정 이력 |
| `지난판/` | 지난 판 사본 — `<이름>_v<판>.md` · 한 번 넣으면 고치거나 옮기지 않는다 | 이름에 |
| `대장/` | 표(TSV)로 된 정본 대장 — 요구 · 시험-요구 · API ID · 표 속성 · 반입 · 이식 · 점검표 | 없음(한 파일을 고쳐 간다) |
| `평가셋/` (시험) | 평가셋 · 사람 판정 · 표본 밖 TSV | 이름에(코드가 판 이름으로 읽는다) |
| `내보내기/` (계획서) | 다른 형식으로 낸 사본(docx) | 이름에 |
| `img/` | 그림 PNG · SVG | 이름에(그림 판) — 옮기지 않는다 |

### 2.3 판 올리는 법 (정리 뒤)

1. 지금 파일을 `지난판/<이름>_v<지금 판>.md` 로 **복사**한다.
2. 같은 파일을 고치고 머리표의 판 · 최종 수정 · 개정 이력을 올린다.
3. 산출물목록의 판 칸을 고친다. **다른 문서의 링크는 고치지 않아도 된다**(이름이 그대로라서).
4. `python docs_reorg.py --check`(S97 에 `scripts/` 로 옮길 후보) — 맨 위에 판 붙은 문서 0 · 새로 깨진 링크 0.

## 4. S97 순서

1. `git pull --ff-only` · 팀원 브랜치가 docs 를 건드리나(받아 둔 참조) — 겹치면 멈추고 묻는다.
2. `python docs_reorg.py --plan` 을 **S96 머지 뒤 트리**로 다시 — 부딪힘 0 · 줄 수 확인.
3. `--apply` 를 더한다 — ① 옮김(파일만 · git 명령 없이) ② 링크 고쳐 쓰기(옛 자리 기준으로 대상을 풀고 새 자리 기준으로 다시 씀) ③ 코드 경로(3.2) ④ `docs/README.md` 옮긴 자리 표.
   먼저 **사본**(`git ls-files` 로 추린 파일을 scratch 에 복사)에 돌려 `--check` 가 새로 깨진 링크 0 인지 본다.
4. 실제 저장소에 적용 → `--check`(새로 깨진 링크 0 · 코드 경로 0 · 맨 위 판 붙은 문서 0) · `pytest -q`(관련: completion_badge · schema_scan · post_check · learn · kb 평가 시험) · `rtm_scan` · `api_scan` · `schema_scan` · `raglab_scan` 의 `--check` · `post_check`.
5. 문서: `docs/README.md`(폴더 지도 — Figma 그림 한 장 · 전후 트리) · 문서 작성 기준 v0.3(이름 · 판 규칙 2.2 · 2.3) · 산출물목록(경로 칸 · 이 결정) · `AGENTS.md` · `CLAUDE.md` 의 docs 경로 · 갱신 대장 · TIL.
6. 팀 대화방 안내 파일 `docs/회의/2026-10-0X-문서-폴더-정리.md`(아래 5절 초안 · 2,000자 안).
7. git bash 블록 하나 — 브랜치 `docs/reorganize-by-kind` → `git add -A docs` + 3.2 의 코드 파일 → 커밋(옛 경로 · 새 경로를 함께 담아 git 이 이름 바꿈으로 읽게) → push(GitHub · GitLab) → PR.
   커밋 전에 `git status --short | grep -v '^R'` 로 이름 바꿈 아닌 변경을 한 번 훑는다.
