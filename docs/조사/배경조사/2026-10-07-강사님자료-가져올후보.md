「없는 구간 받아 적재」 를 앱에서 하면 생기는 충돌:
1. **쓰는 곳이 둘이 된다.** 앱은 수집 DB 를 `mode=ro` 로 열고 도커는 읽기 전용으로 붙인다(DF-08 설계). 쓰는 곳이 러너 하나라 잠금(`daily_update.lock`) · 회차 기록 · 「한 단계 다시」 의 막는 때가 성립한다. SQLite 는 쓰는 연결이 하나뿐이라, 12:30 ~ 13:30 에 앱이 upsert 하면 러너와 잠금을 다툰다.
2. **수정주가는 통째로 다시 만든다.** 원시 일봉(`price_daily`)이 들어오면 `collector.rebuild_adjusted` 가 그 앞 전체의 계수를 다시 쓴다. 야후 봉을 수정주가 표에 끼우면 계수 사슬 · 매니페스트 지문 · HF `krx-ohlcv` 보관본이 어긋난다.
3. **출처가 섞인다.** 수집 DB 에는 행마다 출처 칸이 없다. 야후 행이 섞이면 공공데이터포털 자료라는 전제(지문 · 보관본 · 「공개 저장소 · 발표엔 원자료 없음」 원칙)가 깨진다.
4. **강사님도 섞으려고 원시 종가로 내려갔다.** 우리가 수정주가를 지키면서 섞을 방법은 없다.

빈 구간은 이렇게 나눠 다루면 된다:
- **앞(2020-01-02 이전)** — 포털이 2020-01-02 부터라 앱이 메울 수 없다. 더 길게(KRX 2010-01-04 ~) 받는 것은 출처 · 인증키 · 이용 조건 결정(#31 · D5)이지 백테스트가 부를 때 받는 일이 아니다. 응답에 `first_date` 를 싣고 화면이 「요청한 10년보다 짧다」 고 밝힌다(후보 A).
- **뒤(마지막 봉이 며칠 전)** — 12:30 러너 몫이다. 응답의 `as_of` 와 데이터 관제 판정(최신 · 정상 · 늦음 · 멈춤)으로 보인다.
- **수집 DB 밖 종목(지수 · ETF · 해외)** — 지금처럼 야후 경로로 · 저장하지 않음 · 응답 `source` 로 「외부 시세」 표시.
- **손으로 메울 빈 날** — 「자료 직접 받기」 의 받을 범위로 넘기고 받는 것은 수집기 명령이 한다(후보 D). 이것이 「없는 구간 받아 적재」 의 우리 판이다.

```python
def span(data: dict | None) -> dict:
    """일봉 응답(`get_candles` 모양)의 자료 출처 · 첫 봉 · 마지막 봉 · 봉 수.

    백테스트처럼 일봉을 받아 다시 계산하는 응답이 「어떤 자료로 언제부터 언제까지」 를 함께 싣게 한다
    (DF-08 이슈 D-1 · API 명세서 F6). 수집 DB 는 2020-01-02 부터라 「10년」 요청도 약 6.8년이다.
    - source: "collector" = 수집 DB(수정주가) · "external" = 옛 경로(지수 · ETF · 해외 · 수집 DB 가 없는 PC)
    - as_of: 다리가 준 값이 있으면 그것, 없으면 마지막 봉 날짜(옛 경로)
    """
    data = data or {}
    candles = data.get("candles") or []

    def day(t) -> str:
        return datetime.fromtimestamp(int(t), tz=timezone.utc).strftime("%Y-%m-%d")

    return {
        "source": data.get("source") or "external",
        "first_date": day(candles[0]["time"]) if candles else None,
        "as_of": data.get("as_of") or (day(candles[-1]["time"]) if candles else None),
        "rows": len(candles),
    }
```
