> **이 문서로 알 수 있는 것**
> 1. 근거 답이 「근거에 있는 말만 했는가」 를 자동으로 재는 지표에는 무엇이 있고, 정확한 이름은 무엇인가?

> **읽는 순서** — 팀원: 요약 → 3절 · 강사님: 요약 → 2절 · 처음 온 사람: 부록 B 용어 → 요약

## 요약

1. **근거 충실도를 재는 대표 지표는 Ragas 의 `Faithfulness` 다.** 답을 주장(claim)으로 쪼갠 뒤, 찾은 근거로 뒷받침되는 주장의 비율을 낸다(「근거로 뒷받침되는 주장 수 ÷ 답의 주장 수」 · Ragas 공식 문서). 입력은 `user_input`(질문) · `response`(답) · `retrieved_contexts`(근거) 셋이고, 주장 쪼개기와 확인을 **심판 LLM** 이 한다.
2. 이 PC 에 깔린 Ragas 0.4.3 에서 지표는 `ragas.metrics.collections` 아래 39개 클래스다. 근거 충실도와 직접 닿는 것은 `Faithfulness` · `ResponseGroundedness`(NVIDIA · 두 심판 프롬프트의 0 ~ 2 점 평균) · `QuotedSpansAlignment`(답 안 따옴표 인용이 근거에 그대로 있나 · LLM 없음) · `NoiseSensitivity`(관련 없는 근거에 흔들리나) 넷이다. `ragas.metrics` 에서 바로 가져오는 길은 v1.0 에서 없어진다고 경고가 뜬다(설치된 코드 실측).
3. **LLM 없이 도는 `FaithfulnesswithHHEM` 은 우리 답에 맞지 않는다.** 바탕 모델 HHEM-2.1-Open 은 영어 전용이고(모델 카드), 한국어를 지원하는 HHEM-2.3 은 상용이다.
4. **심판 LLM 을 로컬 소형 모델로 두면 심판 자체를 믿을 근거가 먼저 필요하다.** 그래서 우리 순서는 ① 사람 판정 20(정답 · 부분 · 지어냄)을 기준으로 두고 ② 같은 20 에 자동 지표를 돌려 사람 판정과 얼마나 맞는지 잰 다음 ③ 맞는 지표만 평가셋 50 에 넓힌다.
5. 당장 쓸 수 있는 LLM 없는 확인은 「숫자 근거 확인」 이다 — 답의 세율 · 금액 · 기한(1만분의 5 · 30억원 · 5일)이 인용한 근거 글에 그대로 있는지. 2026-10-04 근거답 평가에서 시행령이 「30억원」 으로 바뀐 조(2026.7.28 개정)에 답 모델이 옛 지식 「10억원」 을 쓰지 않았는지 이 확인으로 잡을 수 있다. 다만 법 조의 기본값(1만분의 35)을 고른 오답(DF-59)은 그 숫자도 근거에 있으므로 이 확인으로는 못 잡는다.

**<표 1> 조사 질문과 확인 방법**

| 질문 | 1차 출처 | 2차 확인 | 확실도 |
|---|---|---|---|
| Ragas 지표 이름 · 묶음 | 설치된 Ragas 0.4.3 코드(`ragas.metrics.collections` 의 클래스 목록) | Ragas 공식 문서 「Available Metrics」 | 확인 |
| `Faithfulness` 계산 · 입력 · 심판 LLM | Ragas 공식 문서 「Faithfulness」 | 설치된 코드의 클래스 정의(`name='faithfulness'` · `llm` 칸) | 확인 |
| `ResponseGroundedness` · `QuotedSpansAlignment` 동작 | 설치된 코드의 클래스 설명(docstring) | 공식 문서 목록의 NVIDIA 묶음 | 확인 |
| HHEM 의 언어 · 크기 · 라이선스 | Vectara 모델 카드(Hugging Face) | Ragas 문서의 `FaithfulnesswithHHEM` 설명 | 확인 |
| 로컬 소형 심판의 신뢰도 | — | — | 조사하지 않음(우리 사람 판정 20 으로 잴 것) |

조사하지 않은 것: TruLens · DeepEval 등 다른 평가 도구(같은 「주장 쪼개기 + 심판」 방식으로 알려져 있으나 원문을 열지 않았다) · 상용 HHEM-2.3 의 한국어 품질 · 심판 프롬프트의 한국어 번역.

## 2. 지표 — 이름 · 입력 · 심판 · 한국어

Ragas 공식 문서는 지표를 일곱 묶음으로 나눈다(RAG · NVIDIA · 에이전트 · 자연어 비교 · SQL · 일반 · 요약). 근거 답의 품질과 닿는 것은 <표 2> 와 같다.

**<표 2> 근거 답 품질 지표** · 출처: 설치된 Ragas 0.4.3 코드 · Ragas 공식 문서 · 조회 2026-10-04

| 지표(클래스 · 이름) | 묻는 것 | 필요한 칸 | 심판 LLM | 한국어 답 | 우리에게 |
|---|---|---|---|---|---|
| `Faithfulness` · `faithfulness` | 답의 주장 가운데 근거로 뒷받침되는 비율 | 질문 · 답 · 근거 | 필요 | 심판 모델이 한국어를 읽으면 됨 | **1순위 후보** — 사람 판정 20 과 맞춰 본 뒤 |
| `FaithfulnesswithHHEM` | 같은 계산을 분류 모델(HHEM)로 | 같음 | 없음(T5 분류기 · CPU) | **안 됨**(HHEM-2.1-Open 영어 전용) | 쓰지 않는다 |
| `ResponseGroundedness` | 답이 근거에 얼마나 기대나(0 · 1 · 2 → 0 ~ 1) | 답 · 근거 | 필요(두 프롬프트 평균) | 심판 모델에 달림 | 2순위 — `Faithfulness` 보다 호출이 적다 |
| `QuotedSpansAlignment` | 답 안 따옴표 인용이 근거에 글자 그대로 있나 | 답 · 근거 | 없음 | 됨(글자 비교) | 우리 답은 따옴표 인용이 드물다 → 숫자 근거 확인(3.3절)으로 바꿔 쓴다 |
| `NoiseSensitivity` | 관련 없는 근거가 섞이면 틀린 말을 하나 | 질문 · 답 · 근거 · 정답 | 필요 | 심판 모델에 달림 | 위임 조 · 동의어로 근거를 늘린 뒤 다시 잴 때 |
| `ContextPrecision` · `ContextRecall` | 찾은 근거의 정밀도 · 재현율 | 질문 · 근거 · 정답 | 필요(Non-LLM 판도 있음) | — | 이미 「정답 조」 로 Recall@5 · MRR@10 을 잰다(LLM 없음) — 따로 들이지 않는다 |
| `AnswerAccuracy` · `FactualCorrectness` | 정답 글과 답이 맞나 | 질문 · 답 · 정답 글 | 필요 | 심판 모델에 달림 | 평가셋에 정답 글(조문 요지)을 더하면 |

`Faithfulness` 의 계산은 세 단계다(공식 문서). ① 답의 주장을 모두 찾는다 ② 주장마다 근거로 추론되는지 본다 ③ 「뒷받침되는 주장 수 ÷ 전체 주장 수」. 심판 모델은 공식 예시에서 OpenAI 모델을 쓰지만, `llm_factory` 로 다른 모델을 끼울 수 있다.

HHEM-2.1-Open 은 `google/flan-t5-base` 를 바탕으로 한 분류기이고 Apache-2.0 이며, 32비트로 600MB 미만 · x86 CPU 에서 2천 토큰에 약 1.5초라고 모델 카드가 적는다. 하지만 지원 언어는 영어뿐이고, 한국어를 포함한 11개 언어는 상용 HHEM-2.3 이 지원한다.

## 3. 우리 프로젝트에 맞추기

### 3.1 심판 LLM 의 한계

이 PC 에서 돌릴 수 있는 심판은 Ollama 의 4B ~ 8B 모델이다(로컬 LLM 조사서 4절). 답 모델(qwen3:4b-instruct)과 같은 모델로 심판을 하면 자기 답을 좋게 보는 치우침이 생길 수 있고, 8B 모델(Kanana 1.5 · llama3.1)도 2026-10-03 근거답 비교에서 오답 · 지어낸 답이 있었다. 그래서 심판의 점수를 그대로 품질로 쓰지 않고 사람 판정과 맞춰 본다.

### 3.2 사람 판정 20 을 기준으로

근거답 평가셋 v1(20문항 · 2026-10-04)의 사람 판정(정답 · 부분 · 오답 · 지어냄 · 미룸)은 자동 지표의 「정답지」 가 된다. 자동 지표가 사람 판정과 맞는 정도는 「지어냄으로 판정한 답에서 `Faithfulness` 가 낮게 나오는가」 처럼 갈래별로 본다. 20 은 작아 숫자 하나(상관계수)로 정하지 않고, 어긋난 답을 하나씩 읽는다.

### 3.3 LLM 없는 숫자 근거 확인(제안)

법령 답의 핵심은 대개 숫자다(세율 · 금액 · 기한 · 비율). 답에서 숫자 표현(「1만분의 N」 · 「N분의 M」 · 「N억원」 · 「N일」 · 「N%」)을 뽑아 인용한 근거 글에 그대로 있는지 보는 확인은 심판 LLM 없이 몇 밀리초에 끝나고 한국어에서도 된다. 잡는 것 · 못 잡는 것은 <표 3> 과 같다.

**<표 3> 숫자 근거 확인이 잡는 것**

| 경우 | 예 | 잡나 |
|---|---|---|
| 근거에 없는 숫자를 지어냄 | 시행령이 30억원인데 옛 지식 10억원을 씀 | 잡는다 |
| 근거의 다른 숫자를 고름 | 시행령 1만분의 5 대신 법 조의 기본값 1만분의 35(DF-59) | **못 잡는다**(둘 다 근거에 있다) |
| 숫자 없이 틀린 말 | 「허용된다」 ↔ 「금지된다」 | 못 잡는다 |

그래서 숫자 근거 확인은 `Faithfulness` 를 대신하지 않고, 답 화면 · 평가에서 「근거에 없는 숫자가 있다」 를 바로 알리는 안전장치로 쓴다.

## 5. 이 조사를 뒤집을 조건

- Ragas 가 v1.0 을 내며 지표 이름 · 가져오는 길을 바꾸면(지금 경고가 뜬다) 표 2 를 다시 본다.
- 한국어를 지원하는 공개 환각 분류기(HHEM 같은 LLM 없는 판)가 나오면 3.2절 순서를 바꿀 수 있다.
- 사람 판정 20 에서 로컬 심판의 `Faithfulness` 가 지어냄을 잡지 못하면 1순위를 `ResponseGroundedness` 나 숫자 근거 확인 + 사람 판정 표본으로 바꾼다.
