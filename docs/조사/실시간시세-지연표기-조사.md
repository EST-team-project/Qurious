## 0. 맨 위 요약 · 확인할 것 · 정할 것

### 0.1 요약 5줄

1. 야후 공식 표에서 국내(`.KS` · `.KQ`)는 **20분 지연**, 미국은 Nasdaq 「Real-time」(그 거래소 체결만 · NYSE 개별 행 없음)이다. 우리 앱은 야후를 문서 없는 길로 부르고 미국 종목 카드는 서버 캐시가 최대 2시간이라, 화면의 「실시간」 · 「● LIVE」 는 근거가 없다.
2. 시세 응답에 받은 시각 · 체결 시각 · 장 상태 칸이 없다(야후 길은 출처 칸도 없음). 야후 응답의 `regularMarketTime` · `currentTradingPeriod` 로 채울 수 있고, 우리 환율 응답(`source` · `as_of` · `note`)과 강사님 lumina-invest 평가액 응답(`as_of` · `market` · `source`)이 같은 꼴의 선례다.
3. 실제 서비스는 라이선스가 있을 때만 「실시간」 이라 쓴다(네이버는 2022-05-26 나스닥 제휴 뒤). 권고 낱말은 「지연 시세(약 20분) · 받은 시각 HH:MM」 · 「장 마감 · MM월 DD일(현지) 종가」 이고, 「● LIVE」 는 지우는 것을 추천한다.
4. 실시간 접속(KIS WebSocket)은 기술보다 약관이 먼저 막는다 — KIS 약관 제5조③(시세는 개인 업무 한정 · 제3자 제공 금지) · KIS 제휴안내(제휴사 앱 화면 시세 표시 불가 통보) · 코스콤 「정보이용정책」(2024-01-01)(일반 대중용 웹 · 앱은 호가를 뺀 조회 방식만 · 개인가입자는 제3자 분배 금지). 사용자 자기 키 · 자기 화면만 된다. TradingView 무료 위젯은 한국이 목록에 없고 미국도 지연이다.
5. 실사용자가 아쉬워한 걸음 아홉 중 일곱은 「지금 값 + 언제 값인가」, 셋은 장중 분봉, 틱은 0이다. 2차는 표기 + 응답 칸(A안), 3차는 종목 허브 머리 한 줄(세 안 공통) + 분봉 작은 차트 + (자기 키) 호가를 추천한다.

## 1. 화면 표기 — 야후 시세의 지연 · 장이 닫힌 때 · 표기 낱말

### 1.1 야후 시세는 얼마나 늦나

야후 공식 도움말에 거래소마다 지연 시간이 표로 나와 있다. 「지연(delay)」 은 거래소에서 체결된 값이 야후 화면에 닿기까지 걸리는 시간이다.
「실시간(real-time)」 은 이 지연이 사실상 없다는 뜻이지만, 아래 <표 1> 의 미국 「Real-time」 은 **그 거래소 안에서 체결된 값**이라는 한정이 붙는다(구글 금융 면책 표 원문 — <표 2>).

### 1.2 장이 닫힌 때 야후가 돌려주는 값

- 장이 닫히면 새 체결이 없다. 야후 원문은 실시간을 「장이 열린 동안(일부는 장 전후 포함)」 으로 한정한다(1.1 인용). 장 마감 뒤 · 주말에 화면에 보이는 값은 **마지막 체결가**(대개 정규장 종가)다(확실도 높음).
- 우리 길은 장 전후 값을 받지 않는다. `_yahoo_chart` 는 `interval` · `range` 만 보내고(`stock.py:75`), 야후 차트 길에서 장 전후 봉을 달라는 인자(`includePrePost`)는 보내지 않는다.
  → 미국 장 마감 뒤에 받는 `regularMarketPrice` 는 **정규장 마지막 값**이고, 장 전 · 장 후 거래 값은 우리 화면에 오지 않는다(확실도 중간 — 야후가 이 길을 문서로 내지 않아 일반에 알려진 동작으로 판정 · 같은 날 실측으로 확인).
- **우리 응답에는 받은 시각 · 체결 시각 · 장 상태 칸이 없다**(확실도 높음 — 코드 줄):
  - 야후 길 `get_quote` 반환 칸 = `symbol · name · price · prev_close · change · change_pct · currency · market`(`stock.py:133-142`) — `source` 칸도 없다.
  - KIS 길 `get_quote` 반환 칸 = 위 칸 + `source: "kis"` · `open · high · low · volume`(`kis_market_data.py:176-178`) — 받은 시각은 없다.
  - 미국 카드 `_get_latest` = `symbol · price · change · change_p · unit`(`macro.py:23-29`).
  - 그래서 화면은 지금 값이 장중 값인지 · 종가인지 · 몇 분 전 값인지 가를 수 없다.
- 야후 응답 `meta` 에는 가를 재료가 있다 — `regularMarketTime`(마지막 체결 시각 · 유닉스 초) · `currentTradingPeriod`(장 전 · 정규 · 장 후 시작 · 끝) · `exchangeTimezoneName`.
  조사 때는 우리 앱 코드에서 이 칸을 쓰는 곳이 없었다 → 같은 날 고침 — 응답이 `regularMarketTime` 을 시세 시각(`as_of`)으로, `currentTradingPeriod` 로 받을 때 정규장 안이었나(`market_open`)를 싣는다.
  강의 화면 1분봉만 `marketState` 를 읽고 받은 시각 `updated_at` 을 붙인다(`lecture_market.py:355-367`) — 다만 `marketState` 는 차트(v8) 응답이 아니라 시세(quote) 응답 칸으로 알려져 있어 늘 빈 값일 수 있다(확실도 낮음 · 확인 필요).
- 지금 시각으로 보면(2026-10-16 금 20:40 무렵 KST): 국내 정규장(09:00 ~ 15:30 KST)은 끝났고, 미국은 서머타임 중이라 정규장이 22:30 ~ 05:00 KST(11월 1일 서머타임 끝 · 11월 2일부터 23:30 ~ 06:00 KST)다.
  → 이 시각에 미국 카드의 「● LIVE」 아래 값은 **현지 10월 15일(목) 종가**다. 시장별 거래 시간 · 서머타임은 [시장범위 조사서 v0.3](시장범위-미국코인-거래기준-조사.md) 과 같은 사실이라 여기서는 한 줄로 둔다.

### 2.2 사용자 피드백이 가장 바라는 것

원문: 「실시간 주식 정보를 확인할 수 있는 기능이 없는 점이 아쉽다 … 실시간 투자를 할 때도 참고해야 되는데」.
모의투자 점검 둘째 바퀴 6절의 걸음 아홉을 <표 3> 의 넷과 맞대면 아래와 같다.

읽은 점(확실도 중간 — 걸음 기록에서 추론 · 사용자에게 직접 묻지 않음):

- 피드백의 「실시간」 은 대부분 **「지금 값이 얼마이고, 언제 값인가」**(아홉 중 일곱)다. 그다음이 **장중 분봉**(셋)이다.

- 그래서 첫 걸음은 실시간 접속이 아니라 **현재가 + 받은 시각 + 장 상태를 정직하게 보여 주는 것**이고, 그것만으로 일곱 걸음이 풀린다.

### 6.2 3차 — 무엇을 어디에

- **종목 허브**: 머리에 「현재가 · 받은 시각 · 장 상태 · 출처」 한 줄(모든 안 공통). 종목 허브 데이터 묶음 API 를 「칸마다 기준일 · 출처」 로 설계한 것(순위화면 조사서 263줄)과 같은 원칙이다.
- **차트 화면**: Lightweight Charts(이미 있음)로 장중 분봉 + 「조회 HH:MM」 메타 줄(강사님 stock-coin-trade 꼴). 국내는 KIS 분봉(자기 키 연결 때) · 아니면 야후 분봉에 「약 20분 지연」 표기. 미국은 야후 분봉 또는 TradingView 위젯(지연 표기 그대로).
- **모의주문**: 주문 직전 「현재가 · 받은 시각 · 장 상태」 + (자기 KIS 키 연결 때) 매수 · 매도 1호가.
- **실시간 접속**은 3차 후반 후보 — 자기 키 · 자기 화면만 · 등록 상한을 KIS 원문으로 확인한 뒤.
