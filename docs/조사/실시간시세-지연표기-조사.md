> 기준: `main` `f17d310` — 파일:줄은 이 커밋 기준이다(같은 날 뒤에 고친 `public/app.html` · `public/js/core.js` · `public/js/products.js` 는 `git show f17d310:<파일>` 로 읽었다). 코드는 읽기만 했고 앱 화면 · API 는 부르지 않았다.

> 앞 판 [v0.1](지난판/실시간시세-지연표기-조사_v0.1.md)(2026-10-16)은 야후 길 · 미국주식 화면을 다뤘다. 이 표는 **「현재가」 처럼 보이는 국내 종목 값** 전체를 화면 기준으로 다시 훑은 것이다.

### 1.1 210,000 은 어디서 왔나 — 가장 유력: 투자 인디케이터 › 기본 인디케이터 전략

- 위 탭 「투자 인디케이터」 를 누르면 묶음의 첫 항목 `indicator-strategy` 가 열린다(`public/js/core.js:555-558` · 항목 차례 `core.js:73-85`). 기본 종목은 **삼성전자 · 1년**(`public/app.html:1982-1995`).
- 이 화면의 카드 「현재가」 는 `ind.current_price`(`public/js/indicator.js:19` · `:28`)이고, 서버는 그 값을 **일봉 마지막 봉의 종가**로 채운다 — `current_price: closes[-1]`(`app/services/stock.py:409`). 국내 일봉은 수집 DB 에서 먼저 읽는다(`stock.py:284-286` → `app/services/collector_db.py`).
- 수집 DB 는 공공데이터포털이 **다음 영업일에** 주는 값만 담는다(`collector/README.md:256-279` · `collector_db.py:23-24`). 오늘 러너 상태 파일(`data/collector/state/daily_update_last.json` — DB 아님)에 「시세가 바뀌었다 (20261015 → 20261016)」 · 회차 12:30:01 ~ 13:24:43 이 적혀 있다.
  → **10-19(월) 오전에는 10-15(목) 종가, 13:24 뒤에는 10-16(금) 종가**가 「현재가」 로 보였다(확실도 대체로 — 화면 값은 직접 보지 않음).
- 등락률도 오늘 값이 아니다 — `closes[-1] ÷ closes[-2]`(`indicator.js:20`), 즉 **그 과거 하루의 등락**이다.
- 서버 응답에는 이미 `as_of` · `source` · `data_note`(「수집 DB 일봉(수정주가) · … 종가」)가 있다(`stock.py:411-415`). 화면만 버린다. 같은 응답을 쓰는 **전략 분석(`quant-backtest`)은 10-16 에 「마지막 종가」 + 「자료: …」 로 고쳤다**(`public/js/quant.js:244` · `:249` · DF-15 일부 닫힘).
- 두 번째 후보: 같은 묶음의 **지표 대시보드**(`company-dashboard`) 카드 「현재가」 — 야후 quoteSummary 값에 서버 캐시 6시간이 붙는다(아래 표 2행). 기본 인디케이터 전략이 첫 화면이고 값 차이(약 3%)가 「이틀 전 종가」 와 맞아 1행을 더 유력하게 본다(추정).

### 1.3 읽은 점

1. **「현재가」 라는 이름으로 과거 종가를 보이는 곳이 화면 넷**(1 · 6 · 7 의 대체값 · 8)과 **자동매매 체결가 하나**(5) 남았다. DF-15(「현재가 자리에 직전 거래일 종가 5곳」 · 🟠 · 일부 닫힘)의 남은 몫과 같다. 셋은 신장환 님 화면, 엔진은 오준영 님 몫.
2. **이 PC 의 수집 DB 는 12:30 회차 전까지 D-2 다.** 포털이 금요일 값을 월요일에야 주므로, 월요일 오전엔 목요일 종가가 「현재가」 로 보인다. 그래서 장중 실제 시세와 차이가 커진다(삼성전자 210,000 ↔ 217,000 ≈ 3.3%).
3. **값을 고칠 재료는 이미 응답에 있다** — 1 · 7 · 8 은 서버가 `as_of` · `data_note` 를 주는데 화면이 버린다. 표기만 고치는 데 서버 일은 거의 없다.
4. **본보기도 이미 셋** — 전략 분석(「마지막 종가 + 자료 줄」) · 상품 안내(「기준일 · 출처」) · 종목 허브 카드(「MM-DD 종가」). 새 낱말을 지어낼 필요가 없다.
5. **진짜 「지금 값」 의 길은 하나뿐** — `stock.get_quote`(KIS 게이트웨이 → 야후 20분). 이 함수도 KIS 길은 시각 칸이 없고(`kis_market_data.py:176-178`), 모의 주문 길(`resolve_stock`)은 야후의 `as_of` 마저 떨군다.

**읽은 점**

1. **2차에 되는 것은 ①(내 KIS 키가 있는 사용자) + ④ · ⑤ 의 정직한 표기**다. ①은 코드 조각이 다 있다 — 묶기만 하면 된다.
2. **키가 없는 사용자**(대부분)에게는 ④(지연 · 시각) 또는 ⑤(「MM-DD 종가」)만 보인다. 이것이 약관상 할 수 있는 최선이다.
3. **②는 3차 몫이다** — 한도(41건)는 우리 유니버스 31종목에 맞지만, 사용자마다 세션이 하나라 「서버 하나가 모두에게」 가 아니라 「사용자마다 자기 세션」 구조여야 한다.
4. 「현재가」 도 **어느 시장 값인가**가 갈린다 — 네이버는 「KRX 제공」 을 적고, KIS 공지(2026-09-09 「KRX 애프터마켓 도입 및 NXT 제도 변경에 따른 안내」 · 제목만 확인)처럼 대체거래소(NXT) 값이 섞일 수 있다. KIS 현재가 조회의 시장 구분 `J` 가 무엇을 덮는지는 이번에 원문으로 확인하지 못했다(확인 필요).

**공통 구조(글 그림)**

```text
증권사 웹소켓 (사용자마다 1세션 · 합산 41건)
   │  체결 하나하나
   ▼
수신기(서버 상주 · 재접속하면 구독 복원) ──► Redis 키  quote:{사용자}:{종목} = {가격, 체결 시각, 출처}  (TTL 수십 초)
   │                                             ▲ 처음 화면은 REST 로 이 키를 읽음
   └─ Redis Pub/Sub 알림 ──► SSE 끝점(FastAPI · ping 15초) ──► 브라우저 (값 옆에 「증권사 실시간 · 14:02:31」)
```

- 화면은 **처음 값은 REST**, 갱신은 **SSE** 로 받는다 — 알림을 놓쳐도 키가 남는다(Pub/Sub 은 at-most-once).
- 저장은 **키 하나(최신 값)뿐**이고 TTL 로 사라진다 — 실시간 시세를 쌓아 두지 않는다(3.4 저장 금지).

### 6.3 (다) 발표 장에 넣을 「현재 한계 · 확장 설계」 세 줄

1. **현재 한계** — 판단 · 학습 · 백테스트는 같은 자료로 다시 돌릴 수 있게 공공데이터 일봉(다음 영업일 공개)으로 했고, 그 탓에 장중 「현재가」 칸이 하루 이틀 전 종가로 보이는 곳이 있었습니다(삼성전자 210,000 ↔ 실제 217,000).
2. **바로 고친 것**(10-20 에 1 · 2 를 마치면) — 값마다 출처와 기준 시각을 붙여, 내 증권사 키가 있으면 증권사 조회값, 없으면 「지연 시세」 · 「10월 16일 종가」 로 밝히고 「실시간」 이라고 쓰지 않습니다. *(못 마치면: 「값마다 출처 · 기준 시각을 붙이는 서버 함수를 설계했고, 우선 화면에 기준일을 밝힙니다」)*
3. **확장 설계** — 증권사 웹소켓(사용자별 세션) → Redis 최신 값 → SSE 로 화면을 갱신하고, 「판단은 저장 자료 · 실행 직전 확인만 실시간」 으로 나눕니다. 실시간 시세는 약관상 저장 · 공유하지 않고 「언제 어떤 값으로 판단했나」 만 남깁니다.

## 7. 기능별 두 갈래 — 저장 자료로 충분 / 실시간이 필요

### 7.3 한 줄 원칙

- **「판단은 저장 자료, 실행 직전 확인과 표시는 실시간」** — 둘 다인 기능(R3 · R5 · R8 · S9)은 이 원칙으로 나눈다.
- 실시간 값을 **못 받으면 「실시간이 아님」 을 밝히고**(「10월 16일 종가」 · 「지연 시세 · 13:40 체결」), 돈이 움직이는 일(R1 · R2 · R3 의 주문)은 **기준 시각이 오래된 값으로 실행하지 않는다**(예: 받은 지 N초 넘은 값이면 주문을 막고 까닭을 보인다 — N 은 정할 값).
- 실시간 시세는 **저장 · HF 공유 대상에서 뺀다**(3.4). HF 에 남는 것은 지금처럼 공공데이터 · DART · 법령 판뿐이다.
