## 요약

1. **DART 는 받아 쌓아도 된다.** FAQ 「공시정보를 상업적으로 사용해도 되나요?」 의 답이 「공공데이터법에 따른 공공데이터 … 공개 및 활용은 제한되지 않습니다」 이고, 재배포 · 재가공 책임만 이용자에게 있다. 개인 인증키는 하루 20,000건(83종 합계)이고, 분당 1,000회를 넘기면 그 IP 를 1시간 막는다. 상장사 공시는 평일 하루 약 700건 · 한 달 약 8,000건이라 2020년부터 전부 받아도 약 8,300회다.
2. **DART 재무 API 는 가장 최근 정정본만 준다.** GS건설 2023 사업보고서는 2024-03-21 첫 제출 뒤 세 번 정정됐고, 지금 부르면 2026-06-30 정정본 값만 온다. 받은 72,248개 판 가운데 4,288개(5.9%)가 법정 기한 + 여유보다 늦게 접수된 정정본이고, 사업보고서는 14.4%(가운데값 224일 뒤)다.
3. **현업은 「처음 보고된 값 + 제출일」 과 「정정 반영값」 을 따로 둔다.** Sharadar 는 As Reported(AR · 「excludes restatements」 · 제출일 기준)와 Most-Recent Reported(MR · 「includes restatements」 · 기간 기준)를 나누고, Compustat 은 처음 보고값(HIST_STD · Snapshot)과 정정값(RST_STD)을 따로 둔다. 1차 프로젝트(Alpha_Stack)도 정정일을 그대로 쓰고 접수일 다음 거래일부터 보이게 했다. 그래서 재무 API 의 기본은 `pit=strict`(그날 전에 접수된 판만)다.
4. **네이버 검색 API 로 뉴스를 모으는 설계는 버린다.** 약관(2026-09-07 개정) 검색 API 2.3 이 검색 결과(가공 · 파생물 포함)의 복사 · 저장 · 캐싱, AI 입력 · 학습 · 평가 활용, 제3자 제공을 금지한다(예외: 이력 조회용 서버 보관 최대 21일). 개발자센터 검색 API 는 2026-07-30 에 신규 신청을 닫았고 2027-06-30 에 끝난다.
5. **뉴스는 세 갈래로 나눈다.** 저장 · 이름표 · 검색 · AI 에 쓰는 것은 재사용이 허락된 공공 자료(공시 · 정책브리핑 정책뉴스 — 공공누리 제1유형)로 하고, 언론사 기사는 제목 + 원문 링크만(언론진흥재단 규칙상 단순 링크는 자유), 네이버는 저장 없이 그때그때 보여 주기만 한다. 실제 증권 서비스는 언론사와 콘텐츠 계약을 맺는다.

### 3.1 DART 는 최신 정정본만 준다

### 3.3 우리가 고른 것

- 기본은 `pit=strict` — 기준일 전날까지 접수된 판의 값만 쓴다(Sharadar AR · Compustat 처음 보고값과 같은 뜻). 정정된 기간은 정정일 전까지 비고, 그 자리는 직전 기간이 대신한다.
- `pit=first` — 그 기간 원본이 기준일 전에 나왔으면 정정본 값이라도 쓰고 `values_revised_after_as_of` 로 알린다(빈 기간이 없는 대신 값에 미래가 섞인다).
- 1차 프로젝트에서 가져온 것 — 「접수일 다음 거래일」(`available_from` · 거래일 달력으로 셈) · 「그 판 자기 제목의 정정 표시」(`amended` · 공시 목록 비고 「정」 은 나중에 붙는 표시라 쓰지 않음) · 「결산 순서로 최근」.
- 2차에서 더한 것 — 정정본마다 새 판으로 쌓는다(기본 키에 접수번호). 2026-10-05 부터 매일 받는 정정은 그날의 판이 남아, 그 뒤 기간은 진짜 처음 보고값 이력이 생긴다. 분기 · 반기까지 · 상장폐지 포함 3,990곳(1차는 사업보고서 · 350종목). 그 기간 원본 접수일(`first_known_at`)을 함께 둬 「정정으로 잃는 몫」 을 셀 수 있다.
- 다음 후보 — DART 「XBRL 재무제표 원문 내려받기」 는 접수번호로 묻는다. 정정된 4,288개 판의 원본 접수번호로 원문을 받아 처음 보고값을 되살리면 Compustat HIST_STD 와 같은 판을 과거에도 가질 수 있다(호출 약 4,300회 · 계정 대응표 필요).
