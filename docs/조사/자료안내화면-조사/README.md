# 데이터 안내 화면 조사 — 요약 (2026-10-08)

> 이 조사 셋은 2026-10-08 에 「자료 안내」 화면을 설계하며 쓴 것이다(안 B + 안 A 서랍으로 결정 · 같은 날 1단계 구현). 구현에서 바뀐 곳: 설명 대장은 표 속성 대장에 칸을 더하지 않고 새 대장 넷(`docs/데이터/대장/자료안내-*.tsv`)으로 나눴고, 숫자는 1단계에서 상태 · 백업 목록 두 장을 요청 때 읽는다(러너 숫자 파일은 2단계) — [UI 명세서 5.7절](../../화면/UI명세서.md) · [API 명세서 `API-DATA-11`](../../인터페이스/API명세서.md).

요청: 우리 자료가 어떻게 구성되고 · 어떻게 수집되며 · 어느 것을 읽으면 되는지를 분석해 보여 주는 화면([원문](00-사용자요청-원문.md)). 파일: [01 우리 자료 목록](01-우리-자료-목록.md) · [02 실무 사례](02-실무-사례-조사.md) · [03 화면 세 안](03-화면-세-안.md).

1. **자료** — 아홉 묶음 · 서른 줄. 시세는 2020-01-02 부터(주식 일봉 4,489,419줄) · 공시 774,972 · 재무 1,879,368 · 뉴스 42,303 · 근거 문서 128개(2026-10-08 12:07 로컬 앱 API). 매일 12:30 러너 19단계(받기 7 · 계산 6 · 백업 5 · 근거 문서 1)가 만들고 HF 비공개 데이터셋 여섯 가운데 둘에 날마다 올린다.
2. **재료가 이미 있다** — 연도별 · 시장별 줄 수와 파일마다 처음 · 마지막 날짜가 백업 매니페스트 두 장에 있어, 수집 DB 를 열지 않고 「자료 × 연도」 바둑판을 그릴 수 있다. 지금 API 는 마지막 날짜 · 줄 수만 준다.
3. **어긋난 곳** — 총수익(TR) · 벤치마크 · 조정 이벤트는 앱에서 읽는 길이 없다 · 데이터 관제의 「정책뉴스」 줄이 언론사 기사까지 센다(42,303 = 32,983 + 9,320) · 백업 카드의 이용 조건 「공공누리 제1유형」 은 틀렸다(공공데이터포털 원문은 제4유형 — 출처표시 · 상업적 이용금지 · 변경금지).
4. **실무** — 열 곳(HF · Kaggle · 공공데이터포털 · KRX · Sharadar · WRDS · dbt · DataHub · OpenMetadata · Datasheets · Data Cards)이 같은 뼈대를 쓴다: 사양 표 → 칸 정의 · 분포 → 어떻게 모았나 → 무엇을 읽나. 우리 HF 데이터셋은 무료 조직의 비공개라 표 미리보기가 꺼져 있어, 새 화면이 그 자리를 채운다.
5. **추천 안** — 안 B(한 장 보고서: 구성 · 수집 · 읽기 세 절 + 숫자 띠 · 연도별 바둑판)에 안 A 의 「자료 한 장」 서랍을 합친다. 자리는 데이터 묶음 왼쪽 메뉴 둘째 줄(관제 아래 · 모든 로그인 사용자) · 늦음 판정 색은 관제 몫.
6. **새 서버** — 설명은 git 생성물(스캐너가 표 속성 대장 · 코드 주석에서 만들고 `--check`), 숫자는 러너가 회차마다 쓰는 상태 파일, 앱은 둘을 읽기만 한다(선례: 단계 이름표 · 백업 판정 · API 문서 카탈로그). 1단계만으로 안 B 의 일곱 블록을 그린다.
7. **정할 것 넷**(추천 = 첫 칸) — ① 누가 보나(모든 로그인 사용자 · 개발 정보만 관리자) ② 개발 말(본문은 쉬운 이름 · 표 이름 · API 는 관리자 펼침에 · 서버가 관리자에게만 싣는다) ③ 그림(지금 숫자로 되는 셋 — 바둑판 · 기간 막대 · 흐름) ④ 숫자 정본(생성물 둘).
8. **다음** — Figma 에 세 안 나란히 3틀 → 고른 안의 상태 × 폭 9틀(03 문서 11절) → 사용자 결정 → 구현.
