> **이 문서로 알 수 있는 것**
> 1. 실제 서비스는 「이 자료가 무엇이고, 어떻게 모았고, 무엇을 읽으면 되나」 를 한 화면에 어떻게 나눠 보여 주나
> 2. 어떤 그림(포괄 범위 · 칸 분포 · 빈칸 비율 · 신선도 · 계보)을 쓰고, 그 그림의 재료는 무엇인가
> 3. 우리 화면에 가져올 것과 가져오지 않을 것은 무엇인가
>
> **읽는 순서** — 화면을 그릴 사람: 요약 → 3절(부품 표) → 4절 · 근거를 볼 사람: 2절 곳마다

## 요약

1. 열 곳이 거의 같은 뼈대를 쓴다 — **① 한 줄 요약과 사양 표(기간 · 갱신 주기 · 포괄 범위 · 이용 조건) → ② 칸 정의와 칸마다 작은 분포 그림 → ③ 어떻게 모았나(출처 · 방법론 · 계보) → ④ 무엇을 읽나(불러오는 예시 · 함께 쓰는 자료 · 쓰지 말 곳)**. 숫자 칸(행 수 · 크기 · 마지막 갱신 · 칸 분포)은 시스템이 채우고, 글 칸(왜 · 어떻게 · 주의)은 사람이 쓴다.
2. 금융 자료를 파는 곳(Nasdaq Data Link 의 Sharadar · WRDS)은 맨 위에 **사양 표**를 두고, 방법론을 「정정 처리 · 시간 색인」 처럼 **쓰는 사람이 틀리기 쉬운 주제**로 나눈다. 우리 재무 기준일 거르기(`pit`) · 수정주가 누적 방향 · 받은 시각의 뜻이 바로 그 주제다.
3. 「데이터를 분석해 보여 주는」 그림은 다섯 가지로 모인다 — 칸 머리의 분포 막대(HF · Kaggle) · 빈칸 · 고유값 비율(OpenMetadata · HF) · 행 수 시간 추이(OpenMetadata) · 포괄 범위가 넓어진 추이(Sharadar 「Progress」) · 계보 그림(dbt · DataHub).
4. 공공데이터포털 주식시세정보 원문은 이용허락범위를 **「출처표시, 상업적 이용금지, 변경금지 (제 4유형)」** 으로 적고, 「상업적 목적 여부와 상관 없이 제3자 무단 제공 및 재배포가 엄격히 금지」 라고 쓴다. 우리 백업 카드의 「공공누리 제1유형」 이 틀렸다는 근거다(01 문서 6절 3번). 같은 페이지 안에서도 메타 칸 「업데이트 주기: 실시간」 과 설명 글 「영업일 하루 뒤 오후 1시 이후」 가 어긋난다 — 선언한 주기보다 **잰 신선도**를 보여 줘야 하는 까닭이다.
5. 우리 HF 데이터셋은 무료 조직의 비공개라 Hugging Face 의 표 미리보기(Data Studio)가 켜지지 않는다(원문: 비공개는 PRO · Team · Enterprise 에서만). 팀원이 HF 웹에서 표를 미리 볼 길이 없으므로, 새 화면이 그 빈자리를 채울 수 있다.

## 1. 조사 방법

원문을 직접 열어 확인했다. 검색 요약만 보고 쓴 칸은 없다. 열지 못한 곳은 「확인 못 함」 으로 적었다.

**<표 1> 원문을 연 방법**

| 방법 | 곳 | 비고 |
|---|---|---|
| 웹 문서 가져오기(요약 도구) | Hugging Face 문서 · 데이터셋 페이지 · 공공데이터포털 · KRX 첫 화면 · WRDS · dbt · DataHub · OpenMetadata · arXiv | 칸 이름 · 인용 문장은 원문 그대로 받았다 |
| 본문 추출(tavily) | Kaggle 문서 · 공공데이터포털(전문) | 스크립트로 그리는 페이지의 본문 |
| 브라우저로 그린 뒤 글 읽기 | Kaggle 데이터셋 페이지 · Nasdaq Data Link SF1 | 스크립트로만 그려지는 페이지 |
| PDF 쪽 읽기 | Datasheets for Datasets v8(arXiv) | 3절 질문 묶음 |

열지 못한 곳 — KRX 「데이터 종합사전」(직접 주소가 403 · 정보데이터시스템 약관 제10조②가 자동 수집을 막아 더 시도하지 않았다) · Kaggle 사용성 점수의 세부 항목(마우스를 올려야 열리는 풍선 글) · Amundsen(공식 주소 amundsen.io 가 2026-10-08 조회 때 관련 없는 누리집으로 넘어가 따라가지 않았다 · 저장소 문서는 GitHub 에 있어 이번 조사 규칙상 열지 않았다).

## 4. 우리 화면에 가져올 것 · 가져오지 않을 것

**<표 12> 가져올 것** · 차례 = 효과 ÷ 비용(높은 것부터) · 재료 칸은 [01 문서](01-우리-자료-목록.md) 5절

| # | 가져올 것 | 본보기 | 우리 재료 | 비용 |
|:-:|---|---|---|---|
| 1 | 자료마다 같은 꼴의 사양 카드 — 처음 ~ 마지막 · 줄 수 · 갱신 주기 · 공개 시각 · 출처 · 이용 조건 | SF1 · WRDS · 공공 | API-DATA-01 + 매니페스트 + 출처 표 | 작다 |

| 6 | 칸 정의(펼침) · 칸 설명 채움 비율 | HF Data Fields · dbt | 스캐너 결과(데이터 사전 3절) | 중간 — 스캐너가 JSON 을 써야 한다 |
| 7 | 칸 분포 · 빈칸 비율 그림 | HF · Kaggle · OpenMetadata | 지금 없음 — 스캐너에 칸 통계를 더해야 한다 | 크다 — 큰 표를 훑는다 |
| 8 | 쓰지 말 곳 · 주의 | Datasheets Uses · HF Limitations | 백업 카드 「주의」 · 설계서 | 글 |

**가져오지 않을 것** — 사용성 점수 · 조회수 · 추천(한 팀의 자료라 견줄 상대가 없다) · 소유자 · 대화 · 거버넌스(큰 조직 기능) · 화면 안 SQL 창(수집 DB 를 앱이 쓰기 연결로 열 위험 · 지금 앱은 읽기 전용 연결만 둔다) · 원자료 내려받기 단추(원자료 재배포 금지 · 제4유형).

**반대 의견** — Datasheets 의 저자는 데이터시트 만들기를 자동화하지 말라고 한다. 숫자를 자동으로 채우는 것과 「왜 · 어떻게」 를 사람이 쓰는 것은 다르므로, 우리 화면은 **숫자는 생성물(정본 한 곳), 글은 사람이 쓴 문서(수집기 README · 설계서)에서 옮긴 것**으로 나눈다. 글을 화면에 따로 써 두면 문서와 갈라진다 — 01 문서 6절의 어긋남 다섯이 그 예다.
