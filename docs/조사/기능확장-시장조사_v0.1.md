## 이 문서로 알 수 있는 것

1. 우리 기능의 다섯 부분(근거 답 · 검색 RAG, 인디케이터, 로보어드바이저, 데이터, 학습)에서 잘 만든 오픈소스와 실제 서비스는 무엇을 하고 있나
2. 그중 우리 저장소에 들여와 고쳐 쓸 수 있는 것은 무엇이고, 라이선스로 막히는 것은 무엇인가
3. 부분마다 「지금 → 100% → 확장」 의 다음 걸음은 무엇이고, 누구 몫인가
4. 우리가 이미 가진 차별점(근거 번호가 달린 답 · 판 고르기 · 거래일 달력 · 규격 데이터)을 어떻게 더 키울 수 있나

## 요약

다섯 부분에서 27곳을 봤고, 결정에 쓰는 사실(라이선스 · 기능 · 숫자)은 원문이나 이 PC 실측으로 다시 맞췄다. 오픈소스 13곳 가운데 들여올 수 있는 라이선스(MIT · BSD · Apache-2.0)는 11곳, 조건이 붙는 것은 1곳(vectorbt · 판매 금지 조항), 들이지 않을 것은 1곳(backtesting.py · AGPL-3.0)이다. 나머지 14곳(실제 서비스 · 공공 API 13곳과 표준 문서 1건)은 코드가 아니라 모양과 규칙을 빌린다.

가장 바로 쓸 수 있는 것은 셋이다. 한국은행 ECOS Open API 는 표본 키로 실제 불러 보니 공식 용어 풀이(통계용어사전)와 오늘 값이 든 100대 통계지표(101개)를 돌려줬다. 거시 지표 화면(지금 야후)과 용어사전의 공식 출처를 함께 채울 수 있다. 다음은 Betterment 의 리밸런싱 규칙(기본 이탈 허용 3% · 현금흐름으로 먼저 맞추고 모자라면 사고팔기)으로, 팀이 논의 중인 리밸런싱 주기 · 허용 이탈률 결정에 실제 서비스 근거가 된다. 셋째는 코스콤 로보어드바이저 테스트베드의 공식 심사 단계(사전 0.5개월 → 본심사 6개월 → 최종 0.5개월)로, 우리 테스트베드 화면이 맞춰 볼 기준표가 된다.

근거 답 부분에서는 우리가 가진 「답 아래 출처 카드」 가 실제 서비스의 방향과 같다(AlphaSense 는 문장마다 원문 조각에 이어지는 인용을 단다). 키울 곳은 평가(Ragas 의 근거 충실도 · 맥락 재현율 같은 지표)와 재순위(bge-reranker-v2-m3 · Apache-2.0 · 0.6B)다.

## 2. 근거 답 · 검색 RAG (이동원)

우리 지금: AI 투자 상담의 근거 답(출처 카드 · 근거 없음 · 거절)은 점검표 84점이다. 법령 · 감독규정 14문서를 낱말 검색과 벡터 검색(bge-m3)으로 찾고 순위를 합친다(평가셋 38문항 Recall@5 0.868). 남은 결함은 시행령에 맡긴 조를 함께 찾지 못하는 것(DF-59)이고, 「투자 정보 리서치」 화면은 RAG 가 아니라 글자 찾기다(41점).

## 8. 우리 프로젝트에 주는 뜻

부분마다 다음 걸음은 <표 13>(점검 보고서 4절)에 「지금 · 100% · 확장」 으로 옮겼다. 여기에는 조사에서 나온 규칙 후보만 적는다.

1. 근거 답의 품질은 검색 재현율과 사람 판정에 더해 **근거 충실도**를 자동으로 잰다(Ragas 지표 이름을 그대로 쓴다).
2. 공식 공공 API 가 있으면 야후 · 포털보다 먼저 쓴다(ECOS · DART). 데이터 화면에 「출처 · 기준일」 을 보이는 우리 규칙과 같은 방향이다.
3. 용어 관계는 SKOS 이름으로 문서화한다. 지금 표는 바꾸지 않고 설계서에 대응표만 둔다.
4. 들여오는 코드는 MIT · BSD · Apache 만. Commons Clause 는 팀 결정, AGPL 은 들이지 않는다.
5. 팀원 몫(인디케이터 · 로보어드바이저)의 조사 결과는 파트별 점검 이슈 초안에 근거로 붙였다. 고칠지와 순서는 각 주담당이 정한다.
