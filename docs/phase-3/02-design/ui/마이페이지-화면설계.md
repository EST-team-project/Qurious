## 요약

1. **지금 마이페이지는 카드 6장을 쌓은 한 화면이고, 설정은 아홉 곳에 흩어져 있다.** 1단계(메뉴 모으기)는 적용됐고, 이 설계는 마이페이지 안을 **구역으로 나누는 것**이다.
2. **추천은 ㉯** — 1280 은 왼쪽 구역 목록 + 본문, 390 은 「목록 → 본문」 두 단계. 구역 8개: 내 정보 · 보안 · 증권사 연동 · 알림 · 외부 연동 · 화면 설정 · 투자 성향 · 위험 구역(탈퇴). 근거는 약하다 — 「왼쪽 목록」을 직접 확인한 곳은 GitHub 하나뿐(1절).
3. **일을 둘로 나눈다.** 1차(약 0.75 세션) = 틀 + 기존 카드 재배치 + 증권사 연동 · 알림 · 외부 연동은 **요약 + 링크**(본체는 그대로 — 위험 거의 없음). 2차(약 2.5 세션) = 본체를 구역 안으로(오준영 님 화면 포함 — 안내 필요).
4. **원래 계획에 없던 일이다.** 11-05 전 수요가 이미 약 36 대 가용 16 ~ 18(약 2배)이다. 사용자 결정(10-29): 1차 · 2차 모두 11-05 전 → 약 39.25(7절 ⑤ · 8절).

## 3. 옮길 때 고칠 곳

| 무엇 | 사실 | 설계의 처리 |
|---|---|---|
| 칸 id | `trading.js` 가 `broker-*` 4칸을 읽는다 | **id 를 바꾸지 않는다.** 구역 본문은 **정적 HTML 로 두고 보이기만 바꾼다**(열 때 JS 로 만들면 조용히 빈 값이 간다) |
| 카드 붙이는 자리 | `mypage.js` 가 화면 설정 카드를 `.space-y-4` 첫 일치의 두 번째에 붙인다 | 구역 본문 id 를 **이름으로 지정**. TC-GL-28 이 보는 `TERM_VIEWS` · `setTermView` 함수는 그대로 |
| 딥링크 `#settings` | 서버가 `#settings` 링크와 「증권사 API 설정」 이름으로 안내. TC-NV-06 · 07 | 1차: `settings` 화면을 그대로 둔다(위험 0). 2차: `settings` 화면은 **빈 껍데기 + 마이페이지 「증권사 연동」 구역으로 보내기**. 이름 줄은 메뉴에 남긴다. 마이페이지 → `settings` 로 되돌리는 코드를 두지 않아 해시 루프가 없다 |
| e2e | `kis_modes.py` · `broker_feedback.py` 가 `[data-view="settings"]` 를 강제로 보이게 한다 | 2차에서 `mypage` + 증권사 연동 구역으로 선택자를 고친다 |
| 시험 · 사용법 · 그 밖 | TC-NV-01 ~ 02 · 05 ~ 07 · 11, TC-HT-03(`VIEW_GUIDES` 의 settings 등 글) | 화면 키를 안 지우면 통과. 새 구역 글은 TC-NV-05 금지어 확인. 서버 글은 이름을 유지해 낡지 않는다. 2차에서 메뉴 줄을 뺄 때만 머리 경로(`VIEW_PARENT`)가 필요하고, 끝에 IA 전수표 · 점검표를 고친다 |

**서버가 주는 것만 그린다(확인함)**: `GET /api/sessions` 는 세션 번호 목록과 `count` 뿐이라 **기기 이름 · 마지막 로그인 시각이 없다** — 수 + 「모든 기기 로그아웃」만 그린다. `GET /api/broker/settings` 는 `connected`(저장된 키가 있는지) · 가린 키 · 가린 계좌, `/api/quant/settings` 는 위험 한도를 준다. **연결 상태는 「저장된 값이 있는가」이지 연결 시험 결과가 아니다** — 화면 글도 그렇게 쓴다. 알림 · Open API 요약의 응답 칸은 열어 보지 않았다.

| ② | 증권사 연동 | **1차 = 요약 + 링크 · 2차 = 본체를 구역 안으로** | 2차는 오준영 님 화면에 닿는다 → **이슈로 먼저 안내**(초안 `github-archive/2026-10-29/이슈-안내-설정화면-내계정으로-오준영/`(1단계 안내 초안에 2단계를 이어 씀)) |
| ③ | 투자 성향(S8) · 답변 엔진(S7) | **둘 다 안 옮긴다**(「옮기기 애매하다」) | 설문은 자산배분이 쓰고 엔진은 채팅 곁이 편하다. 마이페이지 「화면 설정」 구역에 **현재 값 한 줄 + 링크**만 둔다(추천안 S8 읽기 요약보다 한 걸음 가볍게) — 구현 때 값을 줄 수 있는 읽기 길이 없으면 링크만 |
| ④ | Webhook · Alpaca | **안 옮기고 「외부 연동」에 안내 한 줄**(묻지 않고 추천대로 — 저장하는 설정이 없다) | 사용자가 뒤집으면 2차에서 다시 본다 |
| ⑤ | 일정 | **1차 · 2차 모두 11-05 전** | 약 +3.25 세션이 11-05 전 수요(약 36 → 약 39.25)에 얹힌다. **무엇이 밀리는지는 이동원 할 일 다음 판에서 다시 센다**(8절) |

**상태**: 3단계(그림)까지 · 4단계(검토)는 팀 의견 뒤. 개발 준비됨 아님 — 구현은 1차(틀 + 재배치 + 요약 · 링크)부터, 서버(`app/`)는 건드리지 않는다.

## 8. 일정 영향

- **원래 3차 계획에 없던 일이다**(이번 설계 세션 약 0.5 도 계획 밖). 11-05 전 수요는 **약 36 대 가용 16 ~ 18 — 이미 약 2배**(이동원 파트 할 일 6.1-1). 마무리 기간(11-06 ~ 10)도 같은 문서 표 4 에서 이미 넘친다 — **뒤로 미루는 것도 공짜가 아니다.**

| 단계 | 어림(세션 · 추정) | 안에 든 것 | 11-05 |
|---|--:|---|---|
| 1차 | 0.75 | 틀(목록 · 전환 · 390 목록 → 본문) 0.25 + 기존 카드 재배치 0.25 + 증권사 연동 · 알림 · 외부 연동 요약 + 링크 0.25 | 넣으면 약 36.75 |
| 2차 | 2.5 | 알림 본체 0.5 + Open API 본체 0.5 + 증권사 본체(e2e 둘 · 훅) 0.75 + S4 · S5 링크화 0.25 + 투자 성향 요약 0.25 + 메뉴 · 시험 · 문서 0.25 | 뒤 |

- 숫자는 모두 추정이다. 2차는 팀원 화면에 닿으므로 이슈로 먼저 알린다.
