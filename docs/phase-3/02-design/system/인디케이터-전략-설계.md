## 요약

1. **지표** — 2차에 TradingView 정의로 맞춘 지표 한 벌(`ta_utils.py`)을 그대로 쓰고, LEAN 지표 값과 대조한다(`P02-①-1`). 지표 함수는 t 시점 값을 t 까지의 자료로만 계산하고 새 봉 하나로 이어서 갱신한다(`P02-②-2` · ★ 채점 항목).
2. **전략** — 매수 · 매도 조건 · 손절 · 익절 · 수량 방식 · 체결 시점을 **전략 카드** 하나에 적고, 백테스트 · Pine 생성기 · 자동매매가 같은 카드를 읽는다(`P02-①-2`). 연결 시험용 판 1 은 지금 계약 칸만 썼다. 판 2 에 더할 칸은 #314 에 알렸고 반응 전이다 — 이미 합의된 값과 반응 전인 것을 4.3 에 나눠 적었다.
3. **커스텀 지표** — 이미 있는 자유 산식 · 판 저장을 바탕으로 정규화 산식과 판 다시 계산을 지킨다(`P02-②-1` · `②-3`).
4. **기준 전략** — 미리 적은 조합표만 백테스트하고 시도를 모두 기록해 고른다(`P02-①-3`).
5. **화면** — 전략 카드 편집(`U6`)과 지표 차트(`U7`), 기본 인디케이터 화면의 표시 고침(B1 ~ B3).

## 4. 설계

### 4.1 지표 — 정의 한 벌 · LEAN 대조 (`P02-①-1`)

- 기본 지표(이동평균 · RSI · MACD · 볼린저 · ATR)는 `ta_utils` 하나로 계산한다. TradingView 정의(RSI · ATR = Wilder 평활 · 표준편차 = 모집단)이고, 2차에 TradingView 화면 값과 5일 대조 차 0.00 이었다(2차 설계서 3.9).
- 3차에는 같은 일봉(삼성전자)을 LEAN 에 넣어 날짜별 RSI · ATR · 볼린저를 뽑는 작은 알고리즘을 쓰고, 우리 값과 맞댄다. 지금 앱의 LEAN 연결(`lean_backtest.py`)은 전략 수익률용이라 지표 값을 내지 않는다. 대조는 이 PC 의 LEAN 도커(`LEAN_MODE=docker`)로 돌린다. 「정한 오차」 숫자는 8절 ③.

### 4.2 지표 함수 규격 (`P02-②-2` ★)

| 규칙 | 내용 | 시험 |
|---|---|---|
| 미래 안 보기 | 날 t 의 값은 t 까지의 봉만 쓴다 — 뒤 봉을 바꿔도 앞 값이 같다 | TC-LA(`tests/test_ta_utils_lookahead.py` · 이미 있음) |
| 이어서 갱신 | 새 봉 하나가 오면 이어 붙인 값 = 전체를 다시 계산한 값 | TC-LA 에 더함 |
| 정의 한 벌 | 기본 지표는 `ta_utils` 하나 | TC-IN |
| 같은 입력 같은 값 | 커스텀 산식도 같다(`P02-②-1`) | TC-IN |

자유 산식 DSL 은 문법에서 미래 참조를 막는다(`shift` 양수만 · `formula.py` 머리말). 새로 할 것은 「이어서 갱신」 시험과, 시험 하나로 기본 지표 · 커스텀 산식을 함께 지키는 일이다.

### 4.3 전략 카드 (`P02-①-2`)

**판 1 — 계약 칸만(10/27 연결 시험용).** 계약 v0.5 1절의 칸만 쓴 고정 입력이다. 합격 판정을 받은 전략이 아니라 `backtest_result` · `acceptance` 는 넣지 않았다. 파일: [`예시/strategy-card-ma-cross-v1.json`](예시/strategy-card-ma-cross-v1.json). `apply_strategy_spec_to_signal` 에 넣으면 20일선이 60일선 위로 가는 종가에 「매수」, 아래로 가는 종가에 「매도」 가 나온다(2026-10-22 실행).

**판 2 — 더할 칸(10/27).** #314 2절에 알렸다. 칸의 값은 대부분 #161 · #159 · #183 에서 합의한 것이고, 칸 이름(이미 코드에 있는 이름을 따름)과 손익비 기본값은 #314 에서 반응을 기다린다(8절 ①). 「상태」 칸에 나눠 적었다.

| 칸 | 이름 · 값 | 상태 · 출처 |
|---|---|---|
| 수량 방식 | `position_sizing.size_kind` = `risk_pct` · `fixed_budget` / `risk_pct` = 1.0(%) | 값은 **합의**(#161 A1 · #183) · 이름은 **#314 반응 전**(오준영 님 `execution_policy.py` 12 · 13줄을 따름) |
| 체결 시점 | `entry_mode` · `exit_mode` = `close` · `open` | 값은 **합의**(#161 Q1 · Q2 · 같은 뜻의 `entry` = `close` · `next_open`) · 이름은 **#314 반응 전**(강민석 님 `quant_pipeline.py` 298 · 314줄을 따름) |
| 손절 | `stops.stop_kind` = `atr` · `pct` / `atr_period` 14 · `atr_mult` 2.0 | 값은 **합의**(#161 A1 · A2 · #159 T2) · 이름은 **#314 반응 전** |
| 익절 | `stops.take_kind` = `rr` / `take_rr` 1.5 ~ 3 에서 조정 · 기본값 2 | 범위는 **합의**(#159 T2 · 강민석 님 의견) · 기본값 2 는 **#314 반응 전**(#161 · #159 에 1.5 로 적었던 것을 #314 에서 바로잡음) |
| 손절 판정 | `judge` = `close` · `next_open` · `intrabar` | **합의**(#161 · 강민석 님 의견으로 셋) |
| ATR 고정 | `lock` = `entry` — 진입 때 정하고 보유 중 고정 | **합의**(#161 A1 · 이견 없음) · 「보유 중 고정」 은 #183 에서 드린 의견 |
| 다시 진입 | `reentry` = `new_signal` — 청산 뒤 새 매수 신호에서만 | **합의**(#161 A1 · 이견 없음) · 지금 백테스트 엔진과 같음(#161 Q1) |

- ATR 을 판단 시점의 마지막 확정 일봉까지로 계산하는 것은 #183 에서 드린 의견이다(반응 전).
- 백테스트 결과 응답에 체결 시점 · `judge` 를 같은 이름으로 싣는다 — **합의**(#161 A3 · 강민석 님 찬성).
- 계약 파일은 고치지 않는다. 지금 자동매매는 카드에서 `max_symbols` 만 읽어(`auto_trade.py` 400줄) 칸을 더해도 동작이 그대로다.
- 저장은 기능 설계서 8절 T6(`custom_indicators` 를 D6 ④ 14칸으로 넓혀 규칙 JSON · 해시 · 판 · 결정 D6 ④ 확정), 백테스트 결과는 T7 의 「규칙 판」 칸으로 카드를 가리킨다.
- 카드 칸이 바뀌면 카드의 `version` 을 올리고, 카드를 읽는 세 분(Pine · LEAN · 자동매매)을 PR 에 부른다.

### 4.4 커스텀 지표 · 판 (`P02-②-1` · `②-3`)

- 자유 산식으로 여러 지표를 정규화(z점수 · 백분위)해 합친 지표를 정의한다 — 예: `(close - sma(close, 20)) / std(close, 20)`.
- 판 저장 · 되돌리기 API(`/api/formula-indicators/{id}/versions` · `restore`)는 이미 있다. 먼저 #243 「받지 않은 것」 2번(저장한 지표를 연 뒤 식을 고쳐도 저장본으로 계산)과 커스텀 경로가 비용 인자를 버리는 것(요구 대장 `P02-②-1` 「막는 것」)을 고친다.
- `formula.py` 는 강사님 기초 코드라 주석을 늘리지 않는다(코딩표준 2절).

### 4.5 기준 전략 선정 (`P02-①-3`)

- 조합표는 미리 적고 상한을 둔다(요구 완료 기준). 시도는 모두 T7 에 기록한다(시도 번호 · 카드 판 · 격자 판 · 비용 모델 판).
- 합격선은 D6 ⑦ 확정(교안 기준 + PF · 거래 단위 · 비용 차감 후). 상한 숫자 · 고르는 잣대는 8절 ④.
- 백테스트 엔진 `quant_pipeline.py` 는 강민석 님이 체결 시점을 넣은 파일이라, ATR 손절 · 위험 수량을 넣을 때 강민석 님과 맞춘다.

## 5. 대안

| 대안 | 고르지 않은 까닭 |
|---|---|
| 새 명세 파일을 따로 만든다 | 자동매매가 이미 전략 스펙을 읽는다 — 따로 두면 원본이 둘이 된다 |
| 계약 파일에 칸을 더한다 | 강사님 원본과 같게 두는 자리라 다음 반영 때 어긋난다(docs README 3.3절) |
| 칸 이름을 새로 짓는다 | 오준영 님 · 강민석 님 코드에 이미 이름이 있다 — 두 벌이 생긴다 |
| 손절을 고정 % 로만 | 기본 위험 1% 에서 위험 기준이 수량을 정하지 못한다(#183 답 2) — ATR 을 기본, % 는 비교용(#161 A2) |
| 규칙을 Pine 코드로 적고 파이썬이 따라 한다 | Pine 은 TradingView 밖에서 돌지 않는다 · 기능 설계서도 「명세 → Pine」 방향 |

## 6. 뒤집을 조건

- LEAN 지표 값이 정의 차이로 맞지 않으면 → 대조 기준을 다시 정하고 차이 원인을 적는다.
- 카드를 읽는 쪽(Pine · LEAN · 자동매매)이 칸을 읽지 못하면 → 칸을 줄이고 카드 판을 올린다.
- #314 에서 카드 꼴 · 칸 이름 · 손익비 기본값에 다른 의견이 오면 → 4.3 을 그에 맞춰 고친다.
