## 0. 쉬운 요약 다섯 줄

1. **그림자 일지**는 증권사에 주문을 내지 않고, 정해 둔 규칙이 「그날 이렇게 판단하고 다음 날 아침 시가에 이렇게 샀을 것」 을 매 거래일 한 줄씩 남기는 기록이다. 매매가 없는 날(관망)도 남긴다.
2. 규칙은 둘을 등록한다 — 신장환 님 카드 판 1(`ma_cross_20_60` · 005930) · 지금 자동매매 기본 규칙(31종목 점수 상위 3). 둘 다 **앱의 실제 판단 함수를 그대로** 부르고, 주문 크기도 자동매매 기본값 그대로다.
3. 규칙 코드가 바뀌면 실행기가 **지문으로 알아채 새 판으로 등록**한다(시도 수 +1). 판마다 등록 뒤 첫 장 마감부터가 그 판의 봉인 구간이다. 판 1 의 봉인 구간은 2026-10-26(월)부터다.
4. 2026-09-01 ~ 판 1 등록 전 마지막 거래일은 「사후 봉인 시험」 등급으로, 판 1 등록 직후 **한 번만** 열어 계산한다(개봉 기록을 남긴다).
5. 기록은 앱 DB 표 셋에 **추가만** 하고, 같은 줄을 HF 비공개 원장 `qurious-quant/qurious-paper-log` 에 날짜별 파일로 덧붙인다. 지난 파일이 바뀌면 올리기를 멈춘다.

## 1. 무엇을 · 왜 — 범위

| 칸 | 내용 |
|---|---|
| 하는 것 | 국내 일봉 · 규칙 판 고정 · 매 거래일 1행(관망 포함) · 다음 거래일 시가 가상 체결 · 세목별 비용 · 판 등록 · 판 바뀜 감지 · 사후 봉인 시험 · HF 원장 · 12:30 러너 단계 |
| 왜 지금 | 전진 기록은 「규칙을 정한 뒤에 생긴 날」 만 증거가 된다 — 등록이 하루 늦으면 표본 외 기록이 하루 짧다(조사 0.4절 · 결정 대장 10-24 「실행기 10-25」). 11-05 까지 9거래일 · 11-11 까지 13거래일 |

| 쓰는 곳 | E2 판정(강민석 님 · 10절) · 같은 기간 백테스트와의 네 층 맞대기(신호 · 결정 · 체결 · 성과 · 발표 뒤 B1) · rfp-2 「모의 투자 의사결정 일지」 |

**왜 「그림자」 인가.** 기존 장부(`orders` · `portfolio`)에 섞지 않는다 — 회전율 · 계좌 초기화 · 100일 백테스트 주문과 섞이면 판정할 수 없다(결정 대장 10-23 · 조사 1.1절). 실제 결정에 쓰지 않는 판을 같은 입력에 돌려 결과만 남기는 섀도 시험의 꼴이다(조사 [W29]).

## 2. 하루 흐름 — 한 행 = 거래일 하루

수집 DB 의 일봉은 공공데이터포털이 **다음 영업일 낮**에 준다(D7 2.6.1 실측). 그래서 거래일 D 의 행은 D+1 12:30 러너가 D 의 봉을 넣은 뒤(13:30 즈음)에 생긴다. 한 행에는 D 의 시가 · 종가가 다 들어 있으므로 **한 번 쓰고 다시 고치지 않는다**(D7 의 「결정일 · 체결 확정일」 두 칸은 행 D 의 판단과 행 D+1 의 체결로 나뉜다).

## 3. 등록 규칙 둘 — 판 1 · 시도 수 2

| 칸 | `card_ma_cross_20_60` | `auto_default` |
|---|---|---|
| 무엇 | 신장환 님 카드 판 1 — 이동평균 교차 20 · 60 일봉 | 지금 자동매매의 기본 규칙(전략 카드 없이) |
| 종목 | 카드에 적힌 `005930` 하나(10-24 결정 7 — 실제 코드는 AI 상위 3 과 안 겹치면 상위 3 에 카드를 씀 · 12절) | 31종목(`stock.QUANT_STOCKS`) 중 그날 점수 상위 3(`quant_ai_top_n` 기본값) |
| 지표 | `stock.get_quant_indicators(symbol, "2y")` — 수집 DB 수정주가 · D 종가까지(4절 「기준일 고정」) | 같음 |
| 판단 | `auto_trade.apply_strategy_spec_to_signal(signal, 카드, None, 지표)` — 카드 진입 · 청산 규칙이 행동을 정함(청산 우선): SMA20 > SMA60 → 매수 신호 · SMA20 < SMA60 → 매도 신호 | `stock._generate_signal` 의 행동(RSI · 5/20 교차 · 볼린저 점수 → 강력 매수 ~ 강력 매도) |
| 크기 | 매수 신호마다 100만 원어치(`max(1, int(예산 ÷ 판단가))`) · 종목 비중 30% 까지(`risk_guard.cap_buy_quantity`) · 매도 신호마다 보유의 50%(`max(1, int(보유 × 0.5))`) · 하루 주문 20건 — `BrokerSettings` · `RiskLimits` 기본값을 읽어 판에 적는다(10-24 결정 5) | 같음 |
| 시작 자금 | 1,000만 원(자동매매 장부 `_INITIAL_CAPITAL` 과 같음) | 같음 |
| 일손실 3% | 표시만 — 그날 행에 「실제 자동매매였다면 비상 정지」 · 주문은 이어감(10-24 결정 6) | 같음 |

- 두 규칙 모두 **판단 · 지표 · 비중 상한 · 비용은 앱의 함수를 그대로 부른다.** 주문을 모으는 순서와 크기 셈(`_run_quant_cycle` 안의 몇 줄)만 일지가 옮겨 적었다 — 그 옮긴 함수도 지문에 들어간다(4절).
- 카드 판 2(신장환 님 · 10-27 예정)가 나오면 같은 규칙의 새 판으로 등록한다(시도 수 +1 · 결정 대장 10-23).
- 기준선(매수 후 보유 · 동일가중 · KOSPI 자체 재현)은 판단이 아니라 같은 기간 가격으로 판정 때 계산한다 — 일지에 넣지 않는다.

## 4. 판 등록 · 판 바뀜 · 봉인 구간

### 4.1 판 지문 — 무엇이 바뀌면 새 판인가

판 지문은 아래 조각마다 SHA-256 을 내고, 조각 이름과 값을 정렬해 다시 SHA-256 을 낸 값이다. 함수는 **주석 · 문서 문자열 · 공백 · 줄바꿈을 뺀 구문 나무**(`ast.unparse`)로 재므로 주석만 고친 PR 은 판을 바꾸지 않는다. 자료(종목 목록 · 세율표 · 카드)는 정렬한 JSON 으로 잰다.

| 묶음 | 조각 | 바뀌면 |
|---|---|---|
| 공통 — 지표 · 판단 | `stock.get_quant_indicators` · `_generate_signal` · `_calc_rsi` · `_calc_sma` · `_calc_bollinger` · `_rounded` · `ta_utils.rma` · `rsi` · `bollinger` | 새 판 |
| 공통 — 자료 다리 | `collector_db.read_daily_candles` · `_candle` · `_QUERY` | 새 판 |
| 공통 — 크기 · 비용 | `risk_guard.cap_buy_quantity` · `trading_cost.order_costs` · `cost_rate` · `tax_rates` · `TAX_SCHEDULE` · 수수료 상수 · `DEFAULT_SLIPPAGE_BPS` | 새 판 |
| 공통 — 일지 자신 | `paper_journal` 의 판단 · 크기 · 체결 · 평가 함수 · 판 명세(`rule_spec` 이 만든 JSON — 기본값 · 카드 포함) | 새 판 |
| `card_ma_cross_20_60` | 카드 JSON · `auto_trade.apply_strategy_spec_to_signal` · `evaluate_spec_rules` · `_sma_last` · `_SIGNAL_SCORE_SCALE` | 새 판 |
| `auto_default` | `stock.QUANT_STOCKS` · 상위 N 고르기 | 새 판 |
| 참고(판은 그대로) | `auto_trade._run_quant_cycle` · `_execute_virtual_trade` · `apply_strategy_spec_to_symbols` · `stock.get_candles` | 행 `flags` 에 「참고 지문 바뀜」 — 실제 자동매매 회차가 일지와 달라졌을 수 있다는 표시 |

### 4.2 등록 · 판 바뀜

| 때 | 누가 | 하는 일 |
|---|---|---|
| 판 1 | 사람(`python scripts/paper_journal.py register --rule …`) | 지문 · 명세 · 커밋을 고정하고 봉인 시작일을 정한다 · 사후 봉인 시험 구간을 연다(개봉 기록) |
| 판 n+1 | **기계** — 매 회차 처음에 지문을 다시 재서 등록 판과 다르면 | 바뀐 조각 이름 · 커밋을 적고 새 판 등록(시도 수 +1 · `registered_by = auto_fingerprint`) · 그 회차 종료코드 10(러너 「경고」 · 관제 🟡) · 옛 판의 남은 날은 계산하지 않는다(옛 코드가 없다) |
| 판 바뀜 뒤 | 이동원 · 다음 세션 첫머리 | 까닭 한 줄을 메모 표에(`note` 명령) — 판 줄은 고치지 않는다 |

- **새 판은 새 계좌로 시작한다**(1,000만 원 · 보유 없음) — 판마다 따로 판정한다(「시계를 처음부터」 · D7 ⑦).
- 판 수 = 시도 수다. 시도 수는 모든 규칙을 통틀어 센다(D4 ⑦ 「시도 조합 수」).

### 4.3 봉인 시작일 · 사후 봉인 시험

| 칸 | 규칙 |
|---|---|
| 봉인 시작일 | 등록 시각 뒤 처음 마감(15:30)하는 거래일 — 거래일 15:30 전 등록이면 그날 · 아니면 다음 거래일(거래일 달력 `market_calendar` · 없으면 평일). **판 1 = 2026-10-24(토) 등록 → 10-26(월)** |
| 전진 행 | 거래일 ≥ 봉인 시작일 — 등급 `forward` |
| 사후 봉인 시험 행 | 판 1 에만 · 2026-09-01 ~ 봉인 시작 전 마지막 거래일 — 등급 `post_hoc` · 등록 직후 한 번 계산(그 뒤 다시 계산하지 않음 · 추가만) · 개봉 기록을 메모 표에 |
| 이 등급을 쓰는 법 | 판정은 전진 행으로 · 사후 행은 「한 단계 약한 증거」(조사 0.4절 등급 2 — 사람이 그 기간 시장을 보았고 100일 백테스트가 그 기간을 이미 읽음) |

## 6. 체결 · 비용 · 평가

| 칸 | 규칙 | 근거 |

| 보유 없음 매도 | 미체결 | 같음 |

| 파일 | 내용 | 바뀌나 |
|---|---|---|
| `versions/<규칙>-v<판>.json` | 판 줄 하나 | 안 바뀜 |
| `notes/<번호>.json` | 메모 한 줄 | 안 바뀜 |
| `rows/<규칙>/v<판>/<거래일>.parquet` | 그날 행 하나(묶음 칸은 JSON 글자) | 안 바뀜 |
| `manifest.json` | 파일마다 바이트 · 파일 SHA-256 · **내용 SHA-256**(행을 정렬한 JSON 으로) · 개수 | 올릴 때마다 |
| `README.md` | 데이터셋 카드(칸 설명 · 등급 · 한계) | 드물게 |

- 새 파일이 없으면 올리지 않는다(빈 커밋 없음).
- 저장소가 **private 인지 먼저 본다** — 아니면 멈춤. 없으면 private 으로 만든다. 공유 스위치(`QURIOUS_RAW_SHARING`)는 러너가 올리기 단계에만 켠다(다른 올리기와 같음).
- 공개 위치(GitHub · Pages)에는 원자료를 올리지 않는다(D2 ⑤ K1).

## 12. 알려진 한계 · 다음 판

1. **배당 · 분할을 장부에 넣지 않는다** — 자동매매 장부와 같다. 보유 중 조정 사건은 표시만 한다(봉인 첫 구간에는 대형주 배당락이 없다 — 삼성전자 분기 배당 기준일은 12월).
2. **판단이 하루 늦다** — 실제로는 D 종가를 보고 D+1 장 전에 주문하지만 우리 자료는 D+1 낮에 온다. 행 D 의 판단은 D 까지의 자료만 쓰므로 값은 같다(지연 몫은 백테스트와 맞댈 때 따로 센다 · 조사 5.2절).
3. **체결 현실성은 재지 않는다** — 가상 체결이라 거절 · 지연 · 시장 충격이 없다. 그것은 KIS 모의 경로 점검(오준영 님 B14)의 몫이다.
4. **실제 자동매매와 다를 수 있는 곳(확인 거리 · 오준영 님)** — 실제 코드는 카드 종목이 AI 상위 3 과 겹치지 않으면 상위 3 종목에 카드 규칙을 쓴다(`apply_strategy_spec_to_symbols` 「교집합이 없으면 원본 유지」). 일지는 카드에 적힌 종목만 쓴다(10-24 결정 7).
5. **실제 자동매매와 같아서 드러나는 곳(확인 거리 · 오준영 님)** — 기본 규칙은 그날 점수 상위 3 종목만 판단하므로, 상위 3 에서 빠진 보유 종목은 매도 신호가 나도 팔지 않는다(`_run_quant_cycle` 이 `target_symbols` 만 돈다 · 위험 기준 수량 모드의 손절과 공격 모드만 예외 — 둘 다 기본값은 꺼짐). 일지는 실제 코드와 같게 둔다 — 그림자 일지가 이런 동작을 기록으로 보여 주는 것이 쓸모다.
6. **등록 뒤에는 지문 조각 함수를 고치지 않는다** — 고치면 다음 회차가 새 판을 등록한다(설계대로). 그래서 판 1 등록 전에 합성 자료 시험 · 깨 보기 · 2026-08 실자료 시운전(봉인 구간 앞)을 마쳤다(테스트 계획서 4.30). 내보내기 · 올리기 · 명령 줄처럼 지문 밖의 코드는 판과 상관없다.
7. 화면 · 조회 API 는 다음 판 — 판정 화면을 강민석 님과 정한 뒤(기능 설계서 4.4 의 `GET /api/paper/journal` 안).

| 그림자 일지 | 실제 주문 없이 규칙의 판단 · 가상 체결을 매일 남기는 기록 | `paper_journal_days` 한 행 = 한 판의 거래일 하루 | 모의계좌(PAPER) · 자동매매 장부(QUANT)와 다른 표다 |
| 판 · 시도 수 | 규칙을 고정한 한 벌 · 지금까지 등록한 판의 수 | `paper_journal_versions` 한 줄 | 지표 정의 판(`ta_utils.DEFINITION`)과 다른 말 |
| 판 지문 | 규칙을 이루는 함수 · 자료의 SHA-256 묶음 | 주석 · 공백은 빼고 잼 | 파일 전체가 아니라 함수 단위 |
| 봉인 구간 · 봉인 시작일 | 결과를 보기 전에 떼어 둔 기간 · 그 첫 거래일 | 판마다 등록 뒤 첫 마감일부터 | 목표 기능 ② 설계서의 「09-01 이후 봉인」 은 판 1 등록으로 「사후 봉인 시험」 이 된다 |
| 사후 봉인 시험 | 이미 있는 기간을 규칙을 고정한 뒤 한 번만 여는 시험 | 판 1 의 09-01 ~ 10-23 | 전진 기록보다 한 단계 약한 증거 |
| 재계산 | 예정보다 늦게 계산한 전진 행 | `recomputed = true` | 값은 같다 — 늦었다는 표시일 뿐 |
