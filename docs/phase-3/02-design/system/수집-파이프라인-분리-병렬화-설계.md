## 3. 의존 관계 — 무엇이 무엇 뒤에 와야 하나 (`STEPS` 주석에서 읽음 · 코드 확인 전)

```
받기(10)  ──▶  search(457)                     ← 공시 · 뉴스 색인(받기 뒤 · 계산 체인과 무관해 보임 — H1)
   └──▶ calendar(12) ──▶ adjusted(331) ──▶ total_return(212) ──▶ benchmark(129)
                                  └──▶ ohlcv(558) ──▶ quality(0.4) ──▶ signals(25) ──▶ journal(17)
                                                              └──▶ export(246) ──▶ verify(20) ──▶ upload(43) ──▶ ohlcv_upload(62) ──▶ journal_upload(10)
```

- 확실한 순서(주석으로 확인): `calendar` → `adjusted` → `total_return` → `benchmark`(배당락일이 바뀌면 TR 을 다시 만든다) · `quality` 는 이 셋 뒤 · `signals` 는 일봉 뒤 · `journal` 은 신호 뒤.
- **겹칠 수 있어 보이는 쌍(가설)**: `search` ∥ `calendar → adjusted → … `(색인은 공시 · 뉴스 · 정책뉴스를 읽고 가격 계산 체인을 안 읽는다) · 받기 단계끼리(`gdelt` ∥ `financial_full` ∥ DART 나머지 — 단 DART 하루 한도를 같이 씀).
- **못 겹치는 것**: 같은 DB 표를 쓰는 단계 · 앞 단계 산출물을 읽는 단계 · 올리기(`upload`)는 내보내기 뒤.

## 5. 지켜야 할 제약(겹쳐 돌릴 때)

- **SQLite 는 쓰는 쪽이 하나**다(WAL 이어도). 같은 DB 파일에 쓰는 단계끼리는 겹치지 않거나, 계산은 겹치고 **쓰기만 한 줄로 줄 세운다**. 시장마다 DB 를 나누는 방향(시장 레지스트리의 `us_market` · `crypto_market` 따로)은 이 제약에도 맞는다.
- **DART 하루 한도**(2만 건) · 외부 요청 속도 한도는 단계가 겹쳐도 합쳐서 지킨다(`DART_CAPS` · `ratelimit`).
- **12:30 회차 · 임대(lease)** — 한 자리 한 PC 규칙과 판 문지기를 깨지 않는다. 러너 파일은 모든 PC 가 같은 판이어야 하므로 바꾸면 프로토콜 번호를 올린다.
- **결과가 같아야 한다** — 병렬 · 증분으로 바꾼 단계는 바꾸기 전후 산출물 지문(행 수 · 해시)을 같은 입력으로 대조한다(TC-BF · TC-DU 같은 기존 시험 + 새 지문 시험).
- **12:25 ~ 13:10** 에는 러너 파일을 건드리지 않는다.
