## 1. 이번 구현

`app/services/asset_allocation.py`의 `asset_allocation(risk_profile, horizon_years)`가 자산군 비중의 정본이다. 키는 국내주식·해외주식·국내채권·대체자산·현금 그대로이며, 성향 셋 × 기간 1~10년 모두 합계 100%, 음수 없음이다. 장기 보정은 현금과 채권의 기존 잔여 비중 이내로 제한한다. 음수가 아니던 기존 결과는 유지한다. 예: 공격형 10년은 47/37/8/8/0이다.

| API | 계약 |
|---|---|
| `GET /api/ml/robo/weights?risk_profile=moderate&horizon_years=3` | 로그인 필요. `risk_profile`, `horizon_years`, `allocations` 반환. 성향·기간 오류 422. 시장·캐시·DB 계산 없음. 상품 안내 화면이 사용 |
| `POST /api/ml/robo/allocation` | 기존 시장 계산 후 사용자별 최신 결과 자동 저장. 기존 결과 필드와 `saved: {id, saved_at}` 반환. 실패하면 이전 저장본 유지 |
| `GET /api/ml/robo/allocation/latest` | 로그인한 본인의 `{id, saved_at, result, handoff}` 반환. 저장본 없으면 404. 전달할 수 없는 결과는 `handoff: null` |

`allocation_results`는 사용자당 한 행이다. `user_id`(PK·users FK CASCADE), `result_id`(UUID), `result`(JSONB), `updated_at`을 저장한다. 과거 이력을 계속 쌓지 않는다. 탈퇴 시 삭제된다. `0020_paper_epoch → 0021` 마이그레이션이 필요하다.

## 2. 국내주식 부분만 가져오는 기준 — 팀 검토 요청

현재 최적화 후보는 국내주식이다. 해외주식 비중까지 국내 종목에 합산하던 계산을 수정했다. 국내주식 자산군 비중만 최적화 상대 비중대로 나누고, 소수 둘째 자리에서 합계가 정확하도록 잔여 0.01%p를 배분한다.

리밸런싱 전달 정책은 `domestic_equity_only_v1`이다. 중립형 3년의 자산군 배분은 30/25/30/10/5로 보존하지만, 실행 가능한 목표는 국내주식 30%·현금 70%다. 해외주식 25%·채권 30%·대체자산 10%를 아직 매수하지 않는다는 사실과 종목별 비중을 확인창에 명시하고 동의받는다. 이를 완전한 5자산군 투자라고 표시하지 않는다. ETF 매핑은 후속 검토 대상이다.

추천 종목 화면도 같은 국내주식 비중을 사용한다. 예상 성과 및 목표 시뮬레이션 기본값은 국내주식 바스켓과 나머지 현금의 조합이다. 기존 현금 연 2.5% 가정은 유지하되 화면에 명시하며, 5자산군 실현 수익률로 해석하지 않는다.

## 3. 사용자 흐름과 실행 경계

1. 자산배분 계산 완료 시 결과를 자동 저장한다. `저장한 배분 보기`로 새 접속에서도 다시 볼 수 있다.
2. 리밸런싱의 `저장한 배분 가져오기`에서 저장 시각·종목·미적용 자산군·현금 비중을 확인한다.
3. 취소하면 편집값을 유지한다. 확인하면 편집안에만 목표를 채우고 편집안의 자동 실행을 끈다.
4. 저장 전 서버의 기존 플랜·예약은 그대로다. 상태 조회로 편집안을 덮어쓰지 않으며, 가져온 목표 저장 전에는 미리보기·조건 점검·실행 요청을 막는다.
5. `플랜 저장`을 눌러야 기존 플랜 API에 목표를 보낸다. 저장 자체로 주문하지 않는다. 이후 기존 미리보기→승인→예약→정산 흐름을 사용한다.

전체 자산 비중의 기준은 기존 리밸런싱의 관리 대상 자산이다. `플랜 외 종목 보호`를 켜면 해당 보유 종목은 계산에서 제외되므로, 가져오기만으로 계좌 전체 자산군 배분을 보장하지 않는다.

## 6. #179 의견 반영 — 상품 안내 소비 계약

이동원 의견과 주담당 판단으로 다음 계약을 유지한다. 국내주식 부분 적용·최신 한 건 정책의 팀 전체 승인으로 확대하지 않는다.

- `latest`는 로그인한 본인의 마지막 **성공한 계산** 한 건이다. 다른 기기에서도 같은 저장본을 읽으며 조회 시 현재 진단 성향으로 재계산하지 않는다. 향후 복수 저장이 생겨도 이 의미를 유지한다.
- 필수 필드는 최상위 `id`, `saved_at`, `result`, `handoff`, 결과의 `risk_profile`, `horizon_years`, `allocations`다. 자산군 키 다섯과 백분율 단위를 유지한다. `saved_at`은 시간대를 포함한 ISO 8601 문자열이다. 기존 최적화·종목·성과 필드도 유지한다.
- 두 GET의 응답 모델을 OpenAPI에 명시했다. 소비자가 추가 필드를 허용하도록 기존 결과 확장 필드도 반환한다. 필드/단위/의미 변경은 #179에 먼저 알린다.
- 상품 안내 진입 시 저장본을 한 번 조회하고, 저장본이 있으면 저장된 성향·기간·비중·저장 시각을 사용한다. 현재 진단 성향과 다르면 저장본을 유지하며 재계산 안내를 보인다.
- **404일 때만** 진단 성향·3년 기준 경량 비중으로 대체한다. 인증 실패·통신 실패·서버 오류는 저장본 없음으로 간주하지 않고 원인을 안내한다.
- `handoff: null`은 리밸런싱으로 가져올 수 없다는 의미다. 상품 안내가 유효한 자산군 비중을 읽지 못한다는 뜻은 아니다.
- 상품 안내 자동 조회·오류 표시·화면 시험과 API ID 대장/명세서는 이동원 PR 범위다. 이번 변경은 서버 계약 명시·시험·이 문서에 한정한다.
- 신규 HTTP 시험 5건: 진단과 다른 저장 성향/기간 보존, 확장 결과 보존, 가져오기 불가 시 비중 조회, 인증/404/서버 오류 구분. 기존 실제 PG 저장·계정 격리 시험도 함께 실행했으며 `test_asset_allocation.py`, `test_products_screen.py`, `test_migration_heads.py` 합계 53건 통과했다.

개정: v0.2 (2026-10-14) — #179 소비 계약·응답 스키마·오류 구분 반영. 최초 구현 검증 수치는 4절의 당시 기록이다.

## 7. #217 국내 상장 ETF 후보 연결 (2026-11-02)

기본 `latest` 조회와 `domestic_equity_only_v1` 정책은 유지한다. 리밸런싱 화면에서 **「해외주식·채권·대체자산도 국내 상장 ETF 후보로 채우기」**를 선택하면 `GET /api/ml/robo/allocation/latest?include_etfs=true`가 `domestic_listed_etf_liquidity_v1` 편집안을 돌려준다. 저장된 성향·기간·배분 결과는 그대로이며, GET으로 플랜·예약·주문을 생성하지 않는다.

- 국내주식 비중은 기존 최적화 종목으로 유지한다. 해외주식·국내채권·대체자산별로 국내 상장 ETF 한 개를 연결한다. 원래 현금 비중은 투자하지 않는다.
- 후보 자료는 상품 안내와 같은 `product_etfs.selection_catalog()` 및 `etf_classify`다. 분류는 상품명·기초지수 규칙이며 거래소 공식 상품 적합성 분류나 수익 추천이 아니다.
- 거래정지 여부가 명시적으로 정상, 배수 1, 단일종목/파생 묶음 아님, 레버리지·인버스·선물·합성·옵션 전략 제외, 최근 20개 관측일의 양의 거래대금, 유효 종가·순자산·평균 거래대금이 있는 후보만 자동 선택한다. 상품 안내 전체 목록에서는 제외하거나 숨기지 않는다.
- 후보는 **20일 평균 거래대금 내림차순 → 순자산 내림차순 → 코드 오름차순**으로 결정한다. 각 자산군의 선택 근거와 기준일을 확인 창 및 편집안 안내에 표시한다.
- 거래일 달력으로 마지막 확정 거래일을 확인한다. 당일 장중에는 직전 거래일을 사용하고 15:30 이후에는 당일 자료가 있어야 한다. 수집이 늦거나 달력/자료가 없으면 409/503으로 안내하며 이전 목표를 유지한다.
- 후보가 없는 자산군은 `unapplied_allocations`에 남기고 해당 비중을 현금에 합친다. 종목 목표와 현금의 합계는 100%다. 부적합 후보로 자동 대체하지 않는다.
- 확인을 취소하거나 조회가 실패하면 편집 중인 목표·자동 실행 체크를 유지한다. 확인하면 화면 편집안의 자동 실행을 끄고 기존 미리보기를 폐기한다. **플랜 저장 전까지 서버의 기존 플랜·예약은 그대로**다. 가져온 편집안은 저장하기 전 주문 미리보기/예약 실행을 막는다.
- 종목 허브의 「리밸런싱 목표 편집으로」는 코드만 입력 칸으로 전달하고 이전 비중 입력은 비운다. 사용자가 비중 입력→추가→플랜 저장을 확인한다. 기존 테마 플랜이나 목표 비중을 자동 변환하지 않는다.

정본: `app/services/etf_allocation.py`, `product_etfs.py`, `app/routes/ml.py`, `public/js/rebalance.js`, `stockdrawer.js`. 검증: `test_etf_followups.py`(실제 수집 SQLite 스키마·후보/날짜/현금·GET 무변경), `test_followup_screen_flows.py`(실제 JS 취소/실패/저장 전 차단·종목 전달), 기존 `test_asset_allocation.py`(계정별 PG 저장)와 리밸런싱 회귀 시험. 실제 ETF 주문·성과를 검증한 결과는 아니다.

## 5. 2026-11-03 자산군 배분 모델 확장

주담당 오준영이 리스크 패리티·Black–Litterman·국면별 배분 구현을 직접 승인했다. RFP2-3.1.3-②의 최소분산도 함께 구현한다. 기본 `profile` 요청과 저장본은 기존 성향·기간 동작을 유지한다. 국내주식 종목 선정/최적화와 네 자산군 배분을 구분한다.

| `allocation_model` | 계산 계약 |
|---|---|
| `risk_parity` | 연 공분산으로 자산군별 분산 기여 비율을 균등화한다. 현금 제외 자산군 1~95% 제약, 최종 반올림 뒤 제약·합계 보존. 제약 때문에 완전한 균등화가 안 되거나 반올림 차이가 남으면 최대 차이를 표시한다. |
| `minimum_variance` | 같은 공분산과 제약 아래 분산을 최소화한다. |
| `black_litterman` | Π=3Σw0, τ=0.05. 상대 전망 A−B의 연 초과수익(%p)와 신뢰도 0~99%를 반영한다. Ω의 대각은 τPΣP′×(1−신뢰도)/신뢰도. 뷰 없음·신뢰도 0은 기준 비중을 보존한다. 기본 w0는 성향 배분이며 실제 시가총액 시장 비중이 아니다. 사용자가 다섯 자산군 기준 비중을 직접 입력할 수 있다(0.1% 단위·합계 100%). 전망은 같은 쌍 중복 없이 최대 6개. |
| `regime` | 국내주식 대용 ETF의 종가/120일 평균 ≥1이면 상승, 최근 20일 표본 표준편차×√252 ≥20%이면 고변동. 상승·저변동 / 상승·고변동 / 하락·저변동 / 하락·고변동의 기준 주식 비중 배수는 1.1 / 0.85 / 0.75 / 0.5. 주식 축소분은 채권 70%·현금 30%, 확대 재원은 기존 채권·현금 비율로 조달한다. |

자료는 KODEX 200(069500), TIGER 미국S&P500(360750), KODEX 국고채3년(114260), KODEX 골드선물(H)(132030)의 종가를 자산군 대용치로 쓴다. 대체자산 전체를 금 하나가 대표하는 한계가 있으며 자동으로 해당 ETF를 매수하지 않는다. 수집 DB `etf_daily`를 읽기 전용으로 우선 사용하고 없는 경우 기존 시세 제공 경로를 사용한다. 배당·기업행동·비용·세금은 미조정이다. 계산 모델의 성과와 실제 국내주식+현금 실행 성과를 혼동하지 않는다.

모델 계산은 전날까지의 자료만 받아 미래/당일 진행 중인 봉을 제외하고, 최대 756개의 공통 수익률을 쓴다. RP/최소분산/BL은 최소 60개, 국면은 120개가 필요하다. 결측 날짜를 전일 값으로 채우지 않고 해당 날짜와 다음 날 수익률을 제외한다. 자산군별 마지막 날짜가 다르거나 중복·비정상 가격·계산 미수렴이면 422를 반환하고 기존 저장본을 보존한다. 실제 기준일·표본 수·출처·입력 SHA256·기준 비중·전망·위험 기여도를 저장한다. 오래된 자료를 최신이라고 표시하지 않는다.

국면이 달라지면 **다시 계산한 저장본의 목표 비중**이 달라진다. 이 절의 최초 구현은 §3의 가져오기→명시적 저장 흐름이며, 이후 추가한 예약 점검의 자동 목표 교체는 §8을 따른다. 기존 ETF 편집안 기능은 그대로 사용할 수 있고, 계산용 대용 종목이 실행 상품 선택을 강제하지 않는다.

동시에 기존 국내주식 최적화에서 자르기 후 정규화로 60% 제한이 92.3%까지 풀리던 결함과 공통 표본 부족 시 SVD 오류를 수정했다. 최종 표시 비중 합계는 100%, 종목별 5~60%이다. 기존 최소분산/수익 틸트 산식을 완전한 Markowitz 최적화 구현으로 이름 바꾸지 않는다.

검증: `test_portfolio_allocation_constraints.py`, `test_allocation_models.py`, `test_allocation_data.py`, 기존 배분·ETF·성향·백테스트 회귀 묶음 197건 통과. 독립 대각 공분산 해·BL 신뢰도별 스칼라 해·미래 봉 불변성·네 국면·제약 반올림·PG 계정 격리·실패 보존·주문/플랜 무변경을 검증한다. 실제 HTML/JS Chrome 16건 통과. 실제 수집 종가 728거래일/2026-10-30 기준의 네 모델 계산도 확인했다. 과거 자료 계산 성공을 최신 운영 자동매매 성공으로 집계하지 않는다.

계산 근거: [SciPy SLSQP 공식 문서](https://docs.scipy.org/doc/scipy/reference/optimize.minimize-slsqp.html), [PyPortfolioOpt의 BL 공식 문서](https://pyportfolioopt.readthedocs.io/en/latest/BlackLitterman.html), [Amundi 공분산·리스크 패리티 연구](https://research-center.amundi.com/files/nuxeo/dl/f40e6aed-bba5-46d6-82d4-8eb57c63c8df?inline=). 국면 경계·배수는 본 프로젝트의 명시적 규칙이며 외부 검증된 최적 정책으로 주장하지 않는다.

## 8. 2026-11-03 국면별 목표 자동 갱신

오준영이 11/4 잔여 구현을 당겨 진행하도록 승인했다. 기존 플랜은 자동 갱신이 꺼진 상태를 유지한다.

1. 자산배분에서 `regime`으로 계산한 저장본을 리밸런싱에 가져온다. 국내 상장 ETF 후보를 함께 가져오는 기존 선택도 지원한다.
2. 사용자가 **국면 변화에 따라 목표 비중 자동 변경**을 선택하고 플랜을 저장해야 연결된다. 서버는 본인의 최신 결과 ID와 가져온 목표가 일치하는지 확인한다.
3. 연결 시 기준 자산군 비중·국내 종목 상대 비중·확인한 ETF를 복사해 고정한다. 이후 새 배분 결과를 저장해도 기존 플랜을 자동으로 다시 연결하지 않는다. 미적용 자산군은 계속 현금으로 남는다.
4. 기존 5분 준비 확인 → 거래일별 1회 점검에서, 전 거래일까지 네 대용 ETF의 자료가 모두 있을 때 국면을 계산한다. 네 ETF는 한 SQLite 읽기 트랜잭션에서 읽고 외부 가격으로 대체하지 않는다. 부족·지연·잘못된 가격·계산 중 수집 세대 변경은 기존 목표를 유지하며 다음 점검을 기다린다.
5. 국면이 달라질 때만 목표를 교체한다. 기존 종목을 새로 고르지 않으며 국내 종목 내부 상대 비중은 유지한다. 이후 시간·이탈률·현금흐름 조건과 **기존 자동 예약 설정**을 그대로 적용한다. 자동 예약이 꺼져 있으면 제안 승인까지 기다린다.
6. 기존 예약은 먼저 처리한다. 시가·사용자 확인 대기 중인 예약의 목표를 자동으로 교체하지 않는다. 같은 날 완료된 일별 판단도 다시 실행하지 않는다.
7. 변경 전후 목표·국면·계산 기준일·입력 지문·기준 비중·수집 세대·판단 시각은 `rebalance_target_changes`에 기록한다. 플랜·이력·후속 제안은 같은 PostgreSQL 트랜잭션이며 후속 계산 실패 시 함께 롤백한다. 사용자 잠금과 플랜/정책/기준일 유일성으로 중복 변경을 막는다.
8. 목표를 직접 편집하면 화면의 자동 변경 선택을 끈다. 서버도 자동 변경이 켜진 상태의 임의 목표 수정을 거부한다. 활성화된 플랜 수정에는 `expected_updated_at`이 필요하며, 자동 작업·다른 화면에서 먼저 저장했다면 HTTP 409로 재조회하도록 안내한다. 편집 취소·다시 불러오기로 충돌을 해소한다.

`regime_config`와 `regime_state`는 기존 플랜에 빈 JSON 기본값으로 추가한다. `0042_merge_cancel_audits → 0043_regime_targets`이며 기존 목표·실행 설정은 전환하지 않는다. `GET /api/rebalance/target-changes`는 로그인한 본인의 변경 이력만 반환한다. 계정 삭제 시 함께 제거한다.

TC-RB-REGIME는 실제 수집기 SQLite 스키마와 격리 PostgreSQL에서 연결·국면 전환·제안/자동 예약·현금 보존·자료 지연·원본 세대 변경·동시 점검·수동 편집 충돌·롤백·저장본 독립성을 확인한다. 신규·리밸런싱·배분·ETF 관련 시험 271건 통과. `python scripts/check_regime_ui.py`의 실제 HTML/JS 명시적 연결·편집 보존·409 충돌·재조회·이력 표시 8개 흐름과 기존 리밸런싱 화면 38개 확인·배분 화면 7개 흐름이 Chromium에서 통과했다. API 응답은 화면 시험용 고정값이며 실제 계좌 자동 활성화나 증권사 주문을 실행하지 않는다. Docker 반영 결과는 해당 PR 및 작업 계획에 따로 기록한다.
