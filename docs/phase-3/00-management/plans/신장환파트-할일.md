지표 → 규칙 → 전략을 **전략 카드 하나**로 적고, 백테스트 · Pine 생성기 · 자동매매가 같은 카드를 읽게 한다. 카드는 자동매매가 이미 읽는 전략 스펙(계약 v0.5 1절)에 손절 · 익절 · 수량 칸을 더한 것이다. 커스텀 지표는 미래 자료를 보지 않는 함수와 판 저장으로 마무리한다. 주담당 범위는 팀 계획서의 확정 사항이고, 아래 날짜는 일정 제안이다. 구현 상세는 [설계서](../../02-design/system/인디케이터-전략-설계.md)에 둔다.

Pine 코드 생성 · 웹훅(③ 이동원 님), LEAN 실행 · 대사 · 합격 판정(④ 강민석 님), 증권사 주문 · 수량 계산 · 위험 한도(⑤ 오준영 님)는 각 주담당 몫이고, 이 계획은 그쪽이 읽을 **카드와 지표 값**을 넘기는 데까지다. 계약 파일은 강사님 원본과 같게 두는 자리라 고치지 않는다(docs README 3.3절). 수급 데이터는 3차 범위에서 뺀다(결정 D6 ⑥).

## 3. 10/22 정리한 내용

- 최신 main 의 인디케이터 화면과 API, 자동매매가 읽는 전략 스펙(계약 v0.5 1절)을 대조했다. 같은 지표 값을 곳마다 다른 규칙으로 읽고, 손절 · 익절은 % 만 있으며, 손절 · 익절 · 위험 기준 크기를 한곳에 적은 명세가 없다. 코드를 읽은 것이며 시험 통과 판정은 아니다.
- #314 에 10/27 연결 시험용 카드 판 1(계약 칸만 · 고정 입력)과 10/27 판 2 에 더할 칸을 알렸다. 칸 이름(오준영 님 · 강민석 님 코드의 이름을 따름)과 손익비 기본값 2 는 반응 전이다. 카드 판 1 을 `apply_strategy_spec_to_signal` 에 넣어 규칙대로 매수 · 매도가 나오는 것을 확인했다.
- 규칙 문서(코딩표준 · docs README · 문서작성기준)를 읽고 담당을 확인했다. 계약 파일은 고치지 않고, 오준영 님 자동매매 코드는 읽기만 하며, 백테스트 엔진은 강민석 님과 맞춘다.
- 요구 대장이 내 요구에 적은 시험 이름 가운데 TC-RL · TC-GS 는 시험-요구 대장에서 다른 묶음이 쓰고 있다. TC-LA 는 `P02-②-2` 시험이 이미 있어 넓힌다(설계서 7절).
- 2차 완료보고서 팀원 칸(3 · 7절)은 10/24 에 2차 폴더에서 채운다(PR #310 · #311 요청).

## 5. 팀장 전달문

팀 프로젝트 계획서에서 정한 제 주담당 요구 P02-①-1~3 · P02-②-1~3 과, 같은 계획서 표 7 「따라오는 칸(제안)」 의 U6 · U7 을 기준으로 작성한 일정안입니다. 손절 · 익절 · 수량 방식까지 담은 「전략 카드」 하나를 백테스트 · Pine 생성기 · 자동매매가 함께 읽게 하는 것이 목표입니다. 카드는 자동매매가 이미 읽는 전략 스펙에 손절 · 익절 · 수량 칸을 더하는 안이고(#314 에 알림 · 반응 전), 계약 파일은 강사님 원본이라 고치지 않습니다.

10/22 에 #314 로 카드 판 1 과 판 2 칸을 알렸고, 설계서 v0.1 과 카드 판 1 파일을 만들었습니다. 10/23 ~ 10/24 에 미룬 이슈 답과 자유 산식 고침, 10/26 화면 설계와 지표 함수, 10/27 카드 판 2 · ATR 손절 · 위험 수량 · LEAN 대조, 10/28 커스텀 지표와 Pine 전달, 10/29 기준 전략과 화면을 거쳐 **10/30 에 제 구현을 마치겠습니다.** 11/2 팀원들과 통합 · 예외 시험으로 **제 담당을 마무리**하고, 11/3 ~ 11/5 는 다른 파트 연결 지원에 쓰겠습니다.

이동원 님께 여쭐 것은 #314 「이동원 님께」 넷과 카드 조건 꼴, 산출물목록 두 줄, 새 시험 묶음 이름 등록입니다. 담당 요구는 확정 범위이고 날짜는 검토를 위한 제안입니다.
