## 1. 현재 목표 요약

이번 작업에서 제 역할은 지표와 전략 카드가 실제 백테스트 환경에서
일관되게 작동하는지 확인하고, 백테스트 결과와 다른 구현 간의 차이를
검증하는 것입니다. 기존 MA Cross 기반 흐름을 유지하면서 ATR 손절·익절 및
위험 비율 기반 수량 계산을 백테스트 엔진과 연결하고, 제가 만든 **ERD
지표도 프로젝트의 인디케이터 체계에 연동하는 방향**을 검토·추진합니다.

TradingView와의 대조는 별도 제약이 있습니다. **TradingView CSV 연동은
비용 문제로 현재 진행하기 어렵고, 해당 제약은 이미 이슈로 등록해 둔
상태입니다.** 따라서 CSV 연동이 완료된 것처럼 보고하지 않으며, 가능한
범위의 LEAN 내부 검증과 대체 가능한 비교 절차를 먼저 진행합니다.

## 3. 앞으로 할 일

### P0 --- 성과 검증의 단위 오류 및 회귀 테스트

대상: #362 - `deflated_sharpe_ratio`에 전달되는 Sharpe 값의 단위를
확인합니다. - `calculate_all_metrics`가 연율화 Sharpe를 계산한다면, DSR
함수가 기대하는 관측 주기 기준 Sharpe와 단위가 일치하도록 입력을
조정합니다. - TC-QFRS에 알파가 없는 합성 수익률에서 DSR 통과율이 낮아야
한다는 취지의 회귀 테스트를 추가합니다. - 관련 테스트를 실행하고
`git diff --check`로 패치 형식을 확인합니다. - 이번 범위에서 제외: -
실제 시도 횟수(`n_trials`)를 T7 기록과 연동하는 작업 - 짧은 표본 경고 -
DSR 공식을 정식 방식으로 전환하는 작업 - 슬리피지 민감도 분석 및 성과
화면 지표 개편 - 이슈에 기재된 합성 데이터 통과율은 실행 전까지 제 검증
결과로 단정하지 않습니다.

### P1 --- 전략 카드의 위험 관리 설정을 LEAN 엔진에 연동

-   전략 카드의 ATR 손절·익절 및 위험 비율 기반 수량 설정을 백테스트
    엔진에 연결합니다.
-   `quant_pipeline.py` 연동 범위를 확인하고 필요한 연결을 진행합니다.
-   손절 가격 기준과 수량 계산이 전략 카드 계약과 일치하는지 확인합니다.
-   최소 검증 항목:
    -   진입 가격과 ATR을 기준으로 한 손절 가격 계산
    -   손익비 설정에 따른 익절 가격 계산
    -   위험 비율 기반 주문 수량 계산
    -   같은 봉에서 손절·익절 조건이 겹치는 경우의 처리
    -   수량·가격·데이터가 없거나 유효하지 않은 경우의 예외 처리
    -   카드 설정과 LEAN 실행 결과 간 일관성

### P1 --- 자체 ERD 지표 연동 검토 및 구현

목표: 제가 만든 ERD 지표를 기존 인디케이터 프로젝트에서 사용할 수 있도록
연동 경로를 마련합니다.

진행 순서: 1. ERD 지표의 현재 명세·계산식·입력 데이터·출력값·필요한
워밍업 기간을 확정합니다. 2. 기존 인디케이터 함수의 인터페이스와 비교해
ERD를 공통 규격으로 감쌀 수 있는지 확인합니다. 3. 미래 데이터 참조가
없는 인과적 계산인지 점검합니다. 4. LEAN에서 동일 입력을 사용했을 때
계산 결과가 일관적인지 검증합니다. 5. 전략 카드 또는 지표 설정 화면에서
ERD를 선택할 수 있는지 확인합니다. 단, ERD를 신호·전략에 바로 연결하는
것은 지표 연동 검증과 구분하고 별도 합의 후 진행합니다. 6. 기본 지표와
ERD를 같은 데이터 구간에서 비교하고 결측값·초기 워밍업·경계 조건을
확인합니다. 7. 명세와 테스트 결과를 문서화합니다.

**ERD 연동 시 원칙** - ERD를 곧바로 매수·매도 전략으로 간주하지
않습니다. - 우선은 지표 계산·표시·출력 인터페이스와 값 검증을
완료합니다. - ERD의 정확한 계산식과 출력 형식은 실제 지표 코드 및 명세를
기준으로 확정합니다. 확인하지 않은 계산식을 임의로 추가하지 않습니다.

### P2 --- LEAN 결과 대조 및 팀 통합 지원

-   pandas와 LEAN 결과의 수익률·MDD·주문 수·비용·Sharpe 차이를 원인별로
    정리합니다.
-   가능한 범위에서 신호·체결·손절·익절·수량을 대조합니다.
-   TradingView CSV 연동은 비용 제약이 해소되거나 이슈에 대안이 합의되기
    전까지 완료 항목으로 처리하지 않습니다.
-   11/03\~11/05 팀 통합 기간에 다른 담당자의 카드·Pine·자동매매 연결을
    지원합니다.
-   검증 결과와 미해결 항목을 설계서 및 팀 이슈에 반영합니다.

## 4. TradingView CSV 연동 제약

**현재 상태: 비용 문제로 연동을 진행하기 어려우며, 관련 이슈에 이미
등록했습니다.**

-   TradingView CSV 연동을 완료한 것으로 표현하지 않습니다.
-   직접 CSV를 확보할 수 없는 동안에는 LEAN 내부 테스트, pandas와 LEAN
    결과 대조, 사용 가능한 입력 데이터에 기반한 검증을 우선합니다.
-   대체 검증 방식이나 비용 해결 방안은 이슈에서 결정된 내용을 따릅니다.
-   CSV 확보 여부와 무관하게 수행할 수 있는 검증과, CSV가 있어야만
    가능한 검증을 구분해 기록합니다.

## 7. 팀 공유용 요약

강민석 담당 범위는 LEAN 백테스트·대사·성과 검증이며, 우선 #362의 DSR
Sharpe 단위 문제와 알파 없는 합성 수익률 회귀 테스트를 처리합니다. 이후

연결하고, 제가 만든 ERD 지표도 기존 인디케이터 인터페이스에 연동하는
방향으로 검토·검증할 예정입니다. TradingView CSV 연동은 비용 문제로 현재
진행하기 어려워 관련 이슈에 등록해 두었으며, 해결 전까지는 가능한 내부
검증을 우선하고 해당 연동을 완료로 보고하지 않습니다.
