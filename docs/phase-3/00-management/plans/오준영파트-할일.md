기존 계좌 연결·주문 추적·위험관리·정기 실행 기능을 활용해 전략 카드를 앱에서 평가해 모의 주문까지 연결한다. LEAN은 같은 입력의 실행·성과 검증 경로로 유지한다. 주담당 범위는 팀 계획서의 확정 사항이고, 아래 날짜와 KIS 국내주식 모의계좌 우선 적용은 #314의 10/25 팀장 답변에서 동의를 받았다. 앱 가상 체결을 정본으로 유지하며 KIS는 장중 하루 1~3건 경로 점검으로 제한한다. 구현 상세는 [증권사 연동 설계안](../../02-design/system/증권사-연동-자동화-설계.md)에 둔다.

## 1. 팀 계획서에 따른 범위

근거는 [팀 프로젝트 계획서 4.3절과 2.3절](https://github.com/EST-team-project/Qurious/blob/1fb94b844435c2780edec1017e1f44b6b809c173/docs/3차/계획서/프로젝트계획서.md), [팀 요구 대장](https://github.com/EST-team-project/Qurious/blob/1fb94b844435c2780edec1017e1f44b6b809c173/docs/3차/요구사항/대장/요구-대장.tsv)이다.

| 확정된 요구 | 완료 기준 |
|---|---|
| P02-⑤-1 LEAN 신호와 증권사 API 연결 | 신호가 증권사 어댑터를 거쳐 모의계좌 조회·주문으로 이어지고, 모든 증권사 호출이 실거래 차단 지점을 지난다. |
| P02-⑤-2 중복 주문 방지·손실 한도·비상 정지 | 같은 신호가 두 번 와도 주문은 한 번만 나간다. 손실 한도 초과 또는 정지 상태에서 모든 주문 경로가 거부 사유를 남기고 멈춘다. |
| P02-⑤-3 실행 일정·배포·로그·장애 알림 | 정한 일정에 전략 작업이 돌고, 실패하면 알림이 한 건 가며, 실행마다 로그와 상태가 남는다. |

배포는 로컬 Docker 환경을 기준으로 한다. 팀 계획서에서 AWS는 로컬 완성 뒤 선택하는 항목이므로 EC2·CloudWatch는 필수 작업에 넣지 않는다. 추가 증권사, 실전 주문, 2차 리밸런싱 주문의 KIS 연결, 배당 자동 입금, 별도 주문 정정·취소 기능(SCH-ORD), 별도 모니터링 화면(U10)은 이번 확정 주담당 일정에 추가하지 않는다. 기존 주문 상태 조회·실행 로그·비상 정지 화면은 활용한다.

## 6. 10월 26일 수행 결과

- 실제 조회: 본인 KIS 모의 계좌의 잔고·삼성전자 현재가·매수 가능 금액/수량 확인. 자동매매 꺼짐, 실전 허용 꺼짐, 주문 호출 0회. 09:28 조회 당시 이미지는 `qurious-app:kis-readiness-20261022`였다. 09:48에 아래 새 이미지로 교체했다.
- 코드: main에 빠져 있던 10/22 잔고 검증·오류 안내 수정 이식. DF-145 재현 후 같은 증권사의 빈 키·화면 마스크를 보존하도록 수정했다. 키 변경 시 비밀키를 함께 받고 다른 증권사에는 기존 키를 넘기지 않는다.
- 시험: 수정 전 DF-145 시험 12 실패·8 통과. 수정 후 관련 9파일 **169 통과·0 실패·0 건너뜀**. 일회용 PostgreSQL·Redis와 외부 통신 없는 네트워크에서 실행했다.
- 내일 준비: 저장소의 판 1 카드로 기존 앱 판단 함수의 매수·매도·관망 및 60봉 미만 평가 불가를 확인했다. 고정 입력 시험이며 실제 LEAN 실행이나 KIS 주문 완료가 아니다.
- 운영 반영: PR #340을 main에 병합한 뒤 09:48 KST 앱·워커·스케줄러에 `qurious-app:broker-readiness-20261026`을 배포했다. 기존 실행 코드에 #340 범위만 적용했으며 최신 main 전체를 배포한 것은 아니다. 09:50 잔고 HTTP 200·시세·매수 가능 조회, 마스크 키 재저장 후 설정 보존, 워커 응답·스케줄러 건강 상태를 확인했다.
- 배포 시험: 실제 배포 이미지에 시험 도구만 더한 외부 통신 없는 컨테이너에서 설정 보존·잔고 처리·KIS 인증정보 시험 50건 통과. 사용자·증권사 설정 전체 지문, 환경변수·데이터 볼륨·화면 파일 보존 확인. 자동매매·실전 허용은 꺼짐 유지.
- 관측 사항: 최초 HTTP 잔고 확인에서 502 `BALANCE_UNAVAILABLE` 1회, 재확인에서 200. 원인은 미확정이며 오류 기록 ERR-004에 누적했다. 기존 로그인 세션이 없어 본인 계정의 단기 점검 세션으로 확인하고 즉시 삭제했다.
- 남은 외부 입력: 강민석 20/60 실행 결과(오늘 18:00 목표), 신장환 판 2(10/27 예정). 현재 답글에 완료 결과가 없어 대조는 남겨 둔다.
- #332: 기존 정책의 출처·개선 제안·담당 협의 답글 게시 완료. 공통 판단 함수는 오늘 수정하지 않았다.

[강민석 답글](https://github.com/EST-team-project/Qurious/issues/314#issuecomment-6434717192)은 판 2의 `open`을 당일 종가 판단 → 다음 거래일 시가 체결로 확인한다. 따라서 KIS 경로 점검과 다음 시가 체결 재현을 별도로 검증한다. 아래 오후 HF 수신·실제 주문 시각의 기록 방식은 이 두 기준을 적용하는 우리 구현 방침이며, 해당 세부 문구 자체가 팀 답글로 확정됐다고 표시하지 않는다.
- `open`은 다음 봉 시가라는 계약 의미를 유지한다. 전일 봉을 다음 날 오후 HF에서 받은 뒤 보내는 KIS 점검 주문에는 판단 봉·자료 준비 시각·주문/체결 시각·실제 체결가를 기록한다. 오후 주문을 다음 봉 시가 체결로 표시하거나 그 가격으로 소급하지 않는다.
- 전량 청산의 대상은 해당 전략·판에 귀속된 확정 체결 보유분이다. 수동 보유·다른 전략 물량은 제외하고, 실제 매도 가능 수량·미체결 주문을 대조한다. 사용자 매도 비율로 판 2의 전량 청산을 조용히 바꾸지 않는다. 충돌하거나 귀속을 모르면 보류한다.
- `new_signal`은 청산 후 진입 조건이 해제됐다가 다시 참이 되는 것으로 제안한다. 상승 조건이 계속 참이면 다음 날 새 봉이어도 재진입하지 않는다. 재시작해도 유지되도록 포지션·최근 조건·재진입 대기 상태를 저장한다. 첫 관측이 이미 참인 경우의 취급도 합의·시험한다.
- ATR은 마지막 확정 봉까지의 같은 기준 OHLC로 계산한다. 수정주가 ATR과 실제 주문 가격의 단위를 일치시킨 뒤 사용하고, 체결가·부분 체결 처리에 맞춰 손절선과 익절선을 저장한다. 갭·슬리피지·종가 판정 때문에 실제 손실 1%가 보장된다고 표현하지 않는다.
- `warmup_bars=60`은 최소 자료 조건이다. 직전 신호와의 비교에는 추가 봉 또는 저장된 직전 판단 상태가 필요하다. 판 2 실행 규칙을 지원하기 전에는 새 칸을 무시한 채 판 1처럼 주문하지 않는다.

### #314 최신 제안에 대한 회신 초안 — 미발송

판 2의 필드 위치, `entry_mode/exit_mode=open`, `stops.judge=close`, `warmup_bars=60`, `price_basis=adj_base`(#353 병합본 기준) 방향에 동의합니다. 오준영 담당 주문 경로에서는 다음 경계를 맞추고 싶습니다.

1. 청산 전량은 해당 전략·판에 귀속된 확정 체결 보유분 전량으로 해석하겠습니다. 수동 보유·다른 전략 물량은 제외하며, 매도 가능 수량·미체결 주문을 대조합니다. 이 청산 규칙도 명세에 명시해 사용자 매도 비율과 충돌할 때 조용히 부분 매도로 실행되지 않도록 하겠습니다.
2. `reentry=new_signal`은 청산 뒤 진입 조건이 해제됐다가 다시 발생해야 하는 것으로 제안합니다. 같은 상승 조건이 다음 봉에도 유지되는 것만으로 재진입하지 않으며, 첫 관측 시 이미 참인 신호의 취급도 맞추겠습니다.
3. 현재 HF 자료 도착 시각상 오후 KIS 점검은 다음 봉 시가 체결을 재현할 수 없습니다. KIS는 기존 합의의 장중 하루 1~3건 경로 점검으로 유지하고 판단 봉·자료 준비 시각·주문/체결 시각·가격을 별도 기록하겠습니다. 백테스트·가상 장부의 `open` 의미는 유지합니다.
4. ATR은 마지막 확정 봉까지 계산하고 수정주가 기준과 실제 주문 가격의 단위를 맞추겠습니다. 진입 체결가 기준 손절선·부분 체결 처리·재진입 상태는 10/29 위험관리 범위에서 구현·검증할 계획입니다. 지원 전에는 판 2를 받아도 새 규칙을 무시한 주문은 하지 않겠습니다.

오늘 판 1 연결 점검 준비는 계속하고 판 1 파일·공통 판단 지문은 유지하겠습니다. 판 2는 별도 파일로 받고, 필드 전달·신호 일치 시험과 실제 수량·손절·재진입 실행 시험을 구분하겠습니다. 10/29 위험 관문, 10/30 실행·실패 알림, 11/2 통합 시험 일정은 유지합니다. 이는 작업 계획이며 판 2 구현·배포 완료 보고는 아닙니다.

6. **15:20 전 KIS 이월 점검.** 검증된 판 1 경로와 당일 조건이 준비되는 시간에 배치한다. 순서를 기다리다 시각을 놓치지 않도록 별도로 진행하며, 판 2 전체 완료를 기다리는 작업은 아니다. 신규 위험관리 변경이 미검증이면 그 경로로 주문하지 않는다. 유효 주문 조건이 없으면 보류를 기록하고 다음 거래일로 이월한다. 실제 주문 완료는 주문번호·체결·잔고 대조로 판정한다.
7. **15:40 스냅샷 배치 관측.** 앞 작업의 완료를 기다리다 놓치지 않도록 별도 시각으로 확인한다. scheduler/worker 성공 표기뿐 아니라 사용자별 `ok/fail`·오류 결과와 DB 기록을 본다. 운영 접근이 안 되면 미확인으로 남기고 10/30 운영 검증에 이어간다. 성과 계산 방식은 이 확인 중 임의 변경하지 않는다.
8. **업무 종료 전 증거·남은 일 정리.** 오늘 소스/시험/배포/실제 주문 결과를 각각 기록한다. 판 2 오늘 목표의 완료·지연과 #366 미합의 정책, #364 ETF 최소 경고안, #371 담당 경계·확인 못 한 운영 이력을 정리한다. 팀원 댓글 발송은 사용자 지시가 있을 때 수행한다. 스트레스/배분 고도화를 오늘 확정 개발 범위에 추가하지 않는다.

오늘 핵심 완료 조건은 **현재 가격을 쓰는 위험 판단·수량·기록의 일치, 합의된 판 2 실행 규칙 구현, 공통 관문의 전체 경로 검증, 배포 상태의 확인**이다. 미완료 판 2·운영 확인·시간 제약이 있는 실주문 점검은 지연 또는 이월로 명시하고 완료 범위를 구분한다.

### 19.4 10/29 오전 — 위험 가격·조치 기록·배치 실패 판별 구현

`fix/risk-pricing-v2-20261029`에서 다음 변경을 구현하고 격리 환경에서 검증했다. 브랜치 이름의 v2는 오늘 전체 작업 방향이며 판 2 실행 지원 완료를 뜻하지 않는다.

- **#364:** 비상 정지 감사 기록에 자동매매 중지·kill switch·취소 요청의 requested/failed/skipped·알림 호출 결과를 추가했다. 취소 요청과 알림 예외가 정지 상태를 해제하거나 감사 호출을 생략하지 않는다. 취소 요청은 취소 확정이 아니며, 알림 함수 반환은 채널별 전달 성공 증명이 아니다. 기존 직접 KIS 취소 미지원은 skipped로 남는다.
- **#371:** 전체 예외뿐 아니라 사용자 일부 실패도 Celery FAILURE로 남긴다. 성공한 날짜를 다른 시각으로 덮어쓰는 자동 재시도는 추가하지 않았다. 스냅샷 평가 방식·GET upsert·가격 근거 스키마는 변경하지 않았다.
- **#366 준비:** 판단일 원주가·수정주가·계수의 일치 검증과 `수정 ATR / 판단일 계수` 공통 함수를 추가했다. 비정상 계수·정확한 판단일 조회·조정 방향 시험을 포함한다. 판 2 실행 경로 연결과 보유 중 조정 사건 처리 완료를 뜻하지 않는다.
