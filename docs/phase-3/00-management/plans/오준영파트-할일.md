기존 계좌 연결·주문 추적·위험관리·정기 실행 기능을 활용해 전략 카드를 앱에서 평가해 모의 주문까지 연결한다. LEAN은 같은 입력의 실행·성과 검증 경로로 유지한다. 주담당 범위는 팀 계획서의 확정 사항이고, 아래 날짜와 KIS 국내주식 모의계좌 우선 적용은 #314의 10/25 팀장 답변에서 동의를 받았다. 앱 가상 체결을 정본으로 유지하며 KIS는 장중 하루 1~3건 경로 점검으로 제한한다. 구현 상세는 [증권사 연동 설계안](../../02-design/system/증권사-연동-자동화-설계.md)에 둔다.

## 1. 팀 계획서에 따른 범위

근거는 [팀 프로젝트 계획서 4.3절과 2.3절](https://github.com/EST-team-project/Qurious/blob/1fb94b844435c2780edec1017e1f44b6b809c173/docs/3차/계획서/프로젝트계획서.md), [팀 요구 대장](https://github.com/EST-team-project/Qurious/blob/1fb94b844435c2780edec1017e1f44b6b809c173/docs/3차/요구사항/대장/요구-대장.tsv)이다.

| 확정된 요구 | 완료 기준 |
|---|---|
| P02-⑤-1 LEAN 신호와 증권사 API 연결 | 신호가 증권사 어댑터를 거쳐 모의계좌 조회·주문으로 이어지고, 모든 증권사 호출이 실거래 차단 지점을 지난다. |
| P02-⑤-2 중복 주문 방지·손실 한도·비상 정지 | 같은 신호가 두 번 와도 주문은 한 번만 나간다. 손실 한도 초과 또는 정지 상태에서 모든 주문 경로가 거부 사유를 남기고 멈춘다. |
| P02-⑤-3 실행 일정·배포·로그·장애 알림 | 정한 일정에 전략 작업이 돌고, 실패하면 알림이 한 건 가며, 실행마다 로그와 상태가 남는다. |

배포는 로컬 Docker 환경을 기준으로 한다. 팀 계획서에서 AWS는 로컬 완성 뒤 선택하는 항목이므로 EC2·CloudWatch는 필수 작업에 넣지 않는다. 추가 증권사, 실전 주문, 2차 리밸런싱 주문의 KIS 연결, 배당 자동 입금, 별도 주문 정정·취소 기능(SCH-ORD), 별도 모니터링 화면(U10)은 이번 확정 주담당 일정에 추가하지 않는다. 기존 주문 상태 조회·실행 로그·비상 정지 화면은 활용한다.

## 3. 10월 22일 착수 기록

- 최신 main의 계좌·주문·위험관리·LEAN·정기 실행 코드를 대조했다. 구현과 시험 파일의 존재를 확인한 것이며 실제 계좌 시험 통과 판정은 아니다.
- 기존 홈페이지의 `#settings`와 `#quant-auto`를 활용하는 연결안을 작성했다.
- 기존 전략 명세 조회와 LEAN 실행 신호 수신을 구분했다. 신호 식별자, 기준 시각, 전략 버전, 주문 연결 및 응답 불명 처리안을 작성했다.
- 설계 문서에 요구별 시험 14항목을 작성하고, [신호 예시 JSON](../../02-design/system/예시/lean-signal-v1.json)을 준비했다. 예시는 주문 전송 기능이 없는 계약 검토 자료다.
- 추가 사전 점검(10/22 10:08 KST): 실행 중인 앱의 오준영 사용자 설정으로 KIS 모의 인증·잔고·삼성전자 시세 조회가 성공했다. 자동매매는 꺼짐이며 주문은 보내지 않았다. [점검 범위와 LEAN 준비 상태](../../02-design/system/증권사-연동-자동화-설계.md#8-10월-22일-연결-사전-점검)에 기록했다.
- LEAN 원격 연결은 미설정이고, 로컬 설정이 참조하는 `quantconnect/lean:latest` 이미지도 없다. 26일 계좌·시세 작업은 시작할 수 있지만, 27일 실제 LEAN 연결 시험 전에는 담당자와 실행 위치·신호 계약을 맞추고 실행 환경을 준비해야 한다.

## 5. 10월 22일 팀장 전달문 원안

팀 프로젝트 계획서에서 확정된 제 주담당 요구 P02-⑤-1~3을 기준으로 작성한 일정안입니다. ① LEAN 신호와 증권사 계좌·시세·주문 연결, ② 중복 주문 방지·손실 한도·비상 정지, ③ 전략 실행 일정·배포·로그·장애 알림 자동화를 포함했습니다. 기존 KIS 국내주식 모의계좌를 우선 대상으로 제안합니다.

10월 22일은 오전만 작업하고 23일과 주말은 제외합니다. 10/26 계좌·시세, 10/27 신호·주문 연결, 10/28 연결 검증, 10/29 위험관리, 10/30 정기 실행·로그·실패 알림까지 구현을 목표로 합니다. 11/2 통합 시험, 11/3 예외 시험·수정, 11/4 문서·발표·PR 검토를 거쳐 11/5 최종 확인과 인수인계를 마치겠습니다.

오늘은 기존 코드 대조와 설계·신호 계약 초안·시험 항목 정리를 완료했습니다. LEAN 담당자와 10/26까지 신호 전달 형식을 맞추고자 합니다. 배포는 팀 계획서에 따라 로컬 Docker 기준이며 EC2·CloudWatch는 필수 범위에 넣지 않았습니다. 담당 요구는 확정 범위이고 날짜와 KIS 우선 적용은 검토를 위한 제안입니다.

## 6. 10월 26일 수행 결과

- 실제 조회: 본인 KIS 모의 계좌의 잔고·삼성전자 현재가·매수 가능 금액/수량 확인. 자동매매 꺼짐, 실전 허용 꺼짐, 주문 호출 0회. 현재 실행 이미지는 `qurious-app:kis-readiness-20261022`다.
- 코드: main에 빠져 있던 10/22 잔고 검증·오류 안내 수정 이식. DF-145 재현 후 같은 증권사의 빈 키·화면 마스크를 보존하도록 수정했다. 키 변경 시 비밀키를 함께 받고 다른 증권사에는 기존 키를 넘기지 않는다.
- 시험: 수정 전 DF-145 시험 12 실패·8 통과. 수정 후 관련 9파일 **169 통과·0 실패·0 건너뜀**. 일회용 PostgreSQL·Redis와 외부 통신 없는 네트워크에서 실행했다.
- 내일 준비: 저장소의 판 1 카드로 기존 앱 판단 함수의 매수·매도·관망 및 60봉 미만 평가 불가를 확인했다. 고정 입력 시험이며 실제 LEAN 실행이나 KIS 주문 완료가 아니다.
- 운영 반영: 오늘 코드 변경은 작업 브랜치에 있으며 배포하지 않았다. 오늘 조회 결과로 DF-145 운영 수정 완료를 주장하지 않는다.
- 남은 외부 입력: 강민석 20/60 실행 결과(오늘 18:00 목표), 신장환 판 2(10/27 예정). 현재 답글에 완료 결과가 없어 대조는 남겨 둔다.
- #332: 기존 정책의 출처·개선 제안·담당 협의 답글 게시 완료. 공통 판단 함수는 오늘 수정하지 않았다.

상세 기록: [오류·처리 누적 기록](../../04-testing/오준영-오류수정기록.md). 실제 조회·시험 근거는 `data/local-run/kis-readiness-20261026/`에 보관한다. 최종 완료 11/5, 3차 발표 11/12 일정은 유지한다.
