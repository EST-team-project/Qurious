# ①-23 E(경제지표 발표일) · F(공모 청약 · 상장) 일정 — 데이터 원천 · 약관 · 규모

## 0. 요약 (3줄)

1. **E 는 할 만하다** — 날짜가 연 단위로 이미 공표돼 있고(한국은행 · 국가데이터처 · 미국 BLS · BEA) 건수가 작다(전체 연 400건 안팎 · 핵심만 추리면 약 120건). 약관이 가장 깨끗한 쪽은 미국(BLS · BEA 둘 다 공공 도메인)이고, 한국은행은 저작권보호방침 ③(제공대상 공공데이터 목록 밖 정보는 링크 외 이용에 사전 승인)이 걸려 **사용자 결정이 한 번 필요**하다(기존 금통위 일정 수집도 같은 문제).
2. **F 는 E 보다 훨씬 크다** — OpenDART 증권신고서(지분증권) API 에는 청약기일 · 납입기일 · 공모가 · 모집총액이 있지만 **상장일 · 환불일 칸이 없고**, 요청에 `corp_code` 가 필수이며, **IPO 기업(비상장 · 법인구분 E)은 지금 수집 범위 밖**이다(바로팜 · 동원파츠 등 5곳 공시 0건 확인). KIND 공모일정은 모든 단계(청약 · 납입 · 상장)가 있어 가장 완전하지만 **법적고지가 사전 동의 없는 복제 · 배포를 막아 쓰지 않는 쪽을 권한다**.
3. **규모는 계획(E+F 1.2)을 넘는다** — 내 어림은 E 0.6~0.8 + F 0.9~1.3 = 1.5~2.1(F 를 상장사 유상증자 청약만으로 줄이면 합 1.0~1.2). 달력에 새 칩이 생기므로 Figma 결정 한 번은 어느 안이든 필요하다.

### 5.3 틀린 날짜를 보일 위험 · 확실도

| 위험 | 내용 | 완화 방안(결정 거리) |

| 일정 변경 | 한국은행 · 국가데이터처 · BLS 모두 「변경될 수 있음」 을 명시(위 인용). 한국은행 표에는 실제로 「변경일시」 가 달린 행이 있다. 청약일은 신고서 정정으로 바뀐다(F6 경고 문구) | 앞날은 `scheduled`(예정) 고정. 갱신 주기: 지금 금통위는 **7일**(`REFRESH_DAYS`) — BLS 는 「최소 1주 전 추가」 라 적당하나 **IPO 는 매 영업일**(러너 12:30 단계에 얹기)이 필요 |

### 5.4 「화면에 보이는 가공 일정」 vs 「원자료를 저장소 · HF 에 올림」

| 갈래 | 판단 |
|---|---|
| 화면: 날짜 + 이름 + 출처 기관명 | 가공한 일정이다. 출처 표시를 붙이면 BLS · BEA(공공 도메인) · 국가데이터처(공공누리 표시 확인 시)는 문제가 작다. 한국은행은 8절 1번 |
| 저장소(Public): 원문 · DB | 수집 DB · 원문은 커밋하지 않는 규칙 그대로. 시험 픽스처는 합성 문자열만 |
| HF private: 새 일정 표 | 지금 일정 표 다섯이 올라간다. 새 표(예: 경제지표 · 공모 일정)를 TABLES 에 **넣을지 말지**는 결정 거리 — 일정은 재생성 가능하므로 안 넣어도 잃는 것이 작다 |
| F 의 경우 `raw_response` 에 estkRs 원문이 쌓인다 | 공시 원문은 기존 DART 원문과 같은 취급(약관에 재배포 조항 없음 — 도구 답). 다만 약관에서 출처 · 재배포를 **허용한다고도** 적혀 있지 않다는 점은 기존 DART 수집과 같다 |

| **순서(가치 대비 규모)** | ① E-1(0.4) → ② E-2 한국은행(0.2 · 문의 뒤) → ③ F-lite(0.4) → ④ F-IPO(+0.5~0.9) → ⑤ 상장일(보류) | ①②는 작은 일로 가치가 분명하다. ③은 기존 수집 범위 안이라 위험이 낮다. ④는 계획을 넘기는 부분이라 다음 판으로 미룰 후보 |

## 8. 사용자가 정할 것

1. **한국은행 저작권보호방침 ③ 을 어떻게 할까** — (a) 한국은행에 문의(방침 쪽에 적힌 담당 `bokpr@bok.or.kr`) (b) 그대로 진행(위험 감수) (c) 한국은행 일정은 빼고 국가데이터처 + 미국으로만. **지금 돌고 있는 금통위 일정 수집(`policy_meeting`)에도 같은 조항이 걸리므로 한 번에 같이 결정**하는 것이 좋다.
2. **E 의 범위** — 전체(연 400건 안팎) vs 핵심 부분집합(약 120건). 달력 칸 혼잡(「+N」)과 Figma 칩 결정에 걸린다.
3. **날짜 기준** — 미국 릴리스를 KST 로 바꿔 넣을까, 미국 날짜 + ET 시각 표기로 둘까(FOMC 도 맞출지).
4. **칩 구성(Figma 결정 한 번)** — E 를 칩 하나(경제지표)로 할지 한국 · 미국 둘로 나눌지, F 를 청약 · 납입 · (상장) 몇 개로 할지. 지금 칩은 10종이다.
5. **F 의 범위** — F-lite(상장사 유상증자만 · 수집 범위 불변) / F-IPO(비상장 포함 · 큼) / 상장일(보류).
6. **상장일** — 사후 시세 표기만 둘지, KRX 에 사용 허락을 문의해 KIND 를 쓸 길을 열지.
7. **새 일정 표를 HF 백업(TABLES)에 넣을지.**
8. **「confirmed」 의 뜻** — 지난 날 표기를 지금 규칙(자동 확정) 그대로 둘지.
9. 위 결과로 **계획의 E+F 1.2 를 조정할지**(E 만 이번에, F 는 다음 판으로 등).
