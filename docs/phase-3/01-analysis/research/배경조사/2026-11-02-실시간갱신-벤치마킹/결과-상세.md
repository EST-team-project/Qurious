## ① 다섯 줄 요약 (결론 먼저)

1. **한계도 구현 잘못도 아니다. 업계 표준 설계다.** TradingView 전략은 기본이 「봉 마감 때만 계산」이고, Freqtrade 는 미완성 캔들을 아예 데이터에 넣지 않으며, QuantConnect 는 봉이 닫힐 때 핸들러를 부른다. Seeking Alpha · Stockopedia 같은 점수 서비스도 점수를 **하루 한 번**(장 시작 전 / 전일 마감 뒤 밤사이)만 계산한다. 분석 값과 실시간 · 지연 딱지가 붙은 가격을 한 화면에 나란히 두는 사례로는 Investing.com 을 확인했다(발췌만).
2. **어색함의 원인은 계산 방식이 아니라 표시와 갱신 쪽일 가능성이 크다.** 과제가 준 사실로는 신호 순위 화면이 열 때 한 번만 받고 갱신이 없다. 그래서 10초마다 갱신되는 현재가와 시간대가 어긋나 보인다. 순위 화면이 기준일을 적고 있는지는 이번 확인 범위 밖이다. 덧붙여 12:30 회차가 「전 거래일 일봉」을 받는 구조라면, 다음 날 오전장 동안 신호가 업계(장 시작 전 갱신)보다 하루 늦다. 이 점은 우리 쪽에서 확인할 일이다.
3. **과제 전제 하나를 바로잡는다.** KIS 유량 공지 원문(2026.04.20 기준)은 실전 **초당 18건**(기존 20), 모의 **초당 1건**(기존 2)이다. 한 번에 30종목을 받는 관심종목 시세 API 는 **모의투자 미지원**이다. 그래서 모의 키 하나로 「보이는 행 10초 폴링」을 하면 이론 상한이 사용자당 약 10행이다.
4. **약관과 시장 제도도 바뀌었다.**
   - KIS 약관 제5조 ③ 과 FAQ(2026-10-06)는 시세를 「본인 업무에 한해」 쓰게 하고, 제3자 제공과 「불특정 다수가 이용 가능한 웹 · 앱 서비스 배포」를 허용하지 않는다. 본인 키로 받은 값을 본인 화면에만 보이는 것은 지킬 수 있지만, 배포형 웹앱은 회색지대로 KIS 에 물어봐야 한다.
   - 2026-09-14 부터 KRX 애프터마켓(16:00~20:00)이 생겨 「장 종료 = 15:30」 가정이 깨졌다.
5. **추천** : 「마감 신호 확정 + 기준일 · 지금가 · 출처 · 시각 병기 + 보이는 행만 폴링(숨은 탭 · 세션 밖 중지)」을 유지한다. 다만 폴링 주기는 키 종류(모의 / 실전 / 지연 시세)에 맞춰 달리 하고, 장중 신호는 「잠정」 표시를 붙인 선택 기능으로만 둔다. 확신도는 방향 약 85%, 「10초」라는 숫자 약 60%(모의 키에서는 조건부)다.

**질문 1 결론**

- 「봉 마감 확정」은 업계 표준이 맞다. 확인한 공식 문서 다섯 곳(TradingView 셋, Freqtrade, QuantConnect)이 모두 기본값으로 둔다.
- 장중 미확정 신호를 기본으로 보이는 주류 사례는 둘을 확인했다. TradingView Technical Ratings(옵션을 켜지 않았을 때)와 키움 실시간 조건검색이다.
- 이들이 「미확정」을 다루는 방식은 셋이다.
  - 확정 후에는 확정값만 남긴다.
  - 사건(편입 / 이탈)으로 보낸다.
  - 「마감까지 기다림」을 옵션으로 고르게 한다.

**질문 3 결론 — 우리 규모에서의 선택**

1. 신호 순위 · 종목 카드는 **폴링**을 유지한다. 서버 쪽 10초 저장과 맞물려 단순하다.
2. 같은 화면에서 탭을 여럿 여는 경우가 많아지면, HTTP/2 를 확인한 뒤 **SSE + 탭 간 공유**를 검토한다.
3. KIS 실시간(WebSocket)은 키가 있는 사람의 관심 종목에 한해 **서버 중계**로만 쓴다. 실패하면 REST 폴링으로 내려간다. 토스와 같은 구조다.
4. **숨은 탭은 직접 멈춘다.** 브라우저는 늦추기만 하고 멈추지는 않는다.
5. **세션 밖에서는 멈추거나 늦춘다.** 세션 기준은 질문 4의 애프터마켓 때문에 15:30 하나로 정할 수 없다.

### 질문 7. 반박 증거 — 이 안이 틀릴 수 있는 이유

검토한 안은 「마감 신호 확정 + 지금 가격 병기 + 보이는 행 10초 폴링」이다. 아래는 이 안을 **약하게 하는** 증거만 모은 것이다.

| # | 반박 증거 | 근거(확인 정도) | 무게 |
|---|---|---|---|
| R1 | **장중 신호를 기본으로 보이는 주류 사례가 있다.** TradingView Technical Ratings 는 옵션을 켜지 않으면 열린 봉에서 실시간으로 등급이 바뀐다. | 표 1-1(원문 읽음 · 기본값은 확인 못 함) | 중 — 「마감 확정만이 정답」은 아니다. 다만 확정 후 확정값만 남기는 규칙이 붙어 있다. |
| R2 | **국내 HTS 의 핵심 기능이 장중 미확정 신호다.** 키움 실시간 조건검색은 편입 · 이탈을 실시간으로 보낸다. | 표 1-1(발췌만) · 키움 REST 「세션당 실시간 조건검색 10건」(원문 읽음) | 중 — 국내 사용자는 「장중 신호」에 익숙하다. 마감 신호만 보이면 「느리다」고 느낄 수 있다. |
| R3 | **확정을 기다리는 데는 비용이 있다.** TradingView 문서는 repainting 을 피하는 모든 방법이 신호를 늦춘다고 「inevitable compromise」라 부른다. | 표 1-1(원문 읽음) | 중 — 사용자가 느낀 어색함 자체가 이 비용이다. 설계로 없앨 수 없으니 표기로 설명해야 한다. |
| R4 | **10초 폴링이 자료 신선도와 안 맞을 수 있다.** 야후 경로는 20분 지연인데 10초마다 받는 것은 낭비다. Finviz 는 지연 무료판을 3분마다 갱신한다. | 표 2-1(원문 읽음) | 중 — 경로별로 주기를 달리 해야 한다. |
| R5 | **모의 키로는 「보이는 행 10초」가 성립하기 어렵다.** 모의 초당 1건이고 멀티종목 조회도 미지원이다. 그러면 10초에 약 10번 호출이 이론 상한인데, 현재가 카드 · 잔고 · 주문이 같은 예산을 나눠 쓴다. KIS 는 일부 호출이 통과되지 않을 때 즉시 재호출하라고 해서 재시도도 예산을 먹는다. | 표 4-1(원문 읽음) | 높음 — 숫자를 그대로 쓰면 EGW00201(초당 거래건수 초과)이 날 수 있다. |
| R6 | **장 종료 가정이 낡았다.** KRX 애프터마켓(16:00~20:00)으로 15:30 뒤에도 가격이 움직인다. 「장 마감 뒤 폴링 중지」를 15:30 으로 두면 애프터마켓 가격을 놓친다. 계속 받으면 「지금가 ≠ 신호 기준 종가」 차이가 커져 어색함이 오히려 늘 수 있다. | 표 4-2(원문 읽음) | 중 — 장 구분(정규 / 애프터)을 화면에 적어야 한다. |
| R7 | **신호의 기준 시점 자체가 업계보다 늦을 수 있다.** SA 는 장 시작 전, Stockopedia 는 전일 마감 뒤 밤사이에 갱신한다. 우리 12:30 회차가 「전 거래일 일봉」을 받는다면 오전장 동안은 전전일 종가 기준이다. | 표 2-1(원문 읽음) + 우리 회차의 실제 내용은 확인 못 함 | 조건부 높음 — 사실이라면 「한계」가 아니라 **고칠 수 있는 구현 선택**이다. |
| R8 | **배포형 웹앱은 약관상 회색지대다.** 「본인 키 → 본인 화면」이라도 「불특정 다수가 이용 가능한 웹 및 앱 서비스 배포」 문구에 걸릴 수 있다. | 표 4-2(원문 읽음) | 중 — 기술 설계보다 먼저 KIS 문의가 필요하다. |
| R9 | **WebSocket 을 미루는 것도 비용이다.** 토스는 폴링에서 WebSocket 으로 옮겼다. 큰 서비스의 시세 표시는 푸시가 표준이다. | 표 3-1(원문 읽음) | 낮음 — 우리 규모 · 한도(41건 · 1세션) · `ws://` 평문을 생각하면 지금 옮길 이유는 약하다. |

### 추천 (결정은 사용자)

1. **신호는 마감 확정을 유지한다.** 그 대신 순위 화면 제목줄에 기준을 적는다. 예: 「기준 : YYYY-MM-DD KRX 정규장 종가 · 계산 : YYYY-MM-DD HH:MM」. 이미 적고 있다면 그대로 둔다.
2. **12:30 회차의 의미를 확인한다.** 전 거래일 일봉을 그날 낮에 받는 구조라면, 수집 가능 시각을 앞당길 수 있는지 검토한다. 업계 기준은 장 시작 전 갱신이다. 회의 안건으로 올린다.
3. **지금가 칸**은 출처별로 표기와 주기를 나눈다.
   - 본인 KIS : 「실시간 · 정규 / 애프터 · n초 전」
   - 야후 : 「20분 지연 · HH:MM 기준」
   - 종가 : 「종가 · YYYY-MM-DD」
   - 주기도 출처를 따른다. KIS 실전 10초, KIS 모의는 행 수에 맞춰 늘린다, 야후 1~3분, 종가는 갱신하지 않는다.
4. **보이는 행만 · 숨은 탭 중지 · 세션 밖 중지** 를 기본으로 하고, 새로고침 단추를 둔다.
   - 세션은 「정규장」과 「애프터마켓(16:00~20:00)」 중 무엇을 보일지 정한다. 애프터 가격을 보이면 「애프터」 딱지를 붙인다.
5. **장중 참고 신호**는 기본으로 끈다. 켜면 「잠정 · 종가 확정 전」 딱지를 붙이고, 확정 뒤에는 확정값으로 덮어쓴다. TradingView Technical Ratings 방식이다. 알림은 확정 신호로만 보낸다(TradingView 알림 FAQ).
6. **약관** : 사용자별 캐시 키 · 무저장 · 「실시간」 낱말 제한을 지킨다. 배포 범위를 넓히기 전에 KIS 에 「사용자 각자 키로 쓰는 웹앱」이 허용되는지 문의한다.
7. **KIS 웹소켓**은 서버 중계 · 앱키당 1세션 · 합산 41건 · 접속키 초당 1건 · `ws://` 평문을 전제로, 후속 과제로만 둔다. 같은 앱키를 다른 프로그램(예: 자동매매 스크립트)과 함께 쓰면 세션이 겹치는 문제를 먼저 정리한다.

**확신도**

- 방향(마감 확정 + 병기 + 표기 보강) 약 85% : 공식 문서 다수가 일치한다.
- 「10초」라는 숫자 약 60% : 실전 키에서는 적합하고, 모의 키 · 지연 경로에서는 조정이 필요하다.
- 약관 판정 : 보류(KIS 문의 필요).

## ④ 확인하지 못한 것

1. 토스증권 · 키움 영웅문 · 한국투자 MTS 의 실제 화면 문구(지연 · 기준일 표기). 앱 화면이라 열람하지 못했다.
2. TradingView Technical Ratings 의 「마감 기다림」 옵션 이름과 기본값. 원문에 「If enabled」만 있다.
3. 키움 조건검색 개발가이드 PDF 원문(발췌만 봤다).
4. KIS 웹소켓 「40 vs 41」 차이의 정확한 이유. 공식은 「체결통보 포함 합산 41」이다.
5. HTTPS 페이지에서 `ws://` 연결이 막힌다는 MDN 문장. 혼합 콘텐츠 문서에 WebSocket 언급이 없었다.
6. 「20분이 지나면 실시간이 아니다」의 코스콤 계약서 원문. 블로그 인용만 봤다.
7. 현재 코스콤 정보이용료 금액(2014 기사만 봤고, 2016 개편 기사가 있다).
8. Yahoo Finance 약관 원문과, 야후 지연 시세를 다른 사용자 화면에 보이는 것의 허용 여부.
9. 「사용자가 자기 앱키를 서비스에 맡기는 구조」가 KIS 약관 제5조 ② 의 「위임」에 해당하는지. 원문만으로 판단할 수 없어 KIS 문의가 필요하다.
10. KRX 정규장 · NXT 프리마켓의 시작 시각. 이번에는 원문으로 확인하지 않았다. NXT 프리마켓 종료 08:50 만 KIS 공지에서 확인했다.
11. 우리 12:30 회차가 「전 거래일 일봉」인지 「당일 일봉」인지(우리 쪽 사실이라 이번 조사 범위 밖).
12. LS증권 웹소켓 구독 한도 공식 수치, Zipline 의 장중 처리, KIS 위키독스 본문.
13. 토스증권 SLASH 23 발표자료 PDF 본문.
