# 지금 값(실시간)과 저장 자료(수집) 판정표

> 작성 2026-10-28 · S158 · 로컬 main `64fb3d7` 코드 **읽기만**(실행·화면 확인 안 함) · 영역별로 읽고 사용자 확인을 받으며 채운다 — 추측으로 칸을 채우지 않는다.
> 판정: **⒜** 지금 값이 꼭 필요 · **⒝** 저장(수집) 자료로 충분 · **⒞** 둘을 섞음(기준일·출처 표시가 필요)
> 이어지는 문서: `docs/phase-3/02-design/system/실시간표시-저장자료-설계.md`(①-04) · ②-13 「실시간 시세 구조」(11-05) · 기준일 표시 ②-21

## 0. 이미 정해진 원칙 (바꾸는 것이 아니라 확인하는 것)

`app/services/quote_now.py` 머리말(2026-10-19 사용자 결정): 화면이 수집 DB 마지막 종가를 「현재가」로 보여 삼성전자 210,000 ↔ 실제 217,000 이 된 일이 계기.
- **판단·백테스트·학습은 저장 자료**(같은 자료로 다시 돌릴 수 있어야 해서). **실행 직전 확인과 화면 표시만 지금 값.**
- 지금 값은 **저장하지 않는다**(10초 메모리 저장본만). 거래소 계약이 없어 「실시간」이라는 낱말은 쓰지 않고, 출처·시각 글을 단다.
- 이용 조건: 증권사 실시간 시세는 **자기 키·자기 화면까지** — 남의 화면에 쓰지 않는다.
- 값 찾는 차례: ① 로그인한 사람의 KIS 키 → ② `stock.get_quote`(게이트웨이 → 야후 지연 약 20분) → ③ 수집 DB 마지막 종가.

### 영역 ② 읽고 나온 것

- **큰 불일치는 한 가지다**: QUANT(자동매매) 쪽 평가는 「출처·시각 필수 · 못 받으면 보류」인데, PAPER(손으로 하는 모의투자) 쪽 평가는 「못 받으면 평단가로 대체」. 같은 규칙 하나로 맞추는 것이 후보(바꿀 곳: `stock_positions` · `get_portfolio` · 화면 두 곳).
- **(가) 로 해결되는 것**: 2-1 · 2-2 표시 — 보유 행에 출처 · 시각을 붙이고, 못 받은 종목은 「가격 확인 불가」로 표시(총자산 합산에서 빼지 않고 「일부 종목 평가 보류」로 말한다). 이슈 A 에 붙일 수 있는 크기.
- **(가) 로 안 풀리는 것**: 2-4 는 값이 **저장**되므로 표시 문제가 아니다. 이슈 A 에 섞지 말고 따로 둔다 — 스냅샷에 가격 기준 칸(`valuation_basis` 같은 JSON 또는 대체 종목 목록)을 추가할지, 대체값이 섞인 날은 기록을 건너뛸지는 **이동원 님·성과 지표 담당 확인 필요**(QFRS 값이 바뀌므로).
- 이 영역에서 **돈이 움직이는 곳(2-5 · 2-6)은 이미 지금 값 확인이 들어가 있다.** 고칠 것은 평가 · 표시 · 저장 근거 쪽이다.
- 읽지 않은 것: `get_quote` 자체 캐시(`stock.py:108`), 스탑 감시 호출 주기, `/api/portfolio` 와 `/api/paper/account` 실제 값 차이, 15:40 배치 실패 이력.

### 영역 ③ 읽고 나온 것

- **돈이 실제로 나가는 쪽(live)이 오히려 지금 값을 안 쓰고, 모의(paper)가 본보기다.** 영향 범위는 `QURIOUS_ALLOW_LIVE_TRADING` 관문이 켜져야 실계좌이므로 평소엔 모의 요청 경로로 한정(관문 동작은 이번에 시험하지 않음).
- 이슈 B 의 B-3 는 「주문 유형이 뭔지 못 읽었다」 에서 **「코드 기본은 지정가라 지난 종가가 단가가 된다 (공격 모드만 시장가)」** 로 바뀐다. 실제 값은 `.env` · 게이트웨이 보정 여부를 확인해야 해서 질문은 남는다.
- B-3 를 고치는 최소 형: live 도 paper 와 같이 체결 직전 `quant_valuation.quote(fresh=True)` 로 교체하고 `판단 X → 주문 Y` 를 사이클 로그에 남기며, 수량은 교체 후 계산(3-2). 주문 유형 정책(지정가 vs 시장가)은 별도 결정.
- 읽지 않은 것: 수동 주문 길(`stock_order`), `routes/kis_monitor.py`, 게이트웨이 외부 서비스, 건별 live 일손실 재확인이 빠진 이유(설계 의도인지 누락인지).
