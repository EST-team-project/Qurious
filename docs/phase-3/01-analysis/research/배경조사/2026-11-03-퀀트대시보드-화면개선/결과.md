## ① 5줄 요약

1. **가장 큰 구조 결함은 한 화면에 신호가 두 갈래라는 점**이다. 카드의 신호는 일봉 하나에 RSI·이동평균·볼린저 세 규칙으로 *요청할 때마다 계산*하고(`quant.js:104` → `stock.py:420`), 「종목 근거 →」·「신호 · 근거 보기」로 여는 모달은 12:30 에 *기록해 둔 다중 주기(60분·일·주) 신호*를 보인다(`stock_hub.py:283`). 같은 종목이 카드는 「매수 · 강」, 모달은 「매도 쪽」으로 나올 수 있고 근거 개수도 세는 방법이 다르다.
2. **관찰 목록은 5개가 아니라 31개**다(`stock.py:29` `QUANT_STOCKS` 31줄 · 제목은 `stocks.length` 로 31종목을 센다). 첫 화면이 카드 31장(5열 × 7줄)이고 로드할 때 지표 요청이 31번 나간다. 근거는 카드마다 접힌 `<details>` 안이라 첫 화면에서 근거가 한 줄도 안 보인다.
3. **「모든 종목 검색 + 근거」는 새 서버 계산 없이 이미 풀린다** — 종목 찾기(`stockfind.js`) → 신호 순위 `?symbols=코드` 한 줄 → 종목 근거 모달(`data-hub-open`). 신호 기록 대상이 약 3,950종목으로 넓어지는 중이고(`신호-전체종목-기록-설계.md` v0.2), 기록이 없는 종목(해외·KONEX)은 모달의 서버 안내와 차트 응답의 일봉 규칙(이미 받는 값)으로 받는다.
4. 벤치마킹(8곳)의 공통 패턴은 **「요약 한 줄(매수·중립·매도 개수) + 지표별 값·판단 표 + 주기 탭 + 기준 시각 + 투자 권유 아님 고지」** 이고 우리 서버의 `counts`·`observed`·`contribution` 에 거의 그대로 대응한다. 새로 만들 서버 값이 없다.
5. **추천: 11-05 전엔 A(최소, 약 0.5~0.75 세션)**. B(종목 허브형, 1.5~2 세션)는 동결 뒤 화면을 크게 바꾸는 일이라 사용자가 우선순위를 줄 때만, C(작업대 통합)는 발표 뒤 로드맵. A 는 Figma 없이 가능, C 는 화면별 Figma 파일이 먼저다.

## ④ 개선안

### 공통 원칙

- **서버 계산을 새로 만들지 않는다.** 기록(`signal-rank` · `stock-hub`)을 읽고, 없을 때만 이미 받는 일봉 규칙 응답을 쓴다.
- **`sig.action` 원본은 바꾸지 않는다**(자동매매가 읽는 글자 — `quant.js:35-36`). 화면에 보이는 낱말만 `_displayAction` 에서 맞춘다.
- **두 신호에 이름표를 단다**(문제 P1): 카드·즉석 계산 = **「일봉 단독 규칙」**(자동매매 기본 규칙과 같은 계산), 모달·순위 = **「기록된 신호(60분 · 일 · 주)」**. 화면 글 예: 「일봉 규칙 RSI · 이동평균 · 볼린저 — 마지막 종가 기준」, 「기록된 신호 — 11-02 종가 기준 · 12:30 기록」.
- 화면 글에 개발 티(「정할 것」 · 팀원 이름 · 파일명)를 쓰지 않고, 「추천 · 사세요」 같은 말을 쓰지 않는다 — 「매수 쪽」 「중립」 「매도 쪽」 과 고지 한 줄.
- TradingView 자리: 화면에 **이름만 정하고 비워 둔다**(차트 도구 줄 한 칸 / 차트 탭 한 칸). 임베드 · 약관 · 위젯은 별도 조사.

### 안 C — 큰 개편: 약 4 세션 이상 · 발표 뒤 (Figma 먼저, 화면별 파일)

**아이디어**: `quant-dashboard` · `signal-rank` · 종목 근거 모달을 **한 화면 「종목 작업대」**로 합친다. 왼쪽 목록(관찰 목록 + 신호 순위 + 필터 칩) · 가운데 차트(우리 일봉 · TradingView 탭 · 신호 이력 표시) · 오른쪽 **상시 근거 패널**(모달이 아니라 옆에 고정). 모바일은 목록 → 상세 두 단계.

```
┌ 목록 ──────────┬ 차트 ──────────────────────┬ 근거 ───────────────┐
│[검색…………]      │ 삼성전자  000,000 (예시)    │ 기록된 신호           │
│[전체][관찰][보유]│ [우리 일봉][TradingView]      │ 매수 쪽 · 약          │
│[매수쪽][중립][..]│  차트 + 신호 바뀐 날 표시     │ 근거 7개              │
│삼성전자 매수쪽   │                              │ 주기별 근거 …         │
│SK하이닉스 중립   │ 비교 · 기간                   │ 쉬운 뜻 · 조심할 점    │
│…                │                              │ 공시 · 기사 · 일정     │
└─────────────────┴──────────────────────────┴───────────────────┘
```

- **재사용**: 신호 순위 표 · 모달의 칸 일곱 · 찾기 · 비교.
- **새로 필요한 것**: 필터 칩(업종 · 시장 · 신호 방향)은 서버 `signal-rank` 에 조건이 없어 **서버 읽기 항목 추가**(기록을 읽는 것이지 새 계산은 아니지만 신장환 님 영역) · 신호 이력(기록 33일치)을 차트에 표시하려면 *기간별 기록 읽기* 가 필요 — 지금 API 는 한 날짜 기준 한 줄이다. 화면 키 변경 → IA · 화면대장 · UI명세서 표 16 · core.js 메뉴 · 사용법 · 완성도 표 · 다수 시험.
- **장점**: 사용자 요구 ①②③ 을 가장 잘 푼다. **단점**: 비용 · 팀 영역 침범 · 동결 위반 · 발표 11-12 까지 불안정. → **로드맵 한 줄**로만 남긴다.
