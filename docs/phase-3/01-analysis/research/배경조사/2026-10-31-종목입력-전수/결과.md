# 종목 입력 자리 전수 조사 — 검색으로 고르는 곳과 아닌 곳

- 기준일: 2026-10-31 · 대상: `public/app.html` · `public/js/*.js`
- 요청(사용자 병렬 피드백 10-31): 종목 코드 · 기업명을 입력하는 자리는 검색해서 고르게 한다.
- 센 방식: `app.html` 에서 `id` · `name` · `placeholder` 에 symbol · ticker · 종목 · 코드가 든 `<input>` 과 종목용 `<select>` 를 센 뒤, JS 문자열 틀(`<input`)에서 같은 낱말을 찾았다.
- 한계: 낱말이 없는 입력 · 동적으로 만드는 입력은 아직 못 셌다. 아래 숫자는 「센 범위의 수」다.

## 3. 고정 목록에서 고르는 곳 (7)

`paper-alternative`(`pa-symbol`) · `quant-backtest`(`ibt-symbol`) · `indicator-strategy`(`ind-symbol`) · `ml-regression`(`mlr-symbol`) · `ml-tune`(`mlt-symbol`) · `invest-fundamental`(`fund-symbol`) · `invest-technical`(`tech-symbol`). 대표 4 ~ 5종목만 들어 있어 다른 종목은 고를 수 없다.

## 4. 숨은 값 (3)

`chart-symbol`(trading-chart) · `quant-symbol`(quant-dashboard) · `bt-symbol`(quant-backtest). 사람이 직접 고치지 않는다. 앞의 둘은 종목 검색 창(`stock-search-modal`)을 여는 단추(`chart-symbol-btn` · `quant-symbol-btn`)가 채우고, 셋째는 공용 선택기가 채운다. 이 셋은 이미 검색으로 고르는 셈이라 1절 8곳에 더해 「검색으로 고르는 화면 자리」가 늘어난다(1절은 입력칸 기준으로 센 값).

## 5. 재사용안

- 국내 칸: 공용 선택기 `mountStockPick` 를 그대로 재사용한다. 검색원 `/api/stocks/search`(국내는 KRX 상장법인 로컬 엔진)가 이미 있다.
- 걸림돌 1 — 해외 칸(`us-symbol` · `us-ord-symbol`, 일부 `ps-symbol` · `ql-ticker`): 공용 선택기의 `filterResults` 는 국내 기호(`000000.KS|KQ`)만 통과시킨다. 해외는 `/api/stocks/search` 의 야후 자동완성 폴백(`app/routes/stocks.py:134`)에 기대고 있다. 야후 참조를 늘리지 않는다는 규칙과 부딪히므로 해외 검색원을 정해야 한다(사용자 결정).
- 걸림돌 2 — 고정 목록 7곳: 목록을 선택기로 바꾸면 화면 이동 없이 종목이 늘지만, 그 화면이 쓰는 서버 길(수집 DB 다리 · 모델 학습 대상)이 임의 종목을 받는지 먼저 확인해야 한다.
- 걸림돌 3 — `ord-symbol` + `ord-name`: 코드와 이름을 따로 치는 칸이라 선택기로 바꾸면 이름 칸이 사라진다. 주문 화면은 증권사 연동과 얽혀 있어 팀원 영역인지 확인한다.

## 5-1. 사용자 결정 반영 (10-31)

사용자 답: 「입력을 유지하되 모달 창을 띄워서 검색하면 관련 기업명이나 그런 것을 띄워주는 방식(연관 검색어 나오듯이)」.
이미 같은 방식의 창이 있다 — `stock-search-modal`(`app.html:3066`) · `company.js` 의 즉시 실행 함수(글자를 치면 320ms 뒤 `/api/stocks/search` 를 불러 이름 · 시장 · 기호를 목록으로 보이고, 고르면 호출한 쪽에 `{ symbol, name }` 을 돌려준다). 지금은 이 창이 `company.js` 안에 갇혀 3곳(`chart-symbol-btn` · `quant-symbol-btn` · `company-search-btn`)만 쓴다.

- 해외 칸 걸림돌 1 은 풀린다: 이 창은 이미 국내(KRX 로컬 엔진) 결과가 없으면 해외 자동완성으로 넘어가므로 새 검색원을 정하지 않는다. 다만 해외 쪽 호출 길(야후)을 이 창이 더 자주 쓰게 되는 점은 규칙(야후 참조를 늘리지 않기)과 맞닿으니, 구현 전 한 번 더 알린다.
- 방식: 칸은 그대로 타자 입력이 가능하고, 칸 옆에 돋보기 단추를 둔다. 누르면 창이 열리고, 고른 기호가 칸에 채워진다.
- 해야 할 일: 창을 `company.js` 밖(`stockpick.js` 옆)으로 꺼내 `openStockSearch(callback)` 로 내보낸다 → 12칸 옆에 단추를 단다 → TC-SPK 계열 시험. 이 창의 해외 결과(`.NS` 등 기호 꼴)가 각 화면의 서버 길에서 받아들여지는지는 화면마다 확인한다.
- 고정 목록 7곳(3절)은 이번 결정 범위 밖이다. 따로 묻는다.

## 6. 화면을 바꾸기 전에

규칙: 화면을 바꾸기 전에 UI 명세서 · 화면 대장의 상세 절 유무를 확인하고(없으면 2차 태그에서 소급), Figma 에서 지금 화면과 바꿀 화면을 먼저 나란히 둔다. 이 조사는 코드를 고치지 않았다.

## 7. 사용자 결정 거리

1. ~~해외 종목 검색원~~ — 결정됨(5-1절): 입력 유지 + 검색 창.
2. 한 번에 몇 곳을 바꿀지(국내 타자 입력 먼저 · 고정 목록 · 해외는 뒤).
3. 팀원 화면(trading-order · paper-stock 등)은 HTML · 프런트 JS 만 이동원이 고칠 수 있고, 고치면 안내 이슈 초안이 필요하다.
