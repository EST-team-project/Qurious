# TradingView 기능 활용 조사 (2026-11-03)

> 질문: TradingView 의 다양한 기능을 우리 앱에서 더 활용하려면 무엇을 · 어디에 · 어떻게 쓸 수 있나? (퀀트 대시보드 개선과 함께)
> 조사 방식: 코드 읽기(읽기 전용) + 공식 문서 직접 열람 + 위젯 실제 렌더 시험(헤드리스, 11-03). 코드·문서는 고치지 않았다. 투자 권유 아님.

## 맨 위 요약 (5줄)

1. **무료 임베드 위젯은 KRX(코스피·코스닥) 종목·지수를 그리지 못한다.** 위젯 공식 시장 목록(아시아·태평양)에 KRX 가 없고, `KRX:005930`·`KRX:KOSPI` 를 Advanced Chart 위젯에 넣어 보니 둘 다 「This symbol is only available on TradingView」 였다(대조군 AAPL · USDKRW 는 정상). 위젯은 국내 종목 화면에 쓸 수 없고, 환율·미국·코인·해외 지수 쪽에만 쓸 수 있다.
2. **쓸 만한 것은 이미 쓰는 Lightweight Charts(Apache 2.0, v5.2.1 사본 보유) 심화와 「TradingView 에서 열기」 딥링크**다. 퀀트 대시보드 차트는 아직 ApexCharts 선(`quant.js:131`)인데, 같은 앱의 `indicator.js` 가 이미 캔들 + 이동평균 + 하위 창 + 매매 표식을 그린다 → 재사용하면 새 외부 의존 없이 개선된다.
3. **서드파티 위젯을 붙이면 처리방침 문구가 틀려진다**(`terms.js:152` 「광고·분석용 쿠키나 스크립트는 쓰지 않습니다」 · 6절 국외 이전). 위젯 FAQ 는 「쿠키 없음, 페이지 URL·위젯 종류·심볼·IP 를 TradingView 가 받는다」고 밝힌다 → 위젯 도입은 동결(11-05) 뒤에 처리방침과 함께.
4. **Charting Library(Advanced Charts)는 못 쓴다** — 회사·공개 웹 프로젝트 전용, 비공개 GitHub 저장소로만 배포, 공개 저장소에 올리는 것 금지. 우리는 학생 팀 + Public 저장소.
5. **이미 있는 웹훅·Pine 연동에 약관 위험이 있다** — TradingView 이용 정책이 웹훅 포함 콘텐츠를 「표시 전용」으로 두고 자동 주문 생성·그것을 내세우는 서비스를 금지한다. 우리는 모의계좌 체결이라 확정은 아니나(법률 판단 아님), 발표·문서에서 「자동매매」로 내세우지 않는 표현 정리가 필요하다.

### 1.3 이 조사에 영향을 주는 앱 제약 (코드로 확인)

- **처리방침**(`public/js/terms.js`): 4절 「제3자에게 제공하지 않습니다」(`:135`), 6절 국외 이전은 OpenAI 모드·디스코드만(`:137-141`), 10절 「세션 쿠키 한 가지만 · 광고·분석용 쿠키나 스크립트는 쓰지 않습니다」(`:152`). **위젯을 붙이면 4·6·10절이 현실과 어긋난다** → 문구 수정 필요.
- **CSP**: 앱 코드(`app/`, `public/`)에 CSP 헤더 설정은 없다(검색은 docs 제외, 테스트 파일에만 CSP 메타). 배포 쪽(nginx 등) 설정은 **확인 못 함**. 즉 지금은 외부 스크립트 차단 장치가 없어 기술적으로는 붙는다.
- **외부 스크립트 현황**: `app.html:10-17` 이 이미 Tailwind CDN · jsDelivr(ApexCharts · Pretendard)를 불러온다 → 시연 시 인터넷이 필요한 부분은 이미 있다(오프라인 시연은 이미 영향).
- **상표 규칙**: `NOTICE.md:71` 「화면 이름·메뉴에는 TradingView 를 쓰지 않는다(상표) — 크레딧 줄에만」 ↔ 실제 메뉴 라벨 `core.js:121` 은 「TradingView 연동 (Webhook·교차검증)」. **내부 규칙과 현재 화면이 어긋난다**(저작권 고지 의무 자체는 아님, 정리 거리).
- 루트 `tradingview.md`(미추적 학습 노트)는 웹훅 개념 설명이며 「유료 플랜 필요」를 적고 있다. 이 노트 내용 중 플랜 요건은 이번에 공식 문서로 **확인 못 함**(아래 5절).

### 2.1 위젯 실제 렌더 시험 (직접 수행, 11-03)

헤드리스 브라우저(미국 프록시)로 `tradingview-widget.com/embed-widget/advanced-chart/` 에 심볼만 바꿔 열었다.

| 심볼 | 결과 |
|---|---|
| `NASDAQ:AAPL` | 정상(OHLC · 거래량 표시) |
| `FX_IDC:USDKRW` | 정상(원·달러 환율 OHLC 표시) |
| `KRX:005930` | 「This symbol doesn't exist … only available on TradingView」 |
| `KRX:KOSPI` | 같은 메시지 |

- Symbol Info 위젯은 `KRX:005930` 에서 이름·시가총액·배당수익률·EPS 같은 **정보 칸은 채우지만 가격은 「No trades」+ 「only available on TradingView」** 로 나왔다.
- 한계: 시험은 구형(iframe 엔드포인트) 경로였고, **신형 Web Component 판 · 한국 IP 에서의 동작은 확인 못 함**. 시장 목록과 일치하므로 같은 결과일 가능성이 높다(추측).
