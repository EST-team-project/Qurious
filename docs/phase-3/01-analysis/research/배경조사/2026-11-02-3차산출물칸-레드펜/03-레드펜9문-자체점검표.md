> **원자료 확인(11-03 S196)** — `3일차7.pdf` p01 ~ p07 을 눈으로 읽어 원문 문항 이름과 쪽을 채웠다(결과: `docs/_local/레드펜-원문확인-2026-11-03/결과.md` · git 밖). 3일차7 에는 「9」 표시가 없고 「기관 실무진의 피드백 (Red-Pen)」 상자가 9개 있다. 「9문」 이름은 10-28 점검(`질문-강사님.md` 나-3)에서 처음 보이므로 「9」 는 상자를 센 우리 쪽 묶음일 수 있다(확정 못 함).
> **확실도** — 🟢 파일에서 확인 / 🟡 제안이거나 확인 전 / 🔴 확인 못 함 · 비어 있음.

## 1. 점검 방법 (제안)

1. 점검자는 항목마다 아래 3절의 「우리 증거 후보」 를 **직접 열어서** 확인한다. 기억이나 요약 문서만 보고 🟢 를 주지 않는다.
2. 판정은 세 가지다 — 🟢 증거를 열어 확인함 · 🟡 일부이거나 확인 전 · 🔴 없음 또는 확인 못 함.
3. 🟡 · 🔴 은 「누가 · 언제까지 · 안 하면 보고서에 어떻게 적나」 를 같은 줄에 적는다. 안 고치는 것은 보고서 5단의 「제약」 (5단) 이나 한계로 옮긴다.
4. 11-10 점검은 11-05 표를 복사해서 이어 쓴다(바뀐 줄만 고친다). 11-05 에 🔴 였던 줄은 11-10 에 어떻게 되었는지 남긴다.
5. 슬라이드 문장은 표에 붙여 넣지 않는다. 점검 질문은 우리 말로 쓴다.
