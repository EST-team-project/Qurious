## 4. 칸 위치 대조 상세 (대조 거리 5)

글 1절 꼴의 9칸을 `pine_strategy.py` 의 판 2 감지(`V2_KEYS` `:32` · `V2_NESTED` `:33` · 감지식 `:120`)와 맞댔다. 시험 TC-PN-08(`tests/test_pine_strategy.py:120-135`)이 같은 카드를 쓴다(돌리지 않고 읽음).

| 칸 | 글의 위치 | 코드가 찾는 위치 | 같은가 |
|---|---|---|:-:|
| `size_kind` | `position_sizing.size_kind` | `V2_NESTED` `("position_sizing","size_kind")` `:33` | 같음 🟢 |
| `risk_pct` | `position_sizing.risk_pct` | `V2_NESTED` `("position_sizing","risk_pct")` `:33` | 같음 🟢 |
| `judge` | `stops.judge` | 이름으로는 **없음**. `stops` 가 `V2_KEYS` 에 있어 카드에 `stops` 가 있으면 `stops` 하나로 잡힘 · `V2_KEYS` 의 최상위 `judge` 는 옛 초안 자리(`:31`) | `stops` 통째로 🟡 |
| `lock` | `stops.lock` | 코드 어디에도 없음(`V2_KEYS` · `V2_NESTED` · 머리말 `:11` 모두) · `stops` 통째로만 잡힘 | `stops` 통째로 🟡 |
| `entry_mode` | 최상위 | `V2_KEYS` `:32` | 같음 🟢 |
| `exit_mode` | 최상위 | `V2_KEYS` `:32` | 같음 🟢 |
| `reentry` | 최상위 | `V2_KEYS` `:32` | 같음 🟢 |
| `warmup_bars` | 최상위 | `V2_KEYS` `:32` | 같음 🟢 |
| `price_basis` | 최상위 | `V2_KEYS` `:32` | 같음 🟢 |

- **9칸 중 7칸이 같은 위치**이고, 나머지 둘(`judge` · `lock`)은 `stops` 객체 안에 있으면 `stops` 로 잡혀 **결과는 같다**. 시험 기대값도 `{"stops","reentry","entry_mode","exit_mode","warmup_bars","price_basis","position_sizing.size_kind","position_sizing.risk_pct"}` 여덟 개(`:128-129`)다 — `judge` · `lock` 단독 항목은 없다. 시험 설명문 `:121-122` 가 「stops 안의 judge · lock 을 중첩 위치로 찾는다」 고 적은 것은 코드보다 많이 말한다.
- 글의 예시 카드는 `generate()` 의 거부 조건(`:98-117` — 일봉 · `lightgbm` 0 · `ma_cross` · 같은 창 · `max_position_pct` 30.0 · 유니버스 하나)을 모두 통과하므로, 판 2 카드로도 Pine 코드는 **판 1 과 같은 몸통에 경고만 붙어** 나온다(`skipped_v2` 여덟 · 읽어서 추론 🟡).
- 코드 머리말 `:30-31` 이 「#314 제안(2026-10-27 · 확정 전)의 중첩 자리」 라고 적어, 이동원 님이 글의 위치를 이미 따른 것이다. 확정이 바뀌면 `V2_KEYS` · `V2_NESTED` 두 줄만 고치면 된다.
