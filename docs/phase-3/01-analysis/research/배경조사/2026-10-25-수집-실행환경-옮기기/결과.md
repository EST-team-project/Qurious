## 2. 물음마다

### Q1. 수집을 실행 자리에서 떼어 내는 정석 — 우리 러너와 견줌

**답.** 공식 문서들의 말은 한 문장으로 모인다 — 「실행 자리는 언제든 버리고 새로 띄울 수 있게, 남아야 하는 것(상태 · 설정 · 의존성 · 기록)은 자리 밖에」. Airflow · Dagster · Prefect 는 이것을 틀(작업 = 트랜잭션 · 파티션 · 되채우기 · 결과 기록)로 주고, Twelve-Factor 는 설정 · 의존성 · 상태 · 로그를 자리에서 떼는 규칙으로, SRE 책은 멱등 변경 · 체크포인트 · 복원 시험으로 말한다. 우리 러너는 **멱등 · 단계 기록 · 복원 시험이 이미 강하고**(벤치마크 조사서 <표 8>), 빈 곳은 「자리에 묻은 것」 — PC 마다 다른 판 · 목록에 없는 비밀값 · PC 에만 있는 상태 파일 · 「지금」 에 묶인 창 · 현지 시각 — 이다. 이 빈 곳은 PC 가 여럿이 되는 지금 이미 아프고, 클라우드로 갈 때 더 아프다.

  4. 로그는 stdout → CloudWatch Logs 로(지금 러너는 자식 출력을 파일로만 보낸다 — 작업이 끝나면 임시 디스크와 함께 사라진다).
  5. 컨테이너에 `TZ=Asia/Seoul`(Q1 덧붙임).
  6. 새 계정의 무료 플랜은 「6 months after you open it or when your credits run out」 에 닫힌다 — 팀 계정 종류를 먼저 본다(유료 플랜은 크레딧 최대 $200).

**(다-2) AWS Batch** — 추가 요금 없이 큐 · 재시도 · 작업 시간 한도를 준다. 「By default, AWS Batch doesn't have a job timeout.」 · 「Jobs that run on Fargate resources can't expect to run for more than 14 days.」 한 작업짜리 하루 회차에는 (다-1) 보다 설정만 는다 — 회차를 여러 작업으로 쪼갤 때 다시 본다.

**(다-3) AWS Lambda** — 표준 함수 「900 seconds (15 minutes)」 · `/tmp` 「Between 512 MB and 10,240 MB」 · 「Lambda is designed for short-lived compute tasks that do not retain or rely upon state between invocations.」 30 ~ 60분 회차는 단계를 쪼개 Step Functions 로 잇는 다시 짜기가 된다 → 맞지 않는다. 문서에 새 갈래 둘(Managed Instances 비동기 「up to 90 minutes」 · MicroVMs 「8 hours」 · ARM64)이 보이나 값 · 서울 여부는 보지 않았다.

**(다-4) Google Cloud Run jobs + Cloud Scheduler** — 작업 시간 「up to 168 hours (7 days)」 · 기본 「10 minutes」. 파일시스템이 「an in-memory file system, so writing to it uses the instance's memory」 라 6GB DB 를 그대로 놓으면 메모리값이 커진다 — 임시 디스크(미리보기 · 「`1Gi` and `100Gi`」 · 인스턴스 기본 「10 GiB of total space」 · 넘으면 할당량 요청)로 피한다. 셈(Tier 1 값 · 무료 한도는 결제 계정 합산이고 「applied as a spending based discount using Tier 1 pricing」): 2 vCPU · 16GiB(메모리에 DB) → vCPU (252,000 − 240,000) × $0.000018 = $0.22 · 메모리 (2,016,000 − 450,000) × $0.000002 = $3.13 → **약 $3.4** / 임시 디스크 + 8GiB → **약 $1.3** + 디스크값(못 봄). 서울(`asia-northeast3`)은 「Subject to Tier 2 pricing」. 팀이 AWS 로 가면 쓰지 않을 견줌용이다.

**(다-5) Hugging Face Jobs** — 예약이 있다(`create_scheduled_job` · `hf jobs scheduled run` · CRON 또는 `@daily`). 같은 예약이 겹쳐 돌지 않는 것이 기본이다(`concurrency` 「Defaults to False」 — 작업 스케줄러 `IgnoreNew` 와 같은 뜻) · 재시도 `attempts`. 값은 cpu-basic(2 vCPU · 16GB · 50GB) 「$0.01」/시간 → 월 약 $0.35 — 가장 싸다. 조건은 「a positive credit balance」(PRO · Team · Enterprise 월 크레딧도 셈) · 기본 시간 한도 「30 minutes」 라 늘려야 한다 · 비밀값은 「encrypted server side」 · 데이터셋은 「always mounted **read-only**」. 걸리는 것:
1. **실행 나라 · 바깥 IP · CRON 시간대가 문서에 없다** — 국내 API 도달을 모른다(Q3). 시간대를 UTC 로 보면 12:30 KST = `30 3 * * *`(추정).
2. 신호 · 일지 단계가 쓰는 **PC 의 앱 DB(PostgreSQL)에 닿지 못한다**(SSH 는 「not supported for scheduled jobs」).
3. 과금 단위가 문서마다 「seconds」(가이드) · 「by the minute」(가격 문서)로 다르다 — 값에 큰 차이는 없다.

**(라) GitHub Actions** — 사용자 계정 보호 규칙(전역 10절 · GitHub 원격 작업은 사람이)으로 쓰지 않는다. 조사하지 않았다.

**답.** 확인한 다섯 곳(공공데이터포털 · OpenDART · ECOS · 포털을 거치는 KASI 특일 · 정책브리핑)의 약관 · 데이터 안내에는 **해외 IP 를 막는다 · 서버 위치를 묻는다 · 국외 서버 보관을 금한다는 문장이 없다.** 포털 공통 오류표에 「차단된 IP」 가 있지만 나라 단위 규칙인지 알 수 없다. 그러니 **서울 리전(국내 IP)이면 위험이 낮고, 실행 나라를 모르는 자리(HF Jobs)는 한 번 불러 보기 전에는 모른다.** 실제로 걸릴 수 있는 것은 차단보다 둘 — **IP 등록**(OpenDART 기업용 · 법제처로 보임)과 **키 명의**(DART · ECOS 키는 사람 것이고 제3자 이용 · 양도 금지)다.

**판단 다섯**

1. **서울 리전이면 「해외 IP」 문제는 생기지 않는다.** AWS `ap-northeast-2` · GCP `asia-northeast3` 은 국내 IP 다. 클라우드 대역 자체를 막는 규칙은 문서로 찾지 못했다 → 이전 절차의 「도달 시험」(출처마다 한 번 · 올리기 끔)으로 확인한다(Q4 ④).
2. **실행 나라를 모르는 자리는 도달 시험 없이 쓰지 않는다** — HF Jobs.
3. **IP 등록** — 공인 IP 가 회차마다 바뀌는 자리(Fargate 공용 서브넷 · 학원 회선)는 IP 를 등록해야 하는 출처에 못 붙는다. 우리 DART 키가 **개인용**이면 해당 없다(신청 구분은 확인 안 함). 법제처는 먼저 확인한다(3.1 N5).
4. **국외 보관** — 다섯 약관 어디에도 막는 문장이 없다. 이미 HF(Team · Enterprise 가 아니면 늘 미국 저장)에 private 로 두고 있는 판단과 같다. 「해외 서버 · 클라우드 저장 = 국외 반출」 이 걸린 것은 AI 허브 자료([10-23 번역모음 조사](../2026-10-23-번역모음-대조-대안/결과.md))이고 러너 출처가 아니다. 서울 리전 S3 는 오히려 국내다.
5. **키 명의** — 지금 키는 사람 명의다(데이터수집안내 <표 1>). DART 는 「인증키를 제3자에게 이용하게 해서는 안 됩니다」 · 2개 발급 금지, ECOS 는 키 양도 금지다. 팀 AWS 계정에서 돌리면 「누가 키를 쓰는가」 가 바뀐다 → 키 주인이 그 실행의 운영자로 남거나, 팀(또는 기관) 명의로 새로 받는 쪽을 이전 전에 정한다. 09-20 「팀원은 제3자가 아니다」 결정(`hf_dataset.py` `SHARING_DECISION`)은 원자료 **공유**에 대한 것이라 키 **사용**으로 그대로 옮겨 오지 않는다(해석 · 중간).

### Q4. 환경을 옮길 때의 절차

**답.** 클라우드 공급자 · SRE 의 안내는 같은 뼈대다 — 목록을 만들고(평가), 새 자리를 차리고, 리허설하고, 되돌리는 법을 적어 두고, 단계적으로 바꾸고, 검증한다. 데이터 파이프라인에서는 둘이 더해진다 — **쓰는 쪽은 언제나 하나**(그림자 자리는 결과를 쓰지 않는다)와 **상태는 복원해 봐야 옮겨진 것**. 우리에게는 오늘 설계의 임대가 「두 자리가 겹쳐도 하나만 돈다」 를 이미 보장하므로, 새 자리도 같은 임대를 잡게 만들면 전환이 「옛 예약 끄기」 하나로 줄어든다(판단).

**지금 하면 손해인 것**
- **Airflow · Dagster · Prefect 들이기** — 정석 여섯 가운데 멱등 · 따라잡기 · 기록을 러너가 이미 하고, 스케줄러 · 메타데이터 DB · 웹 서버라는 새 운영 대상이 생긴다(벤치마크 <표 8> 8). 발표 3주 전에 옮길 이득이 없다.
- **발표 전 클라우드 이전** — 계정 종류(무료 플랜은 6개월 뒤 닫힘) · 결제 · IAM · 네트워크 · 법제처 IP · 키 명의를 3주 안에 풀어야 하고, 강사님 안내 전이다(로컬실행안내서 7절 「보류」).
- **상시 기계 사기** — 장비 · OS · 정전 · 디스크를 새로 맡는다. PC 2 ~ 3대 + 임대가 이미 서로 받쳐 준다. 발표 뒤 AWS 를 가지 않게 되면 다시 볼 후보다.
- **망 파일시스템(EFS · NAS 공유 폴더 · 동기화 폴더) 위 SQLite** — SQLite 문서가 말린다(잠금이 「operate incorrectly for some network filesystems」).
- **Litestream 같은 실시간 복제** — 하루 한 번 쓰는 DB 에 늘 도는 프로세스가 붙는다. HF 증분 + 주 1회 리허설로 충분하다.
- **쿠버네티스 · 전체 인프라 코드** — 하루 한 번 한 작업에 과하다.
- **HF Jobs 로 지금 옮기기** — 값은 가장 싸지만 실행 나라를 몰라 국내 API 도달이 미지수이고, 신호 · 일지 단계가 PC 의 앱 DB 에 닿지 못한다.

### 3.2 나중 — 팀 AWS 배포 때

**그림(권고).** 로컬실행안내서 7절 표 6 의 「수집 DB + 작업 스케줄러 → S3 + 스케줄러(EventBridge) · 또는 지금처럼 담당 PC」 줄을 이렇게 채운다.

```
EventBridge Scheduler   cron(30 12 * * ? *) · 시간대 Asia/Seoul · 재시도
  └─▶ ECS RunTask  (Fargate · 서울 · ARM64 · 1 ~ 2 vCPU · 4 ~ 8GB · 임시 디스크 30 ~ 40GiB
                    · 공용 서브넷 + 공인 IP · NAT 없음)
        컨테이너 = 수집기 이미지(N10) · TZ=Asia/Seoul · 비밀값 = Parameter Store → 환경변수
          ① 환경 점검(N2)  ② 임대 잡기  ③ HF 에서 맞추기(없으면 복원)  ④ 회차 25단계
          ⑤ HF 올리기 · 회차 기록  ⑥ (선택) VACUUM INTO 사본 → S3 서울  ⑦ 임대 닫기
          로그 = stdout → CloudWatch Logs
  신호 · 일지 단계 → 앱이 쓰는 PostgreSQL(RDS 등) — DATABASE_URL 로
```

월 약 $2.3 ~ 5.2(+ 로그 · 이미지 저장 몇십 센트 — 값 안 봄). 공유 스위치를 켜는 결정은 예약 대상의 명령줄(`--upload`)에 남는다 — 지금 작업 스케줄러 명령줄과 같은 성질이라 `hf_dataset` 의 게이트(private 확인 등)가 그대로 걸린다. 새 자리가 PC 와 **같은 임대**를 잡으면 그림자 운영 · 전환 동안 PC 예약을 켜 둬도 하루 한 회차가 지켜진다.

## 4. 남은 불확실

### 4.1 확인 못 한 것

- **국내 API 의 클라우드 · 해외 IP 동작** — 약관 · 안내에 문장이 없을 뿐, 실제로 막는지는 불러 봐야 안다(포털 「차단된 IP」 29 의 기준을 모름).
- **법제처 IP 등록 규칙** — 2차 출처 · 메뉴 이름뿐. 공식 안내 문장을 못 찾았다.
- **우리 DART 키가 개인용인가 기업용인가** — 확인 안 함(`.env` · 계정을 보지 않음).
- **HF Jobs 실행 위치 · 바깥 IP · CRON 시간대** — 문서에 없다. 과금 단위 표기도 「seconds」 · 「by the minute」 로 갈린다.
- **Fargate 작업 시간 상한** — 문서에서 못 찾음(Batch 쪽 「14일」 만).
- **Cloud Run 서울(Tier 2) 값 · 임시 디스크 값** — 정적 페이지에서 Tier 1 값만 읽었다. Cloud Scheduler · Secret Manager 값은 검색 요약으로 봤다(페이지 본문은 스크립트로 그려져 못 읽음).
- **Lambda 새 갈래(Managed Instances · MicroVMs)** — 값 · 서울 여부를 보지 않았다.
- **AWS 무료 플랜에 ECS · EventBridge Scheduler 가 드는지** — 「Limited to select services only」 만 봤다. NAT 게이트웨이 서울 값도 못 봄(오하이오 예만).
- **회차의 메모리 최대 사용량** — 재지 않았다(Fargate · Cloud Run 크기를 정하는 값).
- **이 PC `.venv` 가 잠금과 다른 까닭** — 언제 · 무엇으로 깔았는지 보지 않았다. 노트북 · 학원 PC 는 재지 않았다.
- **전기요금** — 한전 표의 적용일이 2023-11-09(페이지 인코딩이 깨져 숫자만 읽음)이고 그 뒤 바뀌었는지 못 봤다. 미니 PC · 데스크톱 전력은 추정이다.
- **책 · 원저자 글** — DDIA(원문 미열람) · Maxime Beauchemin 「Functional Data Engineering」(Medium 이 403 으로 막아 못 읽음).
- **키 명의 해석** — 약관 문장은 확인했지만 「팀 계정 실행 = 제3자 이용」 인지는 해석이다. 필요하면 기관에 묻는다.
