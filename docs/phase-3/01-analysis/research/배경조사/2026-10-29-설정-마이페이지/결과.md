# 「설정」 화면·카드 전수 조사 — 마이페이지로 옮기기 전 (2026-10-29)

> **5줄 요약**
> 1. 지금 마이페이지는 카드 6장을 위아래로 쌓은 한 화면이다(내 정보 · 화면 설정 · 이름 · 비밀번호 · 기기 · 탈퇴). 탭도 접이식도 없다.
> 2. 「설정」 성격은 **9곳**: 화면 3(증권사 API 설정 · 알림 설정 · Open API 키) + 다른 화면 안 카드 3(증권사 API 자동화 · 주문/매매의 증권사 연동 상자 · 미국 주문의 Alpaca 상자) + 이 브라우저에만 저장되는 것 2(답변 엔진·OpenAI 키 · 투자성향 진단) + 이미 마이페이지에 있는 1(용어 풀이 화면 설정). 설정이 아닌 경계 4곳은 6절.
> 3. 칸 id 는 전부 문서 전체에서 찾는 방식이라 **app.html 안에서 옮기기만 하면 동작은 그대로**다. 깨지는 곳은 서버 글(`#settings` 링크 · 「증권사 API 설정 화면」 문구)과 시험 몇 개다.
> 4. 추천: **① 메뉴만 옮기기를 먼저 → 그다음 ③ 마이페이지 안 탭**. ② 카드를 마이페이지 view 에 직접 넣는 것은 가장 위험.
> 5. 서버는 못 고치므로 `settings` 화면 키 · 「증권사 API 설정」 이름은 **바꾸면 안 된다**(서버가 그 이름으로 안내함).

범위: `public/app.html` · `public/js/*.js` 를 읽었고 `app/` · `tests/` 는 읽기만 했다. 코드에서 읽은 것만 적었고 모르는 것은 8절.

## 3. 「그대로 옮겨도 되는가」 — 칸 id 의존

핵심: 모든 입력칸은 `document.getElementById(...)` 로 **문서 전체**에서 찾고, 단추 연결(`addEventListener`)은 파일을 읽을 때 한 번 건다(`settings.js` 의 `?.addEventListener`, `paper.js:772` 의 `on(...)`). 칸이 **정적 HTML 로 app.html 안에 남아 있기만 하면** 어느 view 안으로 옮겨도 연결은 유지된다. 단 불러오기(load) 호출은 화면 키에 묶여 있어 따로 손봐야 한다.

| # | 다른 화면이 이 칸을 읽는가 | 불러오기 훅(옮기면 고칠 곳) | 판정 |
|---|---|---|---|
| S1 | **예**: `trading.js:148-154` 가 `broker-app-key` · `broker-app-secret` · `broker-account` · `broker-paper` 를 읽는다(주문/매매 저장 단추의 **숨은 의존** — 점검표에도 적혀 있음) | `main.js:113` `if (view==="settings") loadSettings()` | id 를 바꾸지 않고 DOM 에만 있으면 OK. 훅만 마이페이지 쪽으로 |
| S2 | 아니오(`noti-*` 는 `settings.js` 안에서만) | `main.js:114` | OK |
| S3 | 아니오(`po-*` 는 `paper.js` 안). 단 TradingView 화면 글(`app.html:1376`)이 「모의투자 › Open API」 라고 가리킴 | `paper.js:789` `view==="paper-openapi"` | OK, 안내 글 고칠 곳 있음 |
| S4 | 아니오(`iapi-*`) | `main.js` `indicator-api` → `loadIndicatorApiSettings` | OK. **S1 과 같은 서버 행을 쓰는 중복** — 하나로 줄일 후보 |
| S5 | 아니오 | `main.js:110` `trading-order` 에서 `loadBrokerStatus` | OK |

| S7 | `agent.js` 가 `chat-llm-mode` · `chat-openai-key` 를 질문 보낼 때 읽는다 | `agent.js` 시작 때 복원 | 채팅 입력줄 옆에 있어야 편함 — 옮기면 채팅이 마이페이지 값을 읽게 해야 함 |

## 5. 메뉴/IA 제약과 마이페이지의 구조

- **위 탭 여섯**: `MENU_TOP = agent, company, paper, quant, finance, crawl`(`core.js:469`, TC-NV-01). `account` 는 탭이 아니고 `TAB_OF` 도 비어 있어 마이페이지에서는 **위 탭 어디에도 불이 안 켜진다**(지금도 같음). 새 탭은 만들지 않는다 → 설정은 `account` 묶음이나 마이페이지 안으로.
- **왼쪽 트리**: 모든 묶음이 `MENU_TREE` 에 한 번씩(TC-NV-02). 항목을 `GNB_MENUS.<묶음>.items` 에서 빼서 `account.items` 에 넣으면 트리 · 아바타 메뉴에 자동으로 나타난다. IA I11 은 「숨는 탭 없음 · 탭 줄은 통째로 접힘」 이므로 항목 수가 늘어도 탭 폭 문제는 없음.
- **마이페이지가 새 구역을 받으려면**: 지금은 `.space-y-4` 안에 카드가 쌓인 평면. 탭/접이식 부품은 **공용이 없다**.
  - 재사용 가능한 것: `app.css:672-678` 의 `.overview-tabs` · `.overview-tab(.active)`(전역 CSS · 알약 모양 · `role="tab"`; 대시보드 계좌 탭이 쓰는 중). `<details><summary>`(`app.html:803`)도 이미 쓰임.
  - 화면마다 자기 탭을 JS 로 만들고 CSS 도 자기 파일에 둠(`cu-tabs` · `se-tabs` · `rc-tab` · `pd-tab`). 즉 **본뜰 모양은 많지만 공유 부품은 없다.**
  - 큰 카드(S1 은 약 160줄)를 평면에 넣으면 마이페이지가 곧 길어진다 → 탭이나 접이식이 사실상 필요.

1. 먼저 ① 로 메뉴를 `내 계정` 아래로 모은다(위험이 거의 없고 「설정은 마이페이지 쪽」 결정이 바로 반영됨). 항목이 `account` 에 있으니 머리 경로도 따라와 `VIEW_PARENT` 는 필요 없다.
2. 그다음 ③ 으로 마이페이지 안에 탭을 만들어 S1~S3 를 **같은 id 그대로** 옮기고, `settings` view 는 비우지 말고 마이페이지 탭으로 보내는 안내를 남겨 `#settings` 딥링크를 살린다. e2e 두 개의 선택자도 같이 고친다.
3. S4 · S5 는 같은 서버 행을 쓰는 **S1 의 복사본**이다 — 옮기지 말고 「증권사 API 설정으로」 링크로 바꾸는 편이 난잡함을 가장 많이 줄임(주담당 오준영 · 이동원과 합의).
4. S6 은 저장이 없는 껍데기라 이전 대상에서 빼고 안내 글만 남기는 쪽(이동원 판단).
5. S7 · S8 은 채팅 · 자산배분 화면에서 쓰는 값이라 **마지막**, 마이페이지에는 현재 값 보기/바꾸기 한 줄만.

### 위험 셋 (제일 먼저 볼 것)
1. **`settings` 키 · 「증권사 API 설정」 이름 삭제 금지** — 서버가 `#settings` 링크와 그 이름으로 안내함(고칠 수 없음), TC-NV-06/07 이 글자로 확인.
2. **S1 e2e 둘과 숨은 의존** — `kis_modes.py` · `broker_feedback.py` 가 `[data-view="settings"]` 를 강제 표시, `trading.js:148-154` 가 S1 칸 4개를 읽음. 칸 id 를 바꾸면 주문/매매 저장이 조용히 빈 값을 보낸다.
3. **`mypage.js:35` 첫 일치 선택자** — S1 처럼 `space-y-4` 를 품은 덩어리를 마이페이지 안에 넣을 때 화면 설정 카드가 엉뚱한 곳에 붙는다.
