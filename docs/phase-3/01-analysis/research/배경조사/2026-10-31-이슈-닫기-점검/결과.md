## 0. 읽는 법

- **의뢰문의 「83건」은 `Github-링크.md` 열린 이슈 절의 마지막 번호(83)다.** 닫힌 글을 지우면서 번호가 건너뛰어, 실제 항목은 **70줄**이다(번호 2·5·8~10·13 등이 비어 있음). 그중 한 줄(`pull/378`)은 이슈가 아니라 PR 이다. 합계는 70 기준으로 맞춘다.
- 옛 저장소 번호(`이슈-011` 같은 폴더 이름)와 새 번호가 겹친다. 새 번호는 README 색인의 `issues/N` 주소로만 이었다.
- 「닫아도 됨(확실)」은 내가 코드 줄 · 시험 · 머지 PR · 팀원 원문을 **직접 열어 본 것**만 넣었다. 팀원 영역은 그 팀원이 「끝났다」 고 쓴 원문을 근거에 달았다.
- 이 저장소의 `git log` 에는 `Closes #N` 문구가 하나도 없다(제목 · 본문 grep 0건). 머지된 PR 이 이슈를 자동으로 닫았을 가능성은 로컬로 알 수 없다.

## 7. 마무리

- 판정표의 `^| #` 행을 기계로 세어 맞췄다: 1절 7 · 2절 7 · 3절 51 · 4절 5 = **70**, 5절(목록 밖) 14. `Github-링크.md` 70줄의 번호와 표 70행의 번호가 **일대일로 같음**(빠진 것 0 · 남는 것 0).
- 판정 기준은 의뢰문 그대로다. 「근거 약함」 에는 해결된 듯하지만 고리가 하나 남은 글만 넣었고, 팀원 영역 글은 그 팀원이 닫는다고 쓴 경우에만 「확실」 로 올렸다.
- 팀원 영역 글 가운데 본인이 「OPEN 유지」 라고 쓴 것(#213 · #217 · #212)은 코드가 구현돼 있어도 「열어 둠」 으로 두었다.
