## 4. 정리안 (제안 · 결정 전)

**A. 폴더 README — 한 폴더당 20줄 안팎**: 무엇이 들어 있나 · 넣지 않는 것 · 이름 규칙 · 관련 문서 링크 · 지키는 시험(있으면). 우선순위: ① 파일이 많은 `app` · `tests` · `public` · `scripts` · `data` ② 나머지 최상위 4곳(`alembic` · `screenshots` · `tools` · `prompts`) ③ 20개 이상 2단 폴더 15곳 중 `app/services` · `public/js` · `tests/e2e` · `data/lean-workflows` 부터. 공개 저장소이므로 사용자 경로 · 비밀값은 쓰지 않는다.

**B. 루트 README 보강**: 「한계와 알려진 약점」 절을 새로 둔다 — (가) 시험: 알려진 실패 · CI 없음 · 이 PC 시험 DB 필요 (나) 교차검증: TradingView 실제 CSV 대사 전이라 「일치」 판정을 하지 않는다 (다) 데이터: 야후 시세는 화면 표시용 · 수집 DB 날짜가 PC 마다 다를 수 있음 · 금요일 종가는 월요일 오후에 나옴 (라) 성과: 과거 수익률 고지 · 합격 전략이 아직 없음(기준 전략 시도 결과) (마) 운영: 사람이 켜 둔 PC 한 대에서 도는 수집기. 숫자는 모두 문서 · 대장에서 다시 세어 쓴다. 기존 기억 「루트 readme 는 이동원 파트 쏠림 없이 앱 전체」 와 같은 판에서 한 번에 고친다.

**C. 폴더 이동 후보와 비용**
- 루트 낱장 넷(`onprem.md` · `pipeline.md` · `screening.md` · `tradingview.md`) → `docs/common/…`: 참조 48파일 100곳 · 지난판 사본은 얼린 것이라 고치지 않는 쪽으로 정해야 한다. **지금은 옮기지 않고 루트 README 의 「문서」 절에서 한 줄로 안내하는 안이 싸다.**

- `tools/` · `prompts/` 는 작고 이름이 분명해 그대로 두고 README 만 더한다.
- 이동을 한다면 규칙 그대로: `git mv` · 옛 이름 전수 grep · `.gitignore` 먼저 확인 · 옮긴 뒤 전체 시험 한 번.
