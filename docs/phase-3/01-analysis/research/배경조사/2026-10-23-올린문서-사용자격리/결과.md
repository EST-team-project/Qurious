## 맨 위 5줄 요약

1. **추천은 안 B** — 올린 문서만 따로 모음(예 `user_docs`)에 넣고, 그 안은 주인 칸(`metadata.owner_id`) + `is_tenant` 키워드 색인, 읽기 · 쓰기 · 지우기는 주인 ID 를 꼭 받는 문지기 모듈 한 곳으로만 한다. 공용 모음 `fin_chunks` 에는 비공개 조각이 아예 없게 한다.
2. **까닭** — (가) 공용 경로(채팅 · 그래프 검색 · 강사님 코드)가 거름을 잊어도 볼 비공개 조각이 없다. 지금 주인 거름이 없는 검색 경로가 6곳이고 그중 `/api/graph/rag` 는 로그인도 없다(2절). (나) 공식 권고 둘을 함께 따른다 — Microsoft 다중 사용자 RAG 안내의 「공용 저장소는 거름 불필요 · 섞인 저장소는 모든 검색에 주인 거름 · 저장소 앞에 문지기 API」 와 Qdrant 의 「한 모음 안 payload 로 가르기 + `is_tenant`」. 모음은 사용자 수와 상관없이 2개다. (다) 탈퇴 · 문서 지우기 · 옛 조각 정리가 한 키로 끝나고, 지우기 앞뒤 `count` 로 지운 수를 재 503 판정 · 파기 결과 확인을 한다.
3. **안 A(같은 모음 + 주인 칸)는** 「주인 칸 없음 = 공용」 으로 짜면 옛 올린 조각이 공용으로 샌다(실측 M6). 「`metadata` 칸 없음 = 공용」 으로 가르면 막히지만 강사님 크롤 저장 꼴에 기댄다. **안 C(사용자마다 모음)는** Qdrant · Microsoft · Open WebUI 가 모두 「사용자가 많은 개인 서비스에는 안 맞다」 고 한다.
4. **실측(qdrant-client 1.19.1 · langchain-qdrant 1.1.0 · 메모리 Qdrant)** — `IsEmpty(metadata.owner_id)` 는 `metadata` 가 아예 없는 점도 잡는다 · 키에서 `metadata.` 를 빠뜨리면 예외 없이 0건 · 거름에 dict 를 주면 예외 · `is_tenant` 색인은 메모리 모드에서 경고 뒤 무시 · strict mode 는 경고도 없이 무시 · `delete` 는 지운 수를 주지 않는다(앞뒤 `count` 로 잰다) · Qdrant 가 꺼지면 `ResponseHandlingException`(약 2초). 요구 파일이 `>=1.12.0` 이라 새로 빌드하면 들어올 1.20.0 은 **빈 upsert · 빈 ID 지우기를 예외로 바꿨다.**
5. **옛 조각** — ① 공용 검색에 「`metadata.uploader` 가 비어 있는 점만」 거름을 먼저 넣어 바로 막고 ② 옮기기 스크립트(미리 보기 → 실제 · 다시 돌려도 0)로 주인이 살아 있는 조각은 `user_docs` 로 옮기고, 탈퇴자 · 행 없는 조각은 지운다(법 제21조 「지체 없이」 · 표준지침 제10조 「5일 이내」). 메인이 정할 것 여섯은 9절.

## 이 문서의 말

| 말 | 뜻 |
|---|---|
| 조각(chunk) · 점(point) | 문서를 잘게 나눈 글 한 덩이. Qdrant 에는 벡터 + payload 한 쌍(점)으로 들어간다 |
| 모음(collection) | Qdrant 에서 점을 담는 단위. 지금은 `fin_chunks` 하나에 크롤 조각과 올린 조각이 함께 있다 |
| payload | 점에 붙는 JSON 칸. 크롤 조각은 맨 위에 `url · title · source · text · chunk_index`, 올린 조각은 `page_content` + `metadata.{url, title, source, uploader}` |
| 주인 칸 | 조각을 올린 사람의 사용자 ID 를 적는 payload 칸(이 문서에서는 `metadata.owner_id`) |
| 거름(filter) | 검색 · 세기 · 지우기에 붙이는 조건. 빼먹으면 모음 전체에서 찾는다 |
| 기본 막힘(fail-closed) | 조건이 빠지거나 애매하면 「안 보여 줌」 쪽으로 실패하는 꼴. 반대는 기본 열림 |
| `is_tenant` 색인 | 주인 칸에 거는 Qdrant 색인 옵션. 같은 주인의 점을 디스크에 모아 빨리 읽는다 — **보안 장치가 아니라 성능 장치**다(격리는 거름이 한다) |
| strict mode | Qdrant 모음 설정. 색인 없는 칸으로 거르는 검색 · 갱신을 서버가 거절하게 할 수 있다 |
| 문지기 모듈 | 비공개 모음을 여는 코드를 한 파일에 모으고, 주인 ID 없이는 부를 수 없게 한 함수 묶음 |
| 메모리 Qdrant | `QdrantClient(":memory:")`. 파이썬 안에서 도는 시험용 구현 — 서버(Rust)와 같은 코드가 아니다 |
| 3-way 병합 | 강사님 기초 코드를 받을 때 지난 반영 커밋을 기준으로 합치는 방식. 충돌 없이 들어오는 줄이 위험하다(TC-BM) |

**추천 B 를 고른 까닭 세 줄**

1. 실패 방향이 「안 보임」 이다 — 공용 경로가 거름을 잊어도, 로그인 없는 그래프 검색이 있어도, 병합으로 강사님 코드가 거름 없이 `rag_search` 를 불러도 비공개 조각이 거기 없다.
2. 공식 권고 둘을 함께 따른다 — Microsoft 의 「공용 저장소 + 섞인 저장소 + 문지기 API」, Qdrant 의 「섞인 저장소 안은 한 모음 + payload + `is_tenant`」. 모음은 사용자 수와 상관없이 2개다.
3. 지우기 · 옮기기 · 점검이 `user_docs` 안 `metadata.owner_id` 한 키로 끝나고, 공용 모음 점검은 「`metadata.uploader` 있는 점 = 0」 한 줄이다.

**B 를 만들 때 넣을 것** (설계 메모 · 판단이라 확실도 중간)

- 문지기 모듈은 우리 파일 하나(예 `app/services/user_docs.py`)에 두고 강사님 파일에는 부르는 줄만 둔다(`crawl_points.py` 와 같은 방식). 모음 이름 · 주인 칸 키(`metadata.owner_id`)는 그 파일의 상수로.
- 모든 함수는 `owner_id` 를 키워드 전용 · 기본값 없이 받고, 함수 첫 줄(try 바깥)에서 `uuid.UUID(owner_id)` 로 검사해 빈 값 · 틀린 값이면 `ValueError`. 지금 `rag_search` 처럼 except 가 삼키면 버그가 「검색 결과 없음」 으로 숨는다.
- 검색 거름은 `must=[주인 일치]` 에 사용자가 준 `source` 를 **AND 로만** 더한다 — 남의 `source` 를 줘도 0건(18행 꼴).
- 모음을 만들 때 `metadata.owner_id` 에 keyword `is_tenant=True` 색인(+ `metadata.source` keyword). strict mode(13행)는 서버에서 확인한 뒤.
- payload 에서 올린 사람 이메일(`uploader`)은 빼고 주인 UUID 만 둔다 — 탈퇴 뒤 남을 개인정보를 줄인다. 문서 ID(`uploaded_docs.id`)를 넣어 같은 이름 파일 문제를 없앤다.
- 채팅은 공용 `rag_search` 결과와 내 문서 검색 결과를 점수로 합친다(같은 임베딩 · 코사인 · 합치기 동작만 M13 에서 확인 · 순위 품질은 안 잼).
- 탈퇴(올린 문서 행이 있을 때) — ① `n0 = count(주인)` ② `delete(주인 거름, wait=True)` ③ `n1 = count(주인)`. 예외가 나거나 `n1 ≠ 0` 이면 DB 를 건드리기 전에 503 「잠시 뒤 다시」. ④ 그다음 DB 지우기 · 커밋 · 감사 기록에 「비공개 조각 n0 개」(표준지침 제10조 ③ · ④). Qdrant 지우기는 다시 해도 결과가 같아(멱등) ④ 가 실패해도 다시 탈퇴하면 끝난다. 올린 문서 행이 없으면 Qdrant 를 부르지 않는다(사용자 결정).
- 문서 지우기도 같은 순서 — Qdrant 먼저 · 실패하면 503 · DB 행 유지(지금은 실패해도 DB 행을 지운다 · 표 5).
- 탈퇴 길의 Qdrant 클라이언트에는 짧은 `timeout` — 닫힌 포트는 약 2초에 실패했다(M20). 응답 없는 서버를 얼마나 기다리는지는 안 쟀다.

## 7. 곁가지 발견 (이번 범위 밖 · 메인이 따로 판단)

1. **`/api/graph/rag` 에 로그인 의존성이 없다** — 지금은 로그인 안 한 사람도 그래프 검색으로 `fin_chunks` 를 볼 수 있다(코드상 높음 · 실행 확인 안 함). 안 B 뒤에는 공용 자료만 보이지만, 로그인해야 쓰는 기능이라면 막는 편이 맞다.
2. **지금 `rag_search` 는 보통 `QdrantVectorStore`(본문 키 `page_content`)로 열어, 크롤 꼴 조각은 본문 · 제목이 빈 글로 나온다**(M18 · 라이브러리 `_document_from_point` 확인 · 높음). 채팅 근거에 크롤 글은 비어 들어가고 올린 조각만 글이 있었던 셈이다. 안 B 로 올린 조각을 빼면 공용 근거가 빈 글만 남을 수 있다 → 공용 검색을 `CompatibleQdrantStore(content_payload_key="text")` 로 열지 함께 정해야 한다(개발 앱으로는 안 잼 · 확인 필요).
3. **qdrant-client 1.19.1 에는 `search` 가 없다**(`QdrantClient` · `AsyncQdrantClient` 모두 `query_points` 만) → `crawl.qdrant_search`(부르는 곳 없음)와 `app/services/translation_ingest.py:252` 의 `client.search`(`ingest.py:171` 이 부름)는 부르면 예외다(높음). 예외가 삼켜져 빈 결과가 되는지는 이번에 끝까지 보지 않았다.
4. **판 고정** — 요구 파일이 `>=` 라 새로 빌드하면 qdrant-client 1.20.0 이 들어오고 빈 upsert 동작이 바뀐다(표 8). compose 주석의 「서버 · 클라이언트 부 판 차이 1 이내」 는 1.20 ↔ 서버 1.19 로도 지켜진다.

## 8. 한계 (확인 못 한 것)

- 실측은 **메모리 Qdrant(파이썬 구현)**뿐이다. 서버(Rust) 1.19.1 에서 `IsEmpty` 중첩 키 · `is_tenant` · strict mode 를 직접 재지 않았다(개발 Qdrant · 컨테이너는 건드리지 않음). 문서(9 · 10 · 13행)는 같은 동작을 말한다.
- 지운 점이 디스크에서 실제로 치워지는 시점 — vacuum 기본값(조각 벡터 1,000개 · 지운 비율 20%)만 문서로 확인했다. WAL · 스냅숏에 남는 기간, 모음째 지울 때 파일이 바로 지워지는지는 확인 못 했다 → 시행령 제16조 「영구 삭제」 · 표준지침 제10조 ② 「사회통념상 적정한 비용으로 복원 불가」 를 우리 Qdrant 가 채우는지는 판단하지 못했다(낮음).
- 법 해석 — 올린 문서 조각이 모두 「개인정보」 인지는 글 내용에 따른다. 다만 payload 의 올린 사람 이메일과 `source` 의 사용자 UUID 는 그 사람을 알아볼 수 있는 정보로 본다(판단 · 중간). 안전성 확보조치 기준 제5조 ① 은 개인정보취급자(직원)의 권한을 말하는 조항이라, 이용자끼리 격리의 직접 근거라기보다 「최소 범위」 원칙의 근거로 적었다(판단 · 중간).
- 웹 인용은 요약 모델이 돌려준 짧은 원문 조각이다. OWASP · Qdrant · Microsoft 는 쪽 내용(Microsoft 는 전문)과 맞대 봤고, Open WebUI · AnythingLLM · LangSmith 는 요약 인용만이라 중간으로 적었다.
- 두 모음 결과를 점수로 합칠 때의 순위 품질은 가짜 임베딩이라 재지 않았다. 응답 없는 서버(포트는 열려 있고 답이 없음)에서 몇 초를 기다리는지도 안 쟀다(닫힌 포트 약 2초만).
