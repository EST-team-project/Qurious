# ②-31 설정 본체 이동 범위 조사 (2026-11-03 · S194)

> 조사 에이전트(Sonnet)가 읽기 전용으로 만들고, 메인이 핵심 줄 번호(화면 시작 줄 · 마이페이지 구역 · 시험 단언 · 서버에 화면 키 없음)를 원문으로 다시 확인했다. 에이전트에게 쓰기 도구가 없어 본문을 받아 메인이 이 파일로 저장했다.
> 확인 표시: 🟢 직접 열어 확인 · 🟡 추측 · 🔴 못 본 것. 줄 번호는 2026-11-03 작업 트리(PR #504 반영) 기준이다.

## 요약

1. 「남은 본체」는 실제로 있다 — 알림 화면(`public/app.html` 1062줄~, 약 243줄)과 Open API 화면(546줄~, 약 31줄). 마이페이지의 「알림」 「외부 연동」 구역은 요약과 링크만 있다.
2. 옮겨도 서버는 바뀌지 않는다. 다만 `#notification-settings` · `#paper-openapi` 주소는 살려야 한다(서버 문구 · 약관 문구 · 다른 화면 링크가 가리킴). `settings` 처럼 빈 껍데기 화면을 남기고 구역으로 보내는 방식이 최소 변경이다.
3. 고쳐야 하는 시험은 3~4 파일. `tests/test_mypage_sections.py` 는 「마이페이지 안에 `noti-` · `po-` 칸이 없다」를 단언해 이번 이동의 정반대라 다시 써야 한다.
4. 주인은 이동원 쪽 화면으로 읽힌다(오준영 님 답글에도 「알림 · OpenAPI 본체 이동은 별도 담당 범위」). git 이력은 못 봐서 오늘 같은 구역 변경 여부는 🔴.
5. 가치: 알림은 중간, Open API 는 낮다. 알림만 한나절 안팎(🟡). 할 일 문서도 ②-31 을 「먼저 자를 후보」로 적었다(225줄).

## 2. 이 마크업의 id 를 누가 쓰나 (옮기면 깨질 수 있는 선택자)

| 파일 | 하는 일 | 확인 |
|---|---|---|
| `public/js/settings.js` | `noti-` 접두 id 약 66곳 — 채널 토글 · 동의 박스와 철회 · 사건별 알림 · `loadNotificationSettings` · 이력 · 저장 · 시험 발송. 모듈이 불러와질 때 `getElementById` 로 이벤트를 붙이므로 마크업이 정적으로 문서 안에 있으면 위치가 바뀌어도 동작 | 🟢 |
| `public/js/main.js` 122줄 | `view === "notification-settings"` 일 때 `loadNotificationSettings()` | 🟢 |
| `public/js/paper.js` | `loadPaperOpenApi` · `po-*` id 약 16곳 · 버튼 바인딩. `loadPaperOpenApi` 는 export 되지 않아 마이페이지에서 부르려면 이 파일을 건드려야 한다 | 🟢 |
| `public/js/mypage.js` | 구역 전환은 변수와 class 로만(해시를 안 건드림). 증권사 구역은 `showSection` 에서 `loadSettings()` 를 부르는 선례 | 🟢 |
| `public/js/core.js` | 메뉴 줄(198~199줄) · 화면 안내 글 · `VIEW_PARENT` — `settings` 는 `=== "settings" ? "mypage"` 하드코딩 | 🟢 |
| `public/js/howto.js` 56줄 | `settings` → 마이페이지 하드코딩 | 🟢 |
| `public/js/main.js` 81~82줄 | 처음 주소 해시가 있으면 `[data-view="<해시>"]` 가 있을 때만 이동 — 빈 `data-view` 껍데기가 없으면 `#주소` 로 들어올 때 대시보드로 떨어짐 | 🟢 |
| `completion.js` · `teamcompletion.js` · `howtoview.js` | 두 화면 키로 점수와 사용법을 찾음 — 키를 없애면 표와 어긋남 | 🟢 |
| 이 주소를 가리키는 곳 | `app.html` 링크 · `us.js` · `core.js` · `terms.js`(「알림 설정 화면」 문구) · `app/routes/tradingview.py` · `app/services/tradingview.py`(「모의투자 › Open API 화면」 문구) · 오준영 님 운영 문서 | 🟢 |

서버 API(`/api/notification/settings`, `/api/paper/api-keys` 등)는 화면 위치와 무관하다. `app/` 에는 두 화면 키 문자열이 없다(메인이 `grep` 으로 확인). 🟢

## 3. 단언하는 시험 (옮길 때 고칠 목록)

반드시 고칠 것:
- `tests/test_mypage_sections.py` — 마이페이지 view 를 `data-view="notification-settings"` 시작 앞까지 잘라 읽는 정규식(알림 화면을 옮기면 끝 표지가 바뀜) · 두 링크 존재 · **`id="noti-` · `id="po-` 가 마이페이지 안에 없다는 불포함 단언(65줄 — 이번 이동과 정반대라 뒤집어야 함)** · 요약 칸 id 목록이 `["mp-sum-broker","mp-sum-notify","mp-sum-external"]` 와 같다는 단언(68줄) · `loadSummaries` 의 `.catch(() => null)` 개수 단언 · `test_settings_views_untouched`(세 화면이 `<div class="view" data-view="...">` 꼴로 있다는 단언 — 껍데기를 남기면 통과).
- `tests/test_user_consents.py` 141줄 — `APP_HTML.split('data-view="notification-settings"', 1)[1]...` 로 화면 조각을 읽어 동의 칸 id 다섯 개와 문구를 단언. 본체가 구역으로 가면 구역 id(`mp-sec-notify`) 기준으로 바꿔야 한다.

조건에 따라 고칠 것:
- `tests/test_concept_learn_view.py` 40줄 — `VIEW_PARENT` 가 정확히 정해진 꼴이라는 정규식. `VIEW_PARENT` 를 늘리면 깨지므로 별도 지도를 만들거나 정규식을 고친다.
- `tests/test_completion_badge.py` TC-CP-02 — 점수표 키가 실제 `.view` 이거나 `VIEW_ALIAS` 키여야 함. 껍데기를 남기면 통과, 없애면 깨진다.
- `tests/test_nav_dashboard_shell.py` TC-NV-11 — 일반적으로 읽어 메뉴 줄을 빼도 통과할 것(🟡).

고치지 않아도 되는 것: `tests/test_us_order_screen.py` 219줄(`href="#paper-openapi"` — 주소를 살리면 그대로) · `tests/test_help_media.py` TC-HM-09(장면 파일에 두 화면 키가 없음).

🔴 못 본 것: 점검표 CSV · UI 명세서 · 메뉴 항목 개수 문서 · `tests/e2e/*`(`smoke_views.py` 는 모든 `.view` 가 활성화되는지 보므로 껍데기를 더 만들면 지적 목록이 늘어남).

## 5. 최소 변경 계획

옮길 것:
- 알림 설정 본체(1062줄~)를 `mp-sec-notify` 안으로. 요약과 링크는 제거하거나 요약만 남긴다.
- Open API 본체는 사용자 결정(카드 세 장 — Alpaca 처리).

그대로 둘 것:
- `data-view="notification-settings"` · `data-view="paper-openapi"` 빈 껍데기 화면(초기 이동 검사 · 점수 키 · 서버 / 약관 문구 주소 때문).
- 서버 코드 한 줄도 안 바꿈. 칸 id(`noti-*` · `po-*`)도 그대로(`settings.js` · `paper.js` 를 안 바꾸려고).

코드 변경 범위(🟡 추정):
1. `app.html`: 마크업 약 275줄 이동 + 껍데기 둘.
2. 하드코딩된 `settings → mypage` 네 곳(`core.js` 둘 · `howto.js` · `mypage.js`)을 지도 하나로 일반화(예: `{settings: "broker", "notification-settings": "notify", "paper-openapi": "external"}`).
3. 로더 호출을 `mypage.js` 의 `showSection` 으로(`main.js` 122줄 · `paper.js` — `loadPaperOpenApi` export 필요).
4. `core.js` 198~199줄 메뉴 두 줄 제거(같은 화면을 두 줄이 가리키지 않게 — 11-01 증권사 줄 선례) · `VIEW_PARENT` 에 키를 더하면 위 정규식 시험도 같이.
5. 시험: 3절 목록.

되돌리는 법: 한 커밋에 모으면 `git revert` 한 번(서버 · DB 없음, 🟡). 소요: 알림만 한나절 안팎, 알림 + Open API + 시험 정리 + 브라우저 확인(1280 · 390)이면 계획표 1.5~1.75 근처(🟡). 브라우저 확인은 이 조사에서 하지 않았다 🔴.

## 6. 옮길 가치가 있나

- 지금도 마이페이지 「알림」 구역의 버튼 한 번이면 알림 화면에 가고, 메뉴 「내 계정」 묶음에도 두 줄이 이미 있다. 접근 면에서 막힌 곳은 없다.
- 알림은 옮길 이유가 있다 — 채널 인증 정보 · 동의 · 저장 단추가 있는 진짜 설정 폼이고, 좁은 화면(390px)에서는 「목록 → 구역 → 링크 → 다른 화면」 우회가 한 번 더 있다. 10-29 결정 「설정은 전부 마이페이지로」 와도 맞다.
- 반대 이유: 마이페이지 view 가 이미 약 285줄이고 `app.html` 은 팀 공용 파일이다. 선택 동의와 비밀값 입력 칸이 있어 위치만 바뀌어도 동의 · 철회 흐름을 다시 점검해야 한다. 시험 수정이 3~4 파일에 걸친다.
- Open API 는 열쇠 발급 · 문서 · Alpaca 시험이 섞여 「내 설정」 이라기보다 별도 도구다 — 사용자 결정 전에는 옮기지 않는다.
- 추천: 시간이 남을 때만 **알림만** 옮기고 Open API 는 링크로 둔다.
