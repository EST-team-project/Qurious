## 0. 진행 방식 (사용자 결정 11-05)

1. 이동원이 영상 · 슬라이드 후보를 **먼저 전부 만든다.**
2. 팀원이 자기 파트의 **대사(자막) · 숫자 · 표현**을 확인하고 피드백을 준다(아래 4절 체크리스트).

## 2-1. 발표 자료 한 파일 판 (다른 PC 로 옮겨도 재생)

- 파일: `docs/phase-3/06-retrospective/전체-발표자료.html` (**한 파일 판** · 영상 5편 + 글꼴 포함 · 약 20 MB) · 원본 `전체-발표자료-원본.html`(영상을 상대 경로로 부르는 작은 파일 · `tools/deck/build_video_deck.py` 가 장면 파일에서 생성)
- 장마다 **발표자 노트(N 키)에 자막 전문**이 들어 있어 팀원이 대사를 읽고 피드백할 수 있다.
- **검증(11-05 15:17 · 자막 순서 다시 촬영 뒤):** 이 HTML 한 파일(21.3 MB)만 빈 폴더에 복사해 Chrome 으로 열어 확인 — 영상 5편 모두 1920×1080 으로 디코딩 · 재생(재생 시간이 흐름) · 포스터 5장 로드 · 글꼴 포함 · 외부 요청 0 · 콘솔 오류 0. mp4 는 `videos/파일/{발표,사용법}/` 에 따로도 있다(10편 · 각 2.4~4.8 MB).
- **자막 점검(11-05 15:14):** 10편 모두 「동작 뒤 자막 0곳 · 읽을 시간 모자람 0곳」(`tools/demo/subtitle_sync.py check`). 단, 이 점검은 **자막이 동작보다 앞에 오는지와 읽을 시간**만 본다 — 말과 화면의 의미가 맞는지는 사람이 본다(팀원 피드백 체크리스트 첫 항목).
- 영상이 늘면 장면 파일을 고친 뒤 `build_video_deck.py` → `bundle_deck.py` 를 다시 돌린다(영상 파일이 하나라도 없으면 번들을 거부한다).

## 4. 팀원 피드백 체크리스트 (영상 · 슬라이드 공통)

자기 파트 영상(`발표/` · `장면/` 의 yaml 자막)과 위 슬라이드 후보를 보고 아래를 확인해 이슈나 댓글로 알려 주세요.

- [ ] **자막이 화면과 맞는가** — 자막이 말하는 것이 화면에 실제로 보이는가 (「자막 = 화면」)
- [ ] **숫자 · 날짜가 맞는가** — 영상에 나온 값이 발표 때도 같은가 (기준일 · 건수 · 비율)
- [ ] **용어 · 표현** — 내 파트를 잘못 설명하거나 과장한 곳이 없는가 (「추천」 「예측」 같은 단정 표현)
- [ ] **빠진 핵심** — 내 파트에서 꼭 보여 줘야 하는데 영상에 없는 기능
- [ ] **찍지 말아야 할 화면** — 키 · 계좌 · 개인정보가 보이는 칸
- [ ] **내 발표 초안** — 이 영상 · 슬라이드를 내 발표 초안 어디에 넣을지 (초안이 나오면 이 문서에서 옮겨 간다)
