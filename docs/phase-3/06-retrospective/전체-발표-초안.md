## 2-1. 발표 자료 한 파일 판 (다른 PC 로 옮겨도 재생)

- 파일: `docs/phase-3/06-retrospective/전체-발표자료.html` (**한 파일 판** · 영상 5편 + 글꼴 포함 · 약 20 MB) · 원본 `전체-발표자료-원본.html`(영상을 상대 경로로 부르는 작은 파일 · `tools/deck/build_video_deck.py` 가 장면 파일에서 생성)
- 장마다 **발표자 노트(N 키)에 자막 전문**이 들어 있어 팀원이 대사를 읽고 피드백할 수 있다.
- **검증(11-05 15:17 · 자막 순서 다시 촬영 뒤):** 이 HTML 한 파일(21.3 MB)만 빈 폴더에 복사해 Chrome 으로 열어 확인 — 영상 5편 모두 1920×1080 으로 디코딩 · 재생(재생 시간이 흐름) · 포스터 5장 로드 · 글꼴 포함 · 외부 요청 0 · 콘솔 오류 0. mp4 는 `videos/파일/{발표,사용법}/` 에 따로도 있다(10편 · 각 2.4~4.8 MB).
- **자막 점검(11-05 15:14):** 10편 모두 「동작 뒤 자막 0곳 · 읽을 시간 모자람 0곳」(`tools/demo/subtitle_sync.py check`). 단, 이 점검은 **자막이 동작보다 앞에 오는지와 읽을 시간**만 본다 — 말과 화면의 의미가 맞는지는 사람이 본다(팀원 피드백 체크리스트 첫 항목).
- 영상이 늘면 장면 파일을 고친 뒤 `build_video_deck.py` → `bundle_deck.py` 를 다시 돌린다(영상 파일이 하나라도 없으면 번들을 거부한다).

## 4. 팀원 피드백 체크리스트 (영상 · 슬라이드 공통)

자기 파트 영상(`발표/` · `장면/` 의 yaml 자막)과 위 슬라이드 후보를 보고 아래를 확인해 이슈나 댓글로 알려 주세요.

- [ ] **자막이 화면과 맞는가** — 자막이 말하는 것이 화면에 실제로 보이는가 (「자막 = 화면」)
- [ ] **숫자 · 날짜가 맞는가** — 영상에 나온 값이 발표 때도 같은가 (기준일 · 건수 · 비율)
- [ ] **용어 · 표현** — 내 파트를 잘못 설명하거나 과장한 곳이 없는가 (「추천」 「예측」 같은 단정 표현)
- [ ] **빠진 핵심** — 내 파트에서 꼭 보여 줘야 하는데 영상에 없는 기능
- [ ] **찍지 말아야 할 화면** — 키 · 계좌 · 개인정보가 보이는 칸
- [ ] **내 발표 초안** — 이 영상 · 슬라이드를 내 발표 초안 어디에 넣을지 (초안이 나오면 이 문서에서 옮겨 간다)

### 6.4 통합 덱을 어떻게 만드나

- 지금 **영상 모음 덱**(`전체-발표자료-원본.html`)은 표지 + 발표용 영상 5편이고, 이동원 17장 · 오준영 6장 슬라이드는 각자 파일이다. 세 덱은 모두 1280×720 무대를 쓰지만 CSS · 장 이름이 달라 그대로 이어 붙이면 스타일이 섞인다.
- 합치는 방법은 `tools/deck/build_video_deck.py` 에 사람별 슬라이드를 장으로 가져오는 단계를 더하는 것이다(CSS 를 덱별로 가둬야 한다). 신장환 · 강민석 슬라이드가 없는 지금은 **이동원 + 오준영 슬라이드 + 영상 5편** 만 먼저 합칠 수 있다. 장 순서는 시간 배정이 정해진 뒤에 확정하는 편이 헛수고가 적다.

### 6.5 통합 덱 순서 · 번호 규칙 (사용자 결정 11-09 S214 — 발표 구성 피드백 반영)

팀 발표 자료의 **수집 · 초안 작성은 이동원**이 하고 **발표 분배는 팀이 임의로 정한 상태**라서, 덱 순서는 「누가 발표하나」에 맞춘다.

1. **맨 앞 = 문제 정의 · 시장 조사 · 빈 곳(이동원 슬라이드 2~9장)** — 이동원이 이어서 자기 파트(한 일 · 구조 · 신호 · 일지 · TradingView)까지 한 흐름으로 발표한다.
2. **맨 끝 = 한계 · 이어갈 길(이동원 자료 18 · 19장 → 통합 덱 58 · 59장)** — 강민석 님이 발표한다. 강민석 님 자기 파트(14장 · 터미널 출력 사진 3장은 8장 · #618 · #622 · PR #627)는 그 앞에 둔다.
3. **쪽 번호는 덱 전체 하나 — 「N / 59」**(11-10 S216 기준 · 장이 늘면 조립기가 다시 센다). 담당자 덱 안의 번호(「3 / 29」 · 눈썹의 「10 · 」 · 본문의 「12 ~ 14장」)는 조립기가 통합 덱 번호로 바꾼다(`tools/deck/build_team_deck.py` 의 `fix_numbers`). 담당자 자기 파일(`이동원/발표자료.html`)은 자기 번호(1~19)를 그대로 쓴다.
4. **이동원 분량 축소(사용자 조율)** — 29장 → 19장: 수집(12 · 13 · 14) · 낡은 일봉(18) · 시험 실패(24) · 체결가(22 · 강민석 사진과 같은 주제) · 비교 화면(27)을 빼고 도입부(문제 정의 + 개인투자자 행태) · 빈 곳 둘 · 일지 둘을 합쳤다. 낡은 일봉 영상 B 도 덱에서 뺐다(장면 파일은 그대로). 빠진 장의 근거는 `이동원/발표대본.md` 부록 A.
5. 순서 상수는 조립기 맨 위 `ORDER` · `TAIL_SLIDES` · `TAIL_PRESENTER` · `EXCLUDE_SCENES` 에 있다.

### 6.6 시간 배정 (사용자 결정 11-09 S215)

- **사람별 10 ~ 15분, 전체 최대 60분, 목표는 지난번처럼 50분 이내.** 시간 제한은 없다고 했지만 너무 줄이면 핵심을 발표하기 어렵고, 50분 안쪽이 좋다는 판단이다. 대본 예상 시간은 실제보다 길게 나오는 편이다(발표 때 생략하고 넘어가므로).
- 그래서 **강민석 님이 말한 「약 4분에 맞춰 축소」(이슈 #622 답글)는 필요 없다.** 10 ~ 15분이 기준이고, 한계 2장(약 1분 50초)은 강민석 님 시간 안에 들어간다.
