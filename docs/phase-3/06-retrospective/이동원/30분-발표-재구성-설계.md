# 이동원 파트 30분 발표 재구성 — 설계 (초안 · 2026-11-11 S222)

> 상태: **승인됨(사용자 11-11) · 구현 끝 · 한 파일 판 단독 검증 38/38**(통합 덱 50장 · 한 파일 판 25.9 MiB · 영상 7 · 그림 7(카드 2 포함) · 외부 요청 0). 구현 중 제가 더한 것 셋: ① 영상 장 **Shift+→ = 영상 건너뛰기**(영상 장에서 →가 「이어서 재생」이라 영상을 통째로 못 넘기는 문제) ② 이동원 1장 개요의 장 범위(「2 ~ 5장」 「8 ~ 15장」)를 덱 쪽에서만 치환(`TEXT_PATCH` — 원본 불변) ③ 말풍선 위치 옵션(`place: right` · `dx`) — 다음에 누를 버튼을 가리지 않게. 근거는 구현계획 ledger.
> 대화(브레인스토밍)에서 사용자가 정한 것은 「정한 것」, 제가(AI) 정한 것은 「제 판단」으로 표시했다.

## 1. 왜 하는가

11-10 에 강사님이 **전체 발표를 30분 안에** 하라고 하셨다. 이동원 파트는 지금 슬라이드 12분 40초 + 영상 약 3분 ≈ 15분 37초이고, 이를 **절반(약 7분 30초 ~ 8분)** 으로 줄여야 한다. 줄이는 방법은 글을 깎는 것이 아니라 **같은 내용을 슬라이드와 영상이 두 번 말하는 시간을 없애는 것**이다 — 영상을 보여 주면서 멈추고 설명하는 방식으로 슬라이드와 영상을 합친다.

청중이 가져가야 할 것(정한 것): **핵심 수치와 근거**, 그리고 **우리가 발견한 한계점과 차별점**.

## 2. 목표 · 비목표 · 하지 말 것

**목표**
- 이동원 파트가 약 8분 안에 끝난다(리허설로 확정).
- 영상 시연 중 정해진 지점에서 영상이 멈추고 카드(그림) 또는 말풍선이 뜨며, 발표자가 **키를 눌러 직접 이어간다**(정한 것).
- 영상에 굽힌 큰 자막은 없애되 **강조 박스 · 체크(링) · 클릭 물결 · 커서는 그대로** 둔다(정한 것).
- 자막이 영상보다 밀리지 않는다(정한 것).

**비목표**
- **영상 길이를 줄이지 않는다**(정한 것 — 줄이면 설명이 애매해진다). 영상 E 약 2분 2초 · 영상 C 약 55초 유지.
- **슬라이드 내용을 고치지 않는다**(정한 것 — 내용이 많아도 발표에서 생략하며 넘긴다).
- 다른 사람(신장환 · 오준영 · 강민석) 파트와 전체 시간 배분은 이 문서 범위 밖이다.
- 한계(16 · 17장)는 이동원 시간에서 뺀다(정한 것 — 덱 맨 끝 강민석 발표 그대로).

**하지 말 것(실패 조건)**
- 멈춘 뒤 이어가는 방법을 발표자가 모르는 것(화면에 키 안내가 있어야 한다).
- 카드 · 말풍선이 영상의 핵심 화면 요소를 가리는 것.
- 한 파일 판(`전체-발표자료.html`)에서 영상 · 카드 · 자막이 안 나오는 것.
- 자막이 재생 · 멈춤 · 되감기 뒤에 어긋나는 것.

## 3. 발표 순서와 시간

| 순서 | 구간 | 방식 | 시간 |
|---|---|---|---|
| 1 | 도입 · 문제 정의 · 시장 조사 · 비어 있는 곳 (슬라이드 1 · 3 · 4 · 6 · 7장) | 슬라이드(그대로) · 「이런 것이 있었고 이렇게 했다」 수준으로 | **3분 이내**(사용자 리허설) |
| 2 | 수집부터 증권사 모의 주문까지 한눈에 (슬라이드 9장 · 구조 그림) | 슬라이드(그대로) | 약 45초(제 추정) |
| 3 | 신호 기록 넓히기 — 영상 E(신호 순위 · 근거 상세) | **카드 먼저(401 → 약 3,950) → 영상 + 쉬운 말 자막 + 말풍선 멈춤** | 영상 2분 2초 + 멈춤 설명 |
| 4 | 그림자 일지 — 영상 C(일지 판 고정) | **카드 먼저(규칙 → 지문 → 판 → 행) → 영상 + 쉬운 말 자막 + 말풍선 멈춤** | 영상 55초 + 멈춤 설명 |

합계: 3분 + 45초 + 2분 2초 + 55초 = 약 **6분 42초 + 멈춤 설명(제 추정 약 1분 30초, 리허설로 확정) ≈ 8분 10초**. 목표 7분 30초 ~ 8분을 약간 넘을 수 있어, 리허설에서 멈춤 횟수를 줄이는 것이 첫 조절 수단이다.

**덱에서 빠지는 이동원 슬라이드**(원본 `발표자료.html` 은 그대로 두고 통합 덱 조립에서만 뺀다 — 제 판단): 2 · 5 · 8장, 10 ~ 15장(영상 두 구간이 대신함). 16 · 17장은 지금처럼 덱 맨 끝(강민석 발표). 빠진 슬라이드의 내용은 `예상질의응답.html` 이 받는다.

## 4. 만드는 방법

사용자는 방법을 제게 맡겼다. 아래는 **제 판단**이며 승인 때 바꿀 수 있다.

### 4.1 두 영상을 「깨끗한 판」으로 다시 녹화
- 녹화 도구 `tools/demo/record_demo.py` 에 **`--clean` 옵션**을 더한다. 켜면 화면에 굽는 큰 제목 카드(`#__demo-chap`)와 하단 자막(`#__demo-sub`)만 숨기고, 강조 박스(`#__demo-ring`) · 클릭 물결 · 커서 · 배지는 그대로 둔다.
- 자막 · 장 · 강조가 **뜬 시각과 내용(좌표 포함)을 JSON 으로 함께 기록**한다(이미 `.ko.vtt` · `.chapters.vtt` 가 있으나 장의 라벨 · 설명 · 강조 좌표가 빠져 있다). 이 기록이 이후 모든 시각의 기준이다.
- 장면 파일(`P-이동원-E-…yaml` · `P-이동원-C-…yaml`)의 동작과 자막(`say`)은 **고치지 않는다.** pace(E 1.5 · C 1.4)도 그대로.
- **녹화는 12:30 수집 회차 전에 끝낸다**(회차 뒤에는 일지가 47행이 되어 영상 C 의 「46행」이 달라진다). 수집 회차(12:30 ~ 13:10)에는 녹화 · 시험 · 8966 요청을 하지 않는다.

### 4.2 통합 덱의 영상 층(플레이어)
통합 덱(`전체-발표자료-원본.html`)의 영상 장을 **영상 + 겹침 층**으로 바꾼다. 조립기(`build_team_deck.py`)가 만들고, `bundle_deck.py` 가 한 파일 판에 함께 넣는다.
- **자막**: 기록 JSON 의 시각에 맞춰 영상 **재생 시각(`currentTime`)** 으로 띄운다(타이머가 아니라 재생 시각 기준 → 멈춤 · 되감기 · 건너뛰기 뒤에도 안 밀림). 내용은 지금의 `say` 문장 그대로 + 쉬운 말 보충.
- **멈춤 지점(큐)**: 큐 파일에 적은 시각에 영상이 **자동으로 멈추고** 카드(A) 또는 말풍선(C)을 띄운다. **스페이스(또는 →)로 카드를 닫고 이어서 재생**한다. 화면 구석에 「스페이스: 이어서」 안내를 항상 보인다. 멈춤 시간 고정(자동 재개)은 선택 항목으로만 둔다(기본 꺼짐 — 사용자가 키 입력을 택함).
- **타임라인 점**: 영상 아래 바에 멈춤 지점을 점(●)으로 표시한다(네이티브 컨트롤은 점을 못 그리므로 간단한 자체 바 — 제 판단).
- **말풍선(C) 위치**: 기록 JSON 의 강조 박스 좌표 옆에 자동 배치(가리지 않는 쪽).
- **카드(A) 그림**: 슬라이드 10 · 11장의 그림 부분을 **캡처한 이미지**를 쓴다(사용자가 보낸 두 그림과 같은 것). 슬라이드는 고치지 않는다.

### 4.3 큐 파일
`docs/phase-3/06-retrospective/videos/발표/큐/<영상 이름>.큐.yaml` 한 곳에 멈춤 시각(장 · 자막 순번 기준) · 종류(카드/말풍선) · 쉬운 말 문구를 적는다. 문구를 고쳐도 **영상을 다시 녹화하지 않는다.**

## 6. 확인 방법(완료 기준)

1. **자막 안 밀림**: Playwright 로 영상 시각을 여러 곳으로 건너뛰며(`currentTime` 설정) 그 시각에 떠야 할 자막과 실제 자막이 같은지 — 재생 · 멈춤 · 되감기 뒤 모두.
2. **멈춤 · 재개**: 큐마다 영상이 멈추고 스페이스로 이어지는지, 카드가 핵심 요소를 안 가리는지(캡처 확인).
3. **한 파일 판**: 빈 폴더에 한 파일 판만 복사해 열어 영상 · 카드 · 자막 · 외부 요청 0 · 오류 0 (S216 TIL 절차). 이동원 슬라이드 쪽번호 · 장 수 표기 정합.
4. **강조 유지**: 깨끗한 영상에서 강조 박스 · 클릭 물결이 그대로 보이는지(프레임 캡처).
5. **리허설 시간**: 사용자가 처음부터 끝까지 재서 약 8분 이내인지.

## 7. 위험과 되돌리는 길

- 오늘이 **동결일(마지막 작업일)** 이고 내일 오전이 발표다. 녹화(12:30 전) · 플레이어 · 큐 · 덱 재생성 · 단독 검증을 오늘 끝내야 한다.
- **되돌리는 길**: 지금 덱(PR #639 시점 `fcbc3472`)이 git 에 그대로 있다. 새 덱이 문제면 그 판으로 돌아간다. 영상 원본(자막 굽힌 판)도 덮어쓰지 않고 `지난판/` 에 보관한 뒤 교체한다(제 판단).
- 가장 큰 불확실성: 플레이어 층을 한 파일 판(영상을 base64 로 품음)에서 시각 정밀도로 동작시키는 것 — 막히면 **자막만 영상에 굽는 기존 방식 + 멈춤 없는 단순 카드**로 물러선다(제 판단).

## 8-1. 빌더 점검에서 나온 질문과 제 판단(전부 제가 정함 — 마음에 안 들면 바꾼다)

| 질문 | 제 판단 |
|---|---|
| 키 충돌: 덱은 이미 →(PageDown · 스페이스)로 **다음 장**, ←(PageUp)로 이전 장을 넘긴다(덱 키 처리 코드 확인) | 영상 장에서만 키 의미를 바꾼다. **멈춤 중**이면 →· PageDown · 스페이스 = 「이어서 재생」(장은 안 넘어감). **재생 중**이면 → · PageDown 은 무시(실수로 장이 넘어가지 않게)하고 스페이스는 영상 일시정지. **영상이 끝난 뒤**의 → · PageDown · 스페이스는 기존대로 다음 장. ←(PageUp)은 항상 이전 장. 발표용 리모컨(PageDown/Up)도 같은 규칙으로 동작 |
| 큐 시각의 기준 | 큐는 **녹화 기록의 장 · 자막 · 강조 순번**에 묶는다(절대 시각이 아님) — 다시 녹화해도 큐 파일은 그대로 쓴다. 큐는 재생 시각이 **앞으로 지나갈 때만** 멈춤을 띄운다(건너뛰기로 지난 큐는 띄우지 않음). **자막은 언제나 현재 재생 시각에 맞는 것**이 보인다 |
| `--clean` 이 길이를 바꾸나 | 장면 파일의 동작 · 대기(`pause`)는 그대로라 길이는 거의 같다(대기 시간만큼 변동 ±수 초 — 화면 로딩에 달림). 큐가 기록 기준이라 길이가 달라져도 어긋나지 않는다. 새 길이는 시간표에 다시 적는다 |
| 시간 상한 | 하드 상한은 두지 않는다(사용자가 「절반 정도」). 큐마다 켜고 끄는 칸(`enabled`)을 두어 리허설에서 넘치면 큐를 끈다 |
| 카드 그림 | 빌드 때 Playwright 로 슬라이드 10 · 11장의 그림 요소를 **캡처(2배 해상도)** 해 한 파일 판에 base64 로 넣는다 — 슬라이드가 바뀌면 다시 빌드할 때 따라 바뀜(옛 그림이 남지 않음) |
| 한 파일 판 크기 · 브라우저 | 현재 한 파일 판 28.2 MiB 가 영상 7개를 이미 base64 로 품고 단독 검증을 통과했다. 영상 두 개를 다시 녹화해도 크기는 거의 같다. 크롬 기준. 영상은 발표자가 키를 눌러 시작하므로 자동재생 정책에 걸리지 않는다 |
| 물러서는 시점 | **오늘 15:00 까지 플레이어가 한 파일 판 단독 검증(6절)을 통과하지 못하면** 7절의 물러서는 길로 간다 |

## 8. 제가(AI) 정한 것 — 확인해 주세요

1. 두 영상을 모두 다시 녹화(`--clean`)하고 자막은 겹침 층으로 옮긴다.
2. 카드 그림은 슬라이드 10 · 11장 그림을 캡처해 쓴다.
3. 이동원 슬라이드 2 · 5 · 8 · 10 ~ 15장은 **덱 조립에서만** 뺀다(원본 불변).
