## 0. 강사님 기준과 범위

- 영상은 **3개 이상, 각 3분 내외**, 편마다 다른 기능, **목적 → 실행 과정 → 결과** 순서, 자막 또는 설명을 넣는다.
- **2차 프로젝트 때 발표한 내용은 다시 찍지 않는다.** 이미 있는 장면 V01~V07 · F01~F08(수집 검증, 용어, 성향 진단 등)은 이번에 쓰지 않는다.
- 영상 세 편은 모두 **3차에서 새로 만든 것**만 다룬다.

| 편 | 기능 | 3차 신규 근거 | 화면 키 | 장면 파일 |
|---|---|---|---|---|
| A | 전체 종목 신호 걸러 보기 · 새로고침 · 근거 | 신호 순위 필터(#553) · 새로고침(#558) · 퀀트 카드 필터(#556) | `signal-rank` · `quant-dashboard` | `V-이동원-A-신호순위.yaml` |
| B | 낡은 일봉 방어 · 기준일 표시 | 신선도 가드(#529 · #537) · 기준일 · 신선도 배지 | `signal-rank` · `quant-dashboard` | `V-이동원-B-낡은일봉방어.yaml` |
| C | 그림자 일지 지문 고정 · 대사 | 일지 판 1 · 지문 · LEAN 대사 | 터미널 + `indicator-tradingview` | `V-이동원-C-일지와대사.yaml` |

## 1. 시연 전 준비

1. **자료 기준일을 확인한다.** 11월 5일 12:30 회차가 끝난 뒤(13:10 이후) 수집 DB 마지막 거래일이 11월 4일인지 본다. 아니면 화면의 기준일을 그대로 말하고 날짜를 적는다.
2. **일지 상태를 확인한다.** `paper_journal.py status`에서 두 규칙이 판 1 · 지문 같음인지 본다. 판 2 이상이 보이면 영상을 찍지 않는다.
3. **화면에 키·계정이 나오지 않게 한다.** `.env`, 개발자 도구, 증권사 키 화면은 띄우지 않는다.
4. 녹화 계정은 전용 시연 계정(`DEMO_EMAIL`/`DEMO_PASSWORD`, 기본은 이 PC 로컬 `demo-video@example.com`)을 쓴다. 관리자 전용 데모 데이터 단추는 누르지 않는다.
5. 녹화 도구는 `C:\workspace\venvs\demo`(playwright + pyyaml)의 파이썬으로 돌린다. 시험용 venv에는 playwright가 없다.

| 실행 4 | 퀀트 대시보드의 일봉 단독 규칙 카드 필터 | 31종목 중 N개 일치. 「일봉 단독 규칙」과 「기록된 신호」는 계산이 다르다는 이름표 |

## 3. 편 B: 낡은 일봉 방어 · 기준일 표시 (약 3분)

앱에 「데이터 대기」 문구를 직접 보여 주는 화면은 **없다**(코드 검색 결과). 그래서 이 편은 화면에 항상 나오는 **기준일 · 신선도 표시**(`data-sr-fresh`)와 설명 카드로 만든다. 낡은 일봉 상태를 일부러 만들지 않는다.

| 단계 | 조작 | 보여 줄 결과 · 설명 |
|---|---|---|
| 목적 | 제목 카드 | 11월 4일 오전에 신호가 이틀 전 종가였던 사례, 왜 위험한가 |
| 실행 1 | 신호 순위 상단의 기준일 · 계산 시각 · 배지 | 「기준: 날짜 · 계산: 시각」 한 줄과 배지 |
| 실행 2 | 퀀트 대시보드 「기록된 신호」 띠 | 같은 기준일 표시가 종목 화면에도 붙음 |
| 실행 3 | 설명 카드 | 신선도 가드: 있어야 할 마지막 거래일 종가인지 판정, 일반 경로만 해당(판 2 · 내 전략은 readiness) |
| 결과 | 한계 카드 | 증권사 일봉의 오늘 종가 확정 시각은 아직 공식 종가와 대조 전(15:40 값과 17:00 값이 달랐음) |

## 4. 편 C: 일지와 대사 (약 3분)

앱에 일지 전용 화면은 **없다**. 일지 상태는 명령줄이고, 앱에는 TradingView 대사 화면(`indicator-tradingview`)이 있다. 그래서 이 편은 **터미널 장면 + 앱 화면**으로 만든다.

| 단계 | 조작 | 보여 줄 결과 · 설명 |
|---|---|---|
| 목적 | 제목 카드 | 규칙과 코드의 지문으로 판을 고정하고, 그 결과를 외부 계산과 맞춰 본다 |
| 실행 1 | 터미널: `paper_journal.py status` | 판 1, 봉인 10월 26일, 행 수, 두 규칙 지문 「같음」 |
| 실행 2 | 앱: TradingView 대사 화면에서 「LEAN과 비교 실행」 | 같은 입력을 LEAN과 TradingView 값으로 비교 |
| 실행 3 | 결과 표 | 신호 41/41 · 보유 43/43 · 주문 12/12 · 체결 12/12(11월 4일까지 43행, 강민석 님 #567 보고). 11월 5일 이후 행은 맞춰 보기 전이라 「확인 전」으로 보여 줌 |
| 결과 | 조건 카드 | 「ma_cross · 최대 보유 비중 30% 고정」. 일지 43행(봉인 전 사후 계산 35 + 봉인 뒤 전진 8)은 성과가 아니라 기록과 지문 동작의 증거 |

**녹화 방법 확인 필요:** `record_demo.py`는 브라우저만 녹화한다. 터미널 장면은 (1) 명령 출력을 설명 카드로 옮기거나 (2) 강사님 안내의 `screen_recorder.py` 같은 화면 녹화로 따로 찍어 이어 붙인다. 출력을 카드로 옮기면 실제 명령 출력이라고 영상에 밝힌다.

## 5. 녹화 순서

1. 장면 YAML 세 개를 `docs/phase-3/06-retrospective/videos/장면/`에 둔다.
2. `--no-video`로 단계만 밟아 누를 곳을 확인한다.
3. 12:30 회차 뒤 자료가 맞는 상태에서 녹화하고, `export_mp4.py`로 mp4를 만든다. 산출물(`tools/demo/out/`)은 git에 넣지 않는다.
4. 3분 안팎인지 길이를 확인한다(`LIMIT_SEC = 180`).
5. 발표자료에 영상 파일 또는 링크를 연결하고 **발표 전에 재생 여부를 확인**한다.
6. 11월 11일(수) 영상을 동결한다. 동결 전 일지 판과 시험 건수를 다시 확인한다.
