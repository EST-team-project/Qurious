# #619 · B/C 영상의 촬영 조건과 검증

2026-11-09. [요청 #619](https://github.com/EST-team-project/Qurious/issues/619)에 따라 오준영 담당 B·C를 발표용과 사용법용으로 각각 촬영했다. [재생 페이지](영상.html)와 전체 발표자료의 B·C 장은 같은 MP4를 읽는다.

## 촬영 환경

- 앱 기준: main `81e51d06dfe62f82f2d5588114bfae1447fb6fe5`(#620 장면 파일과 #621 포함). 제품 코드와 API 응답을 바꾸지 않았다.
- 운영 DB와 분리한 일회용 PostgreSQL·Redis·앱에서 촬영했다. 외부 연결이 없는 Docker 내부 네트워크이며 KIS 키·계좌·알림 발신 설정은 주입하지 않았다. 자동 실행 worker/Beat도 실행하지 않았다.
- 수집 자료는 읽기 전용 HF 스냅샷 `12101e96262751693d2de7cda6708c924e84d2b6`, 가격 기준일 **2026-11-06**이다. 준비 판정 시각은 시험 전용 `regime_integration_clock.py`로 **11/9 14:00 KST**에 고정했다. 시장 가격·계산 결과·조회 응답은 대체하지 않았다.
- 모든 영상의 상단에 **시험용 격리 환경 · 11/6 수집자료 재현 · KIS 미연결**을 표시한다. 앱이 사용하는 원본 CDN 자산과 촬영 PC 글꼴을 임시 녹화기에 제공했다. 이 글꼴/캐시 파일은 배포물에 포함하지 않는다.

## B · 국면 자동 변경

1. 기존 `tests/e2e/regime_integration.py --phase setup`으로 실제 가입·로그인·시장 국면 배분 계산·PG 저장·플랜 저장을 확인했다. 자동 예약은 OFF다.
2. `regime_integration_fixture.py`로 **시험용 과거 국면(상승·저변동, 국내주식 33%)**만 준비했다. 실제 과거 운용 실적이 아니다.
3. 실제 `/api/rebalance/check`가 11/6 수집 자료의 하락·고변동 국면을 계산하여 국내주식 목표 **33% → 15%**, 현금 **67% → 85%**, 변경 이력 **1건**을 생성했다. 같은 날 재점검은 이력을 늘리지 않았다.
4. 준비 뒤 자동 변경을 OFF로 저장하고, 촬영에서는 배분 가져오기와 체크칸의 **미저장 편집**, 변경 이력 조회만 수행했다. 플랜 저장·주문 산출·예약·주문 실행은 촬영 중 누르지 않는다.

## C · 내 전략 가상 장부

- 기존 카드 저장 서비스로 시험용 이동평균 10·60 카드를 저장하고, 실제 개인 전략 선택 로직으로 내용 지문을 고정했다. 성과 합격 판정이나 전략 추천이 아니다.
- 외부 worker 없이 준비 과정에서 실제 실행기를 순서대로 호출했다. 12:29 시각 입력은 `DATA_NOT_READY`, 14:00 준비된 자료는 `initialized`, 같은 봉 재호출은 `duplicate`, 정지 상태는 `DISABLED`를 반환했다. 조회 화면의 네 로그는 그 호출에서 저장됐다.
- 촬영 시 자동매매는 **OFF**, 비상 정지는 **ON**, 개인 전략 runtime은 **1건**, 가상 체결 및 증권사 주문은 각각 **0건**이다. 손실 한도는 설정 기준만 보여 주며, 손실 한도 초과를 이번에 발생시켰다고 설명하지 않는다.
- 내 전략 선택은 화면의 미저장 편집만 한다. 저장·자동 시작·정지 변경·KIS 주문 단추는 누르지 않는다. App Key/Secret/계좌 입력 구역은 숨기고 이메일·증권사 주문 구역은 마스킹했다.
- 이 영상은 **실제 엔진의 초기 판단과 차단 기록**을 보여 준다. 매수·매도 체결, 정기 스케줄러 실행 성공, KIS 연동 성공 또는 수익률의 근거로 쓰지 않는다.

## 파일과 재촬영

장면 원본은 `../videos/발표/P-오준영-{B,C}-*.yaml`, `../videos/장면/V-오준영-{B,C}-*.yaml`이다. 녹화·자막·장 제목은 기존 `tools/demo/record_demo.py --frames`, MP4·포스터·목록은 `export_mp4.py`를 사용한다. `subtitle_sync.py check`로 **실제 녹화 기록의** 자막 노출 시간을 검사한다. 결과 지문과 녹화 시각은 `../videos/파일/목록.json`에 남긴다.

재촬영 시에는 운영 계정의 빈 상태에 임의 이력을 넣지 않는다. 별도 시연 DB에서 위 조건을 준비한 뒤 동일한 장면을 실행하며, 수집 자료가 바뀌면 기준일·국면·전후 비중·자막을 다시 대조한다. 파일만 재생할 때는 앱·DB·KIS 연결이 필요 없다.
