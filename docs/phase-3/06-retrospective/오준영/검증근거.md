## 2. 현재 조건

11/4 오후에는 11/3 일봉과 오늘 수신 검증 근거가 준비됐다. PAPER 보유 계좌 0개이며 QUANT·KIS 장부와 구분한다. 배포 전후 자동매매 OFF·미확인 주문 0건과 기존 설정·장부 지문 보존을 확인했다. 알림 암호화는 키/복원 준비 완료이고 구현·기존 값 전환은 대기다. #537에서 이동원 PC의 B안 복구가 보고됐고 우리 쪽은 함수 지문 복구·합성 입력 5종 결과 일치를 확인했다. 우리 DB에는 판 2가 없으며, 이미 수신한 다른 PC의 재업로드 위험은 남아 있다. 원격 원장은 이 작업에서 변경하지 않았다.

오늘 15:40 결과는 시각 도래 후 별도 기록한다. 일회용 관측기가 DB를 읽더라도 기존 배치의 성공을 선행해서 선언하지 않는다.

## 3. 검토자가 재현할 곳

- 서버 회귀: `tests/test_rebalance_target_metadata.py`, `test_rebalance_regime.py`, `test_rebalance_daily.py`, `test_rebalance_policy.py`, `test_rebalance_unified.py`, `test_rebalance_exceptions.py`, `test_rebalance_settlement.py`, `test_rebalance_target_rounding.py`, `test_followup_screen_flows.py`, `test_allocation_models.py`, `test_allocation_data.py`, `test_asset_allocation.py`, `test_etf_followups.py`, `test_migration_heads.py`, `test_us_reserve.py`, `test_no_yahoo_regression.py`, `test_us_order_screen.py`, `test_learn.py`.
- 실행: 운영과 분리된 PostgreSQL·Redis를 사용하는 `scripts/personal/test.ps1` 환경. DB 없는 수집 성공이나 건너뜀을 실행 통과로 대체하지 않는다.
- 실제 브라우저: `tests/e2e/regime_integration.py` 및 fixture, 위 재현 절차의 setup→재시작→persist→history 순서.
- KIS: 재시험 도구는 실제 모의 주문을 생성할 수 있다. 발표 준비 과정에서는 기존 성공 근거를 조회하며 재실행하지 않는다.

원본 로그·XML·암호화 백업은 로컬 비공개 증거 폴더에 보존한다. 공개 자료에는 계좌·주문 원문·앱키·웹훅·세션·수집 원자료를 포함하지 않는다. 이 문서의 수량·시각은 확인 결과를 요약한 것이다.
