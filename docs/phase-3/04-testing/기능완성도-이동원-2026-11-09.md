## 4. 같이 찾은 것

1. **시험 2건이 main 에서 실패하고 있었다(고침, 커밋 전).** 강민석 님 PR #602(`bd5d9739`)가 수집 단계 `paper_kis_reconcile` 을 `journal` 과 `signals_all` 사이에 끼웠는데 두 시험의 순서 단언이 낡았다 — `tests/test_daily_update.py::test_signals_step_after_daily_bars_before_manifest` · `tests/test_paper_journal.py::test_pj13_runner_steps`. 두 곳과 앱 DB 단계 목록 단언을 실제 순서에 맞게 고쳤고 `test_daily_update` · `test_paper_journal` · `test_paper_kis_reconciliation` 이 통과한다. 이 실패는 테스트 계획서 표 9 에 아직 없다(결함 번호는 판 올림 때).
2. **100일 백테스트 결과를 읽는 곳이 없다(코드 읽기 · 실행해 재현하지는 않음).** 10-30 부터 결과가 격리 장부(`BacktestSnapshot`)에만 쓰이는데 `app/` 어디에도 그것을 읽는 라우트가 없고, QFRS 지표는 `PaperAccountSnapshot` 만 읽는다. 그런데 카드 문구(`public/js/paper.js` 1459행)는 「완료 후 QFRS 지표가 100일치로 계산됩니다」, 49행은 「SIM 주문 N건 포함 — 자산추이 · QFRS 카드에 반영됨」 이라고 말한다. #559 에서 맞다고 확인한 것은 계좌 · 삭제 범위 · 1억 · 일반 장부 유지이고, **결과가 화면에 나오는지는 확인한 적이 없다.** 강민석 님 화면이라 이슈로 확인을 요청해야 한다. 영상과 발표에는 이 카드를 쓰지 않는다.
3. **결함대장 정리 후보:** DF-21 · DF-94 · DF-95 · DF-96 · DF-139 가 표 9 에 아직 열림 · 후보로 남았는데 코드는 풀렸다는 제안이 있다(강민석 님 줄 · 확인 필요). DF-172 도 「PR 대기」 로 남았다(`f4f15b6b` 로 main 에 들어감).
4. **추적 중인 백업 파일 6개:** `app/` · `tests/` 의 `*.bak_fills` · `*.bak_syntax` · `*.bak_total_fees`. 지울지는 사용자 결정(동결 전에는 건드리지 않는 쪽을 권한다).
