## 1. 정정 요청

### 1-1. 국면 자동 목표 갱신의 미구현 설명 — 우선 수정

[국면 배분 장 124·136·144행](https://github.com/EST-team-project/Qurious/blob/72f07b77/public/learn/content/regime-dynamic-allocation.md#L124)은 예약 작업의 자동 목표 교체가 미구현이라고 설명한다. [#522](https://github.com/EST-team-project/Qurious/pull/522)에서 명시적 활성화·저장, 준비된 일봉으로 국면 변화 판정, 목표 갱신·변경 이력·중복 차단이 구현됐다.

다음처럼 **목표 갱신과 실제 계좌 체결을 구분**하는 설명을 제안한다.

> 처음에는 저장한 국면 배분을 가져와 사용자가 플랜을 확인·저장한다. ‘국면 변화에 따라 목표 비중 자동 변경’을 켜면 준비된 자료의 국면이 바뀔 때 목표와 변경 이력을 갱신한다. 자동 예약은 별도 설정이며, 꺼져 있으면 제안만 생성한다. 목표 변경 자체가 즉시 매매나 KIS 주문을 뜻하지 않는다.

자료 미준비·기존 예약 존재 등 차단 조건도 유지된다. 정본은 `rebalance_regime.py`, `rebalance_daily.py`와 [배분–리밸런싱 연결 §8](../02-design/system/배분-리밸런싱-연결.md#8-2026-11-03-국면별-목표-자동-갱신)이다. 11.2의 최초 가져오기·저장 설명은 맞으며, 이 선택 기능으로 연결하면 두 장의 설명이 이어진다.

### 1-2. ‘효용 최소화’ 표현 — 계산의 부호를 명확히

[평균–분산 70행](https://github.com/EST-team-project/Qurious/blob/72f07b77/public/learn/content/mean-variance-optimization.md#L70), 같은 장의 서비스 설명, [BL 203행](https://github.com/EST-team-project/Qurious/blob/72f07b77/public/learn/content/black-litterman.md#L203)은 ‘효용 최소화’라고 적었다. 앞에서 정의한 효용 `U = wᵀμ − δ/2·wᵀΣw`는 **최대화**한다. 코드가 최소화하는 것은 `−U = δ/2·wᵀΣw − wᵀμ`다.

본문과 예제 설명을 ‘효용 최대화(음의 효용 최소화)’로 맞추면 된다. 실제 `allocation_models.solve_weights`의 목적함수와 예제의 계산 부호는 올바르며, 계산 코드를 뒤집을 사안은 아니다. [He–Litterman 원문](https://people.duke.edu/~charvey/Teaching/BA453_2006/GS_The_intuition_behind.pdf)의 효용 설정과도 대조했다.

### 1-3. ‘국면 모델은 제약이 없습니다’ — 적용 범위 한정

[국면 배분 장 128행](https://github.com/EST-team-project/Qurious/blob/72f07b77/public/learn/content/regime-dynamic-allocation.md#L128)은 제약이 없다고 단정한다. 실제로는 기준 비중 합계 100%·0.1% 단위·비음수·현금 제외 기준 자산군 1~95%를 검사하고, 계산 결과도 비음수·합계 100%로 반환한다. 다른 세 모델과 다른 것은 **국면 조정 뒤 결과에 동일한 1~95% 상하한을 적용하지 않는 것**이다.

‘국면 조정 후 비중에는 다른 세 모델과 같은 1~95% 한도를 적용하지 않는다. 기준 비중 입력 검증과 비음수·합계 제약은 유지한다’로 범위를 좁히는 것을 제안한다.

## 2. 확인한 계산과 예제

외부 네트워크가 없는 최신 앱 이미지에서 `mean_variance.py`, `risk_parity.py`, `black_litterman.py`, `regime_allocation.py`, `rebalance_rules.py`를 각각 실행했다. 아래 **8개 대조 항목이 통과**했다. 별도의 투자 수익성 시험으로 해석하지 않는다.

| 항목 | 결과 |
|---|---|
| 평균–분산 닫힌 식과 SLSQP | 양수 비중 예제에서 최소분산 해 일치 |
| 분산투자 4개 상관 예제 | 공개된 변동성 수치 재현 |
| RP 예제와 앱 함수 | 비중과 25% 위험 기여 일치 |
| 최소분산 예제와 앱 함수 | 1~95% 한도 아래 비중 일치 |
| RP 95% 상한 예제 | 최대 위험 기여 편차 13.556%p, 문서의 13.6%p 재현 |
| BL 25·50·90·99% 신뢰도 | 두 사후 수익 식과 앱 결과 일치. 비중 차이 최대 약 0.000275%p |
| BL 전망 없음·신뢰도 0 | 기준 비중과 사전 수익 유지 |
| 국면 200·240일 예제 | 앱 함수의 국면·추세비·변동성 값 일치 |

표본 공분산·현금 제외 비중 한도, BL의 사용자 기준 비중·상대 전망·0% 신뢰도 처리, 표시 비중으로 위험 기여를 다시 계산하는 설명은 코드와 맞는다. 국내주식 종목 최적화는 일반 MVO 최적화기와 구분하는 것이 맞으며, 실제 정규화는 단순 사후 절단이 아니라 상하한을 유지하는 비례 조정이다.

BL 사후 수익과 신뢰도 식은 [PyPortfolioOpt 공식 문서](https://pyportfolioopt.readthedocs.io/en/latest/BlackLitterman.html) 및 [공식 구현의 `idzorek_method`·`bl_returns`](https://pyportfolioopt.readthedocs.io/en/latest/_modules/pypfopt/black_litterman.html)도 확인했다. ERC 저자 PDF 주소는 이번 열람에서 시간 초과였으므로 원문을 재확인했다고 기록하지 않는다. RP 결과는 앱과 예제의 수치 대조 근거다.

## 4. #546 후속 재검수 — 2026-11-04

[#546](https://github.com/EST-team-project/Qurious/pull/546)의 세 장 수정은 main `910c8ee1`에 포함됐다. §1의 초회 요청 세 건은 반영됐다. 효용 계산 코드는 바뀌지 않았고, 국면 자동 갱신의 명시적 활성화와 입력/결과 제약을 구분했다. 기존 요청·수치 대조는 당시 근거로 보존한다.

다만 국면 장 124행의 새 문장 **‘실제 주문과 증권사 주문은 따로 정한 리밸런싱 실행 설정에 따르며’**는 두 실행 경로를 잘못 연결할 여지가 있다. `rebalance_settlement.py`는 PAPER 보유를 읽고 `paper_trading._fill_stock_order()`로 앱 장부를 정산한다. KIS 증권사 주문은 별도 자동매매 경로다. 작성 담당에게 다음 문구로 보완을 요청했다.

> 앱 PAPER 장부의 주문 예약·정산은 리밸런싱 실행 설정을 따릅니다. KIS 증권사 주문은 별도 자동매매 경로이며, 국면 목표 변경으로 직접 전송되지 않습니다. 자동 갱신을 켜지 않은 플랜은 목표도 저절로 바뀌지 않습니다.

작성자가 미확인으로 남긴 자동 예약 ON/OFF도 `rebalance.check_daily()`→`check_due()`까지 대조했다. **조건과 주문 수량이 충족되면** OFF는 `proposed`, ON은 `scheduled`다. 국면 목표 변경만으로 항상 제안이 생기거나 즉시 체결되는 것은 아니다. 코드 근거는 `rebalance.py:390~411`, `rebalance_settlement.py:237~245`다.

최신 이미지·격리 PostgreSQL에서 `test_learn.py`, `test_concept_learn_view.py`, `test_rebalance_regime.py` **66통과·실패/건너뜀 0**을 확인했다. ON/OFF 두 경우가 실제 DB 시험에 포함된다. 초회 8개 수치 대조를 다시 수행하거나 66건에 합산하지 않았다. 이전 #534 비용 판정 시험의 실패까지 해결된 결과가 아니다. 원본은 Git 제외 `followup-546-20261104`에 보관한다.

[#546 재검수 댓글](https://github.com/EST-team-project/Qurious/pull/546#issuecomment-6625685058)에 반영 확인과 문장 보완을 전달했다. 16:56 최신 Docker에서 세 학습 원문의 HTTP 200·응답 해시 일치를 확인했다. 서비스별 701파일·키/환경/설정/장부 보존, 조회 13경로·16:57 새 heartbeat도 확인했다. 문서가 배포됐다는 것과 추가 문구 보완이 끝났다는 것은 구분한다.

## 5. #549 후속 문구 소스 재검수 — 2026-11-04

[#549](https://github.com/EST-team-project/Qurious/pull/549)는 `4dc18839`로 병합됐다. 로컬 main `2996ac28`의 국면 장 124·136행을 다시 읽고 §4에서 확인한 실행 계약과 대조했다. PAPER 장부의 예약·정산과 KIS 별도 자동매매 경로를 분리했고, 조건과 수량을 충족할 때 자동 예약 OFF는 제안·ON은 예약이며 그 단계에서 즉시 체결하지 않는다고 명시했다. **요청한 후속 문구 보완은 소스에 반영됐다.**

마지막 운영 배포는 `910c8ee1`이므로 #549를 Docker에서 제공 중이라고 표시하지 않는다. 이번 확인은 소스 문구 검수이며 66건 시험·HTTP 조회를 새로 실행하지 않았다. 취소된 추가 전체 시험·KIS 주문도 재개하지 않았다. 누적 상태는 [오류 기록 ERR-035](오준영-오류수정기록.md#err-035--학습-설명과-구현효용제약주문-경로-불일치)에 함께 반영한다.
