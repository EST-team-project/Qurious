## 1. 결과와 범위

연결된 실제 수집 DB의 원종가·원시가·저장된 거래일 달력·출처별 수집 완료 자료를 사용해 **6개 시나리오가 모두 통과**했다. 각 시나리오에서 예약, 체결 대기, 정산, 장부 대조, 중복 방지를 확인했다. 실제 수집 가격을 이용한 예약→정산 검증은 완료다.

원본 DB는 `/mnt/e/Qurious/collector/active/market.sqlite3`이며 `data/collector/market.sqlite3`에서 연결된다. SQLite `mode=ro`로 필요한 행만 읽고, 별도 SQLite 추출본과 일회용 PostgreSQL 시험 계좌에서 실행했다. 원본 DB 크기·수정 시각의 전후 일치도 확인했다.

입력 중 **가격·달력·출처별 `ingest_day`는 원본 자료**다. 과거 시각, 회차 완료 기록, 초기 계좌·목표 비중은 재현용 입력이다. 완료 기록에는 `_verification_only=true`를 명시했고 추출본의 `state/`에만 저장했다. 운영 원본 회차가 실제로 정상 실행됐다는 검증과는 별개다.

## 2. 예약부터 정산까지

| 시점 | 확인 |
|---|---|
| 2026-09-30 종가 | 저장된 원종가로 계좌 평가 |
| 2026-10-01 13:30 | 목표 40%·40%에 맞춘 예약 생성. 주문·현금은 바뀌지 않음 |
| 2026-10-02 13:30 | 전일 자료만 공개된 상태에서 예약 유지. 아직 정산하지 않음 |
| 2026-10-06 13:30 | 주말·개천절 대체휴일 뒤 10/2 시가와 수집 완료 자료 공개. 체결일은 10/2, 정산 확인일은 10/6 |
| 같은 회차 반복 3회 | 새 DB 연결에서도 주문 ID·현금·수량 유지 |

모든 경우 외부 현재가 조회를 금지했으며 앱의 `readiness`, `check_all_due`, 가격 조회, 정산 및 장부 반영 코드를 그대로 실행했다. 미래 날짜의 가격·수집 완료 자료는 해당 재현 단계 전에는 추출 DB에 넣지 않았다.

## 3. 계좌별 결과

초기 평가액은 각 1억 원, 매도 대상 약 60%·매수 대상 약 10%·나머지 현금으로 설정했다. 다음 세 구성을 **정상 회차와 뉴스 단계 실패(`ok=false`) 회차에서 각각** 실행했다. 두 회차 유형의 최종 장부 결과는 동일하다.

| 구성 | 10/2 실제 수집 시가 주문 | 정산 후 수량 | 정산 후 현금 |
|---|---|---|---:|
| 삼성전자 → SK하이닉스 | 삼성 74주 매도 × 273,500원 / 하이닉스 17주 매수 × 1,830,000원 | 삼성 149주 · 하이닉스 22주 | 20,323,937.18원 |
| 삼성전자 → KODEX 200 | 삼성 74주 매도 × 273,500원 / ETF 270주 매수 × 111,185원 | 삼성 149주 · ETF 361주 | 20,325,585.04원 |
| KODEX 200 → 삼성전자 | ETF 183주 매도 × 111,185원 / 삼성 110주 매수 × 273,500원 | ETF 364주 · 삼성 147주 | 20,397,317.44원 |

위 숫자는 저장된 수집 자료의 해당 날짜 값이며 현재 시세나 투자 권고가 아니다. 수량은 시가에서 다시 계산했다.

비용 함수의 반환값을 기대값으로 재사용하지 않고, 프로젝트에 설정된 요율로 수수료·유관기관비·매도 세금을 별도 계산해 장부 칸과 대조했다. ETF 매도 세금 0, 매수 세금 0, 주식 매도 세금 반영을 확인했다. 같은 시가로 평가한 정산 전후 총자산 차이는 비용 합계와 일치한다. 실제 증권사 체결·요율 정확성을 검증한 것은 아니다.

장부는 소수 정밀도를 유지하고 화면·예약 결과는 소수 둘째 자리로 표시한다. 최초 검증 스크립트가 장부까지 둘째 자리로 반올림한다고 가정해 실패했고, 장부 정책대로 기대값을 수정한 뒤 6개 모두 통과했다. 이 과정에서 앱 코드는 추가 변경하지 않았다.

## 4. 근거와 후속 상태

- [#124 검증 결과 댓글](https://github.com/EST-team-project/Qurious/issues/124#issuecomment-6116509322)에 결과와 재현 범위를 공유했다.
- Git 제외 실행 근거: `data/local-run/rebalance-collected-20261012/`의 `test_collected_replay.py`, `pytest.log`, `results.xml`, 시나리오별 JSON 및 `extracts/` 원본 행 추출본. 각 JSON에 추출 자료 SHA-256과 확인 항목 10개를 기록했다.
- 재실행은 프로젝트 의존성을 설치한 환경에서 `ENV_FILE`을 빈 시험 파일로, `QURIOUS_TEST_DATABASE_URL`을 `postgresql+asyncpg://qurious_test@127.0.0.1:25463/qurious_collected_replay_test`로 지정한 뒤 `python -m pytest data/local-run/rebalance-collected-20261012/test_collected_replay.py`로 가능하다. 시험 DB는 별도로 생성해야 한다.
- **완료:** 현재 수집 자료를 사용한 예약→정산 및 현금·보유 수량·비용·중복 방지 검증.
- **후속 결과:** 공통 종목 상태 조회 연결은 아래 §5에서, 원본 러너 기록과 새 운영 일별 점검 대조는 §6에서 완료했다. 새 제안의 실제 승인→예약→정산 관측과는 구분하며, 기존 실제 수집 가격 정산 검증을 미완료로 되돌리지 않는다.
- GitHub 이슈의 체크리스트·닫힘 상태는 이번 검증에서 변경하지 않았다.

## 5. 2026-11-03 공통 종목 상태 조회 연결

#124에서 약속한 소비자 연결을 다시 점검했다. `collector_status.symbol_day_status`는 이미 있었지만 `rebalance_prices.collection_complete`는 수집 기록을 별도 SQL로 해석하고 있었다. 소비자를 공통 함수로 변경하고, 선택 인자 `connection`으로 가격 조회의 열린 트랜잭션을 전달한다. 기본 `path` 호출은 기존 읽기 전용 연결을 유지한다. 전달받은 연결에서는 SELECT만 수행하며 커밋·종료하지 않는다.

수집 사실은 제공자가, 대기/미체결 판정은 리밸런싱이 담당한다. 주식/ETF/혼합/미상 분류와 `done` 기준을 유지하며, 공통 함수 읽기 실패도 가격 대기로 처리한다. 원시 시가·종가와 거래량 결측/0의 구분은 유지한다.

- 격리 SQLite WAL 시험에서 가격을 읽은 뒤 다른 연결이 `error→done`을 커밋했다. 진행 중 조회는 이전 상태로 대기하고, 다음 조회에서만 미체결 확정했다.
- 호출자 연결의 유지·새 연결 금지·SELECT만 수행·실패 시 대기와 기존 종목 상태 14경우를 검증했다.
- 관련 리밸런싱·정산·수집 상태·로보·배분 검증 **336건 통과**, 실제 Chrome 환경이 필요한 기존 화면 시험 1건은 이 Docker 묶음에서 제외됐다. 이번 변경은 화면 코드를 바꾸지 않는다.
- 운영 원본의 새 자연 회차나 실제 증권사 주문을 발생시킨 검증은 아니다.

## 6. 2026-11-03 새 수집 세대와 자연 일별 점검

운영 Docker가 받은 HF `60241f8dc2b5df4be776c39ff6d6a350e3cf70f9`를 원본 회차 기록·manifest·검증 결과·로컬 준비 판정과 대조했다. 아래 시각은 KST다.

- 원본 회차 시작 **12:30:02**, manifest **13:03:29**, 검증 **13:04:16**, 회차 기록 **13:04:18**. 시세·달력·내보내기·검증 단계는 모두 종료코드 0이며 검증 대상 manifest 시각이 일치한다. 업로드 단계에서 기록한 `finished_at=null`은 제공자 계약에 맞는다.
- Docker 검증 세대 반영 **13:14:14**, `ready=true`, `data_as_of=2026-11-02`. 11/2 주식 원주가·수정주가 각각 2,874행, ETF 1,183행이며 관련 출처의 수집 상태는 `done`이다.
- 기존 예약 실행기의 **13:16:36** 일별 점검에서 전일 종가 기준 제안 1건을 생성했다. DRIFT·CASHFLOW 조건, 제안 주문 8개, 모든 제안 가격이 11/2 수집 원종가와 일치했다. 이 관측을 위해 작업을 수동 전송하지 않았다.
- 같은 날 다시 점검하면 `already_checked`이며 새 회차·주문이 생기지 않았다. 사용자 플랜의 `auto_execute=false`를 유지하므로 결과는 **제안(`proposed`)**이다. 승인·예약·체결 완료로 표시하지 않는다.

이번 관측으로 원본 정상 수집 회차→검증 세대 동기화→기존 운영 일별 점검의 연결을 확인했다. 새 제안을 승인한 뒤 예약 시가를 기다리는 운영 정산은 이번 검증에 포함하지 않는다. 비공개 근거는 `data-ready-20261103/source-readiness.json`, `local-readiness.json`, `natural-rebalance.json`이며 계좌 원본과 검증 스크립트는 Git에 올리지 않는다.
