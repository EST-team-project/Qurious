# 판 2 실행 상태·다음 시가 재현 — 2026-10-29

## 범위와 현재 상태

[#314](https://github.com/EST-team-project/Qurious/issues/314)의 고정 `ma_cross_20_60` 판 2를 위한 내부 상태 모듈과 수동 다음 시가 재현기를 추가했다. 처음 관측한 진입 조건이 이미 참이면 60봉·유효 ATR을 확인해 첫 진입한다. 청산 뒤에는 진입 조건이 해제됐다가 다시 참이 되어야 한다([담당자 답변](https://github.com/EST-team-project/Qurious/issues/314#issuecomment-6458391689)).

판 2를 **기존 QUANT 가상계좌·Order·Portfolio와 공통 위험 관문에 연결**했다. 정기/즉시 사이클에서 정확히 이 카드/판을 선택하면 전용 실행기로 분기한다. 처음 실행은 최신 확정 봉을 판단하고 다음 거래일 계획을 저장하며, 다음 자료가 들어오면 해당 일자 시가로 가상 장부를 체결한다. 과거 기간을 운영 장부에 자동 소급 입력하지 않는다.

판 2 KIS·TradingView 주문은 지원하지 않는다. KIS의 장중 현재가를 다음 시가로 바꾸어 표시하지 않으며 판 1 경로 점검은 별도다. 자동 실행 설정을 켜거나 사용자 전략 선택을 변경하지 않는다. 판 1 동결 판단 함수 3개와 점수 배율은 유지한다.

위험관리 운영 배포는 [#395](https://github.com/EST-team-project/Qurious/pull/395), 이번 연결 변경은 [#396](https://github.com/EST-team-project/Qurious/pull/396)를 따른다. 연결 코드의 운영 배포 결과는 아래 운영 확인 절에 추가한다.

| 체결 구분 | `V2_VIRTUAL`의 다음 시가와 `V2_KIS_PROBE`의 장중 점검 상태를 분리. 가상 다음 시가에 장중 체결 시각을 넣으면 거부. 다음 거래일 자료 누락을 더 뒤의 시가로 대체하지 않음 |
| 조정 사건 | 신규 진입 보류. 보유 중 사건은 수량·원가·손절·익절 대조가 필요하다는 상태로 중단. 합의되지 않은 자동 보정을 구현했다고 표시하지 않음 |

`apply_event`는 서버 내부용이다. 연결 실행기는 공통 계좌 잠금 안에서 최종 자료/설정/보유를 대조하고, 주문 의도와 예약을 먼저 commit한다. 이어 기존 가상 장부의 현금·보유·Order를 원자적으로 기록한다. 장부 commit 후 응답이 끊기면 `Order.execution_intent_id`와 수량·가격·모델 시각을 검증해 상태를 복구한다. 장부 체결 근거가 없으면 UNKNOWN을 유지하고 재전송하지 않는다.

최종 연결 검증: 외부 주문망과 분리된 PostgreSQL/Redis 시험 **417건 통과, 실패/건너뜀 0 (43.55초)**. 판 2 상태 신규 40건과 연결 신규 15건, 기존 위험 관문·주문·전략 카드·웹훅·스냅샷·DB 단일 head를 포함한다. 원본은 `data/local-run/strategy-v2-20261029/connected-tests.txt`에 보관한다.

연결 시험은 실제 QUANT 매수→전량 매도→재진입 대기, 5개 동시 호출 1체결, commit 뒤 응답 유실 복구, commit 전 장애의 재전송 0회, 수동 보유 5주 보존, 다른 종목 평가 불가 차단, 0주·자료 세대 변경·조정 사건·누락 거래일 차단, 체결 직전 현금 감소 시 수량 축소 없이 차단, 정기 사이클 분기와 자동 OFF 보존을 확인한다.

### 운영 실행의 구분

- `Order.created_at`은 실제 기록 시각이고 `filled_at`은 다음 거래일 **09:00 KST 모델 시각**이다. `price_basis.mode=virtual_next_open`에 신호일·모델 시각·원 시가·편도 10bp·수량 근거·자료 세대를 남긴다. 실제 KIS 체결 증거가 아니다.
- 일손실/주문 수/쿨다운은 공통 관문의 **실행일** 기준이다. 가상 평가에는 모델 시가를 쓴다. 다른 종목을 보유해 같은 시각 평가를 못 하면 `VALUATION_UNAVAILABLE`로 보류한다.
- 정기 실행은 자동 ON과 정확한 카드/판 선택이 필요하다. 수동 CLI는 `--execute`를 명시해야 상태/가상 장부를 쓰며 자동 설정은 바꾸지 않는다. 기본은 읽기 전용이다.
- 누락된 바로 다음 거래일을 더 뒤의 시가로 대체하지 않는다. 조정 사건 보유 대조·불명 의도의 운영 해소 UI·KIS 판 2 어댑터는 없다.

```bash
python scripts/strategy_v2_execute.py --user-id <사용자-UUID>
# 상태/가상 장부 기록을 승인한 사용자만 아래 명시적 실행 사용
python scripts/strategy_v2_execute.py --user-id <사용자-UUID> --execute
```

운영 백업을 복원한 격리 DB에서 `0029 → 0030 → 0029 → 0030`을 적용하고 기존 사용자 기록 보존을 확인했다. 새 표는 `strategy_runtimes`, `strategy_runtime_events`다. 실제 상태 기록이 생긴 뒤 downgrade하면 해당 상태/사건이 사라지므로, 운영 적용 후 오류는 기록을 보존한 상태에서 복원 또는 전진 수정을 판단한다.
