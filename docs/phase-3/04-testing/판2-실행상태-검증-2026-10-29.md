# 판 2 실행 상태·다음 시가 재현 — 2026-10-29

## 범위와 현재 상태

[#314](https://github.com/EST-team-project/Qurious/issues/314)의 고정 `ma_cross_20_60` 판 2를 위한 내부 상태 모듈과 수동 다음 시가 재현기를 추가했다. 처음 관측한 진입 조건이 이미 참이면 60봉·유효 ATR을 확인해 첫 진입한다. 청산 뒤에는 진입 조건이 해제됐다가 다시 참이 되어야 한다([담당자 답변](https://github.com/EST-team-project/Qurious/issues/314#issuecomment-6458391689)).

이번 코드는 **상태 전이·영속 기록·수동 가상 재현까지**다. 기존 자동매매/TradingView/KIS 주문 어댑터는 여전히 판 2를 거부한다. 이 문서는 판 2 운영 주문 지원·배포 완료 보고가 아니다. 판 1 카드·공통 판단 함수·그림자 일지·기존 가상 장부는 수정하지 않았다.

운영 위험관리 배포는 별도 [#395](https://github.com/EST-team-project/Qurious/pull/395)의 기록을 따른다. 운영은 main `62b3950`·DB `0029`이며, 아래 `0030`은 격리 시험 DB에만 적용했다.

## 구현과 확인한 경계

| 항목 | 구현·시험 |
|---|---|
| 최초 진입 | 60봉과 양의 ATR, 고정 카드 전체 실행 계약 확인. 준비 봉 부족·미래/진행 봉·계수 누락·새 실행 필드는 오류 |
| 가격 단위 | 실제 원/수정 OHLC와 날짜별 계수 일치 확인. 수정 ATR을 판단일 계수로 나누어 원주가 손절 거리 산출. 신호는 기존 공통 판단 함수를 호출 |
| 크기 | 최종 가격 기준 위험 1%, 현금·비용·예산·카드 30%/계정 비중 상한. 0주를 1주로 올리지 않음 |
| 손절·익절 | 확정 체결 가중 평균가 기준 `평균가 − 2 ATR`, `평균가 + 4 ATR`. 부분 체결 중 확정 평균가 변화만 반영하고 최종 체결 뒤 새 ATR로 이동하지 않음. 종가로 판단 |
| 청산 | 해당 상태의 확정 보유 전량만 예약. 일부 매도 후 취소되면 잔여 수량·원가 유지. 기존 수동/다른 전략 물량을 편입하는 API 없음 |
| 재진입 | 전량 청산 뒤 조건 해제를 기다림. 새로운 Python 프로세스에서 PG 상태를 읽어도 대기 유지. 해제 후 새 참 신호에서만 계획 생성 |
| 접수·불명·부분 체결 | 접수/UNKNOWN으로 보유를 늘리지 않음. 누적 체결 역행·초과·동일 누적량의 평균가 변경 거부. 미확인 주문을 새 예약으로 대체하지 않음 |
| 늦은 체결 확인 | 주문 결과 대기 중인 봉은 완료 사건으로 소비하지 않음. 체결 확인 뒤 같은 종가를 다시 처리해 손절 판단 누락 방지 |
| 중복·동시 실행 | 계좌 해시·사용자·장부·전략·판·종목별 PG 잠금. 상태와 사건을 같은 트랜잭션으로 저장. 5개 동시 호출에서 사건 1건, 동일 사건 입력 변경 거부, rollback 시 상태/사건 함께 취소 |
| 체결 구분 | `V2_VIRTUAL`의 다음 시가와 `V2_KIS_PROBE`의 장중 점검 상태를 분리. 가상 다음 시가에 장중 체결 시각을 넣으면 거부. 다음 거래일 자료 누락을 더 뒤의 시가로 대체하지 않음 |
| 조정 사건 | 신규 진입 보류. 보유 중 사건은 수량·원가·손절·익절 대조가 필요하다는 상태로 중단. 합의되지 않은 자동 보정을 구현했다고 표시하지 않음 |

`apply_event`는 서버 내부용이며, 호출자가 트랜잭션을 commit한 뒤 외부 전송해야 한다. 실제 주문 어댑터가 추가될 때는 공통 주문 관문·계좌 잔고/전략 귀속·미체결 대조와 연결하고, 증권사 확정 누적 체결만 전달해야 한다. 예약 성공 자체는 주문 전송·접수·체결이 아니다.

최종 검증: 외부 주문망과 분리된 PostgreSQL/Redis 시험에서 **402건 통과, 실패/건너뜀 0**. 판 2 신규 40건과 기존 공통 위험 관문·주문·전략 카드·웹훅·스냅샷·DB 단일 head 회귀를 포함한다. 원본은 `data/local-run/strategy-v2-20261029/final-tests.txt`에 보관한다.

## 실제 자료의 가상 재현

읽기 전용 수집 DB의 005930 자료로 2026-09-01~10-27을 재현했다. 준비 자료는 마지막 날까지 최근 730일이며, 매 판단에는 그날까지의 봉만 전달했다. 초기 자금 1,000만 원, 1회 예산 100만 원, 편도 슬리피지 10bp, 비용은 기존 `trading_cost` 모델을 사용했다.

- 37일 처리, 가상 체결 2건, 최종 보유 0주.
- 9/28 종가 진입 판단 → 9/29 09:00 가상 매수 3주, 원 시가에 슬리피지를 적용한 체결가 266,266원.
- 10/13 종가 손절 판단 → 10/14 09:00 가상 전량 매도 3주, 체결가 233,266.5원.
- 체결은 다음 시가를 따르므로 갭이 있으면 손절선·예상 위험을 넘을 수 있다. 별도 시험에서는 익절 종가 조건 뒤에도 다음 시가 갭으로 실제 재현 손익이 음수가 되는 사례를 확인했다.
- 입력 SHA-256: `c63d174cf01445de8934d3fc1f530058b9aaf37d114526b15453b40f649d4b62`.
- 카드 실행 계약 SHA-256: `c50053b437a4651cd59ed83883ba1b0d1b2a7ddfb5654fe21aa4c49c46ce69a7`.

이는 합성 입력만의 시험을 넘어 실제 자료로 실행 흐름을 확인한 결과이며, KIS 실제 체결·LEAN 판 2 성과 일치·기존 그림자 일지 판정 결과를 뜻하지 않는다. 원본 JSON은 git 제외 경로 `data/local-run/strategy-v2-20261029/replay-005930-20260901-20261027.json`에 보관했다.

## 마이그레이션·남은 작업

운영 백업을 복원한 격리 DB에서 `0029 → 0030 → 0029 → 0030`을 적용하고 기존 사용자 기록 보존을 확인했다. 새 표는 `strategy_runtimes`, `strategy_runtime_events`다. 실제 상태 기록이 생긴 뒤 downgrade하면 해당 상태/사건이 사라지므로, 운영 적용 후 오류는 기록을 보존한 상태에서 복원 또는 전진 수정을 판단한다.

오늘 남은 개발은 이 내부 모듈을 공통 위험 관문·전략 보유 대조·확정 체결 조회·기존 운영 실행 경로에 연결하는 일이다. 특히 실제 KIS 체결 시각이 응답에 없으면 주문 시각이나 조회 시각으로 채우지 않고 미확인으로 구분해야 한다. 판 2 자동 주문 차단 해제는 이 통합 검증 뒤의 작업이다.

10/29 오전 운영 조회에서는 최신 삼성전자 일봉이 10/27이고, 12:30 자료 갱신 전 상태였다. 오늘 필요한 10/28 봉이 확인되지 않아 실제 모의 주문을 보내지 않았다. 15:20 전 자료·유효 신호·귀속 보유 조건을 확인하고, 15:40에는 스냅샷 실행·사용자별 결과·DB 기록을 대조한다. 일정 등록이나 오늘 기록 0건을 실행 성공/실패로 미리 판정하지 않는다.
