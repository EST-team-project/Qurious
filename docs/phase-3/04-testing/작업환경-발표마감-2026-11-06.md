## 1. 작업환경 정리

- `.codex-work` 아래 완료된 Git 작업 사본 **25개**를 정리했다. 미커밋 파일·병합 여부를 먼저 확인했으며, 마지막 후속 문서는 현재 작업 브랜치에 보존한 뒤 동일한 변경임을 대조했다.
- 작업 브랜치는 삭제하지 않았다. 기존 변경 18파일은 stash와 별도 패치·파일 지문으로 보존했다. 검증 로그·암호화 백업·담당 외 수정 제안은 정리 대상에서 제외했다.
- 이 PC 전용 `.vscode/settings.json`에 `.codex-work`의 파일 감시·검색·Python 분석 제외와 Git 저장소 검색 제외를 적용했다. 이 설정 파일은 기존 Git 제외 규칙을 따른다.
- 기존 #583·#584의 main 병합을 확인하고 팀 문서 PR #586·#587까지 현재 작업 브랜치에 반영했다. 운영 컨테이너는 재배포하지 않았다.

작업 사본은 디스크의 파일이다. 열린 편집기·확장 기능·검색·파일 감시가 이를 읽을 때 CPU나 메모리 사용이 추가될 수 있다. 이번 정리는 그 대상을 줄인 조치이며 **CPU 100%와 WSL 단절의 원인을 확정하거나 재발 해결을 입증한 결과는 아니다.** VS Code 원격 로그의 연결 초기화 기록만으로도 원인은 확정할 수 없다.

자료 렌더링 전 Docker 상태를 한 번 조회했으나 Windows Docker API의 `dockerDesktopLinuxEngine` 파이프가 없다는 오류를 받았다. 명령은 Windows Docker Desktop의 `docker.exe`를 사용했으므로 Linux 소켓 권한 오류와 구분한다. 엔진 가동·복구는 미확인이다. 기존 운영 성공의 마지막 근거는 [10:05 최종 검증](전체회귀-2026-11-06.md#6-운영-반영후속-일정근거)이며 이 시점에 계속 실행 중이라고 주장하지 않는다.

## 2. 발표자료와 인수인계

[담당 자료 모음](../06-retrospective/오준영/README.md)의 HTML·대본·시연·검증 근거를 **v0.6**, [인수인계](../05-deployment/오준영-담당기능-인수인계.md)를 **v0.7**로 갱신했다. 직전 본문은 링크를 지난판 위치에 맞춰 보존했고 이전 PDF도 유지했다.

반영한 사실은 11/6의 KIS 모의 3종목 각 10주 매수·매도, 시험 잔량/미체결 0, 기존 삼성전자 1주 보존, 고유 4,481통과·2실패·3건너뜀, 담당 수정 관련 244통과, 체결 알림 중복 수정과 DB0044 운영 전환이다. 같은 시험을 중복 합산하지 않았고 이후 main 전체의 통과로 확대하지 않았다.

수수료 [#579](https://github.com/EST-team-project/Qurious/issues/579)는 ‘불일치 유지’ 결정 후 강민석 담당 후속이다. 이동원 담당 인코딩·공통 UI 시험 제안도 미적용 상태를 유지했다. 사람의 수신 확인·인수 실습·발표 시간 측정은 자동 시험으로 완료 처리하지 않았다.

## 3. 자료 검증

Docker 재시작·이미지 빌드 대신 기존 Windows Chrome으로 로컬 HTML만 열었다. 임시 브라우저 프로세스 묶음에 Windows Job 제한을 적용했다: **CPU 한 코어, 전체 CPU 5% 상한, 메모리 768MiB, 낮은 우선순위**. 생성한 브라우저만 종료하며 기존 사용자의 브라우저에는 손대지 않는다. 종료 후 Windows 프로세스 조회에서 해당 임시 프로필의 Chrome 잔여 0개를 확인했다.

| 검사 | 결과 |
|---|---|
| 6장 표시·가로/세로 넘침 | 6항목 통과 |
| 버튼·Home/End 이동 | 통과 |
| 900×650 창에 맞춤 | 통과 |
| PDF 출력 | 통과, 6쪽·162,497바이트 |
| JavaScript 예외 | 0건 |
| 변경한 4~6장 육안 검수 | 잘림 없이 수량·시험 건수·운영 시각 표시 |

총 **9개 자동 검사 통과**. 문서 이름·판 규칙과 동기화 대장 검사는 오류·경고 0이며 변경 문서·지난판의 상대 링크 481개도 모두 존재했다. 첫 렌더링의 작은 창 검사는 크기 변경 직후 옛 위치를 읽어 실패했다. 담당 일회용 검사기에 두 프레임 대기를 추가하고 같은 검사를 통과했다. 발표 HTML의 기능 결함으로 집계하지 않는다. 제품 전체 회귀·새 KIS 주문은 실행하지 않았다.

[PDF v0.6](../06-retrospective/오준영/내보내기/발표자료-v0.6.pdf)는 인터넷이나 앱 접속 없이 사용할 수 있다. 원본 렌더링 JSON·화면 PNG·소스 지문은 Git 제외 `.codex-work/today-closeout-20261106/exports/`에 보존한다.

## 4. 최종 영상과 대체 경로

`python3 tools/demo/export_mp4.py --phase 3 --check` 결과 발표용·사용법 **10편 모두 녹화 원본 없음**, 내보낼 것 0편이었다. 확인한 저장소·작업 경로에 최종 mp4·목록·포스터도 없다. [영상 README](../06-retrospective/videos/README.md)는 재촬영 후 11/11 동결 시 공유한다고 명시한다. 팀의 오준영 영상 제작 보고(발표용 47초·사용법 103초)와 이 PC의 재생 검수를 구분한다.

담당 YAML 두 편의 자막·동작 순서와 설명 범위는 대조했다. 실제 영상의 자막 노출 시간·화면/자막 일치·오프라인 재생은 파일 확보 후 확인해야 한다. 경로 확인을 사용자에게 요청했고 임의의 팀 메시지는 보내지 않았다.

발표 중 연결 장애가 나면 로컬 HTML/PDF의 흐름도와 날짜가 표시된 검증 표로 전환한다. [슬라이드 설명용 대체 MP4](../06-retrospective/오준영/내보내기/오프라인-설명영상-v0.6.mp4)도 완성했다. H.264·1280×800·108.42초·207,721바이트, 6장 각 약 18초이며 자막은 화면에 포함하고 음성은 없다. 실제 앱 조작 녹화와 별도라는 문구를 영상 내내 표시한다. 브라우저 실제 재생과 1초·55초·107초 탐색·화면을 확인했다. 첫 출력의 정지 화면 마지막 18초 누락은 프레임 요청을 명시해 보완하고 길이를 재검증했다. [파일 정보·지문](../06-retrospective/오준영/내보내기/오프라인-설명영상-v0.6.json)도 함께 보관한다.
