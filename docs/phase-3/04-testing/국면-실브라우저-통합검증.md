# 국면 배분–리밸런싱 실제 브라우저 통합 검증

2026-11-03 작성 · 11/4 보완, 오준영. 실제 앱 HTML/JS, 가입·로그인, HTTP API, PostgreSQL, Redis를 연결한다. API 응답을 대체하지 않는다. 외부 CDN 원본 JS만 로컬에서 제공한다.

## 실행 조건

- 운영과 분리된 Docker 내부 네트워크에 앱·PostgreSQL·Redis·Chromium을 둔다. 앱 호스트는 `qurious-regime-live-`로 시작하고 DB 이름은 `regime_live_test`여야 한다. 운영 계좌/키/웹훅을 복사하지 않고 시험용 키와 세션 비밀값을 생성한다.
- 앱의 전체 마이그레이션과 정상 시작을 확인한다. Celery worker/Beat는 실행하지 않는다. 수집 자료는 2026-11-02 HF `60241f8`의 SQLite 사본을 읽기 전용으로 연결한다. 이 시험은 이 스냅샷의 `down_high` 결과를 기준으로 작성됐다.
- 브라우저에 Playwright와 Chromium을 설치하고 `assets/tailwind.js`(3.4.17), `assets/apexcharts.js`(3.49.2) 원본을 준비한다. 나머지 외부 글꼴·아이콘 요청은 차단한다.
- 고정 스냅샷을 다른 날·오전에 재현할 때는 시험 앱을 `tests/e2e/regime_integration_clock.py`로 시작한다. 이 진입점은 배분·리밸런싱의 현재 시각 입력만 파일에서 읽으며, API·자료 준비 판정·계산 함수는 그대로 사용한다. DB 이름과 호스트가 위 시험용 주소가 아니면 시작을 거부한다. 운영 이미지에는 이 파일을 추가하지 않는다.

## 고정 자료의 시험 시각

11/4 오전에 기존 history 단계를 그대로 돌리면 `data_waiting`을 정상 반환하지만, 시험이 `regime_auto` 키를 무조건 읽어 `KeyError`로 끝났다. 11/2 일봉만 준비된 상태에서 11/4의 국면 변경 성공을 요구할 수 없다. 따라서 과거 자료의 재현과 현재 운영 자료 준비 관측을 구분한다.

시험 앱에 진입점과 기준 시각 파일을 임시 복사하고, 앱의 시작 명령을 다음과 같이 설정한다. `PYTHONPATH=/app`과 기존 격리 DB·Redis·시험 키 설정을 함께 사용한다.

```sh
python /tmp/regime_integration_clock.py --clock-file /tmp/regime-reference-time.txt
```

기준 시각 파일은 `2026-11-03T12:29:00+09:00`으로 시작한다. setup·persist·waiting을 끝낸 뒤 `2026-11-03T17:20:00+09:00`으로 바꾸고 history를 실행한다. 읽기 전용 수집 스냅샷과 준비 근거는 수정하지 않는다. 브라우저의 기본 예상 자료일/판정일은 각각 11/2·11/3이며, 다른 고정 스냅샷을 사용할 경우 `--expected-data-as-of`, `--expected-decision-date`와 목표 비중·국면 기대값도 함께 검토해야 한다.

## 순서

브라우저 컨테이너에서 같은 `results` 폴더를 사용한다. 기본 Chromium 경로는 `/usr/bin/chromium`이며 `--chromium`으로 변경할 수 있다.

```sh
python tests/e2e/regime_integration.py --base-url http://qurious-regime-live-test-app:8000 --phase setup --out results --assets assets
```

앱 컨테이너만 실제로 재시작하고 헬스와 DB/Redis 연결 복구를 기다린다. 전후 플랜·저장 배분·현금 해시와 주문 건수를 대조한다. 이어 브라우저에서 실행한다.

```sh
python tests/e2e/regime_integration.py --base-url http://qurious-regime-live-test-app:8000 --phase persist --out results --assets assets
```

12:30 이전의 대기 이유, 실행 버튼 차단, 반복 점검의 목표·이력·제안·완료 날짜 보존을 확인한다.

```sh
python tests/e2e/regime_integration.py --base-url http://qurious-regime-live-test-app:8000 --phase waiting --out results --assets assets
```

앱 컨테이너의 `/app`에서 아래 fixture를 실행한다. 시험 DB 이름을 확인한 뒤 시험 사용자 플랜의 과거 국면만 준비한다. 기존 API/계산 함수와 현재 수집 자료는 바꾸지 않는다.

```sh
PYTHONPATH=/app python tests/e2e/regime_integration_fixture.py
```

`tests`를 이미지에 포함하지 않는 환경에서는 파일을 임시 복사하고 `PYTHONPATH=/app python /tmp/regime_integration_fixture.py`로 실행한다. 기준 시각 파일을 위 17:20으로 바꾼 뒤 브라우저에서 마지막 단계를 실행한다. history는 자료 준비 상태와 자료일·판정일을 먼저 검사하므로 대기 응답을 국면 변경 성공으로 처리하지 않는다.

```sh
python tests/e2e/regime_integration.py --base-url http://qurious-regime-live-test-app:8000 --phase history --out results --assets assets
```

## 결과와 경계

| 단계 | 확인한 흐름 |
|---|---|
| setup (5) | 가입, 로그아웃/재로그인, 실제 자료 계산/PG 저장, 가져오기/명시적 활성화, 새로고침 보존 |
| persist (3) | 서버 재시작 보존, 두 화면 동시 편집 409/편집안·서버 보존, 편집 취소 후 최신 조회 |
| waiting (2) | 갱신 전 대기 표시/실행 차단, 반복 점검의 목표·이력·제안·완료 날짜 보존 |
| history (4) | 과거 상태→현재 국면의 목표 33%→15%/제안/이력, 일별 중복 방지, 해제 후 이력 보존, 다른 계정의 접근 분리 |

11/3에는 waiting을 제외한 세 단계 모두 `status=passed`, 브라우저 JS 오류 0이었다. 종료 시 시험 DB의 주문·증권사 주문·보유·자동 실행·국면 활성 플랜은 각각 0이고 변경 이력은 1건이다. 운영 계좌와 설정은 전후 동일하다. 서버 재시작은 정상 재시작이며 강제 장애 복구 시험은 아니다. 국면 전환은 과거 상태를 합성한 결과로서 운영의 자연 전환과 구분한다. 11/4부터의 고정 시각 재현도 당일 자연 운영 성공으로 집계하지 않는다.

최초 원본에서는 목표 저장이 외부 시세 조회에 의존해 400으로 실패했다. 수정 후 위 12개 흐름과 관련 pytest 282건을 통과했다. 로컬 증거는 Git 제외 `regime-live-evidence-20261103`에 보관한다. 쿠키가 든 `session.json`은 시험 컨테이너에만 두고 컨테이너 정리 때 삭제한다. 결과 JSON·로그·스크린샷에 인증/계좌 비밀값을 포함하지 않는다.

최종 배포 후보 `c8d89151`(#523 병합 기준)에서는 관련·변경 영향 회귀 **364건 통과·2건 건너뜀·실패 0건**을 확인했다. 건너뜀은 미지원 해외 매수 체결 시험 2건이다. 동일 후보 이미지로 빈 시험 DB부터 위 12개 브라우저 흐름과 앱 재시작을 다시 통과한 뒤 운영 Docker에 반영했다. app/worker/beat의 651파일 일치, HTTP 6경로와 17:15:41 heartbeat, 기존 설정·장부 보존을 확인했다. 배포 DB는 `0043_regime_targets`다.

11/4 보완 후에는 위 고정 시각으로 **14개 흐름을 모두 통과**했다. 운영 DB 주소·호스트, 호스트 누락, 시간대 없는 시각을 시험 진입점이 거부하는 4개 점검도 통과했다. 앱 재시작 전후 DB 보존과 종료 시 주문 0·자동 실행 0·이력 1건, 운영 설정·장부 보존을 다시 확인했다. 최초 11/4 실행의 `KeyError` 근거와 수정 후 결과는 각각 Git 제외 `regime-live-evidence-20261104`, `regime-live-evidence-20261104-fixed`에 보존한다. 당일 11/3 자료 수신이나 자연 국면 전환을 확인한 결과는 아니다.
