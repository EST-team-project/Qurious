## 장중 실행 순서

1. 앱·worker·beat 버전과 DB0042, 거래일 달력, KIS 모의 환경, 본인 계좌, 미확인/미체결 주문 0건, 기존 전략 1주와 시험 귀속 1주를 확인한다. 다른 값이면 주문 전에 중단한다.
2. 09:10경 **남은 시험용 1주만** 새 당일 지정가 매도로 낸다. 최신 시세·호가 단위를 확인한 가격과 당일 고유 요청 ID를 기록한다. 매수는 추가하지 않는다. 새 매도가 즉시 체결됐다면 종료하고 재주문 성공으로 세지 않는다.
3. 기존 `/api/quant/kis/orders/{id}/cancel`로 한 번 취소한다. 접수 응답만으로 완료 처리하지 않는다. 체결 조회에서 원 수량 1·체결 0·취소 확정 1·잔량 0을 확인한 새 부모 UUID를 사용한다. 불명확하면 중단하고 조회만 한다.
4. 부모 생성 후 30분이 지난 09:40경 아래 조회 명령을 실행한다. 허용 범위는 생성 후 30~43분이다. 날짜, 계좌, 전략, 1주, 취소 상태, 기존 위험 설정을 검사한다. 실제 재주문 함수가 다시 증권사 취소 증거·보유 귀속·시세·모든 공통 위험 관문을 확인한다.
5. 승인된 시험의 `--execute` 실행에서만 창을 15→45분으로 잠시 바꾼다. 독립 원복 감시기가 준비되지 않으면 설정을 바꾸지 않는다. 재주문 결과 직후 원복하며 120초 기한/실행기 종료 때도 원복을 시도한다. 원 지정가·1% 이탈 한도·30분 쿨다운은 유지한다.
6. 접수 번호 → KIS 체결 조회 → 앱 자식 주문 → 귀속 보유/실계좌 잔고를 대조한다. 최종 성공 기준은 자식 1건·1주 FILLED, 시험 귀속 0주, 기존 전략 1주 유지, 미체결 0건, 창 15분 원복이다. 접수 불명이나 미체결은 성공으로 기록하지 않는다. 미체결 자식은 기존 취소 경로로 한 번 취소하고 확정 조회한다. 추가 매도/매수·두 번째 재주문으로 정리하지 않는다.

Linux 앱 컨테이너의 `/app`에서 실행한다. UID/PARENT는 그날 확인한 본인 사용자/새 부모 UUID로 넣는다. 기본 동작은 조회이며 `--execute`가 없으면 설정·주문·시험 기록을 만들지 않는다.

```bash
python scripts/kis_recovery_trial.py retry --user-id "$TRIAL_UID" --parent-id "$TRIAL_PARENT"
python scripts/kis_recovery_trial.py retry --user-id "$TRIAL_UID" --parent-id "$TRIAL_PARENT" --execute
```

일반 주문 API와 동일한 멱등·한도 검사를 사용한다. 본 도구는 임의 주문을 보내는 우회 경로가 아니다. 오늘 수행한 테스트나 조회 명령은 내일의 주문 예약/실행을 의미하지 않는다.

## 종료·장애 복구

시험 기록은 Git 제외 영구 데이터 볼륨의 `data/local-run/kis-recovery-trials/<UID>-<PARENT>.json`에 0600으로 저장한다. 계좌번호·키·토큰은 넣지 않는다. **부모별 기록**이며 다른 날의 완료 파일로 현재 원복을 판단하지 않는다. 같은 사용자의 미원복 기록이 있으면 다음 시험을 차단한다.

- 조회 실패·가격 이탈·재주문 예외·90초 처리 제한: `finally`에서 창 원복.
- 실행기 SIGKILL: 독립 프로세스가 종료를 감지하여 원복만 수행. 감시기는 주문을 만들지 않는다.
- 컨테이너/호스트/DB 중단: 그동안 원복을 보장하지 않는다. 재기동 후 **다른 시험 전에** 아래 복구 명령을 실행하고 DB 설정과 기존 자식 주문을 확인한다. 자동매매는 계속 OFF로 둔다.
- 다른 위험 필드나 비상 정지 변경은 보존한다. 계좌 또는 창이 다른 값으로 바뀌었으면 임의 덮어쓰기 대신 수동 확인한다. 완료 기록의 반복 복구는 새 정책을 바꾸지 않는다.

```bash
python scripts/kis_recovery_trial.py restore --journal "$TRIAL_JOURNAL"
```
