## 1. 운영 결과

- 사용자가 **기존 주문 알림 Discord 채널 사용**을 선택했다. DB에서는 이름이 ‘오준영’인 사용자의 설정 한 건만 읽었다. 앱의 알림 설정·키·주문 장부는 변경하지 않았다.
- 웹훅은 평문 파일이나 명령행에 남기지 않고 표준입력으로 Windows Python에 전달해 **현재 사용자 DPAPI**로 저장했다. 앱의 암호화 키 파일이나 DB가 없어도 이 설정을 읽을 수 있다. 저장 폴더는 해당 Windows 사용자만 접근하도록 ACL을 설정했다.
- `[Qurious 호스트 경보 · 연결 시험]` 한 건을 발송했다. Discord의 메시지 생성 응답을 받았고 사용자가 **“확인했어”**라고 실제 수신을 확인했다. 주문 알림이 아닌 경보 경로 시험으로 표시했다.
- `Qurious-Credential-Watchdog` 예약 작업 등록 완료. **15:10:10 KST 첫 실행·종료 코드 0·initial_ok**, 이후 같은 정상 상태를 다시 검사했을 때 `suppressed`를 확인했다. 실행 제한은 90초, 중복 실행은 `IgnoreNew`다.
- 뒤이어 중지된 컨테이너의 옛 로그를 정상으로 오인하지 않도록 가동 상태 검사와 시험 2건을 추가했다. 보완본을 호스트에 복사한 뒤 실제 조회도 `ok·suppressed`였다.

## 2. 실행 구조와 한계

`Windows 작업 스케줄러 → Windows Python → Docker 가동 상태·최근 10분 로그 → 독립 Discord 경보` 순서다. 실행 파일과 설정은 Windows의 `%LOCALAPPDATA%\QuriousCredentialWatchdog`에 있어 WSL 폴더를 읽지 않는다.

| 조건 | 처리 |
|---|---|
| 최초 정상 | 알림 없이 상태 저장 |
| 앱·worker·beat의 `[CREDENTIAL_STORAGE]` | 암호화 오류 관측 경보 |
| Docker/컨테이너 부재·중지·조회 실패 | 정상으로 간주하지 않고 조회 실패 경보 |
| 같은 장애 지속 | 반복 억제, 1시간마다 지속 알림 |
| 서비스별 상태 변경 | 새 상태 알림 |
| 로그 감시 정상화 | 정상화 알림 한 번. ‘최근 로그 조회 성공·오류 미관측’이며 키 복호화 기능 자체의 복구 확인과 구분 |
| Discord 전달 실패 | 성공 상태를 기록하지 않고 다음 예약 회차에서 재시도. URL·예외 원문은 출력하지 않음 |

- 5분 간격이며 Windows 사용자 로그인 중 실행한다. 로그아웃·절전 중의 24시간 감시를 보장하지 않는다. 실행 시각을 놓치면 가능한 다음 시점에 시작한다.
- 가동 상태 조회는 최대 10초, 서비스별 로그 조회는 최대 15초, Discord 요청은 최대 10초다. 로그는 서비스별 최대 5,000줄로 제한하며 상한에 닿으면 ‘정상’으로 판정하지 않는다.
- 메시지에는 서비스 이름과 분류만 포함한다. 로그 원문·토큰·계좌·키는 보내지 않는다. 리디렉션과 자동 멘션을 허용하지 않는다.
- 중복 억제는 성공 응답과 상태 파일 저장에 의존한다. 전송 응답 유실·상태 저장 실패까지 정확히 한 번 전달을 보장하는 구조는 아니다.
- **운영 키를 실제로 훼손하는 장애 시험은 하지 않았다.** 오류/정상화 분기는 단위 시험, 실제 전달 경로는 표시된 연결 시험과 사용자 수신 확인으로 검증했다.

## 3. 설치·점검·해제

구현은 [감시 도구](../../../scripts/credential_watchdog.py), [Windows 설치 도구](../../../scripts/install_credential_watchdog.ps1), 기존 [로그 검사](../../../scripts/check_credential_storage_logs.py)다. 저장소 루트에서 PowerShell로 실행한다.

```powershell
# 호스트 폴더 준비. 기존 예약 작업·설정은 삭제하지 않는다.
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install_credential_watchdog.ps1 -PrepareOnly

# 새 PC 최초 설정: 웹훅을 화면에 보이지 않게 입력하고 표준입력으로 전달한다.
$watchDir = Join-Path $env:LOCALAPPDATA 'QuriousCredentialWatchdog'
$watchSecret = Read-Host '기존 개인 Discord 웹훅' -AsSecureString
$watchPointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($watchSecret)
try {
    [Runtime.InteropServices.Marshal]::PtrToStringBSTR($watchPointer) |
        python (Join-Path $watchDir 'credential_watchdog.py') --config (Join-Path $watchDir 'config.json') --configure
} finally {
    [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($watchPointer)
}

# 실제 설정을 저장한 뒤 등록한다. Python 경로가 여럿이면 -PythonPath로 지정한다.
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install_credential_watchdog.ps1
Get-ScheduledTaskInfo -TaskName 'Qurious-Credential-Watchdog'
Get-Content (Join-Path $watchDir 'last-run.json')

# 일시 중지 / 재개
Disable-ScheduledTask -TaskName 'Qurious-Credential-Watchdog'
Enable-ScheduledTask -TaskName 'Qurious-Credential-Watchdog'

# 작업 제거: 보호된 설정·실행 결과는 보존한다.
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install_credential_watchdog.ps1 -RemoveTask
```

`config.json`은 덮어쓰지 않는다. 웹훅 교체 때는 작업을 잠시 중지하고 기존 보호 설정을 별도 보존한 뒤 새 설정·표시된 연결 시험·재등록을 진행한다. 앱에서 웹훅을 바꿨다고 호스트 설정까지 자동으로 바뀌지 않는다. 다른 Windows 사용자나 새 PC에서는 DPAPI 파일 복사만으로 복호화할 수 없으므로 새로 설정해야 한다. 인수자의 새 PC 실습은 아직 별도 잔여다.

## 4. 담당 요청 처리

- **#586 점수:** `kis-results`를 UI 18·서버 26·연동 20·시험 20 = **84, 핵심 검증**으로 검토했다. UI는 11/5 실제 주문 16건 화면의 필터·새로고침, 연동은 11/6 모의 3종목 각 10주 매수/매도 6건의 KIS 직접 조회·API·화면 일치를 근거로 각각 +2·+5를 반영했다. 상태 열 개·CSV·페이지·390px·오류 흐름 전체의 실제 브라우저 검증과 외부 장애 자동 회귀는 남긴다. `settings`는 새 경보 근거만 추가하고 **63점 유지**다.
- **#586 시험:** `TC-SV2CA` 8사례를 P02-⑤-2/3, `TC-CSL` 4사례를 P02-⑤-3에 연결했다. 신규 `TC-CWD` 19사례도 P02-⑤-3에 연결했다. 대장·RTM·테스트 계획서의 담당 행에 반영했으며 일부 검증을 뜻하는 🟡를 유지한다.
- **#589 표 검토:** `broker_cancel_requests`의 주문 삭제 CASCADE, `rebalance_target_changes`의 사용자/계획 삭제 CASCADE, `execution_risk_stops`의 사용자 삭제 CASCADE를 모델에서 대조했다. ‘보존기간 정하지 않음·사용자 비공개’ 기록을 유지하는 것으로 검토했다. 삭제 연쇄가 보존기간 정책을 새로 정한 것은 아니다. 강민석 담당 표는 변경하지 않았다.

## 5. 검증 범위

담당 관련 단위 시험의 최종 고유 범위는 **61건 통과**다. 경보 19·기존 로그 검사 4·배지 6·RTM/문서 도구 31·UTF-8 진입점 검사 1건으로 구성된다. 기존 공통 앱 fixture와 플러그인 자동 로드를 제외한 파일/단위 검사라 asyncio 설정 안내 경고 2개가 있었으며 제품 실패는 아니다.

전체 수집은 완료로 표시하지 않는다. Windows 보충 환경은 bs4·jose·scipy 등의 의존성 부족으로 68개 파일 수집 오류가 났고, 그 실행에서 TC-SV2CA 8·TC-CSL 4는 수집됐다. 기존 Docker 이미지의 제한된 수집 환경은 WSL 폴더 연결 실패와 소스 전달 중 통신 시간 초과로 완료하지 못했다. 해당 임시 컨테이너와 소스 전달 사본은 정리했다. 현재 전체 건수는 미확정이며 과거 전체 실행 성적을 바꾸지 않는다.

원격 [#594](https://github.com/EST-team-project/Qurious/pull/594)는 이동원 담당 ERR-045·046 수정이 병합됐고 작성자가 인코딩 18건 및 실제 화면 검증을 보고했다. [#579 후속](https://github.com/EST-team-project/Qurious/issues/579#issuecomment-6677885008)은 강민석 담당 수수료 계약 시험 8건 통과를 보고했다. 이번 61건을 프로젝트 전체 회귀나 이 두 담당자의 모든 실행 검증으로 확대하지 않는다.

비공개 실행 근거는 `.codex-work/own-followup-20261106/`에 보관한다. 공개 문서·PR에는 비밀 설정과 원문 로그를 포함하지 않는다.
