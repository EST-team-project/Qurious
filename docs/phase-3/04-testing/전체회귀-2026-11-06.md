## 2. 실제 앱·브라우저 확장 검사

- 합성 API를 이용한 실제 Chromium 시나리오 15개 통과.
- 실제 앱·PG·Redis의 국면 배분 저장, 재시작, 편집 충돌, 일별 중복, 사용자 격리와 담당 화면 19항목 통과. 이 시험만 기준 시각을 11/5, 수집일을 11/4로 맞추고 과거 국면을 합성했다. 자연 회차 관측으로 세지 않는다.
- 실제 Beat·worker·Redis·PG·로컬 HTTP 알림 5시나리오 통과: 중복 회차, 실패 전달 성공/실패, SIGKILL 후 복구, 새 작업 실행. 외부 알림·증권사 주문은 없는 별도 환경이다.
- 실제 가입·로그인·로그아웃·첫 화면 이동 6항목 통과.
- 공통 화면 스모크·메뉴 폭·학습 시험 3개는 통합 전 구조를 기대하여 원본 실행에 실패했다. 이동원 담당이라 현재 소스를 수정하지 않는다.
- 분리 보관한 제안으로는 스모크 77화면·문제/JS 오류 0, 메뉴 폭 12곳·추가 폭 83곳·모델 비교 3곳·키보드·아바타 및 학습 동선 검사가 통과했다. **제안 검증 결과이며 최종 적용 소스의 통과로 세지 않는다.**
- 도움말 창은 390/768/1280/1920 폭과 관제 화면 33초 갱신 검사까지 통과.
- 영상 재생·영상 목록 시험 2개는 영상 표와 실제 영상이 없는 환경이어서 완료하지 못했다. 빈 영상 환경의 도움말 검사는 위 결과에 포함한다.

보관용 `rag-lab` 사본도 별도로 시도했으나 6통과·11실패였다. 반입 안내에 명시된 배포 파일 제외와 본 앱과 같은 패키지 이름의 충돌이 원인이다. 이 폴더는 실행 앱이 아닌 원본 보관 사본이며 수정하지 않았다. 이 시도를 본 앱 pytest 4,486건에 섞거나 전체 통과로 표시하지 않는다.

## 3. 홈페이지 진단과 종목 선정

운영 홈페이지에서 일회용 시험 계정으로 일곱 질문의 가운데 선택지를 골랐다. **21/35점·위험중립형**, 기간 3년·성향 기반 배분으로 계산했다. 이는 사용자의 실제 투자 성향을 대신 기록한 결과가 아니다. 계산용 금액 5,000만원은 홈페이지 배분 표시 입력이며 주문 예산 제한으로 사용하지 않았다.

화면 추천 목록 상위 3개인 하나금융지주·S-Oil·삼성에스디에스를 각 10주씩 선택했다. 모델 기준일은 11/4이고 세 종목의 모델 판단은 품질 기준 미달로 `관망`이었다. 종목 선택은 요청한 모의 주문 기능 검증용이며, 이 모델을 수익성 검증 완료로 판단하지 않는다. 시험 계정·배분 저장본·세션은 삭제했고 사용자의 기존 성향·배분 설정은 보존했다.

## 5. 발견한 문제와 담당 확인

1. **오준영 · 체결 알림 중복(ERR-044):** 삼성에스디에스 매수 체결은 10주 한 건인데 09:43:14·09:43:16에 동일 알림이 두 번 전달됐다. 정기 체결 확인과 시험용 직접 확인이 겹쳤고 기존 알림에는 주문 식별자 선점이 없었다. 두 경로가 같은 `client_order_id`로 `order_fill` 사건을 선점하도록 수정했다. 실제 PG 동시 호출·재확인·전달 실패·같은 종목의 다른 주문을 검증했다. 주문 중복은 없었다. 공통 알림 파일의 변경도 증권사 체결 알림 함수에 한정하며 P02-⑤-1~3의 주문 추적·운영 알림 담당 범위로 확인했다.
2. **이동원 · 키 교체 도구 인코딩(ERR-045):** `rotate_notification_credentials.py`의 줄표와 UTF-8 초기화 누락이 기존 콘솔 검사에 걸린다. 담당 확인 전 수정·22건 통과·첫 운영 반영까지 진행했으나, 사용자 지시 후 제안 패치를 보관하고 소스와 운영 적용에서 제외했다. 알림 암호화 구현 #576은 유지한다.
3. **이동원 · 공통 화면 시험(ERR-046):** 스모크·메뉴·학습 시험의 옛 기대값은 [담당 검토 초안](../../common/00-management/github-archive/2026-11-06/이슈-인코딩-공통화면시험-이동원/00-본문.md)에 보관하고 원본을 유지한다.
4. **오준영 · 운영 시험 수신기(ERR-047):** 로컬 Slack URL이 제품 주소 검증에 거절됐다. 제품 검증은 유지하면서 시험용 주소의 전송만 로컬 HTTP 수신기로 연결했다. 실제 worker·Beat의 성공/실패 HTTP 응답과 재시작 등 5시나리오를 재확인했다.

담당 근거는 [요구 대장](../01-analysis/requirements/대장/요구-대장.tsv)의 P02-④-1~3(강민석), P02-⑤-1~3(오준영)과 해당 파일의 구현·시험 변경 이력이다. 앞으로 발견하는 오류도 담당을 먼저 확인하고 오준영 담당만 수정한다. 초안은 GitHub에 게시하지 않았다.

접수 알림 6건과 체결 알림 7건의 전달 성공 기록을 확인했다. 체결 알림 7건 중 1건은 위 중복이다. 수신자가 직접 읽었다는 확인과 상시 경보 연결 완료를 의미하지 않는다.

## 6. 운영 반영·후속 일정·근거

첫 수정 이미지 `qurious-app:paper-fill-dedupe-20261106`는 09:56에 반영됐고, 담당 범위를 정리한 최종 이미지 `qurious-app:paper-fill-dedupe-owned-20261106`로 교체했다. 기존 DB0044를 유지하며 키 교체 도구의 담당 외 수정만 제외했다. 암호화 백업 생성·원문 일치 검증 후 app·worker·beat를 전환했고 각각 712파일 일치, HTTP 11경로 성공, **10:05:40 KST 새 heartbeat**, 인증 키·환경·위험 설정·주문·장부 보존과 암호화 오류 로그 0건을 확인했다. 추가 모의 주문은 보내지 않았다.

11/6은 팀 자료·영상 대조와 사람의 발표 연습, 11/9~10은 리허설·피드백 반영, 11/11은 최종 리허설·영상 동결, 11/12 오전은 발표 일정이다. 주말 작업은 배정하지 않았다. 수수료 시험 계약 정합화·인코딩·공통 화면 시험, 검색 색인·해외 비용 모델, 실제 영상 재생과 상시 경보 연결은 완료로 처리하지 않는다.

원본 로그·JUnit·환경별 고유 집계·진단 화면·주문 저널·체결 결과 화면·초기 실패·수정 후 결과·암호화 백업은 Git 제외 `.codex-work/final-validation-20261106/`에 보존한다. 주문번호·계좌 식별자·인증 키·세션은 이 문서에 싣지 않는다. GitHub push·PR·팀 댓글은 수행하지 않았다.

### 11/6 오후 최신 main·Docker 반영 후속

main `8b97486c`(#597 포함)과 오준영 위험 표시 수정으로 앱·worker·beat를 갱신했다. 변경 관련 **고유 145사례 통과**(최종 알림 19·나머지 서버/운영 67·Node 화면 53·배지 6), Windows cp949의 같은 화면 3사례도 별도 통과했다. 전수 회귀의 재실행 수가 아니며 위 원래 결과를 소급 수정하지 않는다. #594 UTF-8 도구가 실제 이미지에 포함됐고 #597 카카오 키 마스킹도 반영했다. 운영 보존·화면 검증 범위와 잔여 일정은 [작업 계획 §61](../00-management/plans/오준영파트-할일.md), 신규 ERR-048·049는 [누적 오류 기록](오준영-오류수정기록.md)을 따른다.
