## 요약

릴리스는 아직 태그를 붙이지 않고, **main 에 머지된 날짜**를 릴리스 이름으로 쓴다(제안 · 1절). 2차가 시작된 10-01 부터 사흘 동안 사용자가 볼 수 있는 큰 변화는 투자 대시보드(로그인 첫 화면), 용어사전 화면과 모든 화면의 용어 설명, 데이터 관제와 금융 일정 화면, 법령 근거 찾기 API, 모의계좌 성과 지표다. 증권사 모의 키는 사용자마다 따로 쓰게 바뀌었다.

## 1. 읽는 법

- 한 릴리스 = 그날 main 에 머지된 PR 묶음이다. 태그 · 판 번호(예: 0.2.0)를 붙일지는 팀이 정한다.
- 갈래는 넷이다 — **추가**(새 기능) · **변경**(있던 기능의 동작) · **수정**(결함) · **보안**. 문서만 바뀐 PR 은 「문서」 한 줄로 모았다.
- 줄 끝 괄호는 PR 번호, `DF-NN` 은 결함대장 번호다.

날짜별로 머지된 PR 수는 <그림 1> 과 같다.

**DB 구조 — 올리는 순서 주의**
- 알림 비밀 암호화 `0044_notification_secrets`(#576 · 11-05 머지)와 Paper↔KIS 대사 `0044_paper_kis_reconciliations` · `0045_paper_kis_track`(#602 · 11-06 머지)이 모두 `0043` 에서 갈라져 head 가 둘이 되어 `alembic upgrade head` 가 `Multiple head revisions` 로 실패했다(안내 이슈 #603).
- 병합 리비전 `0046_merge_notif_paper_kis` 로 하나로 이었다(스키마 변경 없음 · #604).
- 이미 `0044_notification_secrets` 까지 전환한 운영 DB 는 새 이미지로 `alembic upgrade head` 를 돌리면 대사 표 두 리비전이 적용된 뒤 0046 이 기록된다(일회용 PG 재현 11-09). **운영 DB 는 11-09 에 오준영 님이 이 순서로 `0046` 까지 전환을 마쳤다**(기존 64표 보존 · 앱·worker·beat 정상). 순서와 확인 방법은 [알림 비밀값 암호화 운영](알림-비밀값-암호화-운영.md) 의 「0046 병합」.

**고침**
- 100일 백테스트 카드 안내의 맞지 않는 「(회차 +1)」 두 곳 삭제(#559 · `paper.js` · #604).

> **10-28 ~ 11-06 (v0.22 · 기계 초안)** — 머지 커밋의 PR 제목을 날짜별로 옮겼고 갈래는 제목 머리말로 나눴다(feat · refactor · perf → 추가 · 변경 / fix → 수정 / docs · chore → 문서 · 기타 / test → 시험 · 머리말이 없으면 낱말로 가름). 제목이 영어이거나 병합 메시지뿐인 줄은 그대로 두었다. 같은 일을 하는 PR 여럿을 묶고 쉬운 말로 다듬는 일은 아직 하지 않았다.
