## 1. 결과와 범위

실제 `public/app.html`·`public/js/rebalance.js`를 Chrome으로 실행했다. `tests/test_rebalance_screen.py` **1건 통과**, 그 안의 브라우저 검사 **17항목 통과**, 건너뜀 없음이다. 시험-요구 대장의 TC-RBUI를 U2·U5에 연결했다. 기존 U5 비고의 「지금 없음」도 실제 구현·시험 근거로 교체했다.

API는 합성 응답으로 대체하고 외부 API 연결을 차단했다. 표·이력·버튼은 실제 DOM으로 검증한다. 차트는 ApexCharts 입력을 기록하는 어댑터로 현재·목표 계열과 범주를 확인했으며, 외부 차트 라이브러리의 SVG 렌더링·배치·사용성 평가는 포함하지 않는다. 운영 계정·플랜·현금·주문을 변경하지 않았다.

「시험 있음」은 이 범위의 재현 가능한 시험이 있다는 뜻이다. 전체 #170의 진행률, 모든 인수 기준 충족, 운영 러너의 실자료 정산 완료를 뜻하지 않는다.

단계별 결과는 실행 산출물 `browser-result.json`, `browser-dom.html`, pytest JUnit XML에 남는다. 각 파일은 임시 실행 경로에 보관하며 계정 비밀정보를 포함하지 않는다.

## 3. 재현

Python의 pytest와 Chrome이 필요하다. 일반 시험 환경에서 Chrome 경로·격리 프로필을 지정하지 않으면 이 시험은 건너뛰며, 화면을 검증한 것으로 세지 않는다.

Linux Chrome 예:

```bash
QURIOUS_TEST_CHROME=/usr/bin/google-chrome \
QURIOUS_TEST_CHROME_PROFILE=/tmp/qurious-rb-ui-profile \
python -m pytest tests/test_rebalance_screen.py
```

독립된 pytest 환경에서는 `--noconftest`로 저장소의 DB·수치 라이브러리 공통 고정물 없이 브라우저 시험만 실행할 수 있다. 이 시험은 공통 고정물에 의존하지 않는다.

WSL에서 Windows Chrome을 호출하면 `QURIOUS_TEST_CHROME`은 Windows Chrome 실행 파일의 `/mnt/c/.../chrome.exe` 경로, `QURIOUS_TEST_CHROME_PROFILE`은 **Windows 임시 경로**를 지정한다. Windows에서 WSL localhost 전달이 되지 않으면 `QURIOUS_TEST_BROWSER_HOST`에 현재 WSL IP를 지정한다. 실제 실행에서는 새 격리 프로필을 사용했다.

브라우저 CLI를 직접 실행할 수도 있다.

```bash
python tests/e2e/rebalance_portfolio.py \
  --chrome /usr/bin/google-chrome \
  --profile /tmp/qurious-rb-ui-profile \
  --out /tmp/qurious-rb-ui-evidence
```

## 4. 운영 확인과 남은 범위

2026-10-19 확인 시점에 배포 앱의 `rebalance_daily.readiness()`는 `ready=false`, `state=before_update`, 「12:30 데이터 갱신 이후 자동 점검합니다.」를 반환했다. 당시 `data_as_of`·`update_finished_at`은 없었다. 이 값은 그 시점의 준비 상태이며 운영 장애나 이후 회차 결과로 확대 해석하지 않는다.

운영 러너가 만든 회차 기록과 실제 수집 자료를 이용한 갱신 후 자동 점검·정산 대조는 별도로 확인해야 한다. 스트레스 검증의 손실·성과 보고, 제안요청서의 신규 모델, #196·#244의 3차 범위 결정도 이 화면 시험에 포함하지 않았다. #170은 열린 상태로 유지한다.
