# KIS 주문 방식 표시 검증 (#211)

기준 main `7073cd2`, 브랜치 `fix/kis-mode-labels-211`. #212와 별도 PR이다.

## 변경 결과

기존 `mode=live`, `paper=false` 설정도 실제 주문 환경이 `paper`이면 「KIS 모의투자(Testbed)로 주문」으로 표시한다. 앱 가상매매와 KIS 계좌 주문을 구분하며, 주문 환경을 확인하지 못한 경우 증권사 주문 선택·저장을 보류한다. 실거래 승인 관문과 주문·저장 로직은 변경하지 않았다.

- 설정: 투자 모드 → 자동매매 주문 방식. 선택칸·설명·저장 확인창이 같은 환경을 표시한다.
- 중복 모의투자 체크박스를 숨겼다. 기존 직접매매 설정 코드가 읽는 호환값은 유지한다.
- 대시보드: 내부 값 `live` 대신 KIS 모의/실전 환경을 표시한다. 승인된 실전 경로를 모의투자 실행 중이라고 표시하지 않는다.
- 계좌 탭의 이름·사이트도 실제 환경에 맞춘다.
- 의사결정 설명: 가상 주문만 실행한다고 단정하지 않고, 설정한 방식으로 주문하고 결과를 확인한다고 설명한다.

## 검증

Python 관련 회귀시험 **121개 통과, 실패·건너뜀 0**. KIS 설정·원클릭·대시보드·자격증명·실거래 차단·메뉴·자동매매 사이클·배치 상태를 포함했다. 신규 11개 시험은 직접/게이트웨이 × 승인 여부 × 자동매매 모드, 원클릭 후 설정 재조회, 실전 계좌 탭 이름을 검증한다.

실제 Chrome에서 **13항목 통과**. 저장소의 실제 `app.html`, `settings.js`, `dashboard.js`, 공통 모듈을 실행하고 API 응답만 합성했다. 기존 설정 표시, 체크박스 숨김, 대시보드 표시, 모드 전환 설명, 저장 요청의 기존 mode 값, 전환 확인창, 승인된 실전 표시, 미확인 환경 선택·저장 차단을 확인했다. CSP로 외부 연결을 차단했으며 실제 계좌와 주문은 사용하지 않았다.

재현:

```sh
python tests/e2e/kis_modes.py --chrome /path/to/chrome --profile /tmp/kis-mode-profile --out /tmp/kis-mode-evidence
```

WSL에서 Windows Chrome을 사용할 때 `--profile`에는 Windows 임시 경로를 지정한다. 기본 로컬 포트는 18961이며 `--port`로 변경할 수 있다. 임의 포트는 이 환경의 Windows→WSL 전달에서 연결 거부되어 연결 가능한 포트를 명시하도록 했다. 합성 응답 시험이므로 로그인·운영 자격증명이 필요 없다.

API 문서·카탈로그 일치와 문서 규칙을 확인했다. 전체 RTM 재생성은 하지 않고 관련 시험 건수만 갱신했다. 실행 중인 앱에는 배포하지 않았다.
