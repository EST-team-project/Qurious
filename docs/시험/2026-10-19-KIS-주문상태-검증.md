# KIS 주문 상태·가상 장부 분리 검증 (#212)

기준: main `9bea3ee`, 작업 브랜치 `fix/kis-order-status-212`. 실제 서비스 배포·외부 주문 없이 검증했다.

## 결과

KIS 연동 모드는 주문 성공 여부와 무관하게 QUANT 가상 현금·보유·주문을 변경하지 않는다. 매수·매도 판단은 KIS 잔고를 사용하고, 잔고를 읽지 못하면 주문을 보류한다. 앱 가상매매는 기존 가상 장부만 사용한다.

화면·의사결정 로그에서 가상 체결, 증권사 접수, 일부/전량 체결, 실패, 접수 여부 미확인을 구분한다. 직접 KIS 주문도 전송 전에 추적 기록을 저장한다. 과거 가상 체결 기록은 그대로 두되 KIS 체결 증거로 취급하지 않는다. 토큰은 Redis에서 환경·키별로 공유하고 만료·동시 발급을 관리한다.

## 자동 검증

- 관련 Python 회귀시험 **258개 통과, 실패·건너뜀 0**. 자동매매 사이클, KIS 직접/게이트웨이 주문, 사용자 분리, 위험 한도, 재주문, 연결 설정, 원클릭 시작, 배치, 모니터링, 정합성 점검을 포함한다.
- 실제 JS 렌더러 시험 **1개 통과**(Windows Node). 실패·미확인 표시, 요청 수량과 확인된 체결 수량의 분리, 과거 가상 기록 및 HTML 이스케이프를 확인했다. 전체 브라우저 시나리오 시험을 의미하지 않는다.
- 격리 PostgreSQL에서 매수/매도 × 접수/거절/응답 불명 6개 조합을 실행했다. KIS 주문 뒤 QUANT 현금·보유·가상 주문 불변, `live_orders` 상태, 접수 후 별도 체결 조회·체결 알림을 검증했다.
- 격리 Redis에서 동시 8개 호출과 별도 Python 프로세스가 같은 토큰을 재사용하는지 확인했다. KIS HTTP는 시험 대역으로 대체했다.
- 토큰 403 뒤 주문 미전송·즉시 재발급 억제, 만료 갱신, Redis 장애, 전송 후 타임아웃·잘못된 JSON·결과 코드 누락을 검증했다. 응답 불명은 자동 재주문하지 않는다.
- 체결 조회는 계좌·주문일·주문번호·종목·방향·주문 수량을 대조한다. 잔고 변화에 따른 추정, 초과 수량, 불완전한 가격으로는 체결 확정·알림을 하지 않는다.

재현: `tests/test_kis_execution_outcomes.py`는 일회용 DB에 `QURIOUS_TEST_DATABASE_URL`, 일회용 Redis에 `QURIOUS_TEST_REDIS_URL`을 지정한다. `tests/test_trade_status_screen.py`는 Node 또는 `QURIOUS_NODE_EXECUTABLE`이 필요하다. 운영 DB를 시험용으로 지정하지 않는다.

## 실제 계좌 연결 확인

2026-10-19 로컬 Qurious(`http://localhost:8966`)는 HTTP 200으로 응답했다. 최초 확인 때는 사용자 API 설정이 없었으나, 이후 사용자가 모의투자용 자격증명을 등록하여 실제 연결을 검증했다.

**실제 KIS 모의계좌 인증·잔고 조회에 성공했다.** 실행 중인 앱 컨테이너의 `KISClient(paper=True)`와 해당 계정에 저장된 키를 사용했다. 사용자 제공 계좌와 저장된 계좌가 일치하는 설정 하나만 선택했다.

- KIS 모의 서버 `POST /oauth2/tokenP`: HTTP 200.
- `GET /uapi/domestic-stock/v1/trading/inquire-balance`: HTTP 200, `rt_cd=0`, `msg_cd=20310000`.
- 검증 요청은 위 두 경로만 허용했다. 주문 요청 0건, 자동매매 활성화·설정 변경 없음.
- API 키·계좌번호는 출력하지 않았으며, 계좌의 자산 금액은 이 공개 검증 기록에 싣지 않는다.

이는 현재 실행 중인 앱의 실제 인증·잔고 조회 확인이다. PR 코드를 실행 환경에 배포한 검증이나 실제 주문 접수·체결 검증을 의미하지 않는다. PR의 주문 상태·토큰 공유 로직은 위 격리 시험으로 검증했다.

## 운영상 범위

- 기존 가상 기록은 삭제·역분개하지 않는다. 현재 KIS 보유와 가상 장부는 독립적이며, 이전 허위 성공 기록은 화면에서 별도로 표시한다.
- 직접 경로의 주문번호 없는 미확인 주문 및 미체결 취소는 KIS 내역에서 수동 확인한다. 게이트웨이 재전송·취소 경로로 넘기지 않는다.
- 토큰 공유용 Redis가 필요하다. Redis 장애 때 인증 발급을 우회하지 않는다.
- KIS 연동 모드의 잔고 확인은 KIS를 지원한다. 다른 증권사로 설정한 연동 모드는 주문을 보류한다.
- 이 변경에는 DB 스키마 마이그레이션이 없다. 기존 `live_orders`에 직접 경로를 구분하는 값과 계좌 해시를 저장한다.
- PR 작성 단계이며 실행 중인 앱에는 배포하지 않았다.
