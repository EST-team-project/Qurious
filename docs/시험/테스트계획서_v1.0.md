## 1. 목적과 범위

### 1.1 이 문서가 하는 일

「무엇을, 어떤 기준으로, 누가 판정하는가」를 못박는다.
지금까지 이 저장소에는 **자동화 시험이 한 건도 없었다**(2026-09-21 이전 `tests/` 부재).
검증은 사람이 화면을 보고 "되는 것 같다"고 말하는 방식이었고, 그 방식은
S38~S39 에서 두 번 실패했다 — 요율이 화면마다 달랐고(#45), 업로드가 4시간 반 조용히 막혔다(#53).

## 2. 시험 전략 — 3계층

```
        ┌──────────────────────────────────────────────┐
  느림  │  인수시험 (Acceptance)                        │   6건
   ↑    │  "발주 요구사항을 지키는가"                    │   → 요구사항이 근거
        │  예: 실거래는 승인 없이 나가지 않는다           │
        ├──────────────────────────────────────────────┤
        │  봉인시험 (Characterization)                  │   2건
        │  "나쁜 상태가 더 나빠지지 않는가"              │   → 실측값이 근거
        │  예: 야후 참조가 72줄보다 늘지 않는다           │
        ├──────────────────────────────────────────────┤
   ↓    │  단위시험 (Unit)                              │  15건
  빠름  │  "함수가 약속대로 도는가"                      │   → 명세가 근거
        │  예: "on" 은 참, "아니오" 는 거짓              │
        └──────────────────────────────────────────────┘
```

> **봉인시험**(characterization test) — 「지금 이런 상태다」를 *그대로 찍어 고정하는* 시험이다.
> 옳은 상태를 검사하는 게 아니라 **변화를 감지**하는 데 목적이 있다.
> 당장 고칠 수 없는 부채가 **더 늘어나지 않게** 울타리를 치는 용도라, 부채를 갚으면
> 시험도 함께 낮춰 준다. 헷갈리기 쉬운 점: 이 시험이 통과한다고 코드가 좋은 게 아니다.
> **나빠지지 않았다**는 뜻일 뿐이다.

### 2.1 판정 원칙 (#62 규칙 3)

- **자기 판정 금지.** 시험을 만든 사람이 "통과했다"고 선언하는 것으로 끝내지 않는다.
  시험 밖에서 한 번 더 실행해 대조표를 남긴다(ADR-0001 §4.3).
- **조용한 성공을 의심한다.** 차단·검증이 **아무 소리도 내지 않고** 통과하면,
  기능이 도는 게 아니라 기능이 죽어 있을 수 있다. 그래서 「승인하면 열린다」는 쪽도
  반드시 짝으로 시험한다.
- **환경 오염을 막는다.** 개발자 셸에 `QURIOUS_ALLOW_LIVE_TRADING=1` 이 남아 있으면
  차단 시험이 거짓 통과한다. `tests/conftest.py` 가 매 시험마다 이 변수를 지운다.

**TC-LT-06 이 왜 있는가** — 차단이 과하면 모의투자까지 죽는다.
"막혔다"와 "기능이 죽었다"를 구분하는 시험이다.

**TC-LT-03 의 `"2"` `"아니오"`** — 애매한 값을 **참으로 읽지 않는다**는 확인이다.
`bool("2") == True` 라서 순진하게 짜면 여기서 뚫린다.

### 4.1 개발 중 실제로 잡아낸 것

시험을 짠 뒤 처음 돌렸을 때 **TC-LT-10 이 실패**했다.
원인은 관문 파일 자신의 설명문에 든 `paper=False` 문자열이었다.
막아야 할 하드코딩이 아니라 **무엇을 막는지 적은 정의**라 대상에서 제외하고 그 이유를 시험에 적었다.

이것이 시험의 첫 수확이다 — 시험이 없었다면 「전부 지웠다」고 믿었을 자리다.
